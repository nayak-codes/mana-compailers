Git & GitHub — git status & git log

🔀 Git & GitHub 🟢 Lesson 5 📅 2026
Once you're making commits regularly, you need ways to check what's currently going on in your repository and review what's happened in the past. git status and git log are the two commands you will type more than any other.
1git status: What's Happening Right Now
git status

This command shows you: which files have been modified but not staged, which files are staged and ready to commit, and which files Git doesn't know about yet (untracked). Running git status constantly, before and after almost every action, is one of the best habits a new Git user can build.

2git log: Reviewing Commit History
git log

This prints every commit in the repository, newest first, showing the author, date, unique commit hash, and message. For a more compact view that's easier to scan:

git log --oneline          # one line per commit
git log --oneline --graph  # adds a visual branch diagram
3Understanding Commit Hashes

Every commit gets a unique identifier called a hash — a long string like a3f5c9e2b1d4.... You rarely need the full hash; the first 6-7 characters are almost always enough to uniquely identify a commit when using other Git commands like git checkout or git revert.

⚠️ Common Mistake: Not Checking git status Before Committing

Skipping git status before you commit means you might accidentally commit files you didn't mean to include, or miss staging a file you actually wanted saved. Making it a habit to run git status before every commit prevents most beginner mistakes.

💻 Try It Yourself

Make a small change to a file, then run these commands in order to see how status and log respond at each stage.

git status
git add .
git status
git commit -m "Update notes"
git log --oneline
