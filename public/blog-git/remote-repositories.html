Git & GitHub — Remote Repositories

🔀 Git & GitHub 🟢 Lesson 11 📅 2026
Everything covered so far has happened entirely on your own computer. Remote repositories are how you connect your local project to a copy hosted elsewhere — like GitHub — so you can back up your work and collaborate with others.
1Connecting to a Remote

If you started your project with git init rather than git clone, you need to manually connect it to a remote repository:

git remote add origin https://github.com/username/repository-name.git
git remote -v   # confirm it was added correctly

origin is just a conventional nickname for "the main remote" — you could technically name it anything, but almost every Git user keeps this default.

2Pushing Your Commits
git push origin main

This uploads your local commits to the remote repository. The very first time you push a new branch, add -u to remember the connection, so future pushes only need git push:

git push -u origin main
3Pulling Updates from Others
git pull origin main

This downloads and merges any new commits your teammates have pushed since you last synced. git pull is actually shorthand for two separate commands run back to back: git fetch (downloads new commits) followed by git merge (combines them into your branch).

⚠️ Common Mistake: Pushing Without Pulling First

If teammates have pushed new commits since you last synced, Git will reject your push with a "non-fast-forward" error to protect their work. Always run git pull before git push when working with others, to make sure your local history is up to date first.

💻 Try It Yourself

Connect a local repository to a remote URL and check the connection was registered correctly.

git remote add origin https://github.com/yourusername/your-repo.git
git remote -v
