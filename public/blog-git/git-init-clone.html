Git & GitHub — git init & git clone

🔀 Git & GitHub 🟢 Lesson 3 📅 2026
Every Git project starts one of two ways: you either create a brand-new repository from scratch, or you copy down an existing one that someone else already started. This lesson covers both starting points.
1git init: Starting a New Repository

To turn any existing folder into a Git repository, navigate into it in your terminal and run:

cd my-project
git init

This creates a hidden .git folder inside your project. That folder is where Git secretly stores your entire project history — deleting it removes all Git tracking, though your actual files remain untouched.

2git clone: Copying an Existing Repository

If a project already exists on GitHub (or anywhere else), you don't create it again — you clone it, which downloads the complete project including its full history:

git clone https://github.com/username/repository-name.git

This creates a new folder named after the repository, already fully set up with a connection back to the original online source (called origin, which you'll use again in the Remote Repositories lesson).

3Checking Whether a Folder Is Already a Repository

Not sure if a folder is already tracked by Git? Look for the hidden .git folder, or simply run any Git command — if it isn't a repository yet, Git will tell you clearly with fatal: not a git repository.

⚠️ Common Mistake: Running git init Inside an Already-Cloned Project

If you clone a repository and then run git init again inside it "just to be safe," you risk resetting Git's internal tracking. There's no need — git clone already fully initializes the repository for you. Only use git init for genuinely new projects.

💻 Try It Yourself

Create a new folder called practice-repo, turn it into a Git repository, and confirm it worked by checking for the hidden .git folder.

mkdir practice-repo
cd practice-repo
git init
ls -la   # you should see a .git folder listed
