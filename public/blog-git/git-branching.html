Git & GitHub — Branching in Git

🔀 Git & GitHub 🟢 Lesson 6 📅 2026
Branches let you work on new features, experiments, or bug fixes in complete isolation from your project's main, stable code. This is one of Git's most powerful ideas — you can try something risky, and if it doesn't work out, simply delete the branch with zero impact on anything else.
1What Is a Branch, Really?

A branch is simply a lightweight, movable pointer to a specific commit. When you create a new branch, Git doesn't copy your entire project — it just creates a new pointer, which makes branching in Git extremely fast, even on huge projects.

git branch                  # list all branches, current one marked with *
git branch feature-login    # create a new branch (doesn't switch to it yet)
2Switching Between Branches
git checkout feature-login          # switch to an existing branch
git checkout -b feature-signup      # create AND switch in one command

Newer versions of Git also support git switch feature-login, a clearer, purpose-built alternative to checkout for changing branches specifically.

3Why Branching Matters for Teams

In a real team, the main branch usually stays stable and deployable at all times. Each developer creates their own branch for their specific task, works there without disturbing anyone else, and only merges their changes back into main once the feature is complete and reviewed.

⚠️ Common Mistake: Making Changes Directly on the main Branch

Committing experimental or half-finished work directly onto main is one of the most common beginner and even professional mistakes — it risks breaking the stable version of the project for everyone. Always create a new branch before starting new work, even for small changes.

💻 Try It Yourself

Create and switch to a new branch called feature-navbar, then confirm you're on it.

git branch feature-navbar
git checkout feature-navbar
git branch   # the * should now be next to feature-navbar
