Git & GitHub — Merging Branches

🔀 Git & GitHub 🟢 Lesson 7 📅 2026
Once work on a branch is finished, you need to bring those changes back into another branch — usually main. This process is called merging, and understanding how it works (including when it goes wrong) is essential for working on any real team project.
1Performing a Basic Merge

First switch to the branch you want to merge into, then run git merge naming the branch you want to merge from:

git checkout main
git merge feature-login

Git will attempt to automatically combine the changes from both branches into one unified history.

2Fast-Forward vs Three-Way Merges

If main hasn't changed at all since you branched off, Git performs a fast-forward merge — it simply moves the main pointer forward, with no new merge commit created. If both branches have diverged with separate new commits, Git creates a merge commit that has two parent commits, recording exactly how the two histories were combined.

3Handling Merge Conflicts

A conflict happens when the same lines of the same file were changed differently on both branches. Git pauses the merge and marks the conflicting sections directly inside the file using <<<<<<<, =======, and >>>>>>> markers. You manually edit the file to keep the correct version, then stage and commit it to complete the merge:

git add conflicted-file.txt
git commit -m "Resolve merge conflict"
⚠️ Common Mistake: Panicking (and Force-Quitting) When a Conflict Appears

Merge conflicts are a completely normal part of collaborative development, not a sign that something is broken. If a merge feels too messy to resolve safely, you can always back out cleanly with git merge --abort and try again with a clearer head, instead of leaving the repository in a half-merged state.

💻 Try It Yourself

Merge your feature-navbar branch back into main and check the resulting history.

git checkout main
git merge feature-navbar
git log --oneline --graph
