Git & GitHub — SSH Keys for Git

🔀 Git & GitHub 🟢 Lesson 12 📅 2026
When pushing to GitHub, you need to prove your identity. SSH keys are the standard, secure way to do this — once set up, you never have to type a password again for Git operations.
1What Is an SSH Key Pair?

SSH authentication uses two mathematically linked keys: a private key, which stays secret on your computer forever, and a public key, which you safely share with GitHub. When you connect, GitHub uses the public key to verify a challenge that only your matching private key could have answered — proving it's really you, without ever transmitting a password.

2Generating a New SSH Key
ssh-keygen -t ed25519 -C "you@example.com"

Press Enter to accept the default file location. You'll be asked for an optional passphrase — adding one provides extra security in case your private key file is ever stolen.

3Adding Your Key to GitHub

Copy your public key to the clipboard:

cat ~/.ssh/id_ed25519.pub

Then, on GitHub, go to Settings → SSH and GPG keys → New SSH key, paste the contents, and save. Test the connection with:

ssh -T git@github.com

A successful message confirms GitHub recognizes your key and you can now push and pull without entering a password.

⚠️ Common Mistake: Sharing or Uploading the Wrong Key File

The file ending in .pub (e.g. id_ed25519.pub) is the one safe to share — it's your public key. The file without .pub is your private key and must never be shared, emailed, or committed to a repository. If it's ever exposed, generate a brand new key pair immediately.

💻 Try It Yourself

Generate a new SSH key pair (skip this if you already have one) and view your public key so you're ready to add it to GitHub.

ssh-keygen -t ed25519 -C "you@example.com"
cat ~/.ssh/id_ed25519.pub
