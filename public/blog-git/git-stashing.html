Git & GitHub — Stashing Work in Progress

🔀 Git & GitHub 🟢 Lesson 10 📅 2026
Sometimes you're in the middle of changes but suddenly need to switch branches — maybe to fix an urgent bug — without committing half-finished work. Git's stash feature lets you temporarily set your changes aside and bring them back later, exactly where you left off.
1Stashing Your Current Changes
git stash

This takes all your uncommitted changes (both staged and unstaged) and saves them onto a stack, leaving your working directory clean — as if you had just committed nothing at all. You can now safely switch branches, pull updates, or do anything else that requires a clean working directory.

2Bringing Stashed Changes Back
git stash list          # see everything you've stashed
git stash pop           # reapply the most recent stash AND remove it from the stack
git stash apply         # reapply the most recent stash but KEEP it on the stack

Use pop when you're confident you want the changes back permanently. Use apply if you might want to apply the same stash to more than one branch.

3Naming Your Stashes

If you stash more than once, it's easy to lose track of what each one contains. Add a descriptive message so future-you can tell them apart:

git stash push -m "WIP: login form validation"
⚠️ Common Mistake: Forgetting You Have Stashed Changes

It's surprisingly common to stash something, get distracted by other work, and forget it exists — days or weeks later you discover uncommitted work sitting silently on the stash stack. Run git stash list periodically, and always give stashes clear names so old ones don't get lost.

💻 Try It Yourself

Make an uncommitted change, stash it, confirm your working directory is clean, then bring the change back.

echo "wip" >> notes.txt
git stash push -m "WIP: testing stash"
git status
git stash pop
