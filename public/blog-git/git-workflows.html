Git & GitHub — Common Git Workflows

🔀 Git & GitHub 🟢 Lesson 14 📅 2026
Knowing individual Git commands is one thing — knowing how a team actually organizes its branches day to day is another. This lesson covers the most common branching workflows used by real teams, so you know what to expect when you join a project.
1Feature Branch Workflow

The most common and beginner-friendly workflow: main always stays stable, and every new feature or fix gets its own short-lived branch, created off main and merged back into it via a pull request once complete and reviewed. Small teams and most personal projects use this pattern.

git checkout main
git pull
git checkout -b feature-search-bar
# ...work, commit...
git push -u origin feature-search-bar
# open a pull request on GitHub
2Gitflow Workflow

A more structured system used by larger teams with scheduled releases, using several long-lived branches: main holds only production-ready released code, develop holds the latest integrated work-in-progress, and separate short-lived feature/, release/, and hotfix/ branches handle specific tasks before merging into develop or directly into main for urgent fixes.

3Trunk-Based Development

The opposite philosophy: everyone commits small, frequent changes directly to main (the "trunk"), often multiple times a day, relying heavily on automated testing and feature flags rather than long-lived branches. This is popular at companies practicing continuous deployment, where new code ships to production many times a day.

⚠️ Common Mistake: Picking a Complex Workflow for a Solo or Tiny Project

Gitflow's multiple long-lived branches add real overhead that mostly pays off on large teams with scheduled releases. For a solo project or a team of two or three people, the simple Feature Branch Workflow is almost always the better, lower-friction choice.

💻 Try It Yourself

No commands to run here — instead, look at a real open-source project on GitHub and try to identify which workflow its branch list suggests they're using.

# Compare branch names on a real GitHub project:
# main + short feature/* branches   → Feature Branch Workflow
# main + develop + release/*        → Gitflow
