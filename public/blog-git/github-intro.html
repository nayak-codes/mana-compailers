Git & GitHub — Introduction to GitHub

🔀 Git & GitHub 🟢 Lesson 13 📅 2026
GitHub is the most widely used platform for hosting Git repositories online, and it's become the default place developers showcase their work, collaborate with teams, and contribute to open-source projects. This lesson introduces the core GitHub concepts every developer should know.
1Repositories on GitHub

A GitHub repository (or "repo") is simply an online, hosted copy of a Git project, complete with its full commit history. You can create a new empty one directly on GitHub's website and then clone it, or push an existing local project up to a new repository you create there.

2Issues and Pull Requests

Issues are GitHub's built-in system for tracking bugs, feature requests, and tasks — essentially a to-do list attached to your project that anyone can comment on. Pull requests (often shortened to "PRs") are how changes get proposed and reviewed before merging: you push your branch to GitHub, open a pull request asking to merge it into main, teammates leave comments and request changes, and only once approved does it get merged.

3Forking vs Cloning

Cloning downloads a copy of a repository to your own computer. Forking creates your own independent copy of someone else's repository on GitHub itself, which you can freely modify without needing permission from the original owner. Forking is the standard way to contribute to open-source projects you don't have direct write access to — you fork it, make your changes, then open a pull request back to the original project.

⚠️ Common Mistake: Editing main Directly on a Team Project

On any shared repository, pushing changes straight to main without going through a pull request skips code review entirely and can break the project for the whole team. Most professional teams configure GitHub to block direct pushes to main, requiring every change to go through a reviewed pull request instead.

💻 Try It Yourself

This lesson is best practiced directly on GitHub's website: create a free account if you don't have one, create a new empty repository, and note the clone URL it gives you for the next steps.

# 2. Name it and click "Create repository"
