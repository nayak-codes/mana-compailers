Python Exceptions & Error Handling (తెలుగులో)

🐍 Python 3.12+ 🟢 Chapter 25 of 65 📂 Phase 6: Exception and File Handling 📅 2026 Edition
📌 Covered in this chapter: Errors vs Exceptions · try-except-else-finally · Multiple Exceptions · raise · Custom Exceptions · Hierarchy · Useful Messages
Python లో ఎర్రర్స్ వస్తే కోడ్ ఆగిపోకుండా ఎలా కాపాడుకోవాలి? try-except బ్లాక్స్, ఎర్రర్ రావడం (Exceptions), మన సొంత ఎర్రర్స్ క్రియేట్ చేయడం గురించి పూర్తిగా నేర్చుకుందాం.
1Syntax Errors vs Runtime Exceptions

పైథాన్ లో బగ్స్ (తప్పులు) రెండు రకాలుగా వస్తాయి:

  1. Syntax Errors (గ్రామర్ తప్పులు): మీరు కోడ్ లో : (కోలన్) మర్చిపోయినా, బ్రాకెట్ క్లోజ్ చేయకపోయినా ఇవి వస్తాయి. కోడ్ రన్ అవ్వకముందే పైథాన్ ఆపేస్తుంది (SyntaxError). వీటిని మనం try-except తో ఆపలేం. మీరు కరెక్ట్ చేయాల్సిందే.
  2. Exceptions (రన్ టైమ్ లో వచ్చేవి): మీ కోడ్ కరెక్ట్ గానే ఉన్నా, రన్ అయ్యేటప్పుడు వచ్చే ఎర్రర్స్. ఉదాహరణకి నెంబర్ ని సున్నా (0) తో భాగిస్తే వచ్చే ZeroDivisionError లేదా లేని ఫైల్ ఓపెన్ చేస్తే వచ్చే FileNotFoundError. వీటిని మనం ఆపి కోడ్ ముందుకు వెళ్లేలా చేయొచ్చు.

The Exception Hierarchy (వంశవృక్షం): పైథాన్ లో అన్ని ఎర్రర్స్ కి ఒక పేరెంట్ ఉంటుంది:

┌────────────────────────────────────────────────────────┐ │ BaseException (తాతయ్య) │ │ ├── SystemExit, KeyboardInterrupt (Ctrl+C) │ │ └── Exception (తండ్రి - మన యాప్ ఎర్రర్స్ కి) │ │ ├── ArithmeticError (ZeroDivisionError) │ │ ├── LookupError (IndexError, KeyError) │ │ ├── TypeError, ValueError │ │ └── OSError (FileNotFoundError) │ └────────────────────────────────────────────────────────┘
⚠️ రూల్: ఎప్పుడూ BaseException ని క్యాచ్ చేయకండి:
మనం ఎప్పుడూ Exception ని మాత్రమే క్యాచ్ చేయాలి. BaseException ని క్యాచ్ చేస్తే, యూజర్ Ctrl+C నొక్కి ఆపాలనుకున్నా మీ కోడ్ ఆపకుండా ఇబ్బంది పెడుతుంది.

# రన్ టైమ్ లో ఈ ఎర్రర్స్ ఏ గ్రూప్ కి చెందుతాయో చూద్దాం:
print("Is ZeroDivisionError an ArithmeticError?", issubclass(ZeroDivisionError, ArithmeticError))
print("Is KeyError a LookupError?", issubclass(KeyError, LookupError))

print("Is ArithmeticError an Exception?", issubclass(ArithmeticError, Exception))
🔍 Inheritance సీక్రెట్:

KeyError అనేది LookupError గ్రూప్ లో ఉంటుంది కాబట్టి, మనం except LookupError: అని రాస్తే చాలు, అది రెండు రకాల ఎర్రర్స్ (IndexError, KeyError) ని ఒకేసారి క్యాచ్ చేస్తుంది!

2ది కంప్లీట్ ఫ్లో: try, except, else, finally

ప్రొఫెషనల్ పైథాన్ కోడ్ లో ఎర్రర్ హ్యాండ్లింగ్ కి 4 బ్లాక్స్ ఉంటాయి:

  • try: ఎర్రర్ రావచ్చు అని డౌట్ ఉన్న రిస్కీ కోడ్ ని ఇందులో రాస్తాం.
  • except: try లో ఎర్రర్ వస్తేనే ఈ కోడ్ రన్ అవుతుంది (కోడ్ క్రాష్ అవ్వకుండా ఆపుతుంది).
  • else: try లో ఎలాంటి ఎర్రర్ రాకపోతేనే ఇది రన్ అవుతుంది (సక్సెస్ అయితే).
  • finally: ఎర్రర్ వచ్చినా, రాకపోయినా లాస్ట్ లో ఖచ్చితంగా 100% రన్ అయ్యేది ఇదే. ఫైల్స్ క్లోజ్ చేయడానికి, డేటాబేస్ డిస్కనెక్ట్ చేయడానికి వాడతారు.
💻 Example 2: The Complete 4-Clause try-except-else-finally Flow
Python 3 ▶ Run in Compiler 
def safe_divide_engine(a, b):
    print(f"\n--- Attempting: {a} / {b} ---")
    try:
        # Step 1: రిస్కీ కోడ్
        result = a / b
    except ZeroDivisionError as err:
        # Step 2: జీరో తో డివైడ్ చేస్తే
        print(f"❌ Handled Error: సున్నా తో భాగించకూడదు! ({err})")
        return None
    except TypeError as err:
        # Step 2: వేరేవి ఇస్తే (ఉదా: స్ట్రింగ్)
        print(f"❌ Handled Error: నెంబర్స్ మాత్రమే ఇవ్వాలి! ({err})")
        return None
    else:
        # Step 3: సక్సెస్ అయితే మాత్రమే రన్ అవుతుంది
        print(f"✅ Calculation Successful! Result = {result}")
        return result
    finally:
        # Step 4: ఎప్పుడూ రన్ అవుతుంది
        print("🔒 [Cleanup] safe_divide_engine సైకిల్ పూర్తయింది.")

# అన్ని రకాలుగా టెస్ట్ చేద్దాం:
safe_divide_engine(100, 4)   # Success (try -> else -> finally)
safe_divide_engine(50, 0)    # Zero Division (try -> except -> finally)
safe_divide_engine(10, "2")  # Type Error (try -> except -> finally)
🔍 గమనించారా?:

ఫస్ట్ దాంట్లో సక్సెస్ అయింది కాబట్టి else రన్ అయింది. మిగతా రెంటిలో ఎర్రర్ వచ్చింది కాబట్టి except రన్ అయింది. కానీ మూడు సార్లూ finally మాత్రం గ్యారెంటీగా రన్ అయింది.

3చాలా ఎర్రర్స్ వస్తే? (Grouping Exceptions)

ఎప్పుడూ సింపుల్ గా except: అని రాయకండి. దేనికి ఆ ఎర్రర్ పేరు పెట్టి పట్టుకోవాలి, అప్పుడే ఏ తప్పు జరిగిందో క్లియర్ గా తెలుస్తుంది. మీరు కావాలంటే ఒకేసారి రెండు ఎర్రర్స్ ని బ్రాకెట్స్ (Tuple) లో పెట్టి క్యాచ్ చేయొచ్చు:

💻 Example 3: Handling Multiple Specific Exceptions and Tuple Grouping
Python 3 ▶ Run in Compiler 
def process_user_record(data_dict, key, divisor):
    try:
        raw_val = data_dict[key]          # కీ లేకపోతే KeyError
        parsed_num = float(raw_val)       # టెక్స్ట్ ఉంటే ValueError
        computed = 1000 / parsed_num      # సున్నా ఉంటే ZeroDivisionError
        return computed
    except KeyError:
        print(f"❌ Error: డేటా లో '{key}' అనే ఫీల్డ్ లేదు!")
    except (ValueError, TypeError) as err:
        print(f"❌ Data Parsing Error: నెంబర్ ఫార్మాట్ తప్పు ({err})")
    except ZeroDivisionError:
        print("❌ Math Error: సున్నా తో క్యాలిక్యులేట్ చేయలేము!")

# టెస్టింగ్:
user_data = {"score": "50", "bonus": "zero", "zero_val": "0"}

print("1. Valid score:    ", process_user_record(user_data, "score", 2))
print("2. Missing key:    ", process_user_record(user_data, "missing_key", 2))
print("3. Bad number string:", process_user_record(user_data, "bonus", 2))
print("4. Division by zero:", process_user_record(user_data, "zero_val", 2))
🔍 ఎందుకు ఇలా రాయాలి?:

ఇలా ఒక్కొక్కదానికి రాస్తే, కీ లేకపోతే యూజర్ ని మళ్ళీ కీ అడగమని చెప్పొచ్చు, సున్నా ఇస్తే వేరే నెంబర్ అడగమని చెప్పొచ్చు. జనరిక్ గా ఫెయిల్ అవ్వకుండా ఉండొచ్చు.

4కావాలని ఎర్రర్ తెప్పించడం (raise)

యూజర్ వయస్సు -5 ఇస్తే మన కోడ్ క్రాష్ అవ్వదు కానీ బిజినెస్ రూల్ ప్రకారం అది తప్పు. ఇలాంటి టైం లో మనమే కావాలని raise వాడి ఎర్రర్ త్రో చేయాలి (విసిరేయాలి):

💻 Example 4: Explicit Exception Raising and Guarding Business Logic
Python 3 ▶ Run in Compiler 
def validate_account_age(age):
    if not isinstance(age, int):
        raise TypeError(f"Age అనేది నెంబర్ అయిఉండాలి, కానీ {type(age).__name__} వచ్చింది")
    if age < 0:
        raise ValueError(f"వయస్సు మైనస్ లో ఉండకూడదు! మీరు ఇచ్చింది: {age}")
    if age < 18:
        raise PermissionError(f"వయస్సు {age} ఇయర్స్. అకౌంట్ కి 18 నిండాలి.")
    return "✅ Age verified successfully!"

# టెస్టింగ్:
try:
    print(validate_account_age(22))  # ఓకే
    validate_account_age(-5)         # ఇక్కడ ValueError వస్తుంది
except (TypeError, ValueError, PermissionError) as err:
    print(f"🚫 Validation Failed: {err}")
🔍 Fail-Fast రూల్:

తప్పు డేటా వస్తే అక్కడే కోడ్ ని ఆపేసి ఎర్రర్ ఇవ్వాలి. లేకపోతే ఆ తప్పు డేటా డేటాబేస్ లోకి వెళ్లిపోయి పెద్ద ప్రాబ్లం అవుతుంది.

5మన సొంత కస్టమ్ ఎర్రర్స్ రాసుకోవడం

పెద్ద ప్రాజెక్ట్స్ (బ్యాంకింగ్ యాప్స్) లో పైథాన్ ఎర్రర్స్ కాకుండా, మన బిజినెస్ కి తగ్గట్టు మన సొంత ఎర్రర్స్ క్లాసెస్ రాసుకోవచ్చు (Exception ని పేరెంట్ గా పెట్టి):

💻 Example 5: Designing Custom Application Exceptions
Python 3 ▶ Run in Compiler 
# మన సొంత ఎర్రర్స్ ని డిజైన్ చేద్దాం:
class BankingAppError(Exception):
    """అన్ని బ్యాంకింగ్ ఎర్రర్స్ కి ఇది పేరెంట్."""
    pass

class InsufficientFundsError(BankingAppError):
    """బ్యాలెన్స్ కంటే ఎక్కువ డబ్బులు అడిగితే వచ్చే ఎర్రర్."""
    def __init__(self, balance, amount_requested):
        self.balance = balance
        self.amount_requested = amount_requested
        self.shortage = amount_requested - balance
        super().__init__(
            f"Withdrawal of Rs.{amount_requested:.2f} failed! "
            f"Current Balance: Rs.{balance:.2f} (Short by Rs.{self.shortage:.2f})"
        )

class AccountLockedError(BankingAppError):
    """అకౌంట్ బ్లాక్ అయి ఉంటే వచ్చే ఎర్రర్."""
    pass

def withdraw_money(account_balance, amount, is_locked=False):
    if is_locked:
        raise AccountLockedError("అకౌంట్ లాక్ లో ఉంది. కస్టమర్ కేర్ కి కాల్ చేయండి.")
    if amount > account_balance:
        raise InsufficientFundsError(account_balance, amount) # మన ఎర్రర్!
    return account_balance - amount

# టెస్టింగ్:
try:
    new_bal = withdraw_money(500.0, 750.0) # బ్యాలెన్స్ 500, కానీ 750 కావాలంటున్నాడు
except InsufficientFundsError as err:
    print("💳 Transaction Blocked:", err)
    print(f"👉 కస్టమర్ ఇంకా Rs.{err.shortage:.2f} వేయాలి.")
except BankingAppError as err:
    print("🏦 General Banking Error:", err)
🔍 ప్రొఫెషనల్ అప్రోచ్:

ఇలా మన సొంత ఎర్రర్స్ (ఉదా: InsufficientFundsError) క్రియేట్ చేయడం వల్ల, వేరే వాళ్ళకి మన కోడ్ లో ఏం జరుగుతుందో ఈజీగా అర్థమవుతుంది. అందులో err.shortage లాంటి ఎక్స్ట్రా డేటా కూడా పంపొచ్చు.

⚠️ Common Developer Pitfall: బ్లైండ్ గా "except:" అని వదిలేయడం

ఉట్టి except: అని రాస్తే అది స్పెల్లింగ్ తప్పులు, అవుట్ ఆఫ్ మెమరీ అన్నీ ఆపేస్తుంది. దీనివల్ల అసలు ఏం తప్పు జరుగుతుందో ఎప్పటికీ అర్థం కాదు. ఎప్పుడూ except ValueError: అలా పేరు పెట్టి పట్టుకోవాలి.

def safe_int_converter(raw_value):
    try:
        return int(raw_value), "Success"
    except ValueError:
        return None, f"'{raw_value}' కరెక్ట్ నెంబర్ కాదు!"

# టెస్టింగ్:
for test_val in ["42", "hello", "100.5", "-99"]:
    val, status = safe_int_converter(test_val)
    print(f"Input: {test_val:8} -> Parsed: {val} ({status})")

try లో ఎర్రర్ రాకుండా అంతా సక్సెస్ అయితేనే else రన్ అవుతుంది. కానీ finally అలా కాదు, ఎర్రర్ వచ్చినా, రాకపోయినా లాస్ట్ లో ఖచ్చితంగా గ్యారెంటీగా రన్ అవుతుంది.

Q catch బ్లాక్ లోనే మళ్ళీ ఎర్రర్ వస్తే ఏమవుతుంది?

except బ్లాక్ లో కూడా ఎర్రర్ వస్తే ప్రోగ్రామ్ అక్కడే క్రాష్ అవుతుంది. పైథాన్ దాన్ని ఆపలేదు.
