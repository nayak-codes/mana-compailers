Closures & Decorators (తెలుగులో)

🐍 Python 3.12+ 🟢 Chapter 37 of 65 📂 Phase 8: Advanced Python 📅 2026 Edition
📌 Covered in this chapter: First-Class Functions · Lexical Closures · @decorator Syntax · functools.wraps · Decorators with Arguments · Execution Timers · Role Authorization
పైథాన్ లో ఫంక్షన్స్ తో మ్యాజిక్ ఎలా చేయాలి? ఒక ఫంక్షన్ కి అదనపు పవర్ ఇవ్వాలంటే (ఉదా: టైమర్, లాగిన్ చెక్) @decorators ఎలా రాయాలో చూద్దాం.
1ఫంక్షన్స్ కూడా ఒక వేరియబుల్ లాంటివే (First-Class Functions & Closures)

పైథాన్ లో ఫంక్షన్స్ ని మనం చాలా ఫ్రీగా వాడుకోవచ్చు. ఒక ఫంక్షన్ ని ఇంకో ఫంక్షన్ లోపల రాయొచ్చు, ఒక ఫంక్షన్ ని రిటర్న్ (return) చేయొచ్చు.

Closure (క్లోజర్) అంటే ఏంటి?

ఒక బయటి ఫంక్షన్ లోపల ఇంకో చిన్న ఫంక్షన్ రాసి, ఆ చిన్న ఫంక్షన్ బయటి వేరియబుల్స్ ని వాడుకుని, తర్వాత ఆ చిన్న ఫంక్షన్ నే రిటర్న్ చేస్తే... ఆ బయటి వేరియబుల్స్ కూడా ఆ చిన్న ఫంక్షన్ తో పాటే గుర్తుండిపోతాయి! దాన్నే Closure అంటారు.

💻 Example 1: Function Factory Closures Retaining Enclosing State
Python 3 ▶ Run in Compiler 
# ఒక ఫంక్షన్ ని తయారు చేసే ఫంక్షన్ (Factory):
def make_power_calculator(exponent):
    """బయటి ఫంక్షన్."""
    def power(base):
        """లోపలి ఫంక్షన్ (ఇది బయట ఉన్న 'exponent' ని వాడుకుంటోంది)."""
        return base ** exponent
    return power  # ఇక్కడ ఆ ఫంక్షన్ నే రిటర్న్ చేస్తున్నాం!

# ఇప్పుడు మనకి నచ్చిన పవర్ ఫంక్షన్స్ తయారు చేద్దాం:
square = make_power_calculator(2) # ఇది స్క్వేర్ చేసే ఫంక్షన్ అవుతుంది
cube = make_power_calculator(3)   # ఇది క్యూబ్ చేసే ఫంక్షన్ అవుతుంది

print("Square of 5:", square(5))  # 25 (exponent 2 అని దీనికి గుర్తుంది)
print("Cube of 5:  ", cube(5))    # 125 (exponent 3 అని దీనికి గుర్తుంది)
print("స్క్వేర్ లోపల ఫ్రీజ్ అయిన వాల్యూ:", square.__closure__[0].cell_contents)
🔍 పైథాన్ లాజిక్:

మామూలుగా ఫంక్షన్ అవ్వగానే దాని లోపల ఉన్న వేరియబుల్స్ అన్నీ డిలీట్ అవ్వాలి. కానీ exponent ని లోపలి ఫంక్షన్ వాడుకుంటోంది కాబట్టి, దాన్ని సేవ్ చేసి ఉంచుతుంది (అదే __closure__).

2Decorators & @functools.wraps (ఒక ఫంక్షన్ కి మేకప్ వేయడం)

Decorator అంటే ఒక ఫంక్షన్ కి ఎక్స్ట్రా ఫీచర్స్ (ఉదా: టైమ్ క్యాలిక్యులేట్ చేయడం) యాడ్ చేసే ఇంకో ఫంక్షన్. ఆ మెయిన్ ఫంక్షన్ లోపల కోడ్ మార్చకుండానే మనం అదనపు పనులు చేయొచ్చు.

@functools.wraps ఖచ్చితంగా ఎందుకు వాడాలి?:

డెకరేటర్ వాడినప్పుడు, మన ఒరిజినల్ ఫంక్షన్ పేరు మాయమైపోయి, ర్యాపర్ ఫంక్షన్ పేరు వస్తుంది. దానివల్ల చాలా ఎర్రర్స్ వస్తాయి. దాన్ని కాపాడ్డానికి ఈ wraps వాడతాం.

💻 Example 2: Execution Timer Decorator with @functools.wraps
Python 3 ▶ Run in Compiler 
import functools
import time

def benchmark_timer(func):
    """ఫంక్షన్ ఎంతసేపు రన్ అయ్యిందో చెప్పే డెకరేటర్."""
    @functools.wraps(func)  # చాలా ముఖ్యం: ఇది వాడితేనే అసలు ఫంక్షన్ పేరు సేఫ్ గా ఉంటుంది!
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        
        result = func(*args, **kwargs)  # అసలు ఫంక్షన్ ని ఇక్కడ కాల్ చేస్తాం
        
        duration_ms = (time.perf_counter() - start) * 1000
        print(f"⏱️ [{func.__name__}] Finished in {duration_ms:.3f} ms")
        return result
    return wrapper

# డెకరేటర్ ని ఈజీగా @ వాడి అప్లై చేద్దాం:
@benchmark_timer
def process_data(limit):
    """నంబర్స్ ని యాడ్ చేసే పని."""
    return sum(x ** 2 for x in range(limit))

# ఫంక్షన్ ని పిలుద్దాం:
res = process_data(500_000)
print("Result Total:", res)
print("అసలు ఫంక్షన్ పేరు:", process_data.__name__)
print("అసలు ఫంక్షన్ కామెంట్:", process_data.__doc__)
🔍 *args, **kwargs ఎందుకు?:

అసలు ఫంక్షన్ కి ఎన్ని ఆర్గ్యుమెంట్స్ ఉన్నాయో మనకు తెలియదు కదా. అందుకే *args, **kwargs అని రాస్తే, ఏ ఫంక్షన్ కైనా ఈ డెకరేటర్ సెట్ అవుతుంది.

3ఆర్గ్యుమెంట్స్ తీసుకునే డెకరేటర్స్ (3-Level Nesting)

కొన్నిసార్లు డెకరేటర్ కి కూడా ఆర్గ్యుమెంట్స్ పంపాలి (ఉదా: @repeat(3)). అప్పుడు దాన్ని 3-లెవెల్స్ గా రాయాలి:

  1. లెవెల్ 1 (బయట): సెట్టింగ్స్ తీసుకుంటుంది (ఉదా: num_times).
  2. లెవెల్ 2 (మధ్యలో): ఫంక్షన్ ని తీసుకుంటుంది.
  3. లెవెల్ 3 (లోపల ర్యాపర్): అసలు పని చేస్తుంది (args తీసుకుని).
💻 Example 3: 3-Level Decorator Factory with Configurable Arguments
Python 3 ▶ Run in Compiler 
import functools

def repeat(num_times=2):
    """డెకరేటర్ ఫ్యాక్టరీ (సెట్టింగ్స్ తీసుకుంటుంది)."""
    def decorator_repeat(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            last_result = None
            for i in range(num_times):
                print(f"🔄 Execution #{i+1} of {func.__name__}():")
                last_result = func(*args, **kwargs)
            return last_result
        return wrapper
    return decorator_repeat

# కస్టమ్ సెట్టింగ్స్ తో డెకరేటర్ ని వాడటం:
@repeat(num_times=3)
def send_alert(message):
    print(f"   🔔 ALERT: {message}")

send_alert("డేటాబేస్ కనెక్షన్ పోయింది!")
🔍 ప్రాక్టికల్ యూజ్:

వెబ్ డెవలప్మెంట్ లో @app.get("/users") అని రాస్తాం కదా, అక్కడ ఈ 3-లెవెల్ మ్యాజిక్కే జరుగుతుంది.

⚠️ Common Developer Pitfall: డెకరేటర్ కి బ్రాకెట్స్ () ఇవ్వడం మర్చిపోవడం

మీరు ఒకవేళ డెకరేటర్ ఫ్యాక్టరీ (ఉదా: def repeat(num=1):) రాస్తే, దాన్ని కచ్చితంగా బ్రాకెట్స్ తోనే పిలవాలి @repeat(). బ్రాకెట్స్ లేకుండా @repeat అని రాస్తే ఎర్రర్ వస్తుంది.

💻 Hands-on Interactive Practice Challenge

ఒక ఆథరైజేషన్ డెకరేటర్ require_role(allowed_role) రాయండి. యూజర్ "Admin" అయితేనే ఫంక్షన్ రన్ అవ్వాలి, లేకపోతే "Access Denied" అని చెప్పాలి.

Python 3 Practice Challenge ▶ Run in Compiler 
import functools

def require_role(allowed_role):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(user, *args, **kwargs):
            if user.get("role") != allowed_role:
                print(f"❌ Access Denied: '{user.get('name')}' కి పర్మిషన్ లేదు!")
                return None
            return func(user, *args, **kwargs)
        return wrapper
    return decorator

@require_role("Admin")
def purge_cache(user):
    print(f"✅ Cache purged successfully by {user['name']}!")

user1 = {"name": "Balaji", "role": "Admin"}
user2 = {"name": "Alex", "role": "Guest"}

purge_cache(user1) # సక్సెస్
purge_cache(user2) # బ్లాక్ చేయబడుతుంది

Q ఒకే ఫంక్షన్ కి రెండు డెకరేటర్స్ వాడొచ్చా?

వాడొచ్చు! అప్పుడు కింద నుంచి పైకి రన్ అవుతాయి. (First కింద ఉన్న డెకరేటర్ అప్లై అవుతుంది, దానిపైన పై డెకరేటర్ అప్లై అవుతుంది).

Q functools.lru_cache అంటే ఏంటి?

ఇది పైథాన్ లో డీఫాల్ట్ గా ఉండే డెకరేటర్. ఇది ఒక ఫంక్షన్ ఇచ్చిన ఆన్సర్ ని గుర్తుపెట్టుకుంటుంది (Cache). మళ్ళీ అవే పారామీటర్స్ ఇస్తే రన్ చేయకుండా డైరెక్ట్ గా పాత ఆన్సర్ ఇచ్చేస్తుంది. చాలా స్పీడ్ అవుతుంది.
