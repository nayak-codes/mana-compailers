Python Encapsulation & Properties (తెలుగులో)

🐍 Python 3.12+ 🟢 Chapter 31 of 65 📂 Phase 7: Object-Oriented Programming 📅 2026 Edition
📌 Covered in this chapter: Encapsulation · Public, Protected (_), Private (__) · Name Mangling · @property Decorator · Getters & Setters
మన డేటాని ఎవరైనా బయటనుండి మార్చకుండా పైథాన్ లో ఎలా హైడ్ చేయాలి? Public, Protected, Private వేరియబుల్స్ అంటే ఏంటి? @property ఎందుకు వాడాలో చూద్దాం.
1Encapsulation అంటే ఏంటి? (Public, Protected, Private)

Encapsulation అంటే మన డేటాని (వేరియబుల్స్) ఒక క్యాప్స్యూల్ లాగా ప్యాక్ చేసి, వేరే ఫైల్స్ నుంచి ఎవరు పడితే వాళ్ళు డైరెక్ట్ గా మార్చకుండా లాక్ చేయడం.

పైథాన్ లో జావా లాగా private, public అనే కీవర్డ్స్ ఉండవు. దానికి బదులు వేరియబుల్ పేర్లతో (Underscores) అడ్జస్ట్ చేస్తాం:

రకంసింటాక్స్ (పేరు)అర్థం
Publicself.nameఎవరైనా, ఎక్కడినుంచైనా డైరెక్ట్ గా రీడ్ / రైట్ చేయొచ్చు.
Protectedself._emailరూల్ మాత్రమే: బయటనుండి వాడొద్దు, ఇది ఇంటర్నల్ అని చెప్తున్నాం. (పైథాన్ దీన్ని ఆపదు).
Privateself.__pinకఠినమైన రూల్: పైథాన్ దీని పేరు మార్చేస్తుంది (మ్యాంగ్లింగ్), కాబట్టి బయటనుండి పిలవడం కుదరదు!
💻 Example 1: Public, Protected (_), and Private (__) Modifiers
Python 3 ▶ Run in Compiler 
class UserAccount:
    def __init__(self, username, email, pin):
        self.username = username      # Public (ఫుల్ యాక్సెస్)
        self._email = email          # Protected (చూసి వదిలేయాలి)
        self.__pin = pin             # Private (పేరు మారిపోతుంది!)

    def verify_pin(self, entered_pin):
        return self.__pin == entered_pin

user = UserAccount("balaji_dev", "balaji@test.com", 1234)

# 1. Public ది యాక్సెస్ చేద్దాం (వస్తుంది):
print("Public Username:", user.username)

# 2. Protected ది యాక్సెస్ చేద్దాం (వస్తుంది, కానీ చేయకూడదు):
print("Protected Email:", user._email)

# 3. Private దాన్ని డైరెక్ట్ గా అడిగితే (AttributeError వస్తుంది):
try:
    print(user.__pin)
except AttributeError as err:
    print("❌ Private Access Blocked:", err)
🔍 user.__pin ఎందుకు రాలేదు?:

పైథాన్ ప్రైవేట్ వేరియబుల్స్ కి ముందు క్లాస్ పేరు తగిలిస్తుంది, తద్వారా బయటనుండి పిలిచినప్పుడు ఆ పేరుతో వేరియబుల్ లేదని ఎర్రర్ ఇస్తుంది.

2Name Mangling (లోపల ఏం జరుగుతుంది?)

మీరు ఒక వేరియబుల్ కి ముందు రెండు అండర్ స్కోర్స్ (__pin) ఇస్తే, పైథాన్ ఆటోమాటిక్ గా దాన్ని _ClassName__attribute (ఉదా: _UserAccount__pin) గా పేరు మార్చేస్తుంది. దీన్నే Name Mangling అంటారు.

ఇది హ్యాకర్స్ నుండి కాపాడటానికి కాదు, వేరే క్లాస్ లో అదే పేరుతో వేరియబుల్ ఉంటే రెండూ ఓవర్ రైడ్ అవ్వకుండా కాపాడటానికి.

💻 Example 2: Inspecting Name Mangling in Python Memory
Python 3 ▶ Run in Compiler 
# మన ఆబ్జెక్ట్ లోపల అసలు వేరియబుల్స్ ఎలా స్టోర్ అయ్యున్నాయో చూద్దాం (__dict__ వాడి):
user = UserAccount("ravi_k", "ravi@test.com", 9988)

print("ఆబ్జెక్ట్ లోపల ఉన్న డేటా ఇదీ:")
print(user.__dict__)

# మార్చిన పేరుతో పిలిస్తే? (ఖచ్చితంగా వస్తుంది):
print("\nమ్యాంగిల్ అయిన పేరుతో పిలిస్తే వస్తుంది:", user._UserAccount__pin)
🔍 పైథాన్ సిద్ధాంతం:

"మనం అందరం పెద్దవాళ్ళం, బాధ్యతగా ఉందాం" అని పైథాన్ నమ్ముతుంది. అంటే హార్డ్ కోర్ గా ప్రైవేట్ చేయదు, మీరు కావాలంటే ఆ మ్యాంగిల్ అయిన పేరుతో యాక్సెస్ చేయొచ్చు, కానీ డెవలపర్స్ అలా చేయరు.

3అద్భుతమైన @property (Getters & Setters)

జావా లాంటి లాంగ్వేజెస్ లో బ్యాలెన్స్ మార్చాలంటే setBalance(val) అని రాయాలి. కానీ పైథాన్ లో మీరు @property డెకరేటర్ వాడితే, అది చూడటానికి మామూలు వేరియబుల్ లాగే ఉంటుంది, కానీ లోపల అది ఒక ఫంక్షన్ రన్ చేస్తుంది!

దీనివల్ల మనం యూజర్ మైనస్ బ్యాలెన్స్ ఎంటర్ చేస్తే చెక్ చేసి ఆపొచ్చు:

💻 Example 3: Clean Data Validation with @property and @setter
Python 3 ▶ Run in Compiler 
class BankAccount:
    def __init__(self, owner, initial_balance):
        self.owner = owner
        self._balance = 0.0          # ఇది రియల్ వాల్యూ స్టోర్ చేసే Protected వేరియబుల్
        self.balance = initial_balance # ఇది కింద ఉన్న setter ని పిలుస్తుంది!

    # 1. Getter (యూజర్ అడిగినప్పుడు):
    @property
    def balance(self):
        """బ్యాలెన్స్ అడిగితే ఇస్తుంది."""
        return self._balance

    # 2. Setter (యూజర్ అప్డేట్ చేసినప్పుడు):
    @balance.setter
    def balance(self, value):
        """బ్యాలెన్స్ మార్చేటప్పుడు వాలిడేట్ చేస్తుంది."""
        if not isinstance(value, (int, float)):
            raise TypeError("బ్యాలెన్స్ కి నెంబర్స్ మాత్రమే ఇవ్వాలి!")
        if value < 0:
            raise ValueError(f"మైనస్ లో బ్యాలెన్స్ ఉండదు! మీరు ఇచ్చింది: ₹{value}")
        self._balance = float(value)

    # 3. Read-Only (ఓన్లీ చదవడానికి మాత్రమే, సెట్టర్ లేదు):
    @property
    def formatted_balance(self):
        return f"₹{self._balance:,.2f}"

# టెస్టింగ్ చేద్దాం:
acc = BankAccount("Balaji", 5000)
print("Balance accessed:", acc.balance) # getter కాల్ అవుతుంది!
print("Formatted:", acc.formatted_balance)

# సక్సెస్ గా అప్డేట్ చేయడం (setter కాల్ అయ్యి వాలిడేట్ చేస్తుంది):
acc.balance = 7500
print("Updated Balance:", acc.formatted_balance)

# మైనస్ వాల్యూ ఇస్తే?
try:
    acc.balance = -1000 # ఇక్కడ కోడ్ ఆగిపోయి, ValueError ఇస్తుంది!
except ValueError as err:
    print("🚫 Validation Prevented Error:", err)
🔍 @property ఎందుకు బెస్ట్?:

యూజర్ acc.balance = 7500 అని నార్మల్ గానే రాస్తాడు (సెట్టర్ ఫంక్షన్ వాడాల్సిన పనిలేదు). కానీ బ్యాక్ గ్రౌండ్ లో ఫంక్షన్ రన్ అయ్యి వాలిడేషన్ జరుగుతుంది.

⚠️ Common Developer Pitfall: Setter లోపల మళ్ళీ ఆ వేరియబుల్ నే పిలవడం (RecursionError)

Setter లోపల "self.balance = value" అని రాస్తే, అది మళ్ళీ అదే setter ని పిలుస్తుంది. అలా తిరిగీ తిరిగీ క్రాష్ అవుతుంది! ఎప్పుడూ లోపల ప్రైవేట్ వేరియబుల్ నే వాడాలి: self._balance = value.

💻 Hands-on Interactive Practice Challenge

ఒక Temperature క్లాస్ రాయండి. అందులో celsius అనే @property ఉండాలి, అది -273.15 కంటే కిందకి ఇస్తే (Absolute Zero) ఎర్రర్ త్రో చేయాలి.

Python 3 Practice Challenge ▶ Run in Compiler 
class Temperature:
    def __init__(self, celsius):
        self.celsius = celsius

    @property
    def celsius(self):
        return self._celsius

    @celsius.setter
    def celsius(self, value):
        if value < -273.15:
            raise ValueError("ఉష్ణోగ్రత అబ్సల్యూట్ జీరో కంటే తక్కువ ఉండదు!")
        self._celsius = value

t = Temperature(25)
print(f"Temperature: {t.celsius}°C")
t.celsius = 38
print(f"Updated: {t.celsius}°C")

❓ Frequently Asked Questions (FAQ)

Q ఒక వేరియబుల్ ని రీడ్-ఓన్లీ (ReadOnly) గా మార్చడం ఎలా?

జస్ట్ దానికి @property అని పెట్టి ఫంక్షన్ రాయండి, కానీ @setter రాయకండి. అప్పుడు ఎవరైనా దాన్ని మార్చడానికి ట్రై చేస్తే AttributeError వస్తుంది.
