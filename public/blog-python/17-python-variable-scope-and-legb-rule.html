Python Scope & LEGB Rule (తెలుగులో)

🐍 Python 3.12+ 🟢 Chapter 17 of 65 📂 Phase 4: Functions & Reusable Code 📅 2026 Edition
📌 Covered in this chapter: LEGB Hierarchy · Local vs Global · global & nonlocal · Closures · Pure Functions · Converters Project
Python లో ఒక వేరియబుల్ ని వెతికేటప్పుడు వాడే LEGB రూల్ అంటే ఏంటి? Local, Global స్కోప్ ల మధ్య తేడా, global మరియు nonlocal కీవర్డ్స్, మరియు Pure Functions గురించి నేర్చుకుందాం.
1LEGB అంటే ఏంటి? (Scope Resolution)

Python లో ఒక వేరియబుల్ క్రియేట్ చేసాక, అది ఎక్కడెక్కడ పనిచేస్తుందో చెప్పేదాన్ని Scope (పరిధి) అంటారు. మీరు ఒక వేరియబుల్ ని వాడినప్పుడు, పైథాన్ దాన్ని 4 అంచెల్లో వెతుక్కుంటూ వెళ్తుంది. దీన్నే LEGB Rule అంటారు:

┌────────────────────────────────────────────────────────┐ │ L - LOCAL: మనం రాసిన ఫంక్షన్ లోపలే వెతుకుతుంది │ ├────────────────────────────────────────────────────────┤ │ E - ENCLOSING: ఒకవేళ ఫంక్షన్ లోపల ఫంక్షన్ ఉంటే బయటిది │ ├────────────────────────────────────────────────────────┤ │ G - GLOBAL: డైరెక్ట్ గా ఫైల్ లో (పైన) రాసిన వేరియబుల్స్│ ├────────────────────────────────────────────────────────┤ │ B - BUILT-IN: పైథాన్ తో పాటు వచ్చే డీఫాల్ట్ ఫంక్షన్స్ │ └────────────────────────────────────────────────────────┘

ఈ నాలుగింటిలో ఎక్కడ దొరికితే అక్కడ పైథాన్ దాన్ని వాడుకుంటుంది. ఎక్కడా దొరకకపోతే NameError ఎర్రర్ ఇస్తుంది.

💻 Example 1: LEGB Scope Resolution Hierarchy in Action
Python 3 ▶ Run in Compiler 
# LEGB రూల్ ఎలా పనిచేస్తుందో చూద్దాం:
global_var = "🌍 I am GLOBAL"

def outer_function():
    enclosing_var = "📦 I am ENCLOSING (Outer Function)"
    
    def inner_function():
        local_var = "🏠 I am LOCAL (Inner Function)"
        print("Inside inner function:")
        print("  1.", local_var)      # తన లోపలే ఉంది కాబట్టి Local (L)
        print("  2.", enclosing_var)  # తన పైన ఉన్న ఫంక్షన్ కాబట్టి Enclosing (E)
        print("  3.", global_var)     # అసలు బయటే ఉంది కాబట్టి Global (G)
        print("  4. Built-in len:", len("Test")) # ఇది పైథాన్ ది Built-in (B)
        
    inner_function()

outer_function()
🔍 సింపుల్ గా చెప్పాలంటే:

లోపల ఉన్నవాళ్లు బయట ఉన్నవాటిని (Global) ఈజీగా చూసి వాడుకోవచ్చు. కానీ బయట ఉన్నవాళ్లు ఫంక్షన్ లోపల ఉన్నవాటిని (Local) వాడుకోలేరు.

2The global Keyword (గ్లోబల్ ని ఫంక్షన్ లోనుంచి మార్చడం)

ఫంక్షన్ బయట ఒక x = 100 ఉందనుకోండి. మీరు ఫంక్షన్ లోపల x = 200 అంటే, బయటి x మారదు! లోపల కొత్తగా ఇంకో లోకల్ x క్రియేట్ అవుతుంది. ఒకవేళ బయట ఉన్నదాన్నే మార్చాలంటే global కీవర్డ్ వాడాలి:

💻 Example 2: Modifying Global Variables with "global"
Python 3 ▶ Run in Compiler 
counter = 0  # ఇది Global వేరియబుల్

def increment_bad():
    # 'global' అని చెప్పకుండా counter కి +1 చేస్తే ఎర్రర్ వస్తుంది!
    pass

def increment_safe():
    global counter  # పైన ఉన్న గ్లోబల్ వేరియబుల్ నే నేను వాడుకుంటాను అని చెప్పడం
    counter += 1
    print("Global counter incremented to:", counter)

increment_safe()
increment_safe()
print("Final Global Counter:", counter)
🔍 బెస్ట్ ప్రాక్టీస్:

పెద్ద పెద్ద ప్రాజెక్ట్స్ లో ఎక్కడ పడితే అక్కడ global వాడటం చాలా రిస్క్. దాన్ని వాడకుండా ఉండటానికే ట్రై చేయండి.

3Closures మరియు nonlocal కీవర్డ్

ఫంక్షన్ లోపల ఇంకో ఫంక్షన్ ఉండి, లోపలి ఫంక్షన్ బయటి ఫంక్షన్ లోని వేరియబుల్స్ ని వాడుకోవడాన్ని Closure అంటారు. ఆ బయటి వేరియబుల్స్ ని లోపల మార్చాలంటే nonlocal వాడాలి:

💻 Example 3: Function Closures and the "nonlocal" Keyword
Python 3 ▶ Run in Compiler 
def create_bank_account(initial_balance):
    balance = initial_balance  # Enclosing వేరియబుల్
    
    def deposit(amount):
        nonlocal balance  # పైన ఉన్న balance నే వాడుకుని మారుస్తా అని చెప్పడం
        balance += amount
        return f"Deposited Rs.{amount} | Current Balance: Rs.{balance}"
        
    return deposit

# మనకోసం ఒక అకౌంట్ క్రియేట్ చేద్దాం:
my_account = create_bank_account(1000)
print(my_account(500))
print(my_account(250))
🔍 Closure లాభం ఏంటి?:

balance అనే వేరియబుల్ బయటికి ఎవరికీ కనపడదు, కానీ my_account దగ్గర మాత్రం అది మెమరీలో బతికే ఉంటుంది. సెక్యూరిటీ కోసం క్లాసెస్ బదులు ఇది వాడతారు.

4Pure Functions vs Side Effects

Pure Function (స్వచ్ఛమైన ఫంక్షన్) అంటే ఏంటంటే:

  1. దానికి ఇచ్చిన ఆర్గ్యుమెంట్స్ కి ఎప్పుడూ ఒకటే కరెక్ట్ రిజల్ట్ ఇస్తుంది (గెస్ చేయొచ్చు).
  2. బయట ఉన్న గ్లోబల్ వేరియబుల్స్ ని మార్చదు (జీరో Side effects).
💻 Example 4: Impure vs Pure Functions
Python 3 ▶ Run in Compiler 
# ❌ IMPURE FUNCTION (బయట ఉన్నదాన్ని మారుస్తుంది కాబట్టి ఇది ఇంప్యూర్):
total_sales = 0
def add_sale_impure(amount):
    global total_sales
    total_sales += amount
    return total_sales

# ✅ PURE FUNCTION (కేవలం ఇచ్చినవి కూడి వెనక్కి ఇస్తుంది, బయటివి ఏమీ ముట్టుకోదు):
def calculate_sale_pure(current_total, new_amount):
    return current_total + new_amount

print("Pure Result 1:", calculate_sale_pure(100, 50)) # ఎప్పుడూ 150
print("Pure Result 2:", calculate_sale_pure(100, 50)) # ఎప్పుడైనా 150!
🔍 Pure అయితే లాభం ఏంటి?:

ఇవి చాలా సేఫ్. కోడ్ లో ఎర్రర్స్ (బగ్స్) రావు. ఏ ఇన్పుట్ కి ఏ అవుట్పుట్ వస్తుందో టెస్ట్ చేయడం చాలా ఈజీ.

5Practical Project 3: కరెన్సీ (Currency) కన్వర్టర్

Pure Functions వాడుకుంటూ ఒక దేశ కరెన్సీ నుండి ఇంకో దేశానికి మార్చే క్యాలిక్యులేటర్ తయారు చేద్దాం:

💻 Example 5: Currency Converter Project
Python 3 ▶ Run in Compiler 
# Dynamic Currency Converter

# ఒక డాలర్ తో మిగతా దేశాల రేట్లు (USD నే బేస్)
EXCHANGE_RATES = {
    "USD": 1.00,
    "INR": 86.50,
    "EUR": 0.92,
    "GBP": 0.79,
    "JPY": 152.00
}

def convert_currency(amount, from_curr, to_curr):
    """Pure ఫంక్షన్ వాడి ఒక కరెన్సీ నుండి ఇంకో దానికి మారుద్దాం."""
    from_rate = EXCHANGE_RATES.get(from_curr.upper())
    to_rate = EXCHANGE_RATES.get(to_curr.upper())
    
    if not from_rate or not to_rate:
        return None, "❌ Invalid Currency Code!"
        
    # ముందుగా ఎంత ఇచ్చినా దాన్ని బేస్ (USD) కి మార్చి, తర్వాత టార్గెట్ కి మార్చాలి
    amount_in_usd = amount / from_rate
    converted_amount = amount_in_usd * to_rate
    return round(converted_amount, 2), f"1 {from_curr} = {to_rate/from_rate:.4f} {to_curr}"

# టెస్ట్ చేద్దాం:
amt_inr, rate_info = convert_currency(100, "USD", "INR")
print(f"💲 100 USD = Rs.{amt_inr} INR ({rate_info})")

amt_eur, rate_info2 = convert_currency(5000, "INR", "EUR")
print(f"💶 5000 INR = €{amt_eur} EUR ({rate_info2})")
🔍 లాజిక్:

ప్రతి కరెన్సీకి ఒకదానితో ఒకటి (INR తో EUR) రేట్లు రాయకుండా, మధ్యలో ఒక బేస్ (USD) ని పెట్టుకోవడం వల్ల లాజిక్ సింపుల్ అయ్యింది!

⚠️ Common Developer Pitfall: గ్లోబల్ ని ముందే వాడి, మళ్ళీ అసైన్ చేయడం (UnboundLocalError)

ఒక ఫంక్షన్ లోపల x ని ఒక లైన్ లో ప్రింట్ చేసి, తర్వాతి లైన్ లో x = 20 అని మారిస్తే UnboundLocalError వస్తుంది. ఒకవేళ మారిస్తే ముందుగానే "global x" అని పెట్టాలి.

💻 Hands-on Interactive Practice Challenge

ఒక ఫంక్షన్ convert_distance(value, from_unit, to_unit) రాసి కిలోమీటర్లు, మీటర్లు, మరియు మైల్స్ మార్చేలా ట్రై చేయండి.

Python 3 Practice Challenge ▶ Run in Compiler 
def convert_distance(val, from_unit, to_unit):
    to_meters = {"km": 1000, "meters": 1, "miles": 1609.34}
    
    meters = val * to_meters[from_unit]
    result = meters / to_meters[to_unit]
    return round(result, 2)

print("5 km in miles:", convert_distance(5, "km", "miles"), "miles")
print("10 miles in km:", convert_distance(10, "miles", "km"), "km")

❓ Frequently Asked Questions (FAQ)

Q LEGB లో B అంటే ఏంటి?

B అంటే Built-in. మీరు రాయకపోయినా పైథాన్ లో ముందే ఉండే print(), len(), sum() లాంటి ఫంక్షన్స్ ఇవన్నీ.

Q global కి nonlocal కి తేడా ఏంటి?

global అంటే ఫైల్ లో ఎక్కడో పైన రాసినదాన్ని వాడటానికి. nonlocal అంటే ఒక ఫంక్షన్ లోపల ఉన్న ఇంకో ఫంక్షన్ లోంచి దాని పేరెంట్ ఫంక్షన్ వేరియబుల్స్ వాడటానికి.
