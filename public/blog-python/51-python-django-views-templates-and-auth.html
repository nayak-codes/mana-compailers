Django Views, Forms & Auth (తెలుగులో)

🐍 Python 3.12+ 🟢 Chapter 51 of 65 📂 Phase 10: Web Development 📅 2026 Edition
📌 Covered in this chapter: URL Dispatcher (path, include) · FBVs vs CBVs · Django Template Language (DTL) · ModelForms · django.contrib.auth · @login_required Decorator
బ్రౌజర్ నుంచి వచ్చే లింక్స్ ని (URLs) జాంగో ఎలా కంట్రోల్ చేస్తుంది? ఫారమ్స్ ని ఆటోమాటిక్ గా ఎలా తయారు చేస్తుంది? జాంగో లో డీఫాల్ట్ గా వచ్చే సేఫ్ లాగిన్ సిస్టమ్ ని ఎలా వాడాలో నేర్చుకుందాం.
1URLs మరియు Views (లాజిక్ ఎక్కడ రాయాలి?)

జాంగో లో ఎవరైనా ఒక లింక్ ని ఓపెన్ చేస్తే, ఫస్ట్ అది urls.py కి వెళుతుంది. అక్కడ ఆ లింక్ కి ఏ ఫంక్షన్ రన్ అవ్వాలో రాసి ఉంటుంది. ఆ ఫంక్షన్ నే View అంటారు (దీన్ని views.py లో రాస్తాం).

Views లో రెండు రకాలు:

  • Function-Based Views (FBVs): ఇవి నార్మల్ పైథాన్ ఫంక్షన్స్ లాగా ఉంటాయి. చూడ్డానికి ఈజీగా అర్థమవుతాయి.
  • Class-Based Views (CBVs): ఫంక్షన్ బదులు క్లాస్ రాస్తాం. ఒకే కోడ్ ని మళ్ళీ మళ్ళీ రాయకుండా (Inheritance) జాంగో మనకు ముందే కొన్ని రెడీమేడ్ క్లాసెస్ (ListView, DetailView) ఇస్తుంది.
💻 Example 1: Django URL Routing, FBVs and Generic CBVs
Python 3 ▶ Run in Compiler 
# 1. లింక్స్ ఎక్కడికి వెళ్లాలో చెప్దాం (store_app/urls.py):
from django.urls import path
from . import views

urlpatterns = [
    # మెయిన్ పేజీ (Products List)
    path("", views.product_list_view, name="product_list"),
    # ఒక ప్రోడక్ట్ డీటెయిల్స్ పేజీ (ఉదా: /5/ ఓపెన్ చేస్తే)
    path("/", views.product_detail_view, name="product_detail"),
    # కొత్త ప్రోడక్ట్ యాడ్ చేయడానికి (CBV)
    path("create/", views.ProductCreateView.as_view(), name="product_create"),
]

# 2. లాజిక్ రాద్దాం (store_app/views.py):
from django.shortcuts import render, get_object_or_404
from django.views.generic import CreateView
from .models import Product

# FBV - ఫంక్షన్ బేస్డ్ వ్యూ (అన్ని ప్రోడక్ట్స్ చూపించడానికి):
def product_list_view(request):
    products = Product.objects.filter(is_active=True)
    context = {"products": products, "page_title": "మన ప్రోడక్ట్స్"}
    return render(request, "store/product_list.html", context)

# FBV - ఒక్క ప్రోడక్ట్ చూపించడానికి:
def product_detail_view(request, product_id):
    # ఒకవేళ తప్పు ఐడీ ఇస్తే, ఆటోమాటిక్ గా 404 ఎర్రర్ చూపిస్తుంది!
    product = get_object_or_404(Product, id=product_id)
    return render(request, "store/product_detail.html", {"product": product})

# CBV - క్లాస్ బేస్డ్ వ్యూ (కొత్త ప్రోడక్ట్ క్రియేట్ చేయడానికి):
class ProductCreateView(CreateView):
    model = Product
    fields = ["title", "category", "price", "stock"]
    template_name = "store/product_form.html"
    success_url = "/"  # అయిపోయాక హోమ్ కి వెళ్ళిపోవాలి
🔍 get_object_or_404 సూపర్ పవర్:

డేటాబేస్ లో లేని ఐడీ ని వెతికితే కోడ్ క్రాష్ అవుతుంది. అలా అవ్వకుండా, get_object_or_404 వాడితే... ఐడీ లేకపోతే యూజర్ కి నీట్ గా "404 Not Found" పేజీ చూపిస్తుంది.

2ModelForms & యూజర్ లాగిన్ (Authentication)

జాంగో లో మనకు యూజర్స్ ని మేనేజ్ చేయడానికి django.contrib.auth అనే సూపర్ సిస్టమ్ డీఫాల్ట్ గా వస్తుంది (పాస్వర్డ్ హ్యాషింగ్, లాగిన్, లాగ్ ఔట్ అన్నీ ఉంటాయి).

ModelForms మ్యాజిక్:

HTML లో ఫారమ్ రాయాలంటే ప్రతి బాక్స్ కి కోడ్ రాయాలి (input type text...). కానీ జాంగో లో ModelForm వాడితే, మన డేటాబేస్ టేబుల్ ని బట్టి అదే ఆటోమాటిక్ గా ఫారమ్ ని, ఎర్రర్ మెసేజెస్ ని తయారు చేసేస్తుంది!

💻 Example 2: Django ModelForms & @login_required Protected View
Python 3 ▶ Run in Compiler 
# 1. ఫారమ్ క్రియేట్ చేద్దాం (store_app/forms.py):
from django import forms
from .models import Product

class ProductForm(forms.ModelForm):
    class Meta:
        model = Product
        fields = ["title", "category", "price", "stock"]

# 2. వ్యూ లో లాగిన్ చెకింగ్ అండ్ ఫారమ్ వాడటం (store_app/views.py):
from django.contrib.auth.decorators import login_required
from django.shortcuts import redirect, render
from .forms import ProductForm

# ఈ పేజీ ఓపెన్ చేయాలంటే లాగిన్ అయి ఉండాలి అని చెప్తున్నాం:
@login_required(login_url="/accounts/login/")
def create_product_view(request):
    if request.method == "POST":
        # సబ్మిట్ చేసిన డేటాని ఫారమ్ కి ఇస్తున్నాం
        form = ProductForm(request.POST)
        
        # డేటా కరెక్ట్ గా ఉందా లేదా చెక్ చేస్తుంది (Validates)
        if form.is_valid(): 
            product = form.save() # ఆటోమాటిక్ గా డేటాబేస్ లో సేవ్ చేసేస్తుంది!
            return redirect("product_detail", product_id=product.id)
    else:
        # ఫస్ట్ టైమ్ ఓపెన్ చేసినప్పుడు ఖాళీ ఫారమ్ చూపిస్తాం
        form = ProductForm()

    return render(request, "store/product_form.html", {"form": form})
🔍 form.is_valid() సేఫ్టీ:

యూజర్ ప్రైస్ దగ్గర "Free" అని అక్షరాలు ఇస్తే, is_valid() దాన్ని పసిగట్టి డేటాబేస్ లో సేవ్ చేయనివ్వదు. ఆటోమాటిక్ గా "దయచేసి నెంబర్ మాత్రమే ఇవ్వండి" అని ఎర్రర్ చూపిస్తుంది.

⚠️ Common Developer Pitfall: HTML ఫారమ్ లో {% csrf_token %} మర్చిపోవడం

జాంగో లో ఏ ఫారమ్ సబ్మిట్ చేయాలన్నా, కచ్చితంగా ఆ ఫారమ్ లోపల {% csrf_token %} అని రాయాలి. లేకపోతే సబ్మిట్ నొక్కగానే "403 Forbidden" ఎర్రర్ వస్తుంది. ఇది హ్యాకర్స్ మన ఫారమ్స్ ని వాడకుండా ఆపడానికి వాడే ఒక సెక్యూరిటీ టోకెన్.

💻 Hands-on Interactive Practice Challenge

@login_required ఎలా పనిచేస్తుందో సిమ్యులేట్ చేద్దాం. యూజర్ ఆబ్జెక్ట్ లో is_authenticated ట్రూ ఉంటేనే లోపలికి పంపే ఫంక్షన్ రాయండి.

Python 3 Practice Challenge ▶ Run in Compiler 
class User:
    def __init__(self, name, logged_in):
        self.name = name
        self.is_authenticated = logged_in

def protect_dashboard(user):
    if not user.is_authenticated:
        return "🛑 ఆపండి: ముందు లాగిన్ పేజీకి వెళ్ళండి (/login)"
    return f"✅ వెల్కమ్! మీ డ్యాష్ బోర్డు ఓపెన్ అయ్యింది, {user.name}."

print(protect_dashboard(User("Guest", False)))
print(protect_dashboard(User("Balaji", True)))

❓ Frequently Asked Questions (FAQ)

Q authenticate() కి, login() కి డిఫరెన్స్ ఏంటి?

authenticate(user, pass) అనేది యూజర్ నేమ్, పాస్వర్డ్ కరెక్టో కాదో చెక్ చేస్తుంది అంతే. లాగిన్ అవ్వరు. login(request, user) అనేది ఆ యూజర్ ని సెషన్ లోకి యాడ్ చేసి లాగిన్ చేస్తుంది.

Q నేను డీఫాల్ట్ User టేబుల్ ని మార్చొచ్చా?

మార్చొచ్చు! మీ ప్రాజెక్ట్ స్టార్ట్ చేసినప్పుడే AbstractUser ని వాడి మీకు నచ్చిన CustomUser (ఉదా: phone_number కాలమ్ యాడ్ చేసి) తయారు చేసుకోవడం చాలా బెస్ట్ ప్రాక్టీస్.
