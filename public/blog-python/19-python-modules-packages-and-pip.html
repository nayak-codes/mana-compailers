మీరు ఒక పూర్తి స్థాయి వెబ్ అప్లికేషన్, ఆర్టిఫిషియల్ ఇంటెలిజెన్స్ మోడల్ లేదా డేటాబేస్ ఇంజిన్‌ను నిర్మిస్తున్నప్పుడు — వేల లైన్ల కోడ్‌ను ఒకే ఒక్క main.py ఫైల్‌లో కుక్కడం ఆత్మహత్యతో సమానం. ఒక పెద్ద సాఫ్ట్‌వేర్ ఆర్కిటెక్చర్‌లో డేటాబేస్ కనెక్షన్లు ఒకచోట, బిజినెస్ లాజిక్ ఒకచోట, యూజర్ ఇంటర్‌ఫేస్ మరొకచోట విడివిడిగా అమర్చబడాలి.

1 మాడ్యూల్ అంటే ఏమిటి? (What is a Python Module?)

పైథాన్‌లో మాడ్యూల్ (Module) అనేది పైథాన్ కోడ్ (ఫంక్షన్లు, క్లాస్‌లు, వేరియబుల్స్) కలిగిన ఏదైనా ఒక సాధారణ .py ఫైల్!

ఉదాహరణకు, మీరు calculator.py అనే ఫైల్‌ను సృష్టిస్తే, అది తక్షణమే ఒక మాడ్యూల్ అవుతుంది. దానిలోని ఫంక్షన్లను వేరే ఫైల్ నుండి import calculator అని రాసి నిశ్చింతగా ఉపయోగించుకోవచ్చు.

  • నేమ్‌స్పేస్ ఐసోలేషన్ (Namespace Isolation): ఒక మాడ్యూల్‌లోని వేరియబుల్స్ మరొక మాడ్యూల్‌లోని వేరియబుల్స్‌తో ఘర్షణ పడకుండా (Name Collisions రాకుండా) పైథాన్ ప్రతి మాడ్యూల్‌కు ప్రత్యేకమైన నేమ్‌స్పేస్‌ను కేటాయిస్తుంది.
  • కోడ్ రీ-యూజబిలిటీ: ఒకసారి రాసిన లైబ్రరీ కోడ్‌ను వందలాది ప్రాజెక్టులలో ఇంపోర్ట్ చేసుకోవచ్చు.

3 Import సింటాక్స్ వైవిధ్యాలు (Variants & Best Practices)

పైథాన్‌లో మాడ్యూల్స్ ఇంపోర్ట్ చేయడానికి నాలుగు ప్రధాన పద్ధతులు ఉన్నాయి:

  • 1. import module_name: అత్యంత సురక్షితమైనది. ఫంక్షన్లను పిలిచేటప్పుడు module_name.func() అని స్పష్టంగా మాడ్యూల్ పేరుతో పిలుస్తాము: import math; print(math.sqrt(16))
  • 2. from module_name import func1, func2: నిర్దిష్టమైన ఫంక్షన్లను నేరుగా మన కరెంట్ నేమ్‌స్పేస్‌లోకి తెస్తుంది: from math import sqrt, pi; print(sqrt(25))
  • 3. import module_name as alias: మాడ్యూల్ పేరు పెద్దదిగా ఉన్నప్పుడు నిక్-నేమ్ (అలియాస్) ఇవ్వడం (డేటా సైన్స్‌లో పరిశ్రమ ప్రమాణం): import numpy as np; import pandas as pd
  • 4. from module_name import * (⚠️ డేంజరస్ యాంటీ-ప్యాటర్న్): ఆ మాడ్యూల్‌లోని అన్ని ఫంక్షన్లను ఒకేసారి గుడ్డిగా తెస్తుంది. దీనివల్ల మన వేరియబుల్స్ ఓవర్‌రైట్ అయిపోయి తీవ్రమైన బగ్‌లు వస్తాయి. ప్రొడక్షన్ కోడ్‌లో దీనిని ఎట్టి పరిస్థితుల్లోనూ వాడకూడదు!

4 కస్టమ్ మాడ్యూల్స్ సృష్టి & లోకల్ ఇంపోర్ట్స్

ఒక కస్టమ్ మాడ్యూల్ ఎలా తయారు చేయాలో చూద్దాం. మీ ప్రాజెక్ట్ ఫోల్డర్‌లో string_utils.py అనే ఫైల్‌ను సృష్టించి అందులో ఫంక్షన్స్ రాసి, ప్రధాన అప్లికేషన్‌లో ఎలా ఇంపోర్ట్ చేయాలో క్రింది కోడ్‌లో చూడండి:

string_utils_and_usage.py 
# =====================================================================
# కస్టమ్ మాడ్యూల్ ఫంక్షన్ల డెమో: string_utils లాజిక్
# =====================================================================

def to_url_slug(title: str) -> str:
    """ఒక ఆర్టికల్ శీర్షికను SEO-ఫ్రెండ్లీ URL స్లగ్‌గా మారుస్తుంది."""
    clean = "".join([c.lower() if c.isalnum() or c == " " else "" for c in title])
    return "-".join(clean.split())

def mask_sensitive_aadhaar(aadhaar_num: str) -> str:
    """ఆధార్ నంబర్‌లోని మొదటి 8 అంకెలను మాస్క్ చేస్తుంది (xxxx-xxxx-1234)."""
    digits = aadhaar_num.replace("-", "").replace(" ", "")
    if len(digits) != 12:
        return "తప్పుడు ఆధార్ నంబర్!"
    return f"XXXX-XXXX-{digits[-4:]}"

# ప్రధాన స్క్రిప్ట్‌లో దీనిని వాడుకోవడం:
blog_title = "Python 3 టుటోరియల్స్ ఇన్ తెలుగు 2026!"
user_aadhaar = "1234-5678-9012"

print("SEO స్లగ్    :", to_url_slug(blog_title))
print("మాస్క్డ్ ఆధార్ :", mask_sensitive_aadhaar(user_aadhaar))

5 The Infamous if __name__ == '__main__': గార్డ్‌రైల్

పైథాన్ ప్రోగ్రామర్లు ప్రతి ఫైల్ చివర రాసే if __name__ == '__main__': వెనుక ఉన్న లోతైన రహస్యం ఏమిటో తెలుసా?

పైథాన్ ఒక ఫైల్‌ను రన్ చేస్తున్నప్పుడు, దానికి స్వయంచాలకంగా __name__ అనే ప్రత్యేకమైన వేరియబుల్‌ను కేటాయిస్తుంది:

  • నేరుగా రన్ చేసినప్పుడు: మీరు టెర్మినల్ నుండి python my_script.py అని ఫైల్‌ను నేరుగా రన్ చేస్తే, పైథాన్ దాని __name__ విలువను '__main__' గా సెట్ చేస్తుంది.
  • మరొక ఫైల్‌లోకి ఇంపోర్ట్ అయినప్పుడు: ఎవరైనా import my_script అని ఇంపోర్ట్ చేసుకుంటే, దాని __name__ విలువ ఆ ఫైల్ పేరు 'my_script' గా మారుతుంది!
గార్డ్‌రైల్ ప్రయోజనం: మీరు రాసిన మాడ్యూల్‌లో టెస్ట్ కోడ్ ఉందనుకోండి. ఆ ఫైల్‌ను వేరేవాళ్ళు ఇంపోర్ట్ చేసుకున్నప్పుడు ఆ టెస్ట్ కోడ్ రన్ కాకుండా కేవలం ఫైల్‌ను నేరుగా రన్ చేసినప్పుడు మాత్రమే ఎగ్జిక్యూట్ అవ్వడానికి ఈ గార్డ్‌రైల్ రక్షణ కల్పిస్తుంది!

6 ప్యాకేజీలు అంటే ఏమిటి? (Packages & __init__.py)

మాడ్యూల్ అనేది ఒక సింగిల్ ఫైల్ అయితే, ప్యాకేజీ (Package) అనేది అనేక మాడ్యూల్స్‌ను కలిగి ఉండే ఒక డైరెక్టరీ (ఫోల్డర్)!

ఒక ఫోల్డర్‌ను పైథాన్ అధికారిక ప్యాకేజీగా గుర్తించాలంటే అందులో సాంప్రదాయకంగా __init__.py అనే ప్రత్యేక ఫైల్ ఉండాలి.

my_ecommerce_app/
│── main.py
└── store/ # Package Directory
    ├── __init__.py # ప్యాకేజీ మార్కర్ & ఇనిషియలైజర్
    ├── products.py # Module 1
    ├── orders.py # Module 2
    └── billing.py # Module 3

పైథాన్ 3.3+ నుండి __init__.py లేకపోయినా Namespace Packages సపోర్ట్ ఉన్నప్పటికీ, ప్యాకేజీ ఎక్స్‌పోర్ట్‌లను (__all__) నియంత్రించడానికి మరియు ప్రారంభ లాజిక్ రన్ చేయడానికి __init__.py ఉంచడం నేటికీ బెస్ట్ ప్రాక్టీస్.

11 ఆధునిక పైథాన్ టూలింగ్ (Poetry, UV, Pipenv)

ఆధునిక క్లౌడ్ నేటివ్ డెవలప్‌మెంట్‌లో సాధారణ pip కాకుండా వేగవంతమైన ప్యాకేజీ మేనేజర్లు ప్రాచుర్యం పొందాయి:

  • UV (Astral): రస్ట్ (Rust) లో రాయబడిన అత్యంత వేగవంతమైన ప్యాకేజీ మేనేజర్. pip కంటే 10-100 రెట్లు వేగంగా లైబ్రరీలను ఇన్‌స్టాల్ చేస్తుంది.
  • Poetry: డిపెండెన్సీ లాకింగ్ (poetry.lock) మరియు ప్రాజెక్ట్ ప్యాకేజింగ్ కోసం పరిశ్రమ ప్రామాణిక టూల్.

12 కామన్ బిగినర్స్ మిస్టేక్స్ & మాడ్యూల్ షాడోయింగ్ ట్రాప్

  • The File Name Shadowing Trap (ప్రమాదకరమైన తప్పు!): మీ ప్రాక్టీస్ స్క్రిప్ట్‌కు math.py, random.py, లేదా email.py అని పేరు పెట్టి, లోపల import math అని రాస్తే — పైథాన్ స్టాండర్డ్ లైబ్రరీని కాకుండా మీ ఫైల్‌నే ఇంపోర్ట్ చేసుకుంటుంది! ఫలితంగా AttributeError: module 'math' has no attribute 'sqrt' వచ్చి ప్రోగ్రామ్ క్రాష్ అవుతుంది! మీ ఫైళ్లకు ఎప్పుడూ పైథాన్ లైబ్రరీ పేర్లను పెట్టకండి.
  • Circular Imports బగ్: File A File B ని, File B File A ని ఇంపోర్ట్ చేసుకోవడం వల్ల వచ్చే డెడ్‌లాక్ ఎర్రర్. దీనిని నివారించడానికి షేర్డ్ లాజిక్‌ను ఒక మూడవ ఫైల్ common.py లోకి తరలించాలి.
  • వర్చువల్ ఎన్విరాన్‌మెంట్ యాక్టివేట్ చేయకుండా ఇన్‌స్టాల్ చేయడం: గ్లోబల్ మెషీన్‌లో లైబ్రరీలను కుక్కేయడం వల్ల పర్మిషన్ ఎర్రర్లు మరియు డిపెండెన్సీ గందరగోళం ఏర్పడుతుంది.

13 రియల్-వరల్డ్ ప్రాజెక్ట్: "Package Dependency Security & Vulnerability Auditor"

ఈ పంతొమ్మిదవ అధ్యాయంలో నేర్చుకున్న అన్ని అంశాలను (మాడ్యూల్స్, ప్యాకేజీలు, __name__ గార్డ్‌రైల్, sys.path, requirements.txt పార్సింగ్) సమగ్రంగా అనుసంధానిస్తూ — సాఫ్ట్‌వేర్ డిపెండెన్సీలలో కాలం చెల్లిన లేదా ప్రమాదకరమైన లైబ్రరీలను గుర్తించే పూర్తి స్థాయి Enterprise Package Security Auditor Engine ను నిర్మిద్దాం!

02_package_security_auditor.py 
# =====================================================================
# చాప్టర్ 19 మినీ ప్రాజెక్ట్: Package Security & Dependency Audit Engine
# కాన్సెప్ట్స్: Custom Modules Architecture, __name__ == '__main__' Guard,
#             requirements.txt Parsing, Vulnerability Advisory Matching
# =====================================================================

# తెలిసిన సెక్యూరిటీ వల్నరబిలిటీస్ గ్లోబల్ డేటాబేస్ (CVE Advisory Mock)
KNOWN_VULNERABLE_PACKAGES = {
    "requests": {"vulnerable_below": "2.31.0", "cve": "CVE-2023-32681", "risk": "CRITICAL"},
    "flask": {"vulnerable_below": "2.2.5", "cve": "CVE-2023-30861", "risk": "HIGH"},
    "urllib3": {"vulnerable_below": "1.26.17", "cve": "CVE-2023-43804", "risk": "MEDIUM"},
    "django": {"vulnerable_below": "4.2.4", "cve": "CVE-2023-36053", "risk": "CRITICAL"}
}

def parse_requirements_manifest(manifest_content: str) -> list[tuple[str, str]]:
    """requirements.txt టెక్స్ట్ ఫైల్‌ను పార్స్ చేసి (ప్యాకేజీ, వెర్షన్) టుపుల్స్‌గా అందిస్తుంది."""
    parsed_packages = []
    lines = manifest_content.strip().split("\n")

    for line in lines:
        line = line.strip()
        if not line or line.startswith("#"):
            continue
        if "==" in line:
            pkg, ver = line.split("==")
            parsed_packages.append((pkg.strip().lower(), ver.strip()))
        elif ">=" in line:
            pkg, ver = line.split(">=")
            parsed_packages.append((pkg.strip().lower(), ver.strip()))

    return parsed_packages

def audit_project_dependencies(dependencies: list[tuple[str, str]]) -> dict:
    """డిపెండెన్సీలను సెక్యూరిటీ డేటాబేస్‌తో పోల్చి సమగ్ర నివేదికను ఇస్తుంది."""
    findings = []
    clean_count = 0

    for pkg_name, installed_ver in dependencies:
        if pkg_name in KNOWN_VULNERABLE_PACKAGES:
            advisory = KNOWN_VULNERABLE_PACKAGES[pkg_name]
            # సాధారణ వెర్షన్ కంపారిజన్
            if installed_ver < advisory["vulnerable_below"]:
                findings.append({
                    "package": pkg_name,
                    "installed": installed_ver,
                    "safe_version": advisory["vulnerable_below"],
                    "cve": advisory["cve"],
                    "risk": advisory["risk"]
                })
            else:
                clean_count += 1
        else:
            clean_count += 1

    return {
        "total_audited": len(dependencies),
        "clean_packages": clean_count,
        "vulnerable_packages": findings
    }

def print_security_audit_report(report: dict):
    """అందమైన సెక్యూరిటీ ఆడిట్ రిపోర్ట్ కన్సోల్ ప్రింటింగ్."""
    print("\n" + "=" * 74)
    print(f"{'🛡️ మన సాఫ్ట్‌వేర్ — పైథాన్ ప్యాకేజీ సెక్యూరిటీ ఆడిట్ రిపోర్ట్ 2026':^74}")
    print("=" * 74)
    print(f"మొత్తం ఆడిట్ చేసిన లైబ్రరీలు : {report['total_audited']}")
    print(f"సురక్షితమైన ప్యాకేజీలు       : {report['clean_packages']}")
    print(f"గుర్తించిన సెక్యూరిటీ లోపాలు : {len(report['vulnerable_packages'])}")
    print("-" * 74)

    if not report["vulnerable_packages"]:
        print("  🎉 అభినందనలు! ఎటువంటి సెక్యూరిటీ లోపాలు కనుగొనబడలేదు. అన్నీ సురక్షితం!")
    else:
        print(f"{'ప్యాకేజీ':<14} {'ఇన్‌స్టాల్ వెర్షన్':<18} {'సేఫ్ వెర్షన్':<16} {'CVE ఐడీ':<16} {'తీవ్రత':^10}")
        print("-" * 74)
        for issue in report["vulnerable_packages"]:
            risk_badge = "🔴 CRITICAL" if issue["risk"] == "CRITICAL" else "🟡 " + issue["risk"]
            print(f"{issue['package']:<14} {issue['installed']:<18} {issue['safe_version']:<16} {issue['cve']:<16} {risk_badge}")

    print("=" * 74)
    print(f"{'👉 తక్షణ చర్య: pip install --upgrade [package] ద్వారా సురక్షిత వెర్షన్‌కు మారండి!':^74}")
    print("=" * 74 + "\n")

# ఆడిట్ డెమో ఎగ్జిక్యూషన్
sample_requirements_file = """
# ప్రొడక్షన్ మైక్రోసర్వీస్ డిపెండెన్సీలు

సమాధానం: ఒక పైథాన్ స్క్రిప్ట్‌ను టెర్మినల్ నుండి నేరుగా రన్ చేసినప్పుడు మాత్రమే ఆ బ్లాక్ లోపలి కోడ్ ఎగ్జిక్యూట్ అయ్యేలా చూస్తుంది. వేరే ఫైల్ నుండి ఆ మాడ్యూల్‌ను ఇంపోర్ట్ చేసుకున్నప్పుడు ఆ టెస్ట్ కోడ్ లేదా స్క్రిప్ట్ రన్ కాకుండా నివారిస్తుంది.
2. CPython ఒక మాడ్యూల్‌ను వెతకడానికి sys.path లో ఏ క్రమాన్ని పాటిస్తుంది?
సమాధానం: 1. ప్రస్తుత వర్కింగ్ డైరెక్టరీ (Current Script Directory). 2. PYTHONPATH ఎన్విరాన్‌మెంట్ వేరియబుల్. 3. పైథాన్ స్టాండర్డ్ లైబ్రరీ డైరెక్టరీ. 4. థర్డ్ పార్టీ ప్యాకేజీలు ఉన్న site-packages డైరెక్టరీ.
3. మీ ఫైల్‌కు math.py అని పేరు పెట్టడం ఎందుకు ప్రమాదకరం?
సమాధానం: sys.path లో ప్రస్తుత డైరెక్టరీ మొదటి స్థానంలో ఉంటుంది. అందువల్ల import math అన్నప్పుడు పైథాన్ స్టాండర్డ్ లైబ్రరీకి బదులుగా మీ లోకల్ ఫైల్‌నే ఇంపోర్ట్ చేసుకుంటుంది (Module Shadowing). ఫలితంగా math.sqrt() వంటి ఒరిజినల్ ఫంక్షన్లు పనిచేయక ఎర్రర్ వస్తుంది.
4. వర్చువల్ ఎన్విరాన్‌మెంట్ (venv) వాడకపోతే వచ్చే నష్టం ఏమిటి?
సమాధానం: అన్ని లైబ్రరీలు గ్లోబల్ పైథాన్‌లో ఇన్‌స్టాల్ అవుతాయి. వేర్వేరు ప్రాజెక్టులకు వేర్వేరు వెర్షన్లు అవసరమైనప్పుడు డిపెండెన్సీ కాన్‌ఫ్లిక్ట్‌లు (Dependency Conflicts) ఏర్పడి ఒక ప్రాజెక్ట్ నడవడానికి మరొక ప్రాజెక్ట్ క్రాష్ అయ్యే ప్రమాదం ఉంది.
5. requirements.txt ఫైల్ ఎలా తయారు చేయాలి మరియు ఎలా ఇన్‌స్టాల్ చేయాలి?
సమాధానం: pip freeze > requirements.txt కమాండ్ ద్వారా ప్రస్తుత ఎన్విరాన్‌మెంట్‌లోని అన్ని ప్యాకేజీలు మరియు వాటి వెర్షన్లను ఫైల్‌లో సేవ్ చేయవచ్చు. కొత్త కంప్యూటర్‌లో pip install -r requirements.txt ద్వారా వాటన్నింటినీ ఒకేసారి ఇన్‌స్టాల్ చేయవచ్చు.
