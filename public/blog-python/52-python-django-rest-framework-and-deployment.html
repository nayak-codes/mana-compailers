Django REST Framework (DRF) & Deploy (తెలుగులో)

🐍 Python 3.12+ 🟢 Chapter 52 of 65 📂 Phase 10: Web Development 📅 2026 Edition
📌 Covered in this chapter: What is DRF? · Serializers & ModelSerializers · ViewSets & Routers · Token Authentication · Production Stack (Gunicorn, Nginx, WhiteNoise, Environment Variables)
జాంగో తో మొబైల్ యాప్స్ కి, రియాక్ట్ యాప్స్ కి API ని (JSON డేటా) ఎలా పంపించాలి? (DRF గురించి). అలాగే మనం చేసిన వెబ్సైట్ ని పబ్లిక్ గా ఇంటర్నెట్ లో (Production) ఎలా డిప్లాయ్ చేయాలో నేర్చుకుందాం.
1Django REST Framework (DRF) అంటే ఏంటి? (Serializers & ViewSets)

జాంగో మామూలుగా HTML పేజీలని ఇస్తుంది. కానీ మనకు రియాక్ట్ (React) యాప్ లేదా మొబైల్ యాప్ కి కేవలం డేటా (JSON) మాత్రమే కావాలి. దానికోసం వాడే ఒక పవర్ఫుల్ టూల్ పేరే Django REST Framework (DRF).

DRF లో 3 ముఖ్యమైన కాన్సెప్ట్స్:

  1. Serializers (సీరియలైజర్స్): ఇవి మన డేటాబేస్ ఆబ్జెక్ట్స్ ని JSON ఫార్మాట్ లోకి మారుస్తాయి. (అలాగే బయటినుంచి వచ్చే JSON డేటాని మళ్ళీ డేటాబేస్ లోకి మారుస్తాయి).
  2. ViewSets (వ్యూసెట్స్): ఒక్క క్లాస్ రాస్తే చాలు.. క్రియేట్, అప్డేట్, డిలీట్, లిస్ట్ ఇలా 5 పనులు అదే చేసేస్తుంది.
  3. Routers (రౌటర్స్): మనం urls.py లో లింక్స్ అన్నీ మాన్యువల్ గా రాయక్కర్లేదు, రౌటర్ దానంతట అదే లింక్స్ ని క్రియేట్ చేస్తుంది!
💻 Example 1: Complete DRF ModelSerializer, ModelViewSet, and DefaultRouter
Python 3 ▶ Run in Compiler 
# 1. Serializer రాద్దాం (api/serializers.py):
from rest_framework import serializers
from store_app.models import Product

class ProductSerializer(serializers.ModelSerializer):
    # కేటగిరీ పేరుని బయటనుంచి చదవడానికి (ReadOnlyField)
    category_name = serializers.ReadOnlyField(source="category.name")

    class Meta:
        model = Product
        fields = ["id", "title", "category_name", "price", "stock", "is_active"]

# 2. ViewSet రాద్దాం (api/views.py):
from rest_framework import viewsets
from .serializers import ProductSerializer

class ProductViewSet(viewsets.ModelViewSet):
    """ఇది ఆటోమాటిక్ గా CRUD ఆపరేషన్స్ అన్నీ ఇస్తుంది!"""
    queryset = Product.objects.filter(is_active=True)
    serializer_class = ProductSerializer

# 3. ఆటోమాటిక్ లింక్స్ కోసం Router వాడదాం (api/urls.py):
from rest_framework.routers import DefaultRouter

router = DefaultRouter()
# /api/products/ అనే లింక్ కి మన వ్యూ ని అటాచ్ చేస్తున్నాం
router.register(r"products", ProductViewSet, basename="product")

urlpatterns = router.urls
🔍 DefaultRouter మ్యాజిక్:

జస్ట్ పైనున్న 3 లైన్స్ రౌటర్ కోడ్ తో... GET /api/products/, POST /api/products/, DELETE /api/products/42/ లాంటి లింక్స్ అన్నీ దానంతట అవే ఆటోమాటిక్ గా తయారైపోతాయి!

2యాప్ ని లైవ్ లో పెట్టడం (Production Deployment & Security)

లోకల్ గా వాడే python manage.py runserver ని ఎట్టి పరిస్థితుల్లోనూ పబ్లిక్ లైవ్ సర్వర్ లో వాడకూడదు. అది చాలా స్లో అండ్ హ్యాక్ చేయడం ఈజీ.

లైవ్ సర్వర్ ఆర్కిటెక్చర్ (ఎలా ఉండాలి?):

  • Gunicorn: ఇది ప్రొడక్షన్ పైథాన్ సర్వర్. ఒకేసారి వందల మంది వచ్చినా హ్యాండిల్ చేస్తుంది.
  • Nginx: ఇది ఫ్రంట్ లో గార్డ్ లాగా ఉండి గూనికోర్న్ కి ట్రాఫిక్ ని పంపుతుంది.
  • WhiteNoise: జాంగో లోని CSS/JS ఫైల్స్ ని చాలా ఫాస్ట్ గా ఇవ్వడానికి దీన్ని వాడతాం.

లైవ్ కి వెళ్ళే ముందు చెక్ లిస్ట్ (settings.py):

  • DEBUG = False: కచ్చితంగా ఇది ఆఫ్ చేయాలి, లేకపోతే ఎర్రర్ వచ్చినప్పుడు మీ సీక్రెట్ కోడ్ బయట పడిపోతుంది.
  • Environment Variables (.env): పాస్వర్డ్స్ ని, డేటాబేస్ లింక్స్ ని settings.py లో డైరెక్ట్ గా రాయకుండా .env ఫైల్ లో దాచిపెట్టి చదవాలి.

# ప్రొడక్షన్ సెట్టింగ్స్ ఎలా ఉండాలో శాంపిల్ (settings.py):
import os
from pathlib import Path

BASE_DIR = Path(__file__).resolve().parent.parent

# 1. సీక్రెట్స్ ని ఎన్విరాన్మెంట్ నుంచి చదువుతున్నాం (కోడ్ లో రాయట్లేదు):
SECRET_KEY = os.getenv("DJANGO_SECRET_KEY", "default-key-not-safe")

# లైవ్ లో DEBUG ఎప్పుడూ False ఉండాలి:
DEBUG = os.getenv("DJANGO_DEBUG", "False") == "True"

# మన వెబ్సైట్ డొమైన్ పేరు ఇక్కడ ఇవ్వాలి (Security కోసం)
ALLOWED_HOSTS = ["mywebsite.com", "127.0.0.1"]

# 2. WhiteNoise యాడ్ చేస్తున్నాం (CSS/JS ఫైల్స్ ఫాస్ట్ గా లోడ్ అవ్వడానికి):
MIDDLEWARE = [
    "django.middleware.security.SecurityMiddleware",
    "whitenoise.middleware.WhiteNoiseMiddleware", # ఇది సెకండ్ లైన్ లో ఉండాలి
    # మిగతావన్నీ...
]

# ఫైల్స్ ఎక్కడ సేవ్ అవ్వాలో చెప్తున్నాం
STATIC_ROOT = BASE_DIR / "staticfiles"
STATICFILES_STORAGE = "whitenoise.storage.CompressedManifestStaticFilesStorage"
🔍 Gunicorn ఎలా రన్ చేయాలి?:

లైవ్ సర్వర్ లోకి వెళ్ళాక రన్ సర్వర్ బదులు.. gunicorn my_project.wsgi:application --workers 4 అని రన్ చేయాలి. (workers అంటే 4 గురు వెయిటర్స్ కింద పని చేస్తున్నట్టు, స్పీడ్ పెరుగుతుంది).

⚠️ Common Developer Pitfall: GitHub లో SECRET_KEY ని కమిట్ చేయడం

మీ settings.py లో ఉన్న SECRET_KEY ని మార్చకుండా అలాగే గిట్ హబ్ పబ్లిక్ లో పెడితే, ఎవరైనా మీ సైట్ లోకి అడ్మిన్ లాగా దూరిపోయి మొత్తం హ్యాక్ చేయగలరు! సీక్రెట్స్ ఎప్పుడూ .env ఫైల్ లో పెట్టి, ఆ ఫైల్ ని .gitignore లో యాడ్ చేయాలి.

ఒక కస్టమ్ వాలిడేషన్ ఫంక్షన్ ని సిమ్యులేట్ చేద్దాం. ప్రైస్ 0 కంటే తక్కువ ఉంటే ValueError ఇచ్చేలా ఒక ఫంక్షన్ రాయండి.

def validate_price(price):
    if price <= 0:
        raise ValueError("ఎర్రర్: ప్రైస్ కచ్చితంగా 0 కంటే ఎక్కువే ఉండాలి!")
    return price

try:
    print("కరెక్ట్ ప్రైస్:  ", validate_price(499.0))
    print("రాంగ్ ప్రైస్: ", validate_price(-10.0))
except ValueError as err:
    print(err)

❓ Frequently Asked Questions (FAQ)

Q JWT (JSON Web Token) ఆథెంటికేషన్ అంటే ఏంటి?

యాప్స్ లో లాగిన్ అయినప్పుడు కుకీస్ కి బదులు ఒక టోకెన్ (కోడ్) ఇస్తారు. ఈ టోకెన్ తోనే యాప్స్ సర్వర్ తో మాట్లాడతాయి. ఇది చాలా ఫాస్ట్ గా ఉంటుంది, సర్వర్ ప్రతిసారీ డేటాబేస్ ని చెక్ చేయక్కర్లేదు.

Q Gunicorn కీ, Uvicorn కీ తేడా ఏంటి?

Gunicorn అనేది ఫ్లాస్క్, జాంగో లాంటి మామూలు (Sync) యాప్స్ కి వాడతారు. Uvicorn అనేది ఫాస్ట్ గా రన్ అయ్యే FastAPI లాంటి (Async) యాప్స్ కి వాడతారు.
