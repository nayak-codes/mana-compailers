OS Automation & Logging (తెలుగులో)

🐍 Python 3.12+ 🟢 Chapter 62 of 65 📂 Phase 12: Automation and Professional Skills 📅 2026 Edition
📌 Covered in this chapter: Automated Directory Organizers · Task Scheduling (schedule) · Production Logging (logging module, RotatingFileHandler) · Config Files (TOML, YAML, .env)
కంప్యూటర్ లో ఫైల్స్ ని ఆటోమాటిక్ గా సర్దడం, ఒక ప్రోగ్రామ్ రోజుకి ఒకసారి ఆటోమాటిక్ గా రన్ అయ్యేలా షెడ్యూల్ చేయడం, ఎర్రర్స్ వస్తే ప్రింట్ చేయకుండా రియల్ ప్రాజెక్ట్స్ లో లాగ్ (Log) ఫైల్స్ లో రాయడం నేర్చుకుందాం.
1ఫైల్స్ ని ఆటోమాటిక్ గా సర్దడం (Smart File Organizer)

మన సిస్టమ్ లో Downloads ఫోల్డర్ ఎప్పుడూ గందరగోళంగా ఉంటుంది. ఏది పిడిఎఫ్, ఏది ఇమేజ్ వెతుక్కోవాలి. పైథాన్ వాడి ఆటోమాటిక్ గా ఆ ఫైల్స్ ని కేటగిరీల వారీగా ఫోల్డర్స్ లోకి మార్చేయొచ్చు!

💻 Example 1: Intelligent File Organizer by Extension Category
Python 3 ▶ Run in Compiler 
# ఇంటెలిజెంట్ ఫైల్ ఆర్గనైజర్:
from pathlib import Path

# ఏ ఫైల్ ఏ ఫోల్డర్ లోకి వెళ్ళాలో రూల్స్:
FILE_CATEGORIES = {
    "Documents (బుక్స్, పత్రాలు)": [".pdf", ".docx", ".txt", ".xlsx"],
    "Images (ఫోటోలు)":           [".jpg", ".png", ".webp", ".svg"],
    "Code (ప్రోగ్రామింగ్)":       [".py", ".js", ".html", ".css"],
    "Videos (వీడియోలు)":         [".mp4", ".mkv"]
}

def check_category(filename):
    # ఫైల్ చివర ఏముందో చూస్తుంది (ఉదా: .pdf)
    ext = Path(filename).suffix.lower()
    for category, extensions in FILE_CATEGORIES.items():
        if ext in extensions:
            return category
    return "Others"

downloads_folder = [
    "Python_Notes.pdf",
    "profile_pic.png",
    "my_script.py",
    "movie_clip.mp4",
    "unknown_file.xyz"
]

print("--- 🗂️ ఆటోమాటిక్ గా ఫైల్స్ ని సర్దుతున్నాం... ---")
for file in downloads_folder:
    folder = check_category(file)
    print(f"• తరలిస్తున్నాం: '{file:18}' ──► 📁 [{folder}/]")
🔍 shutil.move() వాడకం:

అసలు ఫైల్స్ మూవ్ చేయడానికి shutil.move(src, dest) వాడతారు, అంతకంటే ముందు ఆ ఫోల్డర్ ఉందో లేదో చెక్ చేసి క్రియేట్ చేయాలి.

2ప్రొడక్షన్ లో print() వాడకూడదు! (Logging Module వాడుక)

చిన్న కోడ్ రాస్తున్నప్పుడు అవుట్పుట్ కోసం print() వాడతాం. కానీ పెద్ద పెద్ద యాప్స్ లో వాడకూడదు! ఎందుకంటే ప్రింట్ చేస్తే అది స్క్రీన్ మీద కనిపిస్తుంది కానీ సేవ్ అవ్వదు. ఎప్పుడో రాత్రి ఎర్రర్ వస్తే పొద్దున్న చూసుకుందామంటే దొరకదు.

అందుకే Logging వాడుతాం (5 లెవెల్స్):

లెవెల్ఎప్పుడు వాడాలి?
DEBUGమనం కోడ్ టెస్ట్ చేసుకుంటున్నప్పుడు.
INFOప్రతిదీ కరెక్ట్ గా పనిచేస్తుందని రికార్డ్ చేయడానికి.
WARNINGచిన్న ఇబ్బంది (ఉదా: హార్డ్ డిస్క్ ఫుల్ అవుతోంది) వచ్చినప్పుడు.
ERRORఏదైనా తప్పు జరిగినప్పుడు (లాగిన్ ఫెయిల్ అవ్వడం).
CRITICALసర్వర్ ఆగిపోయింది లాంటి డేంజర్ విషయాలకి.
💻 Example 2: Production Structured Logging with Severity Levels
Python 3 ▶ Run in Compiler 
import logging
import sys

# 1. ప్రొఫెషనల్ లాగర్ ని సెటప్ చేయడం:
logger = logging.getLogger("ManaCompilerApp")
logger.setLevel(logging.DEBUG)

# లాగ్స్ ఎలా కనిపించాలి? (టైమ్, లెవెల్, మెసేజ్)
console_handler = logging.StreamHandler(sys.stdout)
formatter = logging.Formatter("[%(asctime)s] [%(levelname)s]: %(message)s", datefmt="%H:%M:%S")
console_handler.setFormatter(formatter)
logger.addHandler(console_handler)

# 2. రకరకాల సిట్యువేషన్స్ లో రికార్డ్ చేయడం:
logger.debug("డేటాబేస్ కి కనెక్ట్ అవుతున్నాం...")
logger.info("డేటాబేస్ కనెక్ట్ అయ్యింది.")
logger.warning("కంప్యూటర్ మెమరీ 80% నిండిపోయింది, చెక్ చేయండి!")
logger.error("యూజర్ పేమెంట్ ఫెయిల్ అయ్యింది (బ్యాంక్ సర్వర్ డౌన్).")
logger.critical("మొత్తం యాప్ క్రాష్ అయ్యింది, వెంటనే రిస్టార్ట్ చేయండి!")
🔍 లాగ్ ఫైల్స్ ఎప్పటికీ పెరగకూడదు:

లాగ్ ఫైల్స్ సేవ్ చేస్తూ పోతే హార్డ్ డిస్క్ ఫుల్ అయిపోతుంది. అందుకే RotatingFileHandler(maxBytes=10MB, backupCount=5) వాడతాం (అంటే 5 ఫైల్స్ కి మించదు, పాతవి ఆటోమాటిక్ గా డిలీట్ అవుతాయి).

⚠️ Common Developer Pitfall: రియల్ వెబ్ సైట్ లో DEBUG లెవెల్ ఉంచడం

కోడ్ రాసేటప్పుడు డీబగ్ పెట్టుకుంటాం. కానీ సైట్ లైవ్ లోకి వెళ్ళాక దాన్ని INFO లేదా WARNING కి మార్చాలి. లేకపోతే సెకనుకి వందల లాగ్స్ సేవ్ అయ్యి వెబ్ సైట్ స్లో అయిపోతుంది.

💻 Hands-on Interactive Practice Challenge

ఒక ఫంక్షన్ రాయండి: మనం "production" అని ఇస్తే ప్రొడక్షన్ సెట్టింగ్స్ ఇవ్వాలి, "dev" అని ఇస్తే డెవలప్మెంట్ సెట్టింగ్స్ ఇవ్వాలి.

Python 3 Practice Challenge ▶ Run in Compiler 
def get_app_config(env_mode):
    if env_mode == "production":
        return {"db": "prod_db", "debug": False, "log": "WARNING"}
    else:
        return {"db": "test_db", "debug": True,  "log": "DEBUG"}

print("డెవలపర్ సెట్టింగ్స్:", get_app_config("dev"))
print("లైవ్ సర్వర్ సెట్టింగ్స్:", get_app_config("production"))
