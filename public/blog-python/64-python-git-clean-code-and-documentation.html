Git, Clean Code & Docs (తెలుగులో)

🐍 Python 3.12+ 🟢 Chapter 64 of 65 📂 Phase 12: Automation and Professional Skills 📅 2026 Edition
📌 Covered in this chapter: Git Version Control Workflow · PEP 8 Style Guide · Formatting with Black & Ruff · Docstrings (Google/NumPy Style) · SOLID Principles
సీనియర్ సాఫ్ట్ వేర్ ఇంజనీర్స్ కోడ్ ఎలా రాస్తారు? Git వాడి టీమ్ లో ఎలా పనిచేస్తారు? కోడ్ ని అర్థమయ్యేలా (Clean Code గా) ఎలా ఉంచాలో నేర్చుకుందాం.
1గిట్ (Git) అంటే ఏంటి? ఎలా వాడతారు?

Git అంటే మనం రాసిన కోడ్ కి ఎప్పటికప్పుడు సేవ్ పాయింట్స్ పెట్టుకోవడం. 10 మంది కలిసి ఒకే ప్రాజెక్ట్ మీద పనిచేస్తున్నప్పుడు ఒకరి కోడ్ ఇంకొకరికి డిస్టర్బ్ కాకుండా ఇది చూసుకుంటుంది.

ఆఫీస్ లో వాడే స్టాండర్డ్ గిట్ వర్క్ ఫ్లో:

  1. git checkout -b feature/login: మెయిన్ కోడ్ ని డిస్టర్బ్ చేయకుండా, లాగిన్ ఫీచర్ కోసం ఒక సపరేట్ కాపీ (Branch) క్రియేట్ చేసుకోవడం.
  2. git add .: మనం చేసిన మార్పులన్నిటినీ యాడ్ చేయడం.
  3. git commit -m "added login page": ఈ మార్పులకి ఒక పేరు పెట్టి సేవ్ చేయడం.
  4. git push origin feature/login: మన కంప్యూటర్ నుంచి గిట్ హబ్ (GitHub) లాంటి సర్వర్ కి పంపించడం.
  5. Pull Request (PR): నా కోడ్ రెడీగా ఉంది, ఎవరైనా చెక్ చేసి మెయిన్ ప్రాజెక్ట్ లో కలపండి అని రిక్వెస్ట్ పెట్టడం.

# ముఖ్యమైన Git కమాండ్స్:
git_cmds = {
    "git status":  "నేను ఏయే ఫైల్స్ మార్చానో చూడటానికి",
    "git diff":    "ఫైల్ లో ఎక్సాక్ట్ గా ఏ లైన్ మార్చానో చూడటానికి",
    "git log":     "ఇంతకు ముందు ఎవరెవరు ఏమేం మార్చారో హిస్టరీ",
    "git branch":  "మన ప్రాజెక్ట్ లో ఉన్న బ్రాంచెస్ (కాపీలు) లిస్ట్",
    "git stash":   "నేను చేసిన సగం పనిని టెంపరరీగా పక్కన పెట్టడానికి"
}

print("--- 🛠️ కచ్చితంగా తెలియాల్సిన Git కమాండ్స్ ---")
for cmd, desc in git_cmds.items():
    print(f"• {cmd:15}: {desc}")
🔍 .gitignore ఫైల్ అంటే?:

పాస్ వర్డ్స్ ఉన్న ఫైల్స్ (.env) లేదా సిస్టమ్ క్రియేట్ చేసే వేస్ట్ ఫైల్స్ (.pyc) గిట్ హబ్ లోకి వెళ్ళకుండా ఆపడానికి ఈ ఫైల్ లో వాటి పేర్లు రాస్తాం.

2క్లీన్ కోడ్, PEP 8 & డాక్యుమెంటేషన్ (Docstrings)

మనం కోడ్ రాసే టైమ్ కంటే, వేరే వాళ్ళు దాన్ని చదివే టైమే ఎక్కువ ఉంటుంది. కాబట్టి కోడ్ నీట్ గా, అందరికీ అర్థమయ్యేలా రాయాలి.

క్లీన్ కోడ్ రూల్స్:

  • DRY (Don't Repeat Yourself): ఒకే కోడ్ ని రెండు సార్లు కాపీ పేస్ట్ చేయకూడదు. దానికి ఒక ఫంక్షన్ రాయాలి.
  • KISS (Keep It Simple): కాంప్లెక్స్ గా రాయడం కంటే సింపుల్ గా రాయడమే గ్రేట్.
  • Black / Ruff: మనం కోడ్ ని ఎలా పడితే అలా రాసినా, ఈ టూల్స్ వాడితే ఆటోమాటిక్ గా ఇంటర్నేషనల్ స్టాండర్డ్స్ కి తగ్గట్టు స్పేస్ లు అడ్జస్ట్ అయిపోతాయి (PEP 8).
💻 Example 2: Clean Code with Type Hints and Google-Style Docstring
Python 3 ▶ Run in Compiler 
def get_bonus(salary: float, rating: float, years: int) -> float:
    """ఎంప్లాయ్ కి యాన్యువల్ బోనస్ లెక్కించే ఫంక్షన్ (Google Style).

    Args:
        salary (float): సంవత్సర జీతం.
        rating (float): పెర్ఫార్మన్స్ రేటింగ్ (1.0 నుంచి 5.0 మధ్యలో).
        years (int): కంపెనీలో ఎన్ని ఏళ్ళుగా ఉన్నాడు.

    Returns:
        float: ఇవ్వాల్సిన బోనస్ అమౌంట్.
        
    Raises:
        ValueError: రేటింగ్ 1-5 మధ్యలో లేకపోతే.
    """
    if not (1.0 <= rating <= 5.0):
        raise ValueError("రేటింగ్ 1 నుంచి 5 మధ్యలోనే ఉండాలి!")

    # రేటింగ్ ని బట్టి 15% వరకు బోనస్
    bonus_pct = (rating / 5.0) * 0.15 
    
    # ఎక్సపీరియన్స్ ని బట్టి ఇంకో 5% వరకు ఎక్స్ట్రా
    loyalty_pct = min(years * 0.01, 0.05)
    
    total = salary * (bonus_pct + loyalty_pct)
    return round(total, 2)

bonus = get_bonus(salary=1200000, rating=4.8, years=3)
print(f"ఎంప్లాయ్ కి ఇవ్వాల్సిన బోనస్: ₹{bonus:,.2f}")
🔍 టైప్ హింట్స్ (Type Hints):

ఫంక్షన్ కి ఇచ్చేవి (salary) నెంబర్లా? టెక్స్టా? అని ముందే : float అని చెప్పడం వల్ల ఎడిటర్ లో తప్పులు ముందే తెలిసిపోతాయి.

⚠️ Common Developer Pitfall: అర్థం కాని పేర్లు పెట్టడం (x, a1, data2)

వేరియబుల్స్ కి x, y, data2 లాంటి పేర్లు పెడితే అందులో ఏముందో రెండు రోజుల తర్వాత మనకే అర్థం కాదు. కచ్చితంగా `user_age`, `total_amount` లాంటి మీనింగ్ ఫుల్ పేర్లు పెట్టాలి.

def is_loan_approved(score: int, income: float, loan_amt: float) -> bool:
    # స్కోర్ 700 పైన ఉండి, అడిగిన లోన్ జీతంలో సగం కంటే తక్కువ ఉంటేనే ఓకే:
    return score >= 700 and loan_amt <= (income * 0.5)

print("పర్సన్ 1 కి వస్తుందా?:", is_loan_approved(750, 100000, 40000)) # True
print("పర్సన్ 2 కి వస్తుందా?:", is_loan_approved(650, 100000, 40000)) # False (స్కోర్ తక్కువ)

❓ Frequently Asked Questions (FAQ)

Q Ruff అంటే ఏంటి?

ఇది పైథాన్ కోసం వచ్చిన కొత్త లైనర్/ఫార్మాటర్. పాత టూల్స్ అన్నింటికంటే ఇది 10-100 రెట్లు స్పీడ్ గా మన కోడ్ లోని తప్పులు వెతికి చెప్తుంది.

Q git merge కీ, git rebase కీ తేడా ఏంటి?

రెండు బ్రాంచెస్ ని కలపడానికే వాడతారు. merge చేస్తే కలిసినట్టు ఒక కొత్త సేవ్ పాయింట్ వస్తుంది. rebase చేస్తే మన కోడ్ ని తీసుకెళ్లి పక్కన పెట్టి, వాళ్లది తీసుకొచ్చి, దానిమీద మనది అప్లై చేస్తుంది (హిస్టరీ క్లీన్ గా ఉంటుంది).
