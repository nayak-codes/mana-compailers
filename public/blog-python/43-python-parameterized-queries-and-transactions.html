Safe Queries (SQLi) & Transactions (తెలుగులో)

🐍 Python 3.12+ 🟢 Chapter 43 of 65 📂 Phase 9: Databases and APIs 📅 2026 Edition
📌 Covered in this chapter: SQL Injection Deep Dive · String Formatting Hazards · Parameterized Placeholders (?) · ACID Principles · commit() & rollback() · Transaction Context Managers
హ్యాకర్స్ డేటాబేస్ ని ఎలా హ్యాక్ చేస్తారు (SQL Injection)? దాన్ని ఎలా ఆపాలి? అలాగే ఒకేసారి రెండు మూడు పనులు జరుగుతున్నప్పుడు మధ్యలో క్రాష్ అయితే ఏం జరుగుతుంది (Transactions & ACID) తెలుసుకుందాం.
1SQL Injection అంటే ఏంటి? దాన్నుంచి ఎలా తప్పించుకోవాలి?

SQL Injection (SQLi) అనేది వెబ్సైట్స్ లో జరిగే అతిపెద్ద సెక్యూరిటీ అటాక్. యూజర్ ఇచ్చే డేటాని డైరెక్ట్ గా మన SQL కోడ్ లో కలిపితే (String Concatenation) హ్యాకర్స్ మన డేటాబేస్ ని కంట్రోల్ చేసేస్తారు.

హ్యాకింగ్ ఎలా జరుగుతుంది?:

మీరు కోడ్ ని f-strings వాడి ఇలా రాశారు అనుకుందాం:

# చాలా డేంజర్ కోడ్:
query = f"SELECT * FROM users WHERE user = '{username}' AND pass = '{password}'"

హ్యాకర్ యూజర్ నేమ్ దగ్గర admin' -- అని ఇచ్చాడనుకోండి, ఆ కోడ్ ఇలా మారుతుంది:

SELECT * FROM users WHERE user = 'admin' --' AND pass = '...'

SQL లో -- అంటే కామెంట్. అంటే ఆ తర్వాత ఉన్న పాస్వర్డ్ చెక్కింగ్ అంతా పనిచేయదు! పాస్వర్డ్ లేకుండానే అడ్మిన్ లాగిన్ అయిపోతాడు.

ఎలా తప్పించుకోవాలి? (Parameterized Queries)

యూజర్ ఇచ్చే డేటాని డైరెక్ట్ గా కలపకుండా, ? (ప్లేస్ హోల్డర్) వాడాలి. అప్పుడు డేటాబేస్ దాన్ని కమాండ్ లాగా కాకుండా, జస్ట్ ఒక టెక్స్ట్ లాగే చూస్తుంది.

💻 Example 1: Demonstrating SQL Injection Defense with Parameterized Placeholders
Python 3 ▶ Run in Compiler 
import sqlite3

conn = sqlite3.connect(":memory:")
conn.row_factory = sqlite3.Row
cur = conn.cursor()

cur.execute("CREATE TABLE users (id INTEGER PRIMARY KEY, username TEXT, role TEXT)")
cur.executemany("INSERT INTO users VALUES (?, ?, ?)", [
    (1, "admin", "SuperAdmin"),
    (2, "balaji", "Developer")
])
conn.commit()

# హ్యాకర్ ఇచ్చే ఇన్పుట్:
malicious_payload = "admin' OR '1'='1"

print("--- 🛡️ సెక్యూర్డ్ క్వెరీ టెస్టింగ్ ---")
# '?' వాడి పంపితే సెక్యూర్ గా ఉంటుంది:
cur.execute("SELECT * FROM users WHERE username = ?", (malicious_payload,))
matched_users = cur.fetchall()

if len(matched_users) == 0:
    print("✅ అటాక్ ఫెయిల్! హ్యాకర్ ఇచ్చిన కోడ్ ని డేటాబేస్ జస్ట్ ఒక స్ట్రింగ్ లాగే ట్రీట్ చేసింది.")

conn.close()
🔍 100% సేఫ్టీ:

? వాడితే, హ్యాకర్ ఎన్ని కోట్స్, సెమికోలన్స్ పెట్టినా సరే... దాన్ని పైకమాండ్స్ లాగా రన్ చేయదు. కేవలం ఆ టెక్స్ట్ తో ఎవరైనా ఉన్నారా అని మాత్రమే వెతుకుతుంది.

2Transactions (అయితే అన్నీ అవ్వాలి, లేకపోతే ఏదీ అవ్వకూడదు) & ACID

బ్యాంక్ లో ఒకరి అకౌంట్ లో డబ్బులు కట్ చేసి, ఇంకొకరి అకౌంట్ లో వేయాలి. మొదటి పని అయ్యాక కరెంట్ పోతే ఏమవుతుంది? డబ్బులు మాయం! ఇలాంటివి జరగకుండా ఉండేందుకే Transactions (ACID రూల్స్) వాడతారు.

రూల్అర్థం
Atomicity (A)పనులు అయితే అన్నీ సక్సెస్ అవ్వాలి. ఏ చిన్న ఎర్రర్ వచ్చినా మొత్తం క్యాన్సిల్ (rollback()) అయిపోయి పాత స్టేజ్ కి వచ్చేయాలి.
Consistency (C)డేటాబేస్ రూల్స్ అన్నీ ఎప్పుడూ కరెక్ట్ గా ఫాలో అవ్వాలి (ఉదా: బ్యాలెన్స్ మైనస్ లోకి వెళ్ళకూడదు).
Isolation (I)ఒక ట్రాన్సాక్షన్ జరుగుతున్నప్పుడు, సగం జరిగిన మార్పులు వేరే వాళ్ళకి కనిపించకూడదు.
Durability (D)ఒకసారి commit() అయ్యాక, సర్వర్ క్రాష్ అయినా సరే డేటా సేఫ్ గా హార్డ్ డిస్క్ లో ఉండాలి.
💻 Example 2: Financial Wallet Transfer with ACID Rollback Protection
Python 3 ▶ Run in Compiler 
import sqlite3

conn = sqlite3.connect(":memory:")
conn.row_factory = sqlite3.Row
cur = conn.cursor()

# బ్యాలెన్స్ నెగెటివ్ అవ్వకూడదని CHECK కండిషన్ పెట్టాం:
cur.execute("CREATE TABLE wallets (id TEXT PRIMARY KEY, balance REAL CHECK(balance >= 0))")
cur.executemany("INSERT INTO wallets VALUES (?, ?)", [("W1", 15000.0), ("W2", 2000.0)])
conn.commit()

def execute_money_transfer(sender, receiver, amount):
    print(f"\n--- 💸 ట్రాన్స్ఫర్ స్టార్ట్: ₹{amount:,.2f} ({sender} -> {receiver}) ---")
    try:
        # 1. డబ్బులు కట్ చేద్దాం:
        cur.execute("UPDATE wallets SET balance = balance - ? WHERE id = ?", (amount, sender))
        
        # 2. డబ్బులు యాడ్ చేద్దాం:
        cur.execute("UPDATE wallets SET balance = balance + ? WHERE id = ?", (amount, receiver))
        
        # 3. రెండు పనులు సక్సెస్ అయితేనే కమిట్ చేద్దాం:
        conn.commit()
        print("✅ ట్రాన్సాక్షన్ సక్సెస్! అకౌంట్స్ అప్డేట్ అయ్యాయి.")
    except Exception as err:
        # ఎర్రర్ వస్తే మొత్తం వెనక్కి తీసుకుందాం (కట్ అయిన డబ్బులు మళ్ళీ వచ్చేస్తాయి):
        conn.rollback()
        print(f"🛑 ట్రాన్సాక్షన్ ఫెయిల్ & క్యాన్సిల్ (Rollback): {err}")

# టెస్ట్ 1: నార్మల్ ట్రాన్స్ఫర్
execute_money_transfer("W1", "W2", 5000.0)

# టెస్ట్ 2: బ్యాలెన్స్ లేదు కాబట్టి ఫెయిల్ అవ్వాలి (నెగెటివ్ కి వెళ్ళనివ్వదు)
execute_money_transfer("W1", "W2", 90000.0)

cur.execute("SELECT * FROM wallets")
print("\n--- కరెంట్ బ్యాలెన్స్ ---")
for w in cur.fetchall():
    print(f"• {w['id']}: ₹{w['balance']:,.2f}")

conn.close()
🔍 CHECK కండిషన్ పవర్:

టేబుల్ క్రియేట్ చేసేటప్పుడు CHECK(balance >= 0) అని ఇచ్చాం. కాబట్టి ఎవరైనా బ్యాలెన్స్ లేకపోయినా ఎక్కువ డబ్బులు పంపాలని చూస్తే, డేటాబేస్ ఆటోమాటిక్ గా ఎర్రర్ ఇస్తుంది.

⚠️ Common Developer Pitfall: Rollback వాడకుండా మాన్యువల్ గా మార్చడం

ఎర్రర్ వచ్చినప్పుడు "కట్ చేసిన డబ్బులు మళ్ళీ యాడ్ చేసేలా" మాన్యువల్ గా కోడ్ రాయకూడదు. దానికి బదులు డైరెక్ట్ గా conn.rollback() అని పిలిస్తే, ఆ ట్రాన్సాక్షన్ లో జరిగిన మార్పులన్నీ డేటాబేస్ ఆటోమాటిక్ గా తీసేస్తుంది (చాలా సేఫ్).

💻 Hands-on Interactive Practice Challenge

ఒక context manager (with conn:) వాడి రెండు రికార్డ్స్ ఇన్సర్ట్ చేయండి. రెండో దాంట్లో కావాలని ఎర్రర్ తెప్పించి, rollback ఆటోమాటిక్ గా జరుగుతుందో లేదో చూడండి.

Python 3 Practice Challenge ▶ Run in Compiler 
import sqlite3

conn = sqlite3.connect(":memory:")
cur = conn.cursor()
cur.execute("CREATE TABLE logs (id INTEGER PRIMARY KEY, msg TEXT UNIQUE)")

try:
    with conn: # ఇది ఆటోమాటిక్ గా commit/rollback చేస్తుంది!
        cur.execute("INSERT INTO logs VALUES (1, 'Log A')")
        cur.execute("INSERT INTO logs VALUES (2, 'Log A')") # UNIQUE ఎర్రర్ వస్తుంది!
except sqlite3.IntegrityError:
    print("ఎర్రర్ వచ్చింది! మొత్తం ఆటోమాటిక్ గా రోల్ బ్యాక్ అయిపోయింది.")

cur.execute("SELECT COUNT(*) FROM logs")
print("మొత్తం రికార్డ్స్:", cur.fetchone()[0]) # 0 (ఫస్ట్ ది కూడా డిలీట్ అయిపోయింది!)
conn.close()

❓ Frequently Asked Questions (FAQ)

Q Table-level locking కి Row-level locking కి తేడా ఏంటి?

SQLite టేబుల్-లెవెల్ లాకింగ్ వాడుతుంది (అంటే ఒకరు రాస్తున్నప్పుడు మిగతావాళ్లు ఆ టేబుల్ మొత్తం మీద ఏం చేయలేరు). PostgreSQL లాంటివి రో-లెవెల్ లాకింగ్ వాడతాయి (అంటే ఏ రో అప్డేట్ అవుతుందో అది మాత్రమే లాక్ అవుతుంది, మిగతావి ఫ్రీగా ఉంటాయి).

Q SQLAlchemy (ORM) వాడితే SQL Injection జరుగుతుందా?

ORM లు ఆటోమాటిక్ గా డేటాని సెక్యూర్ గా (Parameterized గానే) పంపిస్తాయి. కాబట్టి SQL Injection జరగదు.
