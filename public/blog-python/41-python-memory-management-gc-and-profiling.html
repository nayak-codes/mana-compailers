Memory Management, GC & Profiling (తెలుగులో)

🐍 Python 3.12+ 🟢 Chapter 41 of 65 📂 Phase 8: Advanced Python 📅 2026 Edition
📌 Covered in this chapter: Shallow vs Deep Copy · PyObject Anatomy · Reference Counting · Generational GC (Gen 0, 1, 2) · timeit & cProfile · EAFP vs LBYL
పైథాన్ మెమరీని ఎలా వాడుకుంటుంది? డీప్ కాపీ అంటే ఏంటి? Reference Counting, Garbage Collection (GC) అంటే ఏంటి? కోడ్ ఎంత ఫాస్ట్ గా రన్ అవుతుందో చెక్ చేసే `timeit` గురించి నేర్చుకుందాం.
1Shallow Copy vs Deep Copy (కాపీ చేయడంలో తేడాలు)

లిస్ట్స్ లో ఒకదాన్ని కాపీ చేసేటప్పుడు చాలా జాగ్రత్తగా ఉండాలి, లేకపోతే తెలియకుండానే ఒకదాని డేటా ఇంకొకటి మార్చేస్తుంది:

  • మామూలు Assignment (b = a): అసలు కాపీ అవ్వదు. రెండు పేర్లు ఒకే మెమరీ అడ్రెస్స్ ని చూపిస్తాయి.
  • Shallow Copy (copy.copy()): బయట ఉన్న లిస్ట్ వరకే కొత్త కాపీ క్రియేట్ అవుతుంది, కానీ లోపల ఉన్న చిన్న లిస్ట్స్ పాతవి అతుక్కునే ఉంటాయి.
  • Deep Copy (copy.deepcopy()): బయట లిస్ట్ తో పాటు, లోపల ఉన్న ప్రతి చిన్న లిస్ట్ కి కొత్త మెమరీ ఇస్తుంది (పూర్తిగా సేఫ్).
💻 Example 1: Shallow Copy vs Deep Copy Demonstration
Python 3 ▶ Run in Compiler 
import copy

# ఒక లిస్ట్ లోపల ఇంకో లిస్ట్ (Nested):
original = [[1, 2], [3, 4]]

shallow = copy.copy(original)
deep = copy.deepcopy(original)

# అసలు లిస్ట్ లోపల మార్చుదాం:
original[0][0] = 999

print("Original list:                 ", original) # [[999, 2], [3, 4]]
print("Shallow copy (లోపల మారిపోయింది!):", shallow)  # [[999, 2], [3, 4]] (లోపల లిస్ట్ సేమ్)
print("Deep copy (పూర్తిగా సేఫ్!):      ", deep)     # [[1, 2], [3, 4]] (కొత్త మెమరీ)
🔍 ఎప్పుడు ఏది వాడాలి?:

సింగిల్ డైమెన్షన్ లిస్ట్ కి copy() సరిపోతుంది. కానీ లోపల డిక్షనరీలు, లిస్టులు ఉంటే కచ్చితంగా copy.deepcopy() నే వాడాలి.

2పైథాన్ మెమరీ సీక్రెట్: Reference Counting

పైథాన్ లోపల ప్రతి ఆబ్జెక్ట్ కి ఒక Reference Count (రెఫ్ కౌంట్) ఉంటుంది. అంటే ఆ ఆబ్జెక్ట్ ని ఎన్ని వేరియబుల్స్ వాడుకుంటున్నాయి అనే నెంబర్.

ఒకవేళ ఆ నెంబర్ 0 అయిపోతే, పైథాన్ ఆటోమాటిక్ గా ఆ మెమరీని డిలీట్ చేసేస్తుంది!

💻 Example 2: Inspecting CPython Reference Counting with sys.getrefcount
Python 3 ▶ Run in Compiler 
import sys

# 1. కొత్త లిస్ట్ తయారు చేద్దాం:
sample = [1, 2, 3]

# sys.getrefcount() ఎన్ని రెఫరెన్స్ లు ఉన్నాయో చెప్తుంది:
print("sample కి ఉన్న రిఫరెన్స్ లు:", sys.getrefcount(sample) - 1) # 1

# 2. ఇంకో పేరు పెడదాం (రెండు వేరియబుల్స్ ఒకే దాన్ని చూపిస్తున్నాయి):
alias_ptr = sample
print("alias_ptr ఇచ్చాక:       ", sys.getrefcount(sample) - 1) # 2

# 3. ఒక వేరియబుల్ డిలీట్ చేద్దాం:
del alias_ptr
print("ఒకటి డిలీట్ చేసాక:        ", sys.getrefcount(sample) - 1) # 1 (ఇంకా sample ఉంది కాబట్టి డిలీట్ అవ్వదు)
🔍 -1 ఎందుకు చేశాం?:

ఫంక్షన్ లోపలికి పంపినప్పుడు టెంపరరీగా అది కూడా ఒక పేరు ఇచ్చుకుంటుంది కాబట్టి, అసలు నెంబర్ కోసం -1 చేస్తాం.

3Garbage Collector (సైకిల్స్ లో ఇరుక్కుంటే?)

రిఫరెన్స్ కౌంటింగ్ లో ఒక పెద్ద ప్రాబ్లమ్ ఉంది. ఆబ్జెక్ట్ A ని B చూపిస్తూ, B ని A చూపిస్తే (Circular Reference), బయట నుంచి రెండూ డిలీట్ చేసినా వాటి కౌంట్ 0 అవ్వదు. అలాంటప్పుడు Garbage Collector (GC) వస్తుంది.

దీన్ని ఇది బ్యాక్ గ్రౌండ్ లో రన్ అయ్యి, ఇలా ఒకదానికొకటి అతుక్కుని వృధాగా పడి ఉన్నవాటిని వెతికి మరీ మెమరీలోంచి తీసేస్తుంది.

💻 Example 3: Circular Reference Cycles and the gc Module
Python 3 ▶ Run in Compiler 
import gc

# 1. ఒకదానికొకటి లింక్ చేసుకునేలా క్లాస్ రాద్దాం:
class Node:
    def __init__(self, name):
        self.name = name
        self.partner = None

node1 = Node("A")
node2 = Node("B")

node1.partner = node2 # A, B ని చూపిస్తోంది
node2.partner = node1 # B, A ని చూపిస్తోంది (ఇరుక్కుపోయాయి!)

# బయట నుంచి పేర్లు డిలీట్ చేద్దాం:
del node1
del node2

# 2. గూఢచారి (Garbage Collector) ని పంపి వెతికిద్దాం:
unreachable_objects = gc.collect()
print(f"🧹 Garbage Collector {unreachable_objects} వృధా ఆబ్జెక్ట్స్ ని డిలీట్ చేసింది!")
🔍 ఎప్పుడు వాడాలి?:

మామూలుగా GC ఆటోమాటిక్ గా బ్యాక్ గ్రౌండ్ లో రన్ అవుతుంది. మనం దీన్ని మాన్యువల్ గా రన్ చేయాల్సిన అవసరం లేదు.

4ఫాస్ట్ గా ఏది పనిచేస్తుందో చెక్ చేయడం (timeit)

ఒక పని చేయడానికి ఏ కోడ్ ఫాస్ట్ గా ఉందో చెక్ చేయాలంటే మనం timeit వాడతాం. ఇది కోడ్ ని వేలసార్లు రన్ చేసి కరెక్ట్ ఆవరేజ్ టైమ్ చెప్తుంది.

💻 Example 4: Performance Benchmarking and Idiomatic Pythonic Coding
Python 3 ▶ Run in Compiler 
import timeit

# స్ట్రింగ్స్ లోకి మార్చడానికి లిస్ట్ కాంప్రహెన్షన్ బెస్ట్ ఆ? map() బెస్ట్ ఆ?:
time_comp = timeit.timeit('[str(x) for x in range(1000)]', number=10_000)
time_map = timeit.timeit('list(map(str, range(1000)))', number=10_000)

print(f"⚡ List Comprehension (10k సార్లు): {time_comp:.4f} seconds")
print(f"⚡ map(str, ...)       (10k సార్లు): {time_map:.4f} seconds")

# పైథాన్ స్టైల్ (EAFP - ఏది జరిగినా చూసుకుందాం):
user_profile = {"name": "Balaji"}

# పదే పదే చెక్ చేయకుండా (EAFP), డైరెక్ట్ గా ట్రై చేసి ఎర్రర్ వస్తే హ్యాండిల్ చేయడం బెస్ట్:
try:
    email = user_profile["email"]
except KeyError:
    email = "default@example.com"
print("User Email (EAFP వాడుతూ):", email)
🔍 EAFP లాభం:

if "email" in user అని చెక్ చేసి మళ్ళీ user["email"] తీసుకుంటే రెండు సార్లు వెతకాలి. EAFP వాడితే డైరెక్ట్ గా ఒకసారే తీసుకుంటుంది.

⚠️ Common Developer Pitfall: del వాడితే మెమరీ ఫ్రీ అయిపోతుందని అనుకోవడం

del వాడితే వేరియబుల్ పేరు మాత్రమే పోతుంది. ఆ ఆబ్జెక్ట్ ని ఇంకెవరైనా వాడుకుంటూ ఉంటే అది డిలీట్ అవ్వదు. పైథాన్ దాన్ని తీసేసినా, OS కి వెంటనే ఆ మెమరీ తిరిగి ఇవ్వదు, తర్వాత పైథాన్ వాడుకోవడానికి ఉంచుకుంటుంది.

💻 Hands-on Interactive Practice Challenge

ఒక సెట్ లో నెంబర్ ఉందో లేదో చెక్ చేయడం ఫాస్టా? లిస్ట్ లో ఫాస్టా? timeit వాడి చెక్ చేయండి.

Python 3 Practice Challenge ▶ Run in Compiler 
import timeit

setup_code = """
my_list = list(range(1000))
my_set = set(range(1000))
"""

t_list = timeit.timeit('999 in my_list', setup=setup_code, number=100_000)
t_set = timeit.timeit('999 in my_set', setup=setup_code, number=100_000)

print(f"List 'in' check (100k సార్లు): {t_list:.5f} sec")
print(f"Set 'in' check  (100k సార్లు): {t_set:.5f} sec")
print(f"🚀 Set అనేది లిస్ట్ కంటే {t_list/t_set:.1f} రెట్లు ఫాస్ట్!")

❓ Frequently Asked Questions (FAQ)

Q GIL (Global Interpreter Lock) అంటే ఏంటి?

పైథాన్ (CPython) లో ఒకే టైమ్ లో రెండు త్రెడ్స్ (Threads) మెమరీని మార్చకుండా, సేఫ్ గా ఉండటానికి లాక్ వేస్తుంది. దీనివల్లే పైథాన్ మల్టీ-త్రెడింగ్ కొంచెం స్లోగా ఉంటుంది.

Q చిన్న నెంబర్స్ మెమరీ గురించి సీక్రెట్ ఏంటి?

పైథాన్ -5 నుంచి 256 వరకు ఉన్న నెంబర్స్ ని ముందుగానే మెమరీలో ఒకేచోట సేవ్ చేసి పెట్టుకుంటుంది. అందుకే ఆ నెంబర్స్ కి కొత్త మెమరీ అవ్వదు, ఉన్నదాన్నే ఇస్తుంది (చాలా ఫాస్ట్).
