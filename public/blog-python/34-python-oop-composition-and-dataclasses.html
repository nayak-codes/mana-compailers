Composition & Dataclasses (తెలుగులో)

🐍 Python 3.12+ 🟢 Chapter 34 of 65 📂 Phase 7: Object-Oriented Programming 📅 2026 Edition
📌 Covered in this chapter: Composition ("Has-A") vs Inheritance ("Is-A") · Decoupling · @dataclass (PEP 557) · field(default_factory) · Frozen Immutability
Inheritance కంటే Composition ఎందుకు బెస్ట్ (Has-A vs Is-A)? మరియు మోడ్రన్ పైథాన్ లో @dataclass వాడి కోడ్ ని సగానికి సగం ఎలా తగ్గించొచ్చో చూద్దాం.
1Composition ("Has-A" రిలేషన్)

సాఫ్ట్ వేర్ డిజైన్ లో ఒక ఫేమస్ రూల్ ఉంది: "Inheritance కంటే Composition వాడటమే బెస్ట్".

  • Inheritance ("Is-A"): కుక్క (Dog) అనేది ఒక జంతువు (Animal). ఇది స్ట్రాంగ్ లింక్. పేరెంట్ లో ఏమైనా మారిస్తే చైల్డ్ కూడా అఫెక్ట్ అవుతుంది.
  • Composition ("Has-A"): కార్ (Car) లోపల ఒక ఇంజిన్ (Engine) ఉంటుంది. ఇది లూస్ లింక్. రేపు పొద్దున్న ఎలక్ట్రిక్ ఇంజిన్ కావాలంటే పాతదాన్ని తీసేసి కొత్తది పెట్టుకోవచ్చు!
💻 Example 1: Building Modular Systems with Composition
Python 3 ▶ Run in Compiler 
# విడివిడిగా ఉన్న కాంపోనెంట్స్:
class Engine:
    def __init__(self, horsepower, fuel_type):
        self.horsepower = horsepower
        self.fuel_type = fuel_type

    def ignite(self):
        return f"🔥 Engine ({self.horsepower} HP, {self.fuel_type}) స్టార్ట్ అయింది!"

class GPSNavigator:
    def route_to(self, destination):
        return f"🗺️ '{destination}' కి రూట్ కనుక్కుంటున్నాను..."

# వీటిని కలిపి ఒక కార్ ని తయారు చేద్దాం (Composition):
class Automobile:
    def __init__(self, model, engine_hp, fuel_type):
        self.model = model
        # COMPOSITION: కార్ "లోపల" ఇంజిన్ ఉంది, GPS ఉంది:
        self.engine = Engine(engine_hp, fuel_type)
        self.navigator = GPSNavigator()

    def start_trip(self, destination):
        print(f"--- Starting Trip in {self.model} ---")
        print(self.engine.ignite())
        print(self.navigator.route_to(destination))

my_car = Automobile("Porsche 911", 450, "Petrol")
my_car.start_trip("Hyderabad Cyber Towers")
🔍 ఫ్లెక్సిబిలిటీ (మంచి డిజైన్):

రేపు మీరు ఎలక్ట్రిక్ కార్ చేయాలంటే self.engine = ElectricMotor() అని ఇంజిన్ మార్చేస్తే చాలు. కార్ మొత్తం కోడ్ ని మార్చాల్సిన పనిలేదు.

2Dataclasses: బోరింగ్ కోడ్ రాయక్కర్లేదు (PEP 557)

పైథాన్ లో ఒక ఆబ్జెక్ట్ రాస్తే __init__ రాయాలి, __str__ రాయాలి, __eq__ రాయాలి.. చాలా బోర్ కదా? పైథాన్ 3.7 లో @dataclass వచ్చింది. ఇది ఆటోమాటిక్ గా మనకోసం కోడ్ రాసేస్తుంది!

💻 Example 2: Defining Dataclasses with PEP 557
Python 3 ▶ Run in Compiler 
from dataclasses import dataclass, field
from typing import List

# జస్ట్ ఈ ఒక్క పదం రాస్తే చాలు, __init__, __repr__ అన్నీ అదే రాసుకుంటుంది:
@dataclass
class StudentProfile:
    student_id: int
    name: str
    branch: str
    gpa: float = 0.0
    skills: List[str] = field(default_factory=list) # లిస్ట్ కోసం ఇలా వాడాలి!

# ఆబ్జెక్ట్స్ క్రియేట్ చేద్దాం:
s1 = StudentProfile(101, "Balaji", "Computer Science", 9.4, ["Python", "FastAPI"])
s2 = StudentProfile(101, "Balaji", "Computer Science", 9.4, ["Python", "FastAPI"])

print("--- ఆటోమాటిక్ గా వచ్చిన ప్రింట్ అవుట్పుట్ (__repr__) ---")
print(s1)

print("\n--- ఆటోమాటిక్ ఈక్వల్స్ చెక్ (__eq__) ---")
print("s1 == s2?", s1 == s2) # True! రెండు ఆబ్జెక్ట్స్ లోపల డేటా సేమ్ ఉందో లేదో అదే చెక్ చేస్తుంది!
🔍 field(default_factory=list) ఎందుకు?:

ఒకవేళ మీరు skills = [] అని ఎంప్టీ లిస్ట్ ఇస్తే, స్టూడెంట్స్ అందరికీ ఒకే లిస్ట్ షేర్ అవుతుంది. అదే default_factory ఇస్తే ప్రతి స్టూడెంట్ కి ఒక కొత్త లిస్ట్ వస్తుంది.

3Frozen Dataclasses (ఎవరూ మార్చలేరు)

మీరు డేటా క్లాస్ కి frozen=True అని పెడితే, దాన్ని ఎవరు మార్చడానికి ట్రై చేసినా క్రాష్ అవుతుంది. దీన్ని మనం సెట్టింగ్స్ కి, లొకేషన్స్ (GPS) కి వాడతాం:

💻 Example 3: Immutable Read-Only Dataclasses with frozen=True
Python 3 ▶ Run in Compiler 
from dataclasses import dataclass

@dataclass(frozen=True)
class GeoCoordinates:
    latitude: float
    longitude: float

location = GeoCoordinates(17.3850, 78.4867)
print("Geo Coordinates:", location)

# మార్చడానికి ట్రై చేద్దాం (ఎర్రర్ వస్తుంది):
try:
    location.latitude = 18.0000
except Exception as err:
    print("🔒 Frozen Dataclass Protected:", type(err).__name__, err)
🔍 లాభం?:

ఫ్రోజెన్ డేటా క్లాసెస్ ని మనం డిక్షనరీ కి 'Keys' లాగా కూడా వాడుకోవచ్చు (అవి మార్చలేం కాబట్టి Hashable అవుతాయి).

⚠️ Common Developer Pitfall: Dataclass లో లిస్ట్ ని డైరెక్ట్ గా డిఫాల్ట్ గా ఇవ్వడం

మీరు "tags: list = []" అని రాస్తే పైథాన్ ఒప్పుకోదు (ValueError). కచ్చితంగా "tags: list = field(default_factory=list)" అని రాయాలి.

💻 Hands-on Interactive Practice Challenge

ఒక InventoryItem అనే డేటాక్లాస్ రాయండి. అందులో name, price, quantity ఉండాలి. total_value() అనే ఒక మెథడ్ కూడా యాడ్ చేయండి.

Python 3 Practice Challenge ▶ Run in Compiler 
from dataclasses import dataclass

@dataclass
class InventoryItem:
    name: str
    price: float
    quantity: int = 1

    def total_value(self) -> float:
        return self.price * self.quantity

item = InventoryItem("USB-C Hub", 1299.00, 3)
print(item)
print(f"Total Inventory Value: ₹{item.total_value():,.2f}")

❓ Frequently Asked Questions (FAQ)

Q Dataclass లో నేను నా సొంత ఫంక్షన్స్ రాసుకోవచ్చా?

కచ్చితంగా! డేటాక్లాస్ కూడా ఒక నార్మల్ క్లాస్ లాంటిదే. కాకపోతే __init__, __repr__ అది రాసి పెడుతుంది. మిగతా ఫంక్షన్స్ మీ ఇష్టం.

Q __post_init__ అంటే ఏంటి?

కొన్నిసార్లు ఆటోమాటిక్ గా వచ్చిన __init__ తర్వాత మనకి ఇంకొంత లాజిక్ (ఉదా: పాస్వర్డ్ హ్యాష్ చేయడం) కావాలి. అప్పుడు దీన్ని వాడతాం.
