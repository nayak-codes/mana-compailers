Flask Jinja2, Forms & Auth (తెలుగులో)

🐍 Python 3.12+ 🟢 Chapter 49 of 65 📂 Phase 10: Web Development 📅 2026 Edition
📌 Covered in this chapter: Jinja2 Template Engine · Template Inheritance ({% extends %}) · Static Assets · Client Sessions (session) · Password Hashing (werkzeug.security) · Custom Error Pages (404)
పైథాన్ నుంచి HTML పేజీలని ఎలా పంపించాలి (Jinja2 Templates)? ప్రతి పేజీలో నవబార్ లాంటివి కామన్ గా ఎలా ఉంచాలి? యూజర్ లాగిన్ అవ్వగానే వాళ్ళని ఎలా గుర్తుపెట్టుకోవాలి (Sessions)? పాస్వర్డ్స్ ని సెక్యూర్ గా ఎలా సేవ్ చేయాలో నేర్చుకుందాం.
1Jinja2 Templates (HTML లో పైథాన్ వేరియబుల్స్ కలపడం)

పైథాన్ ఫంక్షన్ లోనే పదుల కొద్దీ HTML లైన్స్ రాయడం కష్టం కాబట్టి, Flask లో Jinja2 అనే ఇంజిన్ వాడుతారు. HTML ఫైల్స్ ని templates/ ఫోల్డర్ లో పెట్టి, render_template('page.html', name='Balaji') ద్వారా డేటాని పంపుతాం.

Jinja2 రాసే విధానం:

  • {{ వేరియబుల్ }}: పైథాన్ వేరియబుల్ ని HTML లో ప్రింట్ చేయడానికి (ఉదా: {{ name }}).
  • {% లాజిక్ %}: if కండిషన్స్, for లూప్స్ వాడటానికి (ఉదా: {% if is_admin %} ... {% endif %}).

Template Inheritance (DRY కోడింగ్):

ప్రతి పేజీలో పైన మెనూ (Navbar), కింద ఫూటర్ రాయాలంటే విసుగొస్తుంది. అందుకే ఒక base.html క్రియేట్ చేసి అందులో మెనూ రాసి, కింద పేజీల్లో దాన్ని వాడుకుంటాం (Inherit).

🔍 Template Filters (మ్యాజిక్):

Jinja2 లో {{ username|upper }} అని రాస్తే ఆటోమాటిక్ గా క్యాపిటల్ లెటర్స్ లో వస్తుంది. {{ courses|length }} అంటే ఎన్ని కోర్సులు ఉన్నాయో కౌంట్ వస్తుంది.

2లాగిన్స్ & సెక్యూర్ పాస్వర్డ్స్ (Sessions & Hashing)

HTTP అనేది "స్టేట్ లెస్"... అంటే ఎవరొచ్చారో దానికి గుర్తుండదు. అందుకే లాగిన్ అయిన తర్వాత ఆ యూజర్ ని గుర్తుపెట్టుకోవడానికి Flask లో session వాడతాం. (ఇది బ్రౌజర్ కుకీస్ లో సేవ్ అవుతుంది).

ముఖ్యమైన రూల్: పాస్వర్డ్స్ డైరెక్ట్ గా సేవ్ చేయకూడదు!

ఒకవేళ హ్యాకర్ డేటాబేస్ ఓపెన్ చేసినా కూడా పాస్వర్డ్స్ తెలియకుండా ఉండాలంటే, వాటిని Hash (జిబరిష్ లాగా) చేసి సేవ్ చేయాలి.

🔍 హ్యాషింగ్ ఎందుకు?:

generate_password_hash() వాడితే పాస్వర్డ్ ఒక కోడ్ లాగా మారుతుంది. ఆ కోడ్ ని చూసి ఒరిజినల్ పాస్వర్డ్ ఏంటో ఎవరూ (కనీసం వెబ్సైట్ ఓనర్ కూడా) కనిపెట్టలేరు.

⚠️ Common Developer Pitfall: Session లో క్రెడిట్ కార్డ్స్ / పాస్వర్డ్స్ సేవ్ చేయడం

Session అనేది బ్రౌజర్ కుకీ లో సేవ్ అవుతుంది. యూజర్ దాన్ని మార్చలేడు కానీ, దాన్ని ఓపెన్ చేసి చదవగలడు (అది జస్ట్ Base64 లో ఉంటుంది). అందుకే సెషన్ లో కేవలం యూజర్ ఐడీ లాంటివి మాత్రమే పెట్టుకోవాలి, పాస్వర్డ్స్ లాంటి సెన్సిటివ్ డేటా అస్సలు పెట్టకూడదు.

Python 3 Practice Challenge ▶ Run in Compiler 
from werkzeug.security import generate_password_hash, check_password_hash

raw_pass = "PythonRocks2026"
# కొత్త యూజర్ వచ్చినప్పుడు ఇలా హ్యాష్ చేసి డేటాబేస్ లో సేవ్ చేస్తాం:
hashed_pass = generate_password_hash(raw_pass)

print("హ్యాష్ చేసిన పాస్వర్డ్:", hashed_pass)
print("కరెక్ట్ పాస్వర్డ్ తో మ్యాచ్: ", check_password_hash(hashed_pass, "PythonRocks2026")) # True వస్తుంది
print("రాంగ్ పాస్వర్డ్ తో మ్యాచ్:  ", check_password_hash(hashed_pass, "WrongPass"))      # False వస్తుంది

❓ Frequently Asked Questions (FAQ)

Q CSRF (Cross-Site Request Forgery) అంటే ఏంటి?

ఇది ఒక హ్యాకింగ్ టెక్నిక్. మీరు ఫేస్బుక్ లో లాగిన్ అయి ఉన్నప్పుడు, హ్యాకర్ ఒక లింక్ ఇచ్చి దాన్ని క్లిక్ చేయిస్తే... మీ అకౌంట్ నుంచి పోస్ట్ వెళ్లిపోతుంది. దీన్ని ఆపడానికే ఫారమ్స్ లో "CSRF టోకెన్" వాడతాం.

Q నేను 404 పేజీని నాకు నచ్చినట్టు డిజైన్ చేయొచ్చా?

చేయొచ్చు! @app.errorhandler(404) అని ఒక ఫంక్షన్ రాసి, అందులో మీకు నచ్చిన HTML (లేదా జోక్) పెట్టి పంపొచ్చు.
