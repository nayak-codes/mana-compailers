Python Packages, Virtual Environments & Pip (తెలుగులో)

🐍 Python 3.12+ 🟢 Chapter 24 of 65 📂 Phase 5: Modules and Packages 📅 2026 Edition
📌 Covered in this chapter: Packages & __init__.py · Namespace Packages · venv Isolation · pip & PyPI · requirements.txt · Dependency Locking
ప్రొఫెషనల్ పైథాన్ ప్రాజెక్ట్స్ ఎలా క్రియేట్ చేయాలి? ప్యాకేజెస్ తయారుచేయడం, Virtual Environments తో ప్రాజెక్ట్స్ ని ఐసోలేట్ చేయడం, pip తో బయటి ప్యాకేజెస్ ఇన్స్టాల్ చేయడం, మరియు requirements.txt గురించి.
1Package అంటే ఏంటి? __init__.py ఏం చేస్తుంది?

Package అంటే ఒకట్రెండు పైథాన్ ఫైల్స్ కాకుండా, ఫోల్డర్స్ తో కూడిన ఒక పెద్ద కలెక్షన్. ఒక మాడ్యూల్ అంటే ఒక ఫైల్, కానీ ప్యాకేజ్ అంటే చాలా ఫైల్స్ ఉన్న ఒక ఫోల్డర్.

ప్యాకేజ్ స్ట్రక్చర్ ఇలా ఉంటుంది:

my_application/ ├── __init__.py <-- ఈ ఫోల్డర్ ని పైథాన్ ప్యాకేజ్ అంటాం అని చెప్పే ఫైల్ ├── config.py <-- సబ్-మాడ్యూల్ ├── database/ <-- లోపల ఇంకో ప్యాకేజ్ (Subpackage) │ ├── __init__.py │ ├── connection.py │ └── queries.py └── utils/ <-- ఇంకో సబ్-ప్యాకేజ్ ├── __init__.py └── helpers.py

__init__.py ఎందుకు?:

  1. ఈ ఫైల్ పెడితేనే పైథాన్ ఆ ఫోల్డర్ ని ప్యాకేజ్ లాగా గుర్తిస్తుంది.
  2. ఎవరైనా మీ ప్యాకేజ్ ని ఇంపోర్ట్ చేయగానే, అందులో మీరు ముందుగానే ఈ ఫైల్ లో రాసిన కోడ్ ఆటోమేటిక్ గా రన్ అవుతుంది.
💻 Example 1: Package Structure and Initialization
Python 3 ▶ Run in Compiler 
# __init__.py లో రాసిన కోడ్
"""
Package: my_ecommerce
Version: 1.0.0
"""
__version__ = "1.0.0"

def get_package_info():
    return f"My E-Commerce Engine v{__version__}"

# ఎవరైనా main.py లో దీన్ని వాడితే:
print("Package Info:", get_package_info())
🔍 ఒక చిన్న నోట్:

పైథాన్ 3.3 నుంచి __init__.py రాయకపోయినా ప్యాకేజ్ లానే పనిచేస్తుంది. కానీ పెద్ద కంపెనీస్ అన్నీ ఇప్పటికీ ఆ ఫైల్ వాడటాన్నే ఫాలో అవుతున్నాయి.

2Virtual Environments (venv) ఎందుకు వాడుతారు?

ఒకవేళ మీరు టెర్మినల్ లో pip install django అంటే, అది మీ కంప్యూటర్ మొత్తానికి (Global గా) ఇన్స్టాల్ అవుతుంది.

దీనివల్ల వచ్చే ప్రాబ్లం:

  • Project A కి పాత Django 4.2 కావాలి.
  • Project B కి కొత్త Django 5.1 కావాలి.
  • మీరు కొత్తది ఇన్స్టాల్ చేయగానే పాతది ఎగిరిపోయి Project A పాడైపోతుంది!

దీన్ని సాల్వ్ చేయడానికే ప్రతి ప్రాజెక్ట్ కి ఒక Virtual Environment (.venv) ని క్రియేట్ చేస్తారు. ఇది ఆ ప్రాజెక్ట్ వరకు మాత్రమే పనిచేసే ఒక "సొంత పైథాన్ ఫోల్డర్" లాంటిది.

┌────────────────────────────────────────────────────────┐ │ మీ కంప్యూటర్ (Global Python) │ ├────────────────────────────────────────────────────────┤ │ 📁 Project A (.venv) 📁 Project B (.venv) │ │ ├── Python 3.12 ├── Python 3.12 │ │ └── Django 4.2 └── Django 5.1 │ └────────────────────────────────────────────────────────┘

Python 3 ▶ Run in Compiler 
# టెర్మినల్ లో రన్ చేయాల్సిన కమాండ్స్:

# 1. ప్రాజెక్ట్ ఫోల్డర్ లో .venv ని క్రియేట్ చేయడం:
# python -m venv .venv

# 2. దాన్ని ఆన్ చేయడం (Activate)
# Windows (PowerShell):

#
# Mac / Linux:
# source .venv/bin/activate

# 3. పని అయిపోయాక ఆఫ్ చేయడం (Deactivate):
# deactivate
🔍 PowerShell ఎర్రర్ వస్తే?:

విండోస్ లో ఎర్రర్ వస్తే, అడ్మిన్ గా పవర్ షెల్ ఓపెన్ చేసి Set-ExecutionPolicy RemoteSigned అని ఇవ్వాలి.

3ప్యాకేజ్ మేనేజ్మెంట్: pip & PyPI

pip అంటే పైథాన్ అఫీషియల్ ప్యాకేజ్ ఇన్స్టాలర్. ఇది ప్రపంచంలో ఉన్న లక్షలాది ఓపెన్-సోర్స్ కోడ్ ని PyPI (Python Package Index) నుంచి మన ప్రాజెక్ట్ లోకి డౌన్లోడ్ చేస్తుంది.

ముఖ్యమైన pip కమాండ్స్:

  • pip install django: లేటెస్ట్ వెర్షన్ ని డౌన్లోడ్ చేస్తుంది.
  • pip install "django==4.2.0": పక్కాగా ఇదే వెర్షన్ కావాలని చెప్పడం (పిన్ చేయడం).
  • pip install --upgrade requests: పాతదాన్ని కొత్త వెర్షన్ కి అప్డేట్ చేయడం.
  • pip list: మనం మన .venv లో ఏమేమి ఇన్స్టాల్ చేసామో లిస్ట్ చూపిస్తుంది.
  • pip uninstall django: దాన్ని డిలీట్ చేస్తుంది.

# మన ఫోల్డర్ లో ఉన్న అన్ని ప్యాకేజెస్ లిస్ట్:
# pip list
🔍 బెస్ట్ ప్రాక్టీస్:

ఎప్పుడూ మీ టెర్మినల్ పేరు పక్కన (.venv) అని ఆక్టివేట్ అయి ఉందో లేదో చూసుకున్నాకే pip install రన్ చేయండి.

4వేరే వాళ్ళకి ప్రాజెక్ట్ పంపడం: requirements.txt

మీరు మీ కోడ్ ని Github లో పెట్టినా, లేదా సర్వర్ లో రన్ చేయాలన్నా, ఆ కంప్యూటర్ కి ఏయే ప్యాకేజెస్, ఏ వెర్షన్స్ కావాలో ఖచ్చితంగా చెప్పాలి.

దానికోసం వాడే ఫైల్ పేరే requirements.txt:

# మీరు ఇన్స్టాల్ చేసిన లిస్ట్ అంతా ఒక ఫైల్ లోకి పంపడానికి: pip freeze > requirements.txt # వేరే కంప్యూటర్ లో ఆ ఫైల్ చూసి అన్ని ప్యాకేజెస్ ఒకేసారి డౌన్లోడ్ చేయడానికి: pip install -r requirements.txt

వెర్షన్ సింబల్స్:

  • fastapi == 0.110.0: కరెక్ట్ గా ఇదే వెర్షన్ కావాలి. (బెస్ట్).
  • requests >= 2.31.0: దీనికంటే పై వెర్షన్ ఏదైనా ఓకే.
💻 Example 4: Production requirements.txt File Format
Python 3 ▶ Run in Compiler 
# ప్రొడక్షన్ కోసం వాడే ఒక requirements.txt ఫైల్ ఇలా ఉంటుంది:
sample_requirements_txt = """
# Core Web Framework
fastapi==0.110.0
uvicorn[standard]==0.29.0

# Database
SQLAlchemy==2.0.29

pydantic==2.6.4
requests>=2.31.0
"""

print("--- 📋 Production requirements.txt Blueprint ---")
print(sample_requirements_txt.strip())
🔍 Git Ignore రూల్:

మీరు మీ కోడ్ ని Git లో పెట్టేటప్పుడు ఎప్పుడూ .venv/ ఫోల్డర్ ని .gitignore లో పెట్టి ఇగ్నోర్ చేయాలి. కేవలం requirements.txt ని మాత్రమే పంపించాలి!

⚠️ Common Developer Pitfall: .venv ఫోల్డర్ ని Github కి పంపడం

ఇలా పంపితే మీ రిపోజిటరీ ఫుల్ అయిపోతుంది. పైగా మీ విండోస్ .venv ఫైల్స్ లైనక్స్ ఉన్న వేరే వాళ్ళ కంప్యూటర్ లో పనిచేయవు. ఎప్పుడూ దాన్ని gitignore చేయాలి.

❓ Frequently Asked Questions (FAQ)

Q Module, Package, Library కి తేడా మళ్లీ చెప్తారా?

ఒక .py ఫైల్ ని Module అంటాం. చాలా మాడ్యూల్స్ ఉన్న ఫోల్డర్ ని Package అంటాం. ఇలాంటి చాలా ప్యాకేజెస్ ని కలిపి ఆన్లైన్ లో పెడితే దాన్ని Library (ఉదా: Pandas) అంటాం.

Q requirements.txt పాతది అయిపోయిందా? వేరేవి వాడుతున్నారా?

ఇప్పటికీ ఇదే చాలా పాపులర్. కానీ కొంచెం మోడ్రన్ ప్రాజెక్ట్స్ లో Poetry (pyproject.toml) లేదా uv లాంటి ఫాస్ట్ టూల్స్ వాడుతున్నారు.
