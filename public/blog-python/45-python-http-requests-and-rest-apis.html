HTTP Requests & REST APIs (తెలుగులో)

🐍 Python 3.12+ 🟢 Chapter 45 of 65 📂 Phase 9: Databases and APIs 📅 2026 Edition
📌 Covered in this chapter: What is an API? · REST Architectural Constraints · HTTP Request Methods (GET, POST, PUT, PATCH, DELETE) · Status Codes · JSON Deserialization
API అంటే ఏంటి? ఒక యాప్ నుంచి ఇంకో యాప్ కి డేటాని ఎలా పంపించాలి? GET, POST, DELETE లాంటి HTTP కమాండ్స్ మరియు Status Codes (200, 404, 500) గురించి డీటెయిల్ గా నేర్చుకుందాం.
1API అంటే ఏంటి? REST ఫార్మాట్ ఎలా ఉంటుంది?

API (Application Programming Interface) అంటే రెండు వేర్వేరు సాఫ్ట్ వేర్స్ మాట్లాడుకోవడానికి ఒక బ్రిడ్జి లాంటిది. ఒకే భాష (పైథాన్, జావా) అవసరం లేకుండా, ఇవి నెట్వర్క్ ద్వారా డేటాని షేర్ చేసుకుంటాయి.

REST (Representational State Transfer) రూల్స్:

REST అనేది API లు ఎలా ఉండాలో చెప్పే కొన్ని రూల్స్:

  • Client-Server: ఫ్రంట్ ఎండ్ (UI) వేరుగా, బ్యాక్ ఎండ్ డేటాబేస్ వేరుగా ఉండాలి.
  • Statelessness: సర్వర్ ఎవరినీ గుర్తుపెట్టుకోదు. ప్రతి రిక్వెస్ట్ కి మనమే పాస్వర్డ్/టోకెన్ పంపాలి.
  • Resource-Oriented: వెబ్సైట్ లింక్స్ అన్నీ పనుల పేర్లతో కాకుండా వస్తువుల పేర్లతో (Nouns) ఉండాలి:
    • GET /api/users (అందరి యూజర్స్ ని ఇవ్వు)
    • POST /api/users (కొత్త యూజర్ ని క్రియేట్ చెయ్)
    • GET /api/users/42 (42 వ ఐడీ ఉన్న యూజర్ ని ఇవ్వు)

    204: ("No Content", "సక్సెస్! డిలీట్ చేసాను (చూపించడానికి డేటా లేదు)"),

    404: ("Not Found", "నువ్వు అడిగింది నా దగ్గర లేదు (లింక్ తప్పు)"),
    429: ("Too Many Requests", "చాలా స్పీడ్ గా అడుగుతున్నావ్.. కొంచెం ఆగు"),
    500: ("Internal Server Error", "నా కోడ్ లోనే ఎక్కడో క్రాష్ అయ్యింది (నాదే తప్పు)"),
    503: ("Service Unavailable", "సర్వర్ డౌన్ లో ఉంది (లేదా ట్రాఫిక్ ఎక్కువైంది)")

print("--- 🌐 ముఖ్యమైన HTTP Status Codes ---")
for code, (label, meaning) in status_code_dictionary.items():
    emoji = "✅" if code < 300 else ("⚠️" if code < 500 else "🔥")
    print(f"{emoji} HTTP {code} [{label:20}]: {meaning}")
🔍 REST బెస్ట్ ప్రాక్టీస్:

ఎప్పుడూ కరెక్ట్ నెంబర్ (Status Code) నే ఇవ్వాలి. ఒకవేళ యూజర్ లేకపోతే "404 Not Found" అని ఇవ్వాలి గానీ, 200 నెంబర్ తో పాటు లోపల "User not found" అని ఎర్రర్ పంపకూడదు.

2పైథాన్ `requests` లైబ్రరీతో API కాల్స్ చేయడం (GET, POST...)

పైథాన్ లో నెట్వర్క్ కి కనెక్ట్ అయ్యి డేటా తెచ్చుకోవడానికి requests లైబ్రరీని ఎక్కువగా వాడతారు:

  • requests.get(): డేటాని తెచ్చుకోవడానికి.
  • requests.post(): కొత్త డేటాని (JSON) సర్వర్ కి పంపడానికి (ఉదా: రిజిస్ట్రేషన్).
  • requests.put(): పాత డేటాని పూర్తిగా కొత్త డేటాతో రీప్లేస్ చేయడానికి.
  • requests.patch(): పాత డేటాలో కొంచెం భాగం మాత్రమే (ఉదా: ఈమెయిల్) మార్చడానికి.
  • requests.delete(): డేటాని డిలీట్ చేయడానికి.
💻 Example 2: Complete REST CRUD Method Execution Lifecycle
Python 3 ▶ Run in Compiler 
import json

# API కాల్స్ ని సిమ్యులేట్ చేయడానికి ఒక క్లాస్ రాద్దాం:
class SimulatedRESTClient:
    def __init__(self, base_url="https://api.example.com/v1"):
        self.base_url = base_url

    def get_user_profile(self, user_id):
        endpoint = f"{self.base_url}/users/{user_id}"
        print(f"👉 [GET] ఈ లింక్ ని రిక్వెస్ట్ చేస్తున్నాం: {endpoint}")
        # 200 OK తో డేటా వచ్చినట్టు:
        return {"status": 200, "data": {"id": user_id, "name": "Balaji"}}

    def create_user(self, payload):
        endpoint = f"{self.base_url}/users"
        print(f"👉 [POST] కొత్త యూజర్ ని క్రియేట్ చేస్తున్నాం: {json.dumps(payload)}")
        # 201 Created రెస్పాన్స్:
        return {"status": 201, "data": {"id": 105, **payload}}

    def update_user_email(self, user_id, new_email):
        endpoint = f"{self.base_url}/users/{user_id}"
        print(f"👉 [PATCH] ఈమెయిల్ మాత్రమే అప్డేట్ చేస్తున్నాం: {{'email': '{new_email}'}}")
        return {"status": 200, "data": {"id": user_id, "email": new_email}}

    def delete_user(self, user_id):
        endpoint = f"{self.base_url}/users/{user_id}"
        print(f"👉 [DELETE] యూజర్ ని డిలీట్ చేస్తున్నాం: {endpoint}")
        return {"status": 204, "data": None}

# క్లయింట్ తో టెస్ట్ చేద్దాం:
client = SimulatedRESTClient()
print("1. GET Request:")
print("   Response:", client.get_user_profile(42))

print("\n2. POST Request (Create):")
print("   Response:", client.create_user({"name": "Alex", "email": "alex@mail.com"}))

print("\n3. PATCH Request (Partial Update):")
print("   Response:", client.update_user_email(42, "new_mail@mail.com"))

print("\n4. DELETE Request:")
print("   Response:", client.delete_user(42))
🔍 PUT vs PATCH:

PUT వాడితే రికార్డ్ మొత్తం మారుతుంది (ఏదైనా మర్చిపోతే అది డిలీట్ అయిపోతుంది). PATCH వాడితే మనం చెప్పిన ఫీల్డ్ మాత్రమే మారుతుంది, మిగతావి పాతవే ఉంటాయి.

⚠️ Common Developer Pitfall: response.text ని మాన్యువల్ గా మార్చడం (JSON)

json.loads(response.text) వాడే బదులు, డైరెక్ట్ గా response.json() వాడటం బెస్ట్. ఇది ఆటోమాటిక్ గా స్పెషల్ క్యారెక్టర్స్ ని కరెక్ట్ గా అర్థం చేసుకుని పైథాన్ డిక్షనరీ లాగా ఇస్తుంది.

💻 Hands-on Interactive Practice Challenge

ఒక ఫంక్షన్ parse_api_response(status, json_str) రాయండి. 200-299 వస్తే (True, data) ఇవ్వాలి, వేరేవి వస్తే (False, ఎర్రర్ మెసేజ్) ఇవ్వాలి.

Python 3 Practice Challenge ▶ Run in Compiler 
import json

def parse_api_response(status_code, raw_body_str):
    try:
        data = json.loads(raw_body_str)
        if 200 <= status_code < 300:
            return True, data
        return False, f"ఎర్రర్ {status_code}: {data.get('error', 'Unknown Error')}"
    except json.JSONDecodeError:
        return False, "సర్వర్ నుంచి వచ్చిన డేటా JSON ఫార్మాట్ లో లేదు!"

success, res = parse_api_response(200, '{"user": "Balaji", "status": "active"}')
print(f"Status 200: Success={success}, Data={res}")

success_err, res_err = parse_api_response(404, '{"error": "User not found"}')
print(f"Status 404: Success={success_err}, Error={res_err}")

❓ Frequently Asked Questions (FAQ)

Q JSON కి పైథాన్ డిక్షనరీలకి తేడా ఏంటి?

పైథాన్ డిక్షనరీ మెమరీలో రన్ అవుతుంది. JSON అనేది ఆ డిక్షనరీని నెట్వర్క్ లో పంపడానికి వాడే ఒక "టెక్స్ట్ ఫార్మాట్" అంతే. json.dumps() వాడి డిక్షనరీని టెక్స్ట్ లా మార్చి నెట్ లో పంపుతాం.

Q Webhook అంటే ఏంటి?

మామూలు API అయితే మనమే సర్వర్ ని అడుగుతాం. Webhook లో, ఏదైనా జరిగితే సర్వరే డైరెక్ట్ గా మన యాప్ కి డేటా పంపుతుంది (ఉదా: పేమెంట్ సక్సెస్ అవ్వగానే ఆటోమాటిక్ గా మనకు మెసేజ్ వస్తుంది).
