15. జావా కన్‌స్ట్రక్టర్లు, 'this' కీవర్డ్ & Constructor Chaining (Constructors Mastery)

☕ Java (Java 21+ LTS) 🟢 Lesson 15 of 25 📂 Part 03: Arrays, Methods & OOP (Page 5 of 5) ⏱️ 26 min read
📌 Covered in this lesson: Default vs Parameterized Constructors · Constructor Overloading · Shadowing సమస్య & this కీవర్డ్ పరిష్కారం · Constructor Chaining using this()

సాఫ్ట్‌వేర్ అభివృద్ధిలో ఒక ఆబ్జెక్ట్ హీప్ మెమరీలో సృష్టించబడిన మరుక్షణమే, అది సరైన మరియు చెల్లుబాటు అయ్యే ప్రారంభ స్థితిలో (Valid Consistent State) ఉండటాన్ని నిర్ధారించడానికి జావా అందించిన అత్యంత శక్తివంతమైన మెకానిజం కన్‌స్ట్రక్టర్ (Constructor). కన్‌స్ట్రక్టర్ అనేది క్లాస్ పేరుతోనే సమానమైన పేరు కలిగి ఉండి, ఎటువంటి రిటర్న్ టైప్ లేని ఒక ప్రత్యేకమైన కోడ్ బ్లాక్. ఒకవేళ మనం క్లాస్‌లో ఏ కన్‌స్ట్రక్టర్ రాయకపోతే జావా కంపైలర్ ఉచితంగా డీఫాల్ట్ కన్‌స్ట్రక్టర్‌ను ఎలా అందిస్తుంది? మనం స్వయంగా ఒక్క పారామీటరైజ్డ్ కన్‌స్ట్రక్టర్ రాసిన వెంటనే ఆ డీఫాల్ట్ కన్‌స్ట్రక్టర్ ఎందుకు అదృశ్యమవుతుంది? పారామీటర్ పేరు మరియు ఇన్‌స్టాన్స్ వేరియబుల్ పేరు ఒకటే అయినప్పుడు వచ్చే వేరియబుల్ షాడోయింగ్ (Variable Shadowing) సమస్యను this కీవర్డ్ ఎలా పరిష్కరిస్తుంది? మరియు ఒక కన్‌స్ట్రక్టర్ నుండి మరొక కన్‌స్ట్రక్టర్‌ను this(...) ద్వారా పిలిచే కన్‌స్ట్రక్టర్ చైనింగ్ (Constructor Chaining) యొక్క కఠినమైన నియమాలు ఏమిటి? అనే సమగ్రమైన కోర్ అంశాలను ఈ పాఠంలో ప్రాక్టికల్ విశ్లేషణలతో నేర్చుకుందాం.

హాస్పిటల్ బర్త్ సర్టిఫికేట్ & పాస్‌పోర్ట్ వెరిఫికేషన్ అనాలజీ (The Hospital Birth Certificate & Passport Verification Analogy):

  1. 1. Constructor (ఆసుపత్రిలో శిశువు జనన ధ్రువీకరణ పత్రం - Birth Certificate): ఆసుపత్రిలో ఒక బిడ్డ జన్మించిన వెంటనే (Object Allocation in Heap), వైద్యులు ఆ బిడ్డ పుట్టిన సమయం, బరువు, తల్లిదండ్రుల పేర్లతో అధికారిక బర్త్ సర్టిఫికేట్ నమోదు చేసి గుర్తింపునిస్తారు. ఆ పత్రం లేకుండా బిడ్డకు సమాజంలో గుర్తింపు ఉండదు. జావాలో కన్‌స్ట్రక్టర్ కూడా ఆబ్జెక్ట్ పుట్టిన వెంటనే దాని ఫీల్డ్స్‌కు సరైన ప్రారంభ విలువలను కేటాయించి ఆబ్జెక్ట్‌ను సంసిద్ధం చేస్తుంది.
  2. 2. 'this' Keyword (సెల్ఫీ కెమెరా లేదా అద్దంలో తన ముఖం - Selfie Mirror Pointer): ఒక గదిలో పదిమంది వ్యక్తులు ఉన్నప్పుడు, 'నేను', 'నాది' అని తనను తాను ప్రత్యేకంగా గుర్తించడానికి అద్దం ఎలా ఉపయోగపడుతుందో, ఒక ఆబ్జెక్ట్ తన సొంత ఇన్‌స్టాన్స్ వేరియబుల్స్‌ను లేదా మెథడ్లను ఇతరుల నుండి వేరుచేసి సూచించుకోవడానికి ఉపయోగించే సెల్ఫ్-రిఫరెన్స్ పాయింటరే this.
  3. 3. Constructor Chaining (పాస్‌పోర్ట్ ఆఫీస్ స్టెప్పులు - Step-by-Step Passport Counters): పాస్‌పోర్ట్ కార్యాలయానికి వెళ్లినప్పుడు సాధారణ ఫారమ్ పట్టుకొచ్చిన వ్యక్తిని నేరుగా ఫైనల్ ఆఫీసర్ వద్దకు పంపరు. ముందుగా బేసిక్ కౌంటర్ this() వద్ద ఆధార్ తనిఖీ చేసి, అక్కడి నుండి ఫోటో కౌంటర్‌కు, చివరగా వెరిఫికేషన్ కౌంటర్‌కు చైన్ చేస్తారు. ప్రతి కౌంటర్ తన మునుపటి తనిఖీలను మొదటి నుండి చేయకుండా ఒకే మాస్టర్ కౌంటర్‌కు బదిలీ చేస్తుంది. కోడ్ పునరావృతం కాకుండా ఉండటానికి this() ఉపయోగపడుతుంది!

ఈ పాఠం పూర్తయ్యేసరికి మీరు Part 03 (Arrays, Methods & OOP) ను సంపూర్ణంగా ముగించి, క్లౌడ్ డేటాబేస్ కనెక్షన్ పూల్ మేనేజర్ ప్రాజెక్ట్‌ను సొంతంగా నిర్మించగల పరిపూర్ణ స్థాయికి చేరుకుంటారు!

1. కన్‌స్ట్రక్టర్ అంటే ఏమిటి? మెథడ్స్ తో 3 ప్రధాన తేడాలు (Constructor Fundamentals)

జావాలో ఒక ఆబ్జెక్ట్‌ను new కీవర్డ్ ఉపయోగించి సృష్టించినప్పుడు, ఆ ఆబ్జెక్ట్ యొక్క ఇన్‌స్టాన్స్ వేరియబుల్స్‌ను ప్రారంభించడానికి (Initialize) ఎగ్జిక్యూట్ అయ్యే ప్రత్యేకమైన కోడ్ బ్లాక్‌ను కన్‌స్ట్రక్టర్ అంటారు.

కన్‌స్ట్రక్టర్ vs సాధారణ మెథడ్ — 3 ప్రధాన తేడాలు:

  • 1. పేరు నియమం: కన్‌స్ట్రక్టర్ పేరు తప్పనిసరిగా అది ఉన్న క్లాస్ పేరుతో ఖచ్చితంగా సరిపోలాలి (Same name as Class). సాధారణ మెథడ్లకు ఏ పేరైనా పెట్టుకోవచ్చు.
  • 2. రిటర్న్ టైప్ నిషేధం: కన్‌స్ట్రక్టర్‌కు ఎటువంటి రిటర్న్ టైప్ ఉండకూడదు — చివరకు void కూడా ఉండకూడదు! ఒకవేళ మీరు పొరపాటున void Student() అని రాస్తే, జావా కంపైలర్ దాన్ని కన్‌స్ట్రక్టర్‌గా కాకుండా ఒక సాధారణ మెథడ్‌గా పరిగణిస్తుంది!
  • 3. కాల్ అయ్యే సమయం: new కీవర్డ్ రాసినప్పుడు JVM ఆటోమేటిక్‌గా కన్‌స్ట్రక్టర్‌ను ఒక్కసారే పిలుస్తుంది. సాధారణ మెథడ్ల మాదిరిగా మనం పదే పదే డాట్ ఆపరేటర్‌తో (obj.Student()) పిలవలేము.

2. డీఫాల్ట్ vs నో-ఆర్గ్ vs పారామీటరైజ్డ్ కన్‌స్ట్రక్టర్లు (The 3 Constructor Types)

జావాలో కన్‌స్ట్రక్టర్లు 3 ప్రధాన రకాలుగా ఉంటాయి:

// 1. డీఫాల్ట్ కన్‌స్ట్రక్టర్ (Default Constructor):
// డెవలపర్ ఏ కన్‌స్ట్రక్టర్ రాయనప్పుడు కంపైలర్ ఆటోమేటిక్‌గా జతచేసే నో-ఆర్గ్ కన్‌స్ట్రక్టర్.

// 2. యూజర్-డిఫైన్డ్ నో-ఆర్గ్ కన్‌స్ట్రక్టర్ (No-Argument Constructor):
public class User {
    String role;
    public User() {
        this.role = "GUEST"; // డీఫాల్ట్ స్టేట్ సెటప్
    }
}

// 3. పారామీటరైజ్డ్ కన్‌స్ట్రక్టర్ (Parameterized Constructor):
public User(String role) {
    this.role = role;
}

3. కంపైలర్ డీఫాల్ట్ కన్‌స్ట్రక్టర్ అదృశ్యమయ్యే నియమం (The Vanishing Constructor Rule)

జావాలో బిగినర్లందరూ ఎదుర్కొనే అత్యంత సాధారణ కంపైలేషన్ ఎర్రర్ ఇది:

❌ ది మిస్సింగ్ కన్‌స్ట్రక్టర్ ట్రాప్ (Compilation Error Trap):
public class Product {
    String name;
    public Product(String name) { // పారామీటరైజ్డ్ కన్‌స్ట్రక్టర్ రాశాం
        this.name = name;
    }
}

// వేరే క్లాస్‌లో:
Product p = new Product(); // ❌ COMPILE ERROR: constructor Product() is undefined!

కారణం: క్లాస్‌లో మీరు ఒక్క కన్‌స్ట్రక్టర్ కూడా రాయకపోతేనే జావా కంపైలర్ ఉచితంగా డీఫాల్ట్ నో-ఆర్గ్ కన్‌స్ట్రక్టర్‌ను ఇస్తుంది. కానీ మీరు స్వయంగా కనీసం ఒక్క పారామీటరైజ్డ్ కన్‌స్ట్రక్టర్ రాసినా, కంపైలర్ తన ఉచిత సేవను నిలిపివేస్తుంది! అందువల్ల మీకు నో-ఆర్గ్ కన్‌స్ట్రక్టర్ కూడా కావాలంటే, దాన్ని మీరే స్పష్టంగా కోడ్‌లో రాసుకోవాలి.

4. Constructor Overloading ఆర్కిటెక్చర్ (Multiple Ways to Initialize)

ఒకే క్లాస్‌లో విభిన్న సంఖ్య లేదా విభిన్న రకాల పారామీటర్లతో బహుళ కన్‌స్ట్రక్టర్లను నిర్వచించడాన్ని Constructor Overloading అంటారు. వినియోగదారులకు ఆబ్జెక్ట్‌ను వివిధ పరిస్థితులలో సృష్టించే వెసులుబాటు కల్పించడానికి ఇది అత్యంత ప్రయోజనకరంగా ఉంటుంది.

public class ServerConfig {
    String host;
    int port;
    int timeoutMs;

    public ServerConfig() { ... }                   // లోకల్‌హోస్ట్ డీఫాల్ట్స్
    public ServerConfig(String host, int port) { ... }   // కస్టమ్ హోస్ట్ & పోర్ట్
    public ServerConfig(String host, int port, int timeoutMs) { ... }
}

5. వేరియబుల్ షాడోయింగ్ & this కీవర్డ్ రక్షణ (The Shadowing Problem)

ఒక కన్‌స్ట్రక్టర్ లేదా మెథడ్‌లోని పారామీటర్ పేరు మరియు క్లాస్‌లోని ఇన్‌స్టాన్స్ వేరియబుల్ పేరు రెండూ ఒకేలా ఉన్నప్పుడు, లోకల్ పారామీటర్ ఇన్‌స్టాన్స్ వేరియబుల్‌ను కప్పివేస్తుంది (Shadows it). దీనినే Variable Shadowing అంటారు.

❌ షాడోయింగ్ బగ్ (Data Lost):
class Employee {
    String name;
    Employee(String name) {
        name = name; // ❌ లోకల్ వేరియబుల్ తనకే తాను అసైన్ అయింది!
    }
}
// ఇన్‌స్టాన్స్ ఫీల్డ్ 'name' ఇప్పటికీ null గానే ఉంటుంది!
✅ 'this' తో సరైన పరిష్కారం:
class Employee {
    String name;
    Employee(String name) {
        this.name = name; // ✅ this.name ప్రస్తుత ఆబ్జెక్ట్ ఫీల్డ్‌ను సూచిస్తుంది!
    }
}
// ఇన్‌స్టాన్స్ ఫీల్డ్‌లో డేటా విజయవంతంగా స్టోర్ అవుతుంది!

6. 'this' యొక్క 4 ప్రధాన వాస్తవ ఉపయోగాలు (The 4 Faces of this)

జావాలో this కీవర్డ్ అనేది ప్రస్తుత ఆబ్జెక్ట్‌ను పాయింట్ చేసే ఇంప్లిసిట్ రిఫరెన్స్ వేరియబుల్. ఇది ప్రధానంగా 4 ప్రయోజనాలకు ఉపయోగపడుతుంది:

  • 1. ఇన్‌స్టాన్స్ వేరియబుల్స్ రిఫరెన్స్: షాడోయింగ్ సమస్యను పరిష్కరించడానికి (this.id = id;).
  • 2. ప్రస్తుత క్లాస్ మెథడ్స్ ఇన్వోకేషన్: ప్రస్తుత క్లాస్ లోని మరొక మెథడ్‌ను స్పష్టంగా సూచించడానికి (this.validate();).
  • 3. కన్‌స్ట్రక్టర్ చైనింగ్: అదే క్లాస్‌లోని మరొక ఓవర్‌లోడెడ్ కన్‌స్ట్రక్టర్‌ను కాల్ చేయడానికి (this(...)).
  • 4. మెథడ్ ఆర్గ్యుమెంట్‌గా తనను తాను పంపడం లేదా రిటర్న్ చేయడం: Fluent Builder ప్యాటర్న్‌లో return this; ద్వారా మెథడ్ చైనింగ్‌ను సులభతరం చేయడం.

7. Constructor Chaining: this() ఇన్వోకేషన్ సూత్రాలు (DRY Principle)

ఓవర్‌లోడెడ్ కన్‌స్ట్రక్టర్లలో ఒకే రకమైన ఇనిషియలైజేషన్ కోడ్‌ను పదే పదే రాయడం వల్ల కోడ్ డూప్లికేషన్ పెరుగుతుంది. ఒక కన్‌స్ట్రక్టర్ నుండి అదే క్లాస్‌లోని మరొక కన్‌స్ట్రక్టర్‌ను పిలిచి పనిని అప్పగించడాన్ని Constructor Chaining using this() అంటారు.

public class DatabaseConnection {
    String url;
    int poolSize;

    // 1. నో-ఆర్గ్ కన్‌స్ట్రక్టర్: డీఫాల్ట్ విలువలతో మెయిన్ కన్‌స్ట్రక్టర్‌ను పిలుస్తుంది
    public DatabaseConnection() {
        this("jdbc:postgresql://localhost:5432/main_db", 10); // Calls 2-arg constructor
    }

    // 2. మాస్టర్ పారామీటరైజ్డ్ కన్‌స్ట్రక్టర్ (ఇక్కడే వాస్తవ లాజిక్ ఉంటుంది)
    public DatabaseConnection(String url, int poolSize) {
        this.url = url;
        this.poolSize = poolSize;
    }
}

8. First Statement Rule & రికర్సివ్ చైనింగ్ నిషేధం (Compiler Mandates)

this() కన్‌స్ట్రక్టర్ చైనింగ్ వాడేటప్పుడు జావా విధించిన రెండు అత్యంత కఠినమైన నియమాలు:

1. ఫస్ట్ స్టేట్‌మెంట్ రూల్ (The First Statement Mandate):
కన్‌స్ట్రక్టర్ బాడీలో this(...) కాల్ తప్పనిసరిగా మొట్టమొదటి లైన్‌గా మాత్రమే ఉండాలి! అంతకుముందు ప్రింట్ స్టేట్‌మెంట్లు లేదా వేరియబుల్ డిక్లరేషన్లు రాయకూడదు.

2. రికర్సివ్ చైనింగ్ నిషేధం (No Circular Chaining):
కన్‌స్ట్రక్టర్ A కన్‌స్ట్రక్టర్ B ని పిలిచి, మళ్లీ B కన్‌స్ట్రక్టర్ A ని పిలవడం (Circular / Recursive Constructor Invocation) పూర్తిగా నిషేధం! అలా రాస్తే కంపైలర్ తక్షణమే recursive constructor invocation ఎర్రర్ ఇస్తుంది.

10. డెమో 2: Constructor Chaining using this() (Execution Flow Inspection)

ఒక కన్‌స్ట్రక్టర్ నుండి మరొక కన్‌స్ట్రక్టర్‌కు ఎగ్జిక్యూషన్ కంట్రోల్ ఎలా గొలుసుకట్టుగా బదిలీ అవుతుందో స్టెప్-బై-స్టెప్ లాగ్‌లతో చూపే డెమో:

ConstructorChainingExecutionFlowDemo.java 
public class ConstructorChainingExecutionFlowDemo {

    public static class MicroserviceInstance {
        String serviceName;
        String environment;
        int maxReplicas;
        boolean enableTracing;

        // Constructor 1: No-arg (Calls Constructor 2)
        public MicroserviceInstance() {
            this("AuthService"); // Chaining to 1-arg
            System.out.println("  1️⃣ [Exiting Constructor 1: No-arg]");
        }

        // Constructor 2: 1-arg (Calls Constructor 3)
        public MicroserviceInstance(String name) {
            this(name, "DEVELOPMENT"); // Chaining to 2-arg
            System.out.println("  2️⃣ [Exiting Constructor 2: 1-arg ('" + name + "')]");
        }

        // Constructor 3: 2-args (Calls Master Constructor 4)
        public MicroserviceInstance(String name, String env) {
            this(name, env, 3, false); // Chaining to Master 4-arg
            System.out.println("  3️⃣ [Exiting Constructor 3: 2-args ('" + name + "', '" + env + "')]");
        }

        // Master Constructor 4: Performs actual assignment
        public MicroserviceInstance(String name, String env, int replicas, boolean tracing) {
            System.out.println("  4️⃣ [Executing Master Constructor 4 (Core Initialization)]");
            this.serviceName = name;
            this.environment = env;
            this.maxReplicas = replicas;
            this.enableTracing = tracing;
        }

        public void printTelemetry() {
            System.out.printf("🚀 Service: %-14s | Env: %-12s | Replicas: %d | Tracing: %b%n",
                    serviceName, environment, maxReplicas, enableTracing);
        }
    }

    public static void main(String[] args) {
        System.out.println("=================================================");
        System.out.println("🔗 CONSTRUCTOR CHAINING EXECUTION FLOW TRACER");
        System.out.println("=================================================
");

        System.out.println("Initiating: new MicroserviceInstance():");
        MicroserviceInstance svc = new MicroserviceInstance();

        System.out.println("
Final Initialized State:");
        svc.printTelemetry();

        System.out.println("
=================================================");
        System.out.println("✅ Master Constructor executed first, then callers in reverse!");
        System.out.println("=================================================");
    }
}

CloudDatabasePoolManagerEngine.java 
public class CloudDatabasePoolManagerEngine {

    public static class ConnectionPoolConfig {
        // Core Configuration Properties
        private final String poolName;
        private final String jdbcUrl;
        private final int minConnections;
        private final int maxConnections;
        private final int connectionTimeoutMs;
        private final boolean isSslRequired;

        // Constructor 1: Quick Dev Profile (Chains to Constructor 2)
        public ConnectionPoolConfig() {
            this("DevLocalPool", "jdbc:postgresql://localhost:5432/app_db");
        }

        // Constructor 2: Standard Profile (Chains to Master Constructor 3)
        public ConnectionPoolConfig(String poolName, String jdbcUrl) {
            this(poolName, jdbcUrl, 5, 20, 30000, true);
        }

        // Constructor 3: Master Fully-Parameterized Constructor with Strict Validation
        public ConnectionPoolConfig(String poolName, String jdbcUrl,
                                    int minConn, int maxConn, int timeoutMs, boolean ssl) {
            if (minConn < 0 || maxConn < minConn) {
                throw new IllegalArgumentException("Invalid pool boundaries: min must be >= 0 and max >= min");
            }
            this.poolName = poolName;
            this.jdbcUrl = jdbcUrl;
            this.minConnections = minConn;
            this.maxConnections = maxConn;
            this.connectionTimeoutMs = timeoutMs;
            this.isSslRequired = ssl;
        }

        // Constructor 4: Copy Constructor (Defensive Snapshot)
        public ConnectionPoolConfig(ConnectionPoolConfig source) {
            this(source.poolName + "_ReplicaSnapshot",
                 source.jdbcUrl,
                 source.minConnections,
                 source.maxConnections,
                 source.connectionTimeoutMs,
                 source.isSslRequired);
        }

        public void printAuditReport() {
            System.out.println("-------------------------------------------------");
            System.out.println("🛡️ CLOUD DATABASE POOL TELEMETRY SPECIFICATION");
            System.out.printf("Pool Name:       %s%n", poolName);
            System.out.printf("JDBC URL:        %s%n", jdbcUrl);
            System.out.printf("Connection Band: Min: %d | Max: %d (Scale Factor: %.1fx)%n",
                    minConnections, maxConnections, (double) maxConnections / Math.max(1, minConnections));
            System.out.printf("Timeout Window:  %d ms | SSL Encrypted: %b%n", connectionTimeoutMs, isSslRequired);
            System.out.println("-------------------------------------------------");
        }
    }

    public static void main(String[] args) {
        System.out.println("=================================================");
        System.out.println("☁️ ENTERPRISE CLOUD DATABASE POOL CONFIG MANAGER");
        System.out.println("=================================================
");

        // Profile 1: Using No-arg Chained Constructor
        ConnectionPoolConfig devConfig = new ConnectionPoolConfig();
        devConfig.printAuditReport();

        // Profile 2: Using Production Master Constructor
        ConnectionPoolConfig prodConfig = new ConnectionPoolConfig(
            "AwsAuroraPrimaryPool",
            "jdbc:postgresql://aurora-cluster.us-east-1.rds.amazonaws.com:5432/finance_prod",
            20, 100, 10000, true
        );
        prodConfig.printAuditReport();

        // Profile 3: Using Copy Constructor for Failover Replica
        ConnectionPoolConfig replicaConfig = new ConnectionPoolConfig(prodConfig);
        replicaConfig.printAuditReport();

        System.out.println("=================================================");
        System.out.println("🎉 PART 03 (ARRAYS, METHODS & OOP) COMPLETED 100%!");
        System.out.println("=================================================");
    }
}

12. ప్రొడక్షన్ పిట్‌ఫాల్స్, బెస్ట్ ప్రాక్టీసెస్ & 5 క్విజ్‌లు (Best Practices & Quizzes)

🚫 ప్రొడక్షన్‌లో నివారించాల్సిన 4 ఘోరమైన తప్పులు (Production Pitfalls):

  1. కన్‌స్ట్రక్టర్‌కు రిటర్న్ టైప్ రాయడం: public void Student() అని రాస్తే అది కన్‌స్ట్రక్టర్ అవ్వదు, కేవలం సాధారణ మెథడ్ అవుతుంది. new Student() రన్ చేసినప్పుడు డీఫాల్ట్ కన్‌స్ట్రక్టర్ రన్ అయి మీ కోడ్ అసలు ఎగ్జిక్యూట్ కాదు.
  2. కన్‌స్ట్రక్టర్ లోపల ఓవర్‌రైడబుల్ మెథడ్లను పిలవడం (Subclass Trap): కన్‌స్ట్రక్టర్ లోపల నుండి సబ్‌క్లాస్ ఓవర్‌రైడ్ చేయగల పబ్లిక్ మెథడ్లను పిలిస్తే, చైల్డ్ క్లాస్ ఆబ్జెక్ట్ పూర్తిగా ఇనిషియలైజ్ కాకముందే ఆ మెథడ్ రన్ అయి NullPointerException వస్తుంది.
  3. this() ను రెండవ లైన్‌లో రాయడం: this() తప్పనిసరిగా కన్‌స్ట్రక్టర్ లోని మొట్టమొదటి లైన్‌గా మాత్రమే ఉండాలి.
  4. కన్‌స్ట్రక్టర్‌లో భారీ ప్రాసెసింగ్ (DB Calls, Network Requests) చేయడం: కన్‌స్ట్రక్టర్ కేవలం వేరియబుల్స్‌ను ఇనిషియలైజ్ చేయడానికి మాత్రమే ఉండాలి. అందులో నెట్‌వర్క్ లేదా డిస్క్ ఐ/వో చేస్తే ఆబ్జెక్ట్ క్రియేషన్ బ్లాక్ అయిపోతుంది.

✨ ప్రొడక్షన్ గోల్డెన్ రూల్స్ (Golden Rules):

1. డ్రై కోడ్ (DRY): అన్ని చిన్న కన్‌స్ట్రక్టర్లను this(...) ద్వారా ఒకే ప్రధాన మాస్టర్ కన్‌స్ట్రక్టర్‌కు చైన్ చేయండి.
2. డిఫెన్సివ్ కాపీలు: మ్యూటబుల్ ఆబ్జెక్టులను (Date, Arrays) కన్‌స్ట్రక్టర్‌లో స్వీకరించేటప్పుడు వాటి క్లోన్ లేదా కాపీలను స్టోర్ చేసుకోండి.
3. ఇన్‌పుట్ వాలిడేషన్: తప్పుడు డేటాతో ఆబ్జెక్ట్ ఏర్పడకుండా ఉండేందుకు కన్‌స్ట్రక్టర్ ప్రారంభంలోనే వేలిడేట్ చేసి తగిన ఎక్సెప్షన్ విసరండి.
4. బిల్డర్ ప్యాటర్న్: 5 లేదా అంతకంటే ఎక్కువ కాన్ఫిగరేషన్ ఫీల్డ్స్ ఉన్నప్పుడు టెలిస్కోపింగ్ కన్‌స్ట్రక్టర్ల కంటే Builder Pattern ను వాడండి.

🧠 మీ అవగాహనను పరీక్షించుకోండి (5 Interactive Quizzes):

ప్రశ్న 1: కన్‌స్ట్రక్టర్‌కు రిటర్న్ టైప్ ఉంటుందా?

సమాధానం: ఉండదు! కన్‌స్ట్రక్టర్‌కు ఎటువంటి రిటర్న్ టైప్ ఉండదు (చివరకు void కూడా ఉండకూడదు).

ప్రశ్న 2: డెవలపర్ స్వయంగా పారామీటరైజ్డ్ కన్‌స్ట్రక్టర్ రాసినప్పుడు డీఫాల్ట్ కన్‌స్ట్రక్టర్ పరిస్థితి ఏమిటి?

సమాధానం: కంపైలర్ ఆటోమేటిక్ డీఫాల్ట్ కన్‌స్ట్రక్టర్‌ను అందించడం ఆపివేస్తుంది. నో-ఆర్గ్ కన్‌స్ట్రక్టర్ కావాలంటే డెవలపరే స్వయంగా రాయాలి.

ప్రశ్న 3: 'this' కీవర్డ్ ప్రధాన ప్రయోజనం ఏమిటి?

సమాధానం: ఇది ప్రస్తుత ఆబ్జెక్ట్ యొక్క ఇన్‌స్టాన్స్ వేరియబుల్స్ మరియు మెథడ్లను సూచించే ఇంప్లిసిట్ రిఫరెన్స్ వేరియబుల్. వేరియబుల్ షాడోయింగ్ సమస్యను పరిష్కరిస్తుంది.

ప్రశ్న 4: Constructor Chaining లో 'this()' కాల్ ఎక్కడ ఉండాలి?

సమాధానం: తప్పనిసరిగా కన్‌స్ట్రక్టర్ లోపలి మొట్టమొదటి స్టేట్‌మెంట్ (First Statement) గా మాత్రమే ఉండాలి.

ప్రశ్న 5: సర్క్యులర్ లేదా రికర్సివ్ కన్‌స్ట్రక్టర్ చైనింగ్ (A calls B, B calls A) జావాలో సాధ్యమా?

సమాధానం: సాధ్యం కాదు! జావా కంపైలర్ దీన్ని గుర్తించి తక్షణమే కంపైలేషన్ ఎర్రర్ (Recursive constructor invocation) ఇస్తుంది.
