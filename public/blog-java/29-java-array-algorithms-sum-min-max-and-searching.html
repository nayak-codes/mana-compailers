Java Array Algorithms: Sum, Average, Min/Max & Searching (తెలుగులో)

☕ Java 21+ LTS 🟢 Chapter 29 of 47 📂 Phase 7: Arrays & Matrices 📅 2026 Edition
📌 Covered in this chapter:

Sum & Average Calculations · Finding Maximum and Minimum · Second Largest Element ($O(N)$) · Linear Search Algorithm · Binary Search Algorithm ($O(\log N)$) · Arrays.binarySearch() Mechanics

అరేస్ మీద చేసే కామన్ ఆపరేషన్స్ (Algorithms) ఏంటి? మొత్తం నంబర్స్ ని కలపడం, యావరేజ్ కనుక్కోవడం, అందులో అన్నిటికన్నా పెద్దది (Max) లేదా చిన్నది (Min) ఏది అని కనిపెట్టడం, అలాగే అరే లో మనకు కావాల్సిన ఒక నంబర్ ని వెతకడం (Linear & Binary Search) లాంటి ఇంపార్టెంట్ కాన్సెప్ట్స్ ని ఈ చాప్టర్ లో డీకోడ్ చేద్దాం.

1. అరేలో ఉన్న నంబర్స్ ని కలపడం (Sum) & ఆవరేజ్ (Average)

అరే లో ఉన్న నంబర్స్ అన్నింటినీ కలపాలి అంటే ఒక వేరియబుల్ (counter) పెట్టుకుని లూప్ లో కలుపుకుంటూ వెళ్ళాలి:

int[] numbers = {10, 20, 30, 40, 50};
int sum = 0;

for (int num : numbers) {
    sum += num;
}
// వెరీ వెరీ ఇంపార్టెంట్: ఆవరేజ్ తీసేటప్పుడు sum ని double కి మార్చాలి!
double average = (double) sum / numbers.length;

ఎక్కువ మంది చేసే తప్పు:
ఒకవేళ sum = 15 ఉండి length = 4 ఉంటే.. మీరు మామూలుగా 15 / 4 అని రాస్తే జావా 3.75 బదులు 3 అని ఇంటిజర్ మాత్రమే ఇస్తుంది (పాయింట్ తర్వాత ఎగిరిపోతుంది). అందుకే దాన్ని ముందే (double) sum / length అని క్యాస్టింగ్ చేస్తే పర్ఫెక్ట్ రిజల్ట్ వస్తుంది.

2. మినిమమ్ & మాక్సిమమ్ కనుక్కోవడం (గోల్డెన్ రూల్)

అరే లో అతి పెద్ద నంబర్ లేదా చిన్న నంబర్ కనుక్కోవాలంటే ఒక రూల్ గుర్తుపెట్టుకోవాలి:

చేయకూడని తప్పు:
చాలామంది స్టార్టింగ్ లో int max = 0; అని తీసుకుని కంపేర్ చేస్తారు. ఒకవేళ మీ అరేలో అన్నీ నెగటివ్ నంబర్స్ ({-15, -8, -42}) ఉంటే ఏమవుతుంది? అరే లో లేకపోయినా 0 అనేది పెద్దది కాబట్టి అదే అవుట్పుట్ లో వస్తుంది. ఇది తప్పు!

కరెక్ట్ పద్ధతి:
ఎప్పుడైనా max లేదా min ని స్టార్ట్ చేసేటప్పుడు అరే లో ఉన్న మొదటి వాల్యూ తోనే (arr[0]) స్టార్ట్ చేయాలి:

int[] data = {-15, -8, -42, -99};
int max = data[0];
int min = data[0];

for (int i = 1; i < data.length; i++) {
    if (data[i] > max) max = data[i]; // పాత దానికంటే పెద్దదైతే అప్డేట్ చేస్తాం
    if (data[i] < min) min = data[i]; // పాత దానికంటే చిన్నదైతే అప్డేట్ చేస్తాం
}

3. సెకండ్ లార్జెస్ట్ నంబర్ కనుక్కోవడం (సింగిల్ పాస్)

అరేని సార్టింగ్ చేయకుండా (సార్ట్ చేస్తే టైమ్ పడుతుంది కదా).. ఒకేసారి లూప్ వేసి ఫస్ట్ పెద్దది, సెకండ్ పెద్దది ఎలా కనుక్కోవాలి?

int largest = Integer.MIN_VALUE; // జావాలో అతి చిన్న నంబర్ తో స్టార్ట్ చేస్తున్నాం
int secondLargest = Integer.MIN_VALUE;

for (int num : arr) {
    if (num > largest) {
        // కొత్తది largest కంటే పెద్దదైతే, పాత largest ని second కి ఇచ్చేసి కొత్తదాన్ని largest లో పెట్టుకుంటాం
        secondLargest = largest;
        largest = num;
    } else if (num > secondLargest && num != largest) {
        // largest కంటే చిన్నదే, కానీ second కంటే పెద్దదైతే..
        secondLargest = num;
    }
}

4. లీనియర్ సెర్చ్ vs బైనరీ సెర్చ్ (Linear vs Binary)

అల్గారిథమ్ రూల్స్ (Prerequisite) స్పీడ్ (Time) ఎలా పనిచేస్తుంది?
లీనియర్ సెర్చ్ (Linear Search) రూల్స్ ఏమీ లేవు (డేటా ఎలా పడితే అలా ఉన్నా పనిచేస్తుంది) O(N) (స్లో) మొదటినుంచి లాస్ట్ దాకా ఒక్కొక్కటి వరుసగా వెతుక్కుంటూ వెళ్తుంది.
బైనరీ సెర్చ్ (Binary Search) డేటా కచ్చితంగా సార్టింగ్ చేసి (ఆర్డర్ లో) ఉండాలి O(log N) (సూపర్ ఫాస్ట్) ఎగ్జాక్ట్ గా మధ్యలో చూస్తుంది. టార్గెట్ దానికన్నా చిన్నదైతే లెఫ్ట్ కి, పెద్దదైతే రైట్ సగం మాత్రమే వెతుకుతుంది.

బైనరీ సెర్చ్ పవర్ (ఎంత ఫాస్ట్?):
ఒకవేళ మీ దగ్గర 10 లక్షల (1,000,000) రికార్డ్స్ ఉన్నాయనుకోండి:
- లీనియర్ సెర్చ్ అయితే లక్ష సార్లు వెతుకుతుంది.
- బైనరీ సెర్చ్ అయితే కేవలం 20 సార్లు చెక్ చేసి చెప్పేస్తుంది!

5. బైనరీ సెర్చ్ లో Mid ని క్యాలిక్యులేట్ చేసే సేఫ్ ఫార్ములా

బైనరీ సెర్చ్ రాసేటప్పుడు మధ్యలో ఉన్న నంబర్ తెలుసుకోవడానికి mid = (left + right) / 2 అని రాస్తుంటారు. కానీ ఇది తప్పు!
ఒకవేళ అరే సైజు కోట్లలో ఉండి, left + right కలిపినప్పుడు 214 కోట్ల కన్నా ఎక్కువైతే జావాలో ఇంటిజర్ ఫుల్ అయిపోయి మైనస్ లోకి వెళ్లిపోతుంది (దీన్నే Overflow bug అంటారు).

ప్రొఫెషనల్ గా రాయాల్సిన ఫార్ములా:
$$\text{mid} = \text{left} + \frac{\text{right} - \text{left}}{2}$$

Beginner Example & Code Anatomy

☕ Main.java — Chapter 29 Core Example 
import java.util.Arrays;

public class Main {
    // 1. లీనియర్ సెర్చ్ (వరుసగా వెతకడం)
    public static int linearSearch(int[] arr, int target) {
        for (int i = 0; i < arr.length; i++) {
            if (arr[i] == target) {
                return i; // దొరికితే ఇండెక్స్ ఇస్తుంది
            }
        }
        return -1; // దొరక్కపోతే -1 ఇస్తుంది
    }

    // 2. బైనరీ సెర్చ్ (సగం సగం చేసుకుంటూ వెతకడం)
    public static int binarySearch(int[] arr, int target) {
        int left = 0;
        int right = arr.length - 1;

        while (left <= right) {
            int mid = left + (right - left) / 2; // ఇది సేఫ్ ఫార్ములా

            if (arr[mid] == target) {
                return mid; // మధ్యలోనే దొరికేసింది
            } else if (arr[mid] < target) {
                left = mid + 1; // నంబర్ పెద్దది కాబట్టి రైట్ కి వెళ్తాం
            } else {
                right = mid - 1; // నంబర్ చిన్నది కాబట్టి లెఫ్ట్ కి వెళ్తాం
            }
        }
        return -1; // ఇక్కడ కూడా దొరకలేదంటే లేనట్టే
    }

    public static void main(String[] args) {
        int[] scores = {45, 92, 18, 77, 85, 99, 63};

        System.out.println("=== 1. Sum, Average, Min & Max ===");
        int sum = 0;
        int min = scores[0];
        int max = scores[0];

        for (int s : scores) {
            sum += s;
            if (s < min) min = s;
            if (s > max) max = s;
        }
        double avg = (double) sum / scores.length; // (double) మర్చిపోవద్దు

        System.out.println("ఒరిజినల్ డేటా          : " + Arrays.toString(scores));
        System.out.println("మొత్తం (Sum)           : " + sum);
        System.out.printf("ఆవరేజ్ (Avg)           : %.2f%n", avg);
        System.out.println("అతి చిన్నది (Min)      : " + min);
        System.out.println("అతి పెద్దది (Max)      : " + max);

        System.out.println("
=== 2. సెకండ్ లార్జెస్ట్ నంబర్ (Single-Pass) ===");
        int largest = Integer.MIN_VALUE;
        int secondLargest = Integer.MIN_VALUE;
        for (int s : scores) {
            if (s > largest) {
                secondLargest = largest;
                largest = s;
            } else if (s > secondLargest && s != largest) {
                secondLargest = s;
            }
        }
        System.out.println("ఫస్ట్ లార్జెస్ట్         : " + largest);
        System.out.println("సెకండ్ లార్జెస్ట్        : " + secondLargest);

        System.out.println("
=== 3. లీనియర్ సెర్చ్ (Linear Search) ===");
        int searchTarget = 85;
        int linearIdx = linearSearch(scores, searchTarget);
        System.out.println("లీనియర్ సెర్చ్ లో 85 దొరికిన ఇండెక్స్: " + linearIdx);

        System.out.println("
=== 4. బైనరీ సెర్చ్ (Binary Search) ===");
        Arrays.sort(scores); // బైనరీ సెర్చ్ కి ముందే సార్టింగ్ కచ్చితంగా ఉండాలి!
        System.out.println("సార్ట్ చేసిన డేటా        : " + Arrays.toString(scores));
        
        int binaryIdx = binarySearch(scores, searchTarget);
        System.out.println("మన బైనరీ సెర్చ్ రిజల్ట్    : " + binaryIdx);

        // జావాలో ముందే రాసిపెట్టిన బైనరీ సెర్చ్ కూడా ఉంది
        int builtinIdx = Arrays.binarySearch(scores, searchTarget);
        System.out.println("Arrays.binarySearch() : " + builtinIdx);
    }
}

🔍 Line-by-Line Code Explanation

double avg = (double) sum / scores.length;

డివైడ్ చేసే ముందు sum ని డబుల్ (పాయింట్స్) గా మార్చాము. లేకపోతే డెసిమల్స్ ఎగిరిపోయి తప్పు ఆన్సర్ వస్తుంది.

if (s > largest) { secondLargest = largest; largest = s; }

ఒకేసారి ఫస్ట్ ది, సెకండ్ ది రికార్డ్ చేస్కుంటున్నాం. దీనివల్ల సార్టింగ్ చేయాల్సిన పని తప్పుతుంది.

linearSearch(scores, searchTarget);

ఇది అరే లో ఉన్న నంబర్స్ ని 0 నుంచి వరుసగా ఒక్కొక్కటి వెతుక్కుంటూ వెళ్తుంది. డేటా సార్ట్ అవ్వకపోయినా పనిచేస్తుంది.

int mid = left + (right - left) / 2;

అరే సైజు కోట్లలో ఉన్నప్పుడు కూడా ఇంటిజర్ ఫుల్ అయిపోయి క్రాష్ అవ్వకుండా ఉండటానికి ఈ సేఫ్ ఫార్ములా వాడాము.

Arrays.binarySearch(scores, searchTarget);

ఇది జావా వాళ్ళు రాసిపెట్టిన ఫాస్ట్ బైనరీ సెర్చ్. సగం సగం కట్ చేసుకుంటూ వెతుకుతుంది కాబట్టి డేటా సార్ట్ అయ్యుండాలి.

Practical Real-World Example

☕ PracticalApplication.java — Industry Implementation 
public class PracticalApplication {
    public static void main(String[] args) {
        // రియల్ టైమ్ సినారియో: సర్వర్ రెస్పాన్స్ టైమ్ (మెట్రిక్స్)
        int[] latencyMs = {120, 85, 430, 210, 95, 850, 110, 340};

        int total = 0;
        int slaViolations = 0; // 300ms కన్నా ఎక్కువ టైమ్ తీసుకున్నవి
        int maxLatency = latencyMs[0];

        for (int lat : latencyMs) {
            total += lat;
            if (lat > 300) slaViolations++; // స్లో గా రెస్పాండ్ అయినవి కౌంట్ చేస్తున్నాం
            if (lat > maxLatency) maxLatency = lat; // అన్నిటికన్నా స్లో ఏదో రికార్డ్ చేస్తున్నాం
        }

        double avgLatency = (double) total / latencyMs.length;
        System.out.println("=== API రెస్పాన్స్ రిపోర్ట్ ===");
        System.out.printf("ఆవరేజ్ రెస్పాన్స్ టైమ్ : %.2f ms%n", avgLatency);
        System.out.println("అతి స్లో రెస్పాన్స్ (Max) : " + maxLatency + " ms");
        System.out.println("కండిషన్ ఫెయిల్ అయినవి (>300ms) : " + slaViolations + " రిక్వెస్ట్స్");
    }
}

⚠️ Common Mistakes & Professional Best Practices
  • అరే సార్ట్ చేయకుండా బైనరీ సెర్చ్ వాడటం. అలా వాడితే అది ఎక్కడెక్కడో వెతికి మైనస్ వాల్యూస్ ఇస్తుంది తప్ప కరెక్ట్ ఆన్సర్ ఇవ్వదు.
  • min లేదా max ని 0 తో స్టార్ట్ చేయడం. నెగటివ్ నంబర్స్ ఉన్నప్పుడు మొత్తం రిజల్ట్ తప్పు వస్తుంది. ఎప్పుడూ arr[0] తోనే స్టార్ట్ చేయాలి.
  • ఆవరేజ్ కనుక్కునేటప్పుడు (double) రాయడం మర్చిపోవడం. అప్పుడు 3.75 రావాల్సింది 3 అని వస్తుంది.
  • బైనరీ సెర్చ్ లో mid = (left + right) / 2 అని వాడటం. చిన్న అరేస్ కి పర్లేదు కానీ, లక్షల్లో డేటా ఉన్నప్పుడు క్రాష్ అయ్యే ఛాన్స్ ఉంది.

// Coding Challenge:
// థర్డ్ లార్జెస్ట్ (మూడవ అతిపెద్ద) నంబర్ కనుక్కోండి.
// టైమ్ కండిషన్: O(N) (అంటే ఒకేసారి లూప్ వేయాలి, సార్టింగ్ వాడకూడదు).
// అరే లో 3 కంటే తక్కువ నంబర్స్ ఉంటే, ఉన్నవాటిలో పెద్దది ప్రింట్ చేయాలి.

public class Challenge {
    public static int findThirdLargest(int[] arr) {
        long first = Long.MIN_VALUE;
        long second = Long.MIN_VALUE;
        long third = Long.MIN_VALUE;

        for (int num : arr) {
            if (num > first) {
                third = second;
                second = first;
                first = num;
            } else if (num > second && num != first) {
                third = second;
                second = num;
            } else if (num > third && num != second && num != first) {
                third = num;
            }
        }

        return third == Long.MIN_VALUE ? (int) first : (int) third;
    }

    public static void main(String[] args) {
        System.out.println("థర్డ్ లార్జెస్ట్: " + findThirdLargest(new int[]{10, 45, 99, 85, 23})); // 45
        System.out.println("థర్డ్ లార్జెస్ట్: " + findThirdLargest(new int[]{10, 20})); // 20 (3 నంబర్స్ లేవు కాబట్టి పెద్దదే ప్రింట్ అవుతుంది)
    }
}

💡 Frequently Asked Questions & Interview Insights

❓ Arrays.binarySearch() కి నంబర్ దొరకకపోతే -1 ఇస్తుందా?

ఎప్పుడూ -1 ఇవ్వదు. దొరకకపోతే అది ఎక్కడ ఉండాలో ఆ ఇండెక్స్ ని మైనస్ లో ఇస్తుంది `-(insertion_point + 1)`. ఉదాహరణకి -1 వచ్చిందంటే, ఆ నంబర్ ని మీరు 0వ ఇండెక్స్ లో పెట్టాలి అని అర్థం.

❓ బైనరీ సెర్చ్ అంత ఫాస్ట్ అయినప్పుడు ఇంకా లీనియర్ సెర్చ్ ఎందుకు వాడుతున్నారు?

బైనరీ సెర్చ్ వాడాలంటే డేటా ఆర్డర్ లో (సార్ట్ అయ్యి) ఉండాలి. సార్ట్ చేయడానికి చాలా టైమ్ పడుతుంది. మీరు ఒక్కసారే వెతకాలనుకుంటే అడ్డదిడ్డంగా ఉన్న డేటాలో డైరెక్ట్ లీనియర్ సెర్చ్ చేయడమే ఫాస్ట్. అదే పదే పదే వెతకాలనుకుంటే ఒకసారి సార్ట్ చేసి పెట్టుకుని బైనరీ సెర్చ్ వాడుకోవాలి.

❓ (double) sum / arr.length అంటే ఏం జరుగుతుంది?

జావాలో రెండు పూర్ణ సంఖ్యలని (int) భాగిస్తే ఆన్సర్ కూడా ఇంటిజర్ గానే వస్తుంది. అలా కాకుండా పాయింట్స్ లో రావాలంటే, డివైడ్ చేయకముందే అందులో ఒకదాన్ని డెసిమల్ గా మార్చాలి. అప్పుడే కరెక్ట్ ఆన్సర్ వస్తుంది.

🚀 Quick Chapter Recap

  • ఆవరేజ్ తీసేముందు కచ్చితంగా (double) అని క్యాస్టింగ్ చేయాలి.
  • Min, Max వెతికేటప్పుడు నెగటివ్ నంబర్స్ ఇష్యూ రాకుండా arr[0] తో స్టార్ట్ చేయాలి.
  • ఒకే లూప్ లో సార్ట్ చేయకుండానే సెకండ్ లార్జెస్ట్, థర్డ్ లార్జెస్ట్ లాంటివి కనుక్కోవచ్చు.
  • లీనియర్ సెర్చ్ స్లో కానీ సార్టింగ్ అవసరం లేదు. బైనరీ సెర్చ్ సూపర్ ఫాస్ట్ కానీ కచ్చితంగా సార్టింగ్ ఉండాలి.
  • బైనరీ సెర్చ్ లో mid కనుక్కోవడానికి ఎప్పుడూ left + (right - left) / 2 ఫార్ములానే వాడాలి.
