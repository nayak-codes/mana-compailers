Java String Comparison: == vs equals(), compareTo() & Hashing (తెలుగులో)

☕ Java 21+ LTS 🟢 Chapter 25 of 47 📂 Phase 6: Strings & Text Processing 📅 2026 Edition
📌 Covered in this chapter:

== vs equals() · Reference Equality vs Content Equality · equalsIgnoreCase() · compareTo() & Lexicographical Ordering · Null-Safe Comparison Patterns · String HashCode Caching

స్ట్రింగ్స్ ని ఒకదానితో ఒకటి ఎలా కంపేర్ చేయాలి? ఇక్కడ అందరూ చేసే అతి పెద్ద తప్పు `==` వాడటం. దాని బదులు `.equals()` ఎందుకు వాడాలో ఇక్కడ తెలుసుకుందాం. అలాగే క్యాపిటల్స్/స్మాల్స్ ఉన్నా మ్యాచ్ చేయడం (IgnoreCase), ఆల్ఫాబెట్ ఆర్డర్ లో సార్టింగ్ చేయడం, యాప్ క్రాష్ అవ్వకుండా యోడా (Yoda) ప్యాట్రన్ వాడటం నేర్చుకుందాం.

1. గోల్డెన్ రూల్: == కి, .equals() కి తేడా ఏంటి?

జావా ప్రోగ్రామర్స్ కి ఎప్పుడూ వచ్చే బగ్స్ లో ఇదొకటి. రెండు స్ట్రింగ్స్ సమానమో కాదో చెక్ చేయడానికి == వాడకూడదు:

1. == ఆపరేటర్ (అడ్రెస్ చెక్ చేస్తుంది):
ఇది రెండు వేరియబుల్స్ ర్యామ్ లో ఒకే అడ్రెస్ లో ఉన్నాయా లేదా అని మాత్రమే చూస్తుంది. లోపల ఏ అక్షరాలు ఉన్నాయో ఇది అసలు చూడదు!

2. .equals() మెథడ్ (లోపల ఉన్న కంటెంట్ చూస్తుంది):
ఇది అడ్రెస్ తో సంబంధం లేకుండా, లోపల ఉన్న అక్షరాలని ఒక్కొక్కటిగా చెక్ చేసి పర్ఫెక్ట్ గా చెప్తుంది.

String a = "hello";                  String b = "hello";
      |                                    |
      +-------------> [ 0x1000: "hello" ] <+  ===> (a == b) అంటే TRUE వస్తుంది (రెండు ఒకే SCP అడ్రెస్)

String c = new String("hello");
      |
      +-------------> [ 0x9500: "hello" ]     ===> (a == c) అంటే FALSE వస్తుంది (అడ్రెస్ లు వేరు కదా!)
                                              ===> a.equals(c) అంటే TRUE వస్తుంది (లోపల అక్షరాలు సేమ్ కాబట్టి)

2. స్మాల్స్/క్యాపిటల్స్ పట్టించుకోకూడదు అంటే: equalsIgnoreCase()

యూజర్ లాగిన్ అయ్యేటప్పుడు ఒక్కోసారి క్యాపిటల్స్ లో టైప్ చేయొచ్చు. అప్పుడు నార్మల్ గా చెక్ చేస్తే ఫెయిల్ అవుతుంది:

- equals("admin"): "ADMIN".equals("admin") అని చెక్ చేస్తే false వస్తుంది.
- equalsIgnoreCase("admin"): "ADMIN".equalsIgnoreCase("admin") అని చెక్ చేస్తే పర్ఫెక్ట్ గా true వస్తుంది.

ఇది ఇంటర్నల్ గా రెండిటినీ ముందు ఒకే ఫార్మాట్ కి (లోయర్ కేస్ కి) మార్చుకుని అప్పుడు చెక్ చేస్తుంది.

3. డిక్షనరీ ఆర్డర్ లో చెక్ చేయడం: compareTo()

స్ట్రింగ్స్ ని ఆల్ఫాబెట్ ఆర్డర్ లో (A-Z) సార్ట్ చేయాలంటే ఏ పదం ముందు వస్తుందో తెలియాలి. దానికి compareTo(String other) వాడతాం:

రిటర్న్ వాల్యూ మీనింగ్ ఎగ్జాంపుల్
< 0 (మైనస్ వాల్యూ) కరెంట్ పదం ఆల్ఫాబెటికల్ గా ముందు వస్తుంది. "Apple".compareTo("Banana") అంటే -1 వస్తుంది
0 (జీరో) రెండు పదాలు ఒకటే (equals() == true). "Java".compareTo("Java") అంటే 0 వస్తుంది
> 0 (ప్లస్ వాల్యూ) కరెంట్ పదం ఆల్ఫాబెటికల్ గా తర్వాత వస్తుంది. "Zebra".compareTo("Apple") అంటే 25 వస్తుంది

వచ్చే ఆ నంబర్ ఏంటంటే.. రెండిటి అక్షరాల మధ్య ఉన్న ASCII వాల్యూస్ డిఫరెన్స్ (Result = char1 - char2).
ఒకవేళ క్యాపిటల్స్ పట్టించుకోకుండా సార్ట్ చేయాలంటే compareToIgnoreCase() వాడాలి.

4. యాప్ క్రాష్ అవ్వకుండా చెక్ చేయడం (Yoda ప్యాట్రన్)

జావాలో ఏ వేరియబుల్ లో అయినా null ఉన్నప్పుడు దాని మీద ఏదైనా మెథడ్ కాల్ చేస్తే వెంటనే NullPointerException (NPE) వచ్చి యాప్ మొత్తం క్రాష్ అవుతుంది.

String userRole = null; // డేటాబేస్ నుంచి null వచ్చింది అనుకుందాం

// ఇది డేంజర్ (క్రాష్ అవుతుంది): ఎందుకంటే userRole లో ఏమీ లేదు కదా, దానికి equals ఎలా అడుగుతాం?
if (userRole.equals("ADMIN")) { ... }


// సేఫ్ ప్యాట్రన్ 1 (దీన్నే యోడా ప్యాట్రన్ అంటారు): ఫిక్స్డ్ గా ఉన్న వాల్యూ ని ముందు పెట్టాలి
if ("ADMIN".equals(userRole)) { // ఇది క్రాష్ అవ్వకుండా ప్రశాంతంగా false ఇచ్చేస్తుంది!
    ...
}


// సేఫ్ ప్యాట్రన్ 2 (Java 7+): Objects క్లాస్ వాడటం
if (java.util.Objects.equals(userRole, "ADMIN")) {
    ...
}

5. స్ట్రింగ్ HashCode అనేది ఫాస్ట్ ఎందుకు?

స్ట్రింగ్స్ ఎప్పుడూ మారవు కాబట్టి.. జావా ఒక్కొక్క స్ట్రింగ్ కి ఒక యూనిక్ ఐడీ లాంటిదాన్ని (32-bit hash code) ఇస్తుంది.

- జావా దీన్ని క్యాలిక్యులేట్ చేయడానికి 31 అనే ప్రైమ్ నంబర్ వాడి ఒక పెద్ద మ్యాథ్స్ ఫార్ములా వేస్తుంది.
- ఒకవేళ రెండు స్ట్రింగ్స్ equals() వాడినప్పుడు true అయితే, వాటి hashCode() కూడా కచ్చితంగా ఒకటే ఉంటుంది.
- స్ట్రింగ్ మారదు కాబట్టి జావా ఈ కోడ్ ని ముందే క్యాలిక్యులేట్ చేసి దాచుకుంటుంది. మనం ఎప్పుడు అడిగినా ఏ టైమ్ వేస్ట్ కాకుండా వెంటనే ఇచ్చేస్తుంది (O(1)).

🔍 Line-by-Line Code Explanation

literal1 == literal2

ఇవి రెండు ఒకే SCP ఆబ్జెక్ట్ ని పాయింట్ చేస్తున్నాయి కాబట్టి వాటి అడ్రెస్ ఒకటే ఉండి true వస్తుంది.

heapObj1.equals(heapObj2)

ఈ రెండిటి మెమరీ అడ్రెస్ లు వేరే అయినా సరే, మనం అడుగుతుంది లోపల టెక్స్ట్ సేమ్ ఉందా అని.. కాబట్టి equals() true ఇస్తుంది.

fruitA.compareTo(fruitB)

"A" కి "B" కి ఒక లెటర్ గ్యాప్ (వెనకపడి) ఉంది కాబట్టి -1 ఇస్తుంది.

"ADMIN".equals(nullableRole)

ముందు పదం ఉండటం వల్ల nullableRole లో null ఉన్నా సరే యాప్ క్రాష్ అవ్వకుండా false ఇచ్చేసి సైలెంట్ అవుతుంది (యూజ్ ఫుల్ ట్రిక్).

Practical Real-World Example

☕ PracticalApplication.java — Industry Implementation 
public class PracticalApplication {
    // యూజర్ కి యాక్సెస్ ఉందా లేదా చెక్ చేసే సెక్యూరిటీ మెథడ్
    public static boolean hasAccess(String userRole, String requiredRole) {
        // ముందు ఏమైనా null ఉంటే ఆపేయాలి
        if (userRole == null || requiredRole == null) {
            return false;
        }
        // అడ్డమైన స్పేస్ లు తీసేసి (trim), క్యాపిటల్స్/స్మాల్స్ పట్టించుకోకుండా (equalsIgnoreCase) చెక్ చేయాలి
        return userRole.trim().equalsIgnoreCase(requiredRole.trim());
    }

    public static void main(String[] args) {
        String inputRole1 = "  SUPER_ADMIN  ";
        String inputRole2 = "super_admin";
        String inputRole3 = null;

        System.out.println("యూజర్ 1 కి యాక్సెస్ ఉందా?: " + hasAccess(inputRole1, "SUPER_ADMIN")); // true
        System.out.println("యూజర్ 2 కి యాక్సెస్ ఉందా?: " + hasAccess(inputRole2, "SUPER_ADMIN")); // true
        System.out.println("యూజర్ 3 కి యాక్సెస్ ఉందా?: " + hasAccess(inputRole3, "SUPER_ADMIN")); // false (క్రాష్ అవ్వలేదు)
    }
}

⚠️ Common Mistakes & Professional Best Practices
  • యూజర్ నేమ్, పాస్వర్డ్స్ చెక్ చేయడానికి if (password == "secret") అని రాయడం. ఇలా రాస్తే ఎప్పటికీ లాగిన్ ఫెయిల్ అవుతూనే ఉంటుంది.
  • ఒక వేరియబుల్ లోకి డేటాబేస్ నుంచి ఏమొస్తుందో తెలియకుండా దానిమీద str.equals("ADMIN") వాడటం. దానివల్ల null వస్తే యాప్ క్రాష్ అవుతుంది.
  • compareTo() ఎప్పుడూ -1, 0, 1 మాత్రమే ఇస్తుంది అనుకోవడం. అది క్యారెక్టర్స్ మధ్య ఉన్న గ్యాప్ బట్టి -25, 32 లాంటి నంబర్స్ కూడా ఇస్తుంది.

// Coding Challenge:
// isAlphabeticallySorted(String[] words) అనే మెథడ్ రాయండి:
// 1. అరే లో ఉన్న పదాలు అన్నీ కరెక్ట్ ఆల్ఫాబెట్ ఆర్డర్ లో ఉన్నాయో లేదో compareTo() వాడి చెక్ చేయండి.
// 2. ఉంటే true, లేకపోతే false రిటర్న్ చేయండి.

public class Challenge {
    public static boolean isAlphabeticallySorted(String[] words) {
        for (int i = 0; i < words.length - 1; i++) {
            if (words[i].compareTo(words[i + 1]) > 0) {
                return false;
            }
        }
        return true;
    }

    public static void main(String[] args) {
        String[] list1 = {"Apple", "Banana", "Cherry", "Mango"};
        String[] list2 = {"Banana", "Apple", "Cherry"};

        System.out.println("లిస్ట్ 1 కరెక్ట్ ఆర్డర్ లో ఉందా?: " + isAlphabeticallySorted(list1)); // true
        System.out.println("లిస్ట్ 2 కరెక్ట్ ఆర్డర్ లో ఉందా?: " + isAlphabeticallySorted(list2)); // false
    }
}

💡 Frequently Asked Questions & Interview Insights

❓ రెండు స్ట్రింగ్స్ సమానమా కాదా చెక్ చేయడానికి ఎప్పుడూ .equals() మాత్రమే వాడాలా?

అవును! జావాలో స్ట్రింగ్స్ కంటెంట్ చెక్ చేయడానికి 100% ఎప్పుడూ .equals() మాత్రమే వాడాలి. అడ్రెస్ గురించి పట్టించుకోవాల్సిన పని మనకు లేదు.

❓ రెండు స్ట్రింగ్స్ కి .equals() true వస్తే.. వాటి hashCode() కూడా ఒకటే ఉంటుందా?

కచ్చితంగా ఒకటే ఉంటుంది. ఇది జావా రాసిన వాళ్ళు పెట్టిన రూల్. ఒకవేళ hashCode ఒకటే ఉంటే మాత్రం .equals() ఎప్పుడూ true అవ్వాలని లేదు (దాన్ని హ్యాష్ కొలిజన్ అంటారు).

  • compareTo() వాడి ఆల్ఫాబెట్స్ ని బట్టి వర్డ్స్ ని డిక్షనరీ ఆర్డర్ లో సార్ట్ చేయొచ్చు.
  • స్ట్రింగ్స్ కి hashCode ముందే సేవ్ అయ్యి ఉంటుంది కాబట్టి చాలా ఫాస్ట్ గా వస్తుంది.
