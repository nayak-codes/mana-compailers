Java Good Class Design: Packages, Access Control & SOLID Principles (తెలుగులో)

☕ Java 21+ LTS 🟢 Chapter 46 of 47 📂 Phase 10: Encapsulation & Access Modifiers 📅 2026 Edition
📌 Covered in this chapter:

Java Package System · Package Declaration & import · Package-Private vs Public API Design · Naming Conventions · Single Responsibility Principle · Cohesion vs Coupling · Encapsulation Violation Patterns (Anti-Patterns) · Access Modifier Decision Flowchart

ప్రొఫెషనల్ సాఫ్ట్వేర్ డెవలపర్స్ జావాలో క్లాసులు ఎలా డిజైన్ చేస్తారు? ఫైల్స్ అన్నింటినీ కలిపి ఒకే ఫోల్డర్ లో ఎందుకు పడేయరు? జావా Packages (ప్యాకేజెస్) ఎలా పనిచేస్తాయి? మన కోడ్ ని మంచి డిజైన్ తో (SOLID రూల్స్) క్లీన్ గా ఎలా రాయాలో ఈ చాప్టర్ లో డీటెయిల్డ్ గా నేర్చుకుందాం.

1. అసలు Java Package సిస్టమ్ అంటే ఏంటి?

Package అంటే సింపుల్ గా చెప్పాలంటే ఫోల్డర్. దీనివల్ల రెండు లాభాలు ఉన్నాయి:
1. ఆర్గనైజేషన్: వెయ్యి ఫైల్స్ ఒకే ఫోల్డర్ లో ఉంటే పిచ్చెక్కిపోతుంది, అందుకే నీట్ గా సపరేట్ ఫోల్డర్స్ లాగా పెట్టుకుంటాం.
2. సెక్యూరిటీ కంట్రోల్: "ఈ ఫోల్డర్ లో ఉన్నవాళ్లకు మాత్రమే ఇవి కనపడాలి, వేరే వాళ్ళకి కనపడకూడదు" అని రూల్స్ పెట్టుకోవచ్చు.

ప్యాకేజ్ పేర్లు ఎలా పెడతారు (రివర్స్ డొమైన్):

package com.ourcompiler.java.tutorial.phase10;
// com     = ఇది టాప్ లెవెల్
// ourcompiler = మన కంపెనీ పేరు
// java.tutorial.phase10 = ప్రాజెక్ట్ లోపల ఉన్న ఫోల్డర్స్

ఒక ప్యాకేజ్ ని ఇంకో ప్యాకేజ్ లో వాడుకోవడం (Import):

// ఫైల్ 1: Animal.java (com.zoo.animals ఫోల్డర్ లో ఉంది)
package com.zoo.animals;
public class Animal { ... }


// ఫైల్ 2: Main.java (com.zoo.management ఫోల్డర్ లో ఉంది)
package com.zoo.management;
import com.zoo.animals.Animal;     // ఆ ఫోల్డర్ లో ఉన్న Animal ని తీసుకుంటున్నాం
import com.zoo.animals.*;           // అందులో ఉన్న అన్నీ తీసుకుంటున్నాం (ప్రొడక్షన్ లో ఇలా వాడకూడదు)

2. ప్యాకేజ్ లోపలే దాచిపెట్టడం (Package-Private)

మనం public, private ఏమీ రాయకపోతే దాన్ని default అంటారు కదా. దీనివల్ల మన ప్యాకేజ్ లోపల మాత్రమే పనిచేసే సీక్రెట్ క్లాసులు రాసుకోవచ్చు:

// ప్యాకేజ్: com.company.payments

// ఇది బయట ఎవరికీ కనపడదు, కేవలం ఈ ప్యాకేజ్ లో వాళ్లకు మాత్రమే కనపడుతుంది
class EncryptionUtil {
    static String encrypt(String data) { ... }
}


class FraudDetector {
    boolean isSuspicious(double amount) { ... }
}


// ఇది పబ్లిక్! ప్యాకేజ్ బయటవాళ్ళకి ఇది ఒక్కటే కనపడుతుంది
public class PaymentProcessor {
    public boolean processPayment(String card, double amount) {
        String encrypted = EncryptionUtil.encrypt(card); // ఒకే ప్యాకేజ్ కాబట్టి ఓకే
        if (new FraudDetector().isSuspicious(amount)) return false; // ఇది కూడా ఓకే
        // పేమెంట్ ప్రాసెస్ అవుతుంది
        return true;
    }
}
// వేరే ప్యాకేజ్ వాళ్ళు కేవలం PaymentProcessor మాత్రమే పిలవగలరు, లోపల ఏం జరుగుతుందో వాళ్ళకి తెలియదు!

3. బెస్ట్ క్లాస్ డిజైన్ రూల్స్ (SOLID Principles)

1. Single Responsibility Principle (ఒక్కటే పని):
ఒక క్లాస్ కి ఎప్పుడూ ఒకే ఒక్క పని అప్పజెప్పాలి. అన్ని పనులూ ఒక్కడే చేస్తే కన్ఫ్యూజ్ అవుతాడు (God Class):

చెడ్డ కోడ్: class UserManager { అకౌంట్ క్రియేట్ చేయడం + ఈమెయిల్ పంపడం + డేటాబేస్ లో సేవ్ చేయడం }
మంచి కోడ్: class UserRegistrar, class EmailSender, class UserRepository అని సపరేట్ గా రాయాలి

2. High Cohesion (కలిసికట్టుగా ఉండటం):
క్లాస్ లో రాసిన వేరియబుల్స్, మెథడ్స్ అన్నీ ఒకదానికొకటి లింక్ అయి ఉండాలి. ఎంప్లాయీ క్లాస్ లో శాలరీకి సంబంధించిన ఫార్ములాస్ ఉండకూడదు, దానికి సపరేట్ పేరోల్ క్లాస్ రాయాలి.

3. Low Coupling (ఎవరికి వాళ్ళే యమునా తీరే):
ఒక క్లాస్ కి ఇంకో క్లాస్ కి మధ్య ఎక్కువ డిపెండెన్సీ ఉండకూడదు. రేపు ఒక క్లాస్ తీసేసినా ఇంకో క్లాస్ పనిచేసేలా ఉండాలి.

4. ముందు సెక్యూరిటీ:
ప్రతిదీ కళ్ళు మూసుకుని private పెట్టేయండి. అవసరమైతేనే వాడుకోవడానికి పర్మిషన్ ఇవ్వండి.

4. ఏ వేరియబుల్ కి ఏ పర్మిషన్ ఇవ్వాలో డిసైడ్ చేసే ఫ్లో-చార్ట్

ఒక వేరియబుల్ కి గానీ మెథడ్ కి గానీ పర్మిషన్ ఇచ్చేముందు ఈ ప్రశ్నలు వేసుకోండి:

ప్రశ్న 1: ఇది వేరే ప్యాకేజ్ వాళ్ళు కచ్చితంగా వాడుకోవాలా?
       అవును → public పెట్టు
       కాదు  → ప్రశ్న 2 కి వెళ్ళు

ప్రశ్న 2: వేరే ప్యాకేజ్ లో ఉన్న సబ్-క్లాసులు దీన్ని వాడుకుంటాయా?
       అవును → protected పెట్టు
       కాదు  → ప్రశ్న 3 కి వెళ్ళు


ప్రశ్న 3: కనీసం మన ప్యాకేజ్ లో ఉన్న వేరే క్లాసులు దీన్ని వాడతాయా?
       అవును → default (ఏమీ రాయొద్దు)
       కాదు  → private పెట్టు

గుర్తుపెట్టుకోండి: చాలా వరకు ఆన్సర్ ఎప్పుడూ private ఏ అవుతుంది!

5. మనం సాధారణంగా చేసే చెత్త తప్పులు (Anti-Patterns)

తప్పు 1: వేరియబుల్స్ కి Public పెట్టడం

// భయంకరమైన కోడ్!
class User { public String password; } // ఎవడైనా వచ్చి పాస్వర్డ్ మార్చేయగలడు!

తప్పు 2: అన్నీ గెట్టర్స్, సెట్టర్స్ తోనే నడిపించడం (Anemic Model)

// చూడటానికి బాగానే ఉంది కానీ మీనింగ్ లేదు:
account.setBalance(account.getBalance() - withdrawAmount); // లాజిక్ అంతా బయట క్లాస్ లో రాస్తున్నావ్!
// దానికి బదులు: account.withdraw(amount) అని రాస్తే లాజిక్ క్లాస్ లోపలే సేఫ్ గా ఉంటుంది.

తప్పు 3: లోపల ఉన్న లిస్ట్ ని బయటకి ఇచ్చేయడం

public List<String> getTags() { return tags; } // బయటవాడు దీంట్లో యాడ్/రిమూవ్ చేసేస్తాడు!
// కరెక్ట్ పద్ధతి:
public List<String> getTags() { return Collections.unmodifiableList(tags); }

Beginner Example & Code Anatomy

☕ Main.java — Chapter 46 Core Example 
import java.util.ArrayList;
import java.util.Collections;
import java.util.List;

// ---------------------------------------------------------------
// పర్ఫెక్ట్ గా డిజైన్ చేసిన క్లాస్: CourseEnrollment సిస్టమ్
// ---------------------------------------------------------------
class Course {
    private final String courseId;
    private final String title;
    private final int maxCapacity;
    private final List<String> enrolledStudentIds; // ఇది బయటకి వెళ్ళకూడదు!

    public Course(String courseId, String title, int maxCapacity) {
        if (maxCapacity <= 0) throw new IllegalArgumentException("సీట్స్ కనీసం 1 అయినా ఉండాలి.");
        this.courseId          = courseId;
        this.title             = title;
        this.maxCapacity       = maxCapacity;
        this.enrolledStudentIds = new ArrayList<>();
    }

    // వీటికి మార్చడానికి వీలు లేకుండా కేవలం గెట్టర్స్ మాత్రమే ఉన్నాయి
    public String getCourseId()  { return courseId; }
    public String getTitle()     { return title; }
    public int getMaxCapacity()  { return maxCapacity; }

    // ఎవరైనా జాయిన్ అయ్యారో లేదో కనుక్కోవడానికి ఫార్ములాస్ (Computed properties)
    public int getEnrolledCount()    { return enrolledStudentIds.size(); }
    public boolean isFullyBooked()   { return enrolledStudentIds.size() >= maxCapacity; }
    public int getAvailableSeats()   { return maxCapacity - enrolledStudentIds.size(); }

    // లిస్ట్ ని రీడ్-ఓన్లీ లాగా ఇస్తున్నాం (ఎవడూ యాడ్/రిమూవ్ చేయలేడు)
    public List<String> getEnrolledStudents() {
        return Collections.unmodifiableList(enrolledStudentIds);
    }

    // అసలైన లాజిక్ అంతా క్లాస్ లోపలే రాస్తున్నాం, బయట క్లాస్ కి పనిలేదు
    public boolean enroll(String studentId) {
        if (studentId == null || studentId.isBlank()) return false;
        if (isFullyBooked()) {
            System.out.println("  [ఎర్రర్] '" + title + "' కోర్సులో సీట్స్ ఫుల్!");
            return false;
        }
        if (enrolledStudentIds.contains(studentId)) {
            System.out.println("  [ఎర్రర్] స్టూడెంట్ " + studentId + " ఆల్రెడీ జాయిన్ అయ్యాడు.");
            return false;
        }
        enrolledStudentIds.add(studentId);
        System.out.printf("  [సక్సెస్] %s స్టూడెంట్ జాయిన్ అయ్యాడు. ఇంకా మిగిలిన సీట్స్: %d%n",
                studentId, getAvailableSeats());
        return true;
    }

    public boolean unenroll(String studentId) {
        boolean removed = enrolledStudentIds.remove(studentId);
        if (removed) System.out.printf("  [రిమూవ్] %s ని తీసేసాం.%n", studentId);
        return removed;
    }

    @Override
    public String toString() {
        return String.format("కోర్సు{ఐడీ='%s', పేరు='%s', సీట్స్=%d/%d, ఫుల్_అయ్యిందా=%b}",
                courseId, title, getEnrolledCount(), maxCapacity, isFullyBooked());
    }
}

public class Main {
    public static void main(String[] args) {
        System.out.println("=== కోర్స్ ఎన్రోల్మెంట్ సిస్టమ్ ===");
        Course javaAdvanced = new Course("CS-401", "అడ్వాన్స్డ్ జావా", 3);

        System.out.println("స్టార్టింగ్: " + javaAdvanced);

        System.out.println("
--- జాయిన్ అవుతున్న ఫేజ్ ---");
        javaAdvanced.enroll("STU-001");
        javaAdvanced.enroll("STU-002");
        javaAdvanced.enroll("STU-001"); // ఆల్రెడీ ఉన్నాడు కాబట్టి యాడ్ అవ్వడు
        javaAdvanced.enroll("STU-003"); // లాస్ట్ సీట్!
        javaAdvanced.enroll("STU-004"); // ఇది ఫెయిల్ అవ్వాలి, సీట్స్ లేవు

        System.out.println("
మొత్తం సీట్స్ ఫుల్: " + javaAdvanced);

        System.out.println("
--- లిస్ట్ ని హ్యాక్ చేయాలని చూద్దాం ---");
        List<String> students = javaAdvanced.getEnrolledStudents();
        System.out.println("ఉన్న స్టూడెంట్స్: " + students);
        try {
            students.add("STU-HACKER"); // బయటనుంచి దొంగతనంగా సీట్ తీసుకుందాం
        } catch (UnsupportedOperationException e) {
            System.out.println("హ్యాకింగ్ కుదరదు! Unmodifiable list మిమ్మల్ని బ్లాక్ చేసింది.");
        }

        System.out.println("
--- రిమూవ్ చేయడం ---");
        javaAdvanced.unenroll("STU-002");
        System.out.println("ఒకరిని తీసేసాక: " + javaAdvanced);

        System.out.println("
--- ఫైనల్ చెకింగ్ ---");
        System.out.printf("మిగిలిన సీట్స్: %d | సీట్స్ ఫుల్ ఆ: %b%n",
                javaAdvanced.getAvailableSeats(), javaAdvanced.isFullyBooked());
    }
}

// ఇది కాన్ఫిగరేషన్ మేనేజ్మెంట్ ప్రాజెక్ట్
// ఇంటర్నల్ హెల్పర్ (Package-private — బయట ప్యాకేజ్ వాళ్ళకి ఇది కనపడదు)
class ConfigValidator {
    static void validateKey(String key) {
        // కీ అనేది కచ్చితంగా క్యాపిటల్ లెటర్స్ లోనే ఉండాలి
        if (key == null || !key.matches("[A-Z_]+"))
            throw new IllegalArgumentException("తప్పు కాన్ఫిగ్ కీ: " + key);
    }
}

// ఇది పబ్లిక్ క్లాస్, అందరూ వాడుకోవచ్చు
public class PracticalApplication {
    static java.util.Map<String, String> config = new java.util.HashMap<>();

    public static void setConfig(String key, String value) {
        ConfigValidator.validateKey(key); // ఇక్కడే ప్యాకేజ్ లో ఉన్న వేరే క్లాస్ ని వాడుకుంటున్నాం
        config.put(key, value);
    }

    public static String getConfig(String key) {
        return config.getOrDefault(key, "వాల్యూ లేదు");
    }

    public static void main(String[] args) {
        setConfig("DB_HOST", "localhost");
        setConfig("DB_PORT", "5432");
        System.out.println("డేటాబేస్ హోస్ట్: " + getConfig("DB_HOST"));
        System.out.println("డేటాబేస్ పోర్ట్: " + getConfig("DB_PORT"));
        System.out.println("డేటాబేస్ పాస్వర్డ్: " + getConfig("DB_PASS")); // సెట్ చేయలేదు
    }

⚠️ Common Mistakes & Professional Best Practices
  • బయటకి పంపే లిస్ట్ లకి Collections.unmodifiableList() వాడకుండా డైరెక్ట్ గా రిటర్న్ చేసేయడం.
  • import com.company.*; అని అన్నీ ఇంపోర్ట్ చేసుకోవడం. దీనివల్ల ఏ ఫైల్ నుంచి ఏమొస్తుందో అర్థం కాక కన్ఫ్యూజ్ అవుతాం.
  • చిన్న ప్రాజెక్టే కదా అని ఫైల్స్ అన్నింటికీ అసలు ప్యాకేజ్ (Package) ఏ పెట్టకుండా వదిలేయడం. అలా చేస్తే ఇంటర్నల్ సెక్యూరిటీ ఉండదు.
  • లాజిక్స్ అన్నీ కంట్రోలర్ క్లాసుల్లో రాసి.. మెయిన్ క్లాసుల్లో కేవలం గెట్టర్స్, సెట్టర్స్ మాత్రమే వదిలేయడం (దీన్నే Anemic Model అంటారు).

// Coding Challenge:
// Playlist అనే క్లాస్ క్రియేట్ చేయండి:
// 1. private final String playlistName (మార్చడానికి వీల్లేదు).
// 2. private List<String> songs (లోపల యాడ్/రిమూవ్ అవ్వాలి, బయటకి వెళ్తే అన్-మాడిఫయబుల్ అయిపోవాలి).
// 3. పబ్లిక్ మెథడ్స్: addSong(String song), removeSong(String song), getSongs(), contains(String).
// 4. getSongs() అనేది ఎవరూ మార్చలేని లిస్ట్ ని రిటర్న్ చేయాలి.

import java.util.*;

class Playlist {
    private final String playlistName;
    private final List<String> songs = new ArrayList<>();

    public Playlist(String name) {
        if (name == null || name.isBlank()) throw new IllegalArgumentException("పేరు కావాలి.");
        this.playlistName = name.trim();
    }

    public String getPlaylistName() { return playlistName; }
    public List<String> getSongs()  { return Collections.unmodifiableList(songs); }
    public boolean contains(String song) { return songs.contains(song); }

    public void addSong(String song) {
        if (song != null && !song.isBlank() && !contains(song)) {
            songs.add(song.trim());
        }
    }

    public void removeSong(String song) { songs.remove(song); }
}

public class Challenge {
    public static void main(String[] args) {
        Playlist p = new Playlist("కోడింగ్ సాంగ్స్");
        p.addSong("లో-ఫై హిప్ హాప్"); p.addSong("చిల్ బీట్స్"); p.addSong("ఫోకస్ మ్యూజిక్");
        System.out.println("ప్లే-లిస్ట్: " + p.getSongs());
    }
}

💡 Frequently Asked Questions & Interview Insights

❓ జావాలో ఏ ప్యాకేజ్ పేరూ రాయకపోతే ఏమవుతుంది?

దాన్ని 'unnamed default package' అంటారు. చిన్న చిన్న ప్రయోగాలు చేయడానికి ఇది పర్వాలేదు కానీ, అసలైన ప్రాజెక్ట్స్ లో మాత్రం కచ్చితంగా ప్యాకేజ్ పేరు రాయాల్సిందే.

❓ Collections.unmodifiableList() అసలు ఏం చేస్తుంది?

ఇది మీ ఒరిజినల్ లిస్ట్ చుట్టూ ఒక ఇనుప కంచె లాంటిది వేస్తుంది. బయటనుంచి ఎవరైనా `add` లేదా `remove` అని పిలిస్తే.. వెంటనే క్రాష్ (Exception) అయ్యేలా చేస్తుంది.

❓ Cohesion కి, Coupling కి తేడా ఏంటి?

Cohesion అంటే ఒక క్లాస్ లో ఉన్న మెథడ్స్ కి వేరియబుల్స్ కి ఎంత మంచి లింక్ ఉంది అని. ఇది ఎక్కువగా ఉండాలి (High). Coupling అంటే ఒక క్లాస్ ఇంకో క్లాస్ మీద ఎంత ఆధారపడి ఉంది అని. ఇది తక్కువగా ఉండాలి (Low).
