Java Method Fundamentals, Anatomy & Call Stack Execution (తెలుగులో)

☕ Java 21+ LTS 🟢 Chapter 33 of 47 📂 Phase 8: Methods & Recursion 📅 2026 Edition
📌 Covered in this chapter:

Method ante enti? · DRY Principle · 6 Components of Method Anatomy · Calling Methods · JVM Call Stack Frames · Parameters vs Arguments · Varargs (int... args) · Return Statement & Unreachable Code

ఒక పెద్ద ప్రాజెక్ట్ లో ఒకే కోడ్ ని మళ్ళీ మళ్ళీ రాయకుండా ఉండటానికి మనం వాడేదే **Methods (మెథడ్స్)**. అసలు మెథడ్స్ అంటే ఏంటి? వాటిని ఎలా రాయాలి? మనం ఒక మెథడ్ ని పిలవగానే బ్యాక్-గ్రౌండ్ లో జావా Call Stack లో ఏం జరుగుతుంది? ఇన్‌పుట్స్ (Parameters) ఎలా పంపాలి? అవుట్పుట్ (Return) ఎలా తీసుకోవాలి? ఇవన్నీ ఈ చాప్టర్ లో డీటెయిల్డ్ గా నేర్చుకుందాం.

1. Method అంటే ఏంటి? అసలు ఎందుకు కావాలి?

కంప్యూటర్ ప్రోగ్రామింగ్ లో Method (మెథడ్) (దీన్నే ఫంక్షన్ అని కూడా అంటారు) అంటే కొంత కోడ్ ని ఒక బ్లాక్ లో పెట్టి దానికి ఒక పేరు ఇవ్వడం. మనం దాన్ని ఎప్పుడు పిలిస్తే (Call చేస్తే) అప్పుడు మాత్రమే ఆ కోడ్ రన్ అవుతుంది.

మెథడ్స్ ఎందుకు కావాలి? (DRY Principle):
- Don't Repeat Yourself (DRY): ఉదాహరణకి ఒక బిల్ కి టాక్స్ కట్టే కోడ్ 20 లైన్లు ఉందనుకోండి. దాన్ని ప్రాజెక్ట్ లో 50 చోట్ల రాయాల్సి వస్తే.. ప్రతి చోటా కాపీ-పేస్ట్ చేయం! ఆ 20 లైన్ల కోడ్ ని calculateTax() అనే మెథడ్ లో పెట్టి, కావాల్సినప్పుడు ఆ పేరుతో పిలుస్తాం.
- క్లీన్ కోడ్: 5000 లైన్ల కోడ్ మొత్తం ఒకే చోట (మెయిన్ మెథడ్ లో) రాస్తే చదవడానికి పిచ్చెక్కిపోతుంది. దాన్ని చిన్న చిన్న మెథడ్స్ (ఒక్కోటి 10-20 లైన్లు) కింద విడగొడితే కోడ్ అర్థం చేసుకోవడం, బగ్స్ ఫిక్స్ చేయడం చాలా ఈజీ అవుతుంది.
- మెయింటెనెన్స్ ఈజీ: రేపు టాక్స్ 18% నుంచి 12% కి మారితే.. 50 చోట్ల మార్చాల్సిన అవసరం లేదు. మెథడ్ లో ఉన్న ఒక్క లైన్ మారిస్తే ప్రాజెక్ట్ మొత్తం మారిపోతుంది!

2. ఒక Method లో ఉండే 6 ప్రధాన భాగాలు

జావాలో ప్రతి మెథడ్ కి ఒక పర్ఫెక్ట్ స్ట్రక్చర్ (Anatomy) ఉంటుంది. ఆ 6 భాగాలు ఏంటంటే:

// Method హెడర్ స్ట్రక్చర్:
public static int calculateSum(int firstNumber, int secondNumber) {
  // Method బాడీ
  int total = firstNumber + secondNumber;
  return total;
}

1. Access Modifier (public, private): ఈ మెథడ్ ని వేరే క్లాస్ నుంచి పిలవొచ్చా లేదా అని చెప్తుంది.
2. Non-Access Modifier (static): ఇది ఆబ్జెక్ట్ కి సంబంధించిందా లేక డైరెక్ట్ గా క్లాస్ తోనే పిలవొచ్చా అనేది చెప్తుంది.
3. Return Type (int, double, String, void): ఈ మెథడ్ పని పూర్తయ్యాక మనకి రిటర్న్ గా ఏ టైప్ డేటా ఇస్తుంది అని చెప్తుంది. ఏమి ఇవ్వకపోతే void అని రాయాలి.
4. Method Name (calculateSum): ఇది ఆ మెథడ్ పేరు. camelCase లో ఉండాలి (ఉదాహరణకి getUserName(), sendEmail() లాగా వర్బ్ తో స్టార్ట్ అయితే మంచిది).
5. Parameters (int a, int b): మెథడ్ కి మనం బయట నుంచి పంపించే ఇన్పుట్స్. బ్రాకెట్స్ లోపల రాయాలి. ఏమీ అవసరం లేకపోతే ఖాళీగా () వదిలేయాలి.
6. Method Body ({ ... }): ఈ మెథడ్ ఏం చేయాలో ఆ కోడ్ అంతా ఈ బ్రాకెట్స్ లోపల రాయాలి.

3. JVM Call Stack అంటే ఏంటి? మెథడ్స్ ఎలా రన్ అవుతాయి?

మన ప్రోగ్రామ్ రన్ అవ్వగానే, JVM మెమరీలో Call Stack అనే ఒక రాక్ లాంటి దాన్ని రెడీ చేస్తుంది:
- Stack Frame: మనం ఒక మెథడ్ ని పిలవగానే, JVM ఒక కొత్త Stack Frame (స్టాక్ ఫ్రేమ్) ని క్రియేట్ చేసి ఆ స్టాక్ లో పెడుతుంది. అందులో ఆ మెథడ్ కి సంబంధించిన వేరియబుల్స్, ఇన్పుట్స్ అన్నీ ఉంటాయి.
- Frame Popping: ఆ మెథడ్ పని అవ్వగానే (లేదా return కి చేరుకోగానే) ఆ ఫ్రేమ్ ని స్టాక్ లోంచి తీసి పడేస్తుంది (Pop). దాంతో ఆ వేరియబుల్స్ అన్నీ మెమరీలోంచి డిలీట్ అయిపోతాయి!

CALL STACK ఎగ్జిక్యూషన్:
  
  [ add() Frame ]       <--- 3. add(10, 20) రన్ అవుతుంది; 30 ఇచ్చేసి డిలీట్ (pop) అయిపోతుంది!
  [ main() Frame ]      <--- 2. main() మెథడ్ add(10, 20) ని పిలిచింది.
  +------------------+
  | JVM Call Stack   |  <--- 1. ప్రోగ్రామ్ స్టార్ట్ అవ్వగానే JVM మెయిన్ మెథడ్ ని పుష్ చేస్తుంది.
  +------------------+

4. Parameters vs Arguments (ఈ రెండిటికి తేడా ఏంటి?)

చాలామందికి ఈ రెండూ ఒకటే అనుకుంటారు, కానీ టెక్నికల్ గా చిన్న తేడా ఉంది:

- Parameters (పారామీటర్స్): మెథడ్ ని రాసేటప్పుడు హెడర్ లో వాడే వేరియబుల్స్ ని Parameters అంటారు. ఇవి జస్ట్ ప్లేస్ హోల్డర్స్ లాంటివి.

static int add(int first, int second) // ఇక్కడ "first", "second" లు PARAMETERS

- Arguments (ఆర్గ్యుమెంట్స్): ఆ మెథడ్ ని పిలిచేటప్పుడు (Call చేసేటప్పుడు) మనం నిజంగా పంపించే నంబర్స్ లేదా వాల్యూస్ ని Arguments అంటారు.
int result = add(10, 20); // ఇక్కడ 10, 20 అనేవి ARGUMENTS

5. Varargs (Variable Arguments) `int... numbers`

మెథడ్ కి ఎన్ని నంబర్స్ పంపిస్తామో ముందే తెలియనప్పుడు (ఉదాహరణకి అప్పుడప్పుడు 2 నంబర్స్, అప్పుడప్పుడు 5 నంబర్స్ పంపిస్తుంటే) మనం Array వాడతాం. కానీ జావా 5 నుంచి Varargs అనే కొత్త ఫీచర్ వచ్చింది. ఇది వాడితే మనం ఎన్ని నంబర్స్ అయినా కామాలతో పంపించొచ్చు, అది ఆటోమాటిక్ గా Array లాగా తీసుకుంటుంది:

public static int sumAll(int... numbers) { // ఈ 3 డాట్స్ ని Varargs అంటారు
    int total = 0;
    for (int n : numbers) total += n;
    return total;
}

// ఇప్పుడు దీన్ని ఎలాగైనా పిలవొచ్చు:
sumAll();               // ఏమీ పంపకపోయినా ఆక్సెప్ట్ చేస్తుంది -> 0 వస్తుంది
sumAll(10, 20);         // 2 పంపొచ్చు -> 30 వస్తుంది
sumAll(5, 10, 15, 20);  // 4 పంపొచ్చు -> 50 వస్తుంది

Varargs రూల్స్:
1. ఒక మెథడ్ లో కేవలం ఒకటి మాత్రమే Varargs ఉండాలి.
2. ఒకవేళ వేరే పారామీటర్స్ కూడా ఉంటే, Varargs కచ్చితంగా అన్నిటికన్నా చివరన (Last) మాత్రమే ఉండాలి (ఉదా: (String title, int... scores)).

6. Return స్టేట్మెంట్ & Unreachable Code ఎర్రర్

return కీవర్డ్ కి రెండు పనులున్నాయి:
1. వాల్యూ ని తిరిగి ఇవ్వడం: void కాని మెథడ్స్ లో, రిజల్ట్ ని తిరిగి పంపించడానికి వాడతాం (ఉదా: return first + second;).
2. మధ్యలోనే ఆపేయడం: ఒకవేళ void మెథడ్ అయితే కనుక, జస్ట్ return; అని రాస్తే చాలు.. ఆ మెథడ్ అక్కడితో ఆగిపోయి వెనక్కి వెళ్లిపోతుంది (Early Exit).

Unreachable Code Error (చేరుకోలేని కోడ్):
మెథడ్ లో ఒకసారి return అన్నాక ఆ తర్వాత ఏ కోడ్ రాసినా అది ఎప్పటికీ రన్ అవ్వదు కదా! జావా అలా రన్ అవ్వని కోడ్ రాస్తే ఒప్పుకోదు, కంపైల్ ఎర్రర్ ఇస్తుంది:

static int getScore() {
    return 100; // ఇక్కడినుంచి వెనక్కి వెళ్లిపోతుంది
    System.out.println("Done"); // COMPILE ERROR: ఎందుకంటే ఇక్కడిదాకా రాదు కాబట్టి (Unreachable)!
}

Beginner Example & Code Anatomy

☕ Main.java — Chapter 33 Core Example 
public class Main {
    // 1. రెండు నంబర్స్ ని కలిపి ఆన్సర్ ని రిటర్న్ చేసే బేసిక్ మెథడ్
    static int add(int first, int second) {
        return first + second;
    }

    // 2. వేరు వేరు టైప్స్ ఉన్న పారామీటర్స్ తీసుకునే మెథడ్ (void కాబట్టి ఏమీ రిటర్న్ చేయదు)
    static void printStudentProfile(String name, int age, double gpa, boolean isEnrolled) {
        System.out.println("  పేరు      : " + name);
        System.out.println("  వయసు      : " + age + " ఇయర్స్");
        System.out.printf("  GPA       : %.2f%n", gpa);
        System.out.println("  స్టేటస్     : " + (isEnrolled ? "ఆక్టివ్" : "పాస్ ఔట్"));
    }

    // 3. కండిషన్ ఫెయిల్ అయితే మధ్యలోనే ఆపేయడం (Early Return)
    static void processWithdrawal(double balance, double amount) {
        if (amount <= 0) {
            System.out.println("  [ఎర్రర్] తప్పు అమౌంట్ ఎంటర్ చేసారు: $" + amount);
            return; // కండిషన్ ఫెయిల్ కాబట్టి కిందకి వెళ్లకుండా ఇక్కడే ఆపేసి వెనక్కి వెళ్ళిపోతుంది
        }
        if (amount > balance) {
            System.out.println("  [ఎర్రర్] అకౌంట్ లో బ్యాలెన్స్ లేదు! బ్యాలెన్స్: $" + balance);
            return; // Early exit
        }
        double remaining = balance - amount;
        System.out.printf("  [సక్సెస్] $%.2f డ్రా చేసారు. కొత్త బ్యాలెన్స్: $%.2f%n", amount, remaining);
    }

    // 4. Varargs మెథడ్ (ఎన్ని నంబర్స్ అయినా పంపించొచ్చు)
    static int calculateTotal(int... scores) {
        int sum = 0;
        for (int s : scores) {
            sum += s;
        }
        return sum;
    }

    public static void main(String[] args) {
        System.out.println("=== 1. బేసిక్ మెథడ్ కాల్ ===");
        int result = add(10, 20);
        System.out.println("add(10, 20) రిజల్ట్        : " + result);

        System.out.println("
=== 2. మల్టిపుల్ పారామీటర్స్ పంపడం ===");
        printStudentProfile("Ravi Kumar", 21, 3.85, true);

        System.out.println("
=== 3. Early Return (మధ్యలోనే ఆపేయడం) ===");
        processWithdrawal(500.0, -50.0);  // మైనస్ వాల్యూ ఇచ్చాం కాబట్టి ఆగిపోతుంది
        processWithdrawal(500.0, 700.0);  // బ్యాలెన్స్ కన్నా ఎక్కువ అడిగాం కాబట్టి ఆగిపోతుంది
        processWithdrawal(500.0, 150.0);  // అన్నీ కరెక్ట్ గా ఉన్నాయి కాబట్టి సక్సెస్ అవుతుంది

        System.out.println("
=== 4. Varargs మెథడ్ డెమో ===");
        System.out.println("2 నంబర్స్ పంపితే (10, 20)       : " + calculateTotal(10, 20));
        System.out.println("4 నంబర్స్ పంపితే (5, 15, 25, 35): " + calculateTotal(5, 15, 25, 35));
        System.out.println("ఏమీ పంపకపోతే ()                 : " + calculateTotal());
    }
}

🔍 Line-by-Line Code Explanation

static int add(int first, int second)

రెండు ఇంటిజర్స్ ని తీసుకుని, వాటని కలిపి ఇంటిజర్ ని తిరిగి (return) ఇచ్చే మెథడ్ ని రాసాము.

int result = add(10, 20);

add అనే మెథడ్ కి 10, 20 పంపించాం. అది వాటిని కలిపి 30 ని మనకి ఇచ్చింది, దాన్ని result లో సేవ్ చేసుకున్నాం.

if (amount > balance) return;

డ్రా చేసే అమౌంట్ బ్యాలెన్స్ కన్నా ఎక్కువ ఉంటే, కింద ఉన్న కోడ్ రన్ అవ్వకుండా ముందే ఆపేసి వెనక్కి వెళ్లిపోతుంది (Guard clause).

static int calculateTotal(int... scores)

int... అని వాడటం వల్ల మనం ఎన్ని నంబర్స్ అయినా కామాలు పెట్టి పంపొచ్చు. జావా వాటన్నిటినీ పట్టుకుని లోపల ఒక Array లాగా మార్చేసుకుంటుంది.

Practical Real-World Example

☕ PracticalApplication.java — Industry Implementation 
public class PracticalApplication {
    // రియల్ టైమ్ సినారియో: ఈ-కామర్స్ (ఆన్లైన్ షాపింగ్) కూపన్ డిస్కౌంట్ కాలిక్యులేటర్
    public static double applyCoupon(double orderTotal, String couponCode) {
        // కూపన్ ఏమీ ఇవ్వకపోయినా, కార్ట్ లో అమౌంట్ లేకపోయినా ఉన్నది ఉన్నట్టు ఇచ్చేయాలి
        if (orderTotal <= 0) return 0.0;
        if (couponCode == null || couponCode.isBlank()) return orderTotal;

        // కూపన్ పేరు బట్టి డిస్కౌంట్ వేయడం
        return switch (couponCode.toUpperCase().trim()) {
            case "WELCOME20" -> orderTotal * 0.80; // 20% డిస్కౌంట్
            case "FREESHIP"  -> Math.max(0.0, orderTotal - 15.0); // షిప్పింగ్ ఛార్జ్ $15 తగ్గింపు
            case "VIP50"     -> orderTotal >= 200.0 ? orderTotal * 0.50 : orderTotal; // $200 దాటితేనే 50% ఆఫ్
            default          -> orderTotal; // తప్పు కూపన్ ఇస్తే డిస్కౌంట్ ఉండదు
        };
    }

    public static void main(String[] args) {
        double cart = 250.0;
        System.out.println("=== చెక్-అవుట్ డిస్కౌంట్ సర్వీస్ ===");
        System.out.printf("ఒరిజినల్ బిల్ : $%.2f%n", cart);
        System.out.printf("WELCOME20 తో  : $%.2f%n", applyCoupon(cart, "WELCOME20"));
        System.out.printf("VIP50 తో      : $%.2f%n", applyCoupon(cart, "VIP50"));
        System.out.printf("తప్పు కూపన్ తో : $%.2f%n", applyCoupon(cart, "EXPIRED99"));
    }
}

⚠️ Common Mistakes & Professional Best Practices
  • void కాని మెథడ్స్ కి ఏ కండిషన్ లో అయినా సరే return కచ్చితంగా ఉండాలి. ఒకవేళ మీరు కేవలం if లో మాత్రమే రాసి వదిలేస్తే (కిందకి వెళ్తే రిటర్న్ ఉండదు కాబట్టి) కంపైల్ ఎర్రర్ వస్తుంది.
  • return లేదా break రాసిన తర్వాత దాని కింద ఏమైనా ప్రింట్ చేద్దాం అని రాస్తే, జావా "Unreachable code" అని ఎర్రర్ ఇస్తుంది.
  • Varargs ని వాడేటప్పుడు మొదటి పారామీటర్ గా వాడటం (ఉదా: (int... nums, String name)). ఇది కచ్చితంగా చివరలోనే ఉండాలి.
  • మెథడ్ ని పిలిచేటప్పుడు అడిగిన ఆర్డర్ లో కాకుండా మన ఇష్టం వచ్చిన ఆర్డర్ లో పారామీటర్స్ పంపడం.

☕ Challenge.java 
// Coding Challenge:
// ఒక నంబర్ ని పంపిస్తే అది ప్రైమ్ నంబర్ (Prime number) అవునా కాదా అని చెప్పే isPrime(int n) మెథడ్ ని రాయండి.
// 1. 1 కన్నా తక్కువుంటే false రావాలి.
// 2. ఒకవేళ ప్రైమ్ అయితే true రావాలి, లేకపోతే false.
// 3. main() లో 1 నుంచి 50 మధ్యలో ఎన్ని ప్రైమ్ నంబర్స్ ఉన్నాయో కౌంట్ చేసి ప్రింట్ చేయాలి.

public class Challenge {
    public static boolean isPrime(int n) {
        if (n <= 1) return false;
        if (n == 2) return true;
        if (n % 2 == 0) return false;
        for (int i = 3; i <= Math.sqrt(n); i += 2) {
            if (n % i == 0) return false;
        }
        return true;
    }

    public static void main(String[] args) {
        int primeCount = 0;
        for (int i = 1; i <= 50; i++) {
            if (isPrime(i)) {
                primeCount++;
            }
        }
        System.out.println("1 నుంచి 50 మధ్యలో ఉన్న ప్రైమ్ నంబర్స్ కౌంట్: " + primeCount);
    }
}

💡 Frequently Asked Questions & Interview Insights

❓ Function (ఫంక్షన్) కీ, Method (మెథడ్) కీ తేడా ఏంటి?

రెండూ చేసే పని ఒకటే! కాకపోతే సి లాంటి లాంగ్వేజెస్ లో అవి క్లాస్ కి బయట ఉంటాయి కాబట్టి ఫంక్షన్స్ అంటారు. జావాలో ప్రతిదీ కచ్చితంగా క్లాస్ లోపలే ఉంటుంది కాబట్టి వాటినే మెథడ్స్ అంటారు.

❓ static మెథడ్స్ కీ, non-static మెథడ్స్ కీ తేడా ఏంటి?

`static` అని ఉంటే ఆ మెథడ్ ని మనం ఆబ్జెక్ట్ క్రియేట్ చేయకుండానే డైరెక్ట్ గా పిలిచేయొచ్చు (`Math.sqrt()` లాగా). అదే నాన్-స్టాటిక్ (ఇన్స్టాన్స్) అయితే కచ్చితంగా ముందు ఆబ్జెక్ట్ క్రియేట్ చేసి దానితోనే పిలవాలి (`new Student().getName()`).

❓ ఒక మెథడ్ రన్ అవ్వడం అయిపోయాక అందులో ఉన్న వేరియబుల్స్ ఏమవుతాయి?

మెథడ్ లోపల రాసిన వేరియబుల్స్ ని లోకల్ వేరియబుల్స్ అంటారు. ఆ మెథడ్ రన్ అవ్వడం అయిపోగానే దాని Stack Frame డిలీట్ అయిపోతుంది కాబట్టి, ఆ వేరియబుల్స్ కూడా మెమరీలోంచి ఎగిరిపోతాయి.

🚀 Quick Chapter Recap

  • ఒకే కోడ్ ని మళ్ళీ మళ్ళీ రాయకుండా DRY (Don't Repeat Yourself) ప్రిన్సిపల్ పాటించడానికి మెథడ్స్ వాడతాం.
  • ప్రతి మెథడ్ కాల్ అయినప్పుడు JVM Call Stack లో ఒక కొత్త Stack Frame క్రియేట్ అయ్యి, అందులో ఆ వేరియబుల్స్ సేవ్ అవుతాయి.
  • మెథడ్ ని రాసేటప్పుడు తీసుకునేవి Parameters, పిలిచేటప్పుడు పాస్ చేసేవి Arguments.
  • ఎన్ని వాల్యూస్ పంపిస్తామో ముందే తెలియనప్పుడు Varargs (Type... name) వాడతాం.
  • return అంటే వాల్యూ ఇవ్వడమే కాదు, కండిషన్స్ ఫెయిల్ అయినప్పుడు కోడ్ ని అక్కడితో ఆపేసి బయటికి రావడానికి (Early Exit) కూడా వాడతారు.
