Java Class & Object Fundamentals: Blueprint vs Instance (తెలుగులో)

☕ Java 21+ LTS 🟢 Chapter 38 of 47 📂 Phase 9: Classes & Objects 📅 2026 Edition
📌 Covered in this chapter:

Class ante enti? · Object ante enti? · Blueprint vs Instance Analogy · Fields (Instance Variables) · Methods Inside Classes · Creating Objects with new · Dot Operator · Memory Model: Stack Reference + Heap Object · Multiple Objects from One Class

జావా అంటేనే ఆబ్జెక్ట్ ఓరియెంటెడ్ ప్రోగ్రామింగ్ (OOP). ఈ OOP కి రెండు పునాదులు ఉన్నాయి: అవే క్లాస్ మరియు ఆబ్జెక్ట్. అసలు క్లాస్ (బ్లూప్రింట్) కి, ఆబ్జెక్ట్ (రియల్ వస్తువు) కి తేడా ఏంటి? అందులో డేటాని ఎలా దాచాలి? new కీవర్డ్ తో ఆబ్జెక్ట్స్ ని మెమరీలో ఎలా క్రియేట్ చేయాలో ఈ చాప్టర్ లో చాలా డీటెయిల్డ్ గా నేర్చుకుందాం.

1. Class అంటే ఏంటి?

ఒక Class అనేది కేవలం ఒక బ్లూప్రింట్, డిజైన్, లేదా ప్లాన్ లాంటిది. ఇది ఆబ్జెక్ట్ ఎలా ఉండాలో ముందే చెప్తుంది. ఇందులో ప్రధానంగా రెండు ఉంటాయి:
1. Fields (వేరియబుల్స్/డేటా): ఆబ్జెక్ట్ కి ఏమేమి లక్షణాలు (లెంత్, కలర్, పేరు) ఉండాలి.
2. Methods (పనులు): ఆ ఆబ్జెక్ట్ ఏమేమి పనులు (నడవడం, పాడటం, క్యాలిక్యులేట్ చేయడం) చేయగలదు.

రియల్ వరల్డ్ ఎగ్జాంపుల్ — కారు బ్లూప్రింట్:
- ఒక కారు తయారు చేసేటప్పుడు ఇంజనీర్ ఒక బ్లూప్రింట్ (పేపర్ మీద డిజైన్) గీస్తాడు. ఆ డిజైన్ లో "కారుకి కలర్ ఉంటుంది, టైర్స్ ఉంటాయి, ఇంజిన్ ఉంటుంది" అని రాసి ఉంటుంది.
- కానీ ఆ పేపర్ మీద గీసిన బ్లూప్రింట్ లో కూర్చుని మనం డ్రైవ్ చేయగలమా? చేయలేము కదా! అది కేవలం డిజైన్ మాత్రమే.
- ఆ డిజైన్ ని చూసి కంపెనీ వాడు నిజమైన కార్లని తయారు చేస్తాడు. అప్పుడే మనం వాటిని వాడుకోగలం.

// 1. CLASS = డిజైన్ (ఇది రియల్ కాదు, జస్ట్ ప్లానింగ్ మాత్రమే)
class Car {
    String color;    // Field (కారుకి కలర్ ఉంటుంది అని చెప్తున్నాం)
    int speed;       // Field

void accelerate() { // Method (కారు చేసే పని)
        speed += 10;
    }
}


// 2. OBJECT = బ్లూప్రింట్ చూసి తయారు చేసిన రియల్ కారు
Car myCar = new Car(); // 'new' వాడితేనే రియల్ కారు రెడీ అయినట్టు

2. Object అంటే ఏంటి?

Object అంటే క్లాస్ అనే బ్లూప్రింట్ ని చూసి తయారు చేసిన ఒక నిజమైన వస్తువు (Instance). జావాలో ఇది రన్ టైమ్ లో JVM Heap Memory లో క్రియేట్ అవుతుంది.

ప్రతి ఆబ్జెక్ట్ కీ కిందవి ఉంటాయి:
1. అడ్రెస్: Heap మెమరీలో ఒక సొంత అడ్రెస్.
2. సొంత డేటా (State): క్లాస్ లో ఉన్న ప్రతి వేరియబుల్ కీ ఒక కాపీ ఈ ఆబ్జెక్ట్ కి వస్తుంది.
3. షేర్డ్ పనులు (Behavior): క్లాస్ లో రాసిన మెథడ్స్ అన్నీ ఇది వాడుకోగలదు.

CLASS (దీనికి మెమరీలో కాపీ ఉండదు, ఇది జస్ట్ డిజైన్)   HEAP MEMORY (రియల్ ఆబ్జెక్ట్స్)
  +----------------------------+    +----------------+  +----------------+
  | class Student {            |    | Object #1      |  | Object #2      |
  |   String name;             |    | name = "Ravi"  |  | name = "Priya" |
  |   int age;                 |    | age  = 20      |  | age  = 22      |
  |   void display() { ... }   |    | అడ్రెస్: 0x5A  |  | అడ్రెస్: 0x6B  |
  | }                          |    +----------------+  +----------------+
  +----------------------------+

3. Fields (ఇన్స్టాన్స్ వేరియబుల్స్)

క్లాస్ లోపల (కానీ మెథడ్ కి బయట) రాసే వేరియబుల్స్ ని Fields లేదా Instance Variables అంటారు:

class Student {
    String name;    // ప్రతి స్టూడెంట్ కీ వాళ్ళకంటూ ఒక పేరు ఉంటుంది (own copy)
    int age;        // వయసు
    double gpa;     // మార్కులు
}

కొన్ని రూల్స్:
- ఇవి ఆబ్జెక్ట్ తో పాటే Heap మెమరీలో స్టోర్ అవుతాయి.
- ఎన్ని ఆబ్జెక్ట్స్ క్రియేట్ చేస్తే, అన్ని సార్లు ఈ వేరియబుల్స్ కి వేరు వేరు కాపీలు వస్తాయి. (Ravi కి వేరే వయసు, Priya కి వేరే వయసు లాగా).
- మనం ఏ వాల్యూ ఇవ్వకపోతే జావా వీటిని ఆటోమాటిక్ గా 0, false, null లతో ఫిల్ చేస్తుంది.

4. Objects ఎలా క్రియేట్ చేయాలి? (new & డాట్ ఆపరేటర్)

new అనే కీవర్డ్ జావాకి ఈ మూడు పనులు చెప్తుంది:
1. Heap మెమరీలో కొత్త ఆబ్జెక్ట్ కి స్పేస్ బుక్ చెయ్.
2. అందులో ఉన్న వేరియబుల్స్ అన్నింటికీ డిఫాల్ట్ (0 లేదా null) వాల్యూస్ పెట్టు.
3. కన్స్ట్రక్టర్ ని పిలిచి సెటప్ చెయ్.

ఆబ్జెక్ట్ క్రియేట్ అయ్యాక, అందులో ఉన్న డేటాని గానీ పనులని గానీ వాడాలంటే dot (డాట్) ఆపరేటర్ . వాడాలి:

Student s = new Student(); // ఆబ్జెక్ట్ క్రియేట్ చేసాం
s.name = "Ravi";           // డాట్ వాడి పేరు పెట్టాం
s.age = 20;                // వయసు పెట్టాం
s.displayDetails();        // డాట్ వాడి మెథడ్ ని పిలిచాం

5. JVM మెమరీ మోడల్: Stack రిఫరెన్స్ + Heap ఆబ్జెక్ట్

STACK MEMORY (జిప్ కోడ్స్)         HEAP MEMORY (నిజమైన ఇల్లు)
  +-------------------+          +----------------------------+
  | s1 = 0x4A00       | ------>  | name: "Ravi"               |
  +-------------------+          | age : 20                   |
  | s2 = 0x7C00       | ------>  +----------------------------+
  +-------------------+          | name: "Priya"              |
                                  | age : 22                   |
                                  +----------------------------+

Null Pointer భయం:
ఒకవేళ మీరు పాయింటర్ (రిఫరెన్స్) క్రియేట్ చేసి new తో ఆబ్జెక్ట్ ఇవ్వకపోతే.. అది ఖాళీగా null ని పట్టుకుని ఉంటుంది. దానికి డాట్ . పెట్టి పిలిస్తే.. లేని ఇంట్లోకి వెళ్ళడానికి ట్రై చేసినట్టు జావా కి కోపం వచ్చి క్రాష్ అవుతుంది:

Student ghost = null;
ghost.displayDetails(); // ఎర్రర్: java.lang.NullPointerException వస్తుంది!

☕ Main.java — Chapter 38 Core Example 
class Student {
    // Fields (Instance Variables)
    String name;
    int age;

    // క్లాస్ లోపల రాసిన మెథడ్
    void displayDetails() {
        System.out.println(name + " - " + age);
    }
}

public class Main {
    public static void main(String[] args) {
        System.out.println("=== 1. బేసిక్ ఆబ్జెక్ట్ క్రియేషన్ ===");
        // Student student = new Student("Ravi", 20); // ఇది నెక్స్ట్ చాప్టర్ లో చూద్దాం

        System.out.println("
=== 2. Dot Operator (డాట్) తో ఫీల్డ్స్ కి వాల్యూస్ ఇవ్వడం ===");
        Student s1 = new Student(); // ఆబ్జెక్ట్ క్రియేట్ చేసాం (ఇప్పుడు s1 దగ్గర అడ్రెస్ ఉంటుంది)
        s1.name = "Priya Sharma";   // అడ్రెస్ పట్టుకుని లోపలికెళ్లి పేరు పెట్టాం
        s1.age  = 22;
        s1.displayDetails();

        System.out.println("
=== 3. ఒకే క్లాస్ నుంచి మల్టిపుల్ ఆబ్జెక్ట్స్ ===");
        Student s2 = new Student();
        s2.name = "Kiran Kumar";
        s2.age  = 21;

        Student s3 = new Student();
        s3.name = "Ananya Reddy";
        s3.age  = 23;

        // ఎవరి డేటా వాళ్లదే! ఒకరిది ఒకరికి మిక్స్ అవ్వదు
        System.out.println("ఆబ్జెక్ట్ s1: "); s1.displayDetails();
        System.out.println("ఆబ్జెక్ట్ s2: "); s2.displayDetails();
        System.out.println("ఆబ్జెక్ట్ s3: "); s3.displayDetails();

        System.out.println("
=== 4. ఆబ్జెక్ట్ ఐడెంటిటీ చెకింగ్ (రిఫరెన్స్ కాపీ) ===");
        // s1, s2 వేరు వేరు ఇళ్లు కాబట్టి ఫాల్స్ వస్తుంది
        System.out.println("s1 == s2 (ఒకే ఆబ్జెక్ట్ ఆ?) : " + (s1 == s2));

        Student s4 = s1; // s1 అడ్రెస్ ని s4 కి ఇచ్చాం. ఇప్పుడు ఇద్దరూ ఒకే ఇంటికి పాయింట్ చేస్తారు!
        System.out.println("s4 == s1 (ఒకే ఆబ్జెక్ట్ ఆ?) : " + (s4 == s1));
        
        s4.name = "MODIFIED via s4"; // s4 ద్వారా మార్చినా...
        System.out.println("s1 లో మార్పు వచ్చిందా? : " + s1.name); // s1 కి కూడా మారుతుంది, ఎందుకంటే ఇద్దరికీ ఉన్నది ఒకటే ఇల్లు!
    }
}

🔍 Line-by-Line Code Explanation

class Student { String name; int age; }

ఇది కేవలం ఒక ప్లాన్ (బ్లూప్రింట్). దీనికి మెమరీలో స్పేస్ ఉండదు.

Student s1 = new Student();

new అన్నప్పుడే Heap లో ఆబ్జెక్ట్ పుడుతుంది. ఆ ఆబ్జెక్ట్ అడ్రెస్ ని s1 అనే వేరియబుల్ పట్టుకుని ఉంటుంది.

s1.name = "Priya Sharma";

s1 లో ఉన్న అడ్రెస్ ని పట్టుకుని Heap లో ఉన్న అసలు ఆబ్జెక్ట్ దగ్గరికి వెళ్లి అందులో name ఫీల్డ్ లోకి పేరు పెడుతున్నాం.

Student s4 = s1;

ఇక్కడ కొత్త ఆబ్జెక్ట్ క్రియేట్ అవ్వదు. కేవలం s1 దగ్గర ఉన్న అడ్రెస్ ని కాపీ చేసి s4 కి ఇచ్చాం అంతే. ఇద్దరూ ఒకే ఆబ్జెక్ట్ ని చూస్తున్నారు.

Practical Real-World Example

☕ PracticalApplication.java — Industry Implementation 
class BankAccount {
    String accountNumber;
    String holderName;
    double balance;

    void showBalance() {
        System.out.printf("  అకౌంట్: %s | పేరు: %-12s | బ్యాలెన్స్: $%,.2f%n",
                accountNumber, holderName, balance);
    }
}

public class PracticalApplication {
    public static void main(String[] args) {
        BankAccount acc1 = new BankAccount();
        acc1.accountNumber = "SB-001-2026";
        acc1.holderName = "Ravi Kumar";
        acc1.balance = 15000.00;

        BankAccount acc2 = new BankAccount();
        acc2.accountNumber = "SB-002-2026";
        acc2.holderName = "Priya Devi";
        acc2.balance = 32500.75;

        System.out.println("=== బ్యాంక్ అకౌంట్స్ డేటా ===");
        acc1.showBalance();
        acc2.showBalance();
    }
}

⚠️ Common Mistakes & Professional Best Practices
  • new లేకుండా ఆబ్జెక్ట్ క్రియేట్ చేద్దాం అనుకోవడం. (ఉదా: Student s1 = Student();). ఇది జావాలో తప్పు, కచ్చితంగా new ఉండాలి.
  • ఆబ్జెక్ట్ క్రియేట్ చేయకుండానే (కేవలం null పెట్టుకుని) s1.name అని వాడటం. అప్పుడు NullPointerException వస్తుంది.
  • s4 = s1 అని రాసినప్పుడు మొత్తం ఆబ్జెక్ట్ కాపీ అయిపోతుంది అనుకోవడం. ఆబ్జెక్ట్ కాపీ అవ్వదు, కేవలం దాని అడ్రెస్ మాత్రమే కాపీ అవుతుంది.
  • వేరియబుల్స్ ని క్లాస్ లోపల కాకుండా, ఎక్కడో మెథడ్ లోపల క్రియేట్ చేసి వాటిని వేరే వాళ్ళు కూడా వాడుకోవచ్చు అనుకోవడం. మెథడ్ లోపల ఉంటే అవి లోకల్ వేరియబుల్స్ అయిపోతాయి.

// Coding Challenge:
// 1. Rectangle అనే ఒక క్లాస్ ని క్రియేట్ చేయండి. అందులో length, width అనే రెండు డబుల్ (double) ఫీల్డ్స్ ఉండాలి.
// 2. calculateArea() అనే మెథడ్ రాయండి (అది length * width ని రిటర్న్ చేయాలి).
// 3. calculatePerimeter() అనే మెథడ్ రాయండి (అది 2 * (length + width) ని రిటర్న్ చేయాలి).
// 4. మెయిన్ లో 3 రెక్టాంగిల్స్ ని క్రియేట్ చేసి వాటి వాల్యూస్ ప్రింట్ చేయండి.

class Rectangle {
    double length;
    double width;

    double calculateArea() {
        return length * width;
    }

    double calculatePerimeter() {
        return 2 * (length + width);
    }
}

public class Challenge {
    public static void main(String[] args) {
        Rectangle r1 = new Rectangle();
        r1.length = 10.0; r1.width = 5.0;

        Rectangle r2 = new Rectangle();
        r2.length = 8.5; r2.width = 3.0;

        System.out.printf("R1: ఏరియా=%.2f, చుట్టుకొలత=%.2f%n", r1.calculateArea(), r1.calculatePerimeter());
        System.out.printf("R2: ఏరియా=%.2f, చుట్టుకొలత=%.2f%n", r2.calculateArea(), r2.calculatePerimeter());
    }
}

💡 Frequently Asked Questions & Interview Insights

❓ క్లాస్ లోపల ఏ వేరియబుల్స్, మెథడ్స్ లేకుండా ఖాళీగా రాయొచ్చా?

రాసుకోవచ్చు (`class Empty {}`). కానీ అలా రాస్తే ప్రయోజనం ఏమీ ఉండదు. అయితే పెద్ద ప్రాజెక్ట్స్ లో కొన్నిసార్లు కేవలం గుర్తు పట్టడానికి (Marker Interfaces లాగా) ఇలా ఖాళీ క్లాసులు వాడుతుంటారు.

❓ ఒక క్లాస్ ని చూసి ఎన్ని ఆబ్జెక్ట్స్ తయారు చేయొచ్చు?

ఇన్ని అన్ని అని లిమిట్ లేదు, మీకు Heap మెమరీ ఫుల్ అయ్యేదాకా ఎన్ని కోట్ల ఆబ్జెక్ట్స్ అయినా క్రియేట్ చేసుకోవచ్చు. ఉదాహరణకి అమెజాన్ సర్వర్స్ లో సెకనుకి లక్షల ఆబ్జెక్ట్స్ ఒకే క్లాస్ నుంచి పుడుతూ ఉంటాయి.

❓ క్లాస్ కి, ఆబ్జెక్ట్ కి తేడా ఒక్క ముక్కలో చెప్పండి?

క్లాస్ అనేది పేపర్ మీద గీసిన కారు బొమ్మ (డిజైన్). ఆబ్జెక్ట్ అనేది ఫ్యాక్టరీలో రెడీ అయ్యి రోడ్డు మీద వెళ్తున్న రియల్ కారు.

🚀 Quick Chapter Recap

  • Class అనేది ఒక బ్లూప్రింట్. ఇది ఆబ్జెక్ట్ ఎలా ఉండాలి, ఏం పనులు చేయాలి అనేది డిసైడ్ చేస్తుంది.
  • Object అంటే క్లాస్ ని చూసి క్రియేట్ చేసిన రియల్ ఇన్స్టాన్స్. ఇది Heap మెమరీలో స్టోర్ అవుతుంది.
  • new కీవర్డ్ వాడినప్పుడే ఆబ్జెక్ట్ పుడుతుంది, డిఫాల్ట్ వాల్యూస్ వస్తాయి.
  • డాట్ (.) ఆపరేటర్ వాడి మనం ఆబ్జెక్ట్ లోపల ఉన్న డేటాని గానీ, మెథడ్స్ ని గానీ వాడుకుంటాం.
  • ప్రతి ఆబ్జెక్ట్ కి సపరేట్ మెమరీ ఉంటుంది. ఒక దాంట్లో వాల్యూ మారిస్తే ఇంకో ఆబ్జెక్ట్ కి ఏమీ కాదు.
