Java toString(), Encapsulation, Getters/Setters & Object Best Practices (తెలుగులో)

☕ Java 21+ LTS 🟢 Chapter 41 of 47 📂 Phase 9: Classes & Objects 📅 2026 Edition
📌 Covered in this chapter:

toString() Override · Why Default toString() is Useless · Object.equals() vs == · Encapsulation Principle · private Fields + public Getters & Setters · Data Validation in Setters · Fluent Builder Pattern · Immutable Classes

ఒక ఆబ్జెక్ట్ ని ప్రింట్ చేస్తే పిచ్చి పిచ్చి కోడ్ వస్తుందా? దాన్ని అర్థమయ్యేలా ఎలా మార్చాలి (toString)? మన క్లాస్ లో ఉన్న డేటాని ఎవడు పడితే వాడు మార్చేయకుండా సెక్యూరిటీ (Encapsulation) ఎలా ఇవ్వాలి? జావాలో Getters, Setters ఎందుకు అంత ఫేమస్? అసలు డేటా మార్చకుండా ఫ్రీజ్ (Immutable) ఎలా చేయాలో ఈ చాప్టర్ లో చూద్దాం.

1. toString() మెథడ్ — ఆబ్జెక్ట్ ని అందంగా ప్రింట్ చేయడం

జావాలో ప్రతి క్లాస్ కి డీఫాల్ట్ గా toString() అనే ఒక మెథడ్ ఫ్రీగా వస్తుంది (Object క్లాస్ నుంచి). కానీ దాన్ని ప్రింట్ చేస్తే Student@4aa298b7 అని ఒక చెత్త మెమరీ అడ్రెస్ (హ్యాష్) వస్తుంది.

దాన్ని తీసేసి మనకి అర్థమయ్యేలా మార్చడాన్నే Overriding toString() అంటారు:

class Student {
    String name;
    int age;

@Override
    public String toString() {
        return "స్టూడెంట్ పేరు: " + name + ", వయసు: " + age;
    }
}


Student s = new Student("Ravi", 20);
System.out.println(s); // ఆటోమాటిక్ గా మన toString() కాల్ అవుతుంది!
// అవుట్పుట్: స్టూడెంట్ పేరు: Ravi, వయసు: 20

toString() ఎప్పుడెప్పుడు ఆటోమాటిక్ గా రన్ అవుతుంది?
- System.out.println(object) అన్నప్పుడు.
- స్ట్రింగ్ పక్కన ప్లస్ పెట్టినప్పుడు: "వివరాలు: " + object

2. Encapsulation: ఆబ్జెక్ట్ డేటాకి సెక్యూరిటీ గార్డ్

Encapsulation (ఎన్క్యాప్సులేషన్) అనేది OOP లో ఒక మెయిన్ పిల్లర్ (పునాది). దీని అర్థం ఏంటంటే:
1. వేరియబుల్స్ అన్నీ కచ్చితంగా private పెట్టాలి (బయట వాళ్ళు డైరెక్ట్ గా ముట్టుకోకుండా).
2. ఆ డేటా చదవడానికి public Getter మెథడ్స్ ఇవ్వాలి.
3. ఆ డేటా మార్చడానికి public Setter మెథడ్స్ (కండిషన్స్ తో సహా) ఇవ్వాలి.

ఇది ఎందుకు ముఖ్యం?

// సెక్యూరిటీ లేకపోతే (Dangerous!)
class BankAccount { public double balance; }
account.balance = -50000.0; // ఎవడైనా సరే మైనస్ లోకి లాగేయొచ్చు!


// సెక్యూరిటీ ఉంటే (Safe!)
class BankAccount {
    private double balance; // ప్రైవేట్, ఎవరూ ముట్టుకోలేరు!


public void setBalance(double amount) {
        if (amount < 0) throw new IllegalArgumentException("బ్యాలెన్స్ మైనస్ లో ఉండకూడదు!");
        this.balance = amount;
    }
}

3. Getters and Setters ఎలా రాయాలి?

వీటికి ఒక ఫార్మాట్ (Naming convention) ఉంటుంది:
- Getter: public ReturnType getFieldName() అని రాయాలి. (boolean అయితే isActive() అని రాస్తారు).
- Setter: public void setFieldName(Type value) అని రాయాలి.

class Student {
    private String name;
    private int age;

// Getter (చదవడానికి)
    public String getName() { return name; }


// Setter (మార్చడానికి + వాలిడేషన్)
    public void setName(String name) {
        if (name == null || name.isBlank()) {
            throw new IllegalArgumentException("పేరు ఖాళీగా ఉండకూడదు!");
        }
        this.name = name.trim();
    }


public int getAge() { return age; }


public void setAge(int age) {
        if (age < 5 || age > 120) {
            throw new IllegalArgumentException("వయసు తప్పుగా ఉంది: " + age);
        }
        this.age = age;
    }
}

4. Fluent Builder ప్యాటర్న్ (లైన్ గా రాసుకుంటూ వెళ్ళడం)

Setters రాసేటప్పుడు void బదులు ఆ ఆబ్జెక్ట్ నే రిటర్న్ (return this) చేస్తే.. మనం కోడ్ ని చాలా అందంగా చైన్ లాగా రాసుకోవచ్చు:

class EmailMessage {
    private String from, to, subject, body;

public EmailMessage setFrom(String from)    { this.from = from; return this; }
    public EmailMessage setTo(String to)        { this.to = to; return this; }
    public EmailMessage setSubject(String sub)  { this.subject = sub; return this; }
    public EmailMessage setBody(String body)    { this.body = body; return this; }
}


// ఇంగ్లీష్ చదివినట్టు ఎంత బాగుందో చూడండి!
EmailMessage email = new EmailMessage()
        .setFrom("admin@company.com")
        .setTo("user@gmail.com")
        .setSubject("Welcome!")
        .setBody("నీ అకౌంట్ రెడీ అయిపొయింది.");

class Student {
    // సెక్యూరిటీ కోసం అన్నీ private
    private String name;
    private int age;
    private double gpa;
    private boolean isEnrolled;

    // కన్స్ట్రక్టర్
    public Student(String name, int age, double gpa) {
        setName(name);  // సెట్టర్ లో ఉన్న వాలిడేషన్ ఇక్కడ కూడా పనిచేస్తుంది!
        setAge(age);
        setGpa(gpa);
        this.isEnrolled = true;
    }

    // Getters
    public String getName()     { return name; }
    public int getAge()         { return age; }
    public double getGpa()      { return gpa; }
    public boolean isEnrolled() { return isEnrolled; }

    // సెక్యూరిటీ రూల్స్ (Setters)
    public void setName(String name) {
        if (name == null || name.isBlank())
            throw new IllegalArgumentException("పేరు ఖాళీగా ఉంచకూడదు.");
        this.name = name.trim();
    }

    public void setAge(int age) {
        if (age < 16 || age > 80)
            throw new IllegalArgumentException("వయసు 16 కి 80 కి మధ్యలో ఉండాలి: " + age);
        this.age = age;
    }

    public void setGpa(double gpa) {
        if (gpa < 0.0 || gpa > 4.0)
            throw new IllegalArgumentException("GPA 0.0 నుంచి 4.0 మధ్యలో ఉండాలి.");
        this.gpa = gpa;
    }

    public void setEnrolled(boolean enrolled) { this.isEnrolled = enrolled; }

    // మనకి నచ్చినట్టు toString ని మార్చుకోవడం
    @Override
    public String toString() {
        return String.format("Student{పేరు='%s', వయసు=%d, gpa=%.2f, జాయిన్_అయ్యాడా=%b}",
                name, age, gpa, isEnrolled);
    }

    public void displayDetails() {
        System.out.println(name + " - " + age);
    }
}

🔍 Line-by-Line Code Explanation

@Override public String toString()

Object క్లాస్ ఇచ్చిన చెత్త toString ని పక్కనపెట్టి, మనకి అర్థమయ్యే లాంగ్వేజ్ లో రాసుకుంటున్నాం.

if (gpa < 0.0 || gpa > 4.0) throw new IllegalArgumentException(...)

ఎవడైనా మైనస్ మార్కులు ఇస్తే మన ఆబ్జెక్ట్ పాడైపోతుంది. అందుకే సెక్యూరిటీ గార్డ్ (Setter) తో ఆపేస్తున్నాం.

setName(name); // in constructor

కన్స్ట్రక్టర్ లో మళ్ళీ వాలిడేషన్ కోడ్ అంతా కాపీ-పేస్ట్ చేయకుండా.. డైరెక్ట్ గా Setter నే వాడుకుంటున్నాం.

System.out.println("Student: " + student)

ప్లస్ (+) పెట్టి ఆబ్జెక్ట్ ని యాడ్ చేయగానే జావా వాడి toString() ని ఆటోమాటిక్ గా లాక్కుంటుంది.

Practical Real-World Example

☕ PracticalApplication.java — Industry Implementation 
class BankAccount {
    private final String accountId; // ఇది ఇంకెప్పటికీ మారదు (final)
    private String holderName;
    private double balance;

    public BankAccount(String accountId, String holderName, double initialDeposit) {
        this.accountId  = accountId;
        this.holderName = holderName;
        this.balance    = Math.max(0, initialDeposit);
    }

    // డిపాజిట్ చేయడానికి
    public void deposit(double amount) {
        if (amount <= 0) throw new IllegalArgumentException("డిపాజిట్ మైనస్ లో ఉండకూడదు!");
        balance += amount;
    }

    // డ్రా చేయడానికి
    public void withdraw(double amount) {
        if (amount <= 0 || amount > balance)
            throw new IllegalArgumentException("తప్పు అమౌంట్ లేదా బ్యాలెన్స్ లేదు: $" + amount);
        balance -= amount;
    }

    // చదవడానికి (కానీ డైరెక్ట్ గా మార్చడానికి Setters ఇవ్వలేదు)
    public double getBalance()    { return balance; }
    public String getHolderName() { return holderName; }

    @Override
    public String toString() {
        return String.format("BankAccount{id='%s', పేరు='%s', బ్యాలెన్స్=$%.2f}",
                accountId, holderName, balance);
    }
}

public class PracticalApplication {
    public static void main(String[] args) {
        BankAccount acc = new BankAccount("ACC-2026-001", "Ravi Kumar", 5000.0);
        System.out.println("=== బ్యాంక్ అకౌంట్ ఆపరేషన్స్ ===");
        System.out.println("స్టార్టింగ్: " + acc);
        acc.deposit(2000.0);
        acc.withdraw(800.0);
        System.out.println("ఫైనల్ గా  : " + acc);
    }
}

⚠️ Common Mistakes & Professional Best Practices
  • Getter మెథడ్స్ లో null రిటర్న్ చేయడం. దీనివల్ల వాడుకునేవాడికి NullPointerException వస్తుంది.
  • ఒక్కసారి సెట్ అయ్యాక ఎప్పటికీ మారకూడని వాటికి కూడా (ID, పుట్టినతేదీ లాంటివి) Setters రాసేయడం.
  • toString() రాసేటప్పుడు పైన @Override అని పెట్టడం మర్చిపోవడం. అది లేకపోతే కొన్నిసార్లు తప్పులు జరిగినా కంపైలర్ కి తెలియదు.
  • పనిగట్టుకుని ప్రైవేట్ పెట్టి, Setters లో కనీసం ఒక్క if కండిషన్ వాలిడేషన్ కూడా రాయకుండా వదిలేయడం.

// Coding Challenge:
// ఒక ఇమ్మ్యూటబుల్ (మార్చడానికి వీల్లేని) Point క్లాస్ ని క్రియేట్ చేయండి:
// 1. ఫీల్డ్స్: private final double x, private final double y.
// 2. కన్స్ట్రక్టర్ రాయాలి (Setters అసలే రాయకూడదు).
// 3. "(x, y)" అని వచ్చేలా toString() రాయాలి.
// 4. పాయింట్ నుంచి పాయింట్ కి దూరం (distance) కనుక్కునే మెథడ్ రాయాలి.

class Point {
    private final double x;
    private final double y;

    public Point(double x, double y) {
        this.x = x;
        this.y = y;
    }

    public double getX() { return x; }
    public double getY() { return y; }

    public double distanceTo(Point other) {
        double dx = this.x - other.x;
        double dy = this.y - other.y;
        return Math.sqrt(dx * dx + dy * dy);
    }

    @Override
    public String toString() {
        return String.format("(%.2f, %.2f)", x, y);
    }
}

public class Challenge {
    public static void main(String[] args) {
        Point a = new Point(0, 0);
        Point b = new Point(3, 4);
        System.out.println("పాయింట్ A: " + a);
        System.out.println("పాయింట్ B: " + b);
        System.out.printf("A నుంచి B కి దూరం: %.2f%n", a.distanceTo(b));
    }
}

💡 Frequently Asked Questions & Interview Insights

❓ అన్ని వేరియబుల్స్ కచ్చితంగా private పెట్టాల్సిందేనా?

అవును, అదొక మంచి బెస్ట్ ప్రాక్టీస్. వాళ్ళకి డేటా కావాలంటే Getters తో ఇస్తాం. కేవలం `public static final` అని ఉండే (Math.PI లాంటి) కాన్స్టెంట్స్ కి మాత్రమే ప్రైవేట్ పెట్టం ఎందుకంటే అవి ఎవరూ మార్చలేరు కాబట్టి.

❓ Immutable Class (ఇమ్మ్యూటబుల్ క్లాస్) అంటే ఏంటి?

ఏ ఆబ్జెక్ట్ ని అయితే ఒక్కసారి క్రియేట్ చేసాక అందులో డేటాని జీవితంలో మళ్ళీ మార్చలేమో.. దాన్నే Immutable అంటారు. ఇందులో వేరియబుల్స్ కి `final` పెడతారు, అసలు Setters అనేవే ఉండవు. జావాలో `String` అనేది దీనికి బెస్ట్ ఎగ్జాంపుల్.

❓ మిగతా లాంగ్వేజెస్ లాగా జావాలో ఆటోమాటిక్ గా గెట్టర్స్, సెట్టర్స్ ఎందుకు రావు?

కొత్తగా వచ్చిన జావా 16 నుంచి `record` అనే కీవర్డ్ తో వస్తున్నాయి. అది కాకుండా నార్మల్ గా కూడా Lombok అనే థర్డ్-పార్టీ లైబ్రరీ వాడి `@Getter`, `@Setter` అని రాస్తే మనమేం కోడ్ రాయక్కర్లేదు.

🚀 Quick Chapter Recap

  • ఆబ్జెక్ట్ ని నీట్ గా ప్రింట్ చేయడానికి toString() మెథడ్ ని మార్చుకుంటాం.
  • వేరియబుల్స్ కి private పెట్టి, మెథడ్స్ కి public పెట్టడమే ఎన్క్యాప్సులేషన్.
  • ఎవడైనా పిచ్చి వాల్యూస్ ఇస్తే బ్లాక్ చేయడానికి సెట్టర్స్ లో if కండిషన్స్ రాస్తాం.
  • కన్స్ట్రక్టర్ లో కూడా డైరెక్ట్ గా వాల్యూ అసైన్ చేయకుండా సెట్టర్స్ ని పిలిస్తే సెక్యూరిటీ ఇంకా బాగుంటుంది.
  • ఎప్పటికీ మారకూడని ఆబ్జెక్ట్స్ ని (IDలు, పాస్వర్డ్స్) ఇమ్మ్యూటబుల్ క్లాసులుగా (final) రాసుకోవాలి.
