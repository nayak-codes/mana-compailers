Java Access Modifiers: public, private, protected & Default Explained (తెలుగులో)

☕ Java 21+ LTS 🟢 Chapter 43 of 47 📂 Phase 10: Encapsulation & Access Modifiers 📅 2026 Edition
📌 Covered in this chapter:

Encapsulation ante enti? · Why Access Control Matters · 4 Access Levels · private: Strictest · default (package-private) · protected: Inheritance + Package · public: Widest · Access Modifier Comparison Table · Applying to Fields, Methods & Classes

క్లాస్ లో ఉన్న డేటాని ఎవరెవరు చూడొచ్చు, ఎవరు మార్చొచ్చు అనేది నిర్ణయించేదే Access Modifiers (యాక్సెస్ మోడిఫయర్స్). ఈ చాప్టర్ లో `private`, `default`, `protected`, `public` అనే 4 లెవెల్స్ ని బ్యాంక్ ఏటీఎమ్ (ATM) ఎగ్జాంపుల్ ద్వారా ప్రాక్టికల్ గా అర్థం చేసుకుందాం.

1. Encapsulation అంటే ఏంటి? (సెక్యూరిటీ ఎందుకు ముఖ్యం?)

Encapsulation (ఎన్క్యాప్సులేషన్) అంటే క్లాస్ లో ఉన్న డేటాని (Fields) బయటవాళ్లు ఎవరూ డైరెక్ట్ గా ముట్టుకోకుండా లాక్ చేయడం.

రియల్ వరల్డ్ ఎగ్జాంపుల్ — బ్యాంక్ ATM:
- మీరు ATM కి వెళ్లి కేవలం కార్డు పెట్టి, పిన్ నెంబర్ ఎంటర్ చేసి డబ్బులు తీసుకుంటారు కదా. (ఇది public ఇంటర్ఫేస్).
- కానీ ఆ ATM లోపల ఉన్న డేటాబేస్, క్యాష్ కౌంటింగ్ మోటార్స్, పాస్వర్డ్ వెరిఫికేషన్ అన్నీ మీకు కనపడవు, మీరు ముట్టుకోలేరు. (ఇది private ఇంప్లిమెంటేషన్).
- ఒకవేళ ఆ క్యాష్ బాక్స్ కి లాక్ లేకపోతే (అంటే పబ్లిక్ అయితే) ఏమవుతుందో ఊహించండి! జావాలో కూడా క్లాస్ లో ఉన్న డేటాకి ఇలాంటి సెక్యూరిటీ గార్డ్స్ కావాలి.

జావాలో ఈ గార్డ్స్ నే Access Modifiers అంటారు. ఇవి మన కోడ్ ని ఎవరెవరు వాడుకోవచ్చో కంట్రోల్ చేస్తాయి.

2. జావాలో 4 Access Levels (సెక్యూరిటీ లెవెల్స్)

Modifier అదే క్లాస్ లోపల అదే ప్యాకేజ్ (Package) లో Subclass (వేరే ప్యాకేజ్) మొత్తం ప్రాజెక్ట్ (ప్రపంచం)
private ✅ Yes ❌ No ❌ No ❌ No
default (ఏమీ రాయకపోతే) ✅ Yes ✅ Yes ❌ No ❌ No
protected ✅ Yes ✅ Yes ✅ Yes ❌ No
public ✅ Yes ✅ Yes ✅ Yes ✅ Yes

3. private — అత్యంత కఠినమైన సెక్యూరిటీ

private అని పెడితే ఆ వేరియబుల్ గానీ, మెథడ్ గానీ కేవలం ఆ క్లాస్ లోపల మాత్రమే పనిచేస్తుంది. బయట వాళ్ళెవరికీ అది కనపడదు.

ఎప్పుడు వాడాలి: క్లాస్ లో ఉన్న ప్రతి Field కి (డేటాకి) కచ్చితంగా private పెట్టాలి. అప్పుడే డైరెక్ట్ గా ఎవరూ మార్చలేరు.

class BankAccount {
    private double balance; // ఎవరూ డైరెక్ట్ గా ముట్టుకోలేరు!

private void logTransaction(String msg) { // ఇది మన సెక్యూరిటీ లాగ్ కోసం మాత్రమే
        System.out.println("[LOG] " + msg);
    }
}


class Main {
    public static void main(String[] args) {
        BankAccount acc = new BankAccount();
        // acc.balance = 9999; // ఎర్రర్: ఇది private కదా, నువ్వెలా మారుస్తావ్ అంటుంది!
    }
}

4. Default (Package-Private) — ఏమీ రాయకపోతే

మీరు public, private అని ఏమి రాయకపోతే, జావా దాన్ని default గా తీసుకుంటుంది. దీని అర్థం ఏంటంటే.. "నా ఫ్యామిలీ (అంటే ఒకే ప్యాకేజ్) లో ఉన్నవాళ్లు ఎవరైనా వాడుకోవచ్చు" అని అర్థం.

// ఫైల్: com/company/utils/MathHelper.java
package com.company.utils; // ప్యాకేజ్ పేరు utils

class MathHelper {            // ఏమీ రాయలేదు కాబట్టి default
    double computeTax(double income) { 
        return income * 0.20;
    }
}


// ఫైల్: com/company/ui/Dashboard.java
package com.company.ui;       // ఇది వేరే ప్యాకేజ్ (ui) కదా!
import com.company.utils.MathHelper;


class Dashboard {
    void show() {
        MathHelper h = new MathHelper(); // ఎర్రర్: ప్యాకేజ్ దాటిపోతే ఇది కనపడదు!
    }
}

5. protected — వారసులకు మాత్రమే

protected అని పెడితే ఆ క్లాస్ ఉన్న ప్యాకేజ్ లో ఉన్నవాళ్లతో పాటు, దాన్ని వారసత్వంగా తీసుకున్న (extends) సబ్-క్లాసులు కూడా (అవి వేరే ప్యాకేజ్ లో ఉన్నా సరే) వాడుకోవచ్చు.

// ఫైల్: Animal.java
public class Animal {
    protected String name;         // సబ్-క్లాసులు వాడుకోవచ్చు
    protected void breathe() {     
        System.out.println(name + " ఊపిరి పీల్చుకుంటోంది.");
    }
}

// ఫైల్: Dog.java (వేరే ప్యాకేజ్ లో ఉన్నా సరే)
public class Dog extends Animal {
    public void bark() {
        breathe(); // పేరెంట్ లో ఉన్న protected మెథడ్ ని వాడుకుంటుంది!
        System.out.println(name + " అరుస్తోంది: బౌ బౌ!"); // protected వేరియబుల్!
    }
}

6. public — ఓపెన్ టూ ఆల్

public అని పెడితే ప్రపంచంలో (ఆ ప్రాజెక్ట్ లో) ఎక్కడున్న క్లాస్ అయినా దాన్ని వాడుకోవచ్చు. ఇది మన API లో అందరికీ కనపడే మెయిన్ గేట్ లాంటిది.

ఎప్పుడు వాడాలి: వేరే వాళ్ళు మీ క్లాస్ ని వాడుకోవడానికి (మెథడ్స్, కన్స్ట్రక్టర్స్, getters/setters) మాత్రమే పబ్లిక్ పెట్టాలి. డేటాకి (Fields కి) ఎప్పుడూ పెట్టకూడదు.

థంబ్ రూల్:
ముందు ప్రతిదీ private పెట్టేయండి. కచ్చితంగా వేరే క్లాస్ నుంచి పిలవాలి అనిపిస్తేనే దాన్ని public గా మార్చండి. దీన్నే "Principle of Least Privilege" అంటారు.

Beginner Example & Code Anatomy

☕ Main.java — Chapter 43 Core Example 
class BankAccount {
    // PRIVATE: క్లాస్ లోపల మాత్రమే ఉండే అత్యంత రహస్యమైన డేటా
    private double balance;
    private String pin;
    private int failedAttempts;

    // Package-private (default): ఈ ప్యాకేజ్ లో వాళ్లు వాడుకోవచ్చు
    static final int MAX_FAILED_ATTEMPTS = 3;

    // PUBLIC: బయటవాళ్ళు డబ్బులు డిపాజిట్ చేయడానికి మనం ఇచ్చిన ఓపెన్ గేట్
    public void deposit(double amount) {
        if (amount > 0) {
            balance += amount;
            logTransaction("DEPOSIT", amount);
        } else {
            System.out.println("  [వార్నింగ్] మైనస్ డబ్బులు వేయలేరు!");
        }
    }

    // PUBLIC: బ్యాలెన్స్ చదవడానికి (కానీ మార్చడానికి కాదు) ఒక గెట్టర్
    public double getBalance() {
        return balance;
    }

    // PRIVATE: మనం ఇంటర్నల్ గా లాగ్స్ రాసుకునే సిస్టమ్, బయట వాళ్ళకి ఇది కనపడదు
    private void logTransaction(String type, double amount) {
        System.out.printf("  [సీక్రెట్ లాగ్] %s: $%.2f | కొత్త బ్యాలెన్స్: $%.2f%n",
                type, amount, balance);
    }

    // PUBLIC: అకౌంట్ ఓపెన్ చేయడానికి కన్స్ట్రక్టర్
    public BankAccount(double initialDeposit, String pin) {
        if (initialDeposit >= 0) this.balance = initialDeposit;
        this.pin = pin;
        this.failedAttempts = 0;
    }

    // PUBLIC: పిన్ కరెక్ట్ కాదో చెక్ చేయడానికి
    public boolean verifyPin(String inputPin) {
        if (failedAttempts >= MAX_FAILED_ATTEMPTS) {
            System.out.println("  [సెక్యూరిటీ] 3 సార్లు తప్పు కొట్టారు, అకౌంట్ లాక్ అయ్యింది!");
            return false;
        }
        if (pin.equals(inputPin)) {
            failedAttempts = 0;
            System.out.println("  పిన్ కరెక్ట్!");
            return true;
        }
        failedAttempts++;
        System.out.printf("  [వార్నింగ్] తప్పు పిన్. ఇంక %d ఛాన్సులు ఉన్నాయి%n",
                MAX_FAILED_ATTEMPTS - failedAttempts);
        return false;
    }

    // PUBLIC: డైరెక్ట్ గా ప్రింట్ చేస్తే అర్థమయ్యేలా
    @Override
    public String toString() {
        return String.format("BankAccount{బ్యాలెన్స్=$%.2f}", balance);
    }
}

public class Main {
    public static void main(String[] args) {
        System.out.println("=== బ్యాంక్ అకౌంట్ సెక్యూరిటీ డెమో ===");
        BankAccount account = new BankAccount(1000.0, "9876");

        // పబ్లిక్ మెథడ్స్ తో పర్ఫెక్ట్ గా పనిచేస్తుంది
        account.deposit(500.0);
        account.deposit(250.0);
        System.out.println("ప్రస్తుత బ్యాలెన్స్: $" + account.getBalance());

        System.out.println("
=== పిన్ బ్లాక్ అయ్యే సిస్టమ్ ===");
        account.verifyPin("1234");  // తప్పు పిన్
        account.verifyPin("4321");  // తప్పు పిన్
        account.verifyPin("9876");  // కరెక్ట్ పిన్

        System.out.println("
=== ప్రైవేట్ సెక్యూరిటీ ఎలా పనిచేస్తుందంటే ===");
        // కింద ఉన్న రెండు లైన్స్ లో కామెంట్స్ తీస్తే ఎర్రర్స్ వస్తాయి చూడండి:
        // account.balance = 999999;    // ఎర్రర్: ప్రైవేట్ ఫీల్డ్ కి డైరెక్ట్ యాక్సెస్ లేదు
        // account.logTransaction(...); // ఎర్రర్: ప్రైవేట్ మెథడ్
        System.out.println("ప్రైవేట్ ఉన్న వాటిని మనం ఇక్కడి నుంచి పిలవలేము!");
        System.out.println("ఫైనల్ అకౌంట్: " + account);
    }
}

🔍 Line-by-Line Code Explanation

private double balance;

ఎవడైనా వచ్చి బ్యాలెన్స్ ని డైరెక్ట్ గా మార్చేయకుండా సెక్యూరిటీ (private) పెట్టాం.

public void deposit(double amount)

డబ్బులు వేసుకోవడానికి ఒక పబ్లిక్ దారి ఇచ్చాం. ఈ దారిలో వస్తేనే (కండిషన్స్ తో) లోపల ఉన్న బ్యాలెన్స్ ని మారుస్తాం.

private void logTransaction(String type, double amount)

ఇది బ్యాంక్ వాళ్ళ ఇంటర్నల్ వర్క్ కోసం. కస్టమర్ కి (బయటి క్లాస్ కి) ఇది కనపడాల్సిన అవసరం లేదు.

public double getBalance()

బ్యాలెన్స్ ఎంతుందో చూసుకో (చదువుకో) అంటున్నాం. కానీ మార్చడానికి వీల్లేదు.

Practical Real-World Example

☕ PracticalApplication.java — Industry Implementation 
// ప్యాకేజ్ లోపల మాత్రమే ఉండే క్లాస్ (utility)
class PasswordHasher {
    // ఈ ప్యాకేజ్ లో ఉన్నవాళ్లు మాత్రమే పాస్వర్డ్స్ హాష్ చేయగలరు
    static String hash(String password) {
        // ఇది జస్ట్ డమ్మీ కోడ్ (రియల్ ప్రొడక్షన్ కాదు!)
        int hash = password.hashCode();
        return "HASH_" + Math.abs(hash);
    }
}

// అందరికీ అందుబాటులో ఉండే పబ్లిక్ క్లాస్
public class PracticalApplication {
    public static void main(String[] args) {
        System.out.println("=== Access Modifier డెమో ===");
        String raw = "mySecretPass123";
        String hashed = PasswordHasher.hash(raw); // ఒకే ప్యాకేజ్ కాబట్టి యాక్సెస్ ఉంది
        System.out.println("రా పాస్వర్డ్  : " + raw);
        System.out.println("హాష్ అయ్యాక   : " + hashed);
    }
}

⚠️ Common Mistakes & Professional Best Practices
  • టైప్ చేయడం బద్ధకించి ప్రతి వేరియబుల్ కి ముందు public పెట్టేయడం. ఇది చాలా డేంజర్, మన కోడ్ అంతా ఓపెన్ గా ఉంటుంది.
  • protected ని private లాగా అనుకోవడం. protected పెడితే ఏ దేశంలో ఉన్న సబ్-క్లాస్ అయినా దాన్ని వాడుకోగలదు.
  • public పెట్టాలనుకుని మర్చిపోయి వదిలేయడం (అప్పుడు అది default అవుతుంది). వేరే ప్యాకేజ్ నుంచి వాడుకుందాం అనుకున్నప్పుడు ఎర్రర్ వస్తుంది.
  • ఒక ఫైల్ లోపల రెండు మూడు పబ్లిక్ క్లాసులు పెట్టాలని ట్రై చేయడం. (ఒక ఫైల్ లో ఒకే ఒక పబ్లిక్ క్లాస్ ఉండాలి).

// Coding Challenge:
// ఒక SecureVault క్లాస్ క్రియేట్ చేయండి:
// 1. private String secretCode (ఎవరూ చదవలేరు).
// 2. private int accessAttempts కౌంటర్.
// 3. public boolean attemptAccess(String code) రాసి కరెక్ట్ కోడ్ అయితేనే true ఇవ్వాలి, మాక్స్ 3 టైమ్స్.
// 4. 3 టైమ్స్ అయితే లాక్ అయ్యేలా isLocked() రాయాలి.

class SecureVault {
    private final String secretCode;
    private int accessAttempts = 0;
    private static final int MAX_ATTEMPTS = 3;

    public SecureVault(String secretCode) {
        this.secretCode = secretCode;
    }

    public boolean attemptAccess(String code) {
        if (isLocked()) {
            System.out.println("  వాల్ట్ లాక్ అయ్యింది! అడ్మిన్ కి కాల్ చేయండి.");
            return false;
        }
        accessAttempts++;
        if (secretCode.equals(code)) {
            System.out.println("  యాక్సెస్ గ్రాంటెడ్!");
            return true;
        }
        System.out.println("  పాస్వర్డ్ తప్పు. అటెంప్ట్ " + accessAttempts + "/" + MAX_ATTEMPTS);
        return false;
    }

    public boolean isLocked() { return accessAttempts >= MAX_ATTEMPTS; }
}

public class Challenge {
    public static void main(String[] args) {
        SecureVault vault = new SecureVault("JAVA2026");
        vault.attemptAccess("WRONG1");
        vault.attemptAccess("WRONG2");
        vault.attemptAccess("JAVA2026"); // 3వ సారి కరెక్ట్ కొట్టాం
    }
}

💡 Frequently Asked Questions & Interview Insights

❓ జావాలో నేను పబ్లిక్ గానీ, ప్రైవేట్ గానీ ఏమీ రాయకపోతే ఏమవుతుంది?

దాన్ని 'default' లేదా 'package-private' అంటారు. అంటే మీ ఏరియా (ప్యాకేజ్) లో ఉన్న క్లాసులు అన్నీ దాన్ని వాడుకోవచ్చు కానీ, బయట ఊరి వాళ్ళకి (వేరే ప్యాకేజ్ కి) అది కనపడదు.

❓ ఒక మెయిన్ క్లాస్ కి `private class` అని పెట్టొచ్చా?

కుదరదు! మెయిన్ (Top-level) క్లాస్ ఎప్పుడూ `public` లేదా default లోనే ఉండాలి. క్లాస్ లోపల రాసుకునే (Inner Classes) వాళ్ళకి మాత్రమే `private` కీవర్డ్ వాడొచ్చు.

❓ వేరియబుల్స్ కి private బదులు protected వాడితే సబ్-క్లాసులకి ఈజీ కదా?

ఈజీనే కానీ డేంజర్! బెస్ట్ ప్రాక్టీస్ ఏంటంటే.. ప్రతిదీ `private` పెట్టి, మీ పిల్లలకి (సబ్-క్లాసులకి) కూడా `protected getter` మెథడ్స్ ద్వారానే యాక్సెస్ ఇవ్వడం మంచిది.

🚀 Quick Chapter Recap

  • private అంటే ఆ ఒక్క క్లాస్ (గది) లోపల మాత్రమే ఆక్సెస్ ఉంటుంది. వేరియబుల్స్ కి కచ్చితంగా ఇదే వాడాలి.
  • ఏమీ రాయకపోతే (Default) అది ప్యాకేజ్ (ఇల్లు) మొత్తంలో పనిచేస్తుంది.
  • protected అంటే ఆ ప్యాకేజ్ వాళ్ళతో పాటు, వారసులు (సబ్-క్లాసులు) కూడా వాడుకోవచ్చు.
  • public అంటే మొత్తం ప్రపంచానికి (ప్రాజెక్ట్ కి) ఓపెన్.
  • సెక్యూరిటీ రూల్: అన్నీ ప్రైవేట్ పెట్టి, కచ్చితంగా అవసరమైతేనే పబ్లిక్ చేయాలి.
