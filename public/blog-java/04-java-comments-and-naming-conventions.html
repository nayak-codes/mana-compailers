Java Comments & Industry Naming Conventions (తెలుగులో)

☕ Java 21+ LTS 🟢 Chapter 4 of 47 📂 Phase 1: Java Basics 📅 2026 Edition
📌 Covered in this chapter:

Single-line // · Multi-line /* */ · Javadoc /** */ with Tags · Naming Conventions (PascalCase, camelCase, UPPER_SNAKE_CASE) · Self-Documenting Code

కోడ్ పక్కన మనకు అర్థమయ్యేలా చిన్న నోట్స్ (Comments) ఎలా రాసుకోవాలి? అందులో Javadoc కామెంట్స్ స్పెషాలిటీ ఏంటి? మరియు ఇండస్ట్రీ లో కోడ్ రాసేటప్పుడు ఏ వేరియబుల్ కి ఎట్లాంటి పేర్లు (Naming Conventions) పెట్టాలో నేర్చుకుందాం.

1. కామెంట్స్ (Comments) లో 3 రకాలు

మనం రాసిన కోడ్ ఏంటో తర్వాత చూస్తే మనకే అర్థం కాదు. అందుకే దాని పక్కనే చిన్న వివరణ రాసుకుంటాం. వీటిని కంపైలర్ పట్టించుకోదు, అసలు కోడ్ లోకే తీసుకోదు కాబట్టి ఎంత పెద్దవి రాసినా ఫైల్ సైజ్ పెరగదు.

1. Single-Line Comments (//)

ఒకే లైన్ లో సింపుల్ గా వివరించడానికి: 
// బిల్ కి 18% GST యాడ్ చేస్తున్నాం
double total = amt + (amt * 0.18);

2. Multi-Line Comments (/* ... */)

పెద్ద పెద్ద పేరాలు రాయాలన్నా, లేదా కొంత కోడ్ ని రన్ అవ్వకుండా టెంపరరీ గా ఆఫ్ చేయాలన్నా: 
/*
 * ఈ కింది కోడ్ కస్టమర్ డేటాబేస్ ని చెక్ చేస్తుంది.
 * ప్రస్తుతానికి ఆఫ్ చేసాం.
 */

3. Javadoc Comments (/** ... */)

కంపెనీల్లో ఒక క్లాస్ ఎందుకు రాశారు? ఒక ఫంక్షన్ కి ఏ ఇన్పుట్ ఇవ్వాలి? అని నీట్ గా డాక్యుమెంటేషన్ రెడీ చేయడానికి ఇది వాడతారు. దీన్ని వాడి ఆటోమాటిక్ గా HTML వెబ్ పేజీలని జనరేట్ చేయొచ్చు: 
/**
 * టోటల్ అమౌంట్ ని క్యాలిక్యులేట్ చేసే ఫంక్షన్.
 *
 * @param price ట్యాక్స్ కలపక ముందు ఉన్న ఒరిజినల్ రేటు
 * @param tax ట్యాక్స్ పర్సంటేజ్ (ఉదా: 0.18)
 * @return ఫైనల్ గా కట్టాల్సిన అమౌంట్
 */
public double getFinalPrice(double price, double tax) {
    return price + (price * tax);
}

2. స్టాండర్డ్ Javadoc టాగ్స్

మనం వాడే మెయిన్ టాగ్స్ ఇవే:

టాగ్ఎలా రాయాలి?ఎందుకు వాడుతారు?
**`@author`**
@author Balaji | ఈ కోడ్ రాసింది ఎవరు అని చెప్పడానికి. | | @version | @version 1.0 | ఇది ఎన్నో వెర్షన్ అని రాయడానికి. | | @param | @param name యూజర్ పేరు | ఫంక్షన్ కి ఇచ్చే ఇన్పుట్ వేరియబుల్స్ గురించి వివరించడానికి. | | @return | @return టోటల్ అమౌంట్ | ఫంక్షన్ రన్ అయ్యాక తిరిగి వచ్చే రిజల్ట్ గురించి చెప్పడానికి. | | @throws | @throws Exception ఎర్రర్ వస్తే | ఏ టైమ్ లో ఎర్రర్స్ రావచ్చో చెప్పడానికి. |

3. జావా Naming Conventions (పేర్లు ఎలా పెట్టాలి?)

కంపెనీల్లో కోడ్ రాసేటప్పుడు ఇష్టం వచ్చినట్టు పేర్లు పెట్టకూడదు. జావా కి కొన్ని గ్లోబల్ రూల్స్ ఉన్నాయి. వాటిని ఫాలో అవ్వాల్సిందే:

దేనికి?రూల్ ఏంటి?ఎగ్జాంపుల్గుర్తుపెట్టుకోవాల్సింది
**Classes (క్లాసులు)**
PascalCase | BankAccount, UserLogin | ప్రతి పదం మొదటి అక్షరం క్యాపిటల్ ఉండాలి. ఇవి ఎప్పుడూ నామవాచకాలు (Nouns) అయి ఉండాలి. | | Methods (ఫంక్షన్స్) | camelCase | calculateTotal(), sendEmail() | మొదటి పదం స్మాల్ లెటర్, తర్వాత వచ్చే పదాల మొదటి అక్షరం క్యాపిటల్. ఇవి ఎప్పుడూ పనులు (Verbs) లాగా ఉండాలి. | | Variables (వేరియబుల్స్) | camelCase | userAge, totalPrice | ఇది కూడా camelCase ఏ ఫాలో అవుతుంది. | | Constants (కాన్స్టంట్స్) | UPPERSNAKECASE | MAX_SPEED, DEFAULT_TAX | అన్నీ క్యాపిటల్ లెటర్స్ ఏ, పదాల మధ్యలో అండర్ స్కోర్ (_) ఉండాలి. | | Packages (ప్యాకేజెస్) | అన్నీ స్మాల్ లెటర్స్ | com.ourcompiler.user | అన్నీ స్మాల్ లెటర్స్ లో ఉండాలి, గ్యాప్స్ ఉండకూడదు. |

Beginner Example & Code Anatomy

☕ Main.java — Chapter 4 Core Example 
/**
 * Naming Conventions ని కరెక్ట్ గా ఫాలో అవుతూ రాసిన కోడ్.
 *
 * @author మన కంపైలర్ టీమ్
 */
public class Main { // క్లాస్ పేరు PascalCase లో ఉంది

    // కాన్స్టంట్స్ UPPER_SNAKE_CASE లో ఉన్నాయి
    public static final double DEFAULT_TAX = 0.18;
    public static final String CURRENCY = "₹";

    /**
     * ట్యాక్స్ కలిపి ఫైనల్ అమౌంట్ ఎంత అవుతుందో లెక్కించే ఫంక్షన్.
     */
    public static double computeBill(double itemPrice) { // ఫంక్షన్ పేరు, వేరియబుల్స్ camelCase లో ఉన్నాయి
        // ట్యాక్స్ ని లెక్కించడం
        double taxAmount = itemPrice * DEFAULT_TAX;
        return itemPrice + taxAmount;
    }

    public static void main(String[] args) {
        double productPrice = 2500.0; 
        double totalPayable = computeBill(productPrice);

        System.out.println("ప్రోడక్ట్ ధర : " + CURRENCY + productPrice);
        System.out.println("ట్యాక్స్ రేటు : 18%");
        System.out.println("ఫైనల్ బిల్  : " + CURRENCY + totalPayable);
    }
}

ప్రోడక్ట్ ధర : ₹2500.0 ట్యాక్స్ రేటు : 18% ఫైనల్ బిల్ : ₹2950.0

🔍 Line-by-Line Code Explanation

/** ... */

క్లాస్ కి పైన రాసిన Javadoc కామెంట్. రేపు పొద్దున్న డాక్యుమెంటేషన్ జనరేట్ చేసినప్పుడు ఇది వెబ్ సైట్ లో కనిపిస్తుంది.

public static final double DEFAULT_TAX

ఇది ఒక కాన్స్టంట్ కాబట్టి అన్నీ క్యాపిటల్ లెటర్స్, మధ్యలో అండర్ స్కోర్ ఇచ్చాం (UPPER_SNAKE_CASE).

double taxAmount = ...

లోకల్ వేరియబుల్స్ కాబట్టి ఫస్ట్ లెటర్ స్మాల్ ఉండి, తర్వాత పదం క్యాపిటల్ తో స్టార్ట్ అయ్యేలా (camelCase) ఇచ్చాం.

Practical Real-World Example

☕ PracticalApplication.java — Industry Implementation 
/**
 * ఎంప్లాయ్ డీటెయిల్స్ స్టోర్ చేసే క్లాస్.
 */
class Employee {
    // వేరియబుల్స్ camelCase లో
    private String empName;
    private double monthlySal;

    public Employee(String empName, double monthlySal) {
        this.empName = empName;
        this.monthlySal = monthlySal;
    }

    // ఫంక్షన్స్ camelCase లో
    public double getAnnualCTC() {
        final double BONUS_PCT = 0.10; // కాన్స్టంట్
        double annualBase = this.monthlySal * 12;
        return annualBase + (annualBase * BONUS_PCT);
    }

    public void printInfo() {
        System.out.println("పేరు     : " + empName);
        System.out.println("వార్షిక జీతం: ₹" + getAnnualCTC());
    }
}

public class Main {
    public static void main(String[] args) {
        Employee dev = new Employee("Balaji", 85000);
        dev.printInfo();
    }
}
💻 Practical Console Output
పేరు : Balaji వార్షిక జీతం: ₹1122000.0
⚠️ Common Mistakes & Professional Best Practices
  • క్లాస్ కి స్మాల్ లెటర్ తో స్టార్ట్ చేయడం: "class bankAccount" అని ఇవ్వకూడదు, "class BankAccount" అని మాత్రమే ఇవ్వాలి.
  • వేరియబుల్స్ కి అండర్ స్కోర్స్ వాడటం: C, Python లో "user_age" అని వాడతారు కానీ, జావా లో కచ్చితంగా "userAge" అని camelCase వాడాలి.
  • అవసరం లేని చోటల్లా కామెంట్స్ పెట్టడం: "System.out.println()" పక్కన "ఇది ప్రింట్ చేస్తుంది" అని కామెంట్ పెట్టడం వేస్ట్. అర్థం కాని కాంప్లెక్స్ లాజిక్ కి మాత్రమే కామెంట్స్ రాయాలి.

💡 Frequently Asked Questions & Interview Insights

❓ Javadoc కామెంట్స్ ని HTML లాగా ఎలా మార్చాలి?

టెర్మినల్ లో "javadoc Main.java" అని కమాండ్ ఇస్తే, ఆటోమాటిక్ గా ఒక వెబ్ పేజీ లాగా డాక్యుమెంటేషన్ ఫైల్స్ అన్నీ క్రియేట్ అవుతాయి.

❓ వేరియబుల్ పేర్లలో నంబర్స్ వాడొచ్చా?

వాడొచ్చు, కానీ ఫస్ట్ లెటర్ నంబర్ అవ్వకూడదు (ఉదా: 1stName అని ఇవ్వకూడదు. firstName1 అని ఇవ్వొచ్చు).

🚀 Quick Chapter Recap

  • కామెంట్స్ ని కంపైలర్ వదిలేస్తుంది, కాబట్టి ఎన్ని రాసినా ఫైల్ సైజ్ పెరగదు.
  • Classes కి PascalCase, వేరియబుల్స్ కి, ఫంక్షన్స్ కి camelCase వాడాలి.
  • లైఫ్ లో వాల్యూ మారదు అనుకున్న కాన్స్టంట్స్ కి UPPER_SNAKE_CASE వాడాలి.
