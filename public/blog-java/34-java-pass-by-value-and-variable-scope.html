Java Pass-by-Value Mechanics & Variable Scope Deep Dive (తెలుగులో)

☕ Java 21+ LTS 🟢 Chapter 34 of 47 📂 Phase 8: Methods & Recursion 📅 2026 Edition
📌 Covered in this chapter:

The Ultimate Truth: Java is Strictly Pass-by-Value · Primitive Pass-by-Value · Object Reference Pass-by-Value · Mutating vs Reassigning Objects · Block vs Method Scope · Variable Shadowing · Memory Stack & Heap Diagrams

మెథడ్ కి ఒక వేరియబుల్ పంపించి లోపల దాన్ని మార్చితే, బయట ఉన్న అసలు వేరియబుల్ మారుతుందా లేదా? చాలామంది కన్ఫ్యూజ్ అయ్యే `Pass-by-Value` vs `Pass-by-Reference` కాన్సెప్ట్ ని ఈ చాప్టర్ లో మెమరీ బొమ్మలతో సహా క్లియర్ గా అర్థం చేసుకుందాం. దాంతో పాటే ఏ వేరియబుల్ ఎక్కడివరకే పనిచేస్తుంది (Variable Scope) అనేది కూడా తెలుసుకుందాం.

1. గోల్డెన్ రూల్: జావా ఎప్పటికీ Pass-by-Value మాత్రమే!

జావా నేర్చుకునే వాళ్ళకి ఒక పెద్ద డౌట్ ఉంటుంది. జావాలో Pass-by-Reference ఉంటుందా అని!

ద అబ్సొల్యూట్ రూల్:
జావా 100% ఎప్పుడూ పాస్-బై-వాల్యూ (Pass-by-Value) మాత్రమే! జావాలో పాస్-బై-రిఫరెన్స్ అనే కాన్సెప్ట్ అసలు లేదు.

మీరు ఒక మెథడ్ కి వాల్యూ ని పంపినప్పుడు ఏమవుతుందంటే:
- Primitives పంపితే (int, double లాంటివి): మీరు పంపించిన నంబర్ కి జావా ఒక జిరాక్స్ కాపీ తీసి ఆ మెథడ్ కి పంపుతుంది. ఆ మెథడ్ లోపల దాన్ని ఎంత మార్చినా బయట ఉన్న ఒరిజినల్ వేరియబుల్ మారదు!
- Objects పంపితే (int[], String, Student లాంటివి): అరే పంపితే మొత్తం అరే కాపీ అవ్వదు! ఆ అరే ఎక్కడుందో చెప్పే అడ్రెస్ (Reference) కి జిరాక్స్ కాపీ తీసి ఇస్తుంది. దాన్ని పట్టుకుని వాళ్ళు మెమరీ (Heap) లోపల దాకా వెళ్లి మార్చితే.. అది అందరికీ మారుతుంది. కానీ ఆ కాపీ అడ్రెస్ ని చింపేసి కొత్త అడ్రెస్ పెట్టుకుంటే.. బయట వాళ్ళకి ఏం ప్రాబ్లం ఉండదు!

2. Primitives కి Pass-by-Value ఎలా పనిచేస్తుంది?

static void modify(int x) {
    x = 99; // ఇక్కడ కేవలం మనం పంపిన 'కాపీ' మాత్రమే మారుతుంది!
}

public static void main(String[] args) {
    int number = 10;
    modify(number); // 10 అనే నంబర్ ని కాపీ చేసి పంపిస్తున్నాం
    System.out.println(number); // ఇప్పుడు ఏమొస్తుంది? 10 ఏ వస్తుంది (99 రాదు!)
}

STACK MEMORY (ఎలా జరుగుతుంది?):
  +-------------------------+
  | modify() Frame: [x=99]  | <--- కాపీ మాత్రమే 99 అయ్యింది. మెథడ్ అవ్వగానే ఇది డిలీట్ అయిపోతుంది!
  +-------------------------+
  | main() Frame: [num=10]  | <--- మన ఒరిజినల్ 10 అలానే సేఫ్ గా ఉంది
  +-------------------------+

3. Objects కి పాస్-బై-వాల్యూ (లోపలికి వెళ్లి మార్చడం vs అడ్రెస్ మార్చడం)

ఇది చాలా ఇంపార్టెంట్ ఇంటర్వ్యూ క్వశ్చన్!

// కేస్ A: అడ్రెస్ లోపలికి వెళ్లి మార్చడం (ఇది బయట వాళ్లకి కూడా ఎఫెక్ట్ అవుతుంది)
static void changeFirstElement(int[] arr) {
    arr[0] = 999; // కాపీ ఇచ్చిన అడ్రెస్ పట్టుకుని లోపలికెళ్లి మార్చేసింది!
}

// కేస్ B: అడ్రెస్ ని మార్చేయడం (ఇది బయట వాళ్లకి ఎఫెక్ట్ అవ్వదు)
static void reassignArray(int[] arr) {
    arr = new int[]{100, 200, 300}; // వీడి కాపీలో ఉన్న అడ్రెస్ తీసేసి కొత్త అరే అడ్రెస్ పెట్టుకున్నాడు
}

STACK (main)            STACK (reassignArray)              HEAP MEMORY (అసలు డేటా)
  +---------------+       +---------------+            +---------------------+
  | data = 0x5000 |       | arr = 0x8800  | ---------> | [100, 200, 300]     |
  +-------|-------+       +---------------+            +---------------------+
          |
          +------------------------------------------> +---------------------+
                                                       | [1, 2, 3] (సేఫ్!)    |
                                                       +---------------------+

4. వేరియబుల్ స్కోప్ (Variable Scope) ఎక్కడ వరకే పనిచేస్తుంది?

ఒక వేరియబుల్ కి ఎక్కడిదాకా లైఫ్ ఉంటుంది, దాన్ని ఎక్కడ వాడొచ్చు అని చెప్పేదే Scope:

1. Method Scope: ఒక మెథడ్ లోపల రాస్తే.. ఆ మెథడ్ స్టార్ట్ అయినప్పటినుంచి, పూర్తయ్యే దాకా అది పనిచేస్తుంది.
2. Block Scope ({ ... }): if లోపల గానీ, for లూప్ లోపల గానీ వేరియబుల్స్ రాస్తే (బ్రాకెట్స్ లోపల).. అవి ఆ బ్రాకెట్ ఓపెన్ అయినప్పటినుంచి క్లోజ్ అయ్యేదాకా మాత్రమే బ్రతికి ఉంటాయి.

void example() {
    int x = 10; // ఇది ఈ మెథడ్ మొత్తం పనిచేస్తుంది
    if (x > 5) {
        int y = 20; // ఇది కేవలం ఈ 'if' బ్లాక్ లోపల వరకే పనిచేస్తుంది
        System.out.println(x + y); // రెండు కలిపి యాక్సెస్ చేయొచ్చు
    }
    // System.out.println(y); // ఎర్రర్! ఎందుకంటే y కి లైఫ్ అయిపొయింది కాబట్టి ఇక్కడికి రాదు
}

5. Variable Shadowing (వేరియబుల్ షాడోయింగ్)

ఒక క్లాస్ లోపల ఒక వేరియబుల్ ఉండి, మళ్ళీ మెథడ్ లోపల అదే పేరుతో ఇంకో వేరియబుల్ క్రియేట్ చేస్తే ఏమవుతుంది? లోకల్ వేరియబుల్ వచ్చి క్లాస్ వేరియబుల్ ని కప్పేస్తుంది (Shadow చేస్తుంది).

public class ShadowDemo {
    static int count = 100; // క్లాస్ లోపల రాసిన వేరియబుల్

static void print() {
        int count = 5; // మళ్ళీ అదే పేరుతో లోకల్ గా రాసాము
        System.out.println(count); // ఇక్కడ ఏమొస్తుంది? 5 ఏ వస్తుంది! (లోకల్ కే పవర్ ఎక్కువ)
        System.out.println(ShadowDemo.count); // 100 కావాలంటే ఇలా క్లాస్ పేరుతో పిలవాలి
    }
}

Beginner Example & Code Anatomy

☕ Main.java — Chapter 34 Core Example 
import java.util.Arrays;

public class Main {
    // 1. Primitive Pass-by-Value టెస్ట్ (జిరాక్స్ కాపీ)
    static void tryToModifyPrimitive(int value) {
        value = 999; // మనం కేవలం కాపీ ని మారుస్తున్నాం, ఒరిజినల్ ని కాదు
        System.out.println("  మెథడ్ లోపల (primitive) : " + value);
    }

    // 2. Object Mutation టెస్ట్ (అడ్రెస్ పట్టుకుని వెళ్లి మార్చడం)
    static void modifyArrayContent(int[] arr) {
        arr[0] = 777; // Heap లోపల ఉన్న డేటానే మార్చేస్తున్నాం
        System.out.println("  మెథడ్ లోపల (mutated)   : " + Arrays.toString(arr));
    }

    // 3. Object Reassignment టెస్ట్ (కాపీ చేసిన అడ్రెస్ నే మార్చేయడం)
    static void tryToReassignReference(int[] arr) {
        arr = new int[]{99, 99, 99}; // వీడు ఆ అడ్రెస్ వదిలేసి కొత్త అరే క్రియేట్ చేసుకున్నాడు
        System.out.println("  మెథడ్ లోపల (reassigned): " + Arrays.toString(arr));
    }

    public static void main(String[] args) {
        System.out.println("=== 1. Primitive పాస్-బై-వాల్యూ ===");
        int score = 50;
        System.out.println("మెథడ్ పిలవకముందు          : " + score);
        tryToModifyPrimitive(score);
        System.out.println("మెథడ్ పిలిచిన తర్వాత        : " + score + " (మారలేదు!)");

        System.out.println("
=== 2. అరే లోపలికి వెళ్లి మార్చడం (Mutation) ===");
        int[] scores = {10, 20, 30};
        System.out.println("మెథడ్ పిలవకముందు          : " + Arrays.toString(scores));
        modifyArrayContent(scores);
        System.out.println("మెథడ్ పిలిచిన తర్వాత        : " + Arrays.toString(scores) + " (మొదటి నంబర్ మారిపోయింది!)");

        System.out.println("
=== 3. అడ్రెస్ మార్చేయడం (Reassignment) ===");
        int[] originalArray = {1, 2, 3};
        System.out.println("మెథడ్ పిలవకముందు          : " + Arrays.toString(originalArray));
        tryToReassignReference(originalArray);
        System.out.println("మెథడ్ పిలిచిన తర్వాత        : " + Arrays.toString(originalArray) + " (ఇది సేఫ్, మారలేదు!)");

        System.out.println("
=== 4. Block Scope డెమో ===");
        int outerX = 100;
        {
            int innerY = 500; // బ్రాకెట్స్ ఓపెన్ చేసి దీన్ని లోపల పెట్టాం
            System.out.println("బ్లాక్ లోపల: outerX + innerY = " + (outerX + innerY));
        }
        // ఇక్కడకి వచ్చేసరికి బ్రాకెట్ క్లోజ్ అయిపోయింది కాబట్టి innerY డిలీట్ అయిపొయింది
        System.out.println("బ్లాక్ బయట: outerX = " + outerX);
    }
}

🔍 Line-by-Line Code Explanation

tryToModifyPrimitive(score);

ఇక్కడ 50 అనే వాల్యూ కాపీ అవుతుంది. మెథడ్ లోపల ఆ వాల్యూని 999 గా మార్చినా.. మన ఒరిజినల్ వేరియబుల్ score మాత్రం 50 గానే ఉంటుంది.

arr[0] = 777;

ఇక్కడ అరే యొక్క అడ్రెస్ కాపీ అవుతుంది. కాబట్టి ఆ అడ్రెస్ పట్టుకుని లోపలికెళ్లి మార్చితే, బయట ఉన్న వాళ్లకి కూడా ఆ మార్పు కనిపిస్తుంది.

arr = new int[]{99, 99, 99};

ఇక్కడ మెథడ్ వాడు తనకి వచ్చిన కాపీ అడ్రెస్ ని తీసేసి.. కొత్త అరే అడ్రెస్ పెట్టుకున్నాడు. దానివల్ల మన ఒరిజినల్ అరే కి ఎలాంటి నష్టం జరగదు.

int innerY = 500;

దీన్ని బ్రాకెట్స్ (Block) లోపల రాసాం కాబట్టి.. ఆ బ్రాకెట్స్ వరకే దీని జీవితం. బయట దీన్ని ఎవరూ వాడుకోలేరు.

Practical Real-World Example

☕ PracticalApplication.java — Industry Implementation 
public class PracticalApplication {
    // రియల్ టైమ్ సినారియో: యూజర్ ప్రొఫైల్ ని క్లీన్ చేసే సర్వీస్
    static class UserProfile {
        String username;
        String email;
        UserProfile(String u, String e) { this.username = u; this.email = e; }
    }

    public static void sanitizeProfile(UserProfile profile) {
        if (profile == null) return;
        // ఇక్కడ ఆబ్జెక్ట్ లోపల ఫీల్డ్స్ (Fields) ని మారుస్తున్నాం కాబట్టి అది బయట కూడా మారుతుంది
        profile.username = profile.username.trim().toLowerCase();
        profile.email = profile.email.trim().toLowerCase();
    }

    public static void main(String[] args) {
        // ఎవరో యూజర్ స్పేస్ లు, క్యాపిటల్ లెటర్స్ ఇచ్చి రిజిస్టర్ అయ్యాడు అనుకుందాం
        UserProfile user = new UserProfile("  Admin_User2026 ", "  Support@Company.ORG ");
        System.out.println("=== క్లీన్ చేయకముందు ===");
        System.out.println("యూజర్ నేమ్: [" + user.username + "], ఈమెయిల్: [" + user.email + "]");

        sanitizeProfile(user);

        System.out.println("
=== క్లీన్ చేసిన తర్వాత ===");
        System.out.println("యూజర్ నేమ్: [" + user.username + "], ఈమెయిల్: [" + user.email + "]");
    }
}

⚠️ Common Mistakes & Professional Best Practices
  • జావాలో ఒక అరే ని పాస్ చేసి మార్చగానే మారిపోయింది కదా, అంటే ఇది పాస్-బై-రిఫరెన్స్ అని భ్రమ పడటం. అది రిఫరెన్స్ కాదు, రిఫరెన్స్ కి తీసిన కాపీ వాల్యూ (Pass-by-Value of Reference) అంతే!
  • swap(a, b) అనే మెథడ్ రాసి రెండు నంబర్స్ ని ఎక్స్చేంజ్ చేయొచ్చు అని ట్రై చేయడం. సి, సి++ లో కుదురుతుంది కానీ జావాలో ప్రైమిటివ్స్ ని అలా మార్చలేము.
  • for (int i=0;...) లూప్ వాడాక, ఆ i ని లూప్ బయట కూడా ప్రింట్ చేద్దాం అని ట్రై చేసి ఎర్రర్స్ తెచ్చుకోవడం. i లైఫ్ లూప్ బ్రాకెట్ తోనే అయిపోతుంది.
  • మెథడ్ లోపల పారామీటర్ కే కొత్త ఆబ్జెక్ట్ ఇస్తే (arr = new int[]), బయట ఉన్న వాళ్లకి కూడా ఆ కొత్త ఆబ్జెక్ట్ వస్తుందేమో అని ఆశపడటం.

☕ Challenge.java 
// Coding Challenge:
// ఒక అరే ని తీసుకుని అందులో మొదటి నంబర్ ని, చివరి నంబర్ ని స్వాప్ (Exchange) చేసే swapFirstAndLast(int[] arr) మెథడ్ రాయండి.
// ఇది రాసాక, మెయిన్ మెథడ్ లో నిజంగానే అరే మారిందో లేదో ప్రింట్ చేసి చెక్ చేయండి.

public class Challenge {
    public static void swapFirstAndLast(int[] arr) {
        // అరే లో కనీసం 2 నంబర్స్ ఉంటేనే స్వాప్ చేస్తాం
        if (arr == null || arr.length < 2) return;
        int temp = arr[0];
        arr[0] = arr[arr.length - 1]; // లాస్ట్ దాన్ని ఫస్ట్ లోకి
        arr[arr.length - 1] = temp;   // ఫస్ట్ దాన్ని లాస్ట్ లోకి
    }

    public static void main(String[] args) {
        int[] data = {100, 20, 30, 500};
        System.out.println("స్వాప్ కి ముందు: " + java.util.Arrays.toString(data));
        swapFirstAndLast(data);
        System.out.println("స్వాప్ కి తర్వాత: " + java.util.Arrays.toString(data)); // రిజల్ట్ లో 500 ముందుకి, 100 వెనక్కి వెళ్తుంది
    }
}

💡 Frequently Asked Questions & Interview Insights

❓ జావాలో రెండు నంబర్స్ ని మార్చే swap(int a, int b) మెథడ్ ఎందుకు రాయలేం?

ఎందుకంటే జావా వాల్యూస్ ని జిరాక్స్ కాపీ తీసి ఇస్తుంది. మీరు మెథడ్ లోపల ఎంతసేపు ఆ కాపీలనే అటూ ఇటూ మార్చుకుంటారు తప్ప, అసలైన నంబర్స్ ఉన్న అడ్రెస్ (main లో ఉన్నవి) కి వెళ్ళలేరు.

❓ C++ లో Pass-by-Reference కి, జావాకి తేడా ఏంటి?

C++ లో `void func(int &x)` అని రాస్తే, మీరు డైరెక్ట్ గా ఒరిజినల్ వేరియబుల్ కి లింక్ అవుతారు (కాపీ ఉండదు). కాబట్టి అక్కడ మారుతుంది. జావాలో అడ్రెస్ ని కూడా కాపీ తీసి వాల్యూ గానే ఇస్తారు.

❓ String ని మెథడ్ కి పంపిస్తే ఏమవుతుంది?

స్ట్రింగ్స్ ని పంపిస్తే కూడా అడ్రెస్ కాపీ అయ్యే వెళ్తుంది. కానీ స్ట్రింగ్స్ Immutability (మారవు) రూల్ వల్ల.. మీరు `str.toUpperCase()` అని రాస్తే ఆ పాత స్ట్రింగ్ ఏం అవ్వదు, కొత్త స్ట్రింగ్ క్రియేట్ అవుతుంది కాబట్టి ఒరిజినల్ స్ట్రింగ్ ఎప్పుడూ సేఫ్ గానే ఉంటుంది.

🚀 Quick Chapter Recap

  • జావా ఎప్పుడూ, ఎక్కడైనా, ఏ సిట్యువేషన్ లో అయినా సరే.. 100% Pass-by-Value మాత్రమే వాడుతుంది.
  • మామూలు నంబర్స్ పంపితే వాటి వాల్యూ కాపీ అయ్యి వెళ్తుంది.
  • ఆబ్జెక్ట్స్ పంపితే వాటి అడ్రెస్ (Reference) కాపీ అయ్యి వెళ్తుంది.
  • కాపీ ఇచ్చిన అడ్రెస్ తో ఆబ్జెక్ట్ లోపలికెళ్లి ఏమైనా మారిస్తే.. బయట వాళ్లకి కూడా ఆ మార్పు కనిపిస్తుంది.
  • ఒకవేళ పారామీటర్ కే కొత్త ఆబ్జెక్ట్ అడ్రెస్ ఇస్తే మాత్రం బయట వాళ్లకి ఏం కాదు, సేఫ్ గా ఉంటారు.
  • బ్రాకెట్స్ {} మధ్యలో క్రియేట్ చేసిన వేరియబుల్స్ కి ఆ బ్రాకెట్స్ బయట లైఫ్ ఉండదు (Block Scope).
