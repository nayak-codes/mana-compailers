Java String Fundamentals & String Constant Pool (SCP) (తెలుగులో)

☕ Java 21+ LTS 🟢 Chapter 23 of 47 📂 Phase 6: Strings & Text Processing 📅 2026 Edition
📌 Covered in this chapter:

What is a String? · java.lang.String · String Literals vs new String() · String Constant Pool (SCP) · String Interning (intern()) · String Immutability Deep Dive · Compact Strings (byte[] in Java 9+) · Indexing & charAt()

జావాలో Strings అంటే ఏంటి? `String` క్లాస్ వెనుక ఉన్న అసలు సీక్రెట్ ఏంటి? స్ట్రింగ్స్ ని నార్మల్ గా క్రియేట్ చేయడానికి, `new` వాడి క్రియేట్ చేయడానికి తేడా ఏంటి? **String Constant Pool (SCP)** ఎలా పనిచేస్తుంది? స్ట్రింగ్స్ ని ఎందుకు మార్చలేం (Immutable)? లాంటి అడ్వాన్స్డ్ కాన్సెప్ట్స్ ని ఈ చాప్టర్ లో డీటెయిల్డ్ గా నేర్చుకుందాం.

1. జావాలో String అంటే ఏంటి?

సాధారణంగా నంబర్స్ ని స్టోర్ చేయడానికి int, double వాడతాం, అవి డైరెక్ట్ గా స్టాక్ మెమరీలో సేవ్ అవుతాయి (వాటినే Primitive Data Types అంటారు).
కానీ టెక్స్ట్ ని స్టోర్ చేయడానికి వాడే String అనేది మామూలు డేటా టైప్ కాదు. జావాలో అదొక Reference Type (Object). ఇంటర్నల్ గా ఇది java.lang.String అనే క్లాస్!

String అనేది అక్షరాల కలయిక (sequence of characters). దీన్ని క్రియేట్ చేశాక మార్చలేం (Immutable).

Primitive Type:
  [ int age = 21 ]  ===> స్టాక్ మెమరీలో డైరెక్ట్ గా వాల్యూ ఉంటుంది: 21

Reference Type:
  [ String name = "Ravi" ] ===> స్టాక్ లో కేవలం అడ్రెస్ (Reference) మాత్రమే ఉంటుంది: 0x4F12
                                     |
                                     v
                                Heap / SCP మెమరీలో డేటా ఉంటుంది: ['R', 'a', 'v', 'i']

ప్రతి సాఫ్ట్వేర్ లో పాస్వర్డ్స్, డేటాబేస్ క్వెరీలు, యూజర్ నేమ్స్.. అన్నీ స్ట్రింగ్స్ లోనే ఉంటాయి. కాబట్టి జావా దీన్ని చాలా స్పెషల్ గా ట్రీట్ చేసి, new కీవర్డ్ వాడకుండానే డబుల్ కొటేషన్స్ " " తో డైరెక్ట్ గా క్రియేట్ చేసే ఫెసిలిటీ ఇచ్చింది.

2. Strings ని క్రియేట్ చేయడం: Literal vs new String()

జావాలో స్ట్రింగ్స్ ని రెండు రకాలుగా క్రియేట్ చేయొచ్చు:

1. String Literal (డైరెక్ట్ గా ఇవ్వడం):

String s1 = "Java";
String s2 = "Java";

ఇలా డైరెక్ట్ గా రాసినప్పుడు.. జావా వెంటనే మెమరీలో ఉన్న String Constant Pool (SCP) అనే స్పెషల్ ఏరియాలో చెక్ చేస్తుంది:
- ఒకవేళ అక్కడ ముందే "Java" ఉంటే, మళ్ళీ కొత్తగా క్రియేట్ చేయకుండా పాత దాని అడ్రెస్ నే s2 కి కూడా ఇస్తుంది.
- కాబట్టి ఇక్కడ s1 మరియు s2 రెండూ ఒకే మెమరీ అడ్రెస్ ని పాయింట్ చేస్తుంటాయి (s1 == s2 చెక్ చేస్తే true వస్తుంది).

2. new కీవర్డ్ వాడితే:

String s3 = new String("Java");

మీరు new వాడినప్పుడు జావా మీ మాట విని.. SCP లో ముందే ఉన్నా సరే, దాన్ని పట్టించుకోకుండా జనరల్ Heap మెమరీలో కొత్తగా ఇంకో ఆబ్జెక్ట్ ని క్రియేట్ చేస్తుంది.
- అందుకే s1 == s3 చెక్ చేస్తే false వస్తుంది! ఎందుకంటే రెండిటి అడ్రెస్ లు వేరు.

HEAP MEMORY
 +-------------------------------------------------------+
 |                                                       |
 |   General Heap Objects:                               |
 |   +------------------------+                          |
 |   | String Object (s3)     | (Address: 0x7B20)        |
 |   | Value: "Java"          |                          |
 |   +------------------------+                          |
 |                                                       |
 |   +-----------------------------------------------+   |
 |   | STRING CONSTANT POOL (SCP)                    |   |
 |   |                                               |   |
 |   |   +-----------------------+                   |   |
 |   |   | "Java" (s1, s2)       | (Address: 0x1A05) |   |

3. String Interning: `intern()` మెథడ్ ఎందుకు వాడాలి?

మీరు new String() వాడి మెమరీ వేస్ట్ చేసి ఒక ఆబ్జెక్ట్ క్రియేట్ చేశారనుకోండి. దాన్ని మళ్ళీ SCP లో ఉన్న సేమ్ వాల్యూ కి పాయింట్ చేయాలి అంటే intern() వాడొచ్చు:

String heapStr = new String("Java");
String poolStr = heapStr.intern(); // ఇది SCP లో ఉన్న "Java" అడ్రెస్ ని తెచ్చి ఇస్తుంది

System.out.println(heapStr == "Java"); // false (ఒకటి Heap, ఇంకోటి SCP)
System.out.println(poolStr == "Java"); // true  (రెండు SCP లోవే)

రియల్ టైమ్ లో ఎందుకు వాడతారు?
ఒక కోటి మంది డేటాలో 30 లక్షల మందికి స్టేట్ "TELANGANA" అని ఉందనుకోండి. ప్రతివాడికి వేరే వేరే స్ట్రింగ్ క్రియేట్ చేస్తే మెమరీ ఫుల్ అయిపోతుంది. అదే intern() వాడితే ఆ 30 లక్షల మంది ఒకే SCP ఆబ్జెక్ట్ ని పాయింట్ చేస్తారు. దీనివల్ల ర్యామ్ (RAM) చాలా సేవ్ అవుతుంది!

4. Strings ని ఎందుకు మార్చలేము? (Immutability - 4 కారణాలు)

జావాలో ఒకసారి స్ట్రింగ్ ఆబ్జెక్ట్ క్రియేట్ అయ్యాక, దాన్ని ఎవరూ, ఎప్పటికీ మార్చలేరు. మీరు toUpperCase() గానీ, concat() గానీ వాడినా.. అది పాత దాన్ని మార్చదు, కొత్త స్ట్రింగ్ ని క్రియేట్ చేసి ఇస్తుంది!

String str = "Hello";
str.concat(" World"); // పాత str కి ఏమీ అవ్వదు!
System.out.println(str); // ఇంకా "Hello" అనే ఉంటుంది

str = str.concat(" World"); // ఇక్కడ కొత్తగా వచ్చిన దాన్ని మళ్ళీ str కి సేవ్ చేశాం
System.out.println(str); // అప్పుడు "Hello World" వస్తుంది

జావా దీన్ని ఎందుకు ఇలా డిజైన్ చేసింది?
1. SCP షేరింగ్: వందల వేరియబుల్స్ ఒకే SCP ఆబ్జెక్ట్ ని వాడుతుంటాయి. ఒకవేళ స్ట్రింగ్ ని మార్చే ఆప్షన్ ఇస్తే, ఒకడు మారిస్తే ఆ ఎఫెక్ట్ అందరి మీద పడుతుంది!
2. సెక్యూరిటీ: పాస్వర్డ్స్, ఫైల్ పాత్స్ అన్నీ స్ట్రింగ్స్ లోనే ఉంటాయి. యాప్ రన్ అవుతున్నప్పుడు వాటిని హ్యాకర్స్ ఈజీగా మార్చేయకుండా ఉండటానికి ఇదొక సేఫ్టీ ఫీచర్.
3. Thread Safety: స్ట్రింగ్ ని ఎలాగూ ఎవరూ మార్చలేరు కాబట్టి, మల్టీ-త్రెడింగ్ యాప్స్ లో లాక్స్ వేయాల్సిన పనేలేదు, ఎవరైనా ఎప్పుడైనా వాడుకోవచ్చు.
4. HashCode క్యాషింగ్: స్ట్రింగ్ ఎప్పటికీ మారదు కాబట్టి, జావా దాని hashCode ని ఒక్కసారి క్యాలిక్యులేట్ చేసి సేవ్ చేసుకుంటుంది. అందుకే HashMap లో కీస్ గా Strings వాడితే యాప్ సూపర్ ఫాస్ట్ గా పనిచేస్తుంది.

5. కాంపాక్ట్ స్ట్రింగ్స్ (Java 9 తర్వాత వచ్చిన మ్యాజిక్)

పాత జావాలో (Java 8 వరకు) స్ట్రింగ్స్ ని char[] వాడి స్టోర్ చేసేవాళ్లు. ఒక్కో క్యారెక్టర్ కి 2 బైట్స్ (16 bits) మెమరీ తీసుకునేది. కానీ మనం రాసే కోడ్ లో 99% ఇంగ్లీష్ అక్షరాలే ఉంటాయి. వాటికి 1 బైట్ చాలు, మిగతా 1 బైట్ ఎప్పుడూ వేస్ట్ అవుతూనే ఉండేది.

అందుకే Java 9 లో Compact Strings (JEP 254) అనే ఫీచర్ తెచ్చారు:

// Java 9+ లో స్ట్రింగ్ ఇంటర్నల్ కోడ్ ఇలా ఉంటుంది:
private final byte[] value;
private final byte coder; // 0 అంటే ఇంగ్లీష్ (1 byte/char), 1 అంటే వేరే భాష (2 bytes/char)

- మొత్తం ఇంగ్లీష్/నార్మల్ సింబల్స్ ఉంటే.. జావా ఒక్కో అక్షరానికి 1 బైట్ మాత్రమే తీసుకుంటుంది.
- అందులో ఒక్క తెలుగు అక్షరం గానీ, ఎమోజీ గానీ ఉన్నా.. అప్పుడు ఆటోమాటిక్ గా 2 బైట్స్ (UTF-16) కి మారుతుంది.
దీనివల్ల మనం కోడ్ లో ఎలాంటి మార్పు చేయకపోయినా.. పెద్ద పెద్ద కంపెనీల యాప్స్ లో 15% నుంచి 30% వరకు మెమరీ సేవ్ అయ్యింది!

6. Indexing: అక్షరాలని ఎలా లాగాలి? (length & charAt)

జావాలో స్ట్రింగ్స్ అన్నీ 0-based indexing తో పనిచేస్తాయి. అంటే మొదటి అక్షరం 0 దగ్గర ఉంటుంది, లాస్ట్ అక్షరం length() - 1 దగ్గర ఉంటుంది.

స్ట్రింగ్:   "J   a   v   a"
 ఇండెక్స్:     0   1   2   3   (మొత్తం కౌంట్: 4)

- length(): ఆ స్ట్రింగ్ లో ఎన్ని అక్షరాలున్నాయో చెప్తుంది. (అరేస్ లో అయితే length అని బ్రాకెట్స్ లేకుండా రాస్తాం, కానీ ఇక్కడ length() అని కచ్చితంగా బ్రాకెట్స్ ఉండాలి).
- charAt(int index): మీకు కావాల్సిన ఇండెక్స్ దగ్గర ఏ అక్షరం ఉందో ఇస్తుంది.
- చెక్ చేసుకోండి: మీరు స్ట్రింగ్ సైజు కంటే పెద్ద నంబర్ ఇస్తే, జావా వెంటనే క్రాష్ అయ్యి StringIndexOutOfBoundsException ఇస్తుంది.

=== 3. String Indexing (అక్షరాలని బయటికి తీయడం) ===");
        String greeting = "Java 21";
        System.out.println("ఒరిజినల్ స్ట్రింగ్               : "" + greeting + """);
        System.out.println("మొత్తం అక్షరాలు (Length)        : " + greeting.length());
        System.out.println("మొదటి అక్షరం (index 0)         : " + greeting.charAt(0));
        System.out.println("index 5 దగ్గర ఉన్నది           : " + greeting.charAt(5));
        System.out.println("చివరి అక్షరం                   : " + greeting.charAt(greeting.length() - 1));

        System.out.print("లూప్ వేసి ప్రింట్ చేస్తే: ");
        for (int i = 0; i < greeting.length(); i++) {
            System.out.print("[" + i + "]=" + greeting.charAt(i) + " ");
        }
        System.out.println();
    }
}

🔍 Line-by-Line Code Explanation

String s1 = "Java"; String s2 = "Java";

డైరెక్ట్ గా రాసాం కాబట్టి రెండు ఒకే SCP ఆబ్జెక్ట్ ని పాయింట్ చేస్తాయి.

String s3 = new String("Java");

new వాడాం కాబట్టి, సపరేట్ గా వేరే మెమరీలో స్టోర్ అవుతుంది.

String s4 = s3.intern();

intern() వాడటం వల్ల, SCP లో ఉన్న "Java" అడ్రెస్ ని వెతుక్కుని మరి తెచ్చి s4 లో పెట్టింది.

original.concat(" World");

కొత్త స్ట్రింగ్ ని క్రియేట్ చేసింది గాని, దాన్ని మనం ఏ వేరియబుల్ లో స్టోర్ చేసుకోలేదు, కాబట్టి original అలాగే ఉంది.

greeting.charAt(i);

i పొజిషన్ లో ఏ అక్షరం ఉందో అది ఇస్తుంది. స్ట్రింగ్స్ ఎప్పుడూ జీరో నుంచే స్టార్ట్ అవుతాయి.

Practical Real-World Example

☕ PracticalApplication.java — Industry Implementation 
public class PracticalApplication {
    public static void main(String[] args) {
        // రియల్ టైమ్ ఇష్యూ: ఒకే కేటగిరీ లక్షల సార్లు రిపీట్ అయినప్పుడు ర్యామ్ సేవ్ చేయడం
        String rawCategory1 = new String("ELECTRONICS");
        String rawCategory2 = new String("ELECTRONICS");
        String rawCategory3 = new String("ELECTRONICS");

        // intern() వాడకపోతే 3 వేరు వేరుగా ఉండి మెమరీ వేస్ట్ అవుతుంది
        System.out.println("Intern వాడకముందు:");
        System.out.println("Obj 1 == Obj 2 : " + (rawCategory1 == rawCategory2)); // false

        // intern() వాడితే అన్నీ ఒకటే SCP ఆబ్జెక్ట్ ని పాయింట్ చేస్తాయి
        String pooled1 = rawCategory1.intern();
        String pooled2 = rawCategory2.intern();
        String pooled3 = rawCategory3.intern();

        System.out.println("
Intern వాడిన తర్వాత (Memory Deduplication):");
        System.out.println("Pooled 1 == Pooled 2 : " + (pooled1 == pooled2)); // true
        System.out.println("Pooled 2 == Pooled 3 : " + (pooled2 == pooled3)); // true
        System.out.println("ఫైనల్ కేటగిరీ          : " + pooled1);
    }
}

⚠️ Common Mistakes & Professional Best Practices
  • పాస్వర్డ్స్, యూజర్ నేమ్స్ సేమ్ ఉన్నాయా లేదా అని చెక్ చేయడానికి == వాడటం. == అనేది కేవలం అడ్రెస్ ని మాత్రమే చెక్ చేస్తుంది. ఎప్పుడైనా .equals() మాత్రమే వాడాలి.
  • str.toUpperCase() అని రాసి వదిలేయడం. స్ట్రింగ్స్ ని మార్చలేం కాబట్టి, వచ్చిన రిజల్ట్ ని మళ్ళీ వేరియబుల్ కి సేవ్ చేసుకోవాలి (str = str.toUpperCase();).
  • చివరి అక్షరం కావాలని str.charAt(str.length()) వాడటం. అక్షరాలు జీరో నుంచి స్టార్ట్ అవుతాయి కాబట్టి ఎప్పుడూ str.length() - 1 వాడాలి.

💡 Frequently Asked Questions & Interview Insights

❓ SCP (String Constant Pool) అనేది మెమరీలో ఎక్కడ ఉంటుంది?

జావా 7 కు ముందు ఇది PermGen అనే సపరేట్ మెమరీలో ఉండేది. కానీ జావా 7 తర్వాత దాన్ని మెయిన్ Heap మెమరీ లోకే మార్చేశారు. దీనివల్ల వాడని స్ట్రింగ్స్ ని గార్బేజ్ కలెక్టర్ (GC) ఈజీగా క్లీన్ చేస్తుంది.

❓ Java 9 తర్వాత char[] తీసేసి byte[] ఎందుకు పెట్టారు?

ముందే చెప్పినట్టు Compact Strings ఫీచర్ కోసం. ఇంగ్లీష్ అక్షరాలకు 2 బైట్స్ వాడటం వేస్ట్ అని, 1 బైట్ వాడి మెమరీని దాదాపు సగం సేవ్ చేయడానికి ఇలా మార్చారు.

❓ String s = new String("Java"); రాస్తే మెమరీలో ఎన్ని ఆబ్జెక్ట్స్ క్రియేట్ అవుతాయి?

రెండు! ఒకటి "Java" అనే లిటరల్ కోసం SCP లో క్రియేట్ అవుతుంది (ఒకవేళ ముందే లేకపోతే). ఇంకోటి new వాడినందుకు Heap లో క్రియేట్ అవుతుంది.

🚀 Quick Chapter Recap

  • జావాలో String అనేది ప్రిమిటివ్ కాదు, అదొక క్లాస్. దాన్ని క్రియేట్ చేశాక మార్చలేము (Immutable).
  • డైరెక్ట్ గా క్రియేట్ చేసిన స్ట్రింగ్స్ అన్నీ SCP (String Constant Pool) లో స్టోర్ అవుతాయి.
  • new వాడి క్రియేట్ చేసినవి Heap లో స్టోర్ అవుతాయి. intern() వాడితే SCP లో ఉన్న అడ్రెస్ వస్తుంది.
  • Immutability వల్ల సెక్యూరిటీ, త్రెడ్-సేఫ్టీ, మెమరీ సేవింగ్స్ చాలా బాగుంటాయి.
  • Java 9+ లో ఉన్న కాంపాక్ట్ స్ట్రింగ్స్ ఇంగ్లీష్ అక్షరాలకి సగం మెమరీనే వాడుకుంటాయి.
