Java Recursion & Call Stack Lifecycle Masterclass (తెలుగులో)

☕ Java 21+ LTS 🟢 Chapter 36 of 47 📂 Phase 8: Methods & Recursion 📅 2026 Edition
📌 Covered in this chapter:

What is Recursion? · 2 Pillars: Base Case & Recursive Step · Call Stack Winding & Unwinding · StackOverflowError Prevention · Factorial (N!) · Fibonacci Series · Sum of Digits · Recursion vs Iteration Trade-offs

ఒక మెథడ్ తనని తాను మళ్ళీ మళ్ళీ పిలుచుకుంటే ఏమవుతుంది? అదే **Recursion (రికర్శన్)**. ఇది చాలా పవర్ఫుల్ కాన్సెప్ట్, కానీ కరెక్ట్ గా వాడుకోకపోతే సిస్టమ్ క్రాష్ అవుతుంది (StackOverflowError వస్తుంది). రికర్శన్ అసలు ఎలా పనిచేస్తుంది? మెమరీలో స్టాక్ ఫ్రేమ్స్ ఎలా పుష్, పాప్ అవుతాయి? లూప్స్ కి, రికర్శన్ కి ఉన్న అసలైన డిఫరెన్స్ ఏంటో ఈ చాప్టర్ లో డీకోడ్ చేద్దాం.

1. రికర్శన్ (Recursion) అంటే ఏంటి?

Recursion అంటే ఒక మెథడ్ తనని తాను మళ్ళీ పిలుచుకోవడం (Calls itself). ఒక పెద్ద ప్రాబ్లమ్ ని చిన్న చిన్న భాగాలుగా విడగొట్టి సాల్వ్ చేయడానికి ఇది వాడతాం.

రికర్శన్ పనిచేయాలంటే కచ్చితంగా రెండు పిల్లర్స్ ఉండాలి:
1. Base Case (ఆపే కండిషన్): మెథడ్ తనని తాను పిలుచుకోవడం ఎక్కడ ఆపేయాలో చెప్పే కండిషన్. ఇది లేకపోతే ఇన్ఫినిటీ లూప్ లో పడిపోతుంది.
2. Recursive Step (ముందుకు వెళ్లడం): ప్రతిసారి తనని తాను పిలుచుకునేటప్పుడు.. బేస్ కేస్ కి దగ్గరగా వెళ్లేలా పారామీటర్స్ మార్చుకుంటూ వెళ్ళాలి.

2. Call Stack ఎలా అల్లుకుంటుంది, ఎలా విడిపోతుంది (Winding & Unwinding)

ఉదాహరణకి $4!$ (ఫ్యాక్టోరియల్) అంటే $4 \times 3 \times 2 \times 1 = 24$. ఇది రికర్శన్ లో ఎలా జరుగుతుందో చూద్దాం:

static int factorial(int n) {
    if (n <= 1) return 1;          // Base Case (1 రాగానే ఆగిపోయి 1 ఇస్తుంది)
    return n * factorial(n - 1);    // Recursive Step (తనని తానే చిన్న నంబర్ తో పిలుచుకుంటుంది)
}
ఫేజ్ 1: WINDING (ఫ్రేమ్స్ పైకి వెళ్తూ ఉంటాయి)       ఫేజ్ 2: UNWINDING (ఆన్సర్ తీసుకుని కిందకి వస్తాయి)
  
  [ factorial(1) ] -> 1 ఇస్తుంది కదా         [ factorial(1) ] -> రిటర్న్ 1 (బేస్ కేస్ హిట్)
  [ factorial(2) ] -> 2 * factorial(1)    [ factorial(2) ] -> 2 * 1 = 2 అవుతుంది
  [ factorial(3) ] -> 3 * factorial(2)    [ factorial(3) ] -> 3 * 2 = 6 అవుతుంది
  [ factorial(4) ] -> 4 * factorial(3)    [ factorial(4) ] -> 4 * 6 = 24 (ఫైనల్ ఆన్సర్!)
  [ main()       ]                        [ main()       ]

3. StackOverflowError ఎందుకు వస్తుంది? దాన్ని ఎలా ఆపాలి?

రికర్శన్ వాడేటప్పుడు ఒక మెథడ్ ఇంకో మెథడ్ ని పిలిచిన ప్రతిసారీ JVM Call Stack లో ఒక కొత్త Stack Frame క్రియేట్ అవుతుంది (మెమరీ ఆక్యుపై చేస్తుంది).

మరి StackOverflowError ఎప్పుడు వస్తుంది?
1. Base Case లేకపోతే: అది తనని తాను ఇన్ఫినిటీ సార్లు పిలుచుకుంటూనే ఉంటుంది. దాంతో స్టాక్ మెమరీ ఫుల్ అయిపోయి జావా క్రాష్ అవుతుంది.
2. బేస్ కేస్ కి వెళ్లకపోతే: factorial(n - 1) అని పిలవకుండా పొరపాటున మళ్ళీ factorial(n) నే పిలిస్తే.. అక్కడే ఇరుక్కుపోతుంది.
3. చాలా డీప్ గా వెళ్తే: బేస్ కేస్ ఉన్నా సరే, లక్ష సార్లు పిలవాల్సి వస్తే.. స్టాక్ లో అంత మెమరీ ఉండదు కాబట్టి ఫుల్ అయిపోతుంది.

// BUG: ఇన్ఫినిటీ రికర్శన్.. క్రాష్ అవుతుంది!
static void infinite() {
    infinite(); // java.lang.StackOverflowError వస్తుంది
}

4. పాపులర్ రికర్సివ్ అల్గారిథమ్స్ (Classic Algorithms)

1. Fibonacci (ఫిబోనాచీ సిరీస్ - $0, 1, 1, 2, 3, 5, 8, 13, \dots$):
$$F(n) = F(n-1) + F(n-2) \quad \text{(బేస్: } F(0)=0, F(1)=1)$$

2. నంబర్ ని కలపడం (Sum of Digits):
$1234$ ని కలపాలంటే: $\text{sum}(1234) = (1234 \% 10) + \text{sum}(1234 / 10) = 4 + 3 + 2 + 1 = 10$.

3. పవర్ క్యాలిక్యులేట్ చేయడం ($a^b$):
$$a^b = a \times a^{b-1} \quad \text{(బేస్: } a^0 = 1)$$

5. Recursion vs Iteration (లూప్స్ కి రికర్శన్ కి తేడా ఏంటి?)

ఫీచర్ Recursion (రికర్శన్) Iteration (లూప్స్)
కోడ్ చూడటానికి చాలా క్లీన్ గా, మ్యాథ్స్ ఫార్ములా లాగా అర్థమవుతుంది. కొన్నిసార్లు లూప్స్ లోపల లూప్స్ పడి కొంచెం కష్టంగా మారుతుంది.
మెమరీ వాడకం ఎక్కువ (ప్రతి కాల్ కి ఒక కొత్త స్టాక్ ఫ్రేమ్ పడుతుంది). చాలా తక్కువ (ఒకే స్టాక్ ఫ్రేమ్ లో అయిపోతుంది).
స్పీడ్ కొంచెం స్లో (స్టాక్ లో పుష్, పాప్ చేయాలి కాబట్టి). చాలా ఫాస్ట్ (డైరెక్ట్ సీపీయూ ఎగ్జిక్యూషన్).
రిస్క్ StackOverflowError వచ్చి ప్రోగ్రామ్ క్రాష్ అయ్యే ఛాన్స్ ఉంది. ఇన్ఫినిటీ లూప్ పడితే సిస్టమ్ స్లో అవుతుంది కానీ మెమరీ ఎర్రర్ రాదు.

Beginner Example & Code Anatomy

☕ Main.java — Chapter 36 Core Example 
public class Main {
    // 1. రికర్శన్ తో ఫ్యాక్టోరియల్ (N!)
    static long factorial(int n) {
        if (n <= 1) return 1; // Base case: 1 కి చేరగానే 1 ఇస్తుంది
        return n * factorial(n - 1); // Recursive step: తనని తానే మళ్ళీ పిలుచుకుంటుంది
    }

    // 2. రికర్శన్ తో ఫిబోనాచీ నంబర్
    static int fibonacci(int n) {
        if (n <= 0) return 0; // Base case 1
        if (n == 1) return 1; // Base case 2
        return fibonacci(n - 1) + fibonacci(n - 2); // రెండు సార్లు తనని తాను పిలుచుకుంటుంది
    }

    // 3. రికర్శన్ తో డిజిట్స్ ని కలపడం (Sum of Digits)
    static int sumOfDigits(int n) {
        if (n == 0) return 0; // Base case
        return (n % 10) + sumOfDigits(n / 10); // లాస్ట్ నంబర్ తీసుకుని, మిగిలిన దాన్ని మళ్ళీ పంపుతుంది
    }

    // 4. రికర్శన్ తో పవర్ కనుక్కోవడం (base^exp)
    static long power(int base, int exp) {
        if (exp == 0) return 1; // Base case: దేని పవర్ 0 అయినా 1 ఏ కదా
        return base * power(base, exp - 1); // Recursive step
    }

    public static void main(String[] args) {
        System.out.println("=== 1. ఫ్యాక్టోరియల్ (Factorial) ===");
        System.out.println("5! (5 ఫ్యాక్టోరియల్)              : " + factorial(5));
        System.out.println("10! (10 ఫ్యాక్టోరియల్)            : " + factorial(10));

        System.out.println("
=== 2. ఫిబోనాచీ సిరీస్ (Fibonacci) ===");
        System.out.print("మొదటి 8 ఫిబోనాచీ నంబర్స్     : ");
        for (int i = 0; i < 8; i++) {
            System.out.print(fibonacci(i) + " ");
        }
        System.out.println();

        System.out.println("
=== 3. నంబర్స్ ని కలపడం (Sum of Digits) ===");
        int sampleNumber = 9874;
        System.out.println("9874 లో ఉన్న నంబర్స్ కలిపితే : " + sumOfDigits(sampleNumber));

        System.out.println("
=== 4. పవర్ కనుక్కోవడం (Power) ===");
        System.out.println("2^8 (2 పవర్ 8)               : " + power(2, 8));
        System.out.println("5^3 (5 క్యూబ్)                : " + power(5, 3));
    }
}

🔍 Line-by-Line Code Explanation

if (n <= 1) return 1;

ఇది బేస్ కేస్. రికర్శన్ ఇన్ఫినిటీ కి వెళ్లిపోకుండా ఇది అడ్డుకుంటుంది.

return n * factorial(n - 1);

తనని తానే చిన్న నంబర్ (n-1) తో పిలుచుకుంటూ.. వచ్చిన ఆన్సర్ ని n తో మల్టిప్లై చేస్తుంది.

fibonacci(n - 1) + fibonacci(n - 2);

ఇక్కడ ఒకేసారి రెండు బ్రాంచెస్ లాగా విడిపోయి, ఒకదానికొకటి పిలుచుకుంటూ పాత రెండు నంబర్స్ ని యాడ్ చేస్తుంది.

(n % 10) + sumOfDigits(n / 10);

% 10 వాడి లాస్ట్ నంబర్ ని పీకేస్తుంది. మిగిలిన దాన్ని మళ్ళీ అదే ఫంక్షన్ కి పంపిస్తుంది.

Practical Real-World Example

☕ PracticalApplication.java — Industry Implementation 
public class PracticalApplication {
    // రియల్ టైమ్ సినారియో: ఫోల్డర్ సైజు కనుక్కోవడం (కంప్యూటర్ లో)
    static class Folder {
        String name;
        int directFileSizeKb;
        Folder[] subFolders; // ఫోల్డర్ లోపల ఫోల్డర్స్ ఉంటాయి కదా

        Folder(String name, int sizeKb, Folder... subs) {
            this.name = name;
            this.directFileSizeKb = sizeKb;
            this.subFolders = subs != null ? subs : new Folder[0];
        }
    }

    public static int calculateTotalFolderSize(Folder folder) {
        if (folder == null) return 0; // బేస్ కేస్
        int total = folder.directFileSizeKb;
        for (Folder sub : folder.subFolders) {
            total += calculateTotalFolderSize(sub); // ఫోల్డర్ లోపల ఉన్న ప్రతి ఫోల్డర్ కీ మళ్ళీ ఇదే మెథడ్ ని పిలుస్తున్నాం (Recursion)
        }
        return total;
    }

    public static void main(String[] args) {
        // ఫోల్డర్స్ క్రియేట్ చేస్తున్నాం
        Folder images = new Folder("images", 450);
        Folder docs = new Folder("docs", 250);
        Folder src = new Folder("src", 800, images, docs); // src లోపల images, docs ఉన్నాయి
        Folder projectRoot = new Folder("my-app", 150, src);

        System.out.println("=== డిస్క్ స్పేస్ అనలైజర్ ===");
        int totalSize = calculateTotalFolderSize(projectRoot);
        System.out.println("ప్రాజెక్ట్ మొత్తం సైజు: " + totalSize + " KB (~" + (totalSize / 1024.0) + " MB)");
    }
}

⚠️ Common Mistakes & Professional Best Practices
  • బేస్ కేస్ ని మర్చిపోయి డైరెక్ట్ గా కోడ్ రాయడం. దీనివల్ల కచ్చితంగా java.lang.StackOverflowError వస్తుంది.
  • ఫిబోనాచీ లాంటి వాటికి రికర్శన్ వాడి పెద్ద నంబర్ (ఉదా: 50) ఇవ్వడం. అది కోట్లు సార్లు రన్ అవుతుంది, సిస్టమ్ హ్యాంగ్ అయిపోతుంది (దీనికి లూప్స్ బెటర్).
  • రికర్శన్ లోపల స్టాటిక్ వేరియబుల్స్ ని ఇష్టం వచ్చినట్టు వాడటం. దానివల్ల పాత వాల్యూస్ ఉండిపోయి తప్పు ఆన్సర్స్ వస్తాయి.
  • రికర్శన్ కి పంపించేటప్పుడు n+1 లేదా n-1 బదులు n++ అని పంపడం. అది ఏమవుతుందంటే సేమ్ వాల్యూ నే ఇన్ఫినిటీ సార్లు పంపుతుంది.

Test your understanding by writing the code directly in your editor or running in our online Java compiler:

☕ Challenge.java 
// Coding Challenge:
// రికర్శన్ ని వాడి ఒక స్ట్రింగ్ ని రివర్స్ చేసే reverseString(String str) మెథడ్ ని రాయండి.
// బేస్ కేస్: స్ట్రింగ్ ఎంపటీ అయినా లేదా 1 క్యారెక్టర్ ఉన్నా అదే తిరిగి ఇచ్చేయాలి.
// రికర్సివ్ స్టెప్: return reverseString(str.substring(1)) + str.charAt(0);

public class Challenge {
    public static String reverseString(String str) {
        // బేస్ కేస్
        if (str == null || str.length() <= 1) {
            return str;
        }
        // ఫస్ట్ లెటర్ ని లాస్ట్ లో యాడ్ చేసి, మిగిలిన దాన్ని మళ్ళీ రికర్శన్ కి పంపుతున్నాం
        return reverseString(str.substring(1)) + str.charAt(0);
    }

    public static void main(String[] args) {
        System.out.println("'JAVA' ని రివర్స్ చేస్తే: " + reverseString("JAVA")); // "AVAJ"
        System.out.println("'RECURSION' ని రివర్స్ చేస్తే: " + reverseString("RECURSION"));
    }
}

💡 Frequently Asked Questions & Interview Insights

❓ జావాలో StackOverflowError ఎందుకు వస్తుంది?

ప్రతిసారి మెథడ్ కాల్ చేసినప్పుడు స్టాక్ లో ఒక ఫ్రేమ్ యాడ్ అవుతుంది కదా. ఆ స్టాక్ సైజు మహా అయితే 1MB ఉంటుంది. బేస్ కేస్ లేకపోతే అది లక్షల సార్లు మెథడ్ ని పిలిచేస్తుంది. అప్పుడు ఆ స్టాక్ మెమరీ సరిపోక క్రాష్ అవుతుంది.

❓ రికర్శన్ తో రాసే కోడ్ అంతా లూప్స్ తో కూడా రాయొచ్చా?

కచ్చితంగా రాయొచ్చు! ఎలక్ట్రానిక్స్, కంప్యూటర్ సైన్స్ రూల్స్ ప్రకారం.. రికర్శన్ తో చేయగలిగే ఏ పనినైనా సరే ఒక లూప్, ఒక స్టాక్ వాడి ఈజీగా రాయొచ్చు.

❓ Tail Call Optimization (TCO) అంటే ఏంటి? అది జావాలో ఉందా?

రికర్శన్ లో ఆఖరి స్టెప్ మళ్ళీ రికర్శన్ కాలింగ్ అయితే, కంపైలర్ కొత్త ఫ్రేమ్ క్రియేట్ చేయకుండా పాత ఫ్రేమ్ నే వాడుకుంటుంది, దాన్నే TCO అంటారు. కానీ దురదృష్టవశాత్తూ మన జావా (HotSpot JVM) దీన్ని ఆటోమాటిక్ గా సపోర్ట్ చేయదు! అందుకే డీప్ గా వెళ్లాలంటే జావాలో లూప్స్ ఏ బెటర్.

  • ఒక ప్రాబ్లమ్ ని చిన్న ముక్కలుగా చేయడానికి మెథడ్ తనని తానే మళ్ళీ మళ్ళీ పిలుచుకుంటే దాన్ని రికర్శన్ అంటారు.
  • ప్రతి రికర్శన్ కి కచ్చితంగా ఆపేయడానికి ఒక కండిషన్ (Base Case) ఉండాలి.

  • బేస్ కేస్ లేకపోతే మెమరీ ఫుల్ అయ్యి StackOverflowError వస్తుంది.
  • పెద్ద డేటా ఉన్నప్పుడు రికర్శన్ కన్నా లూప్స్ వాడటమే స్పీడ్, మెమరీకి మంచిది.
