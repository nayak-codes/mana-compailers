Java Immutable Objects, final Keyword & Thread Safety (తెలుగులో)

☕ Java 21+ LTS 🟢 Chapter 45 of 47 📂 Phase 10: Encapsulation & Access Modifiers 📅 2026 Edition
📌 Covered in this chapter:

Immutable Classes: Definition & Benefits · 5 Rules for Creating Immutable Classes · final Fields · final Methods · final Classes · Java String Immutability Recap · Immutable Collections · Thread Safety via Immutability · Java 16+ record Keyword

ఒకసారి క్రియేట్ చేసాక అందులో ఉన్న డేటాని ఇక జీవితంలో ఎవరూ మార్చలేకపోతే.. దాన్నే ఇమ్మ్యూటబుల్ (Immutable) అంటారు. అసలు అలాంటి ఆబ్జెక్ట్స్ ని ఎందుకు క్రియేట్ చేయాలి? వాటిని పర్ఫెక్ట్ గా డిజైన్ చేయడానికి ఉన్న 5 రూల్స్ ఏంటి? కొత్త జావాలో వస్తున్న `record` ఫీచర్ ఎంత ఈజీగా ఉందో ఈ చాప్టర్ లో చూద్దాం.

1. Immutable Object అంటే ఏంటి?

Immutable Object అంటే ఒకసారి new అని ఆబ్జెక్ట్ క్రియేట్ అయ్యాక, అందులో ఉన్న ఏ ఫీల్డ్ వాల్యూ కూడా ఇక ఎప్పటికీ మారదు. ఇది ఒక శిలాశాసనం లాంటిది.

జావాలో మనం రోజూ వాడే ఫేమస్ ఇమ్మ్యూటబుల్ క్లాసులు:
- java.lang.String — స్ట్రింగ్ లో ఒక లెటర్ కూడా మారదు (కలిపితే కొత్త స్ట్రింగ్ వస్తుంది కానీ పాతది మారదు).
- java.lang.Integer, Double — ప్రైమిటివ్ వ్రాపర్స్ అన్నీ ఇమ్మ్యూటబుల్ ఏ.
- java.time.LocalDate — డేట్, టైమ్ క్లాసులు.

ఇవి ఎందుకు అంత తోపు? (లాభాలు ఏంటి?)
1. Thread Safety: ఇది మారదు కాబట్టి, ఎంతమంది (threads) ఒకేసారి వచ్చి చదువుకున్నా ఎలాంటి క్లాష్ (లాక్ ప్రాబ్లెమ్స్) ఉండవు.
2. Safe Sharing: మీ ఫ్రెండ్ కి బైక్ ఇస్తే వాడు టైర్ పంక్చర్ చేసి ఇస్తాడేమో అన్న భయం ఉండదు, ఎందుకంటే ఇది అసలు మారని ఆబ్జెక్ట్.
3. Caching: సేమ్ వాల్యూ ఉంటే కొత్త ఆబ్జెక్ట్ క్రియేట్ చేయకుండా పాతదాన్నే రీయూజ్ చేసుకోవచ్చు.
4. HashMap Keys: వీటిలో వాల్యూ ఎప్పటికీ మారదు కాబట్టి హ్యాష్ మ్యాప్ లో కీస్ కి ఇవే కరెక్ట్ ఫిట్.

2. పర్ఫెక్ట్ గా Immutable క్లాస్ రాయాలంటే ఉన్న 5 రూల్స్

రూల్ 1: క్లాస్ కి final పెట్టాలి (ఎవడూ దీనికి సబ్-క్లాస్ రాసి రూల్స్ బ్రేక్ చేయలేడు).
  రూల్ 2: వేరియబుల్స్ అన్నింటికీ private final అని పెట్టాలి.
  రూల్ 3: సెట్టర్స్ (Setters) అసలు రాయకూడదు.
  రూల్ 4: డేటా అంతా కన్స్ట్రక్టర్ ద్వారానే తీసుకోవాలి.
  రూల్ 5: ఒకవేళ అరే(Array) గానీ డేట్(Date) గానీ తీసుకుంటే, కచ్చితంగా జిరాక్స్ (Defensive Copy) తీసుకోవాలి.
public final class Money {            // రూల్ 1: final క్లాస్
    private final double amount;      // రూల్ 2: private final
    private final String currency;

public Money(double amount, String currency) {  // రూల్ 4: కన్స్ట్రక్టర్ లోనే అంతా సెట్ అవుతుంది
        if (amount < 0) throw new IllegalArgumentException("మైనస్ డబ్బులా!");
        this.amount   = amount;
        this.currency = currency.toUpperCase().trim();
    }


// రూల్ 3: సెట్టర్స్ లేవు కేవలం గెట్టర్స్ మాత్రమే
    public double getAmount()   { return amount; }
    public String getCurrency() { return currency; }


// ఒకవేళ అప్డేట్ చేయాలంటే పాతదాన్ని మార్చకుండా, కొత్తది క్రియేట్ చేసి రిటర్న్ చేస్తాం!
    public Money add(Money other) {
        return new Money(this.amount + other.amount, this.currency);
    }
}

3. `final` కీవర్డ్ తో ఉన్న 3 లాభాలు

దేనికి వాడతాం? ఏమవుతుంది? (ఎఫెక్ట్) ఎగ్జాంపుల్
Field (వేరియబుల్) దాని జీవితకాలంలో ఒక్కసారే వాల్యూ ఇవ్వగలం. రెండోసారి మారిస్తే ఎర్రర్ వస్తుంది. private final String id = "ID-001";
Method దీన్ని పిల్లలు (సబ్-క్లాసులు) ఓవర్ రైడ్ (Override) చేయలేరు. public final double getBalance() { ... }
Class దీన్ని ఎవరూ వారసత్వంగా (extend) తీసుకోలేరు. ఇది ఫుల్ స్టాప్. public final class String { ... }

4. జావా 16+ `record` (సింపుల్ గా డేటాని మోసుకెళ్ళేవి)

జావా 16 నుంచి record అనే కొత్త కీవర్డ్ వచ్చింది. ఇది వాడితే 30 లైన్ల కష్టమైన కోడ్ ఒకే ఒక్క లైన్ లో అయిపోతుంది. కంపైలర్ ఆటోమాటిక్ గా private final ఫీల్డ్స్, కన్స్ట్రక్టర్, గెట్టర్స్, equals, hashCode, toString అన్నీ రాసేస్తుంది!

// పాత కాలంలో రాస్తే 30 లైన్లు
// రికార్డ్ తో రాస్తే జస్ట్ 1 లైన్!
public record Point(double x, double y) {}

// వాడుకోవడం చాలా ఈజీ:
Point p = new Point(3.0, 4.0);
System.out.println(p.x());   // 3.0 (గెట్టర్ లో 'get' అని ఉండదు, డైరెక్ట్ పేరు ఉంటది!)
System.out.println(p.y());   // 4.0
System.out.println(p);       // Point[x=3.0, y=4.0] (ఆటోమాటిక్ గా ఫార్మాట్ వస్తుంది!)

వాలిడేషన్స్ పెట్టాలంటే ఇలా షార్ట్ గా రాసుకోవచ్చు:

public record Range(int min, int max) {
    Range { // దీనికి పెరామీటర్స్ రాయక్కర్లేదు (Compact constructor)
        if (min > max) throw new IllegalArgumentException("మినిమం వాల్యూ మాక్సిమం కన్నా ఎక్కువ ఉండకూడదు!");
    }
}

Beginner Example & Code Anatomy

☕ Main.java — Chapter 45 Core Example 
import java.util.Arrays;

// ---------------------------------------------------------------
// IMMUTABLE CLASS: Money (5 రూల్స్ వాడి రాసింది)
// ---------------------------------------------------------------
final class Money {
    private final double amount;
    private final String currency;

    public Money(double amount, String currency) {
        if (amount < 0) throw new IllegalArgumentException("డబ్బులు మైనస్ లో ఉండవు: " + amount);
        if (currency == null || currency.isBlank()) throw new IllegalArgumentException("కరెన్సీ పేరు కావాలి.");
        this.amount   = amount;
        this.currency = currency.toUpperCase().trim();
    }

    public double getAmount()   { return amount; }
    public String getCurrency() { return currency; }

    // ఇమ్మ్యూటబుల్ స్టైల్: ఆబ్జెక్ట్ ని మార్చం, దానికి బదులు కొత్త ఆబ్జెక్ట్ ఇస్తాం!
    public Money add(Money other) {
        if (!this.currency.equals(other.currency))
            throw new IllegalArgumentException("రెండు వేరు వేరు కరెన్సీలు యాడ్ చేయలేరు: "
                    + this.currency + " and " + other.currency);
        return new Money(this.amount + other.amount, this.currency);
    }

    public Money multiply(double factor) {
        return new Money(this.amount * factor, this.currency);
    }

    @Override
    public String toString() {
        return String.format("Money{%.2f %s}", amount, currency);
    }
}

// IMMUTABLE CLASS విత్ ARRAY: Snapshot (కాపీ తీసి కాపాడుకోవడం)
// ---------------------------------------------------------------
final class DataSnapshot {
    private final String label;
    private final int[] readings; // అరే వచ్చింది అంటే డేంజర్ కాపీ తీయాల్సిందే!
    private final long timestamp;

    public DataSnapshot(String label, int[] readings) {
        this.label     = label;
        this.readings  = readings.clone(); // రూల్ 5: వచ్చేటప్పుడు జిరాక్స్ తీసుకున్నాం
        this.timestamp = System.currentTimeMillis();
    }

    public String getLabel()    { return label; }
    public long getTimestamp()  { return timestamp; }
    public int[] getReadings()  { return readings.clone(); } // రూల్ 5: వెళ్ళేటప్పుడు కూడా జిరాక్స్ ఇచ్చాం

    public double getAverage() {
        int sum = 0;
        for (int r : readings) sum += r;
        return (double) sum / readings.length;
    }

    @Override
    public String toString() {
        return String.format("Snapshot{పేరు='%s', యావరేజ్=%.1f, రీడింగ్స్=%s}",
                label, getAverage(), Arrays.toString(readings));
    }
}

// ---------------------------------------------------------------
// జావా 16+ RECORD: అతి చిన్న కోడ్ తో ఇమ్మ్యూటబుల్
// ---------------------------------------------------------------
record Point(double x, double y) {
    // కుదించి రాసిన కన్స్ట్రక్టర్ (వాలిడేషన్ కోసం)
    Point {
        if (Double.isNaN(x) || Double.isNaN(y))
            throw new IllegalArgumentException("నెంబర్స్ కాకుండా ఏవేవో ఇచ్చారు బ్రో!");
    }

    // రికార్డ్స్ లో మనం సొంత మెథడ్స్ కూడా రాసుకోవచ్చు!
    public double distanceTo(Point other) {
        double dx = this.x - other.x;
        double dy = this.y - other.y;
        return Math.sqrt(dx * dx + dy * dy);
    }
}

// ఇది ఒక కంపెనీ ఆడిట్ లాగ్ సిస్టమ్ (ఇది కచ్చితంగా ఇమ్మ్యూటబుల్ ఉండాలి, లేకపోతే రికార్డ్స్ ఎవరైనా మార్చేయగలరు!)
final class AuditEntry {
    private final String userId;
    private final String action;
    private final long timestamp;

    public AuditEntry(String userId, String action) {
        if (userId == null || action == null) throw new IllegalArgumentException("డేటా కరెక్ట్ గా లేదు.");
        this.userId    = userId;
        this.action    = action;
        this.timestamp = System.currentTimeMillis();
    }

    public String getUserId()   { return userId; }
    public String getAction()   { return action; }
    public long getTimestamp()  { return timestamp; }

    @Override
    public String toString() {
        return String.format("AuditEntry{యూజర్='%s', పని='%s', టైమ్=%d}", userId, action, timestamp);
    }
}

public class PracticalApplication {
    public static void main(String[] args) {
        AuditEntry e1 = new AuditEntry("USR-001", "LOGIN");
        AuditEntry e2 = new AuditEntry("USR-001", "TRANSFER_FUNDS");
        AuditEntry e3 = new AuditEntry("USR-002", "CHANGE_PASSWORD");

        System.out.println("=== సీక్రెట్ ఆడిట్ లాగ్ (ఎవరూ మార్చలేనిది) ===");
        System.out.println(e1);
        System.out.println(e2);
        System.out.println(e3);
    }
}

⚠️ Common Mistakes & Professional Best Practices
  • వేరియబుల్స్ కి final పెట్టి చేతులు దులుపుకోవడం. ఒకవేళ అది Array లేదా Date అయితే final పెట్టినా కూడా లోపల ఉన్న వాల్యూస్ ఈజీగా మార్చేయొచ్చు. అందుకే .clone() తప్పనిసరి.
  • final క్లాస్ కి (సబ్-క్లాస్ ఉండకూడదు) మరియు final ఫీల్డ్ కి (ఒక్కసారే వాల్యూ ఇస్తాం) కన్ఫ్యూజ్ అవ్వడం.
  • record వాడి అందులో మళ్ళీ వాల్యూస్ ని మార్చేలా మెథడ్స్ రాయడం. (రికార్డ్ అంటేనే మారనిది, దాంట్లో మళ్ళీ మార్చే పనులు చేయకూడదు).

// Coding Challenge:
// ఒక ఇమ్మ్యూటబుల్ Version క్లాస్ రాయండి (ఉదాహరణకి ఆండ్రాయిడ్ 14.1.2 లాగా):
// ఫీల్డ్స్: final int major, minor, patch.
// రూల్: అన్నీ >= 0 ఉండాలి.
// మెథడ్స్: isNewerThan(Version other), toString() ఇవి 14.1.2 లాగా రిటర్న్ చేయాలి.

final class Version {
    private final int major;
    private final int minor;
    private final int patch;

    public Version(int major, int minor, int patch) {
        if (major < 0 || minor < 0 || patch < 0) throw new IllegalArgumentException("వర్షన్ మైనస్ లో ఉండదు");
        this.major = major;
        this.minor = minor;
        this.patch = patch;
    }

    public boolean isNewerThan(Version other) {
        if (this.major != other.major) return this.major > other.major;
        if (this.minor != other.minor) return this.minor > other.minor;
        return this.patch > other.patch;
    }

    @Override
    public String toString() {
        return major + "." + minor + "." + patch;
    }
}

public class Challenge {
    public static void main(String[] args) {
        Version v1 = new Version(2, 1, 0);
        Version v2 = new Version(2, 0, 5);
        System.out.println(v1 + " ఇది కొత్తదా " + v2 + " కన్నా ?: " + v1.isNewerThan(v2));
    }
}

💡 Frequently Asked Questions & Interview Insights

❓ జావాలో String అనేది Immutable అవునా కాదా? ఎందుకు?

అవును. ఎందుకంటే: (1) సెక్యూరిటీ బాగుంటుంది (2) రెండు ఒకేలా ఉంటే మెమరీ సేవ్ చేయడానికి String Pool వాడుకుంటుంది (3) ఒకేసారి ఎంతమందైనా చదువుకోవచ్చు (Thread safety).

❓ final అరే అని రాస్తే అది ఎప్పటికీ మారదా?

లేదండి! `final int[] arr = {1, 2}` అంటే ఆ వేరియబుల్ కి వేరే కొత్త అరే ని అటాచ్ చేయలేం అని మాత్రమే. కానీ లోపలకెళ్ళి `arr[0] = 99` అని రాస్తే జావా అస్సలు ఆపదు. అందుకే కాపీ తీసి ఇస్తుండాలి.

❓ మామూలు క్లాస్ కి, Record కి తేడా ఏంటి? ఎప్పుడు ఏది వాడాలి?

జస్ట్ డేటాని అటూ ఇటూ మోసుకెళ్లడానికి అయితే ఒకే లైన్ లో అయిపోయే Record వాడాలి. కానీ అందులో ఏవైనా కాంప్లెక్స్ లాజిక్స్, లేదా పేరెంట్-చైల్డ్ రిలేషన్స్ ఉంటే మామూలు క్లాస్ ఏ వాడాలి.
