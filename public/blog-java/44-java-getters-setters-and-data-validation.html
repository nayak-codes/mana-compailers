Java Getters, Setters, Data Validation & Controlled Access (తెలుగులో)

☕ Java 21+ LTS 🟢 Chapter 44 of 47 📂 Phase 10: Encapsulation & Access Modifiers 📅 2026 Edition
📌 Covered in this chapter:

Getter Methods (Accessors) · Setter Methods (Mutators) · boolean Getter Naming (isActive) · Data Validation in Setters · Defensive Copying · Chained Setters (Fluent API) · Computed Properties · When NOT to Use Setters

వేరియబుల్స్ కి `private` పెట్టగానే పని అయిపోలేదు. వాటిని సేఫ్ గా చదవడానికి Getters, సేఫ్ గా మార్చడానికి (వాలిడేషన్ తో) Setters కావాలి. ఈ చాప్టర్ లో గెట్టర్స్, సెట్టర్స్ ఎలా రాయాలి? Arrays లాంటి వాటిని రిటర్న్ చేసేటప్పుడు సెక్యూరిటీ బ్రేక్ అవ్వకుండా Defensive Copying ఎలా చేయాలి? చూద్దాం.

1. Getter Methods (చదువుకో, కానీ మార్చకు)

ప్రైవేట్ లో పెట్టిన డేటాని బయటవాళ్ళు చూసుకోవడానికి ఇచ్చే ఒక విండో లాంటిదే Getter మెథడ్. దీన్ని ఎలా రాస్తారంటే:
- మామూలు వాటికి: public ReturnType getFieldName()
- boolean (True/False) వాటికి: public boolean isFieldName() (get కాదు సుమా!)

class Employee {
    private String name;
    private double salary;
    private boolean active;

public String getName()    { return name; }
    public double getSalary()  { return salary; }
    public boolean isActive()  { return active; } // ఇక్కడ 'is' అని వాడాలి!
}

డేటాని మార్చి (కలిపి) పంపొచ్చు (Computed Property):

private String firstName;
private String lastName;


// ఈ మెథడ్ కోసం మనం అసలు వేరియబుల్ స్టోర్ చేయట్లేదు, అప్పటికప్పుడు కలిపి ఇస్తున్నాం
public String getFullName() {
    return firstName + " " + lastName; 
}

2. Setter Methods (చెకింగ్ చేసిన తర్వాతే అలో చెయ్)

Setter ద్వారా డేటాని అప్డేట్ చేస్తారు. కానీ ఇక్కడ మనం "వాలిడేషన్" (చేకింగ్స్) పెట్టి, తప్పు డేటా అయితే ఆపేయొచ్చు:

class Employee {
    private String name;
    private double salary;

public void setName(String name) {
        // పేరు ఖాళీగా పంపితే ఆపేస్తున్నాం
        if (name == null || name.isBlank())
            throw new IllegalArgumentException("పేరు ఖాళీగా ఉండకూడదు బాబు.");
        this.name = name.trim();
    }


public void setSalary(double salary) {
        // మైనస్ లో శాలరీ ఇస్తే ఆపేస్తున్నాం
        if (salary < 0)
            throw new IllegalArgumentException("శాలరీ మైనస్ లో ఉండదు!");
        if (salary > 10_000_000)
            throw new IllegalArgumentException("మరీ అంత శాలరీ మన కంపెనీలో లేదులే.");
        this.salary = salary;
    }
}

3. Defensive Copying (అసలైన దాన్ని కాపాడుకోవడం)

ఒకవేళ మీ క్లాస్ లోపల Arrays గానీ, Dates గానీ ఉంటే.. మీరు డైరెక్ట్ గా గెట్టర్ ద్వారా ఆ అరే ని రిటర్న్ చేసేస్తే ప్రాబ్లెమ్ వస్తుంది. బయటవాడు ఆ అరే లోపల ఉన్న వాల్యూస్ ని మార్చేస్తాడు!
అలా జరగకుండా ఉండాలంటే జిరాక్స్ కాపీలు ఇవ్వాలి. దీన్నే Defensive copying అంటారు:

class Report {
    private int[] scores; // ఇది మామూలు డేటా కాదు, డేంజర్ ముఠా!

public Report(int[] scores) {
        // బయటవాడు పంపించిన దానికి కాపీ (జిరాక్స్) తీసుకుని పెట్టుకుంటున్నాం
        this.scores = scores.clone(); 
    }


public int[] getScores() {
        // మన దగ్గరున్న దాన్ని డైరెక్ట్ గా ఇవ్వకుండా, జిరాక్స్ కాపీ ఇస్తున్నాం
        return scores.clone(); 
    }
}

ఒకవేళ ఇలా చేయకపోతే ఏమవుతుంది?

int[] data = {90, 80, 70};
Report r = new Report(data);
data[0] = 0;         // జిరాక్స్ తీయకపోతే, రిపోర్ట్ లోపల ఉన్న డేటా కూడా మారిపోతుంది!
r.getScores()[1] = 0; // గెట్టర్ కి జిరాక్స్ లేకపోతే, వాడు తీసుకున్నాక మారిస్తే మనదీ మారుతుంది!

4. Fluent Setter (లైన్ గా కలుపుకుంటూ వెళ్ళడం)

సెట్టర్స్ రాసేటప్పుడు void అని కాకుండా ఆ ఆబ్జెక్ట్ నే రిటర్న్ (return this) చేస్తే కోడ్ చదవడానికి చాలా బాగుంటుంది:

class QueryBuilder {
    private String table;
    private String condition;
    private int limit;

public QueryBuilder from(String table)    { this.table = table; return this; }
    public QueryBuilder where(String cond)    { this.condition = cond; return this; }
    public QueryBuilder limit(int n)          { this.limit = n; return this; }


public String build() {
        return "SELECT * FROM " + table + " WHERE " + condition + " LIMIT " + limit;
    }
}


// ఒకే లైన్ లో ఇంగ్లీష్ చదివినట్టు ఉందా!
String query = new QueryBuilder()
        .from("students")
        .where("gpa > 3.5")
        .limit(10)
        .build();

5. Setters ఎప్పుడెప్పుడు రాయకూడదు?

ప్రతి వేరియబుల్ కి సెట్టర్ రాయాల్సిన అవసరం లేదు. కొన్ని ఎప్పటికీ మారకూడదు:

1. ఐడెంటిటీస్ (IDs): కస్టమర్ ఐడీ, క్రియేట్ చేసిన టైమ్ లాంటివి ఒక్కసారే పడతాయి, మళ్ళీ మారవు.
2. ఫార్ములాతో వచ్చేవి: పుట్టిన తేదీ తెలిస్తే వయసు ఆటోమాటిక్ గా వస్తుంది, వయసుకి సెట్టర్ అక్కర్లేదు.
3. ఇమ్మ్యూటబుల్ క్లాసులు: అసలు క్లాస్ లో ఏదీ మారకూడదు అనుకున్నప్పుడు.

class Order {
    private final String orderId;          // మారకూడదు — సెట్టర్ రాయొద్దు!
    private final long createdTimestamp;   // మారకూడదు — సెట్టర్ రాయొద్దు!
    private int quantity;                  // మారొచ్చు — దీనికి సెట్టర్ రాసుకోవచ్చు
    
    Order(int quantity) {
        this.orderId           = "ORD-" + System.nanoTime();
        this.createdTimestamp  = System.currentTimeMillis();
        setQuantity(quantity);
    }
    
    public String getOrderId() { return orderId; }
    // ... మిగిలిన గెట్టర్స్, సెట్టర్స్
}

Beginner Example & Code Anatomy

☕ Main.java — Chapter 44 Core Example 
class Employee {
    // సెక్యూరిటీ కోసం ప్రైవేట్ ఫీల్డ్స్
    private final String employeeId; // ఫైనల్ - దీనికి సెట్టర్ ఉండదు
    private String name;
    private String email;
    private double salary;
    private boolean active;
    private int[] projectIds;        // అరే - డేంజర్, కాపీస్ ఇవ్వాలి

    public Employee(String name, String email, double salary, int[] projectIds) {
        this.employeeId = "EMP-" + System.currentTimeMillis() % 100000;
        setName(name); // డైరెక్ట్ వాల్యూ వేయకుండా సెట్టర్ పిలుస్తున్నాం (వాలిడేషన్ కోసం)
        setEmail(email);
        setSalary(salary);
        // అరే కాబట్టి జిరాక్స్ కాపీ చేసుకుంటున్నాం
        this.projectIds = projectIds != null ? projectIds.clone() : new int[0];
        this.active = true;
    }

    // GETTERS (రీడ్ ఓన్లీ)
    public String getEmployeeId()  { return employeeId; }
    public String getName()        { return name; }
    public String getEmail()       { return email; }
    public double getSalary()      { return salary; }
    public boolean isActive()      { return active; } // is అని ఉండాలి!

    // Defensive copy - గెట్టర్ లో కూడా జిరాక్స్ కాపీనే ఇస్తున్నాం
    public int[] getProjectIds()   { return projectIds.clone(); }

    // Computed property — ఫార్ములాతో క్రియేట్ అయ్యేది
    public String getDisplayTitle() {
        return (active ? "[ACTIVE] " : "[INACTIVE] ") + name + " <" + email + ">";
    }

    // SETTERS (వాలిడేషన్ తో)
    public void setName(String name) {
        if (name == null || name.isBlank())
            throw new IllegalArgumentException("పేరు ఖాళీగా ఉండకూడదు.");
        this.name = name.trim();
    }

    public void setEmail(String email) {
        // రెగ్యులర్ ఎక్స్ప్రెషన్ తో ఈమెయిల్ ఫార్మాట్ కరెక్ట్ ఉందో లేదో చెక్ చేస్తున్నాం
        if (email == null || !email.matches("^[\w.-]+@[\w.-]+\.\w{2,}$"))
            throw new IllegalArgumentException("ఈమెయిల్ ఫార్మాట్ తప్పు: " + email);
        this.email = email.toLowerCase().trim();
    }

    public void setSalary(double salary) {
        if (salary < 15000)
            throw new IllegalArgumentException("మరీ ఇంత తక్కువ శాలరీ ఏంటయ్యా: " + salary);
        this.salary = salary;
    }

    public void setActive(boolean active)      { this.active = active; }
    public void setProjectIds(int[] projectIds) {
        this.projectIds = projectIds != null ? projectIds.clone() : new int[0];
    }

    @Override
    public String toString() {
        return String.format("[%s] %-18s | శాలరీ: $%,9.2f | యాక్టివ్: %b",
                employeeId, name, salary, active);
    }
}

    }

🔍 Line-by-Line Code Explanation

public boolean isActive()

boolean వాటికి get అని కాకుండా is అని రాస్తారు (జావా బీన్స్ రూల్స్). దీన్ని బట్టి స్ప్రింగ్, హైబర్నెట్ లాంటి ఫ్రేమ్వర్క్స్ కి అర్థమవుతుంది.

this.projectIds = projectIds.clone();

లోపలికి తీసుకునేటప్పుడు, బయటకి ఇచ్చేటప్పుడు అరే జిరాక్స్ తీసి ఇస్తే, మన ఒరిజినల్ డేటాకి ఎఫెక్ట్ అవ్వదు.

public String getDisplayTitle()

దీనికోసం సపరేట్ గా వేరియబుల్ లేదు, ఉన్న వేరియబుల్స్ తో అప్పటికప్పుడు స్ట్రింగ్ తయారు చేసి ఇస్తున్నాం.

if (!email.matches("^[\\w.-]+@[\\w.-]+\\.\\w{2,}$"))

రెగ్యులర్ ఎక్స్ప్రెషన్ (Regex) వాడి ఈమెయిల్ లో @, .కాం లాంటివి ఉన్నాయో లేదో కచ్చితంగా చెక్ చేసి వదులుతున్నాం.

☕ PracticalApplication.java — Industry Implementation 
class Temperature {
    private double celsius;

    public Temperature(double celsius) {
        setCelsius(celsius);
    }

    // సెట్టర్ విత్ వాలిడేషన్
    public void setCelsius(double celsius) {
        if (celsius < -273.15)
            throw new IllegalArgumentException("మరీ అంత చలి భూమ్మీద ఉండదు బ్రో (Absolute zero)!");
        this.celsius = celsius;
    }

    // రా వాల్యూ (సెల్సియస్)
    public double getCelsius() { return celsius; }

    // ఫార్ములా గెట్టర్స్ (ఫారెన్ హీట్, కెల్విన్ కోసం వేరే వేరియబుల్స్ లేవు, ఫార్ములా అంతే)
    public double getFahrenheit() { return (celsius * 9.0 / 5.0) + 32; }
    public double getKelvin()     { return celsius + 273.15; }

    @Override
    public String toString() {
        return String.format("%.2f°C = %.2f°F = %.2fK", celsius, getFahrenheit(), getKelvin());
    }
}

public class PracticalApplication {
    public static void main(String[] args) {
        Temperature t1 = new Temperature(100.0);
        Temperature t2 = new Temperature(37.0);  // హ్యూమన్ బాడీ టెంపరేచర్

        System.out.println("=== టెంపరేచర్ కన్వర్టర్ ===");
        System.out.println("నీరు మరిగే ఉష్ణోగ్రత : " + t1);
        System.out.println("మానవ శరీరం      : " + t2);

        try {
            new Temperature(-300); // లిమిట్ దాటింది!
        } catch (IllegalArgumentException e) {
            System.out.println("ఎర్రర్: " + e.getMessage());
        }
    }
}

⚠️ Common Mistakes & Professional Best Practices
  • boolean వేరియబుల్స్ కి getIsActive() అని రాయడం — అలా రాస్తే Spring/Hibernate లాంటి ఫ్రేమ్వర్క్స్ గుర్తు పట్టలేవు. isActive() అనే రాయాలి.
  • Arrays ని గానీ Date ఆబ్జెక్ట్స్ ని గానీ డైరెక్ట్ గా గెట్టర్ లో రిటర్న్ చేయడం (Defensive Copy చేయకుండా). ఎవడో ఒకడు బయటనుంచి మీ డేటా మార్చేస్తాడు.
  • this.name = this.name; అని రాసుకోవడం. (పారామీటర్ పేరు, వేరియబుల్ పేరు ఒకటే ఉన్నప్పుడు this.name = name; అని రాయాలి).
  • అన్నింటికీ బ్లైండ్ గా సెట్టర్స్ రాసేయడం. (క్రియేట్ అయిన డేట్ కి, ఐడీలకి కూడా సెట్టర్స్ రాస్తే ఎవరైనా మార్చేస్తారు, అవి ఫైనల్ గా ఉండాలి).

// Coding Challenge:
// ఒక BankAccount క్లాస్ ని క్రియేట్ చేయండి:
// 1. private double balance (దీనికి సెట్టర్ రాయొద్దు, కేవలం deposit, withdraw లే దీన్ని మార్చాలి).
// 2. private String accountHolder (సెట్టర్ వద్దు, డిఫాల్ట్ గా final పెట్టండి).
// 3. getBalance() ఎప్పుడూ 2 డెసిమల్స్ కే రౌండ్ చేసి పంపాలి.
// 4. deposit(amount): పాజిటివ్ అయితేనే బ్యాలెన్స్ లో యాడ్ చేయాలి.
// 5. withdraw(amount): అమౌంట్ > 0 మరియు బ్యాలెన్స్ ఉంటేనే తీయాలి.

class BankAccount {
    private final String accountHolder;
    private double balance;

    public BankAccount(String holder, double initialBalance) {
        if (holder == null || holder.isBlank()) throw new IllegalArgumentException("పేరు కచ్చితంగా ఉండాలి");
        this.accountHolder = holder.trim();
        this.balance = Math.max(0, initialBalance);
    }

    public String getAccountHolder() { return accountHolder; }

    public double getBalance() {
        return Math.round(balance * 100.0) / 100.0;
    }

    public void deposit(double amount) {
        if (amount <= 0) throw new IllegalArgumentException("డిపాజిట్ మైనస్ లో ఉండదు!");
        balance += amount;
    }

    public void withdraw(double amount) {
        if (amount <= 0 || amount > balance)
            throw new IllegalArgumentException("బ్యాలెన్స్ లేదు బ్రో: " + amount);
        balance -= amount;
    }
}

public class Challenge {
    public static void main(String[] args) {
        BankAccount acc = new BankAccount("Priya", 1000.0);
        acc.deposit(500.0);
        acc.withdraw(200.0);
        System.out.println(acc.getAccountHolder() + " అకౌంట్ బ్యాలెన్స్: $" + acc.getBalance());
    }
}

💡 Frequently Asked Questions & Interview Insights

❓ ప్రతి వేరియబుల్ కి కచ్చితంగా గెట్టర్, సెట్టర్ రాయాల్సిందేనా?

లేదు! అవసరమైతేనే రాయాలి. ఎప్పటికీ మారకూడని వాటికి సెట్టర్స్ ఇవ్వకూడదు. అసలు బయటవాళ్లకి తెలియకూడని సీక్రెట్స్ కి గెట్టర్స్ కూడా ఇవ్వకూడదు.

❓ జావా బీన్స్ (Java Beans) రూల్స్ అంటే ఏంటి?

గెట్టర్స్ కి `get...`, బూలియన్ కి `is...`, సెట్టర్స్ కి `set...` అని పేరు పెట్టడాన్నే ఈ రూల్స్ అంటారు. ఈ ఫార్మాట్ లో రాస్తేనే Spring, Hibernate లాంటి పెద్ద లైబ్రరీలు మీ కోడ్ ని ఆటోమాటిక్ గా చదవగలవు.

❓ ఒక వేరియబుల్ ని కేవలం గెట్టర్ తో వదిలేయొచ్చా (సెట్టర్ లేకుండా)?

సూపర్ ఐడియా! దాన్నే రీడ్-ఓన్లీ (Read-only) అంటారు. ఐడీలు, డేట్ ఆఫ్ బర్త్ లాంటివి ఇలా చేస్తేనే సెక్యూర్ గా ఉంటాయి. ఆ వేరియబుల్స్ కి `final` కీవర్డ్ పెడితే ఇంక తిరుగుండదు.
