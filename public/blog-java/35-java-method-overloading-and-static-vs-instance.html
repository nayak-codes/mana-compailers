Java Method Overloading, Type Promotion & Static vs Instance (తెలుగులో)

☕ Java 21+ LTS 🟢 Chapter 35 of 47 📂 Phase 8: Methods & Recursion 📅 2026 Edition
📌 Covered in this chapter:

Method Overloading (Compile-Time Polymorphism) · 3 Valid Overloading Rules · Why Return Type Alone Cannot Overload · Automatic Type Promotion in Overloading · static Methods vs Instance Methods · Memory Allocation of static

ఒకే పేరుతో మల్టిపుల్ మెథడ్స్ రాయొచ్చా? జావాలో దీన్ని 'Method Overloading' అంటారు (దీన్నే Polymorphism అని కూడా అంటారు). అసలు ఒకే పేరు ఎందుకు పెట్టాలి? దీనికి ఉన్న 3 స్ట్రిక్ట్ రూల్స్ ఏంటి? అలాగే, `static` కి `instance` (నాన్-స్టాటిక్) మెథడ్స్ కి ఉన్న అసలైన డిఫరెన్స్ ఏంటో ఈ చాప్టర్ లో కంప్లీట్ గా తెలుసుకుందాం.

1. Method Overloading అంటే ఏంటి? (కలగూరగంప పేర్లు వద్దు!)

Method Overloading అంటే ఒక క్లాస్ లో ఒకే పేరుతో మల్టిపుల్ మెథడ్స్ ని క్రియేట్ చేయడం (కానీ తీసుకునే పారామీటర్స్ వేరుగా ఉండాలి).

ఎందుకు?
ఉదాహరణకి మీరు నంబర్స్ ని యాడ్ చేయడానికి మెథడ్స్ రాస్తున్నారు. రెండిటిని కలపడానికి addTwo(), మూడింటిని కలపడానికి addThree(), పాయింట్ నంబర్స్ కి addDoubles() అని వేరు వేరు పేర్లు పెడితే.. వాడేవాడికి తలనొప్పి కదా! అందుకే అన్నింటికీ add() అని ఒకటే పేరు పెడితే, మనం పంపించే నంబర్స్ ని బట్టి జావా కంపైలర్ అదే ఆటోమాటిక్ గా ఏది రన్ చేయాలో డిసైడ్ చేసుకుంటుంది. దీన్నే Compile-Time (Static) Polymorphism అంటారు.

// ఒకే పేరు, కానీ వేరు వేరు ఇన్పుట్స్:
add(int a, int b)           // రెండు నంబర్స్ ని కలుపుతుంది
add(double a, double b)     // పాయింట్ నంబర్స్ ని కలుపుతుంది
add(int a, int b, int c)    // మూడు నంబర్స్ ని కలుపుతుంది

2. Overloading చేయడానికి 3 రూల్స్

ఒకే పేరుతో మెథడ్స్ ఉండాలంటే, ఈ మూడింట్లో ఏదో ఒక తేడా కచ్చితంగా ఉండాలి:

రూల్ ఉదాహరణ 1 ఉదాహరణ 2
1. పారామీటర్స్ సంఖ్య మారాలి add(int a, int b) add(int a, int b, int c)
2. పారామీటర్ డేటా టైప్ మారాలి print(int x) print(String s)
3. టైప్స్ ఆర్డర్ (సీక్వెన్స్) మారాలి log(String msg, int code) log(int code, String msg)

చాలా ఇంపార్టెంట్ రూల్: కేవలం Return Type మాత్రమే మార్చి, ఒకే పేరు, ఒకే పారామీటర్స్ ఇస్తే జావా ఒప్పుకోదు! (ఎర్రర్ వస్తుంది)

// ఎర్రర్: రెండు మెథడ్స్ సేమ్ ఉన్నాయి అని అరుస్తుంది కంపైలర్
int calculate(int a) { return a * 2; }
double calculate(int a) { return a * 2.0; } // calculate(5) అని పిలిస్తే, జావాకి ఏది రన్ చేయాలో అర్థం కాదు!

3. Automatic Type Promotion (ఆటోమాటిక్ గా పెంచడం)

ఒకవేళ మీరు పంపించిన టైప్ కి ఎగ్జాక్ట్ మ్యాచ్ అయ్యే మెథడ్ లేకపోతే.. జావా దాన్ని ఆటోమాటిక్ గా కొంచెం పెద్ద డేటా టైప్ కి ప్రమోట్ చేసి (మార్చి) సరిపోయే మెథడ్ ఉందేమో వెతుకుతుంది:

$$\text{byte} \rightarrow \text{short} \rightarrow \text{int} \rightarrow \text{long} \rightarrow \text{float} \rightarrow \text{double}$$

static void display(double d) { System.out.println("Double: " + d); }

// ఒకవేళ మనం int ని పంపిస్తే:
display(42); // 42 అనే int ఆటోమాటిక్ గా 42.0 double కి ప్రమోట్ అయ్యి పై మెథడ్ రన్ అవుతుంది!

4. static vs Instance Methods (అసలు తేడా ఏంటి?)

ఫీచర్ static Methods (క్లాస్-లెవెల్) Instance Methods (ఆబ్జెక్ట్-లెవెల్)
ఎవరికీ సంబంధించింది? డైరెక్ట్ గా క్లాస్ కి సంబంధించింది. అందరికీ కామన్. మనం క్రియేట్ చేసిన ఆబ్జెక్ట్స్ కి సంబంధించింది.
ఎలా పిలవాలి? ClassName.methodName() (ఆబ్జెక్ట్ అక్కర్లేదు). object.methodName() (కచ్చితంగా ఆబ్జెక్ట్ ఉండాలి).
this వాడొచ్చా? వాడకూడదు! (దీనికి ఆబ్జెక్ట్ తో సంబంధం లేదు). వాడుకోవచ్చు. ఆబ్జెక్ట్ డేటాని యాక్సెస్ చేయడానికి ఇది వాడతాం.
ఏ వేరియబుల్స్ యాక్సెస్ చేయొచ్చు? కేవలం static వేరియబుల్స్ ని మాత్రమే యాక్సెస్ చేయగలదు. లోపల static, instance రెండింటినీ యాక్సెస్ చేయొచ్చు.
ఎప్పుడు వాడాలి? యూటిలిటీ మెథడ్స్, మ్యాథ్స్ కాలిక్యులేషన్స్ కి (ఉదా: Math.sqrt(), Arrays.sort()). ఆబ్జెక్ట్ కి సంబంధించిన పనులు చేయడానికి (ఉదా: account.withdraw()).

Beginner Example & Code Anatomy

☕ Main.java — Chapter 35 Core Example 
public class Main {
    // -------------------------------------------------------------
    // OVERLOADED METHODS (ఒకే పేరుతో వేరు వేరు పారామీటర్స్)
    // -------------------------------------------------------------
    // వెర్షన్ 1: 2 ints ఇస్తే ఇది రన్ అవుతుంది
    static int multiply(int a, int b) {
        System.out.print("  [multiply(int, int) రన్ అయ్యింది]       : ");
        return a * b;
    }

    // వెర్షన్ 2: 3 ints ఇస్తే ఇది రన్ అవుతుంది (కౌంట్ మారింది)
    static int multiply(int a, int b, int c) {
        System.out.print("  [multiply(int, int, int) రన్ అయ్యింది]  : ");
        return a * b * c;
    }

    // వెర్షన్ 3: 2 పాయింట్ నంబర్స్ ఇస్తే ఇది (డేటా టైప్ మారింది)
    static double multiply(double a, double b) {
        System.out.print("  [multiply(double, double) రన్ అయ్యింది] : ");
        return a * b;
    }

    // -------------------------------------------------------------
    // STATIC vs INSTANCE డెమో
    // -------------------------------------------------------------
    static class BankAccount {
        static String bankName = "HDFC Bank"; // ఇది క్లాస్ లెవెల్ (అందరికీ కామన్)
        double balance;                       // ఇది ఇన్స్టాన్స్ (ఒక్కో కస్టమర్ కి వేరుగా ఉంటుంది)

        BankAccount(double b) { this.balance = b; }

        // స్టాటిక్ మెథడ్ (దీనికి కస్టమర్ తో పని లేదు, డైరెక్ట్ గా బ్యాంక్ గురించి చెప్తుంది)
        static void printBankInfo() {
            System.out.println("  బ్యాంక్ పేరు: " + bankName);
            // System.out.println(balance); // ఎర్రర్ వస్తుంది! కస్టమర్ ఎవరో తెలియకుండా బ్యాలెన్స్ ఎలా చెప్తుంది?
        }

        // ఇన్స్టాన్స్ మెథడ్ (కచ్చితంగా ఆబ్జెక్ట్ ఉంటేనే పనిచేస్తుంది)
        void deposit(double amount) {
            this.balance += amount;
            System.out.printf("  $%.2f యాడ్ చేసారు. కొత్త బ్యాలెన్స్: $%.2f%n", amount, this.balance);
        }
    }

    public static void main(String[] args) {
        System.out.println("=== 1. Method Overloading డెమో ===");
        System.out.println(multiply(4, 5));
        System.out.println(multiply(2, 3, 4));
        System.out.println(multiply(2.5, 4.0));

        System.out.println("
=== 2. Type Promotion (ఆటోమాటిక్ ప్రమోషన్) ===");
        // ఒకటి float (3.5f), ఇంకోటి int (2) పంపిస్తున్నాం. 
        // రెండూ డబుల్ కి ప్రమోట్ అయ్యి థర్డ్ మెథడ్ రన్ అవుతుంది.
        System.out.println(multiply(3.5f, 2));

        System.out.println("
=== 3. Static Method Call (ఆబ్జెక్ట్ అక్కర్లేదు) ===");
        BankAccount.printBankInfo(); // డైరెక్ట్ గా క్లాస్ పేరుతో పిలిచేశాం

        System.out.println("
=== 4. Instance Method Call (ఆబ్జెక్ట్ కావాలి) ===");
        BankAccount account = new BankAccount(1000.0); // ఆబ్జెక్ట్ క్రియేట్ చేసాం
        account.deposit(250.0); // ఆబ్జెక్ట్ తో మెథడ్ ని పిలిచాం
    }
}

🔍 Line-by-Line Code Explanation

static int multiply(int a, int b, int c)

ఒకే పేరుతో ఇంకో మెథడ్ రాసాము. కానీ ఇక్కడ మూడు నంబర్స్ తీసుకుంటుంది కాబట్టి జావా ఒప్పుకుంది (Overloading).

multiply(3.5f, 2);

ఫస్ట్ ది float, సెకండ్ ది int. ఈ రెండు టైప్స్ తో మెథడ్ లేదు కాబట్టి జావా వాటన్నిటినీ పెద్దదైన double కి మార్చి అప్పుడు వెతికింది.

BankAccount.printBankInfo();

ఇది స్టాటిక్ మెథడ్. కాబట్టి మనం ఏ కస్టమర్ ఆబ్జెక్ట్ ని క్రియేట్ చేయకుండానే డైరెక్ట్ గా క్లాస్ పేరుతో పిలిచేసాం.

account.deposit(250.0);

ఇది ఇన్స్టాన్స్ మెథడ్. దీనికి ఒక ఆబ్జెక్ట్ కచ్చితంగా కావాలి. అందుకే 'account' అనే ఆబ్జెక్ట్ పట్టుకుని పిలిచాం.

Practical Real-World Example

☕ PracticalApplication.java — Industry Implementation 
public class PracticalApplication {
    // రియల్ టైమ్ సినారియో: పేమెంట్ గేట్వే (కార్డ్, UPI, వాలెట్ - ఒకే పేరుతో 3 ఫీచర్స్)
    public static class PaymentGateway {
        // 1. కార్డ్ తో పేమెంట్
        public static String processPayment(String cardNumber, String cvv, double amount) {
            return String.format("[కార్డ్] కార్డ్ నంబర్ లాస్ట్ 4 డిజిట్స్ %s కి $%.2f ఛార్జ్ చేసాం",
                    cardNumber.substring(cardNumber.length() - 4), amount);
        }

        // 2. UPI తో పేమెంట్ (Overloaded)
        public static String processPayment(String upiId, double amount) {
            return String.format("[UPI] %s కు $%.2f రిక్వెస్ట్ పంపాం", upiId, amount);
        }

        // 3. వాలెట్ & కూపన్ తో పేమెంట్ (Overloaded)
        public static String processPayment(String walletId, double amount, String promoCode) {
            double finalAmount = promoCode.equals("SAVE10") ? amount * 0.90 : amount;
            return String.format("[వాలెట్] %s అకౌంట్ కి (కూపన్: %s) $%.2f కట్ అయ్యింది",
                    walletId, promoCode, finalAmount);
        }
    }

    public static void main(String[] args) {
        System.out.println("=== పేమెంట్ గేట్వే ఓవర్ లోడింగ్ ===");
        System.out.println(PaymentGateway.processPayment("4111222233334567", "123", 149.99));
        System.out.println(PaymentGateway.processPayment("developer@upi", 49.00));
        System.out.println(PaymentGateway.processPayment("PAYTM_WALLET_88", 100.0, "SAVE10"));
    }
}

⚠️ Common Mistakes & Professional Best Practices
  • కేవలం రిటర్న్ టైప్ ని మార్చి (ఉదా: ఒక దానికి int, ఇంకో దానికి double ఇచ్చి) ఓవర్ లోడ్ చేద్దాం అనుకోవడం. కంపైలర్ కి ఎర్రర్ వస్తుంది.
  • స్టాటిక్ మెథడ్ లోపల ఆబ్జెక్ట్ వేరియబుల్స్ (non-static fields) ని డైరెక్ట్ గా వాడుకోవడానికి ట్రై చేయడం.
  • ఏ మెథడ్ ని పిలుస్తున్నామో తెలియకుండా కన్ఫ్యూజ్ అయ్యేలా ఓవర్ లోడ్ చేయడం (ఉదా: test(int, long) మరియు test(long, int) రాసి test(5, 5) అని పిలవడం).

// Coding Challenge:
// ఒకే పేరుతో (area) 3 రకాల మెథడ్స్ ని రాయండి (Overloading):
// 1. area(double radius) -> సర్కిల్ ఏరియా ఇవ్వాలి: Math.PI * r * r
// 2. area(double length, double width) -> రెక్టాంగిల్ ఏరియా: l * w
// 3. area(double base, double height, boolean isTriangle) -> ట్రయాంగిల్ ఏరియా: 0.5 * b * h

public class Challenge {
    public static double area(double radius) {
        return Math.PI * radius * radius;
    }

    public static double area(double length, double width) {
        return length * width;
    }

    // జస్ట్ టైప్స్ మార్చడానికి boolean పెట్టాం, లేకపోతే పైదానికి దీనికి కన్ఫ్యూజ్ అవుతుంది
    public static double area(double base, double height, boolean isTriangle) {
        return 0.5 * base * height;
    }

    public static void main(String[] args) {
        System.out.printf("సర్కిల్ ఏరియా (r=5)     : %.2f%n", area(5.0));
        System.out.printf("రెక్టాంగిల్ ఏరియా (4x6)  : %.2f%n", area(4.0, 6.0));
        System.out.printf("ట్రయాంగిల్ ఏరియా (b=4,h=5): %.2f%n", area(4.0, 5.0, true));
    }
}

💡 Frequently Asked Questions & Interview Insights

❓ రిటర్న్ టైప్ ఒక్కటే మార్చి మెథడ్ ని ఎందుకు ఓవర్ లోడ్ చేయలేం?

ఎందుకంటే మీరు మెథడ్ ని పిలిచేటప్పుడు రిటర్న్ వాల్యూ ని వాడకపోవచ్చు కదా! (ఉదా: `calculate(5);`). అప్పుడు కంపైలర్ కి అర్థం కాదు, ఏ రిటర్న్ టైప్ ఉన్న మెథడ్ ని రన్ చేయాలి అని. అందుకే అలా ఒప్పుకోదు.

❓ main() మెథడ్ ని కూడా ఓవర్ లోడ్ చేయొచ్చా?

హ్యాపీగా చేయొచ్చు! మీరు `main(int[] args)` అని కూడా రాసుకోవచ్చు. కాకపోతే మీ ప్రోగ్రామ్ రన్ చేసేటప్పుడు జావా మాత్రం కేవలం స్టాండర్డ్ `main(String[] args)` ని మాత్రమే వెతికి ఎగ్జిక్యూట్ చేస్తుంది.

❓ స్టాటిక్ మెథడ్స్, ఇన్స్టాన్స్ మెథడ్స్ ని పిలవగలవా?

డైరెక్ట్ గా పిలవలేవు. ఎందుకంటే స్టాటిక్ మెథడ్స్ గాలిలో (క్లాస్ కి) ఉంటాయి, వాటికి `this` ఆబ్జెక్ట్ అంటే తెలీదు. ఒకవేళ పిలవాలి అనుకుంటే, ముందు ఆ మెథడ్ లోపల ఒక ఆబ్జెక్ట్ ని క్రియేట్ చేసి (`new MyClass().method()`) ఆ తర్వాత పిలవాలి.

🚀 Quick Chapter Recap

  • Method Overloading అంటే ఒకే పేరు, వేరు వేరు పారామీటర్స్ తో మల్టిపుల్ మెథడ్స్ రాయడం.
  • ఇది ఏ మెథడ్ రన్ అవ్వాలో కంపైలర్ ముందే డిసైడ్ చేస్తుంది కాబట్టి దీన్ని Static Polymorphism అంటారు.
  • పారామీటర్స్ కౌంట్ గానీ, డేటా టైప్ గానీ, వాటి ఆర్డర్ గానీ మారితేనే Overloading అవుతుంది.
  • static మెథడ్స్ క్లాస్ కి సంబంధించినవి (డైరెక్ట్ గా పిలవొచ్చు). ఇన్స్టాన్స్ మెథడ్స్ ఆబ్జెక్ట్ కి సంబంధించినవి.
  • static మెథడ్స్ లోపల this అనే కీవర్డ్ వాడకూడదు.
