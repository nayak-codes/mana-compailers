ఎన్‌క్యాప్సులేషన్, యాక్సెస్ మోడిఫైయర్స్ & Auto-Properties

⚡ Modern C# 12 & .NET 8 🟢 Chapter 14 of 20 📂 Phase 04: ఆబ్జెక్ట్ ఓరియెంటెడ్ ప్రోగ్రామింగ్ (OOP) 📅 2026 Edition
📌 Covered in this chapter: public, private, protected, internal · Getters & Setters · Auto-Implemented Properties { get; set; } · init-only యాక్సెసర్స్
ఆబ్జెక్ట్ ఓరియెంటెడ్ ప్రోగ్రామింగ్ యొక్క ముఖ్య ఉద్దేశం డేటా భద్రత. క్లాస్ లోపల ఉండే డేటాను బాహ్య ప్రపంచం ఇష్టారాజ్యంగా తప్పు విలువల (invalid values) తో మార్చకుండా నిరోధించే ప్రక్రియనే Encapsulation (ఎన్‌క్యాప్సులేషన్) అంటారు. C# లో ఎన్‌క్యాప్సులేషన్ సాధించడానికి శక్తివంతమైన యాక్సెస్ మోడిఫైయర్లు, Properties ({ get; set; }), మరియు ఇమ్మ్యూటబిలిటీ కోసం C# 9+ లో ప్రవేశపెట్టిన init-only accessors అందుబాటులో ఉన్నాయి.
1 ఎన్‌క్యాప్సులేషన్ ప్రాముఖ్యత: డేటా హైడింగ్ & వాలిడేషన్

ఒక బ్యాంకు ఖాతాలో public decimal Balance; అని ఉంచితే, ఎవరైనా బయటి నుండి acc.Balance = -99999; అని నెగటివ్ వ్యాల్యూ కేటాయించి సిస్టమ్‌ను పాడు చేయవచ్చు. డేటా ఫీల్డ్స్‌ను private గా దాచిపెట్టి, కేవలం తనిఖీ చేయబడిన (validated) మెథడ్స్ లేదా ప్రాపర్టీల ద్వారా మాత్రమే యాక్సెస్ ఇవ్వడమే ఎన్‌క్యాప్సులేషన్ యొక్క అసలు రహస్యం.

నిజ జీవిత ఉదాహరణ: ATM మెషిన్‌లో డబ్బులు డ్రా చేయాలంటే పిన్ నెంబర్ కొట్టి, తగిన బ్యాలెన్స్ ఉందో లేదో చెక్ చేసిన తర్వాతే క్యాష్ బయటకు వస్తుంది; నేరుగా లాకర్‌లోని కరెన్సీని చేతితో తీసుకోలేము.

2 C# Access Modifiers విశ్లేషణ

క్లాస్ మరియు దాని మెంబర్లను ఎవరు యాక్సెస్ చేయవచ్చో నియంత్రించడానికి C# లో 6 రకాల యాక్సెస్ లెవెల్స్ ఉన్నాయి:

Modifier యాక్సెస్ పరిధి (Scope) ఎప్పుడు వాడాలి?
public ఎక్కడి నుండైనా (ఏ ప్రాజెక్ట్/అసెంబ్లీ నుండైనా) యాక్సెస్ చేయవచ్చు. ఏపీఐ మెథడ్స్, ఎక్స్‌టర్నల్ ఇంటర్‌ఫేస్
private కేవలం అదే క్లాస్ లోపల మాత్రమే యాక్సెస్ ఉంటుంది. ఇంటర్నల్ ఫీల్డ్స్, హెల్పర్ మెథడ్స్ (Default in classes)
protected అదే క్లాస్ మరియు దాని నుండి ఉద్భవించిన చైల్డ్ క్లాసుల్లో మాత్రమే. ఇన్‌హెరిటెన్స్ డిజైన్ కోసం
internal అదే అసెంబ్లీ (.dll/.exe ప్రాజెక్ట్) లోపల మాత్రమే. లైబ్రరీ ఇంటర్నల్ ఇంప్లిమెంటేషన్ (Default for types)
3 C# Properties: Classic Getters/Setters vs Modern Properties

జావా (Java) వంటి భాషల్లో getBalance() మరియు setBalance(val) అని రెండు విడివిడి మెథడ్స్ రాస్తారు. కానీ C# లో Properties ఒకే చోట get మరియు set యాక్సెసర్స్ కలిగి ఉండి, బయటి ప్రపంచానికి సాధారణ ఫీల్డ్‌లా కనిపిస్తాయి.

PropertyValidation.cs ⚡ Try in C# Compiler 
using System;

class BankAccount
{
    // Private backing field
    private decimal _balance;

    // Full Property with Validation
    public decimal Balance
    {
        get => _balance;
        set
        {
            if (value < 0)
            {
                throw new ArgumentException("Balance cannot be negative!");
            }
            _balance = value;
        }
    }
}

class Program
{
    static void Main()
    {
        BankAccount acc = new BankAccount();
        acc.Balance = 1500m; // Calls 'set' accessor seamlessly
        Console.WriteLine($"Balance: {acc.Balance:C}"); // Calls 'get' accessor

        try
        {
            acc.Balance = -500m; // Throws ArgumentException!
        }
        catch (ArgumentException ex)
        {
            Console.WriteLine($"Security Check: {ex.Message}");
        }
    }
}
4 Auto-Implemented Properties & C# 9+ init Accessors

ప్రత్యేకమైన వాలిడేషన్ అవసరం లేని సాధారణ ప్రాపర్టీల కోసం C# 3.0 లో Auto-Implemented Properties ({ get; set; }) ప్రవేశపెట్టబడ్డాయి. బ్యాక్‌గ్రౌండ్‌లో కంపైలరే ఒక సీక్రెట్ ప్రైవేట్ ఫీల్డ్‌ను మేనేజ్ చేస్తుంది.

init Accessor (C# 9+): ఆబ్జెక్ట్ తయారయ్యేటప్పుడు (Object Initializer లో) మాత్రమే విలువను సెట్ చేసి, ఆ తర్వాత ఎవరూ మార్చకుండా ఇమ్మ్యూటబుల్ (Immutable) గా లాక్ చేయడానికి init వాడతారు.

AutoAndInitProperties.cs ⚡ Try in C# Compiler 
using System;

class Customer
{
    // Immutable ID: Can only be set during initialization!
    public int Id { get; init; }
    
    // Read-write Auto Property
    public string Name { get; set; }

    // Read-only externally, settable only inside this class
    public DateTime CreatedAt { get; private set; } = DateTime.UtcNow;
}

class Program
{
    static void Main()
    {
        // Object Initializer syntax
        Customer c = new Customer 
        { 
            Id = 1001, 
            Name = "Kavitha" 
        };

        c.Name = "Kavitha Rao"; // Allowed!
        // c.Id = 1002; // Compile Error! 'init' property cannot be modified after creation!
        
        Console.WriteLine($"Customer #{c.Id}: {c.Name} (Created: {c.CreatedAt:g})");
    }
}
5 Computed (Calculated) Properties

మెమరీలో ప్రత్యేకంగా ఫీల్డ్ లేకుండా, ఇప్పటికే ఉన్న ఇతర ప్రాపర్టీల ఆధారంగా ఎప్పటికప్పుడు ఆటోమేటిక్‌గా లెక్కించబడే ప్రాపర్టీలను Computed Properties అంటారు. వీటి కోసం ఎక్స్‌ప్రెషన్ బాడీడ్ సింటాక్స్ అత్యద్భుతంగా సరిపోతుంది.

ComputedProperty.cs ⚡ Try in C# Compiler 
using System;

class Rectangle
{
    public double Width { get; set; }
    public double Height { get; set; }

    // Computed Property (No backing field in memory)
    public double Area => Width * Height;
    public bool IsSquare => Width == Height;
}

class Program
{
    static void Main()
    {
        Rectangle rect = new Rectangle { Width = 10, Height = 5 };
        Console.WriteLine($"Area: {rect.Area}, Is Square? {rect.IsSquare}");

        rect.Height = 10;
        Console.WriteLine($"After change -> Is Square? {rect.IsSquare}");
    }
}
6 బిగినర్ తప్పులు & ఇంటర్వ్యూ FAQ
⚠️ ప్రమాదకరమైన తప్పు: Property Setter లో ఇన్ఫైనైట్ రికర్షన్ (StackOverflowException)
public int Age { get => _age; set => Age = value; } అని రాస్తే, set లోపలే మళ్ళీ ప్రాపర్టీ Age ని కాల్ చేయడం వల్ల ఇన్ఫైనైట్ లూప్ ఏర్పడి వెంటనే StackOverflowException తో ప్రోగ్రామ్ పేలిపోతుంది! సెట్టర్ లోపల ఎల్లప్పుడూ ప్రైవేట్ బ్యాకింగ్ ఫీల్డ్ _age = value; కే కేటాయించాలి.

తరచుగా అడిగే ప్రశ్నలు (FAQ):

  • { get; private set; } మరియు { get; init; } మధ్య తేడా ఏమిటి?
    private set ఉన్నప్పుడు క్లాస్ లోపలి మెథడ్స్ ఎప్పుడైనా వ్యాల్యూను మార్చవచ్చు. కానీ init వాడితే ఆబ్జెక్ట్ ఇనిషియలైజ్ అయిన తర్వాత ఆ క్లాస్ లోపలి మెథడ్స్ కూడా దాన్ని మార్చలేవు (True Immutability).
  • C# లో క్లాస్‌లకు డీఫాల్ట్ యాక్సెస్ మోడిఫైయర్ ఏమిటి?
    నేరుగా నేమ్‌స్పేస్‌లో రాసే క్లాస్‌లకు డీఫాల్ట్‌గా internal ఉంటుంది. అదే క్లాస్ లోపల ఉండే ఫీల్డ్స్ మరియు మెథడ్స్‌కు డీఫాల్ట్‌గా private ఉంటుంది.
