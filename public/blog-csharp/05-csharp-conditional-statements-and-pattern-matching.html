కండిషనల్ స్టేట్‌మెంట్స్ (if-else) & C# Pattern Matching

⚡ Modern C# 12 & .NET 8 🟢 Chapter 5 of 20 📂 Phase 02: కంట్రోల్ ఫ్లో, లూప్స్ & ప్యాటర్న్ మ్యాచింగ్ 📅 2026 Edition
📌 Covered in this chapter: if, else if, else · డాంగ్లింగ్ else నివారణ · Type Pattern & Relational Pattern Matching · switch Expressions (=>)
కంప్యూటర్ ప్రోగ్రామ్‌లు నిజమైన ప్రయోజనాన్ని ఇవ్వాలంటే అవి పరిస్థితులను బట్టి స్వతంత్రంగా సరైన నిర్ణయాలు (Decision Making) తీసుకోగలగాలి. ఆన్‌లైన్ షాపింగ్‌లో డిస్కౌంట్ కాలిక్యులేషన్, బ్యాంకింగ్ క్రెడిట్ స్కోర్ చెకింగ్ లేదా గేమ్ క్యారెక్టర్ మూవ్‌మెంట్లలో నిర్ణయాలు తీసుకోవడానికి C# లో కండిషనల్ స్టేట్‌మెంట్స్ (if-else) మూలస్తంభాలు. ఆధునిక C# (C# 9 నుండి C# 12 వరకు) లో ప్రవేశపెట్టిన అత్యాధునిక Pattern Matching ఫీచర్లు కోడ్‌ను ఎలా సంక్షిప్తంగా, సురక్షితంగా చేస్తాయో ఈ అధ్యాయంలో సమగ్రంగా పరిశీలిద్దాం.
1if, else if, else డెసిషన్ మేకింగ్ ఆర్కిటెక్చర్

C లేదా C++ లలో ఏదైనా నాన్-జీరో సంఖ్య నిజం (True) గా పరిగణించబడుతుంది. కానీ C# లో టైప్ సేఫ్టీ కఠినమైనది: if కండిషన్ లోపల తప్పనిసరిగా కేవలం 'bool' (true లేదా false) మాత్రమే ఉండాలి. పూర్ణాంకాలను నేరుగా కండిషన్‌గా వాడటం C# లో నిషిద్ధం.

1. if స్టేట్‌మెంట్ (Single Branch):

ఇచ్చిన బూలియన్ షరతు నిజమైతేనే ఆ కోడ్ బ్లాక్ రన్ అవుతుంది. అబద్ధమైతే ప్రోగ్రామ్ దాన్ని దాటవేసి ముందుకు వెళ్తుంది.

2. if-else స్టేట్‌మెంట్ (Two-Way Branch):

షరతు నిజమైతే మొదటి బ్లాక్, అబద్ధమైతే ప్రత్యామ్నాయంగా else బ్లాక్ ఖచ్చితంగా ఎగ్జిక్యూట్ అవుతుంది.

3. else-if లాడర్ (Multi-Way Ladder):

బహుళ షరతులను పై నుండి క్రిందికి వరుసగా తనిఖీ చేస్తుంది. మొదటి ఏ షరతు నిజమైతే ఆ బ్లాక్ రన్ అయి మిగిలిన మొత్తం లాడర్ స్కిప్ అవుతుంది.

C# — ATM Cash Withdrawal Decision Flow ⚡ Try in C# Compiler 
decimal accountBalance = 15000.00m;
decimal withdrawAmount = 5000.00m;

if (withdrawAmount <= 0) {
    Console.WriteLine("❌ చెల్లని మొత్తం! ధన సంఖ్యను నమోదు చేయండి.");
} else if (withdrawAmount > accountBalance) {
    Console.WriteLine($"❌ సరిపడా నిధులు లేవు! మీ బ్యాలెన్స్: ₹{accountBalance}");
} else {
    accountBalance -= withdrawAmount;
    Console.WriteLine($"✅ విత్‌డ్రా విజయవంతమైంది: ₹{withdrawAmount}. మిగిలిన బ్యాలెన్స్: ₹{accountBalance}");
}
2డాంగ్లింగ్ else సమస్య & బ్రాకెట్ల నిబంధన (The Dangling else)

ఒక if లోపల మరొక if రాసినప్పుడు కర్లీ బ్రేసెస్ { } ఉపయోగించకపోతే కంప్యూటర్‌కు ఏ else ఎవరికి చెందుతుందో గందరగోళం ఏర్పడుతుంది:

⚠️ డాంగ్లింగ్ else ట్రాప్: if (score >= 35)
    if (score >= 90)
        Console.WriteLine("A Grade");
else
    Console.WriteLine("Failed!"); // ఈ else ఎవరికి చెందుతుంది?

పై కోడ్‌లో else మొదటి if(score >= 35) కి చెందినదిగా అనిపించవచ్చు. కానీ C# నియమం ప్రకారం ఏ బ్రాకెట్ లేని else ఎల్లప్పుడూ తనకు అత్యంత సమీపంలో ఉన్న మునుపటి if కే జతచేయబడుతుంది! కాబట్టి score = 70 అయితే ఏమీ ప్రింట్ అవ్వదు. అందుకే ప్రొఫెషనల్ కోడింగ్‌లో సింగిల్ లైన్ అయినా ఎల్లప్పుడూ కర్లీ బ్రేసెస్ { ... } వాడాలి.

3C# మోడ్రన్ ప్యాటర్న్ మ్యాచింగ్ (Pattern Matching Revolution)

ఆధునిక C# (C# 9 నుండి C# 12 వరకు) లో ప్రవేశపెట్టిన అత్యంత శక్తివంతమైన ఫీచర్ Pattern Matching. సాంప్రదాయ if-else ల కంటే ఇది కోడ్‌ను విప్లవాత్మకంగా సంక్షిప్తం చేస్తుంది:

1. Type Pattern (టైప్ చెకింగ్ + ఇన్లైన్ వేరియబుల్): if (data is string text) { Console.WriteLine(text.Length); }

డేటా రకాన్ని తనిఖీ చేసి, సరిపోలితే ఆటోమేటిక్‌గా టైప్ కాస్టింగ్ చేసి కొత్త వేరియబుల్‌ను సృష్టిస్తుంది.

2. Relational & Logical Patterns (పరిధుల పోలిక): if (age is >= 18 and < 60) { Console.WriteLine("Working Age"); }

age >= 18 && age < 60 అని రెండుసార్లు వేరియబుల్ రాయకుండా is >= 18 and < 60 అని సహజ ఇంగ్లీష్ లాగా రాయవచ్చు.

3. Negative Pattern (is not null): if (customer is not null) { ... }

customer != null కంటే is not null మరింత స్పష్టంగా మరియు ఆపరేటర్ ఓవర్‌లోడింగ్ సమస్యలు లేకుండా పనిచేస్తుంది.

4టెర్నరీ ఆపరేటర్ (Ternary Operator ?: )

రెండు లైన్ల సాధారణ if-else బ్లాక్‌ను కేవలం ఒకే ఒక్క లైన్‌లో ఎక్స్‌ప్రెషన్‌గా రాయడానికి టెర్నరీ ఆపరేటర్ (?:) ఉపయోగపడుతుంది:

C# — Ternary Conditional Operator ⚡ Try in C# Compiler 
int score = 85;
string result = (score >= 40) ? "ఉత్తీర్ణత (Pass)" : "ఫెయిల్ (Fail)";
Console.WriteLine($"పరీక్ష ఫలితం: {result}");

int a = 120, b = 95;
int maximum = (a > b) ? a : b;
Console.WriteLine($"గరిష్ట సంఖ్య: {maximum}");
5బిగినర్స్ చేసే ఘోరమైన తప్పులు (Beginner Pitfalls)
❌ 1. if పక్కన సెమికోలన్ పెట్టడం (Empty Statement Trap):
if (userRole == "Admin"); { GrantAccess(); } // సెమికోలన్ పెట్టరాదు! if(...); అని పెడితే కండిషన్ అక్కడితో ముగిసిపోతుంది. దాంతో యూజర్ ఎవరైనా సరే కర్లీ బ్రేసెస్ లోని కోడ్ ప్రతిసారీ రన్ అయిపోయి ఘోరమైన సెక్యూరిటీ బగ్ తలెత్తుతుంది!
❌ 2. if లో అసైన్‌మెంట్ ప్రయత్నించడం:
if (status = 1) // Compiler Error! Cannot convert int to bool C/C++ లో ఇది సైలెంట్ బగ్. కానీ C# లో టైప్ సేఫ్టీ వల్ల కంపైలర్ తక్షణమే ఎర్రర్ ఇస్తుంది. పోల్చడానికి ఎల్లప్పుడూ == వాడాలి.
6తరచుగా అడిగే ప్రశ్నలు (FAQ)

Q: is null మరియు == null ల మధ్య సాంకేతిక తేడా ఏమిటి?

ఒక క్లాస్‌లో డెవలపర్ == ఆపరేటర్‌ను ఓవర్‌లోడ్ చేసి తప్పుడు లాజిక్ రాసి ఉండవచ్చు. కానీ is null అనేది ఆపరేటర్ ఓవర్‌లోడింగ్‌ను దాటవేసి, CLR మెమరీ స్థాయిలో ఆ రిఫరెన్స్ నిజంగా శూన్యమా కాదా అని ఖచ్చితంగా తనిఖీ చేస్తుంది. అందుకే మోడ్రన్ C# లో is null వాడటమే సిఫార్సు.

Q: if-else లాడర్ మరియు switch లలో పర్ఫార్మెన్స్ పరంగా ఏది ఉత్తమం?

పరిధులు (Ranges, e.g. age >= 18) ఉన్నప్పుడు if-else సహజమైనది. కానీ స్థిరమైన విలువలపై (Discrete values) పనిచేసేటప్పుడు కంపైలర్ switch ను $O(1)$ జంప్ టేబుల్‌గా ఆప్టిమైజ్ చేస్తుంది కాబట్టి switch వేగవంతమైనది.
