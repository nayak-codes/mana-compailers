యూజర్ ఇన్‌పుట్ (Console.ReadLine), టైప్ కాస్టింగ్ & Parse / TryParse

⚡ Modern C# 12 & .NET 8 🟢 Chapter 3 of 20 📂 Phase 01: C# ఫండమెంటల్స్ & బేసిక్స్ 📅 2026 Edition
📌 Covered in this chapter: Console.ReadLine() · Implicit vs Explicit Casting · int.Parse() vs int.TryParse() ఎర్రర్-ఫ్రీ పార్సింగ్ · Convert క్లాస్
కన్సోల్ అప్లికేషన్లు యూజర్ నుండి సమాచారాన్ని స్వీకరించి ప్రాసెస్ చేసినప్పుడే ఉపయోగకరంగా మారతాయి. C# లో కీబోర్డ్ ఇన్‌పుట్ తీసుకోవడానికి Console.ReadLine() ప్రాథమిక సాధనం. అయితే యూజర్ ఇచ్చే డేటా ఎల్లప్పుడూ టెక్స్ట్ (String) రూపంలోనే ఉంటుంది. ఆ టెక్స్ట్‌ను సంఖ్యలుగా మార్చేటప్పుడు అప్లికేషన్ క్రాష్ కాకుండా రక్షించే ప్రసిద్ధ int.TryParse() ప్యాటర్న్, మరియు టైప్ కాస్టింగ్ నిబంధనలను ఈ అధ్యాయంలో సమగ్రంగా పరిశీలిద్దాం.
1Console.ReadLine() అంతర్గత పనితీరు

యూజర్ కీబోర్డ్ ద్వారా ఒక లైన్ సమాచారాన్ని టైప్ చేసి Enter కీ ప్రెస్ చేసేంత వరకు Console.ReadLine() వేచి చూస్తుంది.

🔑 గోల్డెన్ రూల్: ఇన్‌పుట్ ఎల్లప్పుడూ string మాత్రమే!

యూజర్ నంబర్ 25 అని టైప్ చేసినా, కంప్యూటర్ దృష్టిలో అది సంఖ్య కాదు; కేవలం రెండు అక్షరాల టెక్స్ట్ "25" మాత్రమే. దానిపై గణిత లెక్కలు చేయాలంటే మనం దానిని సంఖ్యగా (Integer / Double) మార్చాల్సిందే.

C# — Basic User Input ⚡ Try in C# Compiler 
Console.Write("మీ పేరు నమోదు చేయండి: ");
string? name = Console.ReadLine();

Console.WriteLine($"స్వాగతం, {name} గారు!");
2టైప్ కన్వర్షన్ రకాలు — Implicit vs Explicit (Casting)

1. Implicit Casting (ఆటోమేటిక్):

చిన్న డేటా టైప్ నుండి పెద్ద డేటా టైప్‌కు మార్చినప్పుడు ఎటువంటి డేటా నష్టం జరగదు కాబట్టి C# కంపైలర్ స్వయంగా చేస్తుంది.

int a = 100;
double b = a; // ఆటోమేటిక్ గా 100.0 అవుతుంది

2. Explicit Casting (మ్యాన్యువల్):

పెద్ద టైప్ నుండి చిన్న టైప్‌కు మార్చినప్పుడు డేటా నష్టం లేదా దశాంశాలు తొలగిపోయే ప్రమాదం ఉంటుంది. డెవలపర్ బాధ్యత తీసుకోవాలి.

double pi = 3.99;
int intPi = (int)pi; // 3 అవుతుంది (దశాంశం తుడిచిపెట్టుకుపోతుంది)
3Parse() vs TryParse() — ఎర్రర్-ఫ్రీ పార్సింగ్ ప్యాటర్న్

ఒక స్ట్రింగ్‌ను సంఖ్యగా మార్చడానికి int.Parse() వాడవచ్చు. కానీ యూజర్ అనుకోకుండా సంఖ్య బదులు అక్షరాలు టైప్ చేస్తే int.Parse() వెంటనే భయంకరమైన FormatException తో యాప్‌ను క్రాష్ చేస్తుంది!

🛡️ ప్రొడక్షన్ స్టాండర్డ్: int.TryParse() ప్యాటర్న్

int.TryParse() క్రాష్ కాకుండా రక్షణ కల్పిస్తుంది. కన్వర్షన్ విజయవంతమైతే true రిటర్న్ చేసి ఆ విలువను out వేరియబుల్ లోకి వేస్తుంది; విఫలమైతే క్రాష్ అవ్వకుండా కేవలం false ఇస్తుంది.

C# — Bulletproof TryParse Demo ⚡ Try in C# Compiler 
Console.Write("మీ వయస్సు నమోదు చేయండి: ");
string? input = Console.ReadLine();

// C# 7+ ఇన్లైన్ out వేరియబుల్ డిక్లరేషన్
if (int.TryParse(input, out int age) && age > 0) {
    Console.WriteLine($"సరైన వయస్సు: {age} సంవత్సరాలు.");
} else {
    Console.WriteLine("❌ చెల్లని సంఖ్య! దయచేసి సరైన పూర్ణాంకాన్ని టైప్ చేయండి.");
}
4Convert క్లాస్ (Convert.ToInt32, Convert.ToDouble)

Convert.ToInt32() పద్ధతి కూడా పార్సింగ్ చేస్తుంది. దీనికి int.Parse() కి ఉన్న ప్రధాన తేడా ఏమిటంటే: ఒకవేళ ఇన్‌పుట్ null అయితే, Convert క్లాస్ ఎర్రర్ ఇవ్వకుండా డిఫాల్ట్ 0 (సున్నా) రిటర్న్ చేస్తుంది.

5బిగినర్స్ చేసే ఘోరమైన తప్పులు (Beginner Pitfalls)
❌ 1. కాస్టింగ్ తో స్ట్రింగ్ మార్చాలనుకోవడం:
string s = "50"; int num = (int)s; // Compiler Error! Cannot convert type string to int స్ట్రింగ్స్ మరియు న్యూమరిక్ టైప్స్ వేర్వేరు మెమరీ ఫార్మాట్లలో ఉంటాయి. కాస్టింగ్ (int) పనిచేయదు; తప్పనిసరిగా int.Parse() లేదా int.TryParse() వాడాలి.
❌ 2. ప్రొడక్షన్ కోడ్‌లో నేరుగా int.Parse() వాడటం:
యూజర్ ఖాళీగా ఎంటర్ నొక్కినా లేదా స్పేస్ ఇచ్చినా int.Parse() మొత్తం యాప్‌ను క్రాష్ చేస్తుంది. ఎల్లప్పుడూ TryParse() నే ప్రాధాన్యత ఇవ్వాలి.
6తరచుగా అడిగే ప్రశ్నలు (FAQ)

Q: checked మరియు unchecked బ్లాక్స్ ఎందుకు ఉపయోగిస్తారు?

C# లో డిఫాల్ట్‌గా ఇంటిజర్ ఓవర్‌ఫ్లో అయినప్పుడు ఎర్రర్ రాకుండా నిశ్శబ్దంగా నెగటివ్ విలువగా మారుతుంది. checked { int max = int.MaxValue + 1; } అని రాస్తే, ఓవర్‌ఫ్లో జరగగానే OverflowException ను త్రో చేసి ప్రమాదాన్ని హెచ్చరిస్తుంది.

Q: Console.ReadLine() పక్కన string? (Question Mark) ఎందుకు కనిపిస్తుంది?

C# 8 లో ప్రవేశపెట్టిన Nullable Reference Types ప్రకారం, యూజర్ ఏమీ టైప్ చేయకుండా Ctrl+Z (EOF) ప్రెస్ చేస్తే null వచ్చే అవకాశం ఉందని కంపైలర్ సూచిస్తుంది.
