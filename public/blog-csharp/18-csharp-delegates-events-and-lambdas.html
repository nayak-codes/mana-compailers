ఆధునిక C# మరియు .NET ప్రపంచంలో ఈవెంట్-డ్రైవెన్ ఆర్కిటెక్చర్, అసమకాలిక ప్రోగ్రామింగ్ (Async), మరియు ఫంక్షనల్ ప్రోగ్రామింగ్ పద్ధతులకు Delegates వెన్నెముక వంటివి. డెలిగేట్ అనేది ఒక మెథడ్‌ను వేరియబుల్ లాగా పారామీటర్‌గా పంపే వీలు కల్పించే Type-Safe Function Pointer. దీనితో పాటు .NET లో అత్యంత విస్తృతంగా ఉపయోగించే Func<T>, Action<T>, మోడరన్ Lambda Expressions (=>), మరియు Events (Publisher-Subscriber) పనితీరును ఈ అధ్యాయంలో లోతుగా ఆవిష్కరిస్తాం.
1 డెలిగేట్స్ అంటే ఏమిటి? Type-Safe Function Pointers

C మరియు C++ లలో ఫంక్షన్ పాయింటర్లు ఉంటాయి, కానీ వాటికి టైప్ సేఫ్టీ ఉండదు (మెమరీ క్రాష్ అయ్యే ప్రమాదం ఉంటుంది). C# లో Delegate అనేది ఆబ్జెక్ట్ ఓరియెంటెడ్ మరియు 100% టైప్-సేఫ్ ఫంక్షన్ పాయింటర్.

ఒక డెలిగేట్ నిర్దిష్ట రిటర్న్ టైప్ మరియు పారామీటర్ సిగ్నేచర్‌ను కలిగి ఉంటుంది. ఆ సిగ్నేచర్‌తో సరిపోలే ఏ మెథడ్‌నైనా ఆ డెలిగేట్ వేరియబుల్‌కు అసైన్ చేసి కాల్ చేయవచ్చు.

CustomDelegateBasics.cs ⚡ Try in C# Compiler 
using System;

// 1. Delegate Declaration: accepts string, returns void
delegate void LogDelegate(string message);

class Program
{
    static void ConsoleLogger(string msg) => Console.WriteLine($"[CONSOLE]: {msg}");
    static void AlertLogger(string msg) => Console.WriteLine($"[ALERT ***]: {msg.ToUpper()}");

    static void Main()
    {
        // 2. Delegate Instantiation pointing to a method
        LogDelegate logger = ConsoleLogger;
        logger("Server started on port 5000");

        // 3. Pointing to a different method at runtime
        logger = AlertLogger;
        logger("High CPU load detected!");
    }
}
2 Multicast Delegates (+, -= ఆపరేటర్లు)

C# లోని అన్ని డెలిగేట్లు అంతర్గతంగా System.MulticastDelegate క్లాస్ నుండి ఉద్భవిస్తాయి. దీనివల్ల += ఆపరేటర్ ఉపయోగించి ఒకే డెలిగేట్‌కు బహుళ మెథడ్స్‌ను ఒక ఇన్వోకేషన్ లిస్ట్ (Invocation List) లో చేర్చవచ్చు. డెలిగేట్‌ను కాల్ చేయగానే ఆ లిస్టులోని అన్ని మెథడ్స్ వరుసగా ఎగ్జిక్యూట్ అవుతాయి. అనవసరమైన మెథడ్‌ను తొలగించడానికి -= ఆపరేటర్ వాడతాం.

MulticastDelegateDemo.cs ⚡ Try in C# Compiler 
using System;

delegate void NotifyUser(string user);

class Program
{
    static void SendEmail(string user) => Console.WriteLine($"Email sent to {user}");
    static void SendSms(string user) => Console.WriteLine($"SMS sent to {user}");

    static void Main()
    {
        NotifyUser notifier = SendEmail;
        notifier += SendSms; // Multicast chaining

        Console.WriteLine("--- Triggering Notifications ---");
        notifier("Ravi Kumar");

        notifier -= SendSms; // Unregistering SMS
        Console.WriteLine("--- After removing SMS ---");
        notifier("Sneha");
    }
}
3 Built-in Generic Delegates: Action<T>, Func<T>, Predicate<T>

ప్రతి చిన్న లాజిక్ కోసం కొత్త డెలిగేట్ టైప్‌ను డిక్లేర్ చేయాల్సిన అవసరం లేకుండా, ఆధునిక .NET మూడు ప్రామాణిక జెనెరిక్ డెలిగేట్లను అందిస్తుంది:

  • Action<T1, T2...>: ఎటువంటి విలువను రిటర్న్ చేయని (void) మెథడ్స్ కోసం వాడతారు. (0 నుండి 16 పారామీటర్ల వరకు సపోర్ట్ చేస్తుంది).
  • Func<T1, TResult>: విలువను రిటర్న్ చేసే మెథడ్స్ కోసం వాడతారు. ఇందులో చివరి టైప్ పారామీటర్ ఎల్లప్పుడూ Return Type అవుతుంది.
  • Predicate<T>: ఒక ఆబ్జెక్ట్‌ను చెక్ చేసి bool (true/false) రిటర్న్ చేసే కండిషన్స్ కోసం వాడతారు. (నిజానికి ఇది Func<T, bool> తో సమానం).
ActionAndFuncDemo.cs ⚡ Try in C# Compiler 
using System;

class Program
{
    static void Main()
    {
        // Action: takes string, returns void
        Action printGreeting = name => Console.WriteLine($"Namaste, {name}!");
        printGreeting("Kiran");

        // Func: takes int and int, returns int (last type)
        Func multiply = (a, b) => a * b;
        Console.WriteLine($"Product: {multiply(8, 5)}");

        // Predicate: takes int, returns bool
        Predicate isAdult = age => age >= 18;
        Console.WriteLine($"Is 20 an adult? {isAdult(20)}");
    }
}
4 Lambda Expressions (=>) & Anonymous Methods

C# లో కోడ్‌ను సూక్ష్మీకరించడానికి లాంబ్డా ఎక్స్‌ప్రెషన్స్ ((parameters) => expression) అత్యంత శక్తివంతమైనవి. ప్రత్యేకంగా మెథడ్ రాయకుండానే, ఇన్‌లైన్‌లో ఇన్స్టాంట్‌గా ఫంక్షన్ బాడీని డిఫైన్ చేయవచ్చు.

Closures: లాంబ్డా ఎక్స్‌ప్రెషన్లు తమ వెలుపల ఉన్న లోకల్ వేరియబుల్స్‌ను క్యాప్చర్ (capture) చేసుకుని గుర్తుపెట్టుకోగలవు. దీనినే క్లోజర్ అంటారు.

LambdaClosures.cs ⚡ Try in C# Compiler 
using System;
using System.Collections.Generic;

class Program
{
    static void Main()
    {
        List numbers = new List { 12, 45, 68, 23, 89, 90 };

        // Lambda used as a filter condition
        List evenNumbers = numbers.FindAll(n => n % 2 == 0);
        Console.WriteLine($"Evens: {string.Join(", ", evenNumbers)}");

        // Closure Example: Capturing external factor
        int multiplier = 10;
        Func scale = n => n * multiplier; // multiplier captured!
        Console.WriteLine($"Scaled 7: {scale(7)}");
    }
}
5 Events & Publisher-Subscriber Pattern

డెలిగేట్‌ను నేరుగా వాడితే బయటి క్లాసులు ప్రమాదవశాత్తు delegate = null; అని అసైన్ చేసి పాత లిజనర్లను తుడిచిపెట్టే ప్రమాదం ఉంది. దీని నివారణకు C# లో event కీవర్డ్ వాడతారు.

  • Publisher: ఏదైనా సంఘటన జరిగినప్పుడు ఈవెంట్‌ను ట్రిగ్గర్ (Raise/Fire) చేసే క్లాస్.
  • Subscriber: ఆ ఈవెంట్ జరిగినప్పుడు స్పందించడానికి += ద్వారా రిజిస్టర్ చేసుకునే క్లాస్. బయటి క్లాసులు ఈవెంట్‌ను కేవలం += లేదా -= మాత్రమే చేయగలవు; నేరుగా ఇన్వోక్ చేయలేవు!
StockTickerEventDemo.cs ⚡ Try in C# Compiler 
using System;

// Publisher Class
class StockMarket
{
    // Event declaration using Action
    public event Action PriceChanged;

    public void UpdatePrice(string symbol, decimal newPrice)
    {
        Console.WriteLine($"[Market Alert] {symbol} updated to {newPrice:C}");
        // Safe null-conditional invoke
        PriceChanged?.Invoke(symbol, newPrice);
    }
}

class Program
{
    static void Main()
    {
        StockMarket market = new StockMarket();

        // Subscribers registering via +=
        market.PriceChanged += (sym, price) => 
            Console.WriteLine($"-> Investor App: Notified about {sym} at {price:C}");
        market.PriceChanged += (sym, price) => 
            Console.WriteLine($"-> Broker Bot: Auto-trading analysis for {sym}");

        // Firing the event
        market.UpdatePrice("TCS", 3950.50m);
    }
}
6 బిగినర్ తప్పులు & ఇంటర్వ్యూ FAQ
⚠️ ప్రమాదకరమైన తప్పు: Event Unsubscribe చేయకపోవడం (Memory Leak)
ఒక లాంగ్-లివ్డ్ పబ్లిషర్ క్లాస్ ఈవెంట్‌కు షార్ట్-లివ్డ్ సబ్‌స్క్రైబర్ రిజిస్టర్ అయ్యి, పని పూర్తయిన తర్వాత -= ద్వారా అన్‌సబ్‌స్క్రైబ్ చేసుకోకపోతే, గార్బేజ్ కలెక్టర్ ఆ సబ్‌స్క్రైబర్‌ను మెమరీ నుండి తొలగించలేదు (Lapsed Listener Problem). దీనివల్ల తీవ్రమైన మెమరీ లీక్ ఏర్పడుతుంది.

తరచుగా అడిగే ప్రశ్నలు (FAQ):

  • Delegate మరియు Event మధ్య ప్రాథమిక తేడా ఏమిటి?
    Delegate అనేది ఒక ఫంక్షన్ పాయింటర్ టైప్. Event అనేది ఆ డెలిగేట్‌పై ఒక ఎన్‌క్యాప్సులేషన్ లేయర్; బయటి క్లాసులు ఈవెంట్‌ను కేవలం += మరియు -= మాత్రమే చేయగలవు తప్ప నేరుగా ఓవర్‌రైట్ చేయలేవు లేదా ఇన్వోక్ చేయలేవు.
  • Action మరియు Func లలో ఏది రిటర్న్ చేస్తుంది?
    Action ఎల్లప్పుడూ void (ఏమీ రిటర్న్ చేయదు). Func ఎల్లప్పుడూ కచ్చితంగా ఏదో ఒక వ్యాల్యూను రిటర్న్ చేస్తుంది.
