క్లాసెస్, ఆబ్జెక్ట్స్ & కన్‌స్ట్రక్టర్స్ (Primary Constructors)

⚡ Modern C# 12 & .NET 8 🟢 Chapter 13 of 20 📂 Phase 04: ఆబ్జెక్ట్ ఓరియెంటెడ్ ప్రోగ్రామింగ్ (OOP) 📅 2026 Edition
📌 Covered in this chapter: క్లాస్ బ్లూప్రింట్ · new ఆపరేటర్ & Heap అలోకేషన్ · డీఫాల్ట్ & పారామీటరైజ్డ్ కన్‌స్ట్రక్టర్స్ · C# 12 Primary Constructors
ఆబ్జెక్ట్ ఓరియెంటెడ్ ప్రోగ్రామింగ్ (OOP) అనేది ఆధునిక సాఫ్ట్‌వేర్ ఆర్కిటెక్చర్‌కు పునాది. C# లో ప్రతి లాజిక్ క్లాసెస్ మరియు ఆబ్జెక్ట్స్ చుట్టూ కేంద్రీకృతమై ఉంటుంది. ఒక క్లాస్ అనేది డేటా (ఫీల్డ్స్) మరియు బిహేవియర్ (మెథడ్స్) లను కలిపి ఉంచే బ్లూప్రింట్. C# 12 మరియు .NET 8 లో కోడ్‌ను అత్యంత క్లీన్‌గా ఉంచే Primary Constructors అందుబాటులోకి వచ్చాయి. ఈ అధ్యాయంలో క్లాస్ డిజైన్, హీప్ అలోకేషన్, కన్‌స్ట్రక్టర్ చైనింగ్ మరియు స్టాటిక్ మెంబర్లను క్షుణ్ణంగా పరిశీలిద్దాం.
1 క్లాస్ బ్లూప్రింట్ & new ఆపరేటర్: Heap మెమరీ వర్కింగ్

Class: ఒక ఇంటిని నిర్మించడానికి ఇంజనీర్ వేసే బ్లూప్రింట్ (నమూనా) ఎలాంటిదో, సాఫ్ట్‌వేర్‌లో క్లాస్ అలాంటిది. ఇది ఆబ్జెక్ట్‌కు అవసరమైన లక్షణాలను నిర్వచిస్తుంది కానీ దీనికి స్వతంత్రంగా మెమరీ ఉండదు.

Object: బ్లూప్రింట్ చూసి నిర్మించిన అసలైన ఇంటిలాంటిదే ఆబ్జెక్ట్ (Instance). new కీవర్డ్ వాడినప్పుడు CLR మేనేజ్డ్ హీప్ (Managed Heap) పై మెమరీ కేటాయించి, ఆబ్జెక్ట్‌ను ఇనిషియలైజ్ చేస్తుంది.

ClassAndObjectBasics.cs ⚡ Try in C# Compiler 
using System;

// Blueprint
class BankAccount
{
    // Fields
    public string AccountNumber;
    public decimal Balance;

    // Method
    public void Deposit(decimal amount)
    {
        Balance += amount;
        Console.WriteLine($"Deposited: {amount:C}, Current Balance: {Balance:C}");
    }
}

class Program
{
    static void Main()
    {
        // Object Creation on Heap
        BankAccount acc1 = new BankAccount();
        acc1.AccountNumber = "SB-10029";
        acc1.Deposit(5000m);

        BankAccount acc2 = new BankAccount();
        acc2.AccountNumber = "SB-10030";
        acc2.Deposit(12000m);
    }
}

మెమరీ వర్కింగ్ విశ్లేషణ: acc1 మరియు acc2 అనేవి స్టాక్ (Stack) మెమరీలోని రిఫరెన్స్ పాయింటర్లు. అసలైన BankAccount డేటా అంతా మేనేజ్డ్ హీప్ (Heap) లో వేర్వేరు మెమరీ అడ్రస్‌లలో స్వతంత్రంగా ఉంటుంది.

2 this కీవర్డ్ & ఫీల్డ్ కన్‌ఫ్లిక్ట్ నివారణ

ఒక క్లాస్ లోపల ప్రస్తుతం ఏ ఇన్స్టాన్స్ (ఆబ్జెక్ట్) అయితే కోడ్‌ను రన్ చేస్తోందో ఆ ఆబ్జెక్ట్‌ను సూచించడానికి this కీవర్డ్ ఉపయోగపడుతుంది. మెథడ్ పారామీటర్ పేరు మరియు క్లాస్ ఫీల్డ్ పేరు రెండూ ఒకేలా ఉన్నప్పుడు కన్‌ఫ్యూజన్ లేకుండా స్పష్టత ఇవ్వడానికి ఇది అత్యవసరం.

ThisKeywordDemo.cs ⚡ Try in C# Compiler 
using System;

class Employee
{
    public int Id;
    public string Name;

    public void SetDetails(int Id, string Name)
    {
        // this.Id points to the Class Field
        // Id points to the Method Parameter
        this.Id = Id;
        this.Name = Name;
    }
}

class Program
{
    static void Main()
    {
        Employee emp = new Employee();
        emp.SetDetails(101, "Suresh");
        Console.WriteLine($"Employee ID: {emp.Id}, Name: {emp.Name}");
    }
}
3 కన్‌స్ట్రక్టర్లు & కన్‌స్ట్రక్టర్ ఓవర్‌లోడింగ్ (Constructor Chaining)

ఆబ్జెక్ట్ పుట్టగానే (క్రియేట్ అవ్వగానే) దానికి అవసరమైన ప్రారంభ విలువలను కేటాయించడానికి Constructor అనే ప్రత్యేక మెథడ్ రన్ అవుతుంది. దీని పేరు కచ్చితంగా క్లాస్ పేరుతో సమానంగా ఉండాలి మరియు దీనికి ఎటువంటి రిటర్న్ టైప్ (void కూడా) ఉండదు.

Constructor Chaining (: this(...)): ఒక కన్‌స్ట్రక్టర్ నుండి అదే క్లాస్‌లోని మరొక కన్‌స్ట్రక్టర్‌ను కాల్ చేయడానికి this కీవర్డ్ వాడతారు. దీనివల్ల డూప్లికేట్ కోడ్ పూర్తిగా తొలగిపోతుంది.

ConstructorChaining.cs ⚡ Try in C# Compiler 
using System;

class Product
{
    public string Name;
    public decimal Price;
    public int Stock;

    // Primary detailed constructor
    public Product(string name, decimal price, int stock)
    {
        this.Name = name;
        this.Price = price;
        this.Stock = stock;
    }

    // Overloaded Constructor calling the main one with defaults
    public Product(string name, decimal price) : this(name, price, 10)
    {
    }

    public void PrintInfo() => 
        Console.WriteLine($"Product: {Name} | Price: {Price:C} | Stock: {Stock}");
}

class Program
{
    static void Main()
    {
        Product p1 = new Product("Mechanical Keyboard", 3500m, 50);
        Product p2 = new Product("Mouse Pad", 450m); // Uses default stock 10

        p1.PrintInfo();
        p2.PrintInfo();
    }
}
4 C# 12 Primary Constructors: మోడరన్ క్లీన్ కోడ్

C# 12 లో ప్రవేశపెట్టబడిన Primary Constructors ద్వారా క్లాస్ డిక్లరేషన్ హెడర్ వద్దనే పారామీటర్లను నిర్దేశించవచ్చు. దీనివల్ల ప్రైవేట్ ఫీల్డ్స్ డిక్లేర్ చేసి, కన్‌స్ట్రక్టర్ బాడీలో this.x = x; అని రాసే బోరింగ్ బాయిలర్‌ప్లేట్ కోడ్ పూర్తిగా తొలగిపోతుంది.

PrimaryConstructorDemo.cs ⚡ Try in C# Compiler 
using System;

// C# 12 Primary Constructor directly in class signature
class Student(int id, string name, double gpa)
{
    public void DisplayReport()
    {
        // Parameters (id, name, gpa) are in scope across the whole class!
        Console.WriteLine($"Student #{id}: {name} -> GPA: {gpa:F2}");
    }
}

class Program
{
    static void Main()
    {
        Student s1 = new Student(101, "Deepika", 9.4);
        s1.DisplayReport();
    }
}
5 Static Members vs Instance Members

ఒక క్లాస్‌లోని మెంబర్‌కు static అని పెడితే, అది ఏ ఒక్క ఆబ్జెక్ట్‌కు కాకుండా మొత్తం క్లాస్‌కు మాత్రమే చెందుతుంది. మెమరీలో దీనికి ఒకే ఒక్క కాపీ ఉంటుంది.

  • Instance Members: ప్రతి ఆబ్జెక్ట్‌కు విడివిడిగా మెమరీ ఉంటుంది. obj.Field ద్వారా యాక్సెస్ చేస్తాం.
  • Static Members: క్లాస్ పేరుతో నేరుగా కాల్ చేస్తాం (ఉదా: Math.Sqrt() లేదా User.TotalUsers). ఆబ్జెక్ట్ లేకుండానే పని చేస్తాయి.
StaticCounterDemo.cs ⚡ Try in C# Compiler 
using System;

class User
{
    public string Username;
    public static int UserCount = 0; // Shared across all instances

    public User(string username)
    {
        this.Username = username;
        UserCount++; // Increments the shared global counter
    }
}

class Program
{
    static void Main()
    {
        User u1 = new User("alice");
        User u2 = new User("bob");
        User u3 = new User("charlie");

        Console.WriteLine($"Total Users Registered: {User.UserCount}");
    }
}
6 బిగినర్ తప్పులు & ఇంటర్వ్యూ FAQ
⚠️ ప్రమాదకరమైన తప్పు: NullReferenceException
BankAccount acc; అని కేవలం రిఫరెన్స్ వేరియబుల్ మాత్రమే డిక్లేర్ చేసి, new BankAccount() చేయకుండా acc.Deposit(100) అని కాల్ చేస్తే ప్రోగ్రామ్ క్రాష్ అవుతుంది. ఎందుకంటే ఆ రిఫరెన్స్ మెమరీలో null ను పాయింట్ చేస్తోంది.

తరచుగా అడిగే ప్రశ్నలు (FAQ):

  • డీఫాల్ట్ కన్‌స్ట్రక్టర్ ఎప్పుడు అదృశ్యమవుతుంది?
    మనం ఏ కన్‌స్ట్రక్టర్ రాయకపోతే C# కంపైలర్ ఉచితంగా డీఫాల్ట్ పారామీటర్-లెస్ కన్‌స్ట్రక్టర్ ఇస్తుంది. కానీ మనం ఏదైనా ఒక్క పారామీటరైజ్డ్ కన్‌స్ట్రక్టర్ రాస్తే, కంపైలర్ ఇచ్చే డీఫాల్ట్ కన్‌స్ట్రక్టర్ రద్దవుతుంది.
  • Static Class లో ఇన్స్టాన్స్ కన్‌స్ట్రక్టర్ ఎందుకు ఉండదు?
    Static క్లాస్‌లకు ఆబ్జెక్ట్స్ క్రియేట్ చేయడం సాధ్యం కాదు (new MyStaticClass() అని రాయలేము). అందువల్ల కేవలం క్లాస్ లోడ్ అయినప్పుడు ఒకసారి రన్ అయ్యే static కన్‌స్ట్రక్టర్ మాత్రమే ఉండగలదు.
