ఆపరేటర్లు, ఎక్స్‌ప్రెషన్స్ & Null-Coalescing (??, ?.)

⚡ Modern C# 12 & .NET 8 🟢 Chapter 4 of 20 📂 Phase 01: C# ఫండమెంటల్స్ & బేసిక్స్ 📅 2026 Edition
📌 Covered in this chapter: అర్థమెటిక్ & లాజికల్ ఆపరేటర్లు · Ternary (?:) · Null-Conditional (?.) & Null-Coalescing (??, ??=) · ఆపరేటర్ ప్రెసిడెన్స్
వేరియబుల్స్‌పై గణిత లెక్కలు చేయడానికి, షరతులను సరిపోల్చడానికి మరియు ఆధునిక C# లో అత్యంత క్లిష్టమైన NullReferenceException క్రాష్‌ల నుండి రక్షణ కల్పించడానికి ఆపరేటర్లు ప్రాణాధారం. సంప్రదాయ ఆపరేటర్లతో పాటు ఆధునిక C# రక్షణ కవచాలైన Null-Conditional (?.) మరియు Null-Coalescing (??, ??=) ఆపరేటర్ల అంతర్గత పనితీరును ఈ అధ్యాయంలో లోతుగా శోధిద్దాం.
1ఫండమెంటల్ ఆపరేటర్లు & షార్ట్-సర్క్యూట్ మూలసూత్రం

C# లో ప్రాథమిక అంకగణిత (+, -, *, /, %) మరియు రిలేషనల్ (==, !=, >, <, >=, <=) ఆపరేటర్లు సాధారణ ప్రోగ్రామింగ్ నిబంధనలనే అనుసరిస్తాయి.

⚡ లాజికల్ షార్ట్-సర్క్యూట్ ఎవాల్యుయేషన్ (Short-Circuit Evaluation):

&& (AND) లో ఎడమవైపు కండిషన్ తప్పు (false) అయితే, కుడివైపు ఏముందో కంప్యూటర్ అసలు తనిఖీ చేయదు. అదేవిధంగా || (OR) లో ఎడమవైపు నిజం (true) అయితే వెంటనే ఫలితాన్ని ఖరారు చేస్తుంది. ఇది నల్ చెకింగ్‌లో ప్రోగ్రామ్ క్రాష్ కాకుండా కాపాడుతుంది.

C# — Integer Division Trap & Casting ⚡ Try in C# Compiler 
int a = 5, b = 2;
// పూర్ణాంకాల భాగహారంలో దశాంశాలు తొలగిపోతాయి (Truncation)
double wrong = a / b;          // 5 / 2 = 2 -> 2.0 (తప్పు!)
double correct = (double)a / b; // 2.5 (సరైనది!)

Console.WriteLine($"తప్పు ఫలితం: {wrong} | సరైన ఫలితం: {correct}");
2Prefix (++x) vs Postfix (x++) ఇంక్రిమెంట్ మెకానిక్స్

⚡ Prefix (++x): Increment Then Fetch

ముందుగా మెమరీలోని విలువను 1 పెంచి, ఆ తర్వాత నవీకరించబడిన తాజా విలువను ఎక్స్‌ప్రెషన్‌కు అందిస్తుంది.

int x = 5;
int y = ++x; // x = 6, y = 6

⏳ Postfix (x++): Fetch Then Increment

పాత విలువను ఎక్స్‌ప్రెషన్‌కు ఇచ్చేసి, ఆ తర్వాత మాత్రమే మెమరీలోని అసలు వేరియబుల్‌ను 1 పెంచుతుంది.

int x = 5;
int y = x++; // y = 5 (old copy), x = 6
3మోడ్రన్ C# నల్ సేఫ్టీ ఆపరేటర్లు (The Null-Defense Shield)

ప్రముఖ కంప్యూటర్ శాస్త్రవేత్త Tony Hoare నల్ పాయింటర్లను కనిపెట్టడాన్ని తన "Billion Dollar Mistake" అని పిలిచారు. ఎందుకంటే ప్రపంచంలో అత్యధిక సాఫ్ట్‌వేర్ క్రాష్‌లు NullReferenceException వల్లనే జరుగుతాయి. ఆధునిక C# దీనికి 3 అద్భుతమైన ఆపరేటర్లను అందించింది:

1. Null-Conditional Operator (?.) — సేఫ్ నావిగేషన్

ఆబ్జెక్ట్ నల్ అయితే క్రాష్ కాకుండా నిశ్శబ్దంగా null నే రిటర్న్ చేస్తుంది: string? upper = name?.ToUpper();.

2. Null-Coalescing Operator (??) — ఫాల్‌బ్యాక్ డిఫాల్ట్ వాల్యూ

ఎడమవైపు విలువ null అయితే ప్రత్యామ్నాయంగా కుడివైపు ఉన్న డీఫాల్ట్ విలువను ఎంచుకుంటుంది: string displayName = name ?? "Guest";.

3. Null-Coalescing Assignment (??=) — స్మార్ట్ క్యాషింగ్

వేరియబుల్ ప్రస్తుతం null అయితే మాత్రమే కొత్త విలువను అసైన్ చేస్తుంది: cache ??= LoadFromDatabase();.

C# — Modern Null-Defense in Action ⚡ Try in C# Compiler 
string? userInput = null;

// ?? ఆపరేటర్ తో సేఫ్ డీఫాల్ట్ ప్రొవైడర్
string username = userInput ?? "Anonymous_User";
Console.WriteLine($"వినియోగదారుని పేరు: {username}");

// ??= తో లేజీ ఇనీషియలైజేషన్
List<string>? logList = null;
logList ??= new List<string>(); // నల్ కాబట్టి కొత్త లిస్ట్ అసైన్ అవుతుంది
logList.Add("Server Started");
Console.WriteLine($"లాగ్ కౌంట్: {logList.Count}");
4ఆపరేటర్ ప్రాధాన్యతా నిచ్చెన (Precedence Hierarchy)
1. ప్రైమరీ ఆపరేటర్లు: (), మెంబర్ యాక్సెస్ ., ?., ఇండెక్సర్ []
2. యునరీ ఆపరేటర్లు: ++, --, లాజికల్ నాట్ !, typeof, await
3. గుణకార ఆపరేటర్లు: గుణకారం *, భాగహారం /, మాడ్యులో %
4. సంకలన ఆపరేటర్లు: కూడిక +, తీసివేత -
5. నల్-కోలెస్సింగ్: ??
6. అసైన్‌మెంట్: =, +=, -=, ??=
5బిగినర్స్ చేసే ఘోరమైన తప్పులు (Beginner Pitfalls)
❌ 1. & మరియు && ల మధ్య కన్‌ఫ్యూజన్:
if (user != null & user.IsActive) // CRASH! user నల్ అయితే NullReferenceException వస్తుంది సింగిల్ & బిట్‌వైజ్ ఆపరేటర్; ఇది షార్ట్-సర్క్యూట్ చేయదు (రెండు వైపులా ఎవాల్యుయేట్ చేస్తుంది). కండిషన్లలో ఎల్లప్పుడూ డబుల్ && మాత్రమే వాడాలి.
❌ 2. if కండిషన్‌లో అసైన్‌మెంట్ ప్రయత్నించడం:
if (x = 5) // Compiler Error! Cannot implicitly convert type int to bool C/C++ లాగా C# నంబర్లను బూలియన్‌గా తీసుకోదు. C# లో కండిషన్ తప్పనిసరిగా bool అయి ఉండాలి కాబట్టి పోల్చడానికి == వాడాలి.
6తరచుగా అడిగే ప్రశ్నలు (FAQ)

Q: C# లో is మరియు as ఆపరేటర్లు ఎలా పనిచేస్తాయి?

is ఆపరేటర్ ఒక ఆబ్జెక్ట్ నిర్దిష్ట క్లాస్‌కి చెందినదో కాదో తనిఖీ చేస్తుంది (ఉదా: if (obj is string s)). as ఆపరేటర్ సేఫ్ టైప్ కాస్టింగ్ చేస్తుంది — కాస్ట్ విజయవంతమైతే ఆబ్జెక్ట్ ఇస్తుంది, విఫలమైతే ఎర్రర్ రాకుండా null రిటర్న్ చేస్తుంది.

Q: Nullable Value Types (int?) అంటే ఏమిటి?

సాధారణంగా int నల్ విలువను తీసుకోదు. కానీ డేటాబేస్‌లలో పూర్ణాంక కాలమ్స్ ఖాళీగా (null) ఉండవచ్చు. అలాంటి సందర్భాలలో int? age = null; అని రాస్తే అది Nullable<int> స్ట్రక్చర్‌గా మారి నల్ విలువను కూడా స్వీకరించగలదు.
