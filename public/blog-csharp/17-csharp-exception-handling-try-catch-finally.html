ఎక్సెప్షన్ హ్యాండ్లింగ్ (try, catch, finally, custom exceptions)

⚡ Modern C# 12 & .NET 8 🟢 Chapter 17 of 20 📂 Phase 05: అడ్వాన్స్‌డ్ C#, LINQ & ప్రాజెక్ట్ 📅 2026 Edition
📌 Covered in this chapter: రన్‌టైమ్ ఎర్రర్ హ్యాండ్లింగ్ · Exception hierarchy · when ఫిల్టర్లు · using స్టేట్‌మెంట్ & IDisposable రీసోర్స్ క్లీనప్
సాఫ్ట్‌వేర్ అభివృద్ధిలో బగ్‌లు లేదా ఊహించని పరిస్థితులు (ఉదా: నెట్‌వర్క్ ఫెయిల్యూర్, డేటాబేస్ డౌన్ అవ్వడం, ఫైల్ లేకపోవడం) రావడం సహజం. అటువంటి సందర్భాలలో అప్లికేషన్ అకస్మాత్తుగా క్రాష్ అవ్వకుండా, సమస్యను గౌరవప్రదంగా నియంత్రించే పద్ధతినే Exception Handling (ఎక్సెప్షన్ హ్యాండ్లింగ్) అంటారు. C# లో try, catch, finally తో పాటు ఆధునిక C# 6+ లో వచ్చిన శక్తివంతమైన Exception Filters (when) మరియు రిసోర్స్ లీక్స్ నివారించే using స్టేట్‌మెంట్ పనితీరును ఈ అధ్యాయంలో సమగ్రంగా నేర్చుకుందాం.
1 Runtime Exceptions vs Compile-time Errors: .NET Hierarchy

Compile-time Errors: కోడ్ సింటాక్స్ లేదా టైప్ మిస్‌మ్యాచ్ ఉన్నప్పుడు కంపైలరే ప్రోగ్రామ్‌ను రన్ అవ్వకుండా ఆపుతుంది. ఉదాహరణకు సెమీకోలన్ మర్చిపోవడం లేదా తప్పు డేటా టైప్ కేటాయించడం.

Runtime Exceptions: ప్రోగ్రామ్ విజయవంతంగా కంపైల్ అయిన తర్వాత, ఎగ్జిక్యూట్ అయ్యే సమయంలో వచ్చే ఊహించని లోపాలు (ఉదాహరణకు 0 తో భాగించడం, లేని ఫైల్‌ను తెరవడానికి ప్రయత్నించడం).

.NET Exception Hierarchy: C# లోని అన్ని ఎక్సెప్షన్లు System.Exception అనే బేస్ క్లాస్ నుండి ఉద్భవిస్తాయి. ప్రతి ఎక్సెప్షన్ ఆబ్జెక్ట్‌లో లోపం వివరాలను తెలిపే Message, ఏ లైన్‌లో ఎర్రర్ వచ్చిందో చూపించే StackTrace, మరియు మూల కారణాన్ని తెలిపే InnerException ఉంటాయి.

2 try, catch, finally వర్కింగ్ మెకానిజమ్స్

ఎర్రర్ వచ్చే అవకాశం ఉన్న కోడ్‌ను try బ్లాక్‌లో ఉంచుతాం. ఏదైనా లోపం తలెత్తితే రన్‌టైమ్ వెంటనే దాన్ని గుర్తించి తగిన catch బ్లాక్‌కు పంపుతుంది.

finally బ్లాక్ యొక్క ప్రత్యేకత: ఎక్సెప్షన్ వచ్చినా రాకపోయినా, ఈవెన్ try బ్లాక్ మధ్యలోనే return స్టేట్‌మెంట్ ఎగ్జిక్యూట్ అయినా సరే finally బ్లాక్ కచ్చితంగా రన్ అవుతుంది! అందువల్ల ఓపెన్ చేసిన ఫైల్స్ లేదా నెట్‌వర్క్ కనెక్షన్లు క్లోజ్ చేయడానికి ఇది అనువైన ప్రదేశం.

TryCatchFinallyDemo.cs ⚡ Try in C# Compiler 
using System;

class Program
{
    static void Main()
    {
        Console.WriteLine("Application Started...");
        try
        {
            int numerator = 100;
            int denominator = 0; // Triggering DivideByZeroException
            int result = numerator / denominator;
            Console.WriteLine($"Result: {result}");
        }
        catch (DivideByZeroException ex)
        {
            Console.WriteLine($"[Math Error Handled]: {ex.Message}");
        }
        catch (Exception ex)
        {
            // Generic Fallback Handler
            Console.WriteLine($"[Unexpected Error]: {ex.Message}");
        }
        finally
        {
            Console.WriteLine("Cleanup: Finally block executed safely.");
        }
        Console.WriteLine("Application continues running smoothly!");
    }
}
3 Modern C# 6+ Exception Filters (when keyword)

C# 6.0 లో ప్రవేశపెట్టబడిన Exception Filters (when) అత్యంత అధునాతనమైన ఫీచర్. సాధారణంగా ఒక ఎక్సెప్షన్‌ను క్యాచ్ చేసిన తర్వాత లోపల if కండిషన్ రాస్తే, అప్పటికే కాల్ స్టాక్ అన్‌వైండ్ (Stack Unwinding) అయిపోతుంది. కానీ when కీవర్డ్ వాడితే, కండిషన్ నిజమైతేనే స్టాక్ అన్‌వైండ్ చేసి ఆ క్యాచ్ బ్లాక్‌లోకి వెళ్తుంది. దీనివల్ల డయాగ్నోస్టిక్స్ మరియు డీబగ్గింగ్ అత్యంత ఖచ్చితంగా జరుగుతాయి.

ExceptionFiltersDemo.cs ⚡ Try in C# Compiler 
using System;
using System.IO;

class Program
{
    static void ProcessFile(int errorCode)
    {
        if (errorCode == 404)
            throw new FileNotFoundException("Report file missing on server!");
        else if (errorCode == 403)
            throw new UnauthorizedAccessException("Admin access denied!");
        else
            throw new Exception("General internal error");
    }

    static void Main()
    {
        try
        {
            ProcessFile(404);
        }
        // Specific exception filter with 'when'
        catch (FileNotFoundException ex) when (ex.Message.Contains("missing"))
        {
            Console.WriteLine($"[Logged as Warning]: {ex.Message}");
        }
        catch (UnauthorizedAccessException ex)
        {
            Console.WriteLine($"[Security Alert]: {ex.Message}");
        }
    }
}
4 using డిక్లరేషన్ & IDisposable రీసోర్స్ క్లీనప్

ఫైల్ హ్యాండిల్స్, డేటాబేస్ కనెక్షన్లు లేదా సాకెట్స్ వంటి అన్‌మేనేజ్డ్ రీసోర్సెస్ గార్బేజ్ కలెక్టర్ ద్వారా వెంటనే క్లీన్ కావు. వీటి కోసం .NET IDisposable ఇంటర్‌ఫేస్ మరియు Dispose() మెథడ్‌ను అందిస్తుంది.

C# లో using స్టేట్‌మెంట్ వాడితే, కంపైలర్ బ్యాక్‌గ్రౌండ్‌లో దాన్ని ఒక try-finally బ్లాక్‌గా మార్చి, చివర్లో ఆటోమేటిక్‌గా Dispose() ని కాల్ చేస్తుంది. C# 8+ లో కర్లీ బ్రేసెస్ అవసరం లేకుండా నేరుగా using var reader = ...; అని రాసే మోడరన్ డిక్లరేషన్ సింటాక్స్ అందుబాటులోకి వచ్చింది.

UsingResourceCleanup.cs ⚡ Try in C# Compiler 
using System;
using System.IO;

class Program
{
    static void Main()
    {
        string samplePath = "test_log.txt";
        
        // Modern C# 8+ using declaration (Auto disposes at scope end)
        using (StreamWriter writer = new StreamWriter(samplePath))
        {
            writer.WriteLine("Transaction Log #1029: SUCCESS");
            writer.WriteLine("Timestamp: " + DateTime.UtcNow);
        } // File handle is automatically closed and disposed here!

        // Reading back safely
        using var reader = new StreamReader(samplePath);
        string content = reader.ReadToEnd();
        Console.WriteLine("File Content Read Safely:
" + content);
    }
}
5 Custom Exceptions (కస్టమ్ ఎక్సెప్షన్లు సృష్టించడం)

మన బిజినెస్ లాజిక్‌కు సంబంధించిన ప్రత్యేకమైన ఎర్రర్లను సూచించడానికి కస్టమ్ ఎక్సెప్షన్ క్లాసులను తయారు చేసుకోవచ్చు. ఇవి ఎల్లప్పుడూ System.Exception క్లాస్ నుండి వారసత్వం పొందాలి.

CustomExceptionDemo.cs ⚡ Try in C# Compiler 
using System;

// Custom Business Exception
class InsufficientFundsException : Exception
{
    public decimal CurrentBalance { get; }
    public decimal AttemptedAmount { get; }

    public InsufficientFundsException(decimal balance, decimal amount)
        : base($"Transaction failed! Attempted to withdraw {amount:C}, but balance is only {balance:C}.")
    {
        CurrentBalance = balance;
        AttemptedAmount = amount;
    }
}

class BankAccount
{
    private decimal _balance = 1000m;

    public void Withdraw(decimal amount)
    {
        if (amount > _balance)
            throw new InsufficientFundsException(_balance, amount);

        _balance -= amount;
        Console.WriteLine($"Withdrew: {amount:C}, Remaining: {_balance:C}");
    }
}

class Program
{
    static void Main()
    {
        BankAccount account = new BankAccount();
        try
        {
            account.Withdraw(500m);
            account.Withdraw(800m); // Triggers custom exception!
        }
        catch (InsufficientFundsException ex)
        {
            Console.WriteLine($"[ALERT] {ex.Message}");
            Console.WriteLine($"Deficit: {ex.AttemptedAmount - ex.CurrentBalance:C}");
        }
    }
}
6 బిగినర్ తప్పులు & ఇంటర్వ్యూ FAQ
⚠️ ప్రమాదకరమైన తప్పు: throw ex; vs throw; (స్టాక్ ట్రేస్ పోగొట్టుకోవడం)
క్యాచ్ బ్లాక్‌లో ఎక్సెప్షన్‌ను రీ-త్రో (re-throw) చేసేటప్పుడు throw ex; అని రాస్తే అసలైన ఎర్రర్ ఎక్కడ వచ్చిందో తెలిపే స్టాక్ ట్రేస్ తుడిచిపెట్టుకుపోతుంది. ఎల్లప్పుడూ కేవలం throw; అని మాత్రమే రాయాలి. దీనివల్ల అసలైన కాల్ స్టాక్ సురక్షితంగా పైకి పాస్ అవుతుంది.

తరచుగా అడిగే ప్రశ్నలు (FAQ):

  • ఎక్సెప్షన్లను Swallow చేయడం అంటే ఏమిటి?
    catch (Exception) { } అని ఏ లాగింగ్ లేకుండా ఖాళీ క్యాచ్ బ్లాక్ రాయడాన్ని "Swallowing an exception" అంటారు. ఇది ప్రొడక్షన్‌లో బగ్‌లను కనుగొనడం అసాధ్యంగా మారుస్తుంది.
  • using స్టేట్‌మెంట్ ఏ క్లాసులపై మాత్రమే పనిచేస్తుంది?
    System.IDisposable లేదా System.IAsyncDisposable ఇంటర్‌ఫేస్‌ను ఇంప్లిమెంట్ చేసిన ఆబ్జెక్టులపై మాత్రమే using పనిచేస్తుంది.
