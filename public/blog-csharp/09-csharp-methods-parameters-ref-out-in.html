మెథడ్స్, పారామీటర్ మోడిఫైయర్స్ (ref, out, in, params)

⚡ Modern C# 12 & .NET 8 🟢 Chapter 9 of 20 📂 Phase 03: మెథడ్స్, స్ట్రింగ్స్ & కలెక్షన్స్ 📅 2026 Edition
📌 Covered in this chapter: మెథడ్ సిగ్నేచర్ · Pass by Value vs ref · out మల్టిపుల్ రిటర్న్స్ · in రీడ్-ఓన్లీ రిఫరెన్స్ · params వేరియబుల్ ఆర్గ్యుమెంట్స్
C# అప్లికేషన్లలో కోడ్‌ను చిన్న చిన్న లాజికల్ భాగాలుగా విభజించి, రీయూజబుల్ (reusable) గా మార్చడానికి Methods (Functions) అత్యంత ప్రధానమైన స్తంభాలు. C# 12 మరియు .NET 8 లో మెథడ్స్ కేవలం సాధారణ పారామీటర్లనే కాకుండా, మెమరీ పర్ఫార్మెన్స్ కోసం ref, out, in, మరియు వేరియబుల్ ఆర్గ్యుమెంట్స్ కోసం params వంటి శక్తివంతమైన కీవర్డ్స్‌ను అందిస్తాయి. ఈ అధ్యాయంలో మెథడ్స్ నిర్మాణం, పారామీటర్ పాసింగ్ మెకానిజమ్స్ మరియు బెస్ట్ ప్రాక్టీసులను లోతుగా నేర్చుకుందాం.
1 మెథడ్ బేసిక్స్ & మోడరన్ ఎక్స్‌ప్రెషన్ బాడీడ్ సింటాక్స్

C# లో ప్రతి మెథడ్ ఏదో ఒక class లేదా struct లోపల ఉండాలి (Top-Level Statements వాడినప్పుడు కంపైలర్ దాన్ని బ్యాక్‌గ్రౌండ్‌లో Program క్లాస్‌లోకి మారుస్తుంది). ఒక మెథడ్ సిగ్నేచర్‌లో Access Modifier, Return Type, Method Name, మరియు Parameter List ఉంటాయి.

సింగిల్ లైన్ లాజిక్ ఉన్న చిన్న మెథడ్స్ కోసం C# 6+ లో ప్రవేశపెట్టిన Expression-bodied syntax (=>) కోడ్‌ను ఎంతో స్పష్టంగా మరియు క్లీన్‌గా ఉంచుతుంది.

MethodDefinition.cs ⚡ Try in C# Compiler 
using System;

class Program
{
    // Standard Method Body
    static double CalculateArea(double width, double height)
    {
        return width * height;
    }

    // Modern Expression-bodied Method (C# 6+)
    static double CalculatePerimeter(double w, double h) => 2 * (w + h);

    static void Main()
    {
        double w = 5.0, h = 3.0;
        Console.WriteLine($"Area: {CalculateArea(w, h)}");
        Console.WriteLine($"Perimeter: {CalculatePerimeter(w, h)}");
    }
}

లైన్-బై-లైన్ వివరణ:

  • static double CalculateArea(...): static మెథడ్ కాబట్టి క్లాస్ ఆబ్జెక్ట్ లేకుండానే నేరుగా కాల్ చేయవచ్చు. double డేటా టైప్‌ను రిటర్న్ చేస్తుంది.
  • CalculatePerimeter(double w, double h) => 2 * (w + h);: ఫ్యాట్ ఆరో సింటాక్స్ వాడటం వల్ల { return ...; } బాయిలర్‌ప్లేట్ తొలగిపోయి ఒకే లైన్‌లో లాజిక్ ముగిసింది.
2 Pass-by-Value vs Reference: ref కీవర్డ్

C# లో డీఫాల్ట్‌గా అన్ని పారామీటర్లు Pass-by-Value పద్ధతిలో పాస్ అవుతాయి. అంటే కాలర్ వేరియబుల్ యొక్క కాపీ (copy) మాత్రమే మెథడ్‌కు అందుతుంది. మెథడ్ లోపల ఆ వేరియబుల్‌ను మార్చినా మెయిన్ మెథడ్‌లోని ఒరిజినల్ వేరియబుల్ మారదు.

ఒరిజినల్ వేరియబుల్ యొక్క అసలైన మెమరీ లొకేషన్‌నే నేరుగా పంపించాలంటే ref కీవర్డ్ వాడాలి. ref ఉపయోగించేటప్పుడు వేరియబుల్‌కు ముందే ఏదో ఒక వ్యాల్యూ ఇనిషియలైజ్ (initialize) అయి ఉండటం తప్పనిసరి.

RefSwapExample.cs ⚡ Try in C# Compiler 
using System;

class Program
{
    static void Swap(ref int a, ref int b)
    {
        int temp = a;
        a = b;
        b = temp;
    }

    static void Main()
    {
        int x = 10, y = 20;
        Console.WriteLine($"Before Swap: x={x}, y={y}");
        
        // Calling with ref keyword
        Swap(ref x, ref y);
        Console.WriteLine($"After Swap:  x={x}, y={y}");
    }
}
Before Swap: x=10, y=20 After Swap: x=20, y=10

ముఖ్యమైన సూచన: మెథడ్ డెఫినిషన్‌లోనూ మరియు మెథడ్‌ను కాల్ చేసేటప్పుడు కూడా ref అని స్పష్టంగా రాయాలి. దీనివల్ల ఆ వేరియబుల్ మారబోతోందని కోడ్ చదివే డెవలపర్‌కు ముందే తెలుస్తుంది.

3 out కీవర్డ్ & Discards (_)

ఒక మెథడ్ నుండి ఒకేసారి రెండు లేదా అంతకంటే ఎక్కువ ఫలితాలు (results) రిటర్న్ చేయాల్సి వచ్చినప్పుడు out కీవర్డ్ వాడతారు. ref లాగే ఇది కూడా రిఫరెన్స్ ద్వారా పనిచేస్తుంది, కానీ రెండు కీలక వ్యత్యాసాలు ఉన్నాయి:

  1. కాలర్ వేరియబుల్‌కు ముందే వ్యాల్యూ ఇవ్వాల్సిన అవసరం లేదు.
  2. మెథడ్ పూర్తయ్యేలోపు ఆ out పారామీటర్‌కు కచ్చితంగా ఏదో ఒక వ్యాల్యూ అసైన్ చేసి తీరాలి (లేకపోతే కంపైలర్ ఎర్రర్ ఇస్తుంది).
OutParameters.cs ⚡ Try in C# Compiler 
using System;

class Program
{
    static void CalculateStats(int[] numbers, out int sum, out double average)
    {
        sum = 0;
        foreach (int n in numbers) sum += n;
        average = numbers.Length > 0 ? (double)sum / numbers.Length : 0.0;
    }

    static void Main()
    {
        int[] scores = { 80, 90, 75, 95 };
        
        // Inline out variable declaration (C# 7+)
        CalculateStats(scores, out int totalSum, out double avgScore);
        
        Console.WriteLine($"Total: {totalSum}, Average: {avgScore:F2}");
        
        // Discards (_) if you only need the sum
        CalculateStats(scores, out int onlySum, out _);
        Console.WriteLine($"Only Sum: {onlySum}");
    }
}

C# 7+ Inline Declaration: పాత C# లో వేరియబుల్‌ను ముందే డిక్లేర్ చేయాల్సి వచ్చేది. ఆధునిక C# లో out int totalSum అని మెథడ్ కాల్ లోపలే నేరుగా డిక్లేర్ చేసుకోవచ్చు. అనవసరమైన రిటర్న్ వ్యాల్యూస్ వద్దనుకుంటే అండర్‌స్కోర్ (out _) డిస్కార్డ్ వాడవచ్చు.

4 in కీవర్డ్ (Readonly Reference) & params కీవర్డ్

హై-పెర్ఫార్మెన్స్ అప్లికేషన్లలో మెమరీ కాపీని నివారించడానికి మరియు వేరియబుల్స్ సంఖ్య మారే సందర్భాల కోసం C# లో ఈ రెండు ప్రత్యేక కీవర్డ్స్ ఉన్నాయి:

1. in కీవర్డ్: పెద్ద పరిమాణంలో ఉండే Structs లేదా డేటా స్ట్రక్చర్స్‌ను పాస్ చేసేటప్పుడు మెమరీ కాపీ అవ్వకుండా రిఫరెన్స్ ద్వారా పంపుతుంది. కానీ ఆ మెథడ్ లోపల దాన్ని మార్చడం (modify) నిషిద్ధం (Read-only reference). ఒకవేళ మార్చడానికి ప్రయత్నిస్తే కంపైలర్ ఎర్రర్ వస్తుంది.

2. params కీవర్డ్: ఒక మెథడ్‌కు ఎన్ని ఆర్గ్యుమెంట్స్ అయినా పాస్ చేసుకునే వీలు కల్పిస్తుంది. మెథడ్ లోపల అది ఒక అరే (array) గా ట్రీట్ చేయబడుతుంది.

InAndParamsDemo.cs ⚡ Try in C# Compiler 
using System;

class Program
{
    // params allows passing variable comma-separated numbers
    static int SumAll(params int[] numbers)
    {
        int total = 0;
        foreach (int n in numbers) total += n;
        return total;
    }

    // in parameter: Read-only reference (avoids struct copying)
    static void PrintCoordinate(in int x, in int y)
    {
        // x = 100; // Compile Error! Cannot modify 'in' variable
        Console.WriteLine($"Point: ({x}, {y})");
    }

    static void Main()
    {
        Console.WriteLine($"Sum (3 args): {SumAll(10, 20, 30)}");
        Console.WriteLine($"Sum (5 args): {SumAll(1, 2, 3, 4, 5)}");
        
        int px = 50, py = 75;
        PrintCoordinate(in px, in py);
    }
}
5 Optional & Named Parameters

మెథడ్ పారామీటర్లకు డీఫాల్ట్ వ్యాల్యూస్ కేటాయిస్తే, కాలర్ ఆ ఆర్గ్యుమెంట్‌ను పాస్ చేయకపోయినా డీఫాల్ట్ వ్యాల్యూ ఉపయోగపడుతుంది. అలాగే Named Arguments ద్వారా పారామీటర్లను ఏ క్రమంలోనైనా (order) పేరు పెట్టి పాస్ చేయవచ్చు.

OptionalNamedArgs.cs ⚡ Try in C# Compiler 
using System;

class Program
{
    static void SendEmail(string to, string subject = "No Subject", bool isUrgent = false)
    {
        string tag = isUrgent ? "[URGENT] " : "";
        Console.WriteLine($"Sending to: {to} | Subject: {tag}{subject}");
    }

    static void Main()
    {
        // Using defaults
        SendEmail("rajesh@example.com");

        // Named arguments (changing order)
        SendEmail(subject: "Meeting Tomorrow", to: "priya@example.com", isUrgent: true);
    }
}
6 బిగినర్ తప్పులు & ఇంటర్వ్యూ FAQ
⚠️ ప్రమాదకరమైన తప్పు: out పారామీటర్‌కు వ్యాల్యూ ఇవ్వడం మర్చిపోవడం
ఒక మెథడ్‌లో out పారామీటర్ ఉండి, మెథడ్ రిటర్న్ అయ్యే ప్రతి బ్రాంచ్ (if/else) లో దానికి వ్యాల్యూ అసైన్ చేయకపోతే, C# కంపైలర్ CS0177: The out parameter must be assigned to before control leaves the current method ఎర్రర్‌ను విసురుతుంది.

తరచుగా అడిగే ప్రశ్నలు (FAQ):

  • ref మరియు out మధ్య ప్రాథమిక తేడా ఏమిటి?
    ref పాస్ చేసే ముందు వేరియబుల్‌కు ముందే వ్యాల్యూ ఉండాలి. out పాస్ చేసేటప్పుడు ముందే వ్యాల్యూ ఉండాల్సిన పనిలేదు, కానీ మెథడ్ ముగిసేలోపు కచ్చితంగా వ్యాల్యూ సెట్ చేయాలి.
  • Method Overloading అంటే ఏమిటి?
    ఒకే క్లాస్‌లో ఒకే పేరుతో వేర్వేరు పారామీటర్ రకాలు (Types) లేదా సంఖ్య (Count) తో బహుళ మెథడ్స్ నిర్వచించడాన్ని మెథడ్ ఓవర్‌లోడింగ్ అంటారు. రిటర్న్ టైప్ మాత్రమే వేరుగా ఉంటే ఓవర్‌లోడింగ్ కుదరదు.
