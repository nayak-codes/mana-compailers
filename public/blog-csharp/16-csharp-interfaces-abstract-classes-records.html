Phase 04 గ్రాండ్ ఫినాలే: అబ్‌స్ట్రాక్షన్ & ఆధునిక C# Records! 🏛️

ఒక ఇంజనీర్ పవర్ సాకెట్‌ను డిజైన్ చేసినప్పుడు, ఆ సాకెట్‌లో టీవీ పెడతారా, ఫ్రిజ్ పెడతారా లేదా ల్యాప్‌టాప్ ఛార్జర్ పెడతారా అనేది సాకెట్‌కు ముఖ్యం కాదు. ఆ సాకెట్ ఒకే ఒక కాంట్రాక్ట్ (Contract) ను మాత్రమే డిమాండ్ చేస్తుంది: "230 వోల్ట్స్, 3-పిన్ ప్లగ్ ఉంటే చాలు, కరెంట్ సరఫరా అవుతుంది!".

సాఫ్ట్‌వేర్ ఆర్కిటెక్చర్‌లో కూడా ఇలాంటి అద్భుతమైన డీకప్లింగ్‌ను సాధించే సాధనాలే ఇంటర్‌ఫేసెస్ (Interfaces) మరియు అబ్‌స్ట్రాక్ట్ క్లాసెస్ (Abstract Classes). మరియు ఆధునిక క్లౌడ్ / మైక్రోసర్వీసెస్ యుగంలో డేటా ఇమ్యుటబిలిటీ (మార్చలేని సురక్షితమైన డేటా) కోసం C# 9 లో వచ్చిన Records డేటా మోడలింగ్‌ను సమూలంగా మార్చివేశాయి. ఈ అధ్యాయంతో మీరు ఎంటర్‌ప్రైజ్ లెవల్ C# ఆర్కిటెక్చర్ డిజైన్‌లో సంపూర్ణ ప్రావీణ్యం సంపాదిస్తారు!

1 🎭 అబ్‌స్ట్రాక్షన్ (Abstraction) తత్వశాస్త్రం — WHAT vs HOW

అబ్‌స్ట్రాక్షన్ (Abstraction) అంటే అవసరం లేని సంక్లిష్టమైన అంతర్గత సాంకేతిక వివరాలను దాచిపెట్టి (Hiding implementation details), యూజర్‌కు అవసరమైన ప్రధాన ఫీచర్లను మాత్రమే ప్రదర్శించడం (Showing essential features).

  • WHAT (ఏం చేయాలి): ఇంటర్‌ఫేస్ లేదా అబ్‌స్ట్రాక్ట్ క్లాస్ నిర్ణయిస్తుంది (ఉదాహరణ: ProcessPayment(amount)).
  • HOW (ఎలా చేయాలి): కాంక్రీట్ క్లాస్ అమలు చేస్తుంది (ఉదాహరణ: పేపాల్ ద్వారా చేయాలా, క్రెడిట్ కార్డుతో చేయాలా లేదా బిట్‌కాయిన్‌తో చేయాలా).

C# లో అబ్‌స్ట్రాక్షన్‌ను సాధించడానికి రెండు ప్రధాన సాధనాలు ఉన్నాయి: 1. Abstract Classes (పాక్షిక అబ్‌స్ట్రాక్షన్) 2. Interfaces (సంపూర్ణ కాంట్రాక్ట్ అబ్‌స్ట్రాక్షన్).

2 🏛️ అబ్‌స్ట్రాక్ట్ క్లాసెస్ (Abstract Classes) & `abstract` మెథడ్స్

ఒక క్లాస్ ముందు abstract అని రాస్తే, దానికి డైరెక్ట్‌గా ఆబ్జెక్ట్‌ను క్రియేట్ చేయలేము (అంటే new AbstractClass() రాయడం కంపైలేషన్ ఎర్రర్). దానిని కేవలం బేస్ క్లాస్‌గా మాత్రమే ఉపయోగించి, ఇతర పిల్ల క్లాసుల ద్వారా ఇన్‌హెరిట్ చేసుకోవాలి.

అబ్‌స్ట్రాక్ట్ క్లాస్ లక్షణాలు:

  1. Abstract Methods: వీటికి బాడీ { } ఉండదు; కేవలం సిగ్నేచర్ సెమికోలన్ ; తో ముగుస్తుంది. డిరైవ్డ్ క్లాస్ తప్పనిసరిగా override చేయాలి.
  2. Concrete Methods: వీటికి పూర్తి కోడ్ బాడీ ఉంటుంది. అన్ని చైల్డ్ క్లాసులు ఉమ్మడిగా వాడుకోవచ్చు.
  3. Fields & Constructors: ఇవి సాధారణ క్లాసుల లాగే ఫీల్డ్స్‌ను, కన్‌స్ట్రక్టర్లను కలిగి ఉంటాయి. చైల్డ్ కన్‌స్ట్రక్టర్ నుండి base(...) ద్వారా ఇనిషియలైజ్ అవుతాయి.
csharp · Abstract Class with Abstract & Concrete Methods 
public abstract class CloudStorageProvider
{
    public string StorageBucketName { get; }

    // కన్‌స్ట్రక్టర్ (చైల్డ్ క్లాసుల కోసం)
    protected CloudStorageProvider(string bucket)
    {
        StorageBucketName = bucket;
    }

    // 1. అబ్‌స్ట్రాక్ట్ మెథడ్ - బాడీ ఉండదు! చైల్డ్ తప్పనిసరిగా కోడ్ రాయాలి
    public abstract void UploadFile(string fileName, byte[] data);

    // 2. కాంక్రీట్ మెథడ్ - అందరికీ కామన్ లాజిక్
    public void PrintBucketInfo()
    {
        Console.WriteLine($"☁️ యాక్టివ్ క్లౌడ్ బకెట్: {StorageBucketName}");
    }
}

// కాంక్రీట్ చైల్డ్ క్లాస్
public class AzureBlobStorage : CloudStorageProvider
{
    public AzureBlobStorage(string bucket) : base(bucket) { }

    public override void UploadFile(string fileName, byte[] data)
    {
        Console.WriteLine($"[Azure] '{fileName}' ({data.Length} బైట్లు) అజూర్ బ్లాబ్‌కు అప్‌లోడ్ అయ్యింది.");
    }
}

// CloudStorageProvider p = new CloudStorageProvider("test"); // ❌ కంపైల్ ఎర్రర్: Cannot create instance of abstract type!
CloudStorageProvider storage = new AzureBlobStorage("prod-media-bucket");
storage.PrintBucketInfo();
storage.UploadFile("invoice.pdf", new byte[1024]);

3 🔌 ఇంటర్‌ఫేసెస్ (Interfaces) అంటే ఏమిటి? ప్యూర్ కాంట్రాక్ట్స్

ఒక ఇంటర్‌ఫేస్ (Interface) అనేది ఒక పవిత్రమైన ఒప్పందం (Formal Contract). "ఈ ఇంటర్‌ఫేస్‌ను ఇంప్లిమెంట్ చేసే ఏ క్లాస్ అయినా సరే, ఖచ్చితంగా ఇందులో పేర్కొన్న మెథడ్స్ మరియు ప్రాపర్టీలను అందించి తీరాలి!".

C# ఇంటర్‌ఫేస్ నియమాలు:

  • పేరు ప్రారంభంలో ప్రామాణికంగా 'I' అక్షరం ఉంటుంది (ఉదా: ILogger, IDisposable, IPaymentGateway).
  • డీఫాల్ట్‌గా అన్ని మెంబర్లు public గా ఉంటాయి.
  • సాంప్రదాయకంగా ఇంటర్‌ఫేస్‌లో ఎటువంటి ఫీల్డ్స్ (ఇన్స్టాన్స్ స్టేట్) లేదా కన్‌స్ట్రక్టర్లు ఉండకూడదు.
  • ఒక క్లాస్ ఎన్ని ఇంటర్‌ఫేస్‌లనైనా ఇంప్లిమెంట్ చేసుకోవచ్చు (Multiple Interface Implementation)!
csharp · Defining & Implementing Interfaces 
public interface INotificationService
{
    // ప్రాపర్టీ కాంట్రాక్ట్
    string ProviderName { get; }

    // మెథడ్ కాంట్రాక్ట్స్
    void SendSms(string mobile, string message);
    void SendEmail(string email, string subject, string body);
}

public class TwilioNotificationService : INotificationService
{
    public string ProviderName => "Twilio Enterprise Cloud";

    public void SendSms(string mobile, string message)
    {
        Console.WriteLine($"📱 SMS -> {mobile}: {message} [via {ProviderName}]");
    }

    public void SendEmail(string email, string subject, string body)
    {
        Console.WriteLine($"📧 Email -> {email} | సబ్జెక్ట్: {subject}");
    }
}

INotificationService notifier = new TwilioNotificationService();
notifier.SendSms("+91 9876543210", "మీ OTP: 549102");

4 ⚖️ Abstract Class vs Interface — సమగ్ర పోలిక పట్టిక

సాఫ్ట్‌వేర్ ఆర్కిటెక్ట్ ఇంటర్వ్యూలలో వచ్చే అతి ముఖ్యమైన ప్రశ్న — "ఎప్పుడు అబ్‌స్ట్రాక్ట్ క్లాస్ వాడాలి? ఎప్పుడు ఇంటర్‌ఫేస్ వాడాలి?":

ఫీచర్ Abstract Class Interface
సంబంధం (Relationship) IS-A (గుర్తింపు - ఉదా: Dog IS-A Animal) CAN-DO (సామర్థ్యం - ఉదా: Dog CAN-DO ISwimmable)
బహుళ వారసత్వం వీలుకాదు (ఒక క్లాస్ ఒకే అబ్‌స్ట్రాక్ట్ క్లాస్‌ను ఇన్‌హెరిట్ చేసుకోగలదు) ఖచ్చితంగా సాధ్యం (ఒకే క్లాస్ 10 ఇంటర్‌ఫేస్‌లైనా ఇంప్లిమెంట్ చేయవచ్చు)
ఇన్స్టాన్స్ ఫీల్డ్స్ & స్టేట్ కలిగి ఉండవచ్చు (Fields, Private variables, State) ఇన్స్టాన్స్ ఫీల్డ్స్ అనుమతించబడవు (No state)
కన్‌స్ట్రక్టర్లు కన్‌స్ట్రక్టర్లు ఉండవచ్చు (base(...)) కన్‌స్ట్రక్టర్లు ఉండవు
యాక్సెస్ మోడిఫైయర్లు public, protected, private, internal అన్నీ సాధ్యం సాధారణంగా public
ఉత్తమ వినియోగం ఒకే కుటుంబానికి చెందిన క్లాసుల మధ్య కోడ్ షేరింగ్ కోసం సంబంధం లేని క్లాసుల మధ్య కాంట్రాక్ట్ & DI కోసం

5 🧩 బహుళ ఇంటర్‌ఫేస్ ఇంప్లిమెంటేషన్ & Explicit Interface Implementation

ఒక క్లాస్ బహుళ ఇంటర్‌ఫేస్‌లను కామాలతో వేరు చేసి ఇంప్లిమెంట్ చేయవచ్చు:

public class SmartOrder : IPrintable, ISerializable, IPayable { ... }

ఒకవేళ రెండు ఇంటర్‌ఫేస్‌లలో ఒకే పేరుతో మెథడ్ ఉంటే (ఉదాహరణ: ISaveable.Save() మరియు IDatabase.Save()), నేమింగ్ కొలిజన్‌ను పరిష్కరించడానికి Explicit Interface Implementation వాడతాం:

csharp · Explicit Interface Implementation for Collision Resolution 
public interface IFileStorage { void Save(); }
public interface IDatabaseStorage { void Save(); }

public class MultiSaver : IFileStorage, IDatabaseStorage
{
    // Explicit Implementation: ఇంటర్‌ఫేస్ పేరుతో ప్రిఫిక్స్ చేస్తాం, public ఉండకూడదు!
    void IFileStorage.Save()
    {
        Console.WriteLine("💾 స్థానిక డిస్క్‌లోని ఫైల్‌లోకి సేవ్ చేయబడింది.");
    }

    void IDatabaseStorage.Save()
    {

8 💎 C# 9+ విప్లవం: `record` — ఇమ్యుటబుల్ డేటా ఆబ్జెక్ట్స్

ఆధునిక వెబ్ అప్లికేషన్లు, మైక్రోసర్వీసెస్ మరియు క్లౌడ్ API లలో ఎక్కువ భాగం డేటా మార్పిడి (DTOs - Data Transfer Objects) మాత్రమే ఉంటుంది. దీని కోసం సాధారణ క్లాసులు రాస్తే Equals, GetHashCode, ToString, కన్‌స్ట్రక్టర్ల కోసం 50 లైన్ల బాయిలర్‌ప్లేట్ కోడ్ రాయాల్సి వచ్చేది.

ఈ సమస్యను చిటికెలో పరిష్కరించడానికి C# 9 లో వచ్చిన అద్భుతమైన ఫీచరే record (లేదా record class)!

csharp · Positional Record Declaration (One Single Line!) 
// కేవలం ఈ ఒక్క లైన్‌తో పూర్తి స్థాయి ఇమ్యుటబుల్ డేటా ఆబ్జెక్ట్ రెడీ!
public record User(int Id, string Name, string Email);

// ఆటోమేటిక్‌గా వచ్చే ఫీచర్లు:
// 1. Primary Constructor
// 2. init-only properties (Id, Name, Email)
// 3. అందమైన ToString() ఫార్మాట్
// 4. Value-based Equality (== మరియు Equals)

9 🔍 Value-based Equality — Class vs Record వ్యత్యాసం

సాధారణ క్లాస్‌లకు, రికార్డులకు మధ్య ఉన్న అతిపెద్ద వ్యత్యాసం ఈక్వాలిటీ (Equality) లో ఉంది:

csharp · Class Equality vs Record Equality 
// 1. సాధారణ క్లాస్
public class CustomerClass
{
    public int Id { get; set; }
    public string Name { get; set; }
}

// 2. రికార్డ్
public record CustomerRecord(int Id, string Name);

// క్లాస్ ఆబ్జెక్ట్స్ పోలిక
var c1 = new CustomerClass { Id = 1, Name = "అరుణ్" };
var c2 = new CustomerClass { Id = 1, Name = "అరుణ్" };
Console.WriteLine(c1 == c2); // ❌ FALSE! (ఎందుకంటే వేర్వేరు మెమరీ అడ్రస్‌లు - Reference Equality)

// రికార్డ్స్ పోలిక
var r1 = new CustomerRecord(1, "అరుణ్");
var r2 = new CustomerRecord(1, "అరుణ్");
Console.WriteLine(r1 == r2); // ✅ TRUE! (ఎందుకంటే లోపల విలువలు సమానం - Value Equality)

10 🔄 నాన్-డిస్ట్రక్టివ్ మ్యుటేషన్ — `with` ఎక్స్‌ప్రెషన్

రికార్డ్స్ ఇమ్యుటబుల్ (మార్చలేనివి). మరి ఒక ఫీల్డ్ మార్చాలంటే మొత్తం కొత్త ఆబ్జెక్ట్ మొదటి నుండి రాయాలా? అవసరం లేదు! C# with ఎక్స్‌ప్రెషన్ ద్వారా అసలు ఆబ్జెక్ట్‌ను డిస్టర్బ్ చేయకుండా, కేవలం కావాల్సిన ఫీల్డ్‌ను మాత్రమే మార్చి ఒక కొత్త క్లోన్ (Clone) కాపీని తక్షణమే తయారు చేయవచ్చు:

csharp · Non-Destructive Mutation with 'with'

ProductOrder originalOrder = new ProductOrder("ORD-101", "IPHONE-15", 1, 79900m);

// Quantity మరియు TotalPrice ని మాత్రమే మార్చి సరికొత్త ఆర్డర్ కాపీని క్రియేట్ చేయడం

11 🚀 `record struct` (C# 10+) — జీరో హీప్ అలోకేషన్

C# 10 లో రికార్డ్స్ స్ట్రక్ట్స్‌కు కూడా అందుబాటులోకి వచ్చాయి:

// 5. మెయిన్ ఆర్డర్ ప్రాసెసర్ (డిపెండెన్సీ ఇంజెక్షన్ పునాది)
public class OrderProcessor(IPaymentGateway paymentGateway, INotifier notifier)
{
    public OrderResult ProcessCheckout(CustomerInfo customer, List cart, DiscountStrategy discountPolicy)
    {
        Console.WriteLine($"🛒 ఆర్డర్ చెక్అవుట్ ప్రారంభమైంది: {customer.Name} ({customer.Tier})");

        decimal grossTotal = 0m;
        foreach (var item in cart) grossTotal += item.Price * item.Quantity;

        decimal discount = discountPolicy.CalculateDiscount(customer, grossTotal);
        decimal netPayable = grossTotal - discount;

        Console.WriteLine($"   స్థూల మొత్తం  : ₹{grossTotal:N2}");
        Console.WriteLine($"   వర్తించిన రాయితీ: ₹{discount:N2} [{discountPolicy.StrategyName}]");
        Console.WriteLine($"   నికర చెల్లింపు: ₹{netPayable:N2}");

        if (paymentGateway.Charge(customer.CustomerId, netPayable, out string txRef))
        {
            var result = new OrderResult("ORD-" + Guid.NewGuid().ToString().Substring(0, 6).ToUpper(),
                                         grossTotal, discount, netPayable, "CONFIRMED");

            notifier.SendConfirmation(customer, result);
            return result;
        }

        return new OrderResult("FAILED", grossTotal, 0, 0, "PAYMENT_FAILED");
    }
}

Q1: C# లో record కి సాధారణ class కి మధ్య ప్రధాన వ్యత్యాసాలు ఏమిటి?

జవాబు: 1) Records డీఫాల్ట్‌గా Value-based Equality ని అందిస్తాయి (లోపల ఫీల్డ్స్ సమానమైతే == ట్రూ అవుతుంది), క్లాసెస్ Reference Equality ని వాడతాయి. 2) Records ఇమ్యుటబుల్ డేటా మోడలింగ్‌కు ప్రాధాన్యత ఇస్తూ with ఎక్స్‌ప్రెషన్‌ను సపోర్ట్ చేస్తాయి. 3) Records ఆటోమేటిక్‌గా అందమైన ToString() మరియు Deconstructors ని అందిస్తాయి.

Q2: Explicit Interface Implementation ఎప్పుడు వాడతారు?

జవాబు: ఒక క్లాస్ రెండు వేర్వేరు ఇంటర్‌ఫేస్‌లను ఇంప్లిమెంట్ చేస్తున్నప్పుడు, రెండింటిలోనూ ఒకే పేరు, ఒకే పారామీటర్లు ఉన్న మెథడ్ ఉంటే నేమింగ్ కొలిజన్ నివారించడానికి void IInterfaceA.Method() రూపంలో ఎక్స్‌ప్లిసిట్ ఇంప్లిమెంటేషన్ వాడతారు.

🧠 మీ నాలెడ్జ్ చెక్ చేసుకోండి — 5 ఇంటరాక్టివ్ క్విజ్ ప్రశ్నలు

❓ ప్రశ్న 1: అబ్‌స్ట్రాక్ట్ క్లాస్‌కు new AbstractClass() ద్వారా ఆబ్జెక్ట్‌ను సృష్టించవచ్చా?
సమాధానం: లేదు. అబ్‌స్ట్రాక్ట్ క్లాసెస్ అసంపూర్ణమైన బ్లూప్రింట్లు. వాటికి నేరుగా ఆబ్జెక్ట్ సృష్టించడం కంపైల్-టైమ్ ఎర్రర్. వాటిని చైల్డ్ క్లాస్ ద్వారా మాత్రమే ఇన్‌హెరిట్ చేసుకోవాలి.
❓ ప్రశ్న 2: ఒక C# క్లాస్ గరిష్టంగా ఎన్ని ఇంటర్‌ఫేస్‌లను ఇంప్లిమెంట్ చేసుకోవచ్చు?
సమాధానం: పరిమితి లేదు (బహుళ ఇంటర్‌ఫేస్‌లు). ఒక క్లాస్ ఒకే ఒక్క క్లాస్ నుండి మాత్రమే ఇన్‌హెరిట్ చేసుకోగలదు, కానీ ఎన్ని ఇంటర్‌ఫేస్‌లనైనా ఇంప్లిమెంట్ చేయవచ్చు.
❓ ప్రశ్న 3: C# 8 లో ఇంటర్‌ఫేస్‌లకు వచ్చిన సరికొత్త ఫీచర్ ఏమిటి?
సమాధానం: Default Interface Methods. ఇంటర్‌ఫేస్ లోపల కూడా డీఫాల్ట్ కోడ్ బాడీని అందించవచ్చు, దీనివల్ల పాత క్లాసులను బ్రేక్ చేయకుండా కొత్త మెథడ్స్ జోడించవచ్చు.
❓ ప్రశ్న 4: ఒక రికార్డ్ యొక్క కాపీని తీసుకొని అందులో కొన్ని ఫీల్డ్స్‌ను మాత్రమే సవరించడానికి ఏ ఎక్స్‌ప్రెషన్ వాడాలి?
సమాధానం: with ఎక్స్‌ప్రెషన్ (Non-destructive mutation). ఉదాహరణ: var newRec = oldRec with { Salary = 50000 };.
❓ ప్రశ్న 5: record struct మరియు record class మధ్య మెమరీ వ్యత్యాసం ఏమిటి?
సమాధానం: record class అనేది Reference Type (Heap మెమరీలో స్టోర్ అవుతుంది, GC కలెక్ట్ చేస్తుంది). record struct అనేది Value Type (Stack లో స్టోర్ అవుతుంది, జీరో GC అలోకేషన్).
