File Errors, feof() & errno (తెలుగులో)

⚡ C (C17 / C23 Standard) 🟢 Lesson 38 📂 Phase 14: File I/O & Preprocessor 📅 2026 Comprehensive Master Edition
📌 Covered in this in-depth guide: feof() · ferror() · perror() · errno codes · Bulletproof File I/O

రియల్ వరల్డ్ యాప్స్ లో ఎప్పుడూ అన్ని పనులు సాఫీగా జరగవు. మీరు ఒక ఫైల్ సేవ్ చేద్దామనుకుంటే సడెన్ గా యూజర్ పెన్ డ్రైవ్ పీకేయొచ్చు, లేదా హార్డ్ డిస్క్ ఫుల్ అవ్వొచ్చు. అలాంటప్పుడు మీ ప్రోగ్రామ్ బ్లూ స్క్రీన్ ఇచ్చి క్రాష్ అయితే యూజర్ చాలా ఫ్రస్ట్రేట్ అవుతాడు. దాన్ని అడ్డుకోవడానికే C లాంగ్వేజ్ లో File Error Handling ఉంది. ఒక ఫైల్ చివరికి వచ్చిందా అని చెప్పే feof(), ఫైల్ చదివేటప్పుడు ఏమైనా ప్రాబ్లమ్ వస్తే వార్నింగ్ ఇచ్చే ferror(), అసలు ఆ ప్రాబ్లమ్ ఏంటో క్లియర్ గా ఇంగ్లీష్ లో చెప్పే perror() / errno గురించి ఈరోజు పోస్ట్‌మార్టం చేసి తెలుసుకుందాం.

1 feof() అంటే ఏంటి? (End of File)

మీరు ఒక బుక్ చదువుకుంటూ వెళ్తున్నారు. లాస్ట్ పేజీ అయిపోయిన తర్వాత కూడా చదవడానికి ట్రై చేస్తే ఏమవుతుంది? ఏమీ ఉండదు! C లో ఫైల్ చదివేటప్పుడు EOF అనేది వస్తుంది. ఈ ఫైల్ నిజంగానే పూర్తిగా చదివేసామా లేదా అని చెక్ చేయడానికి feof(file_pointer) అనే ఫంక్షన్ వాడతాము.

ఫైల్ చివరికి వస్తే feof() ట్రూ (1) పంపుతుంది, లేకపోతే ఫాల్స్ (0) పంపుతుంది.

🚨 రియల్ లైఫ్ స్టోరీ: perror() మరియు errno (డిటెక్టివ్ లు)

మీరు బ్యాంకు కి వెళ్లి లోన్ అడిగితే రిజెక్ట్ చేసారు అనుకోండి (అంటే fopen ఫెయిల్ అయ్యింది). కానీ ఎందుకు రిజెక్ట్ చేసారో రీజన్ చెప్పకపోతే మీకు ఎలా తెలుస్తుంది? C లాంగ్వేజ్ లో బ్యాక్ గ్రౌండ్ లో errno (Error Number) అనే ఒక హిడెన్ గ్లోబల్ నంబర్ ఉంటుంది. ఏదైనా ఫెయిల్ అయినప్పుడు, ఆపరేటింగ్ సిస్టమ్ ఆ నంబర్ ని ఒక ఎర్రర్ కోడ్ కి సెట్ చేస్తుంది (ఉదా: 2 అంటే "File Not Found", 13 అంటే "Permission Denied").

ఆ నంబర్ ని మనుషులకు అర్థమయ్యే ఇంగ్లీష్ లోకి మార్చి ప్రింట్ చేసే స్పెషల్ ఫంక్షనే perror(). ఇది మీ ఎర్రర్ మెసేజ్ పక్కన కరెక్ట్ రీజన్ ని అతుక్కుని స్క్రీన్ మీద చూపిస్తుంది.

2 ఒకే ఒక సింపుల్ కోడ్ (Bulletproof File Reading)

కింద కోడ్ లో కావాలని లేని ఫైల్ ని ఓపెన్ చేసి ఎర్రర్ ఎలా చూపిస్తుందో, అలాగే ఉంటే దాన్ని చదివి feof మరియు ferror తో ఎలా సేఫ్ గా ఆపుతుందో చూడండి.

C — File Errors & errno ▶ Run Code 
#include <stdio.h>
#include <errno.h> // errno వాడాలంటే ఇది కచ్చితంగా ఉండాలి

int main() {
    // 1. కావాలనే తప్పు పేరుతో (లేని ఫైల్ ని) ఓపెన్ చేద్దాం
    FILE* file = fopen("ghost_file.txt", "r");
    
    // ఒకవేళ ఫైల్ ఓపెన్ అవ్వకపోతే
    if (file == NULL) {
        // perror ఆటోమేటిక్ గా errno ని చదివి రీజన్ ప్రింట్ చేస్తుంది
        perror("Error Opening File");
        
        // గ్లోబల్ errno వాల్యూ ఎంత వచ్చిందో కూడా ప్రింట్ చేద్దాం
        printf("System Error Code (errno): %d\n", errno);
        return 1; // యాప్ ని సేఫ్ గా ఆపేద్దాం
    }
    
    // 2. ఒకవేళ ఫైల్ ఉంటే (ఇక్కడ మనం dummy logic రాస్తున్నాం)
    int c;
    printf("--- File Contents ---\n");
    
    // fgetc వాడి ఒక్కొక్క అక్షరం చదువుతున్నాం
    while (1) {
        c = fgetc(file);
        
        if (feof(file)) { // ఫైల్ పూర్తిగా అయిపోతే...
            printf("\n[✓] Successfully reached End of File.\n");
            break;
        }
        
        if (ferror(file)) { // మధ్యలో పెన్ డ్రైవ్ పీకేస్తే (Read Error)...
            printf("\n[!] I/O Error: చదివేటప్పుడు ఎర్రర్ వచ్చింది!\n");
            clearerr(file); // ఎర్రర్ ని క్లియర్ చేయడం
            break;
        }
        
        putchar(c); // అక్షరాన్ని ప్రింట్ చేయడం
    }
    
    fclose(file);
    return 0;
}
3 కోడ్ లో ఏం జరుగుతోంది? (Step-by-Step)
  • errno.h: సిస్టమ్ లో ఎర్రర్ నంబర్స్ ని ట్రాక్ చేసే గ్లోబల్ వేరియబుల్ ని వాడటానికి ఈ హెడ్డర్ కావాలి.
  • perror("Error Opening File"): ఇది మీ టెక్స్ట్ ని ప్రింట్ చేసి, పక్కన కోలన్ (:) పెట్టి, OS ఇచ్చిన ఒరిజినల్ రీజన్ ని అతుకుతుంది (ఉదా: Error Opening File: No such file or directory).
  • feof(file): మనం లూప్ లో ఫైల్ చదువుతున్నప్పుడు, కరెక్ట్ గా లాస్ట్ క్యారెక్టర్ తర్వాత ఇది ఆగిపోయి బ్రేక్ చేస్తుంది.
  • ferror(file): ఫైల్ ని రైట్ (Write) మోడ్ లో ఓపెన్ చేసి, రీడ్ (Read) చేయడానికి ట్రై చేస్తే, ఇది ఎర్రర్ అని కనిపెట్టి ప్రోగ్రామ్ క్రాష్ అవ్వకుండా ఆపుతుంది.
4 ఇంటర్వ్యూలలో అడిగే కామన్ ప్రశ్నలు (FAQ)

Q1: while( !feof(file) ) అని డైరెక్ట్ గా రాయొచ్చా?

చాలా ట్యుటోరియల్స్ లో ఇలాగే చెప్తారు కానీ, ఇది ఒక మహా తప్పు (Anti-Pattern)! feof అనేది ముందే లాస్ట్ కి వచ్చిందా అని గెస్ చేయలేదు. లాస్ట్ అక్షరం చదివాక కూడా, ఇంకోసారి చదివితే అప్పుడు ఫెయిల్ అయ్యి feof ట్రూ అవుతుంది. అంటే మీరు లూప్ లో లాస్ట్ అక్షరాన్ని రెండుసార్లు ప్రింట్ చేసే (Duplicate Print) ఛాన్స్ ఉంటుంది! అందుకే లోపలే చెక్ చేసుకోవాలి.

Q2: clearerr(file) ఎందుకు వాడాలి?

ఒక ఫైల్ లో ఎర్రర్ వచ్చాక (ferror = 1), మీరు దాన్ని క్లియర్ చేయకుండా మళ్ళీ చదవడానికి ట్రై చేస్తే సిస్టమ్ మిమ్మల్ని అనుమతించదు. ఆ ఫైల్ పాయింటర్ ఎర్రర్ స్టేట్ లోనే లాక్ అయిపోతుంది. దాన్ని రీసెట్ చేసి, మళ్ళీ నార్మల్ గా మార్చడానికే clearerr() వాడతారు.

Q3: నెట్వర్క్ ఫైల్స్ లో (Cloud) కూడా errno పనిచేస్తుందా?

ఖచ్చితంగా! సాకెట్ ప్రోగ్రామింగ్ (Sockets) లో కూడా కనెక్షన్ కట్ అయినా, టైమ్ అవుట్ అయినా ఇదే errno లోకి నంబర్స్ వస్తాయి. ఉదాహరణకు errno 110 అంటే 'Connection Timed Out'. అందుకే C లో ఈ errno లాజిక్ ని అర్థం చేసుకోవడం సర్వర్ ప్రోగ్రామర్స్ కి చాలా ముఖ్యం.
