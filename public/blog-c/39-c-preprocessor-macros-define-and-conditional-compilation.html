C Preprocessor, Macros & #define (తెలుగులో)

⚡ C (C17 / C23 Standard) 🟢 Lesson 39 📂 Phase 14: File I/O & Preprocessor 📅 2026 Comprehensive Master Edition
📌 Covered in this in-depth guide: The Preprocessor Phase · #define Macros · Magic Numbers · #ifdef & #ifndef · Inline Functions

మనం రాసిన C ప్రోగ్రామ్ డైరెక్ట్ గా కంపైల్ అవ్వదు. ముందుగా Preprocessor (ప్రీప్రాసెసర్) అనే ఒక చిన్న రోబోట్ వచ్చి మీ కోడ్ లో ఉన్న హాష్ సింబల్స్ (#) అన్నిటినీ చూసుకుంటుంది. అది కోడ్ ని క్లీన్ చేసి, కాపీ-పేస్ట్ చేసి అప్పుడు కంపైలర్ కి ఇస్తుంది. ఇందులో అత్యంత పవర్ ఫుల్ ఆయుధం #define (Macros). దీనితో మనం ఒక చిన్న వర్డ్ కి పెద్ద ఫార్ములాస్ లింక్ చేసి, కోడ్ ని సూపర్ ఫాస్ట్ గా మరియు సింపుల్ గా మార్చొచ్చు. గేమింగ్ ఇంజిన్స్ లో మరియు సిస్టమ్ డెవలప్మెంట్ లో అసలు ఇవి లేకుండా కోడ్ ఉండదు. అవెలా పనిచేస్తాయో డీప్ గా చూద్దాం.

1 ప్రీప్రాసెసర్ అంటే ఏంటి? (The Invisible Robot)

మీరు #include <stdio.h> అని రాసినప్పుడు, ప్రీప్రాసెసర్ వచ్చి నిజంగానే ఆ stdio.h ఫైల్ ని ఓపెన్ చేసి, అందులో ఉన్న వందల లైన్ల కోడ్ ని తీసుకొచ్చి మీ ప్రోగ్రామ్ పైభాగంలో (Top) సింపుల్ గా కాపీ-పేస్ట్ చేస్తుంది. ఇది కంపైలర్ కి వెళ్లే ముందే జరిగే టెక్స్ట్ రీప్లేస్మెంట్ ప్రాసెస్!

✨ రియల్ లైఫ్ స్టోరీ: Find & Replace (మ్యాజిక్ నంబర్స్)

మీరు ఒక గేమ్ కోడ్ రాస్తున్నారు. ఆ గేమ్ లో మొత్తం 100 మంది ఎనిమీస్ (Enemies) ఉంటారు. మీరు కోడ్ లో ప్రతిచోటా for(i=0; i<100; i++) అని రాసుకుంటూ వెళ్లారు. దీన్నే Magic Numbers అంటారు (ఎందుకంటే ఆ 100 అంటే ఏంటో చూసే వాడికి తెలీదు).

రేపు పొద్దున బాస్ వచ్చి "ఎనిమీస్ ని 500 చేయి" అంటే... ఆ వేల లైన్ల కోడ్ లో వెతికి వెతికి ఎక్కడ 100 ఉందో మార్చాలి. అదే మీరు పైభాగంలో #define MAX_ENEMIES 100 అని రాసుకుంటే... రోబోట్ వచ్చి కోడ్ మొత్తంలో ఎక్కడ MAX_ENEMIES ఉంటే అక్కడ 100 పెట్టి కంపైల్ చేస్తుంది. మార్చాలంటే జస్ట్ ఆ ఒక్కచోట మారిస్తే యాప్ అంతా ఆటోమేటిక్ గా అప్డేట్ అయిపోతుంది!

2 మ్యాక్రోస్ (Macros) vs ఫంక్షన్స్ (Functions)

ఫంక్షన్ ని కాల్ చేసినప్పుడు ప్రోగ్రామ్ మెమరీ లో ఒక కొత్త బ్లాక్ (Stack frame) క్రియేట్ చేసి అక్కడికి దూకి పని చేసి వెనక్కి వస్తుంది. ఇది కొంచెం టైమ్ టేకింగ్. కానీ మీరు ఒక ఫార్ములాని మ్యాక్రో లాగా #define SQUARE(x) (x*x) అని రాస్తే, కంపైల్ అయ్యే ముందే ఆ టెక్స్ట్ మొత్తం అక్కడే డైరెక్ట్ గా పేస్ట్ అవుతుంది. దూకడం (Jumping) ఉండదు కాబట్టి ఎగ్జిక్యూషన్ ఫుల్ ఫాస్ట్!

3 ఒకే ఒక సింపుల్ కోడ్ (Advanced Macros)

కింద కోడ్ లో పీ (PI) వాల్యూ ని, ఒక మ్యాక్రో ఫంక్షన్ ని మరియు కండిషనల్ కంపైలేషన్ (Conditional Compilation) ని ఎలా వాడామో క్లియర్ గా చూడండి.

C — Preprocessor & Macros ▶ Run Code 
#include <stdio.h>

// 1. సాధారణ మ్యాక్రో (కాన్స్టంట్)
#define PI 3.14159
#define GAME_NAME "Space Invaders 2026"

// 2. మ్యాక్రో ఫంక్షన్ (బ్రాకెట్లు చాలా ముఖ్యం!)
#define MAX(a, b) ((a) > (b) ? (a) : (b))

// 3. కండిషనల్ కంపైలేషన్ (DEBUG మోడ్)
#define DEBUG_MODE 1

int main() {
    printf("Welcome to %s!\n\n", GAME_NAME);
    
    // మ్యాక్రో తో ఏరియా క్యాలిక్యులేషన్
    float radius = 5.0;
    float area = PI * radius * radius;
    printf("Circle Area: %.2f\n", area);
    
    // మ్యాక్రో ఫంక్షన్ తో హైయెస్ట్ నంబర్ (ఇది టెక్స్ట్ లాగా పేస్ట్ అవుతుంది)
    int score1 = 450, score2 = 720;
    printf("Highest Score: %d\n", MAX(score1, score2));
    
    // 4. ఇక్కడ మ్యాజిక్: DEBUG_MODE 1 ఉంటేనే ఈ లైన్ కంపైల్ అవుతుంది!
#if DEBUG_MODE
    printf("\n[DEBUG]: Variables checking... radius=%.1f\n", radius);
#endif

    return 0;
}
4 కోడ్ లో ఏం జరుగుతోంది? (Step-by-Step)
  • #define PI 3.14: ఇక్కడ కచ్చితంగా గుర్తుపెట్టుకోవాల్సింది ఏంటంటే, చివర్లో సెమికోలన్ (;) పెట్టకూడదు! ఒకవేళ పెడితే, మీరు ఎక్కడ PI వాడితే అక్కడ సెమికోలన్ కూడా పేస్ట్ అయ్యి కోడ్ ఎర్రర్ వస్తుంది.
  • #define MAX(a,b) ((a) > (b) ? (a) : (b)): బ్రాకెట్స్ ఎందుకు అన్నిసార్లు పెట్టామంటే... ఎవరైనా MAX(2+3, 4) అని పిలిస్తే, బ్రాకెట్స్ లేకపోతే బాడ్-మాస్ (BODMAS) రూల్స్ దెబ్బతిని రిజల్ట్ రాంగ్ వస్తుంది. సేఫ్ సైడ్ కి ఎప్పుడూ లోపల కూడా బ్రాకెట్స్ పెట్టాలి.
  • #if DEBUG_MODE: ఇది కంపైలర్ కి వెళ్లే ముందే, 1 ఉంటే ఆ కోడ్ ని ఉంచుతుంది, 0 ఉంటే ఆ కోడ్ ని పూర్తిగా డిలీట్ చేస్తుంది! మనం యాప్ ని రిలీజ్ (Playstore లోకి) చేసేటప్పుడు దీన్ని 0 చేస్తాం, అప్పుడు హ్యాకర్స్ కి మన డీబగ్ కోడ్ ఏమీ కనిపించదు (కనీసం ఫైల్ సైజు కూడా పెరగదు).
5 ఇంటర్వ్యూలలో అడిగే కామన్ ప్రశ్నలు (FAQ)

Q1: const int PI = 3; కి #define PI 3 కి తేడా ఏంటి?

చాలా పెద్ద తేడా ఉంది! const వాడితే దానికి మెమరీ (RAM) లో ఒక అడ్రస్ క్రియేట్ అయ్యి 4 బైట్స్ తీసుకుంటుంది. దాని అడ్రస్ ని ఇంకెవరికైనా పాస్ చేయొచ్చు. కానీ #define కి మెమరీ అడ్రస్ ఉండదు, అది కేవలం టెక్స్ట్ ఫైండ్-రీప్లేస్ లాగా పనిచేస్తుంది. కాబట్టి ఎవరికైనా అడ్రస్ ఇవ్వాల్సిన పని లేనప్పుడు #define వాడటం స్పీడ్ అండ్ సేఫ్!

Q2: #undef అంటే ఏంటి?

మీరు పైన #define MAX 100 అని ఇచ్చారు, కానీ కింద కొంత కోడ్ తర్వాత అది 200 అవ్వాలి అనుకోండి. అప్పుడు #undef MAX అని రాసి (అంటే దాన్ని చెరిపేసి), మళ్ళీ కొత్తగా #define MAX 200 అని రాసుకోవచ్చు. ఒకే ఫైల్ లో వేరు వేరు లిమిట్స్ కావాల్సినప్పుడు ఇది బాగా వాడుతారు.

Q3: #ifndef ఎందుకు వాడుతారు? (Header Guards)

పెద్ద ప్రాజెక్ట్స్ లో ఒకే .h ఫైల్ ని రెండు మూడు సార్లు ఇంక్లూడ్ చేస్తే కంపైలర్ కన్ఫ్యూజ్ అవుతుంది. అలా డూప్లికేట్ అవ్వకుండా ఉండటానికి, If Not Defined (#ifndef) వాడతాం. "ఒకవేళ ముందే ఇంక్లూడ్ అయి ఉంటే, మళ్ళీ చేయొద్దు" అని కంపైలర్ కి ఆర్డర్ వేయడమే ఈ కాన్సెప్ట్ (వీటినే Header Guards అంటారు).
