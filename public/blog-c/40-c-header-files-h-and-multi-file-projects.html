Header Files (.h) & Multi-file Projects (తెలుగులో)

⚡ C (C17 / C23 Standard) 🟢 Lesson 40 📂 Phase 14: File I/O & Preprocessor 📅 2026 Comprehensive Master Edition
📌 Covered in this in-depth guide: Multi-file Architecture · .c vs .h files · Header Guards (#ifndef) · extern keyword · Code Modularity

ఇంతవరకు మనం రాసిన చిన్న చిన్న ప్రోగ్రామ్స్ అన్నీ ఒకే main.c ఫైల్ లో రాసేసాం. కానీ విండోస్ ఆపరేటింగ్ సిస్టమ్ లాంటి వాటికి కోట్ల లైన్ల కోడ్ ఉంటుంది. అదంతా ఒకే ఫైల్ లో రాస్తే ఎవరైనా చదవగలరా? కంపైల్ చేయడానికి రోజులు పడుతుంది! అందుకే ఇండస్ట్రీలో ఒక ప్రాజెక్ట్ ని రకరకాల చిన్న ముక్కలుగా (Modules) విడగొడతారు. మ్యాథ్స్ కి ఒక ఫైల్, ఇంటర్ఫేస్ కి ఒక ఫైల్ ఇలా. అలా విడగొట్టిన ఫైల్స్ అన్నీ మళ్ళీ ఒకదానితో ఒకటి ఎలా మాట్లాడుకుంటాయి? దానికి మనం వాడే బ్రిడ్జి పేరే Header Files (హెడర్ ఫైల్స్ - .h). మీ స్వంత హెడర్ ఫైల్స్ ని ఎలా సృష్టించాలో ఈరోజు డీప్ గా చూద్దాం.

1 .h మరియు .c ఫైల్స్ మధ్య తేడా (The Architecture)

ప్రొఫెషనల్ C డెవలపర్స్ ఎప్పుడూ ఒక రూల్ పాటిస్తారు: "హెడర్ ఫైల్స్ లో కేవలం ఇండెక్స్ (Titles) మాత్రమే ఉండాలి, ఒరిజినల్ స్టోరీ అంతా .c ఫైల్ లోనే ఉండాలి."

  • Header File (math_utils.h): ఇదొక మెనూ కార్డ్ లాంటిది. ఇందులో కేవలం ఫంక్షన్స్ పేర్లు, వాటి పరామిటర్స్ (Declarations) మాత్రమే ఉంటాయి. ఉదా: int add(int a, int b);
  • Source File (math_utils.c): ఇదొక వంటగది (Kitchen). ఆ ఫంక్షన్స్ లోపల అసలు కోడ్ ఎలా పనిచేస్తుంది (Implementation) అని రాసి ఉంటుంది.
  • Main File (main.c): ఇక్కడ యూజర్ ఆర్డర్ ఇస్తాడు. ఇది math_utils.h ని ఇంక్లూడ్ చేసుకుని వాడుకుంటుంది.

🛡️ రియల్ లైఫ్ స్టోరీ: Header Guards (డబుల్ ఇంక్లూడ్ సమస్య)

ఒక రెస్టారెంట్ లో ముగ్గురు మేనేజర్లు ఒకేసారి కిచెన్ కి వెళ్లి మెనూ కార్డ్ తీసుకురమ్మని ఆర్డర్ వేసారు అనుకోండి (అంటే ఒకే .h ఫైల్ ని మూడు .c ఫైల్స్ ఇంక్లూడ్ చేసుకుంటే). కంపైలర్ కి ఆ ఫంక్షన్ పేర్లు మూడు సార్లు పేస్ట్ అవుతాయి, దాంతో ఏది ఒరిజినల్ అని కన్ఫ్యూజ్ అయ్యి "Redefinition Error" ఇస్తుంది.

దీన్ని ఆపడానికే Header Guards వాడతారు. అంటే మెనూ కార్డ్ పైన ఒక తాళం వేస్తారు. "ఎవరైనా నన్ను ఆల్రెడీ చదివి ఉంటే (#ifndef), మళ్ళీ చదవొద్దు, వదిలేయండి" అని ప్రీప్రాసెసర్ కి చెప్తారు. దీనివల్ల వంద ఫైల్స్ ఉన్నా ఎర్రర్స్ రావు.

2 గ్లోబల్ వేరియబుల్స్ షేరింగ్ (extern keyword)

మీరు ఒక ఫైల్ లో int score = 0; అని రాసి, దాన్ని వేరే ఫైల్ లో వాడాలి అనుకుంటే కుదరదు. కానీ మీరు extern int score; అని రాస్తే, కంపైలర్ కి "బాసు, ఈ వేరియబుల్ ఎక్కడో వేరే ఫైల్ లో ఉంది, నన్ను వాడనివ్వు" అని పర్మిషన్ అడిగినట్టు!

3 ఒకే ఒక సింపుల్ కోడ్ (Multi-file Simulation)

(ఈ క్రింది ఉదాహరణలో మూడు ఫైల్స్ ఉంటాయి. వాటిని కంపైల్ చేసేటప్పుడు gcc main.c math_utils.c -o myapp అని కలిపి కంపైల్ చేయాలి.)

C — Header Files (.h) ▶ Run Code 
/* --------------------------------------
   1. math_utils.h (Header File)
-------------------------------------- */
// Header Guard: ఇవి డూప్లికేట్స్ ని ఆపుతాయి
#ifndef MATH_UTILS_H
#define MATH_UTILS_H

// కస్టమ్ మ్యాక్రోస్
#define MAX_POWER 100

// ఫంక్షన్ డిక్లరేషన్ (కానీ లోపల కోడ్ ఉండదు)
int multiply(int a, int b);
int getSquare(int n);

#endif


/* --------------------------------------
   2. math_utils.c (Source File)
-------------------------------------- */
#include "math_utils.h" // స్వంత హెడర్ కాబట్టి డబుల్ కోట్స్ ""

// ఫంక్షన్స్ ఇక్కడ అమలు చేయబడతాయి (Implementation)
int multiply(int a, int b) {
    return a * b;
}

int getSquare(int n) {
    return multiply(n, n);
}


/* --------------------------------------
   3. main.c (Main Application)
-------------------------------------- */
#include <stdio.h>
#include "math_utils.h" // కిచెన్ మెనూ ని ఇక్కడ అడుగుతున్నాం

int main() {
    printf("--- Multi-File Calculator ---\n");
    
    int result = getSquare(12); // వేరే ఫైల్ లో ఉన్న ఫంక్షన్ కాల్
    
    printf("Square of 12 is: %d\n", result);
    printf("Max Power Allowed: %d\n", MAX_POWER);
    
    return 0;
}
4 కోడ్ లో ఏం జరుగుతోంది? (Step-by-Step)
  • #ifndef MATH_UTILS_H: కంపైలర్ ఫస్ట్ టైమ్ ఈ ఫైల్ ని చూసినప్పుడు ఈ పేరు (Macro) డిఫైన్ కాలేదు కాబట్టి, లోపలికి వెళ్లి డిఫైన్ (#define) చేస్తుంది. సెకండ్ టైమ్ ఎవరైనా మళ్ళీ పిలిస్తే, ఆల్రెడీ డిఫైన్ అయ్యింది కదా అని లోపల ఉన్న కోడ్ ని మొత్తం ఇగ్నోర్ చేస్తుంది.
  • #include "math_utils.h": మీరు C లైబ్రరీస్ అయితే < > వాడాలి (అవి సిస్టమ్ ఫోల్డర్స్ లో ఉంటాయి). కానీ మీరు రాసిన ఫైల్ అయితే " " వాడాలి. అప్పుడే కంపైలర్ అదే ఫోల్డర్ లో వెతుకుతుంది.
  • gcc main.c math_utils.c: మీరు రెండు .c ఫైల్స్ ని కలిపి కంపైలర్ కి ఇవ్వాలి. అప్పుడు కంపైలర్ రెంటినీ కలిపి లింక్ చేసి ఒకే .exe ఫైల్ ని ఇస్తుంది. దీన్నే Linking Process (లింకింగ్) అంటారు.
5 ఇంటర్వ్యూలలో అడిగే కామన్ ప్రశ్నలు (FAQ)

Q1: #pragma once కి మరియు #ifndef కి తేడా ఏంటి?

చాలా మోడరన్ కంపైలర్స్ లో ఆ మూడు లైన్ల ifndef లాజిక్ రాయకుండా టాప్ లో సింపుల్ గా #pragma once అని రాస్తారు. ఇది కూడా హెడర్ గార్డ్ లాగానే పనిచేస్తుంది. కానీ ఇది కొన్ని పాత (1990ల) కంపైలర్స్ లో పని చేయదు, అందుకే ఇండస్ట్రీలో అందరూ #ifndef వాడటానికే ప్రిఫర్ చేస్తారు.

Q2: .h ఫైల్ లో ఫంక్షన్ కోడ్ రాస్తే ఏమవుతుంది?

మీరు .h లో డైరెక్ట్ గా కోడ్ (ఉదా: printf తో పాటు) రాసేస్తే, ఆ ఫైల్ ని ఎవరెవరు ఇంక్లూడ్ చేసుకుంటారో వాళ్ళందరికీ ఆ కోడ్ పేస్ట్ అవుతుంది. అప్పుడు ఫంక్షన్ చాలాసార్లు కాపీ అయ్యి "Multiple Definition of function" అనే పెద్ద ఎర్రర్ వచ్చి లింకింగ్ ఫెయిల్ అవుతుంది. అందుకే హెడర్ లో కేవలం ఇండెక్స్ (పేర్లు) మాత్రమే ఉండాలి.

Q3: static ఫంక్షన్స్ అంటే ఏంటి?

మీరు ఒక వేరియబుల్ ముందు గాని లేదా ఫంక్షన్ ముందు గాని static int score; అని రాస్తే, ఆ ఫైల్ లో ఉన్న వాళ్ళు తప్ప బయట ఏ ఫైల్ వాళ్ళు (extern వాడినా కూడా) దాన్ని యాక్సెస్ చేయలేరు. ఇది పబ్లిక్ నుండి ప్రైవేట్ కి మార్చడానికి వాడే బెస్ట్ సెక్యూరిటీ ట్రిక్ (Encapsulation in C).
