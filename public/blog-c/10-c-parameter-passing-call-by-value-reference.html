Call by Value vs Call by Reference (పాయింటర్స్ ద్వారా)

⚡ Modern C (C99 / C11) 🟢 Chapter 10 of 20 📂 Phase 03: ఫంక్షన్స్, స్కోప్ & రికర్షన్ 📅 2026 Edition
📌 Covered in this chapter: మెమరీ కాపీ vs ఒరిజినల్ అడ్రస్ పాసింగ్ · swap(&a, &b) స్వాపింగ్ పోస్ట్‌మార్టం · మల్టిపుల్ రిటర్న్ వాల్యూస్
C లాంగ్వేజ్‌లో ఫంక్షన్లకు డేటాను పంపేటప్పుడు జరిగే అంతర్గత మెమరీ మార్పిడిని అర్థం చేసుకోవడం అత్యంత కీలకమైన అంశం. ఒక వేరియబుల్‌ను ఫంక్షన్‌కు పాస్ చేసినప్పుడు అది కేవలం ఒక కాపీగా వెళ్తుందా లేక అసలు వేరియబుల్ మెమరీనే మారుస్తుందా? ఇంటర్వ్యూలలో అత్యంత ప్రాచుర్యం పొందిన Call by Value vs Call by Reference (పాయింటర్ల ద్వారా) మరియు స్వాపింగ్ మెకానిక్స్‌ను ఈ అధ్యాయంలో సమగ్రంగా పరిశీలిద్దాం.
1Call by Value — సేఫ్ బట్ ఐసోలేటెడ్ మెమరీ క్లోన్

డీఫాల్ట్‌గా C లాంగ్వేజ్ అన్ని ఫంక్షన్ కాల్స్‌లో Call by Value పద్ధతినే అనుసరిస్తుంది. అంటే కాలర్ (Caller) నుండి పాస్ చేయబడిన వేరియబుల్ యొక్క విలువను మాత్రమే కాపీ చేసి, కాల్ చేయబడిన ఫంక్షన్ యొక్క ప్రత్యేక స్టాక్ ఫ్రేమ్‌లో నిల్వ చేస్తుంది.

C — Call by Value (No modification in caller) ⚡ Try in C Compiler 
#include <stdio.h>

void modifyValue(int num) {
    num = 1000; // ఇది కేవలం లోకల్ కాపీని మాత్రమే మారుస్తుంది
}

int main(void) {
    int x = 50;
    modifyValue(x);
    printf("x విలువ మారలేదు: %d\n", x); // x ఇప్పటికీ 50 మాత్రమే!
    return 0;
}

💡 modifyValue() ఫంక్షన్ లోపల num ను ఎంత మార్చినా, main() లోని అసలు వేరియబుల్ x సురక్షితంగా ఉంటుంది.

2Call by Reference (పాయింటర్స్ ద్వారా) — డైరెక్ట్ మెమరీ యాక్సెస్

ఒక ఫంక్షన్ కాలర్‌లోని అసలు వేరియబుల్‌ను నేరుగా మార్చాలనుకుంటే (లేదా రెండు వేరియబుల్స్ విలువలను తారుమారు చేయాలనుకుంటే), మనం విలువను కాకుండా ఆ వేరియబుల్ యొక్క RAM అడ్రస్ (&) ను పాయింటర్ పారామీటర్‌గా పంపాలి.

C — Swap using Pointers (Call by Reference) ⚡ Try in C Compiler 
#include <stdio.h>

// పాయింటర్లు స్వీకరించే ఫంక్షన్
void swap(int *p1, int *p2) {
    int temp = *p1; // *p1 అంటే ఆ అడ్రస్ లోని విలువను చదవడం (Dereferencing)
    *p1 = *p2;      // p1 అడ్రస్ లోకి p2 విలువను రాయడం
    *p2 = temp;     // p2 అడ్రస్ లోకి temp విలువను రాయడం
}

int main(void) {
    int a = 10, b = 20;
    printf("స్వాప్‌కు ముందు : a = %d, b = %d\n", a, b);

    // అడ్రస్‌లను పాస్ చేయడం (&a, &b)
    swap(&a, &b);

    printf("స్వాప్ తర్వాత : a = %d, b = %d\n", a, b);
    return 0;
}
3ఒకే ఫంక్షన్ నుండి బహుళ విలువలను రిటర్న్ చేయడం (Output Parameters)

C లో ఒక ఫంక్షన్ కేవలం ఒకే ఒక్క విలువను మాత్రమే return చేయగలదు. కానీ రెండు లేదా అంతకంటే ఎక్కువ ఫలితాలు అవసరమైనప్పుడు (ఉదా: భాగహారం చేసి భాగఫలం మరియు శేషం రెండూ కావాలన్నప్పుడు) పాయింటర్లను అవుట్‌పుట్ పారామీటర్లు (Output Parameters) గా వాడతాం:

C — Multiple Return Values with Pointers ⚡ Try in C Compiler 
#include <stdio.h>

void divide(int dividend, int divisor, int *quotient, int *remainder) {
    if (divisor != 0) {
        *quotient = dividend / divisor;
        *remainder = dividend % divisor;
    }
}

int main(void) {
    int q, r;
    divide(17, 5, &q, &r);
    printf("17/5 భాగఫలం (Quotient): %d | శేషం (Remainder): %d\n", q, r);
    return 0;
}
4బిగినర్స్ చేసే ఘోరమైన తప్పులు (Beginner Pitfalls)
❌ 1. పాయింటర్స్ లేకుండా స్వాపింగ్ ప్రయత్నించడం:
void swap(int a, int b) { ... } // ఇది main లోని విలువలను మార్చలేదు! ఇది బిగినర్స్ చేసే అత్యంత కామన్ తప్పు. పాయింటర్లు వాడకపోతే స్వాపింగ్ కేవలం ఫంక్షన్ లోపల లోకల్ కాపీలలోనే జరిగి బయట ఎలాంటి ప్రభావం ఉండదు.
❌ 2. డీరిఫరెన్సింగ్ ఆపరేటర్ (*) మర్చిపోవడం:
p1 = p2; // అడ్రస్‌లను మారుస్తుంది కానీ మెమరీలోని విలువలను కాదు! మెమరీ లోపలి విలువను మార్చడానికి ఎల్లప్పుడూ *p1 = *p2; అని ఆస్టెరిస్క్ * ఉపయోగించాలి.
5తరచుగా అడిగే ప్రశ్నలు (FAQ)

Q: C లాంగ్వేజ్‌లో C++ లాంటి Reference (&var) వేరియబుల్స్ ఉన్నాయా?

లేవు! C++ లో void swap(int &a, int &b) అని రాస్తే ఆటోమేటిక్ రిఫరెన్స్ పాసింగ్ జరుగుతుంది. కానీ స్వచ్ఛమైన C లో రిఫరెన్స్ పాస్ చేయాలంటే ఖచ్చితంగా ఎక్స్‌ప్లిసిట్ పాయింటర్స్ (int *a) మరియు అడ్రస్ ఆపరేటర్ (&a) వాడాల్సిందే.

Q: పెద్ద స్ట్రక్చర్లు (Structures) పాస్ చేసేటప్పుడు పాయింటర్లు ఎందుకు వాడాలి?

1000 బైట్ల భారీ స్ట్రక్చర్‌ను Call by Value తో పాస్ చేస్తే ప్రతిసారీ 1000 బైట్లు స్టాక్ మెమరీలోకి కాపీ కావడానికి CPU సమయం వృధా అవుతుంది. పాయింటర్ పాస్ చేస్తే కేవలం 8 బైట్ల మెమరీ అడ్రస్ మాత్రమే పాస్ అయి ప్రోగ్రామ్ వేగంగా నడుస్తుంది.
