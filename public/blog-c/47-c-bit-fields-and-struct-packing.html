Bit Fields & Struct Packing (తెలుగులో)

⚡ C (C17 / C23 Standard) 🟢 Lesson 47 📂 Phase 16: Bitwise & Low-Level 📅 2026 Comprehensive Master Edition
📌 Covered in this in-depth guide: Struct Padding Waste · Bit Fields Syntax · Custom Bit Sizes · Hardware Structs

ఇంతకుముందు లెసన్ లో మనం 8 ఆప్షన్స్ ని ఒకే బైట్ లో పెట్టడానికి మ్యాన్యువల్ గా (మాస్కింగ్) వాడి కోడ్ రాసాం కదా! అది కొంచెం తలనొప్పి పని. దాన్ని సింపుల్ చేయడానికి, C లాంగ్వేజ్ కంపైలర్ ఒక అద్భుతమైన ఫీచర్ ఇచ్చింది. అదే Bit Fields (బిట్ ఫీల్డ్స్). దీని ద్వారా మీరు ఒక స్ట్రక్చర్ (Structure) లోపల ఉన్న వేరియబుల్ కి "నాకు 4 బైట్స్ వద్దు, కేవలం 3 బిట్స్ మాత్రమే ఇవ్వు" అని డైరెక్ట్ గా ఆర్డర్ వేయొచ్చు! స్పేస్ సాటిలైట్స్, IoT డివైజెస్ లో మెమరీని ఒక్క బైట్ కూడా వేస్ట్ కాకుండా ఎలా ప్యాక్ (Pack) చేస్తారో ఈరోజు చూద్దాం.

1 అసలు ప్రాబ్లమ్ ఏంటి? (The Memory Waste)

మీరు ఒక కారు ఇంజిన్ స్టేటస్ గురించి కోడ్ రాస్తున్నారు. కార్ స్టార్ట్ అయిందా (0 లేదా 1), గేర్ నంబర్ ఎంత (1 నుండి 5 వరకు). దీన్ని స్ట్రక్చర్ లో రాస్తే: 

struct Car {
    unsigned int isStarted; // 1 ఆన్, 0 ఆఫ్
    unsigned int gear;      // 1 నుండి 5
};

మామూలుగా ఒక int కి 4 బైట్స్ (32 bits) పడుతుంది. రెండు ఇంట్స్ కి 8 బైట్స్ (64 bits) పడుతుంది! కానీ ఆన్/ఆఫ్ చెప్పడానికి మనకు 1 బిట్ చాలు (మిగతా 31 బిట్స్ గాలికి వదిలేసినట్లే). అలాగే గేర్ చెప్పడానికి 3 బిట్స్ చాలు (2^3 = 8). ఇంత మెమరీ వేస్ట్ కాకుండా అడ్డుకునేదే Bit Fields.

🧳 రియల్ లైఫ్ స్టోరీ: సూట్ కేసు సర్దడం (Struct Packing)

మీరు టూర్ కి వెళ్తూ ఒక పెద్ద సూట్ కేసు కొన్నారు (ఇదే 4 బైట్స్ మెమరీ). అందులో ఒక చిన్న టూత్ బ్రష్ (1 బిట్ డేటా) వేశారు. కానీ రూల్ ఏంటంటే, టూత్ బ్రష్ పక్కన ఇంకేమీ పెట్టకూడదు, మరో వస్తువు కావాలంటే ఇంకో పెద్ద సూట్ కేసు కొనాల్సిందే అంటాడు కంపైలర్ (దీన్నే Padding అంటారు).

ఇలా అయితే ప్లేన్ లో స్థలం సరిపోదు కదా! అప్పుడు మీరు "Bit Fields" అనే జిప్ కవర్ వాడతారు. "ఒకే సూట్ కేసు లో, ఈ మూల టూత్ బ్రష్ (1 bit), పక్కన పేస్ట్ (3 bits), ఆ పక్కన ఇంకోటి ప్యాక్ చేయి" అని కంపైలర్ కి చెప్తారు. దాంతో ఒకే 4 బైట్స్ లో వంద రకాల డేటా ప్యాక్ అయిపోయి మెమరీ ఆదా అవుతుంది!

2 బిట్ ఫీల్డ్స్ సింటాక్స్ (Syntax)

సింటాక్స్ చాలా సింపుల్. వేరియబుల్ డిక్లేర్ చేసాక పక్కన కోలన్ (:) పెట్టి మీకు ఎన్ని బిట్స్ కావాలో ఆ నంబర్ రాయాలి.

unsigned int isStarted : 1; (అంటే దీనికి ఒక్క బిట్ మాత్రమే ఇవ్వు అని అర్థం).

3 ఒకే ఒక సింపుల్ కోడ్ (Bit Field Packing)

కింద కోడ్ లో నార్మల్ స్ట్రక్చర్ కి మరియు బిట్ ఫీల్డ్ స్ట్రక్చర్ కి మధ్య ఎంత మెమరీ ఆదా అయ్యిందో (sizeof) లైవ్ గా చూడండి.

C — Bit Fields ▶ Run Code 
#include <stdio.h>

// 1. నార్మల్ స్ట్రక్చర్ (మెమరీ వేస్ట్)
struct NormalCar {
    unsigned int isStarted; // 32 bits
    unsigned int gear;      // 32 bits
    unsigned int hasAC;     // 32 bits
};

// 2. బిట్ ఫీల్డ్ స్ట్రక్చర్ (మెమరీ ప్యాకింగ్)
struct SmartCar {
    unsigned int isStarted : 1; // 1 bit (0 లేదా 1)
    unsigned int gear      : 3; // 3 bits (0 నుండి 7 వరకు పడుతుంది)
    unsigned int hasAC     : 1; // 1 bit
};

int main() {
    struct NormalCar car1;
    struct SmartCar car2;
    
    printf("--- Memory Size Comparison ---\n");
    // NormalCar 3 ఇంటీజర్స్ కాబట్టి 12 Bytes తీసుకుంటుంది!
    printf("Normal Struct Size : %zu Bytes\n", sizeof(car1));
    
    // SmartCar కేవలం 5 బిట్స్ మాత్రమే అడిగింది, కానీ కంపైలర్ మినిమం 1 ఇంటీజర్ (4 Bytes) ఇస్తుంది.
    // అయినా 12 బైట్స్ నుండి 4 బైట్స్ కి తగ్గింది!
    printf("Bit-Field Size     : %zu Bytes\n\n", sizeof(car2));
    
    // వాడుకునే విధానం సేమ్ నార్మల్ లాగానే ఉంటుంది!
    car2.isStarted = 1;
    car2.gear = 4;
    car2.hasAC = 0;
    
    printf("--- Car Status ---\n");
    printf("Engine : %s\n", car2.isStarted ? "ON" : "OFF");
    printf("Gear   : %d\n", car2.gear);
    printf("AC     : %s\n", car2.hasAC ? "ON" : "OFF");
    
    // ఒకవేళ లిమిట్ దాటి వాల్యూ ఇస్తే ఏమవుతుంది? (ఉదా: 3 bits అంటే మ్యాక్స్ 7)
    car2.gear = 9; // 9 బైనరీలో 1001 (4 bits). కానీ మనం 3 bits ఇచ్చాం కాబట్టి ఫస్ట్ బిట్ కట్ అవుతుంది.
    printf("\n[!] Overflow Test (Gear=9) -> Saved as: %d\n", car2.gear); // ఇది 1 వస్తుంది!
    
    return 0;
}
4 కోడ్ లో ఏం జరుగుతోంది? (Step-by-Step)
  • sizeof(NormalCar): ప్రతి వేరియబుల్ 4 బైట్స్, మొత్తం 3 ఉన్నాయి కాబట్టి 12 బైట్స్ (అంటే 96 బిట్స్) ఆక్రమించింది.
  • sizeof(SmartCar): మనం అడిగింది కేవలం (1+3+1 = 5 బిట్స్). కంపైలర్ ఒక మెమరీ బ్లాక్ (4 బైట్స్ = 32 బిట్స్) తీసుకుని ఆ 5 బిట్స్ ని అందులోనే ప్యాక్ చేస్తుంది. మిగతా 27 బిట్స్ ఖాళీగా ఉంటాయి. సైజు 4 బైట్స్ మాత్రమే! (66% మెమరీ ఆదా).
  • Overflow: మీరు 3 బిట్స్ అడిగి అందులో 9 (1001) పెడితే, కంపైలర్ కుడివైపు ఉన్న 3 బిట్స్ (001) మాత్రమే ఉంచుకుని, ఎడమ వైపు ఉన్నది కట్ చేస్తుంది. అందుకే రిజల్ట్ 1 వచ్చింది.
5 ఇంటర్వ్యూలలో అడిగే కామన్ ప్రశ్నలు (FAQ)

Q1: బిట్ ఫీల్డ్స్ కి పాయింటర్స్ లేదా అడ్రస్ లు (&car2.gear) వాడొచ్చా?

అస్సలు వాడలేరు! కంప్యూటర్ లో మెమరీ అడ్రస్ ఎప్పుడూ కనీసం 1 బైట్ (8 బిట్స్) కి ఒక అడ్రస్ ఉంటుంది. కానీ బిట్ ఫీల్డ్ అనేది 1 బిట్ లేదా 3 బిట్స్ కదా! దానికి అడ్రస్ అసలు ఉండదు. అందుకే scanf("%d", &car2.gear); అని రాయడానికి ట్రై చేస్తే కంపైలర్ వెంటనే ఎర్రర్ ఇస్తుంది.

Q2: నేను 33 బిట్స్ కావాలని int size : 33; అని అడగొచ్చా?

కుదరదు! మీరు బేస్ ఏ టైప్ ఇస్తారో దాని లిమిట్ దాటకూడదు. int కి మ్యాక్స్ 32 బిట్స్ మాత్రమే. అంతకంటే ఎక్కువ కావాలంటే దాన్ని పక్కన నార్మల్ వేరియబుల్ లాగా పెట్టుకోవాల్సిందే.

Q3: నెట్వర్క్ ప్యాకెట్స్ (TCP/IP) లో బిట్ ఫీల్డ్స్ వాడతారా?

C లాంగ్వేజ్ ని నెట్వర్కింగ్ లో వాడటానికి అసలు కారణమే ఇది! ఒక నెట్వర్క్ ప్యాకెట్ లో హెడర్ సైజు చాలా చిన్నదిగా ఉండాలి (20 బైట్స్). అందులో 4 బిట్స్ IP వెర్షన్ కి, 4 బిట్స్ లెంగ్త్ కి ఇలా ప్రతి బిట్ ని లెక్కపెట్టి ప్యాక్ చేస్తారు. దానికి బిట్ ఫీల్డ్స్ పర్ఫెక్ట్ గా సూట్ అవుతాయి.
