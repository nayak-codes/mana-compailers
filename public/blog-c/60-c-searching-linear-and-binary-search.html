Linear & Binary Search (తెలుగులో)

⚡ C (C17 / C23 Standard) 🟢 Lesson 60 📂 Phase 20: Algorithms & Final 📅 2026 Comprehensive Master Edition
📌 Covered in this in-depth guide: Algorithms Basics · Linear Search (O(N)) · Binary Search (O(log N)) · Time Complexity

ఇప్పటివరకు డేటాని (Array, List, Tree, Graph) ఎలా స్టోర్ చేయాలో నేర్చుకున్నాం (ఇవే డేటా స్ట్రక్చర్స్). ఇప్పుడు అసలు ఆట మొదలవుతుంది! ఆ స్టోర్ చేసిన డేటా లోపలికి వెళ్లి మనకు కావాల్సింది లాక్కుని రావడం (దీన్నే Algorithms అంటారు). ఒక లక్ష నంబర్స్ ఉన్న అర్రే లో 99 వ నంబర్ కోసం వెతకాలి. గుడ్డిగా మొదటి నుండి వెతుక్కుంటూ వెళ్తామా? లేదా ఒక స్మార్ట్ టెక్నిక్ వాడి కేవలం 10 స్టెప్స్ లో ఆన్సర్ లాగేస్తామా? ఈరోజు Searching (సెర్చింగ్) ప్రపంచంలో ఉన్న రెండు బ్రహ్మాస్త్రాలు Linear Search మరియు Binary Search ఎలా పనిచేస్తాయో డీప్ గా చూద్దాం.

1 లీనియర్ సెర్చ్ (Linear Search) - కష్టజీవి

లీనియర్ సెర్చ్ అంటే గుడ్డిగా మొదటి బాక్స్ నుండి స్టార్ట్ చేసి, ప్రతి బాక్స్ లోపల తొంగి చూస్తూ వెతుక్కుంటూ వెళ్లడం.

📖 రియల్ లైఫ్ స్టోరీ: డిక్షనరీ లో వెతకడం (Part 1)

ఒక వెయ్యి పేజీలు ఉన్న ఇంగ్లీష్ డిక్షనరీ లో మీరు "Zebra" అనే పదం వెతకాలి. లీనియర్ సెర్చ్ వాడేవాడు ఏం చేస్తాడు? పేజీ నంబర్ 1 ఓపెన్ చేస్తాడు, అందులో ఉందా? లేదు! పేజీ 2, పేజీ 3... ఇలా వెయ్యి పేజీలు తిప్పిన తర్వాత ఆ లాస్ట్ లో వాడికి కనబడుతుంది. దీనికి పట్టే టైమ్ O(N) (అంటే వెయ్యి వస్తువులు ఉంటే వెయ్యి సార్లు వెతకాల్సిందే).

2 బైనరీ సెర్చ్ (Binary Search) - స్మార్ట్ వర్కర్

బైనరీ సెర్చ్ వాడాలంటే ఒక పక్కా రూల్ ఉంది: డేటా ముందే ఒక ఆర్డర్ లో (సార్ట్ అయ్యి) ఉండాలి. (అంటే డిక్షనరీ లాగా A, B, C ఆర్డర్ లో ఉండాలి).

📖 రియల్ లైఫ్ స్టోరీ: డిక్షనరీ లో వెతకడం (Part 2)

బైనరీ సెర్చ్ వాడేవాడు డిక్షనరీ ని డైరెక్ట్ గా కరెక్ట్ గా సగానికి (Middle) ఓపెన్ చేస్తాడు! (పేజీ నంబర్ 500). అక్కడ 'M' లెటర్ ఉందనుకుందాం.

వాడు వెతుకుతున్నది "Zebra". 'M' కన్నా 'Z' పెద్దది (కుడి వైపు ఉంటుంది) అని వాడికి తెలుసు. కాబట్టి 1 నుండి 500 పేజీలను పూర్తిగా చింపేసి డస్ట్ బిన్ లో పడేస్తాడు (సగం డేటా గల్లంతు!). ఇప్పుడు 501 నుండి 1000 మధ్యలో మళ్ళీ సగానికి ఓపెన్ చేస్తాడు. ఇలా సగం చేసుకుంటూ వెళ్తే కేవలం 10 సార్లు (O(log N)) పుస్తకం ఓపెన్ చేసేసరికి ఆన్సర్ దొరికేస్తుంది!

3 ఒకే ఒక సింపుల్ కోడ్ (Binary Search in C)

కింద కోడ్ లో low, high, mid అనే మూడు పాయింటర్స్ వాడి బైనరీ సెర్చ్ తో ఒక నంబర్ ని ఫాస్ట్ గా ఎలా పట్టుకున్నామో చూడండి.

C — Binary Search (Fast Search) ▶ Run Code 
#include <stdio.h>

// బైనరీ సెర్చ్ ఫంక్షన్
// (అర్రే కచ్చితంగా సార్ట్ అయ్యి ఉండాలి)
int binarySearch(int arr[], int size, int target) {
    int low = 0;             // మొదలు (పేజీ 1)
    int high = size - 1;     // చివర (లాస్ట్ పేజీ)
    int steps = 0;           // ఎన్ని సార్లు తిరిగామో కౌంట్
    
    while (low <= high) {
        steps++;
        int mid = (low + high) / 2; // కరెక్ట్ గా సగానికి ఓపెన్ చేసాం
        
        printf("Step %d: Checking middle index %d (value = %d)\n", steps, mid, arr[mid]);
        
        // సగం ఓపెన్ చేయగానే జాక్ పాట్! దొరికేస్తే...
        if (arr[mid] == target) {
            printf("\n-> Found in %d steps!\n", steps);
            return mid; // ఇండెక్స్ రిటర్న్ చేయి
        }
        
        // మన టార్గెట్ సగం వాల్యూ కన్నా పెద్దది అయితే... (కుడి వైపు వెళ్ళు)
        if (target > arr[mid]) {
            low = mid + 1; // ఎడమ పక్క పేజీలన్నీ ఇగ్నోర్ (చింపేసాం)
        } 
        // మన టార్గెట్ చిన్నది అయితే... (ఎడమ వైపు వెళ్ళు)
        else {
            high = mid - 1; // కుడి పక్క పేజీలన్నీ ఇగ్నోర్
        }
    }
    
    return -1; // అసలు బుక్ లో ఆ పదం లేకపోతే -1 ఇస్తాం
}

int main() {
    printf("--- Binary Search Algorithm ---\n\n");
    
    // సార్ట్ చేసిన (చిన్న నుండి పెద్ద) ఒక అర్రే
    int numbers[] = {10, 25, 34, 56, 78, 89, 92, 105, 120};
    int size = sizeof(numbers) / sizeof(numbers[0]);
    
    int target = 92; // మనం వెతకాల్సిన దొంగ
    printf("Searching for %d...\n\n", target);
    
    int resultIndex = binarySearch(numbers, size, target);
    
    if (resultIndex != -1) {
        printf("Success! Number %d found at index [%d].\n", target, resultIndex);
    } else {
        printf("Failed! Number not found.\n");
    }
    
    return 0;
}
4 కోడ్ లో ఏం జరుగుతోంది? (Step-by-Step)
  • mid = (low + high) / 2;: ఇది అసలైన మ్యాజిక్. మీరు 0 నుండి 8 మధ్యలో ఉంటే, (0+8)/2 = 4 ఇండెక్స్ వస్తుంది. 4 దగ్గర ఉన్న వాల్యూ ని టార్గెట్ తో చెక్ చేస్తుంది.
  • low = mid + 1;: ఒకవేళ టార్గెట్ 92, కానీ మిడ్ వాల్యూ 78 అయితే... మన టార్గెట్ కుడివైపు (Right Side) ఉందన్నమాట! అప్పుడు మనం లెఫ్ట్ పాయింటర్ (low) ని తీసుకొచ్చి mid + 1 (అంటే 5) దగ్గర పెడతాం. అప్పుడు లెఫ్ట్ లో ఉన్న 0,1,2,3,4 ఇండెక్స్ లు పర్మినెంట్ గా డిలీట్ అయిపోయినట్టే! సగం పని తగ్గింది.
  • low <= high: ఈ లూప్ ఎంతవరకు తిరుగుతుంది? ఆ రెండు పాయింటర్స్ ఒకదానికొకటి ఎదురుపడి, క్రాస్ అయ్యిపోయేవరకు తిరుగుతుంది. క్రాస్ అయిపోయాయి అంటే ఆ పుస్తకంలో ఆ పేజీ లేనట్టే! అప్పుడు లూప్ బ్రేక్ అయ్యి -1 కి వస్తుంది.
5 ఇంటర్వ్యూలలో అడిగే కామన్ ప్రశ్నలు (FAQ)

Q1: డేటా సార్ట్ అవ్వకపోతే (జంబుల్ గా ఉంటే) బైనరీ సెర్చ్ పనిచేస్తుందా?

అస్సలు పనిచేయదు! డిక్షనరీ లో పదాలు అన్నీ కలగాపులగంగా ఉంటే, సగానికి ఓపెన్ చేసినప్పుడు ఎటు వెళ్ళాలో మీకు ఎలా తెలుస్తుంది? కాబట్టి డేటా సార్ట్ (Sort) అయ్యి ఉంటే మాత్రమే బైనరీ సెర్చ్ వాడాలి, లేదంటే లీనియర్ సెర్చ్ కి వెళ్ళిపోవాల్సిందే.

Q2: చాలా పెద్ద అర్రే లో (Integer Overflow) ఒక బగ్ వస్తుందట కదా?

చాలా పెద్ద ప్రాజెక్ట్స్ లో (ఉదా: గూగుల్ లో) అర్రే సైజు బిలియన్స్ లో ఉంటే, low + high యాడ్ చేసినప్పుడు ఆ వాల్యూ కంపైలర్ int లిమిట్ దాటేసి మైనస్ వాల్యూ వస్తుంది (దీన్నే Integer Overflow బగ్ అంటారు). అందుకే ప్రొఫెషనల్స్ mid = low + (high - low) / 2; అని రాస్తారు. ఇంటర్వ్యూలో ఇది చెబితే మీకు కచ్చితంగా జాబ్ వస్తుంది!

Q3: Linked List మీద Binary Search వాడొచ్చా?

వాడలేము! బైనరీ సెర్చ్ కి ఫస్ట్ సగానికి (Middle index) దూకాలి కదా. లింక్డ్ లిస్ట్ లో డైరెక్ట్ గా మధ్యలోకి జంప్ చేయలేం (O(1) యాక్సెస్ ఉండదు). మొదటి నుండి నడుచుకుంటూ వెళ్ళాలి. కాబట్టి ఆ జంప్ చేయడానికి పట్టే టైమ్ వేస్ట్ అయిపోయి, అది లీనియర్ సెర్చ్ కన్నా స్లో అయిపోతుంది.
