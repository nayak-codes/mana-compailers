switch-case స్టేట్‌మెంట్ & మెనూ డ్రివెన్ ప్రోగ్రామింగ్

ఒక పెద్ద బహుళ అంతస్తుల భవనంలో (Skyscraper) ఉన్న ఆధునిక ఎలివేటర్‌ను ఊహించుకోండి. ఆ భవనంలో 50 అంతస్తులు ఉన్నాయి. మీరు గ్రౌండ్ ఫ్లోర్ నుండి 45వ అంతస్తుకు వెళ్ళాలనుకుంటున్నారు. లిఫ్ట్ ప్రతి ఒక్క అంతస్తు వద్ద ఆగి (1వ ఫ్లోరా? కాదు, 2వ ఫ్లోరా? కాదు, 3వ ఫ్లోరా? కాదు...) చెక్ చేసుకుంటూ వెళ్తే — 45వ అంతస్తుకు చేరుకోవడానికి అరగంట సమయం పడుతుంది కదా?

కానీ నిజమైన ఎలివేటర్ అలా చేయదు! మీరు ప్యానెల్ పై '45' నొక్కగానే — లిఫ్ట్ నేరుగా మధ్యలోని 44 అంతస్తులను గాల్లో దాటేసి, క్షణాల్లో 45వ అంతస్తు వద్దకే నేరుగా దూసుకుపోతుంది! కంప్యూటర్ ప్రోగ్రామింగ్‌లో కూడా సరిగ్గా ఇదే వ్యత్యాసం ఉంటుంది. చాప్టర్ 05 లో మనం నేర్చుకున్న else-if లాడర్ మొదటి అంతస్తు నుండి వరుసగా ప్రతి కండిషన్‌ను తనిఖీ చేసుకుంటూ వెళ్లే నెమ్మదైన మెట్ల లాంటిది (O(n) time complexity). కానీ C లోని switch-case స్టేట్‌మెంట్ నేరుగా కావలసిన కేస్ వద్దకే దూకే ఎక్స్‌ప్రెస్ లిఫ్ట్ లాంటిది!

ఈ ఆరవ అధ్యాయంలో, కంపైలర్ తెరవెనుక నిర్మించే O(1) జంప్ టేబుల్స్ (Jump Tables), అసెంబ్లీ స్థాయి బ్రాంచింగ్ సూత్రాలు, break యొక్క అంతర్గత ప్రాముఖ్యత, ఫాల్-త్రూ (Fall-through) టెక్నిక్ మరియు పూర్తి స్థాయి మెనూ-డ్రివెన్ సైంటిఫిక్ క్యాలిక్యులేటర్ ప్రాజెక్ట్‌ను లోతుగా నేర్చుకుందాం!

1ఈ Chapter లో మీరు నేర్చుకునే అంశాలు
  • switch స్టేట్‌మెంట్ ప్రాథమిక భావన: మల్టీ-వే సెలెక్షన్ మరియు కస్టమర్ కేర్ IVRS మెనూ ఎనాలజీ.
  • switch-case సింటాక్స్ & అనాటమీ: switch, case, break, default కీవర్డ్స్.
  • CPU లెవల్ Jump Tables: else-if కంటే switch ఎందుకు 10 రెట్లు వేగవంతమైనది? అసెంబ్లీ లెవల్ విశ్లేషణ.
  • break స్టేట్‌మెంట్ పాత్ర: కంట్రోల్ ఫ్లోను వెంటనే switch నుండి బయటకు పంపే విధానం.
  • ఫాల్-త్రూ (Fall-Through) మెకానిక్స్: బ్రేక్ లేకపోతే ఏం జరుగుతుంది? దీనిని తెలివిగా ఎలా వాడాలి?
  • default కేస్ ప్రాధాన్యత: యూజర్ తప్పుడు ఆప్షన్ ఇచ్చినప్పుడు ఫాల్‌బ్యాక్ సేఫ్టీ గార్డ్.
  • C లో switch కఠిన నియమాలు: ఫ్లోట్స్ (float) మరియు స్ట్రింగ్స్ ఎందుకు పనిచేయవు?
  • మెనూ డ్రివెన్ ప్రోగ్రామింగ్ (Menu-Driven Architecture): ప్రాక్టికల్ కన్సోల్ అప్లికేషన్లు.
  • రియల్ వరల్డ్ ప్రాజెక్ట్: పూర్తి స్థాయి అరిథ్‌మెటిక్ క్యాలిక్యులేటర్ నిర్మాణం.
  • నెస్టెడ్ switch స్టేట్‌మెంట్స్: మెనూ లోపల సబ్-మెనూలను ఎలా హ్యాండిల్ చేయాలి?
  • బిగినర్స్ చేసే టాప్ 5 తప్పులు: డూప్లికేట్ కేస్‌లు, కేస్ లోపల వేరియబుల్ డిక్లరేషన్ ట్రాప్.
  • ఇంటరాక్టివ్ క్విజ్: 5 లోతైన ప్రాక్టికల్ ప్రశ్నలు & విశ్లేషణ.
2switch స్టేట్‌మెంట్ ప్రాథమిక భావన & IVRS ఎనాలజీ

మనం కస్టమర్ కేర్‌కు ఫోన్ చేసినప్పుడు కంప్యూటర్ స్వరం వినిపిస్తుంది: "తెలుగు కోసం 1 నొక్కండి, ఇంగ్లీష్ కోసం 2 నొక్కండి, మా ప్రతినిధితో మాట్లాడటానికి 9 నొక్కండి". మీరు '1' ప్రెస్ చేయగానే అది నేరుగా తెలుగు విభాగానికి కనెక్ట్ అవుతుంది. దీనినే మల్టీ-వే సెలెక్షన్ (Multi-Way Selection) అంటారు.

ఒకే వేరియబుల్‌ను అనేక స్థిర విలువలతో (Constants) పోల్చవలసి వచ్చినప్పుడు, పొడవైన else-if లాడర్ రాయడం కోడ్‌ను గజిబిజిగా చేస్తుంది. అటువంటి సందర్భాలలో switch-case కోడ్‌ను అత్యంత శుభ్రంగా, చదవడానికి సులభంగా మరియు వేగవంతంగా మారుస్తుంది.

switch స్టేట్‌మెంట్ ఎప్పుడు వాడాలి?

  • ఒకే పూర్ణాంకం లేదా క్యారెక్టర్ వేరియబుల్ వద్ద బహుళ నిర్దిష్ట విలువలు తనిఖీ చేయాల్సి వచ్చినప్పుడు.
  • కన్సోల్ అప్లికేషన్లలో యూజర్ మెనూ ఎంపికలు (1. Add, 2. Edit, 3. Delete, 4. Exit) హ్యాండిల్ చేయడానికి.
  • స్టేట్ మెషీన్లు (Finite State Machines - FSM), గేమింగ్ మూవ్‌మెంట్స్ (W, A, S, D కీలు) అమలు చేయడానికి.
3switch-case సింటాక్స్ & అనాటమీ

C లో switch-case యొక్క ప్రామాణిక సింటాక్స్ ఇది:

switch (ఎక్స్‌ప్రెషన్) {
    case స్థిర_విలువ_1:
        // కోడ్ బ్లాక్ 1
        break;
    case స్థిర_విలువ_2:
        // కోడ్ బ్లాక్ 2
        break;
    default:
        // ఏ కేస్ మ్యాచ్ కాకపోతే రన్ అయ్యే కోడ్
}
C — Basic switch-case Demo
▶ Run in Online C Compiler 
#include <stdio.h>

int main(void) {
    int dayNumber = 3;

    switch (dayNumber) {
        case 1:
            printf("సోమవారం (Monday) — కొత్త వారం ప్రారంభం!\n");
            break;
        case 2:
            printf("మంగళవారం (Tuesday)\n");
            break;
        case 3:
            printf("బుధవారం (Wednesday) — వారం మధ్య రోజు!\n");
            break;
        case 4:
            printf("గురువారం (Thursday)\n");
            break;
        case 5:
            printf("శుక్రవారం (Friday) — వీకెండ్ మొదలవుతోంది!\n");
            break;
        case 6:
            printf("శనివారం (Saturday) — సెలవు దినం!\n");
            break;
        case 7:
            printf("ఆదివారం (Sunday) — ఫ్యామిలీ టైమ్!\n");
            break;
        default:
            printf("❌ తప్పుడు రోజు నంబర్! దయచేసి 1 నుండి 7 మధ్య ఇవ్వండి.\n");
    }

    return 0;
}
4switch vs else-if: CPU Jump Tables & O(1) వేగం

చాలామంది ప్రోగ్రామర్లు "switch చేసే పనిని else-if కూడా చేస్తుంది కదా, అసలు switch ఎందుకు వాడాలి?" అని అడుగుతుంటారు. దీనికి సమాధానం CPU ఆర్కిటెక్చర్ మరియు ఎగ్జిక్యూషన్ వేగం!

ఫీచర్ / అంశం else-if లాడర్ switch-case స్టేట్‌మెంట్
ఎగ్జిక్యూషన్ విధానం లీనియర్ చెకింగ్ (ఒక్కొక్కటిగా తనిఖీ చేసుకుంటూ వెళ్తుంది). జంప్ టేబుల్ (Jump Table / Branch Table) ద్వారా నేరుగా సరైన అడ్రస్‌కు జంప్ అవుతుంది!
టైమ్ కాంప్లెక్సిటీ O(n) — n వ కేస్ కోసం n సార్లు కంపారిజన్ చేయాలి. O(1) — 4 కేస్‌లు ఉన్నా లేదా 1000 కేస్‌లు ఉన్నా ఒకే ఒక్క మైక్రో సెకనులో జంప్ అవుతుంది!
ఎక్స్‌ప్రెషన్ రకాలు సంక్లిష్టమైన కండిషన్లు (x > 10 && y < 5, ఫ్లోట్స్). కేవలం ఇంటిజర్స్ మరియు క్యారెక్టర్ కాన్‌స్టాంట్స్ మాత్రమే.
రీడబిలిటీ (క్లీన్ కోడ్) ఎక్కువ కండిషన్లు ఉంటే కోడ్ గజిబిజిగా మారుతుంది. అత్యంత స్పష్టమైన మెనూ రూపంలో అమర్చబడి ఉంటుంది.
🚀 కంపైలర్ మ్యాజిక్: మీరు 4 కంటే ఎక్కువ వరుస సంఖ్యలతో కేస్‌లు రాసినప్పుడు (ఉదా: 1, 2, 3, 4, 5...) — GCC కంపైలర్ అసెంబ్లీలో ఒక మెమరీ అర్రేని (Jump Table) సృష్టించి, ఇన్-డైరెక్ట్ జంప్ ఇన్‌స్ట్రక్షన్ jmp *table[x] ద్వారా క్షణాల్లో కావలసిన కేస్‌కు దూకుతుంది! దీనివల్ల ప్రతి కేస్‌ను చెక్ చేసుకునే సమయం పూర్తిగా ఆదా అవుతుంది.
5break స్టేట్‌మెంట్ యొక్క కీలక ప్రాముఖ్యత

break అనేది C లోని ఒక జంప్ కీవర్డ్. ఒక కేస్ కోడ్ ముగిసిన వెంటనే — కంట్రోల్ మిగిలిన కేస్‌లలోకి ప్రవహించకుండా, వెంటనే మొత్తం switch { ... } బ్లాక్ నుండి బయటకు విసిరివేయడానికి break తప్పనిసరి!

ఒకవేళ మీరు పొరపాటున break రాయడం మర్చిపోతే — కంపైలర్ తర్వాతి కేస్‌లను మ్యాచ్ అయ్యాయో లేదో కూడా చూడకుండా అన్నింటినీ ఒకదాని తర్వాత ఒకటి గుడ్డిగా ఎగ్జిక్యూట్ చేసుకుంటూ వెళ్ళిపోతుంది! దీనినే Fall-Through అంటారు.

6ఫాల్-త్రూ (Fall-Through) మెకానిక్స్ & వోవెల్ చెకర్

ఫాల్-త్రూ అనేది సాధారణంగా ఒక బగ్ అయినప్పటికీ — సీనియర్ ప్రోగ్రామర్లు దీనిని ఒక శక్తివంతమైన ఫీచర్‌గా మార్చుకుంటారు! అనేక వేర్వేరు కేస్‌లకు ఒకే కోడ్ ఎగ్జిక్యూట్ కావాల్సి వచ్చినప్పుడు మధ్యలో break రాయకుండా వదిలేస్తారు:

C — Intentional Fall-Through (Vowel Checker)
▶ Run in Online C Compiler 
#include <stdio.h>

int main(void) {
    char ch = 'E';

    printf("అక్షరం: %c\n", ch);

    // a, e, i, o, u లన్నింటికీ ఒకే లాజిక్ రన్ చేయడానికి ఫాల్-త్రూ టెక్నిక్!
    switch (ch) {
        case 'a':
        case 'A':
        case 'e':
        case 'E':
        case 'i':
        case 'I':
        case 'o':
        case 'O':
        case 'u':
        case 'U':
            printf("✅ ఇది అచ్చు (Vowel)!\n");
            break; // ఇక్కడ మాత్రమే బ్రేక్ ఉంది!
        default:
            printf("🔤 ఇది హల్లు (Consonant) లేదా ప్రత్యేక చిహ్నం.\n");
    }

    return 0;
}

పై కోడ్‌లో 10 వేర్వేరు if (ch == 'a' || ch == 'A' ...) కండిషన్లు రాయకుండా, కేవలం కేస్‌లను వరుసగా పేర్చి ఒకే ఒక break తో పని పూర్తి చేశాం!

7default కేస్ పాత్ర: అన్నీ ఫెయిల్ అయినప్పుడు ఫాల్‌బ్యాక్

default అనేది if-else లాడర్‌లోని చివరి else లాంటిది. యూజర్ ఇచ్చిన విలువ పైన పేర్కొన్న ఏ ఒక్క కేస్‌తోనూ మ్యాచ్ కానప్పుడు ఈ default బ్లాక్ ఎగ్జిక్యూట్ అవుతుంది.

  • default రాయడం ఆప్షనల్ (తప్పనిసరి కాదు), కానీ ప్రొఫెషనల్ కోడింగ్‌లో ఊహించని యూజర్ తప్పులను కనిపెట్టడానికి ఇది ఖచ్చితంగా ఉండాలి.
  • సాధారణంగా default ను switch చివరలో ఉంచుతారు; అయితే దీనిని switch లోపల ఎక్కడైనా ఉంచవచ్చు.
  • చివరలో ఉన్న default కు break రాయకపోయినా నడుస్తుంది, కానీ రాయడం మంచి ప్రోగ్రామింగ్ అలవాటు.
8C లో switch యొక్క కఠిన పరిమితులు & నియమాలు

C లాంగ్వేజ్‌లో switch స్టేట్‌మెంట్‌కు కొన్ని కఠినమైన ఆర్కిటెక్చరల్ పరిమితులు ఉన్నాయి. వీటిని ఉల్లంఘిస్తే కంపైలర్ కోడ్‌ను అస్సలు అంగీకరించదు:

1. కేవలం ఇంటిజర్ & క్యారెక్టర్లు మాత్రమే అనుమతి:

switch (ఎక్స్‌ప్రెషన్) తప్పనిసరిగా int లేదా char (లేదా enum) మాత్రమే అయి ఉండాలి. ఫ్లోటింగ్ పాయింట్ సంఖ్యలు (float, double) పూర్తిగా నిషేధం! ఎందుకంటే బైనరీ ఫ్లోటింగ్ పాయింట్‌లో ఖచ్చితమైన సమానత్వాన్ని (Exact Equality) లెక్కించడం అసాధ్యం.

2. కేస్ విలువలు కాన్‌స్టాంట్స్ మాత్రమే అయి ఉండాలి:

case x: అని వేరియబుల్స్ రాయకూడదు! case 5: లేదా case 'A': లాంటి స్థిర విలువలు మాత్రమే ఉండాలి. అలాగే రిలేషనల్ కండిషన్లు case > 10: లాంటివి చెల్లవు!

3. డూప్లికేట్ కేస్‌లు నిషేధం:

ఒకే switch లో రెండుసార్లు case 1: అని రాయకూడదు. కంపైలర్ error: duplicate case value అని ఎర్రర్ ఇస్తుంది.

9మెనూ-డ్రివెన్ ప్రోగ్రామింగ్: సైంటిఫిక్ క్యాలిక్యులేటర్ ప్రాజెక్ట్

యూజర్ ఒక ఆపరేషన్‌ను ఎంచుకోవడానికి మరియు దాని ప్రకారం గణిత చర్యలు జరపడానికి switch స్టేట్‌మెంట్‌తో ఒక పూర్తి స్థాయి మెనూ-డ్రివెన్ క్యాలిక్యులేటర్ ప్రోగ్రామ్‌ను నిర్మిద్దాం:

C — Menu-Driven Calculator Project
▶ Run in Online C Compiler 
#include <stdio.h>

int main(void) {
    char operator;
    double num1, num2, result;

    printf("=== మన సింపుల్ క్యాలిక్యులేటర్ ===\n");
    printf("ఆపరేటర్‌ను ఎంచుకోండి (+, -, *, /): ");
    scanf(" %c", &operator); // బఫర్ సమస్య రాకుండా స్పేస్ ఉంచాం!

    printf("రెండు సంఖ్యలను నమోదు చేయండి: ");
    scanf("%lf %lf", &num1, &num2);

    switch (operator) {
        case '+':
            result = num1 + num2;
            printf("ఫలితం: %.2lf + %.2lf = %.2lf\n", num1, num2, result);
            break;

        case '-':
            result = num1 - num2;
            printf("ఫలితం: %.2lf - %.2lf = %.2lf\n", num1, num2, result);
            break;

        case '*':
            result = num1 * num2;
            printf("ఫలితం: %.2lf * %.2lf = %.2lf\n", num1, num2, result);
            break;

        case '/':
            // సున్నాతో భాగాహారం (Division by Zero) నిరోధించడం
            if (num2 == 0) {
                printf("❌ ఎర్రర్: గణితంలో సున్నా (0) తో భాగాహారం అసాధ్యం!\n");
            } else {
                result = num1 / num2;
                printf("ఫలితం: %.2lf / %.2lf = %.2lf\n", num1, num2, result);
            }
            break;

        default:
            printf("❌ చెల్లని ఆపరేటర్! దయచేసి +, -, *, / లలో ఒకటి ఎంచుకోండి.\n");
    }

    return 0;
}
10నెస్టెడ్ switch స్టేట్‌మెంట్స్ (Nested switch)

ఒక case బ్లాక్ లోపల మరొక switch స్టేట్‌మెంట్‌ను రాయడాన్ని నెస్టెడ్ switch అంటారు. ఉదాహరణకు ఒక కాలేజీలో విభాగం (Department: CSE, ECE) ఎంచుకున్న తర్వాత — ఆ విభాగంలోని ఇయర్ (1st Year, 2nd Year) ఎంచుకోవడానికి ఇది ఉపయోగపడుతుంది:

C — Nested switch Example
▶ Run in Online C Compiler 
#include <stdio.h>

int main(void) {
    int deptCode = 1; // 1 = CSE, 2 = ECE
    int year = 2;

    switch (deptCode) {
        case 1:
            printf("విభాగం: కంప్యూటర్ సైన్స్ (CSE)\n");
            // CSE లోపల ఇయర్ సబ్-మెనూ
            switch (year) {
                case 1:
                    printf("సబ్జెక్ట్: C ప్రోగ్రామింగ్ & ఇంజనీరింగ్ ఫిజిక్స్\n");
                    break;
                case 2:
                    printf("సబ్జెక్ట్: డేటా స్ట్రక్చర్స్ & డిజిటల్ లాజిక్\n");
                    break;
                default:
                    printf("ఇతర సంవత్సరాలు.\n");
            }
            break;

        case 2:
            printf("విభాగం: ఎలక్ట్రానిక్స్ (ECE)\n");
            break;

        default:
            printf("తెలియని విభాగం!\n");
    }

    return 0;
}
11బిగినర్స్ చేసే టాప్ 5 switch తప్పులు
❌ 1. కేస్ లోపల నేరుగా వేరియబుల్స్ డిక్లేర్ చేయడం (C Scope Error): 
case 1:
    int x = 10; // C లో కంపైలర్ ఎర్రర్ వస్తుంది!
    break;
ఒక కేస్ లోపల కొత్త వేరియబుల్ డిక్లేర్ చేయాలంటే ఆ కేస్‌కు ప్రత్యేక కర్లీ బ్రేసెస్ case 1: { int x = 10; ... break; } ఇవ్వాలి. లేకపోతే కంపైలర్ జంప్ లేబుల్ స్కోప్ ఎర్రర్ ఇస్తుంది.
❌ 2. ఫ్లోటింగ్ పాయింట్ వేరియబుల్స్‌ను switch లో పెట్టడం: 
float f = 3.14f;
switch (f) { ... } // తప్పు! error: switch quantity not an integer
C లో switch కేవలం పూర్ణాంకాలు (int, char) మాత్రమే అంగీకరిస్తుంది. దశాంశ సంఖ్యల కోసం if-else మాత్రమే వాడాలి.
❌ 3. కేస్ చివర కోలన్ (:) బదులు సెమికోలన్ (;) పెట్టడం: 
case 1; // తప్పు! ఇక్కడ కోలన్ (:) మాత్రమే ఉండాలి!
    printf("వన్");
కేస్ లేబుల్స్ ఎల్లప్పుడూ కోలన్ (:) తో మాత్రమే ముగియాలి. సెమికోలన్ పెడితే సింటాక్స్ ఎర్రర్ వస్తుంది.
12ఇంటరాక్టివ్ నాలెడ్జ్ చెక్ (Self-Assessment Quiz)

ఈ ఆరవ అధ్యాయంలో మీరు నేర్చుకున్న switch-case భావనలను పరీక్షించుకోవడానికి క్రింది ప్రశ్నలపై క్లిక్ చేయండి:

❓ ప్రశ్న 1: switch స్టేట్‌మెంట్‌లో ఎక్స్‌ప్రెషన్ రకంగా float లేదా double ని ఎందుకు వాడకూడదు?
సమాధానం: ఫ్లోటింగ్ పాయింట్ సంఖ్యలలో బైనరీ రౌండింగ్ ప్రెసిషన్ సమస్యల వల్ల ఖచ్చితమైన సమానత్వాన్ని (Exact Match) పోల్చడం సాధ్యం కాదు. అంతేకాకుండా కంపైలర్ వీటిపై O(1) Jump Tables నిర్మించలేదు.
❓ ప్రశ్న 2: ఒక కేస్ బ్లాక్ చివర break రాయకపోతే జరిగే బిహేవియర్ పేరు ఏమిటి?
సమాధానం: ఫాల్-త్రూ (Fall-Through). కంపైలర్ తర్వాతి కేస్‌లు మ్యాచ్ అయ్యాయో లేదో చూడకుండా వరుసగా ఎగ్జిక్యూట్ చేసుకుంటూ వెళ్ళిపోతుంది.
❓ ప్రశ్న 3: switch లోని default కేస్ ఎప్పుడు ఎగ్జిక్యూట్ అవుతుంది?
సమాధానం: పైన పేర్కొన్న ఏ ఒక్క కేస్ విలువ కూడా మ్యాచ్ కానప్పుడు ఫాల్‌బ్యాక్ రక్షణగా default ఎగ్జిక్యూట్ అవుతుంది.
❓ ప్రశ్న 4: case x: అని వేరియబుల్‌ను కేస్ లేబుల్‌గా వాడవచ్చా?
సమాధానం: వాడకూడదు! కేస్ లేబుల్స్ తప్పనిసరిగా కంపైల్-టైమ్ స్థిర విలువలు (Constants, ఉదా: 1, 'A') మాత్రమే అయి ఉండాలి.
❓ ప్రశ్న 5: else-if లాడర్ తో పోలిస్తే switch స్టేట్‌మెంట్ ఎందుకు వేగవంతమైనది?
సమాధానం: else-if ప్రతి కండిషన్‌ను లీనియర్‌గా O(n) లో చెక్ చేస్తుంది. కానీ switch స్టేట్‌మెంట్ జంప్ టేబుల్స్ (Jump Tables) ద్వారా నేరుగా O(1) సమయంలో కావలసిన కేస్‌కు దూకుతుంది.
13మీరే స్వయంగా Try చేయండి & సారాంశం (Quick Summary)
🚀 సైంటిఫిక్ క్యాలిక్యులేటర్‌ను మన ఆన్‌లైన్ C కంపైలర్‌లో రన్ చేయండి!

పైన వివరించిన క్యాలిక్యులేటర్ ప్రాజెక్ట్ మరియు వోవెల్ చెకర్ ఫాల్-త్రూ కోడ్‌ను మన ఆన్‌లైన్ C కంపైలర్‌లో ఓపెన్ చేసి స్వయంగా రన్ చేయండి. కొత్త ఆపరేటర్లను (ఉదా: మాడ్యులో %) జోడించి మీ స్వంత మెనూ అప్లికేషన్‌ను రూపొందించండి!

📌 క్విక్ సారాంశం (Key Takeaways):

  • switch: ఒకే విలువ ఆధారంగా బహుళ మార్గాల్లోకి దూకే O(1) జంప్ టేబుల్ కాంపోనెంట్.
  • డేటా పరిమితి: కేవలం int మరియు char మాత్రమే చెల్లుతాయి; ఫ్లోట్స్ పూర్తిగా నిషేధం.
  • break: కంట్రోల్ తర్వాతి కేస్‌లలోకి జారిపోకుండా బయటకు పంపే తాళం చెవి.
  • Fall-Through: బ్రేక్ లేనప్పుడు కింద ఉన్న కేస్‌లు కూడా రన్ అయ్యే స్వభావం.
  • default: ఊహించని తప్పుడు ఇన్‌పుట్‌లను అడ్డుకునే సేఫ్టీ గార్డ్.
తర్వాతి అధ్యాయంలో (Chapter 07): కంప్యూటర్ చేత పనులను వేలసార్లు పదేపదే చేయించే లూప్స్ (for, while, do-while), ఎంట్రీ vs ఎగ్జిట్ కంట్రోల్ తేడాలు, మరియు ఇన్ఫినిట్ లూప్స్ నివారణ గురించి అత్యంత ఆసక్తికరంగా నేర్చుకుందాం!
