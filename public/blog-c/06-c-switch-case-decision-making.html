switch-case స్టేట్‌మెంట్ & మెనూ డ్రివెన్ ప్రోగ్రామింగ్

📌 Covered in this chapter: O(1) Jump Table ఆర్కిటెక్చర్ vs else-if · break ప్రాముఖ్యత · Fall-through మెకానిక్స్ · క్యాలిక్యులేటర్ ప్రాజెక్ట్
ఒక ప్రోగ్రామ్‌లో అనేక స్థిరమైన విలువలపై (Discrete integer choices) నిర్ణయం తీసుకోవాల్సి వచ్చినప్పుడు వరుసగా else-if లు రాయడం కోడ్‌ను సంక్లిష్టంగా చేస్తుంది. అటువంటి పరిస్థితుల్లో అత్యంత వేగవంతమైన, పరిశుభ్రమైన ప్రత్యామ్నాయం switch-case స్టేట్‌మెంట్. GCC కంపైలర్ దీనిని $O(1)$ జంప్ టేబుల్‌గా ఎలా మారుస్తుంది, break ప్రాముఖ్యత మరియు ఫాల్-త్రూ మెకానిక్స్‌ను ఈ అధ్యాయంలో నేర్చుకుందాం.
1switch-case అంతర్గత పనితీరు & Jump Table ఆర్కిటెక్చర్

else-if లాడర్‌లో ప్రతి కండిషన్‌ను వరుసగా పై నుండి క్రిందికి తనిఖీ చేస్తూ వెళ్లాలి ($O(N)$ లీనియర్ టైమ్). కానీ switch లో కేస్ విలువలు వరుసగా ఉన్నప్పుడు కంపైలర్ ఒక Jump Table (మెమరీ అడ్రస్‌ల అరే) ను రూపొందిస్తుంది. CPU నేరుగా సంబంధిత కేస్‌కు $O(1)$ స్థిర సమయంలో దూకుతుంది (Direct Branching).

🔒 C లో switch నిబంధనలు (Core Rules):
  • ఎక్స్‌ప్రెషన్ తప్పనిసరిగా పూర్ణాంకం (int, short, long) లేదా క్యారెక్టర్ (char) అయి ఉండాలి.
  • ఫ్లోటింగ్ పాయింట్ (float, double) సంఖ్యలు మరియు స్ట్రింగ్స్‌ను switch లో అనుమతించరు.
  • ప్రతి case లేబుల్ తప్పనిసరిగా ఒక కంపైల్-టైమ్ స్థిరాంకం (Constant Expression) అయి ఉండాలి; వేరియబుల్స్ ఉండకూడదు.
2break కీవర్డ్ & ఫాల్-త్రూ మెకానిక్స్ (Fall-Through Behavior)

switch లో ఒక కేస్ సరిపోలిన తర్వాత, మీరు అక్కడ break పెట్టకపోతే, C కంపైలర్ ఆగిపోదు! తర్వాతి కేస్‌ల షరతులు నిజమా కాదా అనేది పట్టించుకోకుండా వాటిలోని కోడ్‌ను కూడా వరుసగా ఎగ్జిక్యూట్ చేసుకుంటూ వెళ్ళిపోతుంది. దీనిని ఫాల్-త్రూ (Fall-Through) అంటారు.

C — Intentional Fall-through for Vowel Check ⚡ Try in C Compiler 
#include <stdio.h>

int main(void) {
    char ch = 'E';

    switch (ch) {
        case 'a':
        case 'A':
        case 'e':
        case 'E':
        case 'i':
        case 'I':
        case 'o':
        case 'O':
        case 'u':
        case 'U':
            printf("'%c' ఒక అచ్చు (Vowel)\n", ch);
            break;
        default:
            printf("'%c' ఒక హల్లు లేదా ప్రత్యేక చిహ్నం (Consonant)\n", ch);
            break;
    }
    return 0;
}

💡 పై ఉదాహరణలో మనం కావాలనే break పెట్టకుండా బహుళ కేస్‌లను కలిపి (Grouping) ఒకే బ్లాక్‌గా ఉపయోగించాం. దీనిని Intentional Fall-through అంటారు.

3మినీ ప్రాజెక్ట్: మెనూ-డ్రివెన్ అర్థమెటిక్ క్యాలిక్యులేటర్

రియల్-వరల్డ్ కన్సోల్ అప్లికేషన్లలో యూజర్ ఛాయిస్ ఆధారంగా ఆపరేషన్లు చేయడానికి switch అత్యంత ప్రాచుర్యం పొందింది:

C — Menu-Driven Calculator ⚡ Try in C Compiler 
#include <stdio.h>

int main(void) {
    char op;
    double a, b;

    printf("ఆపరేషన్ ఎంటర్ చేయండి (+, -, *, /): ");
    scanf(" %c", &op);

    printf("రెండు సంఖ్యలను నమోదు చేయండి: ");
    scanf("%lf %lf", &a, &b);

    switch (op) {
        case '+':
            printf("ఫలితం: %.2lf + %.2lf = %.2lf\n", a, b, a + b);
            break;
        case '-':
            printf("ఫలితం: %.2lf - %.2lf = %.2lf\n", a, b, a - b);
            break;
        case '*':
            printf("ఫలితం: %.2lf * %.2lf = %.2lf\n", a, b, a * b);
            break;
        case '/':
            if (b != 0) {
                printf("ఫలితం: %.2lf / %.2lf = %.2lf\n", a, b, a / b);
            } else {
                printf("ఎర్రర్: సున్నాతో భాగించడం అసాధ్యం! (Division by zero)\n");
            }
            break;
        default:
            printf("చెల్లని ఆపరేటర్: '%c'\n", op);
            break;
    }
    return 0;
}
4బిగినర్స్ చేసే ఘోరమైన తప్పులు (Beginner Pitfalls)
❌ 1. కేస్ బ్లాక్ లోపల నేరుగా వేరియబుల్స్ డిక్లేర్ చేయడం:
case 1: int x = 10; break; // Compile Error! Jump crosses initialization కేస్ లేబుల్ లోపల కొత్త వేరియబుల్ డిక్లేర్ చేయాలంటే ఆ కేస్‌ను ప్రత్యేక స్కోప్ కర్లీ బ్రేసెస్ case 1: { int x = 10; break; } లో ఉంచాలి.
❌ 2. డూప్లికేట్ కేస్ వాల్యూస్ ఇవ్వడం:
case 1: ... case 1: ... // Error: Duplicate case value ఒకే switch లో రెండు కేస్‌లకు సమానమైన విలువ ఉండకూడదు. కంపైలర్ వెంటనే డూప్లికేట్ ఎర్రర్ ఇస్తుంది.
5తరచుగా అడిగే ప్రశ్నలు (FAQ)

Q: default కేస్ ఎల్లప్పుడూ చివరనే ఉండాలా?

సింటాక్స్ పరంగా default కేస్‌ను మొదటి లేదా మధ్యలో కూడా పెట్టవచ్చు. కానీ దాన్ని చివరనే ఉంచడం గ్లోబల్ కోడింగ్ స్టాండర్డ్. ఒకవేళ మధ్యలో పెడితే దానికి కూడా break పెట్టడం మర్చిపోకూడదు.

Q: C లో switch కి స్ట్రింగ్స్ ("add", "exit") ఎందుకు పనిచేయవు?

C లాంగ్వేజ్ లో స్ట్రింగ్స్ ప్రిమిటివ్ టైప్స్ కావు; అవి కేవలం మెమరీ పాయింటర్లు (char*). రెండు స్ట్రింగ్స్ సమానమా కాదా అని చూడటానికి పాయింటర్ అడ్రస్‌లను కాకుండా అక్షరాలను పోల్చాలి (strcmp). జంప్ టేబుల్ కేవలం సంఖ్యల అడ్రస్‌లతోనే పనిచేస్తుంది కాబట్టి C switch లో స్ట్రింగ్స్ అనుమతించబడవు.
