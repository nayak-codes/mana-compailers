Hashing & Collision Handling (తెలుగులో)

⚡ C (C17 / C23 Standard) 🟢 Lesson 58 📂 Phase 19: Data Structures - 2 📅 2026 Comprehensive Master Edition
📌 Covered in this in-depth guide: Hash Function · Hash Table · Collisions · Chaining · Linear Probing

ఇంతవరకు మనం అర్రేలో (Array) వెతకాలంటే O(N) టైమ్ పడుతుందని, ట్రీ (BST) లో అయితే సగం టైమ్ O(log N) పడుతుందని చూసాం. కానీ వంద కోట్ల మంది యూజర్స్ ఉన్న సిస్టమ్ లో, ఒకడి పేరు కొట్టగానే వాడి అకౌంట్ వివరాలు కరెక్ట్ గా ఒకే సెకనులో (O(1) టైమ్ లో) ఎలా వస్తాయి? ఈ అద్భుతమైన మ్యాజిక్ చేసే టెక్నిక్ పేరే Hashing (హ్యాషింగ్). ఒక పెద్ద పేరుకి ఒక చిన్న నంబర్ (ఇండెక్స్) ని జనరేట్ చేసి, అక్కడే డేటాని దాచడం. మరి ఇద్దరికి ఒకే నంబర్ వస్తే ఏం చేస్తారు? దీన్నే Collision అంటారు. ఇవన్నీ ఎలా జరుగుతాయో యానిమేషన్ లాగా నేర్చుకుందాం.

1 హ్యాషింగ్ (Hashing) అంటే ఏంటి?

హ్యాషింగ్ లో రెండు మెయిన్ పార్ట్స్ ఉంటాయి: 1. Hash Table (హ్యాష్ టేబుల్): ఇది నార్మల్ అర్రే (Array). 2. Hash Function (హ్యాష్ ఫంక్షన్): ఇది ఒక మిక్సీ (Mixer) లాంటిది. మీరు ఏ పేరు (String/Data) ఇచ్చినా, అది క్యాలిక్యులేట్ చేసి ఒక నంబర్ (Index) ని ఇస్తుంది.

🗄️ రియల్ లైఫ్ స్టోరీ: హోటల్ రూమ్ లాకర్స్

ఒక ఫేమస్ క్లబ్ లో వంద లాకర్స్ (Hash Table) ఉన్నాయి. కస్టమర్ వచ్చి తన వస్తువులు ఇవ్వగానే, రిసెప్షనిస్ట్ లాకర్ నంబర్ వెతకడు. వాడి పేరులో ఉన్న అక్షరాలని తీసుకుని ఒక లెక్క వేస్తాడు (ఉదా: A=1, B=2 కాబట్టి 'CAB' అంటే 3+1+2 = 6). డైరెక్ట్ గా వెళ్లి 6వ లాకర్ లో వస్తువులు పెట్టేస్తాడు (ఇదే Hash Function).

రేపు వాడు వచ్చి "నా పేరు CAB" అనగానే, మళ్ళీ లెక్కేసి డైరెక్ట్ గా 6వ లాకర్ తీసి ఇస్తాడు! అంటే లక్ష మంది ఉన్నా సరే, వెతకడానికి పట్టే టైమ్ O(1) (కేవలం ఒక్క సెకను) మాత్రమే.

2 గొడవలు (Collisions) ఎందుకు వస్తాయి?

మన ఫంక్షన్ లో 'CAB' కి 6 వచ్చింది. రేపు 'BCA' అనేవాడు వచ్చాడు. దానికి లెక్కేస్తే (2+3+1 = 6) వాడికీ అదే లాకర్ నంబర్ వచ్చింది! ఆల్రెడీ అందులో వేరే వాడి వస్తువులు ఉన్నాయి. ఇద్దరికి ఒకే లాకర్ ఎలా ఇస్తాం? దీన్నే Collision (కలయిక/గొడవ) అంటారు.

  • సొల్యూషన్ 1 (Linear Probing): 6 ఫుల్ అయితే, పక్కనే ఉన్న 7వ లాకర్ ఖాళీ ఉందేమో చూసి అక్కడ పెట్టడం (ఓపెన్ అడ్రెస్సింగ్).
  • సొల్యూషన్ 2 (Chaining): 6వ లాకర్ లోనే ఒక సంచి తగిలించి, వాడి వస్తువులు, వీడి వస్తువులు రెండూ ఒకదాని కింద ఒకటి (Linked List లాగా) అందులోనే పెట్టడం!
3 ఒకే ఒక సింపుల్ కోడ్ (Hash Table with Chaining)

కింద కోడ్ లో మనం 10 సైజు ఉన్న అర్రే ని హ్యాష్ టేబుల్ గా తీసుకుని, మోడ్యులో (%) ఆపరేటర్ వాడి హ్యాష్ కనుక్కుని, కలయిక (Collision) వచ్చినప్పుడు లింక్డ్ లిస్ట్ వాడి ఎలా చైనింగ్ చేసామో చూడండి.

C — Hashing (Chaining) ▶ Run Code 
#include <stdio.h>
#include <stdlib.h>

#define TABLE_SIZE 10

// చైనింగ్ కోసం ఒక లింక్డ్ లిస్ట్ నోడ్
struct Node {
    int key;
    struct Node* next;
};

// మన హ్యాష్ టేబుల్ (నోడ్ పాయింటర్స్ ఉన్న అర్రే)
struct Node* hashTable[TABLE_SIZE];

// 1. అతి సింపుల్ హ్యాష్ ఫంక్షన్ (మిక్సీ)
int hashFunction(int key) {
    return key % TABLE_SIZE; // 10 తో డివైడ్ చేస్తే 0 నుండి 9 వరకు ఇండెక్స్ వస్తుంది!
}

// 2. డేటాని టేబుల్ లో దూర్చడం (Insert)
void insert(int key) {
    int index = hashFunction(key); // ఇండెక్స్ కనుక్కోవడం
    
    // కొత్త బాక్స్ క్రియేట్ చేద్దాం
    struct Node* newNode = (struct Node*)malloc(sizeof(struct Node));
    newNode->key = key;
    
    // ఆ ఇండెక్స్ లో ఆల్రెడీ ఎవరైనా ఉన్నా (Collision), దాన్ని ముందుకి నెట్టి ఇది హెడ్ అవుతుంది (Chaining)
    newNode->next = hashTable[index];
    hashTable[index] = newNode;
    
    printf("Inserted %d at index %d\n", key, index);
}

// 3. హ్యాష్ టేబుల్ ని ప్రింట్ చేయడం
void displayTable() {
    printf("\n--- Current Hash Table ---\n");
    for (int i = 0; i < TABLE_SIZE; i++) {
        printf("[%d]: ", i);
        struct Node* temp = hashTable[i];
        
        if (temp == NULL) {
            printf("Empty\n");
        } else {
            // ఆ లాకర్ లో ఎంతమంది ఉన్నారో లింక్డ్ లిస్ట్ లూప్
            while (temp != NULL) {
                printf("%d -> ", temp->key);
                temp = temp->next;
            }
            printf("NULL\n");
        }
    }
}

int main() {
    // టేబుల్ మొత్తం ఖాళీ (NULL) చేద్దాం
    for (int i = 0; i < TABLE_SIZE; i++) {
        hashTable[i] = NULL;
    }
    
    // డేటా యాడ్ చేద్దాం
    insert(15); // 15 % 10 = ఇండెక్స్ 5
    insert(25); // 25 % 10 = ఇండెక్స్ 5 (కొలిజన్ వస్తుంది, ఇద్దరూ అక్కడే ఉంటారు!)
    insert(7);  // 7 % 10  = ఇండెక్స్ 7
    insert(42); // 42 % 10 = ఇండెక్స్ 2
    
    // టేబుల్ ఎలా ఉందో చూద్దాం
    displayTable();
    
    return 0;
}
4 కోడ్ లో ఏం జరుగుతోంది? (Step-by-Step)
  • hashFunction(key): మనం 15 పంపితే (15 % 10 = 5) వస్తుంది. 25 పంపినా (25 % 10 = 5) వస్తుంది. ఇక్కడ ఇండెక్స్ 5 దగ్గర కొలిజన్ (Collision) వచ్చింది.
  • newNode->next = hashTable[index];: ఇది లింక్డ్ లిస్ట్ లో (Insert at Head) లాజిక్. 25 వచ్చినప్పుడు, 5వ లాకర్ లో ఆల్రెడీ ఉన్న 15 ని next తో కనెక్ట్ చేసుకుని, 25 ముందుకు వస్తుంది (25 -> 15 -> NULL). దీన్నే Chaining (చైనింగ్) అంటారు.
5 ఇంటర్వ్యూలలో అడిగే కామన్ ప్రశ్నలు (FAQ)

Q1: Linear Probing కన్నా Chaining ఎందుకు బెస్ట్?

Linear Probing లో ఇండెక్స్ ఫుల్ అయితే పక్క ఇండెక్స్ లో దూరుస్తాం కదా. ఒకవేళ పక్కది కూడా ఫుల్ అయితే ఆ పక్కకి... ఇలా వెళ్తూ ఉంటే మొత్తం లాకర్లు ఫుల్ అయ్యి Clustering అనే సమస్య వస్తుంది. వెతకడానికి మళ్ళీ అర్రే లాగా O(N) టైమ్ పడుతుంది. కానీ Chaining లో లిస్ట్ బయటికి పెరుగుతుంది కాబట్టి పక్క లాకర్లు ఖాళీగానే ఉంటాయి.

Q2: ఒక పర్ఫెక్ట్ Hash Function కి రూల్స్ ఏంటి?

1. అది క్యాలిక్యులేట్ చేయడానికి చాలా ఫాస్ట్ గా ఉండాలి (Cryptographic hash లాగా స్లో ఉండకూడదు).
2. వచ్చిన ఇండెక్స్ లు అన్ని లాకర్లకి సమానంగా పంచాలి (Uniform distribution). ఒకటే లాకర్ లోకి అందరినీ పంపకూడదు. Prime numbers (ప్రైమ్ నంబర్స్) తో మోడ్యులో చేస్తే బెస్ట్ రిజల్ట్స్ వస్తాయి.

Q3: పాస్వర్డ్ హ్యాషింగ్ (SHA-256) కి, ఈ డేటా స్ట్రక్చర్ హ్యాషింగ్ కి తేడా ఏంటి?

చాలా డిఫరెన్స్ ఉంది! మనం వాడేది డేటా ని ఫాస్ట్ గా వెతకడానికి వాడే "Data Structure Hashing" (O(1) స్పీడ్ కోసం). కానీ పాస్వర్డ్స్ కి వాడేది "Cryptographic Hashing". అందులో స్పీడ్ కాదు, సెక్యూరిటీ ముఖ్యం. రివర్స్ చేయడానికి వీల్లేకుండా దాన్ని డిజైన్ చేస్తారు (One-way hash).
