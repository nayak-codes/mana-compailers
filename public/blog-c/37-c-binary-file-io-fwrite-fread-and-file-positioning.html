Binary File I/O & fseek() (తెలుగులో)

⚡ C (C17 / C23 Standard) 🟢 Lesson 37 📂 Phase 14: File I/O & Preprocessor 📅 2026 Comprehensive Master Edition
📌 Covered in this in-depth guide: Binary Files (wb, rb) · fwrite() & fread() · Struct Serialization · fseek() & ftell() · Fast I/O

ఇంతకుముందు మనం రాసిన ఫైల్స్ అన్నీ టెక్స్ట్ (Text) ఫైల్స్. అంటే వాటిని నోట్ ప్యాడ్ (Notepad) తో ఓపెన్ చేస్తే ఇంగ్లీష్ అక్షరాలు కళ్ళకు కనిపిస్తాయి. కానీ ఒక MP3 సాంగ్ ని గాని, ఒక .JPG ఇమేజ్ ని గాని నోట్ ప్యాడ్ లో ఓపెన్ చేస్తే విచిత్రమైన గార్బేజ్ సింబల్స్ కనిపిస్తాయి కదా! అవే Binary Files (బైనరీ ఫైల్స్). రియల్ వరల్డ్ యాప్స్ లో ఒక గేమ్ సేవ్ ఫైల్ ని ఎవరూ చదవకుండా లాక్ చేయాలన్నా, లేదా లక్షల మంది స్టూడెంట్స్ డేటాని మిల్లీ-సెకన్లలో హార్డ్ డిస్క్ లోకి సేవ్ చేయాలన్నా ఈ బైనరీ ఫైల్స్ (0s and 1s) వాడాల్సిందే. ఈరోజు fwrite(), fread() మరియు ఫైల్ లో వీడియో ప్లేయర్ లాగా జంప్ చేసే fseek() మ్యాజిక్ ఏంటో డీప్ గా చూద్దాం.

1 Text మోడ్ vs Binary మోడ్ (అసలు తేడా ఏంటి?)

మీరు టెక్స్ట్ మోడ్ లో ("w") ఎంటర్ (Newline - \n) రాస్తే, విండోస్ ఆపరేటింగ్ సిస్టమ్ దాన్ని బ్యాక్ గ్రౌండ్ లో \r\n (క్యారేజ్ రిటర్న్ + న్యూలైన్) కింద మారుస్తుంది. ఆ మార్పుల వల్ల ఫైల్ సైజు పెరగడం, డేటా చదవడం స్లో అవ్వడం జరుగుతుంది.

కానీ బైనరీ మోడ్ లో ("wb" - Write Binary) మీరు RAM లో ఉన్న డేటాని (0s & 1s) ఎలా ఉందో అలాగ (Raw Copy) విసిరేస్తారు. మధ్యలో OS ఎలాంటి ఫార్మాటింగ్ చేయదు! కాబట్టి ఇది సూపర్ ఫాస్ట్ గా ఉంటుంది. పైగా డేటా సెక్యూరిటీ కూడా ఉంటుంది.

🚀 రియల్ లైఫ్ స్టోరీ: ఒక ట్రక్ లో ఇటుకలు వేయడం (fwrite vs fprintf)

fprintf (Text Mode): మీ దగ్గర 10,000 ఇటుకలు ఉన్నాయి. మీరు ఒక్కో ఇటుకని తీసుకుని, దాన్ని శుభ్రంగా కడిగి, ఒక పేపర్ చుట్టి (ఫార్మాటింగ్) ఆ తర్వాతే ట్రక్ లో వేస్తున్నారు అనుకోండి. దీనికి రెండు రోజులు పడుతుంది కదా! ఇది fprintf చేసే పని (స్లో).

fwrite (Binary Mode): మీరు డైరెక్ట్ గా ఒక జేసీబీ (JCB) తో ఆ 10,000 ఇటుకలని (Memory Block) ఒకేసారి ఎత్తి, ఒక్క సెకనులో ఆ ట్రక్ (File) లో పడేస్తారు! ఏ ఫార్మాటింగ్ లేదు, పేపర్స్ లేవు. RAM లో ఉన్న మెమరీ బ్లాక్ ని ఒకే షాట్ లో హార్డ్ డిస్క్ లోకి కాపీ చేయడాన్నే fwrite() అంటారు. డేటాబేస్ ఇంజిన్స్, గేమ్ సేవ్ ఇంజిన్స్ అన్నీ ఇదే వాడుతాయి.

2 fwrite() మరియు fread() సింటాక్స్

వీటి సింటాక్స్ చూడటానికి కొంచెం భయపెట్టేలా ఉంటుంది కానీ, అర్థమైతే చాలా సింపుల్:
fwrite(డేటా_అడ్రస్, ఒక్కో_సైజు, ఎన్ని_ఐటమ్స్, ఫైల్_పాయింటర్);

మీరు ఒక స్ట్రక్చర్ ని (ఉదా: ప్లేయర్ ఇన్వెంటరీ) సేవ్ చేయాలంటే fwrite(&player, sizeof(Player), 1, file) అని రాస్తే, ఆ స్ట్రక్చర్ లోపల వంద ఐటమ్స్ ఉన్నా సరే సింగిల్ లైన్ లో సేవ్ అయిపోతుంది!

3 ఒకే ఒక సింపుల్ కోడ్ (Struct Serialization)

కింద కోడ్ లో ఒక గేమ్ లో ఉన్న ప్లేయర్ స్ట్రక్చర్ ని బైనరీ ఫైల్ (.dat) లోకి రాసి, మళ్ళీ దాన్ని ఎలా ఫాస్ట్ గా చదివి లోడ్ చేసామో చూడండి.

C — Binary File I/O (fwrite/fread) ▶ Run Code 
#include <stdio.h>
#include <stdlib.h>

// ఒక కాంప్లెక్స్ గేమ్ స్ట్రక్చర్
struct Player {
    char name[50];
    int level;
    float health;
};

int main() {
    // 1. మనం సేవ్ చేయాల్సిన డేటా క్రియేట్ చేద్దాం
    struct Player p1 = {"DragonSlayer", 45, 89.5f};
    
    // --- BRAY FILE WRITE (Save Game) ---
    // "wb" అంటే Write Binary (నార్మల్ టెక్స్ట్ కాదు)
    FILE* file = fopen("savegame.dat", "wb");
    if (file == NULL) return 1;
    
    // మ్యాజిక్ ఇక్కడే: RAM లో ఉన్న p1 ని ఒకేసారి ఫైల్ లోకి జేసీబీ తో వేస్తున్నాం
    // (అడ్రస్, సైజు, ఎన్ని బ్లాక్స్, ఫైల్)
    fwrite(&p1, sizeof(struct Player), 1, file);
    
    fclose(file);
    printf("[+] Game State Saved Securely (Binary).\n\n");
    
    // ------------------------------------
    // --- BINARY FILE READ (Load Game) ---
    // ------------------------------------
    struct Player loadedPlayer; // కొత్త ఖాళీ బాక్స్ 
    
    // "rb" అంటే Read Binary
    FILE* loadFile = fopen("savegame.dat", "rb");
    if (loadFile == NULL) return 1;
    
    // ఫైల్ లో ఉన్న బైనరీ డేటాని డైరెక్ట్ గా మన ఖాళీ స్ట్రక్చర్ లోకి కాపీ కొడుతున్నాం!
    fread(&loadedPlayer, sizeof(struct Player), 1, loadFile);
    
    fclose(loadFile);
    
    // లోడ్ అయిన డేటాని చెక్ చేద్దాం
    printf("--- Loaded Game State ---\n");
    printf("Player Name : %s\n", loadedPlayer.name);
    printf("Level       : %d\n", loadedPlayer.level);
    printf("Health      : %.1f\n", loadedPlayer.health);
    
    return 0;
}
4 కోడ్ లో ఏం జరుగుతోంది? (Step-by-Step)
  • fopen("savegame.dat", "wb"): డాట్ టెక్స్ట్ (.txt) బదులు .dat అని ఇచ్చాము (బైనరీ ఫైల్ అని గుర్తుకోసం). 'wb' అంటే OS కి మనం చెప్తున్నాం ఎటువంటి క్యారెక్టర్ ఎన్కోడింగ్ చేయకని.
  • fwrite(&p1, ...): ఇది చాలా డేంజరస్ అండ్ పవర్ ఫుల్! p1 లోపల స్ట్రింగ్స్ ఉన్నా, ఫ్లోట్స్ ఉన్నా దానికి అనవసరం. అది కేవలం ఆ 58 బైట్స్ ఆఫ్ RAM ని కట్ చేసి హార్డ్ డిస్క్ మీద ముద్రిస్తుంది (Serialization). దీనివల్ల స్పీడ్ 100x పెరుగుతుంది.
  • fread(&loadedPlayer, ...): ఆ బైనరీ డేటాని చదివి, మనకి కావాల్సిన స్ట్రక్చర్ రూల్స్ ప్రకారం మళ్ళీ C కోడ్ లోకి ఒకే లైన్ లో లోడ్ చేసేస్తుంది. No parsing needed!
5 ఇంటర్వ్యూలలో అడిగే కామన్ ప్రశ్నలు (FAQ)

Q1: ఫైల్ లో వీడియో ప్లేయర్ లాగా స్కిప్ చేయాలంటే (Seek) ఎలా?

ఒక పెద్ద ఫైల్ లో 1000 రికార్డ్స్ ఉంటే, మధ్యలో 500వ రికార్డ్ చదవాలంటే మొదటి నుండి చదువుకుంటూ వెళ్లక్కర్లేదు. C లో fseek(file, offset, POSITION) అనే ఫంక్షన్ వాడొచ్చు. ఉదాహరణకు fseek(file, 100, SEEK_SET) అంటే స్టార్టింగ్ నుండి 100 బైట్స్ ముందుకు జంప్ అవ్వు అని అర్థం. ఇది డేటాబేస్ అల్గారిథమ్స్ కి ప్రాణం లాంటిది!

Q2: ftell() అంటే ఏంటి? ఫైల్ సైజు ఎలా కనుక్కోవాలి?

మీరు ఫైల్ లోపల ప్రస్తుతం ఎన్నో బైట్ దగ్గర ఉన్నారో ఆ నంబర్ ని ftell(file) చెప్తుంది. ఒక ఫైల్ సైజు కనుక్కోవాలంటే బెస్ట్ ట్రిక్: ముందు fseek(file, 0, SEEK_END) వాడి ఫైల్ చివరికి జంప్ చేయండి. ఆ తర్వాత ftell() వాడి ఆ పొజిషన్ నంబర్ తెచ్చుకోండి. ఆ నంబరే మీ ఫైల్ సైజు (In Bytes)!

Q3: బైనరీ ఫైల్స్ అన్ని సిస్టమ్స్ లో ఒకేలా పనిచేస్తాయా? (Portability Issue)

ఇది చాలా పెద్ద బగ్! ఒక ఇంటెల్ (Little Endian) సిస్టమ్ లో బైనరీ రైట్ చేసి, ఆ ఫైల్ ని మ్యాక్ బుక్ (ARM / Big Endian పాత మోడల్స్) సిస్టమ్ లో చదివితే డేటా మొత్తం ఉల్టా అయిపోతుంది (ఉదాహరణకు లెవల్ 45 కాస్తా 7549747 అవుతుంది). దానికి తోడు స్ట్రక్చర్ ప్యాడింగ్ (Struct Padding) వల్ల సిస్టమ్ కి సిస్టమ్ కి సైజు మారిపోతుంది. బైనరీ ఫైల్స్ ఫాస్ట్ అయినా, అవి పోర్టబుల్ కాదు!
