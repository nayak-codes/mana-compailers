Error Handling (setjmp, longjmp) (తెలుగులో)

⚡ C (C17 / C23 Standard) 🟢 Lesson 48 📂 Phase 17: Advanced Concepts 📅 2026 Comprehensive Master Edition
📌 Covered in this in-depth guide: Exception Handling in C · setjmp() · longjmp() · Stack Unwinding · Goto vs Longjmp

జావా (Java) లేదా పైథాన్ (Python) లాంటి మోడరన్ లాంగ్వేజెస్ లో ఏదైనా ఎర్రర్ వస్తే దాన్ని try-catch బ్లాక్ తో చాలా ఈజీగా హ్యాండిల్ చేస్తారు. కానీ మన C లాంగ్వేజ్ ఏమో 1970లలో పుట్టింది. అప్పట్లో ఈ try-catch లాంటి ఫ్యాన్సీ ఫీచర్స్ ఏమీ లేవు. మరి ఒక పెద్ద ప్రోగ్రామ్ లో ఎక్కడో లోపల (3వ లెవల్ ఫంక్షన్ లో) ఎర్రర్ వస్తే, అక్కడ నుండి డైరెక్ట్ గా మెయిన్ ఫంక్షన్ కి (బయటకి) ఎలా దూకాలి? దానికి C ఇచ్చిన రెండు మాయా అస్త్రాలే setjmp() మరియు longjmp(). ఇవి అచ్చం టైమ్-మెషిన్ లాగా పనిచేస్తాయి. అదెలాగో ఈరోజు డీప్ గా చూద్దాం.

1 నార్మల్ గా ఎర్రర్స్ ఎలా హ్యాండిల్ చేస్తారు?

సాధారణంగా C లో ఫంక్షన్స్ రిటర్న్ చేసే నంబర్స్ (0 అంటే సక్సెస్, -1 అంటే ఫెయిల్) ని చెక్ చేస్తూ if...else రాసుకుంటూ వెళ్తాము. కానీ ఒక ఫంక్షన్ ఇంకో ఫంక్షన్ ని కాల్ చేసి, అది ఇంకో ఫంక్షన్ ని కాల్ చేసినప్పుడు (A -> B -> C), C లో ఎర్రర్ వస్తే B కి చెప్పి, ఆ B వెళ్లి A కి చెప్పి... ఇదంతా చాలా పెద్ద ప్రాసెస్ అయిపోతుంది.

⏳ రియల్ లైఫ్ స్టోరీ: వీడియో గేమ్ లో సేవ్ పాయింట్ (Save Point)

మీరు ఒక వీడియో గేమ్ ఆడుతున్నారు. ఒక సేఫ్ ప్లేస్ లో ఆటని సేవ్ చేసుకుంటారు (ఇదే setjmp). ఆ తర్వాత మీరు గేమ్ లో ముందుకు వెళ్లి, అడవిలోకి వెళ్లి, ఒక రాక్షసుడితో ఫైట్ చేసి (అదే ఫంక్షన్ కాల్స్) చనిపోతారు (Error).

చనిపోగానే మీరు మళ్ళీ నడుచుకుంటూ వెనక్కి రారు కదా! డైరెక్ట్ గా ఎక్కడ సేవ్ చేసారో అక్కడికే టెలిపోర్ట్ (Teleport) అయిపోతారు. ఆ టెలిపోర్ట్ చేసే పవరే longjmp. C ప్రోగ్రామ్ లో కూడా మీరు longjmp వాడితే, కంపైలర్ డైరెక్ట్ గా పాత setjmp దగ్గరికి దూకేస్తుంది!

2 goto వర్సెస్ longjmp

మీరు goto వాడి కూడా వేరే లైన్ కి దూకవచ్చు కదా అనుకోవచ్చు. కానీ goto కేవలం అదే ఫంక్షన్ లోపల (Local) మాత్రమే దూకగలదు. మీరు వేరే ఫంక్షన్ లో ఉండి, మెయిన్ ఫంక్షన్ కి దూకాలంటే goto పనిచేయదు. longjmp అనేది ఫంక్షన్స్ మధ్య బోర్డర్స్ ని దాటి (Non-local jump) దూకగలదు!

3 ఒకే ఒక సింపుల్ కోడ్ (Try-Catch Simulation)

కింద కోడ్ లో డివిజన్ బై జీరో (Division by Zero) ఎర్రర్ వచ్చినప్పుడు, లోపలి ఫంక్షన్ నుండి డైరెక్ట్ గా బయటికి ఎలా దూకామో యానిమేటెడ్ లాగా చూడండి.

C — setjmp & longjmp ▶ Run Code 
#include <stdio.h>
#include <setjmp.h> // ఈ హెడ్డర్ ఫైల్ కచ్చితంగా ఉండాలి

// సేవ్ పాయింట్ ని స్టోర్ చేసుకోవడానికి ఒక గ్లోబల్ బఫర్
jmp_buf save_point;

// ఒక ప్రమాదకరమైన ఫంక్షన్ (B)
void divide_numbers(int a, int b) {
    printf("  [Inside Function] Trying to divide %d by %d...\n", a, b);
    
    if (b == 0) {
        printf("  [Error!] Division by Zero detected! Jumping back!\n");
        // ఎర్రర్ వస్తే డైరెక్ట్ గా బేస్ క్యాంప్ (save_point) కి దూకేయ్!
        // 1 అనే కోడ్ తో దూకుతున్నాం (ఇది క్యాచ్ బ్లాక్ కి సిగ్నల్)
        longjmp(save_point, 1);
    }
    
    // ఒకవేళ ఎర్రర్ రాకపోతే నార్మల్ గా రిజల్ట్ ఇస్తుంది
    printf("  [Success] Result is: %d\n", a / b);
}

// మెయిన్ ఫంక్షన్ (A)
int main() {
    printf("--- Try-Catch in C (Simulation) ---\n\n");
    
    // 1. ఆటని సేవ్ చేయడం (Try Block లాగా)
    // ఫస్ట్ టైమ్ సేవ్ చేసినప్పుడు setjmp 0 ని రిటర్న్ చేస్తుంది.
    int status = setjmp(save_point);
    
    if (status == 0) {
        // ఇదంతా Try Block లోపల అన్నమాట
        printf("Save Point Created. Let's run the risky code.\n");
        divide_numbers(10, 2); // ఇది సక్సెస్ అవుతుంది
        
        printf("\nNow running risky code again...\n");
        divide_numbers(10, 0); // ఇది ఫెయిల్ అయ్యి దూకేస్తుంది
        
        // ఈ లైన్ ఎప్పటికీ ప్రింట్ అవ్వదు, ఎందుకంటే పైనే దూకేసింది
        printf("This line will never print!\n"); 
    } 
    else if (status == 1) {
        // ఇది Catch Block లాగా అన్నమాట (longjmp 1 తో దూకినప్పుడు)
        printf("\n[Caught Exception] We safely landed back in main()!\n");
        printf("Error Code received: %d\n", status);
    }
    
    printf("\nProgram safely finished.\n");
    return 0;
}
4 కోడ్ లో ఏం జరుగుతోంది? (Step-by-Step)
  • jmp_buf save_point;: ఇది కంపైలర్ కోసం ఒక స్పెషల్ బాక్స్. మీరు ఏ ఫంక్షన్ లో ఉన్నారు, మీ CPU రిజిస్టర్స్ (Registers) ఏంటి అని మొత్తం మీ కరెంట్ స్టేట్ ని (టైమ్ మెషిన్ లాగా) ఇందులో దాచుకుంటుంది.
  • setjmp(save_point): ఇది మొదట రన్ అయినప్పుడు అదంతా దాచుకుని 0 ని ఇస్తుంది. అందుకే మనం ఫస్ట్ హాఫ్ కోడ్ రన్ చేస్తాం.
  • longjmp(save_point, 1): ఇది రన్ అవ్వగానే, CPU డైరెక్ట్ గా పాత setjmp లైన్ కి వెళ్లిపోతుంది. కానీ ఈసారి setjmp కి 0 బదులు 1 వస్తుంది (మనం 1 పాస్ చేసాం కాబట్టి). అప్పుడు కంపైలర్ కింద ఉన్న ఎల్స్-ఇఫ్ (Catch block) లోకి వెళ్తుంది. ఇది అచ్చం మ్యాజిక్ లాంటి కాన్సెప్ట్!
5 ఇంటర్వ్యూలలో అడిగే కామన్ ప్రశ్నలు (FAQ)

Q1: ఇది అంత పవర్ ఫుల్ అయితే, అందరూ ఎందుకు వాడరు?

దీనికి ఒక పెద్ద సైడ్ ఎఫెక్ట్ ఉంది. దీనివల్ల Memory Leaks వస్తాయి! మీరు ఒక ఫంక్షన్ లోపల malloc వాడి మెమరీ క్రియేట్ చేసి, దాన్ని free చేయకుండానే longjmp తో బయటికి దూకేస్తే... ఆ మెమరీ అలా లాక్ అయ్యి ఉండిపోతుంది (Stack Unwinding జరగదు). అందుకే C++ లో ఈ సమస్య రాకుండా try-catch కనిపెట్టారు.

Q2: ఒకవేళ setjmp రాసిన ఫంక్షన్ క్లోజ్ అయ్యాక longjmp వాడితే?

ఇది ప్రోగ్రామ్ ని వెంటనే క్రాష్ చేస్తుంది (Undefined Behavior)! మీరు సేవ్ పాయింట్ పెట్టిన ఫంక్షన్ ఇంకా బతికి ఉంటేనే (Stack లో ఉంటేనే) అక్కడికి దూకగలరు. ఆ ఫంక్షన్ ఎండ్ అయిపోయి, వేరే ఫంక్షన్ కి వెళ్లి దూకమని చెప్తే దానికి దారి తెలీక బ్లూ స్క్రీన్ వచ్చేస్తుంది.

Q3: గేమ్ ఇంజిన్స్ లో దీన్ని ఇంకా వాడుతున్నారా?

అవును! క్వేక్ (Quake) లాంటి పాత గేమ్ ఇంజిన్స్ లో సిస్టమ్ క్రాష్ అవ్వకుండా ఆపడానికి (Fatal Errors) దీన్నే వాడేవాళ్ళు. ఇప్పటికీ రొబోటిక్స్ లో హార్డ్వేర్ ఫెయిల్ అయినప్పుడు మెయిన్ లూప్ కి సేఫ్ గా రావడానికి ఈ కాన్సెప్ట్ నే వాడతారు.
