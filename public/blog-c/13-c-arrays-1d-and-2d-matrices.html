అర్రేలు (1D Arrays & 2D Matrices)

⚡ Modern C (C99 / C11) 🟢 Chapter 13 of 20 📂 Phase 04: అర్రేస్, స్ట్రింగ్స్ & పాయింటర్లు 📅 2026 Edition
📌 Covered in this chapter: కంటిగ్యుయస్ మెమరీ బ్లాక్స్ · ఇండెక్సింగ్ మెకానిక్స్ · మ్యాట్రిక్స్ కూడిక/గుణకారం · Row-Major Order మెమరీ ఫార్ములా
కంప్యూటర్ ప్రోగ్రామింగ్‌లో ఒకే రకమైన వేలాది డేటా అంశాలను (ఉదాహరణకు 100 మంది విద్యార్థుల మార్కులు, గేమ్ గ్రిడ్ కోఆర్డినేట్లు, లేదా ఇమేజ్ పిక్సెల్స్) వేర్వేరు వేరియబుల్స్ లేకుండా ఒకే గొడుగు క్రింద నిల్వ చేయడానికి అర్రేలు (Arrays) ప్రాథమిక పునాది. RAM లో వరుస మెమరీ గదుల కేటాయింపు (Contiguous Memory Allocation), $O(1)$ రాండమ్ యాక్సెస్ మెకానిక్స్, C లో బౌండ్స్ చెకింగ్ లేకపోవడం వెనుక ఉన్న ప్రమాదాలు, మరియు 2D మ్యాట్రిక్స్ యొక్క Row-Major Order మెమరీ ఫార్ములాను ఈ అధ్యాయంలో లోతుగా నేర్చుకుందాం.
1అర్రే అంటే ఏమిటి? Contiguous Memory Allocation & O(1) యాక్సెస్

అర్రే (Array) అనేది ఒకే డేటా రకానికి చెందిన స్థిర పరిమాణపు ఎలిమెంట్లను RAM లో వరుసగా ఉండే మెమరీ గదులలో (Contiguous Memory Blocks) నిల్వ చేసే డేటా స్ట్రక్చర్.

⚡ O(1) రాండమ్ యాక్సెస్ వెనుక ఉన్న గణిత ఫార్ములా:

కంప్యూటర్ అర్రేలోని ఏ ఎలిమెంట్‌నైనా (మొదటిదైనా లేదా 10,000వ ఎలిమెంట్ అయినా) ఒకే ఒక్క మైక్రోసెకనులో ఎలా యాక్సెస్ చేయగలదు? CPU కి ఎలిమెంట్లను వరుసగా లెక్కించాల్సిన అవసరం లేదు. అది నేరుగా ఈ క్రింది మెమరీ అడ్రస్ ఫార్ములాను లెక్కిస్తుంది:

Address(arr[i]) = Base_Address + (i × sizeof(DataType))

ఉదాహరణకు int arr[5] బేస్ అడ్రస్ 1000 వద్ద ఉంటే, arr[3] అడ్రస్ నేరుగా 1000 + (3 × 4) = 1012 అవుతుంది. ఈ సింగిల్ మల్టిప్లికేషన్ వల్లే అర్రే ఇండెక్సింగ్ O(1) Constant Time లో మెరుపు వేగంతో పనిచేస్తుంది.

C — 1D Array Declaration, Input & Traversal ⚡ Try in C Compiler 
#include <stdio.h>

int main(void) {
    // 5 పూర్ణాంకాల అర్రే డిక్లరేషన్ & ఇనీషియలైజేషన్
    int scores[5] = {88, 92, 79, 95, 84};
    int total = 0;

    printf("విద్యార్థుల స్కోర్లు:\n");
    for (int i = 0; i < 5; i++) {
        printf("Score[%d] = %d (RAM Address: %p)\n", i, scores[i], (void*)&scores[i]);
        total += scores[i];
    }

    double average = (double)total / 5;
    printf("సగటు స్కోర్: %.2lf\n", average);
    return 0;
}
2C లో బౌండ్స్ చెకింగ్ ఎందుకు ఉండదు? (No Boundary Checking Trap)

Java, Python వంటి ఆధునిక భాషలలో అర్రే సైజ్ దాటి యాక్సెస్ చేయడానికి ప్రయత్నిస్తే (ఉదా: 5 సైజ్ ఉన్న అర్రేకి arr[10] అంటే) వెంటనే ArrayIndexOutOfBoundsException వస్తుంది. కానీ C లాంగ్వేజ్‌లో ఎటువంటి బౌండ్స్ చెకింగ్ ఉండదు!

⚠️ Silent Memory Corruption & Security Exploits:

డెన్నిస్ రిట్చీ C ని రూపొందించినప్పుడు గరిష్ట పనితీరు (Maximum Execution Speed) కోసమే ప్రాధాన్యత ఇచ్చారు. ప్రతి ఇండెక్స్ యాక్సెస్ వద్ద సైజ్ చెక్ చేస్తే CPU సైకిల్స్ వృధా అవుతాయి. ఫలితంగా మీరు arr[10] = 500; అని రాస్తే C మిమ్మల్ని ఆపదు! అది పక్కనే ఉన్న వేరే వేరియబుల్ మెమరీని నిశ్శబ్దంగా ఓవర్‌రైట్ చేస్తుంది (Silent Corruption) లేదా ఆపరేటింగ్ సిస్టమ్ ద్వారా రక్షించబడిన మెమరీని టచ్ చేసినప్పుడు ప్రోగ్రామ్ క్రాష్ అవుతుంది (Segmentation Fault).

32D అర్రేస్ & Row-Major Order మెమరీ లేఅవుట్

గణిత మ్యాట్రిక్స్, చదరంగం బోర్డులు, లేదా గేమింగ్ గ్రిడ్లను సూచించడానికి 2D అర్రేస్ (మల్టీ-డైమెన్షనల్ అర్రేస్) వాడతాం. అయితే భౌతికంగా కంప్యూటర్ RAM లో 2D గ్రిడ్లు ఉండవు! కంప్యూటర్ మెమరీ అనేది కేవలం 1D లీనియర్ బైట్ల వరుస మాత్రమే.

📐 Row-Major Order అంటే ఏమిటి?

C లాంగ్వేజ్ 2D అర్రేలోని మొదటి వరుసను (Row 0) మెమరీలో పూర్తిగా ఉంచిన తర్వాతే, దాని పక్కనే రెండవ వరుసను (Row 1), ఆ తర్వాత మూడవ వరుసను వరుసగా భద్రపరుస్తుంది. దీనిని Row-Major Order అంటారు.

Address(Matrix[row][col]) = Base + (row × Total_Columns + col) × sizeof(DataType)
C — 2D Matrix Addition Demo ⚡ Try in C Compiler 
#include <stdio.h>

int main(void) {
    int A[2][2] = {{1, 2}, {3, 4}};
    int B[2][2] = {{5, 6}, {7, 8}};
    int Sum[2][2];

    // మ్యాట్రిక్స్ కూడిక (Matrix Addition)
    for (int r = 0; r < 2; r++) {
        for (int c = 0; c < 2; c++) {
            Sum[r][c] = A[r][c] + B[r][c];
        }
    }

    printf("మ్యాట్రిక్స్ కూడిక ఫలితం (Sum Matrix):\n");
    for (int r = 0; r < 2; r++) {
        for (int c = 0; c < 2; c++) {
            printf("%4d", Sum[r][c]);
        }
        printf("\n");
    }
    return 0;
}
4బిగినర్స్ చేసే ఘోరమైన తప్పులు (Beginner Pitfalls)
❌ 1. Off-by-one ఇండెక్స్ ట్రాప్:
int arr[5]; arr[5] = 100; // ప్రమాదకరమైన బగ్! చెల్లుబాటు అయ్యే ఇండెక్స్‌లు 0 నుండి 4 మాత్రమే 5 ఎలిమెంట్స్ ఉన్న అర్రే చివరి ఇండెక్స్ 4 మాత్రమే. arr[5] రాస్తే అది అర్రే హద్దులు దాటి పక్కనున్న మెమరీని నాశనం చేస్తుంది.
❌ 2. అర్రే మొత్తాన్ని ఒకేసారి అసైన్ చేయడానికి ప్రయత్నించడం:
int a[5] = {1, 2, 3, 4, 5}; int b[5]; b = a; // Compiler Error! C లో అర్రేలను నేరుగా b = a; అని అసైన్ చేయలేం. లూప్ వాడి ఒక్కో ఎలిమెంట్‌ను కాపీ చేయాలి లేదా memcpy() ఫంక్షన్ వాడాలి.
5తరచుగా అడిగే ప్రశ్నలు (FAQ)

Q: అర్రే సైజ్ కనుగొనడానికి sizeof(arr) / sizeof(arr[0]) ఎందుకు వాడతారు?

sizeof(arr) అర్రే మొత్తం ఆక్రమించిన బైట్ల సంఖ్యను (ఉదా: 5 int లకు 20 బైట్లు) ఇస్తుంది. sizeof(arr[0]) ఒక ఎలిమెంట్ బైట్లను (4 బైట్లు) ఇస్తుంది. 20 ని 4 తో భాగిస్తే ఎలిమెంట్ల సంఖ్య 5 వస్తుంది. ఇది కంపైల్-టైమ్ కాలిక్యులేషన్.

Q: VLA (Variable Length Arrays) అంటే ఏమిటి? వాటిని పరిశ్రమల్లో ఎందుకు నివారిస్తారు?

C99 లో ప్రవేశపెట్టిన VLA ద్వారా రన్‌టైమ్‌లో యూజర్ ఇచ్చిన సైజ్‌తో (int arr[n];) అర్రేను స్టాక్ పై సృష్టించవచ్చు. కానీ యూజర్ అనుకోకుండా చాలా పెద్ద సైజ్ (ఉదా: n = 10000000) ఇస్తే స్టాక్ ఓవర్‌ఫ్లో జరిగి సిస్టమ్ క్రాష్ అవుతుంది. అందుకే లైనక్స్ కర్నల్ మరియు ప్రొఫెషనల్ కోడ్‌బేస్‌లలో VLA లను నిషేధించారు.
