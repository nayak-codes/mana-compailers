System Calls (fork, exec, wait) (తెలుగులో)

⚡ C (C17 / C23 Standard) 🟢 Lesson 64 📂 Phase 20: Algorithms & Final 📅 2026 Comprehensive Master Edition
📌 Covered in this in-depth guide: System Calls Basics · fork() for Child Process · exec() Family · wait() Status

మామూలుగా మనం రాసే printf, scanf ఇవన్నీ ఒక లైబ్రరీ లో ఉన్న ఫంక్షన్స్ మాత్రమే. కానీ అవి మీ కీబోర్డ్ నుండి డేటా ఎలా తెస్తున్నాయి? డైరెక్ట్ గా ఆపరేటింగ్ సిస్టమ్ (OS - విండోస్ లేదా లైనక్స్) ని పర్మిషన్ అడుగుతాయి. దాన్నే System Call (సిస్టమ్ కాల్) అంటారు. C లాంగ్వేజ్ అనేది సిస్టమ్ ప్రోగ్రామింగ్ కి రారాజు! ఒక ప్రాసెస్ (App) రన్ అవుతుండగానే దాన్ని రెండుగా చీల్చడం (fork), లేదా ఒక ప్రాసెస్ ని చంపి ఆ ప్లేస్ లో ఇంకో యాప్ ని ఓపెన్ చేయడం (exec) లాంటివి C తో ఎలా చేయాలో ఈరోజు డీప్ గా నేర్చుకుందాం. గమనిక: ఈ ఫంక్షన్స్ అన్నీ POSIX (Linux/Mac) సిస్టమ్స్ కే బాగా పనిచేస్తాయి.

1 సిస్టమ్ కాల్ అంటే ఏంటి?

మీ కోడ్ (User Mode) లో రన్ అవుతుంది. కానీ RAM, హార్డ్ డిస్క్, ప్రాసెసర్స్ అన్నీ OS (Kernel Mode) కంట్రోల్ లో ఉంటాయి. మీరు ఒక ఫైల్ ఓపెన్ చేయాలన్నా, ఇంటర్నెట్ కి కనెక్ట్ అవ్వాలన్నా, డైరెక్ట్ గా వెళ్ళలేరు. ఒక గేట్ (System Call) గుండా పర్మిషన్ అడిగి వెళ్ళాలి.

2 మాయా అస్త్రాలు: fork() మరియు exec()

🧬 రియల్ లైఫ్ స్టోరీ: ఒక మనిషి రెండు అవ్వడం (Amoeba)

1. fork() - క్లోనింగ్ మ్యాజిక్: ఒక ప్రోగ్రామ్ రన్ అవుతుండగా fork() అని పిలవగానే, అమీబా లాగా ఆ ప్రోగ్రామ్ రెండు ముక్కలు అయిపోతుంది! ఒరిజినల్ దాన్ని Parent Process అని, కొత్తదాన్ని Child Process అని అంటారు. రెండూ ఒకే కోడ్ ని ఒకేసారి (ప్యారలల్ గా) నెక్స్ట్ లైన్ నుండి రన్ చేస్తాయి!

2. exec() - ఆత్మ మారడం: ఆ పుట్టిన చైల్డ్ ప్రాసెస్ ఏం చేస్తుందంటే, "నాకు ఈ పాత కోడ్ వద్దు" అని చెప్పి, ఆ ప్లేస్ లోకి వేరే ప్రోగ్రామ్ (ఉదా: క్రోమ్ బ్రౌజర్) ని లోడ్ చేస్తుంది (exec). అంటే కోడ్ ఆత్మ మారుతుందన్నమాట!

3 ఒకే ఒక సింపుల్ కోడ్ (Fork Demo)

కింద కోడ్ లో fork() వాడి ఒకే కోడ్ ని రెండుగా విడగొట్టి, ఎవరు పేరెంట్, ఎవరు చైల్డ్ అని ఎలా కనుక్కున్నామో చూడండి. (విండోస్ లో ఇది నేటివ్ గా పనిచేయదు, Linux ఆన్లైన్ కంపైలర్ వాడండి).

C — fork() System Call (Linux) ▶ Run Code 
#include <stdio.h>
#include <unistd.h>   // fork() కోసం
#include <sys/wait.h> // wait() కోసం

int main() {
    printf("--- Welcome to System Calls ---\n");
    printf("[Main] I am the single parent process.\n\n");
    
    // 1. మ్యాజిక్! ఇక్కడ కోడ్ రెండుగా చీలిపోతుంది
    pid_t pid = fork();
    
    if (pid < 0) {
        printf("Fork Failed!\n");
    } 
    else if (pid == 0) {
        // ఇది కేవలం చైల్డ్ (కొత్త ప్రాసెస్) లో మాత్రమే రన్ అవుతుంది!
        // ఎందుకంటే చైల్డ్ కి ఎప్పుడూ pid = 0 ఇస్తుంది OS.
        printf("  -> [Child] Hello! I was just born! (My PID is 0)\n");
        printf("  -> [Child] I am doing my homework...\n");
        // చైల్డ్ పని అయిపోయాక ఎగ్జిట్ అవుతుంది
    } 
    else {
        // ఇది కేవలం పేరెంట్ (పాత ప్రాసెస్) లో మాత్రమే రన్ అవుతుంది!
        // పేరెంట్ కి తన చైల్డ్ యొక్క ఒరిజినల్ ఐడీ వస్తుంది.
        printf("[Parent] I just created a child! (Child ID: %d)\n", pid);
        
        // 2. చైల్డ్ పని పూర్తయ్యేదాకా పేరెంట్ వెయిట్ చేయాలి
        printf("[Parent] Waiting for child to finish...\n");
        wait(NULL); // చైల్డ్ ఆత్మహత్య (exit) చేసుకునే దాకా హోల్డ్!
        
        printf("[Parent] Child finished its job. Now I can exit.\n");
    }
    
    // గమనిక: ఇక్కడ ఉన్న లాస్ట్ లైన్ ఇద్దరికీ కామన్ గా రన్ అవుతుంది
    printf("--- Code execution finished! ---\n");
    
    return 0;
}
4 కోడ్ లో ఏం జరుగుతోంది? (Step-by-Step)
  • fork(): ఈ లైన్ పిలవగానే, OS ఈ మొత్తం యాప్ కి ఒక డూప్లికేట్ క్లోన్ (Clone) ని సృష్టిస్తుంది. ఇప్పటినుండి పేరెంట్, చైల్డ్ ఇద్దరూ విడివిడిగా (Parallel గా) కింద లైన్స్ ని ఎగ్జిక్యూట్ చేస్తారు.
  • if (pid == 0): మరి ఆ రన్ అయ్యేది నేనా లేక నా క్లోన్ ఆ అని తెలుసుకోవడం ఎలా? OS ఒక ట్రిక్ పెట్టింది. చైల్డ్ లో pid వాల్యూ 0 ఉంటుంది. పేరెంట్ లో pid వాల్యూ చైల్డ్ యొక్క రియల్ ఐడీ (ఉదా: 3456) ఉంటుంది. దీన్ని బట్టి ఇఫ్-ఎల్స్ (if-else) లో రెండు వేరువేరు పనులు చేస్తాం!
  • wait(NULL): ఒకవేళ పేరెంట్ వెయిట్ చేయకుండా చనిపోతే (exit), అప్పుడు ఆ చైల్డ్ అనాధ అయిపోతాడు! దాన్నే Orphan Process అంటారు. అలా కాకుండా చైల్డ్ చనిపోయాక పేరెంట్ దాన్ని క్లీన్ చేయకపోతే దాన్ని Zombie Process అంటారు! అందుకే వెయిట్ కచ్చితంగా వాడాలి.
5 ఇంటర్వ్యూలలో అడిగే కామన్ ప్రశ్నలు (FAQ)

Q1: fork() కి, Threads (pthreads) కి తేడా ఏంటి?

చాలా డిఫరెన్స్ ఉంది! త్రెడ్స్ అంటే ఒకే ఇంట్లో ఉన్న ఇద్దరు మనుషులు లాంటి వాళ్ళు (వాళ్ళిద్దరూ ఒకే మెమరీ ని షేర్ చేసుకుంటారు, ఒకడు వేరియబుల్ మారిస్తే ఇంకొకడికి కనబడుతుంది). కానీ fork అంటే పక్కిల్లు! చైల్డ్ కి సపరేట్ మెమరీ కాపీ వస్తుంది. వాడు వేరియబుల్ మారిస్తే పేరెంట్ కి అసలు కనబడదు.

Q2: టెర్మినల్ (Command Prompt) ఎలా పనిచేస్తుంది?

మీరు టెర్మినల్ లో ls అని కమాండ్ టైప్ చేయగానే ఏం జరుగుతుందో తెలుసా? టెర్మినల్ యాప్ తనని తాను fork() చేసుకుని ఒక చైల్డ్ ని పుట్టిస్తుంది. ఆ చైల్డ్ ఏం చేస్తుందంటే exec("ls") అని పిలుస్తుంది. అప్పుడు ఆ చైల్డ్ కాస్తా ls ప్రోగ్రామ్ గా మారిపోయి అవుట్పుట్ ఇస్తుంది. పేరెంట్ అయిన టెర్మినల్ wait() చేస్తూ ఉంటుంది. అదీ మ్యాజిక్!

Q3: fork() ని ఒక లూప్ లో 3 సార్లు (for(i=0;i<3) fork();) పిలిస్తే ఏమవుతుంది?

ఇది ఒక క్లాసిక్ C పజిల్! ఫస్ట్ ఒక పేరెంట్ ఉంటుంది, వాడు ఒక చైల్డ్ ని కంటాడు (మొత్తం 2). నెక్స్ట్ లూప్ లో ఆ ఇద్దరూ తలా ఒకరిని కంటారు (మొత్తం 4). మూడో లూప్ లో ఆ నలుగురూ తలా ఒకరిని కంటారు (మొత్తం 8). సో టోటల్ ప్రాసెస్ లు 2^3 = 8 రన్ అవుతాయి (ఒక పేరెంట్ + 7 చిల్డ్రన్)!
