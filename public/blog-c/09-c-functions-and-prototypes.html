సాఫ్ట్‌వేర్ డెవలప్‌మెంట్‌లో వందల వేల లైన్ల కోడ్‌ను ఒకే main() ఫంక్షన్‌లో రాయడం అసాధ్యం మరియు నిర్వహణకు అత్యంత కష్టం. కోడ్‌ను చిన్న చిన్న మాడ్యూల్స్‌గా విడగొట్టడానికి, పునరావృతాన్ని తగ్గించడానికి (DRY Principle - Don't Repeat Yourself) ఫంక్షన్స్ (Functions) మూలస్తంభాలు. ఈ అధ్యాయంలో ఫంక్షన్ అనాటమీ, ఫార్వర్డ్ డిక్లరేషన్ (Prototypes) ఎందుకు తప్పనిసరి, మరియు RAM లోని కాల్ స్టాక్ (Call Stack) లో యాక్టివేషన్ రికార్డ్స్ ఎలా సృష్టించబడతాయో పరిశీలిద్దాం.
1C ఫంక్షన్ అనాటమీ — డిక్లరేషన్, డెఫినిషన్ & కాల్

ఒక నిర్దిష్టమైన పనిని చేయడానికి రూపొందించిన స్వతంత్ర కోడ్ బ్లాక్‌ను ఫంక్షన్ అంటారు. C లో ఫంక్షన్ మూడు ముఖ్యమైన భాగాలను కలిగి ఉంటుంది:

1. రిటర్న్ టైప్ (Return Type):

ఫంక్షన్ తన పని పూర్తి చేసుకున్న తర్వాత కాలర్ (Caller) కు తిరిగి ఇచ్చే డేటా రకం (ఉదా: int, double). ఒకవేళ ఏ విలువా రిటర్న్ చేయకపోతే void అని పేర్కొనాలి.

2. పారామీటర్లు (Parameters):

ఫంక్షన్ పని చేయడానికి అవసరమైన ఇన్‌పుట్ డేటాను స్వీకరించే వేరియబుల్స్ (Formal Arguments). ఉదా: (int a, int b).

3. ఫంక్షన్ బాడీ (Function Body):

కర్లీ బ్రేసెస్ { ... } లోపల ఉండే వాస్తవ ఎగ్జిక్యూటబుల్ స్టేట్‌మెంట్లు మరియు ఫలితాన్ని పంపే return స్టేట్‌మెంట్.

C — Simple Function Definition & Call ⚡ Try in C Compiler 
#include <stdio.h>

// ఫంక్షన్ డెఫినిషన్: రెండు సంఖ్యల మొత్తం లెక్కించడం
int calculateSum(int a, int b) {
    return a + b;
}

int main(void) {
    int x = 25, y = 75;
    // ఫంక్షన్ కాల్: ఫలితాన్ని స్వీకరించడం
    int result = calculateSum(x, y);

    printf("మొత్తం (Sum): %d\n", result);
    return 0;
}
2ఫంక్షన్ ప్రోటోటైప్స్ (Function Prototypes) ఎందుకు తప్పనిసరి?

C కంపైలర్ మీ సోర్స్ కోడ్‌ను పై నుండి క్రిందికి ఒకే పాస్ (Single-pass compilation) లో చదువుతుంది. ఒకవేళ మీరు main() ఫంక్షన్ తర్వాత మీ కస్టమ్ ఫంక్షన్‌ను రాస్తే, కంపైలర్ main() లో ఆ ఫంక్షన్ పిలుపును చూడగానే "ఈ ఫంక్షన్ ఏమిటో నాకు తెలియదు" అని భావిస్తుంది.

⚠️ Implicit Declaration Warning / Error:

పాత C ప్రమాణాలలో కంపైలర్ అన్-డిక్లేర్డ్ ఫంక్షన్‌ను డీఫాల్ట్‌గా int రిటర్న్ చేస్తుందని భావించేది. కానీ ఆధునిక C99 / C11 / C23 లలో ఇది కంపైలర్ వార్నింగ్ లేదా ఎర్రర్ ఇస్తుంది.

✅ ది సొల్యూషన్: Function Prototype (Forward Declaration)

double calculateTax(double amount, double rate); // ప్రోటోటైప్ చివర సెమికోలన్ తప్పనిసరి!

main() కు ముందే ఈ ప్రోటోటైప్ రాయడం వల్ల కంపైలర్‌కు "ఈ పేరుతో ఒక ఫంక్షన్ క్రింద ఉంది, అది ఏ పారామీటర్లు తీసుకుంటుందో, ఏ డేటా టైప్ రిటర్న్ చేస్తుందో చూసుకో" అని ముందస్తు సమాచారం అందుతుంది.

3RAM కాల్ స్టాక్ & యాక్టివేషన్ రికార్డ్స్ (Call Stack Architecture)

ప్రోగ్రామ్ రన్ అవుతున్నప్పుడు మెమరీ (RAM) లోని కాల్ స్టాక్ (Call Stack) విభాగం ఫంక్షన్ల ఎగ్జిక్యూషన్‌ను ట్రాక్ చేస్తుంది. ప్రతి ఫంక్షన్ కాల్ జరిగినప్పుడు స్టాక్ పై ఒక Stack Frame (లేదా Activation Record) పుష్ అవుతుంది.

📦 ఒక స్టాక్ ఫ్రేమ్ లోపల ఏముంటుంది?
  • Return Address: ఫంక్షన్ పని ముగిశాక CPU తిరిగి కాలర్‌లో ఏ లైన్‌కు వెళ్లాలో తెలిపే ఇన్స్ట్రక్షన్ పాయింటర్.
  • Function Arguments: ఫంక్షన్‌కు పాస్ చేసిన ఇన్‌పుట్ పారామీటర్లు.
  • Local Variables: ఆ ఫంక్షన్ లోపల డిక్లేర్ చేసిన లోకల్ వేరియబుల్స్.

💡 స్టాక్ LIFO (Last-In, First-Out) సూత్రంపై పనిచేస్తుంది. ఫంక్షన్ పూర్తయి return అవ్వగానే దాని స్టాక్ ఫ్రేమ్ మెమరీ నుండి పాప్ (Pop) అయి పూర్తిగా క్లియర్ అవుతుంది.

4బిగినర్స్ చేసే ఘోరమైన తప్పులు (Beginner Pitfalls)
❌ 1. ఫంక్షన్ ప్రోటోటైప్ మిస్ అవ్వడం:
main() తర్వాత ఫంక్షన్ రాసి పైభాగంలో ప్రోటోటైప్ ఇవ్వకపోతే కంపైలర్ టైప్ మిస్‌మ్యాచ్ వార్నింగ్‌లు ఇస్తుంది.
❌ 2. లోకల్ వేరియబుల్ అడ్రస్‌ను రిటర్న్ చేయడం (Dangling Pointer Trap):
int* getNumber() { int x = 10; return &x; } // ప్రమాదకరమైన బగ్! ఫంక్షన్ ముగియగానే x ఉన్న స్టాక్ ఫ్రేమ్ ధ్వంసమైపోతుంది. దాని అడ్రస్‌ను రిటర్న్ చేస్తే గార్బేజ్ డేటా లేదా సెగ్మెంటేషన్ ఫాల్ట్ వస్తుంది.
5తరచుగా అడిగే ప్రశ్నలు (FAQ)

Q: C లాంగ్వేజ్‌లో ఫంక్షన్ ఓవర్‌లోడింగ్ (Function Overloading) సాధ్యమేనా?

సాధ్యం కాదు! C++ లో ఒకే పేరుతో వేర్వేరు పారామీటర్లతో బహుళ ఫంక్షన్లు రాయవచ్చు కానీ C లాంగ్వేజ్‌లో ప్రతి ఫంక్షన్‌కు ఖచ్చితమైన ప్రత్యేకమైన పేరు ఉండాలి. C కంపైలర్ నేమ్ మాంగ్లింగ్ (Name Mangling) చేయదు.

Q: Call Stack గరిష్ట పరిమాణం (Stack Limit) ఎంత ఉంటుంది?

ఇది ఆపరేటింగ్ సిస్టమ్ మరియు కంపైలర్ కాన్ఫిగరేషన్‌పై ఆధారపడి ఉంటుంది. సాధారణంగా లైనక్స్/మాక్‌లలో డీఫాల్ట్‌గా 8MB, మరియు విండోస్‌లో 1MB స్టాక్ మెమరీ కేటాయించబడుతుంది.
