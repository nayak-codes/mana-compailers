C Passing Arrays to Functions, Pointer Decay & Limitations (తెలుగులో)

⚡ C (C17 / C23 Standard) 🟢 Lesson 16 📂 Phase 07: Arrays & Memory Organization 📅 2026 Edition
📌 Covered in this in-depth guide: Pointer Decay Mechanics · Why sizeof(arr) Fails Inside Functions · Explicit Size Passing · const Read-Only Arrays · Array Limitations

Phase 7 (Chapter 16): Passing Arrays & Pointer Decay Masterclass కు స్వాగతం! C నేర్చుకునేవాళ్ళు ఎక్కువగా కన్ఫ్యూజ్ అయ్యే టాపిక్ ఫంక్షన్స్ కి Arrays ని పాస్ చేయడం. C లో మనం ఒక Array ని ఫంక్షన్ కి ఇస్తే, అది మొత్తం కాపీ అవ్వదు. దానికి బదులుగా, ఆ Array తన మొదటి ఎలిమెంట్ అడ్రస్ ఉన్న ఒక Pointer లాగా మారిపోతుంది (దీన్నే Pointer Decay అంటారు). ఈ గైడ్ లో, Pointer Decay అంటే ఏంటి, ఫంక్షన్ లోపల sizeof వాడితే సైజు ఎందుకు కరెక్ట్ గా రాదు, మన Array ని వేరేవాళ్ళు మార్చకుండా const తో ఎలా ఆపాలి, మరియు C Arrays కి ఉన్న లిమిట్స్ ఏంటో తెలుగులో నేర్చుకుందాం.

1Pointer Decay అంటే ఏంటి? అది ఎలా జరుగుతుంది? ⭐

C లో మీరు ఒక Array ని ఫంక్షన్ కి పాస్ చేసినప్పుడు, ఆ Array మొత్తం లోపలికి కాపీ అవ్వదు. దానికి బదులుగా, కంపైలర్ ఆటోమేటిక్ గా ఆ Array ని తన మొదటి ఎలిమెంట్ అడ్రస్ కి పాయింటర్ (&arr[0]) లాగా మార్చేస్తుంది (Decay చేస్తుంది):

ఫంక్షన్ లోకి వెళ్ళేటప్పుడు Array పాయింటర్ లాగా మారడం:

main() లో: int numbers[1000]; (RAM లో 4,000 బైట్స్ తీసుకుంటుంది)
ఫంక్షన్ కాల్: processArray(numbers);

ఫంక్షన్ లోపల: void processArray(int* ptr) <--- ఇక్కడికి కేవలం ఒక చిన్న 8-బైట్ల అడ్రస్ మాత్రమే వస్తుంది!

ప్లస్ పాయింట్: డేటా మొత్తం కాపీ అవ్వదు కాబట్టి చాలా ఫాస్ట్ గా ఉంటుంది.
మైనస్ పాయింట్: ఫంక్షన్ కి ఆ Array లో అసలు ఎన్ని ఎలిమెంట్స్ ఉన్నాయో సైజు తెలిసిపోదు (సైజు పోతుంది)!

⚠️ ఫంక్షన్స్ లోపల sizeof(arr) వాడితే వచ్చే పెద్ద ప్రాబ్లం:

మీరు పొరపాటున ఫంక్షన్ లోపల sizeof(arr) అని పిలిస్తే, అది Array సైజ్ ని ఇవ్వదు! అది లోపలికి పాయింటర్ లాగా వచ్చింది కాబట్టి ఆ పాయింటర్ సైజు ని ఇస్తుంది (సాధారణంగా 8 బైట్స్ అని వస్తుంది).
✅ దీనికి సొల్యూషన్: ఎప్పుడైనా Array ని ఫంక్షన్ కి ఇస్తున్నారంటే, కచ్చితంగా దానికి తోడుగా సైజు ని కూడా రెండో ఆర్గ్యుమెంట్ గా పంపాలి: void process(int arr[], int size);

2In-Place మార్పులు & "const" తో సేఫ్ గా ఉంచడం

ఫంక్షన్ కి లోపలికి డైరెక్ట్ గా మన ఒరిజినల్ అడ్రస్ వెళ్తుంది కాబట్టి, ఫంక్షన్ లోపల దాన్ని మార్చితే బయట మన ఒరిజినల్ Array కూడా మారిపోతుంది! అలా ఫంక్షన్ మన డేటాని మార్చకుండా, కేవలం చూసుకొనేలా చేయాలంటే const అని వాడాలి:

C — Passing Arrays & const Protection Demo ▶ Run Code 
#include <stdio.h>

// 1. Read-Only display function (Protected with const)
void printArray(const int arr[], int size) {
    printf("Array elements: ");
    for (int i = 0; i < size; i++) {
        printf("%d ", arr[i]);
        // arr[i] = 0; // ❌ Compile Error: Assignment of read-only location!
    }
    printf("\n");
}

// 2. In-Place doubling function (Modifies caller's RAM memory!)
void doubleElements(int arr[], int size) {
    for (int i = 0; i < size; i++) {
        arr[i] *= 2;
    }
}

int main(void) {
    int data[] = {10, 20, 30, 40};
    int size = sizeof(data) / sizeof(data[0]);

    printArray(data, size);
    doubleElements(data, size);
    printf("After Doubling: ");
    printArray(data, size);

    return 0;
}
3C Arrays తో వచ్చే సమస్యలు (లిమిటేషన్స్)
సమస్య (Limitation)C లో దాని ప్రభావందీనికి సొల్యూషన్ ఏంటి?
సైజు ఫిక్స్డ్ గా ఉండటంఒకసారి సైజు ఇచ్చాక ప్రోగ్రామ్ రన్ అయ్యేటప్పుడు దాన్ని పెంచలేము, తగ్గించలేము.malloc() వాడి Dynamic గా మెమరీ క్రియేట్ చేయాలి.
ఒకే రకమైన డేటా ఉండటంనెంబర్లని, పేర్లని కలిపి ఒకే Array లో పెట్టలేము.దీనికి బదులు struct వాడాలి.
సైజు దానికి తెలియకపోవడంతన సైజు ఎంతో దానికి తెలియదు, మనమే దాన్ని గుర్తుపెట్టుకొని క్యాలిక్యులేట్ చేయాలి.పాయింటర్ తో పాటు సైజు కూడా ఇచ్చేలా కస్టమ్ స్ట్రక్చర్ వాడాలి.
సైజు లిమిట్ చెక్ చేయకపోవడంలిమిట్ దాటితే ఆపదు, వేరే మెమరీ లోకి వెళ్లి హ్యాక్ కి ఛాన్స్ ఇస్తుంది.లూప్ రాసేటప్పుడే కరెక్ట్ గా లిమిట్స్ ఇవ్వాలి.
