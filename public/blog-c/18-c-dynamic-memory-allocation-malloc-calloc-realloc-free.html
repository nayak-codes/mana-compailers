డైనమిక్ మెమరీ కేటాయింపు (malloc, calloc, realloc, free)

⚡ Modern C (C99 / C11) 🟢 Chapter 18 of 20 📂 Phase 05: స్ట్రక్చర్స్, డైనమిక్ మెమరీ & ప్రాజెక్ట్ 📅 2026 Edition
📌 Covered in this chapter: Stack vs Heap మెమరీ · రన్‌టైమ్ అర్రే సైజింగ్ · మెమరీ లీక్స్ (Memory Leaks) · free() ప్రాముఖ్యత
ఇప్పటివరకు మనం సృష్టించిన అన్ని వేరియబుల్స్ మరియు అర్రేలు కంపైల్-టైమ్‌లోనే స్థిరమైన సైజును కలిగి ఉండేవి. కానీ ఒక గేమ్‌లో ఎంతమంది ఆటగాళ్ళు చేరతారో లేదా డేటాబేస్ నుండి ఎన్ని రికార్డులు వస్తాయో రన్‌టైమ్‌కు ముందు ఎవరికీ తెలియదు. రన్‌టైమ్‌లో యూజర్ అవసరాలకు తగినట్లుగా కంప్యూటర్ మెమరీని డైనమిక్‌గా పొందడానికి C లో Heap Memory మరియు <stdlib.h> లోని malloc, calloc, realloc, free ఫంక్షన్లు గుండెకాయ లాంటివి.
1Stack vs Heap మెమరీ ఆర్కిటెక్చర్

📦 స్టాక్ మెమరీ (Stack):

  • కంపైలర్ ద్వారా స్వయంచాలకంగా నిర్వహించబడుతుంది.
  • అత్యంత వేగవంతమైనది, కానీ పరిమిత పరిమాణం (సాధారణంగా 1MB - 8MB).
  • ఫంక్షన్ ముగియగానే లోకల్ వేరియబుల్స్ తుడిచిపెట్టుకుపోతాయి.

🌐 హీప్ మెమరీ (Heap):

  • ప్రోగ్రామర్ తన చేతులతో కోరినప్పుడు కేటాయించబడుతుంది.
  • సిస్టమ్ RAM పరిమాణమంత భారీ స్థలం అందుబాటులో ఉంటుంది.
  • మనం free() చేసేంత వరకు డేటా మెమరీలోనే శాశ్వతంగా ఉంటుంది.
2malloc() vs calloc() — కేటాయింపు తేడాలు

హీప్ మెమరీని రిక్వెస్ట్ చేయడానికి C లో రెండు ప్రధాన ఫంక్షన్లు ఉన్నాయి:

1. malloc() — Memory Allocation: int *arr = (int*) malloc(5 * sizeof(int)); కేవలం ఒకే పారామీటర్ (మొత్తం బైట్ల సంఖ్య) తీసుకుంటుంది. మెమరీలోని పాత గార్బేజ్ విలువలను తొలగించదు (చాలా వేగవంతమైనది).
2. calloc() — Contiguous Allocation: int *arr = (int*) calloc(5, sizeof(int)); రెండు పారామీటర్లు (ఎలిమెంట్ల సంఖ్య, ఒక్కో ఎలిమెంట్ సైజ్) తీసుకుంటుంది. కేటాయించిన ప్రతి బైట్‌ను సున్నా (0) తో ఇనీషియలైజ్ చేస్తుంది.
C — Dynamic Array with malloc & free ⚡ Try in C Compiler 
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    int n = 5;
    // హీప్‌పై 5 పూర్ణాంకాల మెమరీ కేటాయింపు
    int *arr = (int*) malloc(n * sizeof(int));

    // మెమరీ లభించిందో లేదో తనిఖీ చేయడం తప్పనిసరి!
    if (arr == NULL) {
        printf("ఎర్రర్: మెమరీ కేటాయింపు విఫలమైంది!\n");
        return 1;
    }

    for (int i = 0; i < n; i++) {
        arr[i] = (i + 1) * 10;
        printf("%d ", arr[i]);
    }
    printf("\n");

    // పని ముగిసిన తర్వాత మెమరీని విడుదల చేయడం
    free(arr);
    arr = NULL; // Dangling pointer నివారణ
    return 0;
}
3realloc() — రన్‌టైమ్‌లో అర్రే సైజును రీసైజ్ చేయడం

మీరు మొదట 5 ఎలిమెంట్స్ కోసం మెమరీ కేటాయించారు, కానీ రన్‌టైమ్‌లో యూజర్ మరిన్ని విలువలను నమోదు చేయాలనుకుంటే పాత డేటా నష్టపోకుండా మెమరీని విస్తరించడానికి realloc() అద్భుతంగా పనిచేస్తుంది:

C — realloc Dynamic Growth ⚡ Try in C Compiler 
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    int *ptr = (int*) malloc(2 * sizeof(int));
    ptr[0] = 10; ptr[1] = 20;

    // సైజును 2 నుండి 4 కి విస్తరించడం
    int *temp = (int*) realloc(ptr, 4 * sizeof(int));
    if (temp != NULL) {
        ptr = temp;
        ptr[2] = 30; ptr[3] = 40;
        printf("విస్తరించిన అర్రే: %d %d %d %d\n", ptr[0], ptr[1], ptr[2], ptr[3]);
    }

    free(ptr);
    ptr = NULL;
    return 0;
}
4free() ప్రాముఖ్యత & మెమరీ లీక్స్ (Memory Leaks) ప్రమాదం

C లాంగ్వేజ్‌లో Java లేదా Python లాగా వెనుక తిరిగే Garbage Collector ఉండదు. మీరు malloc ద్వారా తీసుకున్న ప్రతి బైట్ మెమరీని ప్రోగ్రామ్ ముగిసేలోపు free(ptr) తో ఆపరేటింగ్ సిస్టమ్‌కు తిరిగి అప్పగించాలి.

💥 మెమరీ లీక్ (Memory Leak) అంటే ఏమిటి?

ఒక ఫంక్షన్ లోపల malloc చేసి, ఆ పాయింటర్‌ను free() చేయకుండా ఫంక్షన్ ముగిస్తే, ఆ మెమరీకి సంబంధించిన అడ్రస్ పోతుంది కానీ RAM లో ఆ స్థలం అలాగే బ్లాక్ అయి ఉంటుంది. నిరంతరం రన్ అయ్యే వెబ్ సర్వర్లలో లేదా గేమింగ్ ఇంజిన్లలో ఇలా మెమరీ లీక్స్ జరిగితే కొన్ని గంటల్లోనే సిస్టమ్ RAM అంతా నిండిపోయి సర్వర్ క్రాష్ అవుతుంది (Out of Memory Crash).

5బిగినర్స్ చేసే ఘోరమైన తప్పులు (Beginner Pitfalls)
❌ 1. డబుల్ ఫ్రీ (Double Free Crash):
free(ptr); free(ptr); // CRASH! free(): double free detected ఇప్పటికే విడుదల చేసిన పాయింటర్‌ను మళ్లీ ఫ్రీ చేస్తే రన్‌టైమ్ ఎర్రర్ వస్తుంది. మొదటిసారి ఫ్రీ చేసిన వెంటనే ptr = NULL; చేస్తే C లో free(NULL) ఎటువంటి ప్రమాదం కలిగించదు.
❌ 2. స్టాక్ వేరియబుల్స్‌ను free చేయడానికి ప్రయత్నించడం:
int x = 10; free(&x); // ఘోరమైన అక్రమ చర్య! free() ఫంక్షన్ కేవలం malloc, calloc, లేదా realloc ద్వారా హీప్‌పై తీసుకున్న అడ్రస్‌లపై మాత్రమే పనిచేస్తుంది.
6తరచుగా అడిగే ప్రశ్నలు (FAQ)

Q: C లో malloc రిటర్న్ వాల్యూను టైప్ కాస్ట్ (int*) చేయడం తప్పనిసరా?

స్వచ్ఛమైన C లో void* ఏ ఇతర పాయింటర్ కైనా ఆటోమేటిక్‌గా ఇంప్లిసిట్‌గా కన్వర్ట్ అవుతుంది కాబట్టి int *p = malloc(...) అని నేరుగా రాయవచ్చు. అయితే C++ కంపైలర్లలో ఎక్స్‌ప్లిసిట్ కాస్టింగ్ తప్పనిసరి.

Q: malloc(0) అని రాస్తే ఏం జరుగుతుంది?

C స్టాండర్డ్ ప్రకారం ఇది అమలుపై ఆధారపడి ఉంటుంది (Implementation Defined). కంపైలర్ NULL రిటర్న్ చేయవచ్చు లేదా free() చేయదగిన ఒక ప్రత్యేకమైన నాన్-నల్ పాయింటర్‌ను ఇవ్వవచ్చు. అయితే దాన్ని డీరిఫరెన్స్ చేయకూడదు.
