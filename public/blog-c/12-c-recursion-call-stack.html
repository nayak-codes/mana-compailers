రికార్షన్ (Recursion) & కాల్ స్టాక్ మెకానిక్స్

⚡ Modern C (C99 / C11) 🟢 Chapter 12 of 20 📂 Phase 03: ఫంక్షన్స్, స్కోప్ & రికర్షన్ 📅 2026 Edition
📌 Covered in this chapter: బేస్ కండిషన్ ప్రాముఖ్యత · ఫ్యాక్టోరియల్ & ఫిబోనాకి కాల్ ట్రీ · స్టాక్ ఓవర్‌ఫ్లో (Stack Overflow) ఎర్రర్ నివారణ
కంప్యూటర్ సైన్స్‌లో అత్యంత శక్తివంతమైన మరియు అందమైన అల్గారిథమిక్ టెక్నిక్ రికార్షన్ (Recursion). ఒక పెద్ద సమస్యను పరిష్కరించడానికి ఒక ఫంక్షన్ తనను తాను మళ్లీ మళ్లీ పిలుచుకోవడమే రికార్షన్. అయితే రికార్షన్‌ను నియంత్రించే బేస్ కండిషన్ (Base Condition) లేకపోతే కంప్యూటర్ మెమరీ నిండిపోయి స్టాక్ ఓవర్‌ఫ్లో (Stack Overflow) క్రాష్ ఎలా సంభవిస్తుందో, ఫ్యాక్టోరియల్ మరియు ఫిబోనాకి కాల్ ట్రీల ద్వారా లోతుగా నేర్చుకుందాం.
1రికార్షన్ 2 మూలస్తంభాలు — బేస్ కండిషన్ & రికర్సివ్ స్టెప్

ఏదైనా రికర్సివ్ ఫంక్షన్ సరిగ్గా పనిచేయాలంటే అది ఖచ్చితంగా రెండు నియమాలను కలిగి ఉండాలి:

1. బేస్ కండిషన్ (The Base Case):

ఇది రికార్షన్ ఆగాల్సిన గమ్యస్థానం. ఫంక్షన్ ఇకపై తనను తాను పిలవకుండా ఖచ్చితమైన సమాధానాన్ని రిటర్న్ చేసి వెనక్కి మళ్ళే షరతు (ఉదా: if (n <= 1) return 1;).

2. రికర్సివ్ స్టెప్ (The Recursive Step):

సమస్య పరిమాణాన్ని కుదిస్తూ (Reducing problem size) బేస్ కండిషన్ దిశగా తీసుకువెళ్లే పిలుపు (ఉదా: n * factorial(n - 1)).

C — Recursive Factorial ⚡ Try in C Compiler 
#include <stdio.h>

long long factorial(int n) {
    // బేస్ కండిషన్
    if (n <= 1) {
        return 1;
    }
    // రికర్సివ్ కాల్
    return n * factorial(n - 1);
}

int main(void) {
    int num = 5;
    printf("%d యొక్క ఫ్యాక్టోరియల్ = %lld\n", num, factorial(num));
    return 0;
}
2కాల్ స్టాక్ విజువలైజేషన్ & స్టాక్ ఫ్రేమ్‌ల పేర్చివేత (Call Tree Trace)

factorial(4) పిలిచినప్పుడు RAM కాల్ స్టాక్‌లో రెండు విభిన్న దశలు జరుగుతాయి:

దశ 1: వైండింగ్ ఫేజ్ (Winding Phase - ఫార్వర్డ్ కాల్స్):

factorial(4) ➔ factorial(3) ➔ factorial(2) ➔ factorial(1). ప్రతి కాల్‌కు కొత్త స్టాక్ ఫ్రేమ్ మెమరీలో పేర్చబడుతుంది.

దశ 2: అన్‌వైండింగ్ ఫేజ్ (Unwinding Phase - ఫలితాల రిటర్న్):

బేస్ కండిషన్ factorial(1) = 1 రీచ్ అవ్వగానే ఫ్రేమ్‌లు పాప్ అవుతూ గుణకారం పూర్తవుతుంది: 1 ➔ 2 * 1 = 2 ➔ 3 * 2 = 6 ➔ 4 * 6 = 24.

3స్టాక్ ఓవర్‌ఫ్లో (Stack Overflow) ఎర్రర్ నివారణ

బేస్ కండిషన్ రాయడం మర్చిపోయినా లేదా ఇన్పుట్ సైజ్ చాలా పెద్దదై వేల సంఖ్యలో రికర్సివ్ కాల్స్ జరిగినా, కాల్ స్టాక్ కోసం OS కేటాయించిన మెమరీ (8MB) పూర్తిగా నిండిపోతుంది.

💥 Segmentation fault (core dumped):

స్టాక్ బౌండరీ దాటి పక్కనున్న మెమరీ గార్డ్ పేజీలోకి వెళ్ళిన క్షణంలో ఆపరేటింగ్ సిస్టమ్ ప్రోగ్రామ్‌ను బలవంతంగా క్రాష్ చేస్తుంది. దీనినే Stack Overflow అంటారు.

⚖️ లూప్స్ vs రికార్షన్ (Comparison Matrix):

లక్షణం లూప్స్ (Iteration) రికార్షన్ (Recursion)
మెమరీ వినియోగం $O(1)$ స్థిరమైన మెమరీ $O(N)$ స్టాక్ ఫ్రేమ్‌ల మెమరీ ఓవర్‌హెడ్
వేగం (Speed) అత్యంత వేగవంతమైనది ఫంక్షన్ కాల్ ఓవర్‌హెడ్ వల్ల కొద్దిగా నెమ్మది
కోడ్ పరిశుభ్రత ట్రీస్/గ్రాఫ్స్‌కు సంక్లిష్టమైన కోడ్ డివైడ్ & కాంకర్ సమస్యలకు అత్యంత సూక్ష్మమైన కోడ్
4బిగినర్స్ చేసే ఘోరమైన తప్పులు (Beginner Pitfalls)
❌ 1. బేస్ కండిషన్ లేకపోవడం:
బేస్ కండిషన్ లేకపోతే అనంతమైన రికర్సివ్ కాల్స్‌తో ప్రోగ్రామ్ తక్షణమే క్రాష్ అవుతుంది.
❌ 2. ఫిబోనాకి డూప్లికేట్ కాల్స్ ట్రాప్:
fib(n-1) + fib(n-2) అని రాస్తే ఒకే విలువను లెక్కించడానికి వందల సార్లు డూప్లికేట్ కాల్స్ జరిగి $O(2^N)$ తో సిస్టమ్ ఫ్రీజ్ అవుతుంది. డైనమిక్ ప్రోగ్రామింగ్ లేదా లూప్స్ వాడాలి.
5తరచుగా అడిగే ప్రశ్నలు (FAQ)

Q: Tail Recursion అంటే ఏమిటి? కంపైలర్ దాన్ని ఎలా ఆప్టిమైజ్ చేస్తుంది?

ఒక రికర్సివ్ ఫంక్షన్‌లో రికర్సివ్ కాల్ అనేది ఆ ఫంక్షన్ యొక్క ఆఖరి స్టేట్‌మెంట్ అయితే దాన్ని Tail Recursion అంటారు. ఆధునిక GCC కంపైలర్లు (Tail Call Optimization - TCO) ద్వారా కొత్త స్టాక్ ఫ్రేమ్స్ సృష్టించకుండా దాన్ని స్వయంచాలకంగా ఒక సాధారణ లూప్‌గా మార్చి మెమరీని ఆదా చేస్తాయి.

Q: పరిశ్రమల్లో రియల్-వరల్డ్ ప్రాజెక్టులలో రికార్షన్‌ను ఎక్కడ వాడతారు?

ఫైల్ సిస్టమ్ డైరెక్టరీలను ట్రావర్స్ చేయడానికి, JSON / XML పార్సింగ్ చేయడానికి, బైనరీ సెర్చ్ ట్రీస్ (BST) మరియు క్విక్ సార్ట్ (QuickSort), మెర్జ్ సార్ట్ (MergeSort) వంటి అల్గారిథమ్‌లలో రికార్షన్ విస్తృతంగా వాడతారు.
