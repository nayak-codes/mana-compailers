వేరియబుల్స్‌పై లెక్కలు చేయడానికి, పరిస్థితులను సరిపోల్చడానికి మరియు కంప్యూటర్ బిట్లను మార్చడానికి ఆపరేటర్లు (Operators) ప్రాణాధారం. ఇంటర్వ్యూలలో ఎక్కువగా అడిగే ++i vs i++ అంతర్గత అసెంబ్లీ తేడా, షార్ట్-సర్క్యూట్ మూలసూత్రం, బిట్‌వైజ్ ఆపరేటర్లు మరియు ప్రెసిడెన్స్ నియమాలను ఈ అధ్యాయంలో లోతుగా పరిశీలిద్దాం.
1Prefix (++i) vs Postfix (i++): అంతర్గత మెమరీ తేడా

చాలామంది ++i మరియు i++ రెండూ ఒకే విధంగా వేరియబుల్ విలువను 1 పెంచుతాయని అనుకుంటారు. కానీ అవి ఎక్స్‌ప్రెషన్‌లో పాల్గొన్నప్పుడు CPU రిజిస్టర్లలో జరిగే ప్రక్రియ పూర్తిగా భిన్నం:

⚡ Prefix (++i): Increment Then Fetch

ముందుగా మెమరీలోని విలువను వెంటనే 1 పెంచుతుంది (Increment), ఆ తర్వాత ఆ తాజా నవీకరించబడిన విలువను ఎక్స్‌ప్రెషన్‌కు అందిస్తుంది.

int x = 5;
int y = ++x; // x = 6, y = 6

⏳ Postfix (i++): Fetch Then Increment

పాత విలువను ఒక తాత్కాలిక కాపీగా దాచి ఎక్స్‌ప్రెషన్‌కు ఇచ్చేస్తుంది. ఆ తర్వాత మాత్రమే మెమరీలోని అసలు వేరియబుల్‌ను 1 పెంచుతుంది.

int x = 5;
int y = x++; // y = 5 (old copy), x = 6
2Short-Circuit Evaluation: లాజికల్ సేఫ్టీ షీల్డ్

C లాంగ్వేజ్ లాజికల్ ఆపరేటర్లైన && (AND) మరియు || (OR) లలో షార్ట్-సర్క్యూట్ ఎవాల్యుయేషన్ అనే అద్భుతమైన ఆప్టిమైజేషన్‌ను అనుసరిస్తుంది. మొదటి కండిషన్ ఫలితంతోనే మొత్తం సమాధానం ఖరారైపోతే, CPU రెండో కండిషన్‌ను అస్సలు టచ్ చేయదు!

🛡️ పాయింటర్ల రక్షణ కవచం (Real-World Safety Guard):

if (ptr != NULL && *ptr > 0)
ఒకవేళ పాయింటర్ ptr శూన్యం (NULL) అయితే, ఎడమ వైపు కండిషన్ తప్పు (0) అవుతుంది. కాబట్టి C కంపైలర్ కుడివైపు ఉన్న *ptr ను యాక్సెస్ చేయడానికి ప్రయత్నించదు! ఒకవేళ షార్ట్-సర్క్యూట్ లేకపోతే NULL పాయింటర్‌ను డీరిఫరెన్స్ చేసి ఆపరేటింగ్ సిస్టమ్ ప్రోగ్రామ్‌ను వెంటనే క్రాష్ చేస్తుంది.

3బిట్‌వైజ్ ఆపరేటర్లు (Bitwise Operators & Hardware Control)

ఎంబెడెడ్ సిస్టమ్స్ మరియు ఆపరేటింగ్ సిస్టమ్స్ ప్రోగ్రామింగ్‌లో మెమరీని మరియు హార్డ్‌వేర్ రిజిస్టర్లను సింగిల్ బిట్ స్థాయిలో నియంత్రించడానికి బిట్‌వైజ్ ఆపరేటర్లు వాడతారు:

ఆపరేటర్ పేరు ఉదాహరణ (a=5, b=3) బైనరీ ఆపరేషన్
& Bitwise AND 5 & 3 = 1 రెండూ 1 అయితేనే ఫలితం 1 (0101 & 0011 = 0001)
| Bitwise OR 5 | 3 = 7 ఏ ఒక్కటి 1 అయినా ఫలితం 1 (0101 | 0011 = 0111)
^ Bitwise XOR 5 ^ 3 = 6 బిట్లు వేర్వేరుగా ఉంటే 1, సమానమైతే 0
<< Left Shift 5 << 1 = 10 బిట్లను ఎడమవైపు జరుపుతుంది (2 తో గుణించడం సమానం)
>> Right Shift 5 >> 1 = 2 బిట్లను కుడివైపు జరుపుతుంది (2 తో భాగించడం సమానం)
4ఇంటిజర్ డివిజన్ ట్రాప్ (5 / 2 = 2) & టైప్ కాస్టింగ్

C లో రెండు పూర్ణాంకాలను భాగిస్తే (5 / 2) వచ్చే ఫలితం పూర్ణాంకం మాత్రమే అవుతుంది. దశాంశ భాగమైన .5 ను C నిర్దాక్షిణ్యంగా తొలగిస్తుంది (Truncation towards zero).

C — Type casting demo ⚡ Try in C Compiler 
#include <stdio.h>

int main(void) {
    int a = 5, b = 2;

    float wrong = a / b;          // 5/2 = 2 -> 2.000000 (తప్పు!)
    float correct = (float)a / b; // ఎక్స్‌ప్లిసిట్ టైప్ కాస్టింగ్ -> 2.500000 (సరైనది!)

    printf("Wrong   : %f\n", wrong);
    printf("Correct : %f\n", correct);
    return 0;
}
5ఆపరేటర్ ప్రాధాన్యతా క్రమం (Precedence Hierarchy)

ఒక ఎక్స్‌ప్రెషన్‌లో బహుళ ఆపరేటర్లు ఉన్నప్పుడు ఏది ముందు లెక్కించబడుతుందో నిర్ణయించే ప్రాధాన్యతా క్రమం (Precedence Ladder):

1. అత్యున్నత ప్రాధాన్యత: బ్రాకెట్లు (), అర్రే ఇండెక్స్ [], మెంబర్ యాక్సెస్ ., ->
2. యునరీ ఆపరేటర్లు: ++, --, !, ~, sizeof, పాయింటర్ *, అడ్రస్ &
3. గుణకార ఆపరేటర్లు: *, /, మాడ్యులో %
4. సంకలన ఆపరేటర్లు: కూడిక +, తీసివేత -
5. రిలేషనల్ & కంపారిజన్: <, <=, >, >= మరియు ==, !=
6. లాజికల్ ఆపరేటర్లు: && (AND) తర్వాతి స్థానంలో || (OR)
7. అత్యల్ప ప్రాధాన్యత: అసైన్‌మెంట్ =, +=, -=, *=

💡 గోల్డెన్ రూల్: ప్రెసిడెన్స్ రూల్స్ పై సందేహం ఉన్నప్పుడు ఎల్లప్పుడూ బ్రాకెట్లను ( ... ) ఉపయోగించడం ఉత్తమ ఇంజనీరింగ్ పద్ధతి.

6బిగినర్స్ చేసే ఘోరమైన తప్పులు (Beginner Pitfalls)
❌ 1. if కండిషన్‌లో = బదులు == వాడడం మర్చిపోవడం:
if (x = 5) { ... } // తప్పు! ఇది ఎల్లప్పుడూ TRUE అవుతుంది! సింగిల్ ఈక్వల్స్ = అసైన్‌మెంట్ చేస్తుంది (x లోకి 5 వేస్తుంది). అది నాన్-జీరో కాబట్టి కండిషన్ ఎప్పటికీ సత్యమే అవుతుంది. పోల్చడానికి ఎల్లప్పుడూ డబుల్ ఈక్వల్స్ == వాడాలి.
❌ 2. ఫ్లోటింగ్ పాయింట్ సంఖ్యలకు మాడ్యులో % వాడడం:
float rem = 5.5 % 2; // కంపైలర్ ఎర్రర్! C లో % ఆపరేటర్ కేవలం పూర్ణాంకాలపై (integers) మాత్రమే పనిచేస్తుంది. ఫ్లోట్ శేషం కావాలంటే <math.h> లోని fmod() ఫంక్షన్ వాడాలి.
7తరచుగా అడిగే ప్రశ్నలు (FAQ)

Q: for లూప్‌లో i++ కంటే ++i వాడితే ఏమైనా స్పీడ్ పెరుగుతుందా?

ప్రిమిటివ్ ఇంటిజర్లకు ఆధునిక ఆప్టిమైజింగ్ కంపైలర్లు రెండింటికీ ఒకే విధమైన అసెంబ్లీ కోడ్ ఉత్పత్తి చేస్తాయి. అయితే C++ లో హెవీ ఆబ్జెక్ట్ ఇటరేటర్లతో పనిచేసేటప్పుడు టెంపరరీ ఆబ్జెక్ట్ కాపీ అవసరం లేని ++i వాడటమే ఉత్తమ అలవాటు.

Q: Bitwise Left Shift (x << 1) ఎందుకు x * 2 కంటే వేగవంతమైనది?

పాత ప్రాసెసర్లలో గుణకారం (Multiplication) చేయడానికి బహుళ క్లాక్ సైకిల్స్ పట్టేది. కానీ షిఫ్ట్ ఆపరేషన్ కేవలం ఒకే ఒక్క సింగిల్ సైకిల్ బారెల్ షిఫ్టర్‌తో ముగుస్తుంది. ఆధునిక కంపైలర్లు కూడా మీరు x * 2 అని రాస్తే అంతర్గతంగా x << 1 గా మారుస్తాయి.
