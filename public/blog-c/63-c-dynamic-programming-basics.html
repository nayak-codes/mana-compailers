Dynamic Programming (DP) Basics (తెలుగులో)

⚡ C (C17 / C23 Standard) 🟢 Lesson 63 📂 Phase 20: Algorithms & Final 📅 2026 Comprehensive Master Edition
📌 Covered in this in-depth guide: Recursion vs DP · Memoization (Top-down) · Tabulation (Bottom-up) · Fibonacci DP

మామూలుగా మనం Recursion (రికర్షన్) వాడి ప్రాబ్లమ్స్ సాల్వ్ చేస్తాం. కానీ రికర్షన్ లో ఒక పెద్ద ప్రాబ్లమ్ ఉంది! ఒకసారి చేసిన లెక్కనే, అది పిచ్చోడిలాగా మళ్ళీ మళ్ళీ చేస్తూనే ఉంటుంది. దీనివల్ల టైమ్ వేస్ట్ అయిపోయి 40వ నంబర్ కనుక్కోవడానికే గంటల టైమ్ పడుతుంది. ఇక్కడే Dynamic Programming (DP) అనే అద్భుతమైన కాన్సెప్ట్ వస్తుంది. "ఒకసారి ఆన్సర్ కనుక్కున్నాక, దాన్ని ఒక బుక్ లో రాసుకుని గుర్తుపెట్టుకో, మళ్ళీ చేయొద్దు" అని చెప్పేదే డైనమిక్ ప్రోగ్రామింగ్. గూగుల్ మ్యాప్స్ లో రూట్స్ కనుక్కోవాలన్నా ఈ DP నే వాడతారు. అదెలాగో ఈరోజు ఫిబొనాచీ (Fibonacci) సిరీస్ తో చూద్దాం.

1 రికర్షన్ లో ఉన్న పిచ్చితనం (Overlapping Subproblems)

ఫిబొనాచీ (Fibonacci) అంటే ముందు రెండు నంబర్స్ ని కలిపితే నెక్స్ట్ నంబర్ వస్తుంది (0, 1, 1, 2, 3, 5, 8...). దీనికి fib(n) = fib(n-1) + fib(n-2) అని ఫార్ములా వాడి రికర్షన్ రాస్తాం.

🧠 రియల్ లైఫ్ స్టోరీ: ఒకే లెక్క మళ్ళీ మళ్ళీ...

మీరు ఒక చిన్న పిల్లాడిని పిలిచి "బాబు 2+2 ఎంత?" అని అడిగారు. వాడు వేళ్ల మీద లెక్కపెట్టి "4" అని చెప్పాడు. ఆ తర్వాత వెంటనే "బాబు 2+2+1 ఎంత?" అని అడిగారు. వాడు ఏం చేయాలి? "ఇందాకే 4 అన్నావు కదా, దానికి 1 కలిపితే 5" అని టక్కున చెప్పాలి (ఇదే Dynamic Programming).

కానీ ఆ పిల్లాడు పిచ్చోడైతే ఏం చేస్తాడు? మళ్ళీ మొదటినుండి "1, 2, 3, 4.. దానికి ఇంకో 1 కలిపితే 5" అని మొత్తం లెక్క పెడతాడు! (ఇదే నార్మల్ Recursion). రికర్షన్ ట్రీ లో పాత లెక్కలని మర్చిపోయి మళ్ళీ చేయడం వల్ల fib(50) కనుక్కోవడానికి సంవత్సరాల టైమ్ పడుతుంది!

2 DP లో రెండు పద్ధతులు (Memoization & Tabulation)

1. మెమోయిజేషన్ (Memoization / Top-Down): ఇది రికర్షన్ కి ఒక మెమరీ (అర్రే) ని తగిలిస్తుంది. ఒకసారి లెక్క కనుక్కోగానే దాన్ని నోట్ బుక్ (Array) లో రాసుకుంటాం. మళ్ళీ ఆ లెక్క వచ్చినప్పుడు, ఆన్సర్ నోట్ బుక్ లో ఉంటే డైరెక్ట్ గా ఇచ్చేస్తాం, లేకపోతేనే లెక్క చేస్తాం!

2. ట్యాబులేషన్ (Tabulation / Bottom-Up): ఇది అసలు రికర్షన్ కే పోదు. డైరెక్ట్ గా ఒక ఫర్ లూప్ (for loop) వేసుకుని, కింద నుండి (0 నుండి) లెక్క చేసుకుంటూ పైకి వస్తుంది. ఇది ఇంకా చాలా ఫాస్ట్!

3 ఒకే ఒక సింపుల్ కోడ్ (Fibonacci with DP)

కింద కోడ్ లో నార్మల్ రికర్షన్ కి, DP కి మధ్య స్పీడ్ డిఫరెన్స్ ఎలా ఉందో చూడండి. memo అనే ఒక చిన్న అర్రే యాడ్ చేస్తే చాలు, కోడ్ రాకెట్ లాగా దూసుకెళ్తుంది.

C — Dynamic Programming (Memoization) ▶ Run Code 
#include <stdio.h>

// మనం ఒక నోట్ బుక్ (అర్రే) తయారుచేద్దాం (మ్యాక్స్ 100 దాకా)
// మొదట్లో అన్నీ -1 తో నింపుదాం (అంటే ఏ ఆన్సర్ తెలీదని అర్థం)
int memo[100];

// మామూలు రికర్షన్ (స్లో) - అర్థం చేసుకోవడానికి మాత్రమే!
int fibSlow(int n) {
    if (n <= 1) return n;
    return fibSlow(n - 1) + fibSlow(n - 2);
}

// డైనమిక్ ప్రోగ్రామింగ్ రికర్షన్ (సూపర్ ఫాస్ట్!)
long long fibDP(int n) {
    if (n <= 1) return n;
    
    // ఆన్సర్ కోసం నోట్ బుక్ చెక్ చేద్దాం! 
    // -1 కాకుండా వేరే నంబర్ ఉందంటే, ఆన్సర్ ఆల్రెడీ చేసేసినట్టే!
    if (memo[n] != -1) {
        return memo[n]; // డైరెక్ట్ గా ఆన్సర్ ఇచ్చేయ్ (టైమ్ సేవ్)
    }
    
    // ఒకవేళ ఆన్సర్ లేకపోతే, అప్పుడు లెక్క చేసి నోట్ బుక్ లో రాయి
    memo[n] = fibDP(n - 1) + fibDP(n - 2);
    
    return memo[n]; // రాసిన దాన్ని రిటర్న్ చేయి
}

int main() {
    printf("--- Dynamic Programming (DP) ---\n\n");
    
    // నోట్ బుక్ అంతా -1 (ఖాళీ) చేద్దాం
    for (int i = 0; i < 100; i++) {
        memo[i] = -1;
    }
    
    int num = 45; // 45 వ నంబర్ కనుక్కోవాలి
    
    // [గమనిక: fibSlow(45) రన్ చేస్తే మీ కంప్యూటర్ దాదాపు 10 సెకన్లు ఫ్రీజ్ అవుతుంది]
    // printf("Slow Recursive Answer: %d\n", fibSlow(num)); 
    
    // కానీ DP వాడితే... 0.0001 సెకనులో ఆన్సర్ వస్తుంది!
    printf("DP Fast Answer for fib(%d) : %lld\n", num, fibDP(num));
    
    return 0;
}
4 కోడ్ లో ఏం జరుగుతోంది? (Step-by-Step)
  • memo[100]: ఇది గ్లోబల్ అర్రే. ఇందులో ఇండెక్స్ అంటే n. (ఉదాహరణకు 5వ ఫిబొనాచీ నంబర్ వాల్యూ 5 అనుకుంటే, అది memo[5] = 5 అని సేవ్ అవుతుంది).
  • if (memo[n] != -1) return memo[n];: ఇదే DP కి గుండెకాయ! రికర్షన్ కిందికి వెళ్లేముందు ఇక్కడ బ్రేక్ పడుతుంది. ఆన్సర్ దొరికితే వెంటనే వెనక్కి వచ్చేస్తుంది (O(1) టైమ్). దీనివల్ల fib(40) లాంటివి మళ్ళీ క్యాలిక్యులేట్ అయ్యే పనే లేదు!
  • memo[n] = ...: ఆన్సర్ కనుక్కున్నాక, దాన్ని నెక్స్ట్ టైమ్ కోసం సేవ్ చేసి పెట్టుకుంటుంది.
5 ఇంటర్వ్యూలలో అడిగే కామన్ ప్రశ్నలు (FAQ)

Q1: DP కి Time Complexity (టైమ్) ఎంత?

నార్మల్ రికర్షన్ కి O(2^N) పడుతుంది (అంటే n=50 ఇస్తే కోట్లు టైమ్ పడుతుంది). కానీ DP కి కేవలం O(N) పడుతుంది! అంటే మీరు n=50 ఇస్తే కేవలం 50 సార్లు మాత్రమే లెక్క చేసి పడేస్తుంది. దట్స్ ద పవర్ ఆఫ్ DP!

Q2: DP ఎక్కడ పడితే అక్కడ వాడొచ్చా?

వాడలేం! దీనికి రెండు రూల్స్ ఉన్నాయి. 1. Overlapping Subproblems: పాత లెక్కలే మళ్ళీ మళ్ళీ రిపీట్ అవ్వాలి (ఇప్పుడు చూసింది). 2. Optimal Substructure: ఒక పెద్ద ప్రాబ్లమ్ ని చిన్న ముక్కలుగా చేసి, ఆ చిన్న ఆన్సర్స్ కలిపితే పెద్ద ఆన్సర్ రావాలి. ఈ రెండు ఉంటేనే DP పనిచేస్తుంది.

Q3: Knapsack Problem (బ్యాగ్ లో వస్తువులు నింపడం) ఏంటి?

అది ప్రపంచంలో అత్యంత ఫేమస్ DP క్వశ్చన్! ఒక దొంగ దగ్గర 10 కేజీలు పట్టే సంచి ఉంది. ఇంట్లో 5 వస్తువులు ఉన్నాయి (వాటి బరువు, రేటు వేరువేరుగా ఉంటాయి). ఏయే వస్తువులు పెట్టుకుంటే వాడికి ఎక్కువ డబ్బులు వస్తాయి? దీన్ని కూడా ఒక 2D అర్రే (Tabulation DP) వాడి సెకనులో సాల్వ్ చేసేస్తారు. గూగుల్ ఇంటర్వ్యూస్ లో ఇవి పక్కా అడుగుతారు!
