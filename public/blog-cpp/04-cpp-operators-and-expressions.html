ఆపరేటర్లు & ఎక్స్‌ప్రెషన్స్ (Operators, Precedence & Associativity)

⚡ Modern C++20 / C++17 🟢 Chapter 4 of 20 📂 Phase 1: C++ Basics & Fundamentals 📅 2026 Edition
📌 Covered in this chapter: Arithmetic, Relational & Logical Operators · Prefix (++i) vs Postfix (i++) Deep Dive · Short-Circuit Evaluation (&&, ||) · Bitwise Operators & Flag Masking · Operator Precedence Hierarchy · Integer Division Trap
వేరియబుల్స్‌పై లెక్కలు చేయాలన్నా, రెండు విలువలను పోల్చాలన్నా, లేదా హార్డ్‌వేర్ లెవల్‌లో బిట్లను మార్చాలన్నా ఆపరేటర్లు (Operators) ప్రాణాధారం. ఈ అధ్యాయంలో ఇంటర్వ్యూలలో ఎక్కువగా అడిగే ++i vs i++ తేడా, షార్ట్-సర్క్యూట్ ఇవాల్యుయేషన్ మరియు ఆపరేటర్ ప్రాధాన్యతా నియమాలను నేర్చుకుందాం.
1Prefix (++i) vs Postfix (i++): అసలైన అంతర్గత తేడా

చాలామంది ++i మరియు i++ రెండూ ఒకటే అనుకుంటారు, ఎందుకంటే రెండూ విలువను 1 పెంచుతాయి. కానీ కంప్యూటర్ మెమరీలో జరిగే ప్రక్రియ పూర్తిగా వేరు:

⚡ Prefix: ++i (Increment Then Use)

ముందుగా మెమరీలోని విలువను వెంటనే 1 పెంచి, ఆ తర్వాత నవీకరించబడిన తాజా విలువనే నేరుగా రిటర్న్ చేస్తుంది. ఎటువంటి తాత్కాలిక కాపీ క్రియేట్ కాదు. అందుకే ఇది అత్యంత వేగవంతమైనది!

🐢 Postfix: i++ (Use Then Increment)

ఇది పాత విలువను ఒక తాత్కాలిక వేరియబుల్‌లో కాపీ చేసుకుంటుంది, ఆ తర్వాత ఒరిజినల్ వేరియబుల్‌ను 1 పెంచుతుంది, కానీ ఈ ఎక్స్‌ప్రెషన్‌కు మాత్రం పాత విలువను ఇస్తుంది. తాత్కాలిక కాపీ వల్ల కొద్దిగా ఓవర్‌హెడ్ ఉంటుంది.

💻 Example 1: Prefix vs Postfix in Action
C++17 ▶ Run in Compiler 
#include <iostream>

int main() {
    int a = 5;
    int b = 5;

    int res1 = ++a; // a becomes 6, res1 receives 6
    int res2 = b++; // res2 receives 5, then b becomes 6

    std::cout << "Prefix:  a = " << a << ", res1 = " << res1 << "\n"
              << "Postfix: b = " << b << ", res2 = " << res2 << "\n";
    return 0;
}
2Short-Circuit Evaluation: లాజికల్ సేఫ్టీ షీల్డ్

C++ లో && (AND) మరియు || (OR) ఆపరేటర్లు షార్ట్-సర్క్యూట్ సూత్రంపై పనిచేస్తాయి:

  • A && B: మొదటి కండిషన్ A గనుక false అయితే, రెండవ కండిషన్ B ని కంపైలర్ అస్సలు టచ్ చేయదు! ఎందుకంటే ఒకటి false అయితే మొత్తం false అని CPU కి ముందే తెలుసు.
  • A || B: మొదటి కండిషన్ A గనుక true అయితే, రెండవ కండిషన్ B ని అస్సలు రన్ చేయదు.

🛡️ Real-World Lifesaver: Crash Prevention

పాయింటర్లు చెక్ చేసేటప్పుడు if (ptr != nullptr && ptr->hasData()) అని రాస్తాం. ఒకవేళ ptr నల్ అయితే మొదటి కండిషన్ ఫెయిల్ అయి అక్కడితో ఆగిపోతుంది; రెండవ పార్ట్ రన్ అవ్వదు కాబట్టి సాఫ్ట్‌వేర్ క్రాష్ అవ్వకుండా సురక్షితంగా రక్షించబడుతుంది!

3ఆపరేటర్ ప్రాధాన్యతా నియమాలు (Operator Precedence)

గణితంలో BODMAS లాగే C++ లో కూడా ఏ ఆపరేటర్ మొదట సాల్వ్ అవ్వాలో కంపైలర్‌కు కచ్చితమైన నియమాలు ఉంటాయి:

Level 1 (Highest): Parentheses & Scope () [] :: . ->
Level 2: Unary Operators ++ -- ! ~ sizeof * (deref) & (address)
Level 3: Multiplicative & Additive * / % (పై లెవల్) | + - (కింది లెవల్)
Level 4: Relational & Equality < <= > >= | == !=
Level 5 (Lowest): Logical & Assignment && | || | = += -= *= /=
4బిగినర్స్ చేసే ఘోరమైన తప్పులు (Beginner Pitfalls)
❌ Trap 1: Integer Division Trap (5 / 2 = 2)

రెండు పూర్ణాంకాలను భాగిస్తే (5 / 2) C++ లో ఫలితం 2 మాత్రమే వస్తుంది (దశాంస భాగం కత్తిరించబడుతుంది). కనీసం ఒక్క వేరియబుల్‌నైనా static_cast<double>(a) / b అని డబుల్‌గా మార్చితేనే కచ్చితమైన 2.5 వస్తుంది!

❌ Trap 2: = (Assignment) vs == (Equality Check)

కండిషన్‌లో if (score == 100) రాయడానికి బదులుగా పొరపాటున if (score = 100) రాస్తే అది ఎప్పటికీ true అవుతుంది! ఎందుకంటే 100 ని అసైన్ చేసి ఆ నాన్-జీరో విలువనే కండిషన్‌గా తీసుకుంటుంది.
