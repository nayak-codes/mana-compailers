Constructors, Destructors & RAII (తెలుగులో)

ఆబ్జెక్ట్ పుట్టుక నుండి మరణం వరకు లైఫ్‌సైకిల్ నిర్వహణ! Default & Parameterized Constructors, Member Initializer List యొక్క అద్భుతమైన స్పీడ్ సీక్రెట్, Copy Constructor, Deep Copy vs Shallow Copy క్రాష్ ప్రమాదాలు, స్టాక్ మెమరీలో LIFO Destructor Execution Order, మరియు ప్రామాణిక Rule of Three / Five.

1 కన్‌స్ట్రక్టర్ (Constructor) అంటే ఏమిటి?

ఒక ఆబ్జెక్ట్ మెమరీలో పుట్టిన వెంటనే దాని వేరియబుల్స్‌ను ప్రారంభించడానికి (Initialize) కంపైలర్ స్వయంచాలకంగా పిలిచే ఒక ప్రత్యేకమైన మెంబర్ ఫంక్షనే Constructor.

[Constructor ప్రాథమిక నియమాలు] 1. కన్‌స్ట్రక్టర్ పేరు ఖచ్చితంగా క్లాస్ పేరుతోనే సమానంగా ఉండాలి. 2. దీనికి ఎలాంటి Return Type ఉండదు (చివరికి void కూడా రాయకూడదు!). 3. ఆబ్జెక్ట్ డిక్లేర్ చేయగానే మనం స్పష్టంగా పిలవాల్సిన పనిలేకుండా ఆటోమేటిక్‌గా రన్ అవుతుంది. 4. దీనిని ఓవర్‌లోడ్ చేయవచ్చు (Overloading: పారామీటర్లను బట్టి వేర్వేరు కన్‌స్ట్రక్టర్లు).
2 కన్‌స్ట్రక్టర్ రకాలు & Member Initializer List సీక్రెట్

C++ లో ప్రధానంగా మూడు రకాల కన్‌స్ట్రక్టర్లు ఉంటాయి:

  • Default Constructor: ఎటువంటి పారామీటర్లు తీసుకోని కన్‌స్ట్రక్టర్ (ఉదా: Player()). మనం ఏ కన్‌స్ట్రక్టర్ రాయకపోతే కంపైలర్ ఉచితంగా డమ్మీ డిఫాల్ట్ కన్‌స్ట్రక్టర్‌ను ఇస్తుంది.
  • Parameterized Constructor: మనం బయటి నుండి పంపే విలువల ఆధారంగా ఆబ్జెక్ట్‌ను ప్రారంభించేది (ఉదా: Player("Arjun", 100)).
  • Copy Constructor: ఇప్పటికే ఉన్న మరొక ఆబ్జెక్ట్ నుండి పూర్తి డూప్లికేట్ ఆబ్జెక్ట్‌ను సృష్టించేది (Player(const Player& other)).
🔥 Member Initializer List (: var(val)) ఎందుకు వాడాలి?
చాలామంది ప్రారంభకులు కన్‌స్ట్రక్టర్ బాడీ లోపల అసైన్ చేస్తుంటారు:
Player(string n, int h) { name = n; health = h; } // ❌ పాత & నెమ్మదైన పద్ధతి!
ఇక్కడ ముందుగా name డమ్మీగా క్రియేట్ అయి, తర్వాత కొత్త స్ట్రింగ్ కాపీ అవుతుంది (రెండు స్టెప్స్!).

దీనికి బదులుగా Modern C++ లో Member Initializer List వాడాలి:
Player(string n, int h) : name(n), health(h) {} // ⚡ సూపర్ ఫాస్ట్ డైరెక్ట్ ఇనిషియలైజేషన్!
ఇది సింగిల్-స్టెప్‌లో డైరెక్ట్‌గా మెమరీని నిర్మిస్తుంది. అంతేకాకుండా const వేరియబుల్స్ మరియు References (&) లను బాడీ లోపల మార్చలేము కాబట్టి, వాటిని కేవలం Member Initializer List ద్వారా మాత్రమే ఇనిషియలైజ్ చేయగలం!
3 Deep Copy vs Shallow Copy (డబుల్ ఫ్రీ క్రాష్ ముప్పు)

మనం ఒక ఆబ్జెక్ట్‌ను మరొక ఆబ్జెక్ట్‌కు కాపీ చేసినప్పుడు (Player p2 = p1;), కంపైలర్ ఇచ్చే డిఫాల్ట్ కాపీ కన్‌స్ట్రక్టర్ రన్ అవుతుంది. మీ క్లాస్‌లో సాధారణ వేరియబుల్స్ (int, double) ఉంటే ఏ సమస్యా లేదు. కానీ హీప్ మెమరీ పాయింటర్లు (Pointers) ఉన్నప్పుడు విపత్తు జరుగుతుంది!

[Shallow Copy Disaster vs Deep Copy Safety] 1. Shallow Copy (డిఫాల్ట్ బిట్‌వైజ్ కాపీ): p1.dataPtr (0x1000) ──┐ ├──► [ HEAP MEMORY: "Secret Data" ] p2.dataPtr (0x1000) ──┘ • సమస్య: రెండు ఆబ్జెక్టులూ ఒకే మెమరీ అడ్రస్‌ను చూపిస్తాయి! • ఫంక్షన్ ముగిసినప్పుడు p2 డిస్ట్రక్టర్ ఆ మెమరీని delete చేస్తుంది. • ఆ తర్వాత p1 డిస్ట్రక్టర్ అదే మెమరీని మళ్ళీ delete చేయబోతుంది! • ఫలితం: 💥 DOUBLE FREE CRASH (Segmentation Fault / Abort)! 2. Deep Copy (కస్టమ్ కాపీ కన్‌స్ట్రక్టర్): p1.dataPtr ──► [ HEAP 1 (0x1000): "Secret Data" ] p2.dataPtr ──► [ HEAP 2 (0x8000): "Secret Data" ] (విడిగా కొత్త మెమరీ!) • రెండు ఆబ్జెక్టులకూ స్వతంత్ర మెమరీ ఉంటుంది; క్రాష్ అయ్యే అవకాశమే లేదు!
💻 Code Example 1: Member Initializer List & Safe Deep Copying

#include <iostream>
#include <string>

class DeepBuffer {
private:
    std::string tag;
    int* data; // డైనమిక్ హీప్ పాయింటర్

public:
    // 1. Parameterized Constructor with Member Initializer List
    DeepBuffer(const std::string& t, int val) 
        : tag(t), data(new int(val)) {
        std::cout << "  [+] Constructor: " << tag << " created with value " << *data 
                  << " at Heap address: " << data << "\n";
    }

    // 2. Custom Copy Constructor for DEEP COPY (Zero Shared Pointer Trap)
    DeepBuffer(const DeepBuffer& other) 
        : tag(other.tag + "_Copy"), data(new int(*other.data)) { // కొత్త హీప్ కేటాయింపు!
        std::cout << "  [+] Deep Copy Constructor: " << tag 
                  << " allocated NEW Heap address: " << data << "\n";
    }

    // 3. Destructor - ఆటోమేటిక్ హీప్ క్లీనప్
    ~DeepBuffer() {
        std::cout << "  [-] Destructor: Cleaning " << tag 
                  << " and freeing Heap address: " << data << "\n";
        delete data;
    }

    void setValue(int v) { *data = v; }
    void print() const {
        std::cout << "    " << tag << " holds value: " << *data << "\n";
    }
};

int main() {
    std::cout << "=== 1. Creating Original Object ===\n";
    DeepBuffer original("Buffer_A", 100);

    std::cout << "\n=== 2. Creating Deep Copy ===\n";
    DeepBuffer cloned = original; // Deep Copy Constructor పిలవబడుతుంది

    std::cout << "\n=== 3. Modifying Clone to Prove Independence ===\n";
    cloned.setValue(999);
    original.print(); // ఒరిజినల్ 100 గానే ఉంటుంది!
    cloned.print();   // క్లోన్ 999 కి మారింది

    std::cout << "\n=== 4. Leaving Scope (Watch Destructors) ===\n";
    return 0;
}

4 డిస్ట్రక్టర్ (Destructor) & LIFO Execution Order

టిల్డే గుర్తు (~) తో మొదలయ్యే ఫంక్షనే Destructor. ఆబ్జెక్ట్ తన జీవితకాలాన్ని ముగించుకొని మెమరీ నుండి తొలగించబడే క్షణంలో ఇది ఆటోమేటిక్‌గా రన్ అవుతుంది. ఫైల్స్ క్లోజ్ చేయడానికి, సాకెట్స్ డిస్‌కనెక్ట్ చేయడానికి, హీప్ మెమరీని విడుదల చేయడానికి ఇది అద్భుతమైన రక్షణ సాధనం.

⚙️ LIFO (Last-In, First-Out) Destructor Order:
స్టాక్ మెమరీలో ఆబ్జెక్టులు ఒకదానిపై ఒకటి పేర్చబడతాయి (Stack of plates). కాబట్టి ఆబ్జెక్టులు ఏ క్రమంలో సృష్టించబడ్డాయో దానికి పూర్తి వ్యతిరేక క్రమంలో (Reverse Order) Destructors రన్ అవుతాయి!
మొదట పుట్టిన ఆబ్జెక్ట్ అన్నింటికంటే చివరగా డిస్ట్రాయ్ అవుతుంది; చివరగా పుట్టిన ఆబ్జెక్ట్ అందరికంటే ముందుగా డిస్ట్రాయ్ అవుతుంది.
5 Rule of Three & Rule of Five సూత్రాలు

ఒక క్లాస్‌లో డైనమిక్ రిసోర్సెస్ (హీప్ పాయింటర్లు, ఫైల్ హ్యాండిల్స్) ఉన్నప్పుడు అనుసరించాల్సిన ముఖ్యమైన సాఫ్ట్‌వేర్ ఇంజనీరింగ్ నియమాలు:

రూల్ చేర్చాల్సిన ఫంక్షన్లు ఎందుకు అవసరం?
Rule of Three (C++98) 1. Destructor
2. Copy Constructor
3. Copy Assignment (operator=)		 వీటిలో ఏదైనా ఒక్కదాన్ని మీరు స్వయంగా రాయాల్సి వస్తే, మిగిలిన రెండింటిని కూడా తప్పక రాయాలి; లేకపోతే డబుల్ ఫ్రీ లేదా మెమరీ లీక్ జరుగుతుంది.
Rule of Five (Modern C++11) Rule of Three +
4. Move Constructor
5. Move Assignment Operator		 లక్షలాది ఎలిమెంట్స్ ఉన్న పెద్ద ఆబ్జెక్టులను కాపీ చేయకుండా పాయింటర్లను వేరొక ఆబ్జెక్ట్‌కు నేరుగా బదిలీ (Move Semantics) చేసి అత్యంత వేగాన్ని సాధించడానికి.
Rule of Zero (బెస్ట్ ప్రాక్టీస్) ఏ ప్రత్యేకమైన డిస్ట్రక్టర్ గానీ కాపీ లాజిక్ గానీ రాయొద్దు. రా పాయింటర్లకు బదులుగా std::unique_ptr, std::string, std::vector వాడండి. అన్నీ కంపైలరే ఆటోమేటిక్‌గా హ్యాండిల్ చేస్తుంది!
💻 Code Example 2: RAII Scope Lifecycle & Reverse LIFO Execution Proof
raii_lifo_order.cpp
⚡ Try in Compiler 
#include <iostream>
#include <string>

class ServerResource {
private:
    std::string serviceName;

public:
    ServerResource(const std::string& name) : serviceName(name) {
        std::cout << "  --> [STARTED] Service: " << serviceName << " initialized.\n";
    }

    ~ServerResource() {
        std::cout << "  <-- [STOPPED] Service: " << serviceName << " shut down safely.\n";
    }
};

void runServerWorkflow() {
    std::cout << "\nEntering runServerWorkflow() Scope...\n";
    ServerResource db("DatabaseConnection"); // 1st created
    ServerResource auth("AuthSecurityToken"); // 2nd created

    {
        std::cout << "\n  [Inner Scope Started]\n";
        ServerResource cache("RedisCacheWorker"); // 3rd created
        std::cout << "  [Inner Scope Ending]\n";
    } // RedisCacheWorker ఇక్కడే డిస్ట్రాయ్ అవుతుంది

    ServerResource logger("AuditLogger"); // 4th created
    std::cout << "\nExiting runServerWorkflow() Scope (Watch Reverse LIFO Order)...\n";
}

int main() {
    std::cout << "=== Demonstrating Constructor & Destructor Execution Order ===\n";
    runServerWorkflow();
    std::cout << "\nWorkflow completely finished. All resources cleaned.\n";
    return 0;
}

❓ Frequently Asked Questions (FAQ)

Q కన్‌స్ట్రక్టర్ బాడీ లోపల అసైన్ చేయడానికి బదులుగా 'Member Initializer List' ఎందుకు వాడాలి?

Member Initializer List (: var(val)) ద్వారా వేరియబుల్స్ డైరెక్ట్‌గా ఆబ్జెక్ట్ మెమరీ క్రియేట్ అయిన క్షణంలోనే ఇనిషియలైజ్ అవుతాయి. బాడీ లోపల అసైన్ చేస్తే ముందు డిఫాల్ట్ ఇనిషియలైజేషన్ జరిగి తర్వాత అసైన్‌మెంట్ జరిగి డబుల్ పని అవుతుంది. ముఖ్యంగా const వేరియబుల్స్ మరియు References (&) ను కేవలం Member Initializer List ద్వారా మాత్రమే ఇనిషియలైజ్ చేయగలం.

Q Shallow Copy కి Deep Copy కి ముఖ్యమైన తేడా ఏమిటి?

క్లాస్‌లో డైనమిక్ మెమరీ పాయింటర్లు ఉన్నప్పుడు కంపైలర్ ఇచ్చే డిఫాల్ట్ కాపీ కేవలం పాయింటర్ అడ్రస్‌ను మాత్రమే కాపీ చేస్తుంది (Shallow Copy); దీనివల్ల రెండు ఆబ్జెక్టులు ఒకే మెమరీని పాయింట్ చేసి 'Double Free' క్రాష్ జరుగుతుంది. Deep Copy లో కాపీ కన్‌స్ట్రక్టర్ స్వయంగా కొత్త హీప్ మెమరీని కేటాయించి అసలైన డేటాను డూప్లికేట్ చేస్తుంది.

Q స్టాక్ లో ఆబ్జెక్టులు డిస్ట్రాయ్ అయ్యేటప్పుడు Destructor ఏ ఆర్డర్ లో రన్ అవుతుంది?

స్టాక్ మెమరీ LIFO (Last-In, First-Out) సూత్రం పై పనిచేస్తుంది కాబట్టి, ఆబ్జెక్టులు ఏ క్రమంలో పుట్టాయో దానికి పూర్తి వ్యతిరేక క్రమంలో (Reverse Order) Destructors ఎగ్జిక్యూట్ అవుతాయి. చివరగా సృష్టించబడిన ఆబ్జెక్ట్ మొదటగా డిస్ట్రాయ్ అవుతుంది.
