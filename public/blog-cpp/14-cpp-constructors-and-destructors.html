Constructors, Destructors & RAII

🌐 Modern C++ (C++20/C++17/C++11) 🟢 Chapter 14 of 20 📂 Phase 04: ఆబ్జెక్ట్ ఓరియెంటెడ్ OOP 📅 2026 Edition
📌 Covered in this chapter: Default, Parameterized & Copy Constructor · Member Initializer Lists · Destructors · Rule of Three / Five / Zero

కంప్యూటర్ మెమరీలో ఒక ఆబ్జెక్ట్ పుట్టడం మరియు గిట్టడం (Object Life and Death) సాఫ్ట్‌వేర్ ఇంజనీరింగ్‌లో అత్యంత పవిత్రమైన ప్రక్రియ. ఒక ఆబ్జెక్ట్ RAM లో సృష్టించబడిన వెంటనే అది గందరగోళ గార్బేజ్ విలువలతో కాకుండా, కచ్చితమైన ప్రాథమిక నిబంధనలతో (Valid Invariants) జన్మించాలి. అలాగే ఆ ఆబ్జెక్ట్ తన పనిని ముగించుకుని నశించే సమయంలో అది ఆక్రమించిన మెమరీని, ఫైల్స్ మరియు నెట్‌వర్క్ సాకెట్లను ఒక్క బైట్ కూడా వృధా కాకుండా స్వయంచాలకంగా క్లీన్ చేయాలి.

ఈ జీవన చక్రాన్ని అద్భుతంగా శాసించే సాధనాలే కన్‌స్ట్రక్టర్లు (Constructors) మరియు డిస్ట్రక్టర్లు (Destructors). వీటితో పాటే C++ ప్రపంచాన్ని శాసించే పవిత్ర నియమాలు: Rule of Three, Rule of Five మరియు Rule of Zero. అంతేకాకుండా భారీ డేటాను కాపీ చేయకుండా మెరుపు వేగంతో బదిలీ చేసే Modern C++11 యొక్క విప్లవాత్మక Move Semantics.

ఈ లోతైన మాస్టర్‌క్లాస్‌లో మనం Default & Parameterized Constructors, Member Initializer Lists యొక్క హై-పెర్ఫార్మెన్స్ మెకానిక్స్, Shallow Copy vs Deep Copy వల్ల వచ్చే డబుల్ ఫ్రీ ప్రమాదాలు, Move Constructors, మరియు లీక్-ఫ్రీ "Enterprise High-Performance Dynamic Matrix Engine" ప్రాజెక్ట్‌ను ప్రత్యక్షంగా నిర్మించి నేర్చుకుందాం!

1 కన్‌స్ట్రక్టర్ల ఆవశ్యకత & ఆబ్జెక్ట్ లైఫ్‌సైకిల్ (Object Lifecycle & Invariants)

C++ లో ఒక క్లాస్ యొక్క ఆబ్జెక్ట్ సృష్టించబడిన తక్షణమే కంపైలర్ చేత స్వయంచాలకంగా (Automatically) అమలు చేయబడే ఒక ప్రత్యేకమైన మెంబర్ ఫంక్షన్‌నే కన్‌స్ట్రక్టర్ (Constructor) అంటారు.

కన్‌స్ట్రక్టర్ యొక్క 3 ప్రధాన నియమాలు:

  1. కన్‌స్ట్రక్టర్ పేరు ఖచ్చితంగా క్లాస్ పేరుతోటే సమానంగా ఉండాలి.
  2. కన్‌స్ట్రక్టర్‌కు ఎటువంటి రిటర్న్ టైప్ ఉండదు (void కూడా రాయకూడదు!).
  3. ఆబ్జెక్ట్ డిక్లేర్ కాగానే ఇది ఆటోమేటిక్‌గా రన్ అవుతుంది; మనం సాధారణ ఫంక్షన్ వలె దీన్ని మాన్యువల్‌గా పిలవలేము.

కన్‌స్ట్రక్టర్ ప్రాథమిక బాధ్యత: ఆబ్జెక్ట్ యొక్క మెంబర్ వేరియబుల్స్‌ను సురక్షితమైన, చెల్లుబాటు అయ్యే విలువలతో ఇనిషియలైజ్ చేసి Class Invariants ను నెలకొల్పడం.

2 డిఫాల్ట్ కన్‌స్ట్రక్టర్ & = default / = delete కీవర్డ్‌లు

ఎటువంటి పారామీటర్లు తీసుకోని కన్‌స్ట్రక్టర్‌ను డిఫాల్ట్ కన్‌స్ట్రక్టర్ (Default Constructor) అంటారు.

మనం మన క్లాస్‌లో ఏ ఒక్క కన్‌స్ట్రక్టర్‌ను కూడా రాయకపోతే, C++ కంపైలర్ మన తరఫున ఒక ఖాళీ డిఫాల్ట్ కన్‌స్ట్రక్టర్‌ను ఉచితంగా అందిస్తుంది (Compiler-Generated Default Constructor).

⚠️ కంపైలర్ డిఫాల్ట్ కన్‌స్ట్రక్టర్ ఎప్పుడు అదృశ్యమవుతుంది?
మీరు మీ క్లాస్‌లో ఏదైనా ఒక్క పారామీటరైజ్డ్ కన్‌స్ట్రక్టర్‌ను రాసిన తక్షణమే, కంపైలర్ తన డిఫాల్ట్ కన్‌స్ట్రక్టర్‌ను ఇవ్వడం శాశ్వతంగా ఆపివేస్తుంది! అప్పుడు మీరు MyClass obj; అని ఆర్గ్యుమెంట్లు లేకుండా సృష్టించడానికి ప్రయత్నిస్తే కంపైలేషన్ ఎర్రర్ వస్తుంది.

Modern C++11 పరిష్కారం: మనం పారామీటరైజ్డ్ కన్‌స్ట్రక్టర్ రాసినప్పటికీ, కంపైలర్ అందించే డిఫాల్ట్ కన్‌స్ట్రక్టర్‌ను స్పష్టంగా కోరడానికి = default; ను, లేదా నిర్దిష్ట ఆపరేషన్‌ను నిషేధించడానికి = delete; ను వాడతాం.

default_constructor_modern.cpp 
#include <iostream>
#include <string>

class ServerNode {
public:
    std::string ipAddress;
    int port;

    // Modern C++11 Explicit Default Constructor
    ServerNode() = default;

    // Parameterized Constructor
    ServerNode(std::string ip, int p) : ipAddress(ip), port(p) {
        std::cout << "  [పారామీటరైజ్డ్ కన్‌స్ట్రక్టర్] నోడ్ ప్రారంభమైంది: " << ipAddress << ":" << port << "\n";
    }
};

int main() {
    ServerNode n1; // = default వల్ల సవ్యంగా పనిచేస్తుంది!
    n1.ipAddress = "127.0.0.1";
    n1.port = 8080;

    ServerNode n2("192.168.1.100", 443);
    return 0;
}

3 పారామీటరైజ్డ్ కన్‌స్ట్రక్టర్లు & Constructor Overloading

ఒక ఆబ్జెక్ట్‌ను సృష్టించే సమయంలోనే మనకు కావలసిన ప్రారంభ విలువలను ఆర్గుమెంట్లుగా పంపడానికి పారామీటరైజ్డ్ కన్‌స్ట్రక్టర్లను (Parameterized Constructors) ఉపయోగిస్తాం.

సాధారణ ఫంక్షన్ల మాదిరిగానే ఒకే క్లాస్‌లో బహుళ కన్‌స్ట్రక్టర్లను వేర్వేరు పారామీటర్లతో రాయడాన్ని Constructor Overloading అంటారు.

constructor_overloading.cpp 
#include <iostream>

class Rectangle {
private:
    double width;
    double height;

public:
    // 1. చతురస్రం కొరకు సింగిల్ పారామీటర్ కన్‌స్ట్రక్టర్
    Rectangle(double side) : width(side), height(side) {
        std::cout << "చతురస్రం సృష్టించబడింది (Side: " << side << ")\n";
    }

    // 2. దీర్ఘచతురస్రం కొరకు డబుల్ పారామీటర్ కన్‌స్ట్రక్టర్
    Rectangle(double w, double h) : width(w), height(h) {
        std::cout << "దీర్ఘచతురస్రం సృష్టించబడింది (" << w << " x " << h << ")\n";
    }

    double getArea() const { return width * height; }
};

int main() {
    Rectangle square(10.0);
    Rectangle rect(20.0, 5.0);

    std::cout << "చతురస్ర వైశాల్యం: " << square.getArea() << "\n";
    std::cout << "దీర్ఘచతురస్ర వైశాల్యం: " << rect.getArea() << "\n";
    return 0;
}

4 మెంబర్ ఇనిషియలైజర్ లిస్ట్ (Member Initializer List) — అత్యంత కీలకమైన కాన్సెప్ట్!

C++ కన్‌స్ట్రక్టర్ బాడీ లోపల అసైన్‌మెంట్ చేయడం ({ this->x = x; }) మరియు మెంబర్ ఇనిషియలైజర్ లిస్ట్ (Member Initializer List: : x(x) {}) వాడటం మధ్య భూమికి ఆకాశానికి ఉన్నంత వ్యత్యాసం ఉంది!

ఎందుకు మెంబర్ ఇనిషియలైజర్ లిస్ట్ వాడాలి?

  1. గరిష్ట వేగం (Zero Redundancy): కన్‌స్ట్రక్టర్ బాడీ మొదలయ్యే సమయానికే అన్ని మెంబర్ వేరియబుల్స్ వాటి డిఫాల్ట్ కన్‌స్ట్రక్టర్లతో పుట్టేస్తాయి! మీరు బాడీ లోపల x = val; అని రాస్తే, అది మొదట డిఫాల్ట్ విలువతో పుట్టి, మళ్లీ కొత్త విలువతో ఓవర్‌రైట్ అవుతుంది (Double Work!). ఇనిషియలైజర్ లిస్ట్ వాడితే డైరెక్ట్‌గా ఒకే ఒక్కసారి సరైన విలువతో జన్మిస్తుంది.
  2. తప్పనిసరి సందర్భాలు (Mandatory Cases):
    • const మెంబర్ వేరియబుల్స్: కాన్స్టంట్ వేరియబుల్స్ ఒకసారి పుట్టాక మార్చలేము. బాడీ లోపల వాటికి విలువ ఇవ్వడం నిషిద్ధం! కేవలం ఇనిషియలైజర్ లిస్ట్‌లోనే ఇవ్వాలి.
    • రిఫరెన్స్ (T&) మెంబర్ వేరియబుల్స్: రిఫరెన్స్‌లను తప్పనిసరిగా ఇనిషియలైజర్ లిస్ట్‌లోనే బైండ్ చేయాలి.
    • డిఫాల్ట్ కన్‌స్ట్రక్టర్ లేని ఇతర క్లాస్ ఆబ్జెక్టులు.
member_initializer_list_power.cpp 
#include <iostream>
#include <string>

class HardwarePort {
private:
    const int portNumber; // const మెంబర్ - బాడీలో అసైన్ చేయలేం!
    std::string& logTarget; // reference మెంబర్ - తప్పనిసరిగా లిస్ట్‌లోనే బైండ్ చేయాలి!
    std::string protocol;

public:
    // మెంబర్ ఇనిషియలైజర్ లిస్ట్ సింటాక్స్:
    HardwarePort(int port, std::string& log, std::string proto)
        : portNumber(port), logTarget(log), protocol(proto) {
        // ఇక్కడ బాడీలో ఏమీ చేయాల్సిన పనిలేదు!
        logTarget += "[Port Initialized: " + std::to_string(portNumber) + "] ";
    }

    void status() const {
        std::cout << "పోర్ట్: " << portNumber << " | ప్రోటోకాల్: " << protocol << "\n";
    }
};

int main() {
    std::string systemLog = "LOG_START -> ";
    HardwarePort p1(8080, systemLog, "HTTPS");
    p1.status();

    std::cout << "సిస్టమ్ లాగ్: " << systemLog << "\n";
    return 0;
}
💡 కంపైలర్ ఆర్డర్ రహస్యం (Order of Initialization Warning): వేరియబుల్స్ మీరు ఇనిషియలైజర్ లిస్ట్‌లో రాసిన క్రమంలో కాకుండా, క్లాస్ లోపల మీరు వాటిని డిక్లేర్ చేసిన ఆర్డర్‌లోనే ఇనిషియలైజ్ అవుతాయి! అందుకే ఎల్లప్పుడూ క్లాస్ డిక్లరేషన్ ఆర్డర్‌లోనే ఇనిషియలైజర్ లిస్ట్‌ను రాయడం సురక్షితమైన పద్ధతి.

5 డెలిగేటింగ్ కన్‌స్ట్రక్టర్లు (Delegating Constructors in C++11)

ఒక క్లాస్‌లో బహుళ కన్‌స్ట్రక్టర్లు ఉన్నప్పుడు, ఒకే రకమైన ఇనిషియలైజేషన్ లాజిక్‌ను ప్రతి కన్‌స్ట్రక్టర్‌లో మళ్లీ మళ్లీ రాయడం వల్ల కోడ్ డూప్లికేషన్ ఏర్పడుతుంది.

దీనిని నివారించడానికి Modern C++11 లో డెలిగేటింగ్ కన్‌స్ట్రక్టర్లు (Delegating Constructors) ప్రవేశపెట్టబడ్డాయి. ఒక కన్‌స్ట్రక్టర్ తన ఇనిషియలైజర్ లిస్ట్ ద్వారా అదే క్లాస్‌లోని మరొక ప్రధాన కన్‌స్ట్రక్టర్‌కు పనిని అప్పగించవచ్చు (Delegate).

delegating_constructor.cpp 
#include <iostream>
#include <string>

class CloudInstance {
public:
    std::string instanceType;
    int cpuCores;
    int ramGB;

    // ప్రధాన టార్గెట్ కన్‌స్ట్రక్టర్
    CloudInstance(std::string type, int cores, int ram)
        : instanceType(type), cpuCores(cores), ramGB(ram) {
        std::cout << "  [CloudInstance Target] " << instanceType 
                  << " (" << cpuCores << " Cores, " << ramGB << " GB RAM)\n";
    }

    // డెలిగేటింగ్ కన్‌స్ట్రక్టర్ 1 (కేవలం టైప్ ఇస్తే చాలు)
    CloudInstance(std::string type) : CloudInstance(type, 2, 4) {}

    // డెలిగేటింగ్ కన్‌స్ట్రక్టర్ 2 (డిఫాల్ట్ మైక్రో ఇన్స్టాన్స్)
    CloudInstance() : CloudInstance("t3.micro", 1, 1) {}
};

int main() {
    CloudInstance c1;                   // డెలిగేట్ చేస్తుంది -> t3.micro
    CloudInstance c2("c5.xlarge");       // డెలిగేట్ చేస్తుంది -> c5.xlarge, 2, 4
    CloudInstance c3("m5.2xlarge", 8, 32); // టార్గెట్ డైరెక్ట్ కాల్
    return 0;
}

6 కాపీ కన్‌స్ట్రక్టర్ & షాలో కాపీ వర్సెస్ డీప్ కాపీ (Shallow vs Deep Copy Hazard)

ఒక ఆబ్జెక్ట్ ఆధారంగా మరొక కొత్త ఆబ్జెక్ట్‌ను సృష్టించేటప్పుడు (MyClass obj2 = obj1;) పిలువబడే ప్రత్యేక కన్‌స్ట్రక్టర్‌నే కాపీ కన్‌స్ట్రక్టర్ (Copy Constructor) అంటారు. 

MyClass(const MyClass& other); // కాపీ కన్‌స్ట్రక్టర్ సింటాక్స్ (తప్పనిసరిగా const reference ఉండాలి)

షాలో కాపీ (Shallow Copy) వల్ల వచ్చే డబుల్ ఫ్రీ వినాశనం:

  • మనం కాపీ కన్‌స్ట్రక్టర్ రాయకపోతే, కంపైలర్ అందించే డిఫాల్ట్ కాపీ కన్‌స్ట్రక్టర్ కేవలం బైట్-టు-బైట్ కాపీ (Shallow Copy) చేస్తుంది.
  • ఒకవేళ మన క్లాస్‌లో డైనమిక్ మెమరీ పాయింటర్ (int* data = new int[100];) ఉంటే, షాలో కాపీ వల్ల రెండు ఆబ్జెక్టులూ ఖచ్చితంగా ఒకే మెమరీ అడ్రస్‌ను చూపిస్తాయి!
  • స్కోప్ ముగిసినప్పుడు మొదటి ఆబ్జెక్ట్ డిస్ట్రక్టర్ ఆ మెమరీని delete చేస్తుంది. రెండవ ఆబ్జెక్ట్ డిస్ట్రక్టర్ అదే మెమరీని మళ్లీ delete చేయడానికి ప్రయత్నించి Double Free Error వచ్చి యాప్ క్రాష్ అవుతుంది!

పరిష్కారం - డీప్ కాపీ (Deep Copy): స్వంతంగా కాపీ కన్‌స్ట్రక్టర్ రాసి, కొత్త ఆబ్జెక్ట్ కొరకు హీప్‌పై కొత్త మెమరీని అలొకేట్ చేసి, అసలు డేటాను సురక్షితంగా కాపీ చేయాలి.

deep_copy_solution.cpp 
#include <iostream>

class DynamicArray {
private:
    int* buffer;
    size_t size;

public:
    DynamicArray(size_t s) : size(s), buffer(new int[s]) {
        std::cout << "  [కన్‌స్ట్రక్టర్] హీప్ మెమరీ కేటాయించబడింది (" << size << " అంశాలు) అడ్రస్: " << buffer << "\n";
    }

    // కస్టమ్ డీప్ కాపీ కన్‌స్ట్రక్టర్ (Deep Copy Constructor)
    DynamicArray(const DynamicArray& other) : size(other.size), buffer(new int[other.size]) {
        for (size_t i = 0; i < size; ++i) {
            buffer[i] = other.buffer[i];
        }
        std::cout << "  [డీప్ కాపీ కన్‌స్ట్రక్టర్] స్వతంత్ర కొత్త మెమరీ కేటాయించబడింది: " << buffer << "\n";
    }

    ~DynamicArray() {
        std::cout << "  [డిస్ట్రక్టర్] మెమరీ విడుదల చేయబడింది: " << buffer << "\n";
        delete[] buffer;
    }

    void set(size_t idx, int val) { buffer[idx] = val; }
    int get(size_t idx) const { return buffer[idx]; }
};

int main() {
    {
        DynamicArray a1(5);
        a1.set(0, 999);

        // a1 ఆధారంగా a2 సృష్టి (డీప్ కాపీ రన్ అవుతుంది!)
        DynamicArray a2 = a1;
        std::cout << "a2[0] విలువ: " << a2.get(0) << "\n";
    } // రెండు ఆబ్జెక్టులూ తమ స్వంత మెమరీని సురక్షితంగా విడుదల చేసుకుంటాయి! డబుల్ ఫ్రీ క్రాష్ లేదు!
    return 0;
}

7 మూవ్ కన్‌స్ట్రక్టర్ & Move Semantics (C++11 Rvalue References &&)

ఆలోచించండి: మీ వద్ద 1 GB డేటా ఉన్న ఒక తాత్కాలిక ఆబ్జెక్ట్ (Temporary Rvalue) ఉంది. దానిని మరొక ఆబ్జెక్ట్‌లోకి తీసుకోవాలంటే డీప్ కాపీ చేయడం వల్ల 1 GB కొత్త మెమరీ అలొకేట్ చేసి, కాపీ చేసి, పాత దాన్ని డిలీట్ చేయాలి — ఇది అత్యంత నెమ్మదైన ప్రక్రియ!

Modern C++11 Move Semantics: తాత్కాలిక ఆబ్జెక్ట్ ఎలాగూ నశించబోతోంది కాబట్టి, కాపీ చేసే బదులు దాని మెమరీ పాయింటర్‌ను కొత్త ఆబ్జెక్ట్‌కు బదిలీ చేసి (Steal/Transfer Ownership), పాత పాయింటర్‌ను nullptr గా మార్చేయవచ్చు! దీనినే మూవ్ కన్‌స్ట్రక్టర్ (Move Constructor) అంటారు.

MyClass(MyClass&& other) noexcept; // Rvalue Reference (&&) సింటాక్స్
move_constructor_demo.cpp 
#include <iostream>
#include <utility> // std::move కొరకు

class HeavyBuffer {
public:
    int* data;
    size_t size;

    HeavyBuffer(size_t s) : size(s), data(new int[s]) {
        std::cout << "  [అలొకేషన్] " << size << " పూర్ణాంకాల మెమరీ కేటాయించబడింది.\n";
    }

    // మూవ్ కన్‌స్ట్రక్టర్ (Move Constructor - Zero Memory Copy!)
    HeavyBuffer(HeavyBuffer&& other) noexcept : data(other.data), size(other.size) {
        other.data = nullptr; // పాత ఆబ్జెక్ట్ నుండి ఓనర్‌షిప్ లాగేసుకున్నాం!
        other.size = 0;
        std::cout << "  ⚡ [MOVE కన్‌స్ట్రక్టర్] పాయింటర్ బదిలీ చేయబడింది! సున్నా ఓవర్‌హెడ్!\n";
    }

    ~HeavyBuffer() {
        if (data != nullptr) {
            std::cout << "  [డిస్ట్రక్టర్] మెమరీ క్లీన్ చేయబడింది.\n";
            delete[] data;
        } else {
            std::cout << "  [డిస్ట్రక్టర్] ఖాళీ మూవ్డ్ ఆబ్జెక్ట్ - ఏమీ చేయలేదు.\n";
        }
    }
};

int main() {
    HeavyBuffer buf1(100000);

    // std::move ద్వారా buf1 ని Rvalue గా మార్చి మూవ్ కన్‌స్ట్రక్టర్‌ను పిలుస్తున్నాం
    HeavyBuffer buf2 = std::move(buf1);

    std::cout << "buf1.data ఇప్పుడు nullptr? " << (buf1.data == nullptr ? "అవును" : "కాదు") << "\n";
    return 0;
}

8 ఎక్స్‌ప్లిసిట్ కన్‌స్ట్రక్టర్లు (explicit Keyword)

C++ లో ఒకే ఒక పారామీటర్ తీసుకునే కన్‌స్ట్రక్టర్ ఉన్నప్పుడు, కంపైలర్ స్వయంచాలకంగా ఇంప్లిసిట్ టైప్ కన్వర్షన్ (Implicit Type Conversion) చేయడానికి ప్రయత్నిస్తుంది.

⚠️ ఇంప్లిసిట్ కన్వర్షన్ వల్ల వచ్చే వింత బగ్:
ఉదాహరణకు class Money { Money(int rupees); }; ఉన్నప్పుడు, ఎవరైనా పొరపాటున Money m = 500; అని రాస్తే లేదా ఫంక్షన్‌కు 500 పాస్ చేస్తే కంపైలర్ ఆటోమేటిక్‌గా ఒక Money ఆబ్జెక్ట్‌ను సృష్టించేస్తుంది. ఇది కోడ్‌లో అనుకోని గందరగోళానికి కారణమవుతుంది.

దీనిని అరికట్టడానికి సింగిల్-ఆర్గుమెంట్ కన్‌స్ట్రక్టర్ల ముందు explicit కీవర్డ్ రాయాలి. అప్పుడు కేవలం ప్రత్యక్షంగా Money m(500); అని పిలిచినప్పుడు మాత్రమే కన్‌స్ట్రక్టర్ అమలవుతుంది.

9 డిస్ట్రక్టర్లు (Destructors: ~ClassName()) & LIFO క్రమం

ఒక ఆబ్జెక్ట్ తన జీవితకాలాన్ని ముగించుకుని మెమరీ నుండి తుడిచిపెట్టుకుపోయే ముందు ఆటోమేటిక్‌గా పిలువబడే క్లీనప్ ఫంక్షన్‌నే డిస్ట్రక్టర్ (Destructor) అంటారు.

డిస్ట్రక్టర్ ముఖ్య లక్షణాలు:

  • పేరు క్లాస్ పేరుతోటే ఉండాలి, కానీ ముందు ~ (Tilde) గుర్తు ఉంటుంది.
  • దీనికి ఎటువంటి పారామీటర్లు ఉండవు, రిటర్న్ టైప్ ఉండదు, మరియు ఓవర్‌లోడింగ్ సాధ్యం కాదు.
  • LIFO (Last-In, First-Out) నాశన క్రమం: స్టాక్ మెమరీలో సృష్టించబడిన ఆబ్జెక్టులు ఏ క్రమంలో పుట్టాయో, వాటికి ఖచ్చితంగా వ్యతిరేక క్రమంలో (Reverse Order) డిస్ట్రక్ట్ అవుతాయి!
destructor_lifo_order.cpp 
#include <iostream>
#include <string>

class Tracer {
private:
    std::string name;
public:
    Tracer(std::string n) : name(n) {
        std::cout << "  🌱 సృష్టించబడింది: " << name << "\n";
    }
    ~Tracer() {
        std::cout << "  🍂 నాశనమైంది (Destructor): " << name << "\n";
    }
};

int main() {
    std::cout << "మెయిన్ ఫంక్షన్ ప్రారంభం...\n";
    Tracer t1("మొదటిది (First)");
    Tracer t2("రెండవది (Second)");
    Tracer t3("మూడవది (Third)");

    std::cout << "స్కోప్ ముగుస్తోంది... LIFO రివర్స్ ఆర్డర్ గమనించండి!\n";
    return 0;
}

10 The Sacred "Rule of Three / Five / Zero" in Modern C++

C++ సాఫ్ట్‌వేర్ ఆర్కిటెక్చర్‌లో మెమరీ లీక్స్ మరియు డబుల్ ఫ్రీ బగ్స్ రాకుండా ఉండటానికి ప్రపంచ ప్రఖ్యాత కమ్యూనిటీ రూపొందించిన మూడు పవిత్ర నియమాలు:

సూత్రం (Rule) ఎప్పుడు వర్తిస్తుంది? మీరు రాయాల్సిన 5 ప్రత్యేక మెంబర్ ఫంక్షన్లు
Rule of Three (C++98) మీ క్లాస్ రా పాయింటర్లను లేదా మాన్యువల్ రిసోర్సులను మేనేజ్ చేస్తుంటే 1. Destructor
2. Copy Constructor
3. Copy Assignment Operator
Rule of Five (C++11) పైన పేర్కొన్న మూడింటితో పాటు Move Semantics పనితీరు కావాలంటే 1. Destructor
2. Copy Constructor
3. Copy Assignment
4. Move Constructor
5. Move Assignment Operator
Rule of Zero (Modern C++) మీ క్లాస్‌లో రా పాయింటర్లకు బదులుగా std::unique_ptr, std::vector, std::string వాడితే ఈ ఐదింటిలో ఒక్కటి కూడా మీరు రాయాల్సిన అవసరం లేదు (Zero)! కంపైలర్ అన్నీ ఆటోమేటిక్‌గా సరిగ్గా నిర్వహిస్తుంది.

11 సాధారణ కన్‌స్ట్రక్టర్/డిస్ట్రక్టర్ డిజైన్ తప్పులు & నివారణ

  1. డిస్ట్రక్టర్ లోపల ఎక్సెప్షన్ విసరడం (Throwing Exceptions in Destructor): డిస్ట్రక్టర్ ఎల్లప్పుడూ noexcept గా ఉండాలి. స్టాక్ అన్‌వైండింగ్ సమయంలో డిస్ట్రక్టర్ నుండి ఎక్సెప్షన్ బయటకు వస్తే ప్రోగ్రామ్ తక్షణమే క్రాష్ (std::terminate) అవుతుంది!
  2. Move Constructor లో పాత పాయింటర్‌ను nullptr చేయకపోవడం: మూవ్ చేసిన తర్వాత పాత ఆబ్జెక్ట్ పాయింటర్‌ను nullptr చేయకపోతే, పాత ఆబ్జెక్ట్ డిస్ట్రక్ట్ అయినప్పుడు అసలు డేటా కూడా డిలీట్ అయిపోతుంది.
  3. మెంబర్ ఇనిషియలైజర్ లిస్ట్ వాడకపోవడం: పెద్ద క్లాసులలో బాడీలో అసైన్‌మెంట్లు రాయడం వల్ల విపరీతమైన రన్‌టైమ్ పెనాల్టీ పడుతుంది.

12 రియల్-వరల్డ్ ప్రాజెక్ట్: Enterprise High-Performance Matrix Memory Engine (Rule of Five & RAII)

నిజ జీవితంలో ఆర్టిఫిషియల్ ఇంటెలిజెన్స్ (AI టెన్సార్లు), గేమ్ ఫిజిక్స్ మరియు సైంటిఫిక్ కంప్యూటింగ్‌లో మిలియన్ల సంఖ్యల మ్యాట్రిక్స్ గణనలు జరుగుతాయి. అక్కడ డైనమిక్ మెమరీ కేటాయింపులు డీప్ కాపీ మరియు మెరుపు వేగవంతమైన మూవ్ సెమాంటిక్స్‌తో నడవాలి.

ఈ ప్రాజెక్ట్‌లో మనం Rule of Five ను సంపూర్ణంగా అమలు చేసే ఒక ఎంటర్‌ప్రైజ్ మ్యాట్రిక్స్ మెమరీ ఇంజిన్ ను నిర్మిస్తున్నాం:

MatrixMemoryEngine.cpp 
#include <iostream>
#include <utility>
#include <algorithm>

class MatrixEngine {
private:
    size_t rows;
    size_t cols;
    double** data;

    void allocateMemory() {
        data = new double*[rows];
        for (size_t i = 0; i < rows; ++i) {
            data[i] = new double[cols]();
        }
    }

    void releaseMemory() {
        if (data != nullptr) {
            for (size_t i = 0; i < rows; ++i) {
                delete[] data[i];
            }
            delete[] data;
            data = nullptr;
        }
    }

public:
    // 1. Parameterized Constructor
    MatrixEngine(size_t r, size_t c) : rows(r), cols(c), data(nullptr) {
        allocateMemory();
        std::cout << "  🏗️ [కన్‌స్ట్రక్టర్] " << rows << "x" << cols << " మ్యాట్రిక్స్ కేటాయించబడింది.\n";
    }

    // 2. Destructor
    ~MatrixEngine() {
        if (data != nullptr) {
            std::cout << "  🗑️ [డిస్ట్రక్టర్] " << rows << "x" << cols << " మ్యాట్రిక్స్ మెమరీ విడుదల చేయబడింది.\n";
            releaseMemory();
        } else {
            std::cout << "  🗑️ [డిస్ట్రక్టర్] మూవ్డ్ మ్యాట్రిక్స్ (No-op).\n";
        }
    }

    // 3. Copy Constructor (Deep Copy)
    MatrixEngine(const MatrixEngine& other) : rows(other.rows), cols(other.cols), data(nullptr) {
        allocateMemory();
        for (size_t i = 0; i < rows; ++i) {
            for (size_t j = 0; j < cols; ++j) {
                data[i][j] = other.data[i][j];
            }
        }
        std::cout << "  📋 [డీప్ కాపీ కన్‌స్ట్రక్టర్] " << rows << "x" << cols << " క్లోన్ చేయబడింది.\n";
    }

    // 4. Move Constructor (Zero-Copy Transfer)
    MatrixEngine(MatrixEngine&& other) noexcept
        : rows(other.rows), cols(other.cols), data(other.data) {
        other.data = nullptr;
        other.rows = 0;
        other.cols = 0;
        std::cout << "  ⚡ [MOVE కన్‌స్ట్రక్టర్] మ్యాట్రిక్స్ పాయింటర్లు మెరుపు వేగంతో బదిలీ చేయబడ్డాయి!\n";
    }

    // 5. Copy Assignment Operator
    MatrixEngine& operator=(const MatrixEngine& other) {
        if (this == &other) return *this; // Self-assignment check
        releaseMemory();
        rows = other.rows;
        cols = other.cols;
        allocateMemory();
        for (size_t i = 0; i < rows; ++i) {
            for (size_t j = 0; j < cols; ++j) {
                data[i][j] = other.data[i][j];
            }
        }
        std::cout << "  📝 [Copy Assignment] అసైన్‌మెంట్ డీప్ కాపీ జరిగింది.\n";
        return *this;
    }

    void set(size_t r, size_t c, double val) {
        if (r < rows && c < cols && data != nullptr) data[r][c] = val;
    }

    void display() const {
        if (data == nullptr) {
            std::cout << "  [ఖాళీ మ్యాట్రిక్స్ - Data was Moved]\n";
            return;
        }
        std::cout << "  మ్యాట్రిక్స్ డేటా (" << rows << "x" << cols << "):\n";
        for (size_t i = 0; i < rows; ++i) {
            std::cout << "    [ ";
            for (size_t j = 0; j < cols; ++j) {
                std::cout << data[i][j] << " ";
            }
            std::cout << "]\n";
        }
    }
};

int main() {
    std::cout << "=======================================================================\n";
    std::cout << "🧮 [HIGH-PERFORMANCE MATRIX RAII & RULE OF FIVE ENGINE]\n";
    std::cout << "=======================================================================\n";

    {
        MatrixEngine m1(2, 3);
        m1.set(0, 0, 1.5);
        m1.set(0, 1, 2.5);
        m1.set(1, 2, 9.9);
        m1.display();

        // డీప్ కాపీ పరీక్ష
        MatrixEngine m2 = m1;
        m2.set(0, 0, 99.0); // m1 మారకూడదు
        std::cout << "\nm2 మార్చిన తర్వాత m1 ని పరిశీలించండి (డీప్ కాపీ నిరూపణ):\n";
        m1.display();

        // Move Semantics పరీక్ష (Zero Copy)
        std::cout << "\nMove Constructor పరీక్ష:\n";
        MatrixEngine m3 = std::move(m1);
        std::cout << "\nm3 (Moved-in):\n";
        m3.display();
        std::cout << "m1 (Moved-out):\n";
        m1.display();
    } // స్కోప్ ముగియగానే అన్నీ లీక్-ఫ్రీగా డిస్ట్రక్ట్ అవుతాయి!

    std::cout << "=======================================================================\n";
    std::cout << "✅ జీరో మెమరీ లీక్స్‌తో రూల్ ఆఫ్ ఫైవ్ ఎగ్జిక్యూషన్ విజయవంతమైంది!\n";
    std::cout << "=======================================================================\n";
    return 0;
}

13 సారాంశం & ఇంటరాక్టివ్ క్విజ్ (Summary & Self-Check Quizzes)

📌 ఈ అధ్యాయంలో నేర్చుకున్న ప్రధాన అంశాలు:

  • Constructors: ఆబ్జెక్ట్ పుట్టిన వెంటనే ఇన్వేరియంట్స్‌ను నెలకొల్పి వేరియబుల్స్‌ను ఇనిషియలైజ్ చేసే స్పెషల్ మెథడ్స్.
  • Member Initializer List: బాడీ అసైన్‌మెంట్ల కంటే వేగవంతమైనది. const మరియు రిఫరెన్స్ మెంబర్లకు ఇది తప్పనిసరి.
  • Delegating Constructors: కోడ్ డూప్లికేషన్ లేకుండా ఒక కన్‌స్ట్రక్టర్ నుండి మరొకదాన్ని పిలవడం.
  • Deep vs Shallow Copy: పాయింటర్లు ఉన్నప్పుడు షాలో కాపీ డబుల్ ఫ్రీ ఎర్రర్‌కు దారితీస్తుంది. డీప్ కాపీ స్వతంత్ర మెమరీని ఇస్తుంది.
  • Move Semantics (C++11): తాత్కాలిక ఆబ్జెక్టుల నుండి మెమరీ పాయింటర్లను దొంగిలించి జీరో-కాపీ వేగంతో ట్రాన్స్‌ఫర్ చేసే Move Constructor.
  • explicit Keyword: అనుకోకుండా జరిగే ప్రమాదకరమైన ఇంప్లిసిట్ టైప్ కన్వర్షన్లను అడ్డుకునే రక్షణ కవచం.
  • Destructors: ఆబ్జెక్ట్ నశించే సమయంలో రివర్స్ LIFO క్రమంలో రన్ అయ్యే క్లీనప్ మెథడ్స్.
  • Rule of Five & Zero: డైనమిక్ రిసోర్స్ మేనేజ్ చేసే క్లాసులలో 5 స్పెషల్ మెథడ్స్ రాయాలి; స్మార్ట్ పాయింటర్లు వాడితే ఏదీ రాయాల్సిన పనిలేదు (Rule of Zero).

🧠 మీ అవగాహనను పరీక్షించుకోండి (5 Interactive Quizzes):

ప్రశ్న 1: కన్‌స్ట్రక్టర్ బాడీ లోపల కాకుండా Member Initializer List లో మాత్రమే తప్పనిసరిగా ఇనిషియలైజ్ చేయాల్సిన మెంబర్లు ఏవి?
సమాధానం: const మెంబర్ వేరియబుల్స్ మరియు రిఫరెన్స్ (T&) మెంబర్ వేరియబుల్స్!
వివరణ: const వేరియబుల్స్ మరియు రిఫరెన్సులను సృష్టించేప్పుడే తప్పనిసరిగా బైండ్ చేయాలి. కన్‌స్ట్రక్టర్ బాడీ మొదలయ్యే సమయానికే అవి డిఫాల్ట్‌గా పుట్టేయాలి కాబట్టి, బాడీ లోపల వాటికి = అసైన్‌మెంట్ చేయడం కంపైలర్ నిబంధనల ప్రకారం నిషిద్ధం.
ప్రశ్న 2: డైనమిక్ మెమరీ పాయింటర్లు కలిగిన ఒక క్లాస్‌లో డీప్ కాపీ రాయకుండా కంపైలర్ ఇచ్చే డిఫాల్ట్ షాలో కాపీని వాడితే ఏ ప్రమాదం జరుగుతుంది?
సమాధానం: Double Free Error (మెమరీ క్రాష్ / అన్‌డిఫైన్డ్ బిహేవియర్) జరుగుతుంది!
వివరణ: షాలో కాపీలో రెండు ఆబ్జెక్టులూ ఒకే పాయింటర్ అడ్రస్‌ను షేర్ చేసుకుంటాయి. మొదటి ఆబ్జెక్ట్ నశించినప్పుడు ఆ మెమరీ డిలీట్ అవుతుంది; రెండో ఆబ్జెక్ట్ నశించినప్పుడు మళ్లీ అదే అడ్రస్‌ను delete చేయడానికి ప్రయత్నించడం వల్ల సిస్టమ్ క్రాష్ అవుతుంది.
ప్రశ్న 3: Move Constructor లో పాత ఆబ్జెక్ట్ యొక్క పాయింటర్‌ను nullptr గా మార్చడం ఎందుకు అత్యంత ఆవశ్యకం?
సమాధానం: పాత ఆబ్జెక్ట్ డిస్ట్రక్టర్ అసలు మెమరీని డిలీట్ చేయకుండా నిరోధించడానికి!
వివరణ: మూవ్ చేసిన వెంటనే పాత తాత్కాలిక ఆబ్జెక్ట్ స్కోప్ దాటి నాశనమవుతుంది. దాని పాయింటర్ nullptr కాకపోతే, దాని డిస్ట్రక్టర్ మనం కొత్త ఆబ్జెక్ట్‌కు ఇచ్చిన మెమరీని డీఅలొకేట్ చేసేస్తుంది, ఫలితంగా డాంగ్లింగ్ పాయింటర్ ఏర్పడుతుంది.
ప్రశ్న 4: ఒక ఫంక్షన్ లోపల మూడు స్టాక్ ఆబ్జెక్టులు A a; B b; C c; క్రమంలో సృష్టించబడితే, వాటి డిస్ట్రక్టర్లు ఏ క్రమంలో అమలవుతాయి?
సమాధానం: C, B, A (రివర్స్ LIFO ఆర్డర్) లో అమలవుతాయి!
వివరణ: స్టాక్ మెమరీ లాస్ట్-ఇన్-ఫస్ట్-ఔట్ (LIFO) సూత్రంపై పనిచేస్తుంది. చివరగా సృష్టించబడిన ఆబ్జెక్ట్ స్టాక్ పైభాగంలో ఉంటుంది కాబట్టి, స్కోప్ ముగియగానే ముందుగా c, తర్వాత b, చివరగా a డిస్ట్రక్ట్ అవుతాయి.

వివరణ: క్లాస్‌లో రా పాయింటర్లను వాడకుండా std::unique_ptr, std::vector, std::string లను ఉపయోగించినప్పుడు, కంపైలర్ అందించే డిఫాల్ట్ డిస్ట్రక్టర్, కాపీ మరియు మూవ్ మెథడ్స్ అన్నీ 100% బగ్‌లెస్ గా ఆటోమేటిక్‌గా పనిచేస్తాయి. మనం స్వయంగా ఏ ఒక్కటీ రాయాల్సిన అవసరం లేదు.
