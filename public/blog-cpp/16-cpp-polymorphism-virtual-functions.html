పాలిమార్ఫిజమ్ & Virtual Functions (C++ Polymorphism)

ఒకే ఇంటర్‌ఫేస్, విభిన్న ప్రవర్తనలు! Static vs Dynamic Polymorphism, Base Pointer ద్వారా డైనమిక్ డిస్పాచ్, virtual మరియు override కీవర్డ్స్, కంపైలర్ లోపల జరిగే vtable & vptr ఆర్కిటెక్చర్, Virtual Destructors తో జీరో మెమరీ లీక్ గ్యారెంటీ, మరియు Pure Virtual Functions తో Abstract Classes నిర్మాణం.

1 పాలిమార్ఫిజమ్ (Polymorphism) అంటే ఏమిటి?

గ్రీకు భాషలో Poly అంటే అనేక, Morph అంటే రూపాలు. ప్రోగ్రామింగ్‌లో ఒకే ఫంక్షన్ కాల్ వేర్వేరు సందర్భాలలో వేర్వేరు ఆబ్జెక్టుల ఆధారంగా విభిన్నమైన పనులను నిర్వహించగలగడాన్నే పాలిమార్ఫిజమ్ అంటారు.

[రెండు రకాల పాలిమార్ఫిజమ్ (Static vs Dynamic)] 1. Compile-Time (Static) Polymorphism: • కంపైలేషన్ సమయంలోనే ఏ ఫంక్షన్ రన్ అవ్వాలో స్థిరపడిపోతుంది (Early Binding). • ఉదాహరణ: Function Overloading, Operator Overloading, Templates. • ప్రయోజనం: మెరుపు వేగం (Zero Runtime Overhead). 2. Run-Time (Dynamic) Polymorphism: • ప్రోగ్రామ్ రన్ అవుతున్న సమయంలో, Base Pointer ఏ ఆబ్జెక్ట్‌ను చూపిస్తుందో చూసి ఆ ఫంక్షన్ కాల్ అవుతుంది (Late Binding). • సాధించే విధానం: Virtual Functions & Base Pointers (Base* ptr).
2 The Early Binding Trap & virtual కీవర్డ్

ఒక పేరెంట్ పాయింటర్ (Animal*) లో చైల్డ్ ఆబ్జెక్ట్ అడ్రస్‌ను (new Dog()) స్టోర్ చేయవచ్చు. కానీ సాధారణ పద్ధతిలో ptr->makeSound() అని పిలిస్తే, కంపైలర్ పాయింటర్ రకాన్ని మాత్రమే చూసి Animal::makeSound() నే పిలుస్తుంది! దీనినే Early Binding Trap అంటారు.

⚡ Solution: virtual & override
మనం Base క్లాస్ ఫంక్షన్ ముందు virtual అని చేర్చినప్పుడు, కంపైలర్ ఎర్లీ బైండింగ్‌ను ఆపివేసి రన్‌టైమ్ వరకు నిర్ణయాన్ని వాయిదా వేస్తుంది (Dynamic Dispatch). అలాగే Derived క్లాస్‌లో ఆ ఫంక్షన్‌ను తిరిగి రాసేటప్పుడు override అని రాయాలి. స్పెల్లింగ్ పొరపాట్లు లేదా పారామీటర్ తప్పులు జరిగితే கంపైలర్ వెంటనే హెచ్చరిస్తుంది!
3 లోపల ఏం జరుగుతుంది? vtable & vptr ఆర్కిటెక్చర్

ప్రపంచవ్యాప్తంగా C++ ఇంటర్వ్యూలలో అడిగే అత్యంత ప్రసిద్ధ ప్రశ్న: "వర్చువల్ ఫంక్షన్లు రన్‌టైమ్‌లో సరైన ఫంక్షన్‌ను ఎలా గుర్తిస్తాయి?"

[vtable & vptr అంతర్గత హార్డ్‌వేర్ లేఅవుట్] 1. vtable (Virtual Table): ఒక క్లాస్‌లో ఒక్క virtual ఫంక్షన్ ఉన్నా, కంపైలర్ ఆ క్లాస్ కోసం మెమరీలో స్టాటిక్ ఫంక్షన్ పాయింటర్ టేబుల్ (Array of Function Pointers) ను సృష్టిస్తుంది: ┌───────────────────────────────────────────────┐ │ Dog vtable │ ├───────────────────────┬───────────────────────┤ │ &Dog::makeSound() │ &Dog::~Dog() │ └───────────────────────┴───────────────────────┘ 2. vptr (Virtual Pointer): ఆ క్లాస్ నుండి పుట్టిన ప్రతి ఆబ్జెక్ట్ లోపల కంపైలర్ రహస్యంగా 8 బైట్ల హిడెన్ పాయింటర్ (*vptr) ను మొదటి వేరియబుల్ గా చొప్పిస్తుంది! Dog myDog ఆబ్జెక్ట్ (RAM లో): ┌───────────────────────┬───────────────────────┐ │ *vptr (8 Bytes) │ name / data │ └──────────┬────────────┴───────────────────────┘ │ └───────────────► Points to Dog vtable! రన్‌టైమ్ స్టెప్: ptr->makeSound() పిలవగానే ──► ptr లోని vptr కి వెళ్తుంది ──► vtable లోని అడ్రస్ చదువుతుంది ──► Dog::makeSound() రన్ అవుతుంది!
4 The Virtual Destructor Rule: మెమరీ లీక్ నివారణ

పాలిమార్ఫిజమ్ ఉపయోగించే ప్రతి C++ డెవలపర్ గుర్తుపెట్టుకోవాల్సిన పరమ పవిత్రమైన సూత్రం: Base క్లాస్ Destructor ఎల్లప్పుడూ virtual గా ఉండాలి!

🚨 The Leaking Derived Destructor Catastrophe:
ఒకవేళ మీరు Animal* ptr = new Dog(); delete ptr; అని రాసినప్పుడు, Base Destructor వర్చువల్ కాకపోతే: కంపైలర్ కేవలం ~Animal() ని మాత్రమే పిలుస్తుంది! ~Dog() ఎప్పటికీ పిలవబడదు! డాగ్ క్లాస్ లోపల కేటాయించిన హీప్ మెమరీ మొత్తం రామ్‌లోనే ఉండిపోయి తీవ్రమైన Memory Leak కు దారితీస్తుంది.

virtual ~Animal() = default; అని పెట్టగానే, ముందుగా Derived Destructor రన్ అయి, తర్వాత Base Destructor సురక్షితంగా క్లీన్ అవుతుంది!
💻 Code Example 1: Dynamic Polymorphism with Safe Virtual Destructors
polymorphism_virtual_destructor.cpp
⚡ Try in Compiler 
#include <iostream>
#include <vector>
#include <memory>

// Base Class
class Animal {
public:
    // వర్చువల్ ఫంక్షన్ - రన్‌టైమ్ బైండింగ్‌ను ఎనేబుల్ చేస్తుంది
    virtual void makeSound() const {
        std::cout << "Generic Animal Sound...\n";
    }

    // గోల్డెన్ రూల్: వర్చువల్ డిస్ట్రక్టర్ తప్పనిసరి!
    virtual ~Animal() {
        std::cout << "  [-] Animal Base Destructor cleaned.\n";
    }
};

// Derived Class 1
class Dog : public Animal {
private:
    std::string breed;

public:
    Dog(const std::string& b) : breed(b) {}

    void makeSound() const override { // C++11 override check
        std::cout << "🐕 Dog (" << breed << "): Woof! Woof!\n";
    }

    ~Dog() override {
        std::cout << "  [-] Dog (" << breed << ") Derived Destructor cleaned.\n";
    }
};

// Derived Class 2
class Cat : public Animal {
public:
    void makeSound() const override {
        std::cout << "🐈 Cat: Meow! Meow!\n";
    }

    ~Cat() override {
        std::cout << "  [-] Cat Derived Destructor cleaned.\n";
    }
};

int main() {
    std::cout << "=== 1. Storing Heterogeneous Objects in Base Pointer Vector ===\n";
    std::vector<std::unique_ptr<Animal>> zoo;
    zoo.push_back(std::make_unique<Dog>("German Shepherd"));
    zoo.push_back(std::make_unique<Cat>());

    std::cout << "\n=== 2. Dynamic Dispatch in Action (One Loop, Multiple Behaviors) ===\n";
    for (const auto& animal : zoo) {
        animal->makeSound(); // రన్‌టైమ్‌లో సరైన చైల్డ్ మెథడ్ పిలవబడుతుంది!
    }

    std::cout << "\n=== 3. Cleaning Up (Watch Virtual Destructor Dual Cleanup) ===\n";
    zoo.clear(); // రెండు చైల్డ్ డిస్ట్రక్టర్లు మరియు బేస్ డిస్ట్రక్టర్లు సేఫ్‌గా రన్ అవుతాయి

    return 0;
}

5 Pure Virtual Functions & Abstract Classes (ఇంటర్‌ఫేస్ డిజైన్)

కొన్ని సందర్భాలలో Base క్లాస్ అసలు ఏ నిర్దిష్ట పనిని చేయలేదు; అది కేవలం నియమాలను మాత్రమే నిర్దేశించాలి. ఉదాహరణకు Shape అనే బేస్ క్లాస్‌కు స్వంత ఆకారం ఉండదు; దాన్ని ఇన్హెరిట్ చేసుకునే Circle లేదా Rectangle మాత్రమే ఏరియాను లెక్కించగలవు.

ఇటువంటి సందర్భాలలో ఫంక్షన్ చివర = 0 పెడతారు. దీనినే Pure Virtual Function అంటారు:

[Pure Virtual Function Syntax & Properties] class PaymentGateway { public: virtual void processPayment(double amount) = 0; // Pure Virtual! virtual ~PaymentGateway() = default; }; నియమాలు: 1. ఈ క్లాస్ ఇప్పుడు 'Abstract Class' గా మారిపోయింది. 2. PaymentGateway obj; అని ఆబ్జెక్ట్ ను సృష్టించలేము (కంపల్సరీ కంపైలర్ ఎర్రర్). 3. దీన్ని ఇన్హెరిట్ చేసుకునే UPI, PayPal క్లాసులు తప్పనిసరిగా processPayment() ని ఇంప్లిమెంట్ చేయాలి; లేకపోతే అవి కూడా ఆబ్‌స్ట్రాక్ట్ క్లాసులే అవుతాయి!
💻 Code Example 2: Clean Interface Architecture via Abstract Classes
abstract_payment_interface.cpp
⚡ Try in Compiler 
#include <iostream>
#include <string>
#include <memory>

// Abstract Class (C++ Interface Contract)
class PaymentGateway {
public:
    virtual void processPayment(double amount) = 0; // Pure Virtual Function
    virtual std::string getGatewayName() const = 0;
    virtual ~PaymentGateway() = default;
};

// Concrete Implementation 1: UPI
class UPIPayment : public PaymentGateway {
private:
    std::string vpaId;
public:
    UPIPayment(const std::string& upi) : vpaId(upi) {}

    void processPayment(double amount) override {
        std::cout << "  [UPI] Successfully debited ₹" << amount 
                  << " via VPA: " << vpaId << "\n";
    }

    std::string getGatewayName() const override { return "NPCI-UPI"; }
};

// Concrete Implementation 2: PayPal
class PayPalPayment : public PaymentGateway {
private:
    std::string email;
public:
    PayPalPayment(const std::string& mail) : email(mail) {}

    void processPayment(double amount) override {
        std::cout << "  [PayPal] Successfully charged $" << amount 
                  << " to account: " << email << "\n";
    }

    std::string getGatewayName() const override { return "PayPal Global"; }
};

// Client Checkout System - PaymentGateway ఇంటర్‌ఫేస్ పై మాత్రమే ఆధారపడుతుంది
void checkout(const PaymentGateway& gateway, double bill) {
    std::cout << "Routing transaction via: " << gateway.getGatewayName() << "...\n";
    const_cast<PaymentGateway&>(gateway); // const safe
    // gateway.processPayment(bill);
}

int main() {
    std::cout << "=== Production Interface Pattern ===\n";
    UPIPayment upi("balaji@okhdfcbank");
    PayPalPayment paypal("user@enterprise.com");

    upi.processPayment(1500.00);
    paypal.processPayment(49.99);

    return 0;
}

❓ Frequently Asked Questions (FAQ)

Q C++ లో vtable మరియు vptr ఎలా పనిచేస్తాయి?

ఒక క్లాస్‌లో కనీసం ఒక్క virtual ఫంక్షన్ ఉన్నా, కంపైలర్ ఆ క్లాస్ కోసం ఒక స్టాటిక్ ఫంక్షన్ పాయింటర్ల పట్టికను (vtable) సృష్టిస్తుంది. ఆ క్లాస్ యొక్క ప్రతి ఆబ్జెక్ట్ లోపల ఒక హిడెన్ 8-బైట్ పాయింటర్ (vptr) ఉంటుంది, అది ఆ vtable ను సూచిస్తుంది. రన్‌టైమ్‌లో ఫంక్షన్ కాల్ జరిగినప్పుడు vptr ద్వారా vtable లోని సరైన చైల్డ్ ఫంక్షన్ అడ్రస్‌ను వెతికి ఎగ్జిక్యూట్ చేస్తుంది (Late Binding).

Q Base క్లాస్ లో Destructor ని ఎల్లప్పుడూ 'virtual' గా ఎందుకు ప్రకటించాలి?

Base పాయింటర్ ద్వారా Derived ఆబ్జెక్ట్‌ను డిలీట్ చేసినప్పుడు (Base* b = new Derived(); delete b;), Base destructor వర్చువల్ కాకపోతే కేవలం Base డిస్ట్రక్టర్ మాత్రమే రన్ అవుతుంది; Derived డిస్ట్రక్టర్ ఎప్పటికీ రన్ అవ్వదు! దీనివల్ల Derived ఆబ్జెక్ట్ లోని హీప్ మెమరీ లీక్ అయిపోతుంది. అందుకే పాలిమార్ఫిజమ్ లో virtual ~Base() తప్పనిసరి.

Q Pure Virtual Function అంటే ఏమిటి? దానివల్ల క్లాస్ ఎలా మారుతుంది?

ఏ బాడీ లేకుండా కేవలం = 0 తో ప్రకటించబడిన ఫంక్షన్‌ను Pure Virtual Function అంటారు (ఉదా: virtual void draw() = 0;). క్లాస్‌లో ఒక్క Pure Virtual Function ఉన్నా ఆ క్లాస్ Abstract Class గా మారిపోతుంది. దీనికి నేరుగా ఆబ్జెక్టులను సృష్టించలేము; కేవలం చైల్డ్ క్లాసులు ఆ ఫంక్షన్‌ను తప్పనిసరిగా ఇంప్లిమెంట్ చేయాల్సిన ఒక పక్కా బ్లూప్రింట్ లేదా Interface లాగా పనిచేస్తుంది.
