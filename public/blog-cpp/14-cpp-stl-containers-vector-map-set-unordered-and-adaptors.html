STL Containers: Vector, Map & Set (తెలుగులో)

⚡ Modern C++ (C++17 / C++20 / C++23) 🟢 Lesson 14 📂 Phase 14: STL Containers 📅 2026 Master Edition
📌 Covered in this in-depth guide: Standard Template Library (STL) · std::vector · std::set · std::map · Unordered Containers

ఒక పెద్ద ఇల్లు కట్టేటప్పుడు మీరు ఇటుకలు, సిమెంట్, ఐరన్ స్వయంగా తయారు చేసుకోరు కదా! బయట మార్కెట్ లో రెడీగా దొరికేవి తెచ్చుకుని డైరెక్ట్ గా వాడుకుంటారు. ప్రోగ్రామింగ్ కూడా అంతే. ఒక యాప్ తయారు చేసేటప్పుడు డేటాని స్టోర్ చేయడానికి పదే పదే లింక్డ్ లిస్ట్ (Linked Lists), ట్రీస్ (Trees), క్యూ (Queues) మీరే సొంతంగా కోడ్ రాసుకుంటూ కూర్చుంటే ప్రాజెక్ట్ ఎప్పటికీ అవ్వదు. అందుకే C++ ని తయారు చేసినవాళ్ళు ముందే ఇవన్నీ రాసి మనకోసం ఒక లైబ్రరీ లో పెట్టారు. దాన్నే Standard Template Library (STL) అంటారు. ఇందులో ఉండే రెడీమేడ్ బాక్సులనే Containers (కంటైనర్స్) అంటారు. C++ లో కాంపిటేటివ్ ప్రోగ్రామింగ్ చేయాలన్నా, పెద్ద సాఫ్ట్‌వేర్ రాయాలన్నా ఈ STL మీద పట్టు ఉండాల్సిందే!

1 కంటైనర్స్ (Containers) అంటే ఏంటి? వాటి రకాలు

కంటైనర్ అంటే ఒక పెద్ద బాక్స్. అందులో డేటాని ఎలా అమరుస్తున్నారు అనేదాన్ని బట్టి అవి రకరకాలుగా ఉంటాయి.

  • Sequence Containers: ఇందులో డేటా ఒకదాని పక్కన ఒకటి లైన్ గా ఉంటుంది. (ఉదాహరణ: std::vector, std::deque).
  • Associative Containers: ఇందులో డేటా లైన్ గా కాకుండా, ఒక చెట్టు (Tree) లాగా అమరి ఉంటుంది. దీనివల్ల వెతకడం (Searching) చాలా ఫాస్ట్ అవుతుంది. (ఉదాహరణ: std::set, std::map).
  • Unordered Containers: ఇవి ట్రీస్ లాగా కాకుండా హ్యాష్ టేబుల్స్ (Hash Tables) వాడుతాయి. ఇందులో సెర్చింగ్ కళ్లు మూసి తెరిచే లోపు జరిగిపోతుంది (O(1) టైమ్). (ఉదాహరణ: std::unordered_map).

📚 రియల్ లైఫ్ స్టోరీ: లైబ్రరీ బుక్స్ మరియు std::map

మీరు ఒక పెద్ద లైబ్రరీకి వెళ్లారు. అక్కడ లక్షల పుస్తకాలు ఒక పెద్ద కుప్పగా పోసి ఉన్నాయి అనుకోండి (ఇది మామూలు అర్రే). మీకు కావాల్సిన ఒక బుక్ వెతకడానికి చాలా టైమ్ పడుతుంది కదా.

అదే మీరు ఒక std::map ని వాడారనుకోండి, అది ఒక డిక్షనరీ (Dictionary) లాగా పనిచేస్తుంది. ఒకవైపు బుక్ పేరు (Key), ఇంకోవైపు అది ఏ షెల్ఫ్ లో ఉందో నంబర్ (Value) రాసి ఉంటుంది. మీకు "Harry Potter" బుక్ కావాలంటే డైరెక్ట్ గా మ్యాప్ లోకి వెళ్లి అడిగితే, అది వెంటనే "రాక్ నంబర్ 5" అని సెకనులో చెప్పేస్తుంది. ఈ కీ-వాల్యూ (Key-Value) సిస్టమ్ వల్ల ప్రోగ్రామింగ్ ఎంత ఈజీ అవుతుందో మీరే ఊహించుకోండి.

2 Set మరియు Unordered_Set కి తేడా ఏంటి?

std::set లో మీరు ఏ నంబర్స్ ఇచ్చినా (ఉదా: 5, 2, 8, 2), అది డూప్లికేట్స్ ని పీకేసి, వాటిని ఆటోమేటిక్ గా ఒక ఆర్డర్ లో (చిన్న దాని నుండి పెద్ద దానికి - 2, 5, 8) అరేంజ్ చేసి పెట్టుకుంటుంది. లోపల ఇది "Red-Black Tree" వాడుతుంది.

std::unordered_set లో కూడా డూప్లికేట్స్ ఉండవు, కానీ ఇవి ఆర్డర్ లో ఉండవు. మీరు ఎలా వేస్తే అలా చెల్లాచెదురుగా పడి ఉంటాయి, కానీ ఇందులో వెతకడం (Search) చాలా ఫాస్ట్ గా ఉంటుంది. లోపల ఇది "Hash Table" వాడుతుంది.

3 ఒకే ఒక సింపుల్ కోడ్ (Map & Set Demo)

కింద కోడ్ లో map వాడి ఒక ఫోన్ బుక్ (Phonebook) ని ఎలా తయారు చేశామో, డేటాని కీ (Key) తో ఎలా బయటకి తీస్తున్నామో చూడండి.

C++ — STL Map & Set ▶ Run Code 
#include <iostream>
#include <map>
#include <string>

int main() {
    // 1. Map క్రియేట్ చేస్తున్నాం (పేరు -> ఫోన్ నంబర్)
    std::map<std::string, long long> phoneBook;
    
    // డేటా ఇన్సర్ట్ చేస్తున్నాం
    phoneBook["Ramesh"] = 9876543210;
    phoneBook["Suresh"] = 8765432109;
    phoneBook["Mahesh"] = 7654321098;
    
    // 2. డేటాని వెతకడం (O(log n) టైమ్)
    std::string searchName = "Suresh";
    
    if (phoneBook.find(searchName) != phoneBook.end()) {
        std::cout << searchName << "'s Phone: " << phoneBook[searchName] << std::endl;
    } else {
        std::cout << searchName << " not found!" << std::endl;
    }
    
    // 3. మ్యాప్ లో ఉన్నవన్నీ ప్రింట్ చేద్దాం (ఇవి ఆల్ఫాబెట్ ఆర్డర్ లో వస్తాయి)
    std::cout << "\nAll Contacts:" << std::endl;
    for (auto item : phoneBook) {
        // item.first అంటే కీ (పేరు), item.second అంటే వాల్యూ (నంబర్)
        std::cout << "- " << item.first << " : " << item.second << std::endl;
    }
    
    return 0;
}
4 కోడ్ లో ఏం జరుగుతోంది? (Step-by-Step)
  • std::map<std::string, long long>: ఇక్కడ మొదటి వాల్యూ (string) ని కీ (Key) అంటారు. రెండో దాన్ని వాల్యూ (Value) అంటారు.
  • మనం phoneBook["Ramesh"] = ... అని డైరెక్ట్ గా బ్రాకెట్స్ వాడి అర్రేస్ లాగానే డేటాని ఇన్సర్ట్ చేయొచ్చు. ఇది చాలా పవర్ ఫుల్.
  • మ్యాప్ ఎప్పుడూ లోపల ఒక ట్రీ లాగా ఉంటుంది కాబట్టి, మనం రమేష్, సురేష్, మహేష్ అని ఇన్సర్ట్ చేసినా, అది ప్రింట్ చేసేటప్పుడు ఆల్ఫాబెటికల్ ఆర్డర్ లో (మహేష్, రమేష్, సురేష్) ఆటోమేటిక్ గా మార్చి ఇస్తుంది.
5 ఇంటర్వ్యూలలో అడిగే కామన్ ప్రశ్నలు (FAQ)

Q1: vector మరియు list కి మెయిన్ డిఫరెన్స్ ఏంటి? ఏది వాడాలి?

వెక్టార్ లో డేటా అంతా RAM లో పక్క పక్కనే (Contiguous) ఉంటుంది. కాబట్టి అందులో ఒక వాల్యూ ని వెతకడం గానీ, చదవడం గానీ చాలా ఫాస్ట్ (కాష్ ఫ్రెండ్లీ). కానీ మధ్యలో ఎక్కడైనా ఒక ఐటమ్ ని జొప్పించాలంటే (Insert) చాలా కష్టం, మిగతా ఐటమ్స్ అన్నిటిని పక్కకి జరపాలి. అదే లిస్ట్ లో (Linked List) ఎక్కడ పడితే అక్కడ ఇన్సర్ట్ చేయడం ఈజీ, కానీ వెతకడం చాలా స్లో. 95% సిచువేషన్స్ లో vector వాడటమే సేఫ్ అండ్ ఫాస్ట్.

Q2: map కి unordered_map కి తేడా ఏంటి? ఏది బెటర్?

మీకు డేటా ఆర్డర్ లో (A to Z) ఉండాలి అనుకుంటే map వాడాలి (ఇది చెట్లు వాడుతుంది). అదే మీకు ఆర్డర్ తో పన్లేదు, నాకు ఎంత పెద్ద డేటా అయినా మిల్లీ సెకన్లలో ఫాస్ట్ గా దొరకాలి అనుకుంటే unordered_map వాడాలి (ఇది హాష్ టేబుల్స్ వాడుతుంది). ఫాస్ట్ గా సెర్చ్ చేయడానికి ఎప్పుడూ unordered_map బెస్ట్.

Q3: Container Adaptors అంటే ఏంటి? (Stack, Queue)

ఇవి డైరెక్ట్ గా కొత్త కంటైనర్స్ కావు. ముందే ఉన్న vector లేదా deque లాంటి వాటికి, కొన్ని రూల్స్ పెట్టి ఒక కొత్త ఫీచర్ లాగా ఇస్తారు. ఉదాహరణకు std::stack తీసుకుంటే, అందులో ఒక వైపు నుండే డేటా వేయాలి, అక్కడి నుండే తీయాలి (LIFO - Last In First Out). ఒక గొట్టం (Tube) లాంటి రూల్ పెడతారు. దాన్ని అడాప్టర్ అంటారు.
