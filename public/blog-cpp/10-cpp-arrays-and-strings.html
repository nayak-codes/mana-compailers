అర్రేలు (Arrays) & std::string (తెలుగులో)

C++ లో డేటాను మెమరీలో ఒకే వరుసలో ఎలా నిల్వ చేస్తారు? Contiguous Memory Layout, Base Address గణిత సూత్రం, Array Decay ప్రభావం, 2D Arrays & Row-Major Order, C-String vs std::string, Small String Optimization (SSO), మరియు C++17 లో పరిచయమైన జీరో-కాపీ std::string_view సమగ్ర వివరణ.

1 అర్రే అంటే ఏమిటి? Contiguous Memory Allocation సూత్రం

ఒకే డేటా టైప్‌కు చెందిన అనేక విలువలను కంప్యూటర్ ర్యామ్ (RAM) లో ఒకే వరుసలో (Contiguous Memory Blocks) నిల్వ చేసే అత్యంత ప్రాథమికమైన డేటా స్ట్రక్చర్ Array. వేర్వేరు వేరియబుల్స్ సృష్టించి రామ్‌లో ఎక్కడెక్కడో విసిరేయడానికి బదులుగా, ఒకే వరుస క్రమంలో పక్కపక్కనే ఉంచడం వల్ల CPU Cache Hit రేటు అత్యధికంగా ఉంటుంది.

💡 CPU Cache Locality (స్పీడ్ సీక్రెట్): CPU రామ్ నుండి డేటాను ఒక్కొక్క బైట్ చొప్పున చదవదు; "Cache Line" (సాధారణంగా 64 బైట్లు) రూపంలో మొత్తం బ్లాక్‌ను కాపీ చేసుకుంటుంది. అర్రే ఎలిమెంట్స్ పక్కపక్కనే ఉండటం వల్ల, మొదటి ఎలిమెంట్ చదవగానే మిగిలిన ఎలిమెంట్స్ అన్నీ ఆటోమేటిక్‌గా L1/L2 Cache లోకి వచ్చేస్తాయి. అందుకే లింక్డ్ లిస్టుల కంటే అర్రేలు వందల రెట్లు వేగంగా రన్ అవుతాయి!

ఇండెక్స్ 0 తో ఎందుకు మొదలవుతుంది? (The Offset Formula)

చాలామంది ప్రారంభకులు అర్రే ఇండెక్స్ 1 కాకుండా 0 తో ఎందుకు మొదలవుతుందని ఆశ్చర్యపోతారు. C++ లో అర్రే ఇండెక్స్ అనేది కేవలం సీరియల్ నంబర్ కాదు, అది బేస్ అడ్రస్ నుండి ఎంత దూరం ఉందో సూచించే Memory Offset:

[RAM లో int arr[4] = {10, 20, 30, 40} యొక్క మెమరీ మ్యాప్] Index: arr[0] arr[1] arr[2] arr[3] Value: [ 10 ] [ 20 ] [ 30 ] [ 40 ] Memory: [4 Bytes] [4 Bytes] [4 Bytes] [4 Bytes] RAM Address: 0x1000 0x1004 0x1008 0x100C ▲ └─── Base Address (ఇక్కడి నుంచే అర్రే ప్రారంభం అవుతుంది) గణిత సూత్రం (Hardware Calculation): Address(arr[i]) = Base_Address + (i × sizeof(Type)) • arr[0] = 0x1000 + (0 × 4) = 0x1000 (సున్నా దూరం! అదనపు లెక్కలు అవసరం లేదు) • arr[1] = 0x1000 + (1 × 4) = 0x1004 • arr[2] = 0x1000 + (2 × 4) = 0x1008 • arr[3] = 0x1000 + (3 × 4) = 0x100C

కంప్యూటర్ హార్డ్‌వేర్ లెవల్లో arr[i] ని వెతకడానికి కేవలం ఒక మల్టిప్లికేషన్ మరియు ఒక అడిషన్ మాత్రమే సరిపోతుంది. ఇండెక్స్ 1 తో మొదలైతే ప్రతిసారీ (i - 1) చేయాల్సి వచ్చేది, ఇది కోట్ల ఆపరేషన్లలో విలువైన CPU సైకిళ్లను వృధా చేసేది.

2 అర్రే ప్రకటన, సైజ్ పరిమితులు & Array Decay Trap

C++ లో సాంప్రదాయక C-Style Array ని ప్రకటించేటప్పుడు దాని సైజ్ కంపైల్-టైమ్ లోనే స్థిరంగా (Compile-time Constant) ఉండాలి:

రకం (Syntax) ఉదాహరణ మెమరీలో జరిగే ప్రక్రియ
Explicit Size int scores[5]; రామ్‌లో 20 బైట్ల మెమరీ కేటాయించబడుతుంది; ఇనిషియలైజ్ చేయకపోతే గార్బేజ్ విలువలు ఉంటాయి.
List Initialization int marks[] = {85, 92, 78}; కంపైలర్ ఎలిమెంట్లను లెక్కించి స్వయంగా సైజ్ 3 గా నిర్ణయిస్తుంది (12 బైట్లు).
Partial Init (Zero Fill) int nums[5] = {1, 2}; మొదటి రెండు ఎలిమెంట్లు 1, 2 కాగా, మిగిలిన 3 స్థానాలు ఆటోమేటిక్‌గా 0 తో నింపబడతాయి.
All Zero Initialization int zeroArr[100] = {0}; మొత్తం 100 ఎలిమెంట్లు సున్నా (0) కు సెట్ చేయబడతాయి.
⚠️ Array Decay Trap (ఫంక్షన్లకు అర్రే పంపేటప్పుడు జాగ్రత్త):
మనం ఒక అర్రేని ఫంక్షన్‌కు ఆర్గ్యుమెంట్‌గా పంపినప్పుడు, C++ ఆ అర్రే మొత్తం కాపీ చేయదు. దానికి బదులుగా అర్రే యొక్క మొదటి ఎలిమెంట్ అడ్రస్‌గా (Pointer to first element) మారిపోతుంది. దీనినే Array Decay అంటారు!
దీనివల్ల ఫంక్షన్ లోపల sizeof(arr) అని రాస్తే మొత్తం అర్రే సైజ్ రాదు, కేవలం 8 బైట్ల పాయింటర్ సైజ్ మాత్రమే వస్తుంది. కాబట్టి C-Style అర్రేను ఫంక్షన్‌కు పంపుతున్నప్పుడు అర్రే సైజ్‌ను విడిగా రెండో పారామీటర్‌గా తప్పక పాస్ చేయాలి: void printArr(int arr[], int size).
3 2D Arrays & Row-Major Memory Order

గ్రిడ్లు, మ్యాట్రిక్స్ లెక్కలు లేదా గేమ్ బోర్డుల (ఉదా: టిక్-టాక్-టో, చదరంగం) కోసం మనం Two-Dimensional (2D) Arrays ఉపయోగిస్తాము. మనం కోడ్‌లో 2D గ్రిడ్ లాగా చూసినప్పటికీ, కంప్యూటర్ రామ్ (RAM) అనేది కేవలం ఒక సరళరేఖ (1D Linear strip) లాంటిది!

[2D Matrix vs Linear RAM Layout (Row-Major Order)] మనం రాసే 2x3 మ్యాట్రిక్స్: int matrix[2][3] = { {1, 2, 3}, // Row 0 {4, 5, 6} // Row 1 }; RAM లో భౌతికంగా ఎలా నిల్వ ఉంటుంది (Row-Major): ┌─────────────────────────┬─────────────────────────┐ │ Row 0 │ Row 1 │ ├─────────┬─────────┬─────┼─────────┬─────────┬─────┤ │ 1 │ 2 │ 3 │ 4 │ 5 │ 6 │ └─────────┴─────────┴─────┴─────────┴─────────┴─────┘ 0x1000 0x1004 0x1008 0x100C 0x1010 0x1014 హార్డ్‌వేర్ 2D ఇండెక్స్ ఫార్ములా: Flat_Index = (row × total_columns) + column

దీనివల్ల మనం 2D లూప్స్ రాసేటప్పుడు బాహ్య లూప్ (Outer loop) లో Row, అంతర్గత లూప్ (Inner loop) లో Column ఉంచడం అత్యంత వేగవంతమైన పద్ధతి (Row-by-Row access). ఒకవేళ కాలమ్-ఫస్ట్ క్రమంలో చదివితే ప్రతిసారీ మెమరీలో దూకాల్సి వచ్చి (Cache Miss) ప్రోగ్రామ్ స్లో అయిపోతుంది.

#include <iostream>
#include <cstdint>

// ఫంక్షన్‌కు అర్రే పాస్ చేసినప్పుడు Array Decay జరుగుతుంది (int arr[] -> int* arr)
void displayArray(const int arr[], int size) {
    std::cout << "--- 1D Array Memory Addresses & Elements ---\n";
    for (int i = 0; i < size; ++i) {
        // &arr[i] తో రామ్‌లో ఆ ఎలిమెంట్ యొక్క ఖచ్చితమైన అడ్రస్ ప్రింట్ అవుతుంది
        std::cout << "Index [" << i << "] = " << arr[i] 
                  << " | RAM Address: " << &arr[i] << "\n";
    }
}

int main() {
    // 1. 1D Array Declaration
    int numbers[4] = {10, 20, 30, 40};
    int totalElements = sizeof(numbers) / sizeof(numbers[0]);

    std::cout << "numbers array total size: " << sizeof(numbers) << " bytes\n";
    std::cout << "single element size     : " << sizeof(numbers[0]) << " bytes\n";
    std::cout << "total element count     : " << totalElements << "\n\n";

    displayArray(numbers, totalElements);

    // 2. 2D Array (2 Rows x 3 Columns)
    std::cout << "\n--- 2D Array Matrix (Row-Major Traversal) ---\n";
    int matrix[2][3] = {
        {101, 102, 103},
        {201, 202, 203}
    };

    for (int r = 0; r < 2; ++r) {
        for (int c = 0; c < 3; ++c) {
            std::cout << "matrix[" << r << "][" << c << "] = " 
                      << matrix[r][c] << " (" << &matrix[r][c] << ")  ";
        }
        std::cout << "\n";
    }

    return 0;
}

4 C-Style Strings vs Modern std::string

C లాంగ్వేజ్ కాలం నుండి వచ్చిన పాత పద్ధతి C-Style Strings (`char str[]`), కాగా C++ ప్రోగ్రామర్లకు వరం లాంటిది Standard Library లోని std::string. వీటి మధ్య ఉండే ప్రధాన వ్యత్యాసాలను తెలుసుకుందాం:

లక్షణం (Feature) C-Style String (char[]) Modern std::string
ముగింపు గుర్తు (Termination) ఖచ్చితంగా చివర '\0' (Null character) ఉండాలి. పొరపాటున ఇది లేకపోతే గార్బేజ్ ప్రింట్ అవుతుంది. అంతర్గతంగా సైజ్ స్టోర్ చేసుకుంటుంది. నల్ క్యారెక్టర్‌తో పనిలేదు (అయినా C-లైబ్రరీల కోసం .c_str() ఇస్తుంది).
పరిమాణం (Sizing) స్థిరమైనది (Fixed). ముందుగానే ఎంత సైజ్ కావాలో చెప్పాలి. డైనమిక్. మనం ఎంత టెక్స్ట్ యాడ్ చేసినా మెమరీ దానంతట అదే ఆటోమేటిక్‌గా రీసైజ్ అవుతుంది.
కలపడం (Concatenation) strcat(s1, s2) లాంటి ప్రమాదకరమైన ఫంక్షన్లు వాడాలి. చాలా సులభం: s1 + s2 లేదా s1 += s2 తో నేరుగా కలిపేయవచ్చు.
పోలిక (Comparison) strcmp(s1, s2) == 0 వాడాలి (== వాడితే అడ్రస్ పోలుస్తుంది). నేరుగా సమానత్వ ఆపరేటర్ వాడవచ్చు: if (s1 == s2).
మెమరీ భద్రత అత్యంత ప్రమాదకరం (Buffer Overflow కు దారితీస్తుంది). పూర్తిగా సురక్షితం. RAII ద్వారా ఆటోమేటిక్ డిస్ట్రక్షన్ జరుగుతుంది.
5 Small String Optimization (SSO) అంటే ఏమిటి?

సాధారణంగా std::string డైనమిక్ సైజ్ కోసం హీప్ మెమరీ (Heap) లో స్పేస్ కేటాయిస్తుంది. కానీ హీప్ అలొకేషన్ అనేది చాలా నెమ్మదిగా జరిగే ప్రక్రియ. అందుకోసం ఆధునిక C++ కంపైలర్లు (GCC, Clang, MSVC) Small String Optimization (SSO) అనే ఇంజనీరింగ్ టెక్నిక్‌ను అమలు చేస్తాయి.

⚡ SSO ఎలా పనిచేస్తుంది?
ఒక స్ట్రింగ్ ఆబ్జెక్ట్ పరిమాణం సాధారణంగా 24 నుండి 32 బైట్లు ఉంటుంది (పాయింటర్, సైజ్, కెపాసిటీ కోసం). స్ట్రింగ్ యొక్క అక్షరాల పొడవు చిన్నదిగా ఉన్నప్పుడు (ఉదాహరణకు 15 లేదా 22 అక్షరాల లోపు, కంపైలర్‌ను బట్టి), అది హీప్ మెమరీని అడగదు! ఆ స్ట్రింగ్ ఆబ్జెక్ట్ యొక్క స్టాక్ మెమరీ బఫర్ లోపలే అక్షరాలను భద్రపరుస్తుంది. దీనివల్ల చిన్న పేర్లు, యూజర్‌నేమ్స్ హ్యాండిల్ చేసేటప్పుడు C++ జీరో-ఓవర్‌హెడ్ స్పీడ్‌ను సాధిస్తుంది!
6 Modern C++17: std::string_view తో Zero-Copy Slicing

ఒక ఫంక్షన్‌కు రీడ్-ఓన్లీ టెక్స్ట్‌ను పాస్ చేయాలంటే పూర్వం const std::string& వాడేవాళ్ళం. కానీ దానికి C-String లిటరల్ (ఉదా: "Hello World") పంపినప్పుడు, తాత్కాలికంగా ఒక std::string ఆబ్జెక్ట్ క్రియేట్ అయి మెమరీ అలొకేషన్ జరిగేది. అలాగే ఒక పెద్ద టెక్స్ట్‌లో సబ్‌స్ట్రింగ్ (ఉదా: str.substr(0, 5)) తీసినప్పుడు కూడా కొత్త స్ట్రింగ్ కాపీ అవుతుంది.

దీనికి పరిష్కారంగా C++17 లో std::string_view పరిచయమైంది. ఇది మెమరీని ఓన్ చేసుకోదు (Non-owning). కేవలం ఒక పాయింటర్ మరియు లెంత్ మాత్రమే కలిగి ఉండే ఒక "కిటికీ" (View/Window) లాంటిది.

#include <iostream>
#include <string>

// C++17 బెస్ట్ ప్రాక్టీస్: రీడ్-ఓన్లీ స్ట్రింగ్స్ కోసం string_view వాడండి
void printPrefix(std::string_view sv, std::size_t count) {
    // remove_suffix లేదా substr జీరో-కాపీ తో పనిచేస్తాయి
    std::string_view prefix = sv.substr(0, count);
    std::cout << "Extracted Prefix (" << count << " chars): \"" << prefix << "\"\n";
}

int main() {
    std::cout << "=== 1. Modern std::string Manipulation ===\n";
    std::string title = "Modern C++ ";
    title += "Masterclass"; // Concatenation (+)

    std::cout << "Full Title : " << title << "\n";
    std::cout << "Length     : " << title.length() << " characters\n";
    std::cout << "Capacity   : " << title.capacity() << " bytes allocated\n";

    // Substring శోధన (Find)
    std::size_t pos = title.find("Master");
    if (pos != std::string::npos) {
        std::cout << "'Master' found at index: " << pos << "\n";
    }

    std::cout << "\n=== 2. C++17 std::string_view (Zero-Copy) ===\n";
    // C-string లిటరల్ పై ఎటువంటి మెమరీ అలొకేషన్ లేకుండా వ్యూ పనిచేస్తుంది
    const char* rawArticle = "Hyderabad Tech Hub 2026";

7 బఫర్ ఓవర్‌ఫ్లో (Buffer Overflow) భద్రతా ప్రమాదం

అర్రేలతో పనిచేసేటప్పుడు ప్రతి ప్రోగ్రామర్ తెలుసుకోవాల్సిన అతిపెద్ద ముప్పు Buffer Overflow (Out-of-Bounds Memory Access). జావా లేదా పైథాన్‌లో అర్రే లిమిట్ దాటితే IndexOutOfBoundsException వచ్చి ప్రోగ్రామ్ ఆగిపోతుంది. కానీ C++ లో డిఫాల్ట్‌గా ఎలాంటి బౌండ్స్ చెకింగ్ ఉండదు!

🚨 Undefined Behavior & Hackers:
ఒకవేళ మీరు 5 సైజ్ ఉన్న అర్రేలో arr[10] = 99; అని రాస్తే, C++ కంపైలర్ మిమ్మల్ని ఆపదు! అది రామ్‌లో ఆ ఆఫ్‌సెట్ వద్ద ఉన్న వేరే వేరియబుల్ డేటాను లేదా ఫంక్షన్ రిటర్న్ అడ్రస్‌ను ఓవర్‌రైట్ చేస్తుంది. కంప్యూటర్ చరిత్రలో అతిపెద్ద సైబర్ దాడులకు (ఉదా: Morris Worm, Heartbleed) ఈ బఫర్ ఓవర్‌ఫ్లో కారణం.

సేఫ్టీ సొల్యూషన్: బౌండ్స్ చెకింగ్ కావాలనుకుంటే std::array లేదా std::vector లో .at(i) మెథడ్ వాడండి. ఇండెక్స్ దాటితే అది సురక్షితంగా std::out_of_range ఎక్సెప్షన్ విసురుతుంది.
❓ Frequently Asked Questions (FAQ)

Q C++ లో అర్రే ఇండెక్స్ 0 తో ఎందుకు మొదలవుతుంది (0-based Indexing)?

అర్రే ఇండెక్స్ అనేది కేవలం సీరియల్ నంబర్ కాదు, అది మెమరీలో 'ఆఫ్‌సెట్' (Offset/Distance). మొదటి ఎలిమెంట్ బేస్ అడ్రస్ వద్దే (0 దూరంలో) ఉంటుంది: Address = Base_Address + (Index * sizeof(type)). ఇండెక్స్ 0 అయితే Address = Base_Address అవుతుంది, దీనివల్ల అదనపు కూడికలు లేదా తీసివేతలు లేకుండా కంపైలర్ మెరుపు వేగంతో మెమరీని యాక్సెస్ చేస్తుంది.

Q C-style char array కి Modern C++ std::string కి తేడా ఏమిటి?

C-style string అనేది చివరిలో null character ('\0') కలిగి ఉండే ఫిక్స్‌డ్ క్యారెక్టర్ అర్రే; దీని పరిమాణాన్ని మార్చడం కష్టం మరియు బఫర్ ఓవర్‌ఫ్లో ప్రమాదం ఎక్కువ. Modern std::string అనేది డైనమిక్ క్లాస్; సైజ్ ఆటోమేటిక్‌గా పెరుగుతుంది, మెమరీ సేఫ్టీ ఉంటుంది, +, substr(), find() వంటి ఎన్నో రెడీమేడ్ మెథడ్స్ ఉంటాయి.

Q Modern C++17 లో 'std::string_view' ఎందుకు ఉపయోగించాలి?

std::string_view అనేది కేవలం పాయింటర్ మరియు లెంత్ మాత్రమే కలిగి ఉండే లైట్‌వెయిట్ రీడ్-ఓన్లీ వ్యూ (Non-owning view). పెద్ద స్ట్రింగ్‌లను ఫంక్షన్‌కు పాస్ చేసినా లేదా సబ్‌స్ట్రింగ్స్ కట్ చేసినా ఎలాంటి కొత్త మెమరీ అలొకేషన్ (Heap Allocation) లేదా కాపీ జరగదు. ఇది ప్రోగ్రామ్ స్పీడ్‌ను గణనీయంగా పెంచుతుంది.
