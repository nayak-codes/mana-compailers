Functions, Overloading & Default Arguments (తెలుగులో)

⚡ Modern C++ (C++17 / C++20 / C++23) 🟢 Lesson 6 📂 Phase 06: Functions & Modular Code 📅 2026 Master Edition
📌 Covered in this in-depth guide: Functions & Return Types · Pass by Value · Function Overloading · Default Arguments · Code Reusability

ఒక పెద్ద ప్రాజెక్ట్ (ఉదాహరణకు వాట్సాప్ యాప్) రాస్తున్నప్పుడు, మెసేజ్ పంపడానికి, ఫోటో పంపడానికి, స్టేటస్ అప్‌డేట్ చేయడానికి... అన్నిటికీ కోడ్ ని ఒకే చోట (మెయిన్ లోనే) రాస్తే అది లక్షల లైన్లు దాటిపోతుంది. అలా ఒకేచోట రాయడం వల్ల తప్పులు కనిపెట్టడం అసాధ్యం అవుతుంది. ఆ ప్రాబ్లెమ్ ని సాల్వ్ చేయడానికి కోడ్ ని చిన్న చిన్న ముక్కలుగా విడగొడతాం. ఆ ముక్కలనే Functions (ఫంక్షన్స్) అంటారు. C++ లో ఫంక్షన్స్ కి మామూలు C కంటే ఎన్నో అడ్వాన్స్డ్ ఫీచర్స్ (Overloading, Default Arguments) ఉన్నాయి. ఈ పాఠంలో అవెలా పనిచేస్తాయో డీప్ గా తెలుసుకుందాం.

1 అసలు ఫంక్షన్ అంటే ఏమిటి?

ఫంక్షన్ అంటే కేవలం ఒక పర్టికులర్ పనిని మాత్రమే చేసే ఒక చిన్న ఫ్యాక్టరీ మెషిన్ లాంటిది. దానికి కొంత ఇన్పుట్ ఇస్తే అది ప్రాసెస్ చేసి మనకు అవుట్‌పుట్ ని ఇస్తుంది.

☕ రియల్ లైఫ్ స్టోరీ: కాఫీ వెండింగ్ మెషిన్

ఆఫీస్ లో ఉండే ఒక కాఫీ మెషిన్ ని ఊహించుకోండి. మీరు దానికి 10 రూపాయలు (Input / Argument) ఇస్తారు. ఆ మెషిన్ లోపల నీళ్ళు, పాలు, కాఫీ పౌడర్ అన్నీ మిక్స్ అయ్యి ఒక ప్రాసెస్ (Code execution) జరుగుతుంది. చివరగా మీకు ఒక కప్పు వేడి కాఫీ (Output / Return value) వస్తుంది.

ఫంక్షన్ కూడా అంతే! మీరు ఒక నంబర్ పంపిస్తే, అది లోపల లాజిక్ చేసి మీకు రిజల్ట్ ఇస్తుంది. ఒకసారి ఆ మెషిన్ ని కొనుక్కుంటే (ఫంక్షన్ రాసుకుంటే), మీకు ఎన్నిసార్లు కావాలంటే అన్నిసార్లు వాడుకోవచ్చు (Code Reusability). పదే పదే కాఫీ డికాషన్ మీరే పెట్టుకోవాల్సిన పనిలేదు!

2 Function Overloading అంటే ఏమిటి?

C లాంగ్వేజ్ లో ఒకే పేరుతో రెండు ఫంక్షన్స్ రాయకూడదు. కానీ C++ లో ఉన్న బెస్ట్ ఫీచర్ ఏంటంటే, ఒకే పేరుతో మీరు ఎన్ని ఫంక్షన్స్ అయినా రాయొచ్చు... కానీ వాటన్నిటికీ మీరు పంపించే ఇన్పుట్స్ (Arguments) వేరేలా ఉండాలి. దీన్నే Function Overloading (ఫంక్షన్ ఓవర్‌లోడింగ్) అంటారు.

ఉదాహరణకు print(int x) అని ఒకటి, print(double x) అని ఇంకోటి రాయొచ్చు. మీరు ఏ వాల్యూ పంపిస్తే కంపైలర్ ఆటోమేటిక్ గా దానికి తగ్గ ఫంక్షన్ ని కాల్ చేసుకుంటుంది.

3 ఒకే ఒక సింపుల్ కోడ్ (Function Overloading)

కింద కోడ్ లో calculateArea అనే ఒకే పేరుతో రెండు ఫంక్షన్స్ ఎలా రాశామో చూడండి. ఒకటి స్క్వేర్ (చతురస్రం) కోసం, ఇంకోటి రెక్టాంగిల్ (దీర్ఘచతురస్రం) కోసం.

C++ — Function Overloading ▶ Run Code 
#include <iostream>

// ఫంక్షన్ 1: ఒకటే నంబర్ తీసుకుంటుంది
int calculateArea(int side) {
    return side * side;
}

// ఫంక్షన్ 2: అదే పేరు, కానీ రెండు నంబర్స్ తీసుకుంటుంది
int calculateArea(int length, int breadth) {
    return length * breadth;
}

int main() {
    // కంపైలర్ మీరు పంపిన నంబర్స్ బట్టి ఏ ఫంక్షన్ రన్ చేయాలో డిసైడ్ చేస్తుంది
    int square = calculateArea(5);        // ఫంక్షన్ 1 కి వెళ్తుంది
    int rectangle = calculateArea(5, 10); // ఫంక్షన్ 2 కి వెళ్తుంది
    
    std::cout << "Square Area: " << square << std::endl;
    std::cout << "Rectangle Area: " << rectangle << std::endl;
    
    return 0;
}
4 కోడ్ లో ఏం జరుగుతోంది? (Step-by-Step)
  • మనం calculateArea అనే పేరుతో రెండు ఫంక్షన్స్ రాశాం. ఇది C లో అయితే "Redefinition error" అని ఫెయిల్ అవుతుంది. కానీ C++ లో అలో చేస్తుంది.
  • మనం మెయిన్ నుండి కేవలం (5) పంపినప్పుడు, కంపైలర్ చూసుకుని "అరె ఇక్కడ ఒకటే ఆర్గ్యుమెంట్ ఉంది, కాబట్టి ఫస్ట్ ఫంక్షన్ రన్ చేద్దాం" అని డిసైడ్ అవుతుంది.
  • ఆ తర్వాత (5, 10) అని రెండు పంపినప్పుడు, సెకండ్ ఫంక్షన్ కి వెళ్లిపోతుంది. దీన్నే కంపైల్-టైమ్ పాలిమార్ఫిజం (Compile-time Polymorphism) అని కూడా అంటారు.
5 ఇంటర్వ్యూలలో అడిగే కామన్ ప్రశ్నలు (FAQ)

Q1: కేవలం రిటర్న్ టైప్ (Return Type) మారిస్తే Overloading అవుతుందా?

అస్సలు కాదు! ఉదాహరణకు int getAge(int x) మరియు float getAge(int x) రాస్తే కంపైలర్ కి ఎర్రర్ వస్తుంది. ఎందుకంటే కంపైలర్ ఎప్పుడూ మీరు పంపే పరామీటర్స్ (కొన్నిసార్లు బ్రాకెట్స్ లో ఉన్నవి) చూసి మాత్రమే డిసైడ్ చేస్తుంది, రిటర్న్ ఏమొస్తుందో దానికి సంబంధం లేదు.

Q2: Default Arguments అంటే ఏమిటి?

మీరు ఫంక్షన్ డిక్లేర్ చేసేటప్పుడే int calculateArea(int length, int breadth = 10) అని రాయొచ్చు. దీని అర్థం ఏంటంటే, ఒకవేళ యూజర్ కేవలం ఒకటే నంబర్ పంపిస్తే, రెండో నంబర్ ని ఆటోమేటిక్ గా 10 కింద తీసుకో అని అర్థం. ఇది చాలా పాపులర్ ఫీచర్!

Q3: ఫంక్షన్ డిక్లరేషన్ (Prototype) ఎందుకు పైన రాయాలి?

C++ లో కంపైలర్ ఎప్పుడూ పై నుండి కిందికి చదువుకుంటూ వస్తుంది. మెయిన్ ఫంక్షన్ లోకి వచ్చేసరికి మీరు ఒక ఫంక్షన్ ని కాల్ చేస్తే, "ఇదెక్కడి నుంచి వచ్చింది?" అని కంపైలర్ కన్ఫ్యూజ్ అవుతుంది. అందుకే కింద రాసిన ఫంక్షన్ల గురించి ముందే పైన ఒక హెడ్డింగ్ (Prototype) లాగా చెప్తాము.
