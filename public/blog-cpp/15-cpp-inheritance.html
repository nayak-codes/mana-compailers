ఇన్హెరిటెన్స్ (Inheritance) & The Diamond Problem

కోడ్ పునర్వినియోగం మరియు హైరార్కీల నిర్మాణం! "IS-A" సంబంధం, Base vs Derived Classes, Inheritance Access Modes (public, protected, private), Multiple Inheritance లో తలెత్తే ప్రఖ్యాత The Dreaded Diamond Problem, C++ యొక్క సూపర్ సొల్యూషన్ virtual Base Classes, మరియు Constructor/Destructor ఆర్డర్.

1 ఇన్హెరిటెన్స్ (Inheritance) అంటే ఏమిటి? "IS-A" సంబంధం

ఒక కొత్త క్లాస్‌ను స్క్రాచ్ నుండి రాయకుండా, ఇప్పటికే ఉన్న క్లాస్ యొక్క లక్షణాలు (డేటా) మరియు సామర్థ్యాలను (ఫంక్షన్లు) వారసత్వంగా స్వీకరించే ప్రక్రియనే Inheritance అంటారు.

["IS-A" రిలేషన్‌షిప్ ఉదాహరణలు] • Dog IS-A Animal (జంతువుకు ఉండే గుణాలు కుక్కకు వస్తాయి) • SportsCar IS-A Vehicle (వాహనానికి ఉండే ఇంజిన్, వీల్స్ కారుకు వస్తాయి) • Manager IS-A Employee (ఎంప్లాయ్ జీతం, ఐడీ మేనేజర్‌కు వస్తాయి) టర్మినాలజీ: • Base Class (Parent / Super Class): అసలైన మూల క్లాస్. • Derived Class (Child / Sub Class): లక్షణాలను వారసత్వంగా తీసుకున్న చైల్డ్ క్లాస్.
2 Inheritance Modes: Visiblity Filter ఎలా పనిచేస్తుంది?

ఒక చైల్డ్ క్లాస్ పేరెంట్ క్లాస్‌ను ఇన్హెరిట్ చేసుకునేటప్పుడు (class Child : mode Parent), మూడు రకాల మోడ్స్ ఉంటాయి:

Base Class మెంబర్ public Inheritance protected Inheritance private Inheritance
public public గానే ఉంటుంది (సాధారణ పద్ధతి) protected గా మారుతుంది private గా మారుతుంది
protected protected గానే ఉంటుంది protected గా ఉంటుంది private గా మారుతుంది
private ఎప్పటికీ ఇన్హెరిట్ అవ్వదు (Not Inherited) ఎప్పటికీ ఇన్హెరిట్ అవ్వదు ఎప్పటికీ ఇన్హెరిట్ అవ్వదు
💻 Code Example 1: Base to Derived Constructor Initialization & Protected Scope
inheritance_hierarchy_demo.cpp
⚡ Try in Compiler 
#include <iostream>
#include <string>

// Base Class
class Device {
protected:
    std::string brand;
    int powerWatts;

public:
    Device(const std::string& b, int watts) : brand(b), powerWatts(watts) {
        std::cout << "  [1] Base Device Constructor: " << brand << "\n";
    }

    void showPower() const {
        std::cout << "Device Brand: " << brand << " | Power: " << powerWatts << "W\n";
    }
};

// Derived Class (Public Inheritance)
class SmartPhone : public Device {
private:
    int cameraMegaPixels;

public:
    // చైల్డ్ కన్‌స్ట్రక్టర్ Member Initializer List ద్వారా Base కన్‌స్ట్రక్టర్‌ను పిలుస్తుంది
    SmartPhone(const std::string& b, int watts, int mp) 
        : Device(b, watts), cameraMegaPixels(mp) {
        std::cout << "  [2] Derived SmartPhone Constructor Ready!\n";
    }

    void displaySpecs() const {
        // 'brand' అనేది protected కాబట్టి చైల్డ్ క్లాస్ లో నేరుగా యాక్సెస్ చేయవచ్చు
        std::cout << "SmartPhone: " << brand 
                  << " | Camera: " << cameraMegaPixels << " MP\n";
    }
};

int main() {
    std::cout << "=== Creating SmartPhone Object ===\n";
    SmartPhone myPhone("Google Pixel", 30, 50);

    std::cout << "\n=== Testing Inherited Capabilities ===\n";
    myPhone.showPower();    // Base క్లాస్ మెథడ్
    myPhone.displaySpecs(); // Derived క్లాస్ మెథడ్

    return 0;
}

3 The Dreaded Diamond Problem & Multiple Inheritance

జావా మరియు C# లలో ఒకే క్లాస్ ఒకటికి మించిన పేరెంట్ క్లాసుల నుండి ఇన్హెరిట్ చేసుకోలేదు (No Multiple Inheritance). కానీ C++ లో ఒక క్లాస్ ఎన్ని పేరెంట్ క్లాసుల నుంచైనా ఇన్హెరిట్ చేసుకోవచ్చు. అయితే దీనివల్ల కంప్యూటర్ సైన్స్‌లో ప్రసిద్ధి చెందిన The Diamond Problem తలెత్తుతుంది!

[ద డైమండ్ ప్రాబ్లమ్ ఆకారం (Diamond Shape Architecture)] ┌────────────────┐ │ PoweredDevice │ (Base: int powerRating) └───────┬────────┘ │ ┌────────────────┴────────────────┐ ▼ ▼ ┌─────────────────┐ ┌─────────────────┐ │ Scanner │ │ Printer │ └────────┬────────┘ └────────┬────────┘ │ │ └────────────────┬────────────────┘ ▼ ┌─────────────────┐ │ Copier │ (Derived from Scanner & Printer) └─────────────────┘ రామ్‌లో జరిగే ప్రమాదం: Copier ఆబ్జెక్ట్ లోపల PoweredDevice యొక్క 2 డూప్లికేట్ కాపీలు తయారవుతాయి: • Copier -> Scanner -> PoweredDevice (Copy 1) • Copier -> Printer -> PoweredDevice (Copy 2) ఇప్పుడు మీరు copier.powerRating అని రాస్తే, కంపైలర్ భయపడి ఆగిపోతుంది: "Error: request for member 'powerRating' is ambiguous!"
4 C++ అద్భుత పరిష్కారం: virtual Base Classes

ఈ డైమండ్ ప్రాబ్లమ్‌ను పరిష్కరించడానికి C++ లో virtual Inheritance ని ఉపయోగిస్తారు.

💎 Virtual Base Class మాయాజాలం:
మనం మధ్యలో ఉన్న క్లాసులను ఇలా డిక్లేర్ చేస్తాం:
class Scanner : virtual public PoweredDevice { ... };
class Printer : virtual public PoweredDevice { ... };

ఇలా virtual అని రాసినప్పుడు, కంపైలర్ ఒక రహస్య పాయింటర్ టేబుల్ (Virtual Base Table - vbptr) ను ఉపయోగించి, మెమరీలో PoweredDevice కి కేవలం ఒకే ఒక్క షేర్డ్ కాపీని కేటాయిస్తుంది! రెండు కాపీలు రాకుండా నిరోధిస్తుంది, ఫలితంగా అంబిగ్యుటీ శాశ్వతంగా తొలగిపోతుంది.
💻 Code Example 2: Complete Diamond Problem Solved via virtual Inheritance
diamond_problem_virtual.cpp
⚡ Try in Compiler 
#include <iostream>

// Base Class (Top of Diamond)
class PoweredDevice {
public:
    int voltage;
    PoweredDevice(int v) : voltage(v) {
        std::cout << "  [+] PoweredDevice Constructor (voltage: " << voltage << "V)\n";
    }
};

// Virtual Inheritance ద్వారా PoweredDevice ని షేర్ చేస్తాయి
class Scanner : virtual public PoweredDevice {
public:
    Scanner(int v) : PoweredDevice(v) {
        std::cout << "  [+] Scanner Subsystem Initialized\n";
    }
    void scanDocument() {
        std::cout << "      Scanning document at " << voltage << "V...\n";
    }
};

class Printer : virtual public PoweredDevice {
public:
    Printer(int v) : PoweredDevice(v) {
        std::cout << "  [+] Printer Subsystem Initialized\n";
    }
    void printDocument() {
        std::cout << "      Printing document at " << voltage << "V...\n";
    }
};

// Bottom of Diamond - Multiple Inheritance
class Copier : public Scanner, public Printer {
public:
    // వర్చువల్ బేస్ క్లాస్ ఉన్నప్పుడు, మోస్ట్ డిరైవ్డ్ క్లాస్ నేరుగా Base కన్‌స్ట్రక్టర్‌ను ఇనిషియలైజ్ చేయాలి!
    Copier(int v) : PoweredDevice(v), Scanner(v), Printer(v) {
        std::cout << "  [+] Copier All-in-One Device Ready!\n";
    }
};

int main() {
    std::cout << "=== Initializing Copier (Watch Single Base Constructor Execution) ===\n";
    Copier officeCopier(240);

    std::cout << "\n=== Testing Ambiguity Resolution ===\n";
    // డైమండ్ ప్రాబ్లమ్ ఉన్నట్లయితే ఈ క్రింది లైన్ కంపైల్ అయ్యేది కాదు (Ambiguity Error)!
    // వర్చువల్ ఇన్హెరిటెన్స్ వల్ల ఒకే voltage వేరియబుల్ ఉంటుంది:
    std::cout << "Office Copier Operating Voltage: " << officeCopier.voltage << "V\n";

    officeCopier.scanDocument();
    officeCopier.printDocument();

    return 0;
}

❓ Frequently Asked Questions (FAQ)

Q C++ లో 'The Diamond Problem' అంటే ఏమిటి?

రెండు చైల్డ్ క్లాసులు (B మరియు C) ఒకే పేరెంట్ క్లాస్ (A) నుండి ఇన్హెరిట్ అయ్యి, ఆ తర్వాత నాల్గవ క్లాస్ (D) ఈ B మరియు C రెండింటి నుండి మల్టిపుల్ ఇన్హెరిటెన్స్ చేసుకున్నప్పుడు డైమండ్ ఆకారం ఏర్పడుతుంది. దీనివల్ల D ఆబ్జెక్ట్ లోపల A యొక్క రెండు డూప్లికేట్ కాపీలు తయారై కంపైలర్ కు తీవ్రమైన Ambiguity ఎర్రర్ వస్తుంది.

Q Diamond Problem ని C++ లో ఎలా పరిష్కరిస్తారు?

virtual base class కీవర్డ్ ద్వారా పరిష్కరిస్తారు: class B : virtual public A మరియు class C : virtual public A. దీనివల్ల కంపైలర్ మెమరీలో A కి కేవలం ఒకే ఒక్క షేర్డ్ కాపీని సృష్టిస్తుంది, ఫలితంగా డూప్లికేషన్ మరియు అంబిగ్యుటీ పూర్తిగా తొలగిపోతాయి.

Q ఇన్హెరిటెన్స్ లో Base మరియు Derived క్లాస్ Constructors ఏ ఆర్డర్ లో రన్ అవుతాయి?

Constructors ఎల్లప్పుడూ పైనుండి క్రిందికి (Top-Down: Base Class Constructor ముందు, Derived Class Constructor తర్వాత) రన్ అవుతాయి. Destructors మాత్రం దానికి వ్యతిరేక క్రమంలో (Bottom-Up: Derived Class Destructor ముందు, Base Class Destructor తర్వాత) రన్ అవుతాయి.
