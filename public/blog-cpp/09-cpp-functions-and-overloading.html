ఫంక్షన్స్ & ఫంక్షన్ ఓవర్‌లోడింగ్ (Functions, Call Stack & Overloading)

⚡ Modern C++20 / C++17 🟢 Chapter 9 of 20 📂 Phase 3: Functions, Memory & Pointers 📅 2026 Edition
📌 Covered in this chapter: DRY Principle · Function Declarations vs Definitions · Call Stack Architecture in RAM · Pass-by-Value vs Pass-by-Reference (&) · const Reference Performance Secret · Function Overloading & Name Mangling
వేలాది లైన్ల సంక్లిష్టమైన సాఫ్ట్‌వేర్‌ను చిన్న చిన్న స్వతంత్ర భాగాలుగా విభజించి, రాసిన కోడ్‌ను మళ్లీ మళ్లీ రీయూజ్ చేసుకోవడానికి ఫంక్షన్స్ (Functions) వెన్నెముక వంటివి. కంప్యూటర్ RAM లో Call Stack ఎలా పెరుగుతుంది, పారామీటర్లను పాస్ చేసేటప్పుడు మెమరీ కాపీ అవ్వకుండా const & తో ఎలా ఆప్టిమైజ్ చేయాలి, మరియు కంపైలర్ Name Mangling ద్వారా ఫంక్షన్ ఓవర్‌లోడింగ్‌ను ఎలా అమలు చేస్తుందో ఈ అధ్యాయంలో సమగ్రంగా నేర్చుకుందాం.
1ఫంక్షన్ అనాటమీ & ఫార్వర్డ్ డిక్లరేషన్

ఒక ఫంక్షన్‌లో నాలుగు ముఖ్యమైన భాగాలు ఉంటాయి: Return Type, Function Name, Parameter List, మరియు Function Body.

⚠️ Function Prototype (Forward Declaration) ఎందుకు అవసరం?

C++ కంపైలర్ కోడ్‌ను పై నుండి కిందకి (Top-to-Bottom) చదువుతుంది. main() కింద మీరు ఒక ఫంక్షన్ రాసి, main() లోపల దాన్ని కాల్ చేస్తే కంపైలర్‌కు అది ఇంకా పరిచయం కాలేదు కాబట్టి "identifier not found" ఎర్రర్ వస్తుంది. అందుకే ఫైల్ ప్రారంభంలో int calculateSum(int a, int b); అని కేవలం సిగ్నేచర్‌ను మాత్రమే డిక్లేర్ చేయడాన్ని Function Prototype అంటారు.

ఒక ఫంక్షన్ కాల్ అయినప్పుడు కంప్యూటర్ RAM లోని Stack Memory లో ఒక ప్రత్యేకమైన గది (Stack Frame / Activation Record) కేటాయించబడుతుంది:

3Pass-by-Value vs Pass-by-Reference (&)

ఫంక్షన్‌కు ఆర్గ్యుమెంట్లను పంపే విధానం మీ ప్రోగ్రామ్ స్పీడ్‌ను మరియు ఫలితాన్ని సమూలంగా మారుస్తుంది:

📦 Pass-by-Value (విలువ కాపీ చేయడం)

ఒరిజినల్ వేరియబుల్ యొక్క డూప్లికేట్ కాపీ తయారవుతుంది. ఫంక్షన్ లోపల మార్పులు చేస్తే కేవలం ఆ కాపీ మాత్రమే మారుతుంది, ఒరిజినల్ వేరియబుల్ అలాగే ఉంటుంది. భారీ ఆబ్జెక్టులను కాపీ చేస్తే మెమరీ వేస్ట్ అవుతుంది.

⚡ Pass-by-Reference: Type& (అసలు మెమరీని ఇవ్వడం)

ఎటువంటి కాపీ తయారు కాదు! ఒరిజినల్ మెమరీ అడ్రస్‌కే మరొక మారుపేరు (Alias) క్రియేట్ అవుతుంది. ఫంక్షన్‌లో చేసే ప్రతి మార్పు ఒరిజినల్ వేరియబుల్ పైన నేరుగా ప్రతిఫలిస్తుంది. జీరో మెమరీ ఓవర్‌హెడ్!

💻 Example 1: Swapping Numbers with Pass-by-Reference
C++17 ▶ Run in Compiler 
#include <iostream>

// & గుర్తు ఉండటం వల్ల నేరుగా ఒరిజినల్ వేరియబుల్స్ మారుతాయి
void swapNumbers(int& x, int& y) {
    int temp = x;
    x = y;
    y = temp;
}

int main() {
    int a = 10, b = 99;
    std::cout << "Before: a = " << a << ", b = " << b << "\n";
    
    swapNumbers(a, b);
    
    std::cout << "After:  a = " << a << ", b = " << b << " (Swapped! 🚀)\n";
    return 0;
}

💡 The Gold Standard: const Type& (రీడ్-ఓన్లీ రిఫరెన్స్)

ఒకవేళ మీరు ఫంక్షన్‌లో విలువను మార్చకూడదు, కానీ కాపీ చేయడం వల్ల మెమరీ వేస్ట్ కూడా అవ్వకూడదు అనుకుంటే: const std::string& str వాడాలి. C++ ఇండస్ట్రీలో ఇది అత్యంత విస్తృతంగా ఉపయోగించే గోల్డెన్ బెస్ట్ ప్రాక్టీస్!

4ఫంక్షన్ ఓవర్‌లోడింగ్ & Name Mangling రహస్యం

ఒకే పేరుతో బహుళ ఫంక్షన్లను రాసే సదుపాయాన్ని Function Overloading అంటారు. అయితే పారామీటర్ల సంఖ్య లేదా వాటి డేటా టైపులు తప్పనిసరిగా వేరుగా ఉండాలి:

💻 Example 2: Overloaded add() Function
C++17 ▶ Run in Compiler 
#include <iostream>

int add(int a, int b) { return a + b; }
double add(double a, double b) { return a + b; }
int add(int a, int b, int c) { return a + b + c; }

int main() {
    std::cout << "Integers: " << add(10, 20) << "\n"
              << "Doubles:  " << add(4.5, 2.5) << "\n"
              << "3 Params: " << add(1, 2, 3) << "\n";
    return 0;
}

🔬 Name Mangling అంటే ఏమిటి?

CPU బైనరీ లెవల్‌లో రెండు ఫంక్షన్లకు ఒకే పేరు ఉండటానికి వీల్లేదు. అందుకే C++ కంపైలర్ ఫంక్షన్ పేరుతో పాటు పారామీటర్ల టైపులను కలిపి ఒక ప్రత్యేకమైన అంతర్గత గుర్తుగా మారుస్తుంది. ఉదాహరణకు add(int, int) ను కంపైలర్ లోపల _Z3addii గాను, add(double, double) ను _Z3adddd గాను మారుస్తుంది! దాన్నే Name Mangling అంటారు.
