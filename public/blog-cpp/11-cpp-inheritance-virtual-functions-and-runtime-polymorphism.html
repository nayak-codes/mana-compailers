Inheritance, Virtual Functions & Polymorphism (తెలుగులో)

⚡ Modern C++ (C++17 / C++20 / C++23) 🟢 Lesson 11 📂 Phase 11: Inheritance & Polymorphism 📅 2026 Master Edition
📌 Covered in this in-depth guide: Inheritance Types · Base vs Derived · Virtual Functions · V-Table & V-Ptr · Runtime Polymorphism

ఆబ్జెక్ట్ ఓరియెంటెడ్ ప్రోగ్రామింగ్ (OOP) లో రెండు అతిపెద్ద పిల్లర్స్ ఉన్నాయి. అందులో ఒకటి Inheritance (వారసత్వం), మరొకటి Polymorphism (బహురూపకత). ఒకసారి రాసిన కోడ్ ని పదే పదే రాయకుండా, ఉన్న కోడ్ నే కొద్దిగా మార్చుకుని కొత్త ఫీచర్స్ తయారు చేయడానికి ఇవి ఎంతో ఉపయోగపడతాయి. ముఖ్యంగా గేమ్ డెవలప్‌మెంట్ లాంటి పెద్ద ప్రాజెక్ట్స్ లో వందలాది క్యారెక్టర్స్ కి ఒకే రకమైన మూమెంట్స్ (నడక, పరుగు) ఉన్నప్పుడు, ప్రతి ఒక్కరికీ విడివిడిగా కోడ్ రాయలేము. అప్పుడే ఈ బేస్ క్లాస్ - డిరైవ్డ్ క్లాస్ కాన్సెప్ట్ మనల్ని కాపాడుతుంది. పైగా C++ కి మాత్రమే ప్రత్యేకం అయిన Virtual Table (v-table) ఎలా పనిచేస్తుందో ఈ రోజు డీప్ గా పోస్ట్‌మార్టం చేసి తెలుసుకుందాం.

1 అసలు Inheritance (వారసత్వం) ఎందుకు అవసరం?

మీరు ఒక జూ (Zoo) కి సంబంధించిన సాఫ్ట్‌వేర్ రాస్తున్నారు అనుకోండి. అందులో "సింహం (Lion)", "ఏనుగు (Elephant)", "కుక్క (Dog)" అనే మూడు క్లాసెస్ తయారు చేయాలి. మూడింటికి కామన్ గా కొన్ని లక్షణాలు ఉంటాయి: ప్రాణం ఉంటుంది, తింటాయి, నిద్రపోతాయి, అరుస్తాయి. ఆ మూడింటికి విడివిడిగా eat(), sleep() అనే ఫంక్షన్స్ రాస్తే కోడ్ మొత్తం డూప్లికేట్ (డబుల్) అవుతుంది.

🦁 రియల్ లైఫ్ స్టోరీ: జంతువులు - బేస్ క్లాస్ మరియు డిరైవ్డ్ క్లాస్

ఈ డూప్లికేషన్ ప్రాబ్లెమ్ ని సాల్వ్ చేయడానికి ప్రోగ్రామర్స్ ఏం చేస్తారంటే, ముందుగా "Animal" అనే ఒక పెద్ద క్లాస్ (దీన్నే Base Class లేదా Parent Class అంటారు) తయారు చేస్తారు. అందులో కామన్ గా ఉండే eat(), sleep() లాంటివి రాసి పెడతారు.

ఆ తర్వాత Lion మరియు Elephant అనే చిన్న క్లాసెస్ (దీన్నే Derived Class లేదా Child Class అంటారు) తయారు చేసి, వాటిని Animal కి లింక్ చేస్తారు (దీన్నే Inherit చేసుకోవడం అంటారు). ఇలా లింక్ చేసిన వెంటనే, Animal లో ఉన్న ఫంక్షన్స్ అన్నీ ఆటోమేటిక్ గా Lion లోకి వచ్చేస్తాయి! మళ్ళీ రాయక్కర్లేదు. ఇప్పుడు Lion క్లాస్ లో కేవలం సింహానికి మాత్రమే ప్రత్యేకమైన roar() (గర్జించడం) ఫంక్షన్ రాసుకుంటే చాలు. ఇదే ఇన్హెరిటెన్స్ మ్యాజిక్!

2 Polymorphism (పాలిమార్ఫిజం) అంటే ఏమిటి?

"Poly" అంటే చాలా (Many), "Morphs" అంటే రూపాలు (Forms). ఒకే ఫంక్షన్ వేరువేరు క్లాసెస్ లో వేరువేరు విధాలుగా పనిచేయడాన్నే పాలిమార్ఫిజం అంటారు. ఉదాహరణకు, Animal క్లాస్ లో makeSound() అనే ఫంక్షన్ ఉందనుకోండి. ఆ ఫంక్షన్ ని కుక్క (Dog) కాల్ చేస్తే "భౌ భౌ" అనాలి, పిల్లి (Cat) కాల్ చేస్తే "మియావ్" అనాలి. ఒకే makeSound() పేరు... కానీ అది పనిచేసే విధానం ఆబ్జెక్ట్ ని బట్టి మారిపోతుంది.

3 Virtual Functions మరియు V-Table రహస్యం

C++ లో పాలిమార్ఫిజం సాధించాలంటే బేస్ క్లాస్ లోని ఫంక్షన్ కి ముందు virtual అనే కీవర్డ్ పెట్టాలి. ఆ virtual అని పెడితే కంపైలర్ బ్యాక్ గ్రౌండ్ లో ఏం చేస్తుందో తెలుసా? ఒక రహస్యమైన టేబుల్ ని క్రియేట్ చేస్తుంది. దాన్నే V-Table (Virtual Table) అంటారు.

మీరు ప్రోగ్రామ్ ని రన్ చేసినప్పుడు, పాయింటర్ ఏ ఆబ్జెక్ట్ ని పట్టుకుని ఉందో చూసుకుని (అది కుక్కనా లేక పిల్లా అని), ఆ V-Table లో వెతికి కరెక్ట్ ఫంక్షన్ ని ఆన్ ది స్పాట్ (Runtime) లో కాల్ చేస్తుంది. దీనికి కొంచెం ఎక్స్ట్రా మెమరీ (V-Ptr) మరియు మైక్రో సెకండ్స్ టైమ్ పడుతుంది, కానీ ఇది ఎంతో పవర్ ఫుల్!

4 ఒకే ఒక సింపుల్ కోడ్ (Runtime Polymorphism)

కింద కోడ్ లో virtual కీవర్డ్ వాడి makeSound() అనే ఒకే ఫంక్షన్ తో కుక్కని, పిల్లిని ఎలా అరిపించామో (Polymorphism) జాగ్రత్తగా చూడండి.

C++ — Inheritance & Virtual Functions ▶ Run Code 
#include <iostream>

// Base Class (పేరెంట్)
class Animal {
public:
    // virtual పెట్టడం వల్ల కంపైలర్ కి అర్థమవుతుంది ఇది చైల్డ్ లో మారబోతోందని
    virtual void makeSound() {
        std::cout << "Some generic animal sound..." << std::endl;
    }
};

// Derived Class 1 (చైల్డ్)
class Dog : public Animal {
public:
    // బేస్ క్లాస్ ఫంక్షన్ ని ఓవర్ రైడ్ (Override) చేస్తున్నాం
    void makeSound() override {
        std::cout << "Dog says: Bow Bow!" << std::endl;
    }
};

// Derived Class 2 (చైల్డ్)
class Cat : public Animal {
public:
    void makeSound() override {
        std::cout << "Cat says: Meow Meow!" << std::endl;
    }
};

int main() {
    // బేస్ క్లాస్ పాయింటర్ (Animal*) తో చైల్డ్ ఆబ్జెక్ట్స్ ని కంట్రోల్ చేయడం
    Animal* myPet1 = new Dog();
    Animal* myPet2 = new Cat();
    
    // ఒకే రకమైన పాయింటర్, కానీ ఆబ్జెక్ట్ ని బట్టి రిజల్ట్ మారుతుంది!
    myPet1->makeSound(); // ఇది Bow Bow అని వస్తుంది
    myPet2->makeSound(); // ఇది Meow Meow అని వస్తుంది
    
    // మెమరీ లీక్ రాకుండా డిలీట్ చేయాలి
    delete myPet1;
    delete myPet2;
    
    return 0;
}
5 కోడ్ లో ఏం జరుగుతోంది? (Step-by-Step)
  • class Dog : public Animal: ఇక్కడ public Animal అని రాయడం వల్ల, Animal లో ఉన్న లక్షణాలన్నీ Dog లోకి వచ్చేశాయి.
  • virtual void makeSound(): పేరెంట్ లో virtual అని పెట్టకపోతే, మీరు Animal* పాయింటర్ వాడినప్పుడు అది ఎప్పటికీ పేరెంట్ లో ఉన్న "generic sound" నే కాల్ చేస్తుంది. Virtual పెట్టడం వల్లే అది ఒరిజినల్ ఆబ్జెక్ట్ (కుక్క) ఫంక్షన్ ని రన్ చేస్తుంది.
  • override: ఇది C++11 లో వచ్చిన ఫీచర్. మనం కావాలనే పేరెంట్ ఫంక్షన్ ని మారుస్తున్నాం అని కంపైలర్ కి క్లారిటీ ఇవ్వడానికి (స్పెల్లింగ్ మిస్టేక్స్ లేకుండా) ఇది వాడుతాం.
  • Animal* myPet1 = new Dog();: దీన్నే Upcasting అంటారు. ఒక పేరెంట్ పాయింటర్ తో చైల్డ్ ఆబ్జెక్ట్ ని స్టోర్ చేయడం. పెద్ద ప్రాజెక్ట్స్ లో వేలాది ఆబ్జెక్ట్స్ ని ఒకే అర్రే (Array of Animal Pointers) లో పెట్టి లూప్ తిప్పడానికి ఇది ప్రాణం లాంటిది.
6 ఇంటర్వ్యూలలో అడిగే కామన్ ప్రశ్నలు (FAQ)

Q1: C++ లో Multiple Inheritance (రెండు పేరెంట్స్ నుండి వారసత్వం) ఉంటుందా?

ఉంటుంది! జావా లో మల్టిపుల్ ఇన్హెరిటెన్స్ ఉండదు, కానీ C++ లో ఒక చైల్డ్ కి ఇద్దరు పేరెంట్స్ (ఉదాహరణకు class SmartPhone : public Phone, public Camera) ఉండొచ్చు. అయితే దీనివల్ల ఒక పెద్ద ప్రాబ్లెమ్ వస్తుంది, దాన్నే "Diamond Problem" అంటారు. దీన్ని సాల్వ్ చేయడానికి మళ్ళీ virtual inheritance అనే అడ్వాన్స్డ్ టెక్నిక్ వాడాలి.

Q2: Pure Virtual Function అంటే ఏంటి? Abstract Class అంటే ఏంటి?

కొన్నిసార్లు పేరెంట్ క్లాస్ లో ఫంక్షన్ బాడీ ఉండకూడదు, కేవలం హెడ్డింగ్ మాత్రమే ఉండాలి. అప్పుడు virtual void makeSound() = 0; అని రాస్తారు. దీన్నే ప్యూర్ వర్చువల్ ఫంక్షన్ అంటారు. ఏ క్లాస్ లో అయితే కనీసం ఒక ప్యూర్ వర్చువల్ ఫంక్షన్ ఉంటుందో దాన్ని Abstract Class (అబ్స్ట్రాక్ట్ క్లాస్) అంటారు. ఈ అబ్స్ట్రాక్ట్ క్లాస్ కి మీరు new వాడి డైరెక్ట్ గా ఆబ్జెక్ట్ క్రియేట్ చేయలేరు!

Q3: Destructor ని ఎందుకు ఎప్పుడూ virtual గా పెట్టమని చెప్తారు?

ఇది చాలా ఇంపార్టెంట్ ఇంటర్వ్యూ క్వశ్చన్! మీరు పేరెంట్ పాయింటర్ (Animal*) తో చైల్డ్ ఆబ్జెక్ట్ (Dog) ని క్రియేట్ చేసి, చివరికి delete myPet1; అని కాల్ చేస్తే, కంపైలర్ కేవలం Animal డిస్ట్రక్టర్ ని మాత్రమే రన్ చేసి Dog డిస్ట్రక్టర్ ని వదిలేస్తుంది (దీనివల్ల మెమరీ లీక్ వస్తుంది). అదే మీరు బేస్ క్లాస్ లో virtual ~Animal() అని పెడితే, అది ముందు కుక్క డిస్ట్రక్టర్ ని కాల్ చేసి, ఆ తర్వాత యానిమల్ డిస్ట్రక్టర్ ని క్లీన్ చేస్తుంది. పూర్తి సేఫ్టీ!
