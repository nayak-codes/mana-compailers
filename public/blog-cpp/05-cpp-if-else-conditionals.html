కండిషనల్ స్టేట్‌మెంట్స్ (if, else if, else & Nested Branches)

⚡ Modern C++20 / C++17 🟢 Chapter 5 of 20 📂 Phase 2: Control Flow & Loops 📅 2026 Edition
📌 Covered in this chapter: Decision Making in Code · CPU Branch Prediction · Simple if & if-else · else-if Ladder · Dangling Else Ambiguity · Modern C++17 if with initializer · Common Assignment Traps
కంప్యూటర్ కేవలం లెక్కలు మాత్రమే చేయదు, సందర్భాన్ని బట్టి సరైన నిర్ణయాలు (Decisions) కూడా తీసుకుంటుంది. ఈ అధ్యాయంలో ప్రోగ్రామ్ ఫ్లోను కంట్రోల్ చేసే if, if-else, else-if ladder, బగ్స్‌కు కారణమయ్యే Dangling Else సమస్య, మరియు Modern C++17 లో వచ్చిన సూపర్ ఆప్టిమైజ్డ్ if with initializer ఫీచర్‌ను నేర్చుకుందాం.
1Decision Making అంటే ఏమిటి? (Branching Logic)

సాధారణంగా ఒక ప్రోగ్రామ్ మొదటి లైన్ నుండి చివరి లైన్ వరకు వరుసగా (Sequentially) రన్ అవుతుంది. కానీ నిజ జీవితంలో పరిస్థితులను బట్టి దారి మార్చుకోవాల్సి వస్తుంది.

🚦 Real-World Analogy: ట్రాఫిక్ సిగ్నల్ & CPU బ్రాంచ్ ప్రిడిక్షన్

రోడ్డుపై వెళ్తున్నప్పుడు సిగ్నల్ GREEN అయితే ముందుకు వెళ్తాం, RED అయితే ఆగుతాం. ఆధునిక CPU లలో కూడా హార్డ్‌వేర్ లెవల్‌లో Branch Predictor ఉంటుంది. ప్రోగ్రామ్‌లోని కండిషన్ ఏ వైపు మొగ్గు చూపుతుందో ముందే ఊహించి ఆ ఇన్స్ట్రక్షన్లను CPU పైప్‌లైన్‌లో సిద్ధంగా ఉంచుతుంది.

2The Simple if & if-else Statements

ఒక నిర్దిష్ట షరతు (Condition) true అయినప్పుడు ఒక పని, false అయినప్పుడు ప్రత్యామ్నాయ పని చేయాలంటే if-else వాడతాం:

💻 Example 1: ATM Cash Withdrawal Authorization
C++17 ▶ Run in Compiler 
#include <iostream>

int main() {
    double accountBalance = 5000.0;
    double withdrawAmount = 2500.0;

    if (withdrawAmount <= accountBalance) {
        accountBalance -= withdrawAmount;
        std::cout << "Success: Cash Dispensed Rs. " << withdrawAmount << "\n";
    } else {
        std::cout << "Declined: Insufficient Funds!\n";
    }

    std::cout << "Available Balance: Rs. " << accountBalance << "\n";
    return 0;
}

🔍 లైన్-బై-లైన్ కోడ్ విశ్లేషణ:

  • if (withdrawAmount <= accountBalance): విత్‌డ్రా మొత్తం బ్యాలెన్స్ కంటే తక్కువ లేదా సమానమా అని బూలియన్ చెక్ చేస్తుంది.
  • accountBalance -= withdrawAmount;: కండిషన్ true అయితేనే ఖాతా నుండి డబ్బు కట్ అవుతుంది.
  • else { ... }: కండిషన్ false అయినప్పుడు మాత్రమే ఈ బ్లాక్ ఎగ్జిక్యూట్ అవుతుంది.
3else-if Ladder (బహుముఖ నిర్ణయాలు)

రెండు కంటే ఎక్కువ అవకాశాలు ఉన్నప్పుడు else-if నిచ్చెన వాడతాం. పై నుంచి కిందకి పరిశీలిస్తూ ఏ కండిషన్ మొదట true అయితే ఆ బ్లాక్ ఎగ్జిక్యూట్ చేసి నిచ్చెన నుండి బయటకు వచ్చేస్తుంది:

💻 Example 2: Academic Grading System
C++17 ▶ Run in Compiler 
#include <iostream>

int main() {
    int score = 88;

    if (score >= 90) {
        std::cout << "Grade: A+ (Outstanding 🌟)\n";
    } else if (score >= 75) {
        std::cout << "Grade: A (Distinction 🎓)\n";
    } else if (score >= 60) {
        std::cout << "Grade: B (First Class 📚)\n";
    } else if (score >= 35) {
        std::cout << "Grade: C (Pass ✅)\n";
    } else {
        std::cout << "Grade: F (Needs Improvement ⚠️)\n";
    }

    return 0;
}
4Modern C++17: if with Initializer

C++17 లో ప్రవేశపెట్టబడిన విప్లవాత్మక ఫీచర్ if with initializer. ఒక వేరియబుల్‌ను క్రియేట్ చేసి, వెంటనే కండిషన్ చెక్ చేసి, ఆ వేరియబుల్ పరిధిని (Scope) కేవలం ఆ if బ్లాక్‌కే పరిమితం చేయవచ్చు:

💻 Example 3: Scoped Initialization (C++17)
C++17 / C++20 ▶ Run in Compiler 
#include <iostream>

int fetchBatteryPercentage() { return 18; }

int main() {
    // C++17: if (Init; Condition)
    if (int battery = fetchBatteryPercentage(); battery < 20) {
        std::cout << "Low Battery: " << battery << "%! Please connect charger.\n";
    }
    // battery variable ఇక ఇక్కడ అందుబాటులో ఉండదు! మెమరీ క్లీన్ & సేఫ్.

    return 0;
}
5బిగినర్స్ చేసే ఘోరమైన తప్పులు (Beginner Pitfalls)
❌ Trap 1: The Semicolon after if Bug

పొరపాటున if (x > 10); { doSomething(); } అని రాస్తే, సెమికోలన్ వల్ల ఆ కండిషన్ అక్కడితో ముగిసిపోయి (Null Statement), కండిషన్ true అయినా false అయినా బ్రాకెట్ లోపలి కోడ్ ఎల్లప్పుడూ రన్ అయిపోతుంది!

❌ Trap 2: Dangling Else Problem

కర్లీ బ్రేసెస్ { } లేకుండా నెస్టెడ్ if-else రాసినప్పుడు, కంపైలర్ else ను ఎల్లప్పుడూ దానికి అతి సమీపంలో ఉన్న లోపలి if కే జతచేస్తుంది. దీనివల్ల లాజిక్ తలకిందులవుతుంది. అందుకే సింగిల్ లైన్ అయినా సరే ఎల్లప్పుడూ బ్రేసెస్ వాడటం గోల్డెన్ రూల్.
