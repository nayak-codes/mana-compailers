డెసిషన్ మేకింగ్ (if, else if, else)

🌐 Modern C++ (C++20/C++17) 🟢 Chapter 5 of 20 📂 Phase 02: కంట్రోల్ ఫ్లో & లూప్స్ 📅 2026 Edition
📌 Covered in this chapter: if-else కండిషన్స్ · if with initializer (C++17) · Nested if · షార్ట్-సర్క్యూట్ ఎవాల్యుయేషన్ · బెస్ట్ ప్రాక్టీసెస్

నిజ జీవితంలో మనం ప్రతిరోజూ వందలాది నిర్ణయాలు (Decisions) తీసుకుంటాం: "వర్షం పడితే గొడుగు తీసుకెళ్లు, లేకపోతే బైక్ పై వెళ్లు", "సిబిల్ స్కోర్ 750 కంటే ఎక్కువ ఉంటే లోన్ ఆమోదించు, లేకపోతే తిరస్కరించు". ప్రోగ్రామింగ్‌లో కంప్యూటర్ ఇటువంటి తెలివైన నిర్ణయాలు తీసుకోవడానికి ఉపయోగపడే అతి ముఖ్యమైన అంశమే Control Flow (డెసిషన్ మేకింగ్).

ఈ సమగ్ర పాఠంలో మనం ప్రాథమిక if, if-else, మరియు if - else if - else లాడర్ల నుండి మొదలుకొని — ఆధునిక C++17 లో ప్రవేశపెట్టబడిన విప్లవాత్మక if with Initializer (Scope Isolation), కంపైల్-టైమ్ నిర్ణయాలు తీసుకునే if constexpr, C++20 హై-పెర్ఫార్మెన్స్ [[likely]] / [[unlikely]] Branch Hints, మరియు ఎంటర్‌ప్రైజ్ సాఫ్ట్‌వేర్ ఆర్కిటెక్చర్‌లో వాడే Guard Clauses నమూనాల వరకు లోతుగా అధ్యయనం చేస్తాం. చివరిగా బ్యాంకింగ్ రంగం వాడే పూర్తి స్థాయి "Enterprise Credit Risk & Loan Approval Engine" ప్రాజెక్ట్‌ను లైవ్ కంపైలర్‌లో రన్ చేసి ప్రాక్టీస్ చేస్తాం!

1 కంట్రోల్ ఫ్లో అంటే ఏమిటి? కంప్యూటర్ నిర్ణయాలు ఎలా తీసుకుంటుంది?

సాధారణంగా ఏ ప్రోగ్రామ్‌లోనైనా కోడ్ మొదటి లైన్ నుండి చివరి లైన్ వరకు వరుసగా ఒకదాని తర్వాత ఒకటి (Sequential Execution) రన్ అవుతుంది. కానీ నిజ జీవిత సాఫ్ట్‌వేర్ అప్లికేషన్లు అలా కేవలం ఒకే సరళరేఖలో పనిచేయలేవు. కొన్ని పరిస్థితులలో ఒక బ్లాక్ కోడ్‌ను రన్ చేయాలి, మరికొన్ని పరిస్థితులలో ఆ కోడ్‌ను పూర్తిగా దాటవేసి (Skip) ప్రత్యామ్నాయ మార్గాన్ని ఎంచుకోవాలి.

ప్రోగ్రామ్ రన్ అయ్యే క్రమాన్ని మార్చే ఈ విధానాన్ని కంట్రోల్ ఫ్లో (Control Flow) లేదా బ్రాంచింగ్ (Branching) అంటారు. కంప్యూటర్ సిస్టమ్‌లో అంతర్గతంగా CPU ఒక డెసిషన్‌ను ఎలా తీసుకుంటుందో క్రింది రేఖాచిత్రం ద్వారా స్పష్టంగా అర్థం చేసుకోవచ్చు:

🧠 CPU Decision Flow Architecture (బ్రాంచింగ్ అంతర్గత సూత్రం)

[ప్రోగ్రామ్ మొదలు] ➔ [నిబంధనను పరిశీలించు (Evaluate Condition)]
                            │
           ┌────────────────┴────────────────┐
           ▼ [నిజమైతే (true / non-zero)]      ▼ [అబద్ధమైతే (false / 0)]
  [if బ్లాక్ కోడ్ రన్ అవుతుంది]      [else బ్లాక్ లేదా స్కిప్ అవుతుంది]
           └────────────────┬────────────────┘
                            ▼
           [తదుపరి ప్రోగ్రామ్ స్టేట్‌మెంట్లు రన్ అవుతాయి]

C++ లో ప్రతి కండిషన్ కూడా అంతిమంగా ఒక బూలియన్ విలువగా (bool) మారుతుంది: అది true (1 లేదా ఏ నాన్-జీరో సంఖ్య అయినా) లేదా false (0 లేదా nullptr). ఈ బూలియన్ ఫలితం ఆధారంగానే హార్డ్‌వేర్ లెవల్‌లో CPU ఇన్స్ట్రక్షన్ పాయింటర్ (Instruction Pointer - RIP/EIP) సరైన మెమరీ లొకేషన్‌కు జంప్ చేస్తుంది.

2 సాధారణ if స్టేట్‌మెంట్: సింటాక్స్ & బూలియన్ ఎవాల్యుయేషన్

C++ లో అత్యంత ప్రాథమిక డెసిషన్ మేకింగ్ స్టేట్‌మెంట్ if. ఇవ్వబడిన నిబంధన (Condition) true అయినప్పుడు మాత్రమే ఆ కర్లీ బ్రాకెట్ల { ... } లోపల ఉన్న కోడ్ ఎగ్జిక్యూట్ అవుతుంది; ఒకవేళ అది false అయితే కంపైలర్ ఆ బ్లాక్‌ను పూర్తిగా దాటవేసి (Skip) క్రింది కోడ్‌కు వెళ్లిపోతుంది.

if (కండిషన్ / బూలియన్ ఎక్స్‌ప్రెషన్) {
    // కండిషన్ true అయినప్పుడు మాత్రమే రన్ అయ్యే కోడ్ స్టేట్‌మెంట్లు
}

బూలియన్ ట్రూత్‌నెస్ నియమాలు (Truthiness in C++):
C++ లో కండిషన్ బ్రాకెట్లలో కేవలం true, false మాత్రమే కాకుండా పూర్ణాంకాలు లేదా పాయింటర్లను కూడా ఉంచవచ్చు. C++ నియమాల ప్రకారం:

  • సున్నా కాని ఏ సంఖ్య అయినా (ఉదాహరణకు 5, -10, 100) అంతర్గతంగా true గా పరిగణించబడుతుంది.
  • సున్నా (0), 0.0, లేదా nullptr మాత్రమే false గా పరిగణించబడతాయి.
💻 Example 1: Simple if Statement (స్మార్ట్‌ఫోన్ బ్యాటరీ వార్నింగ్ సిస్టమ్)
C++17 
#include <iostream>

int main() {
    int batteryLevel = 15; // 15% ఛార్జింగ్ మిగిలి ఉంది

    std::cout << "బ్యాటరీ స్థాయి: " << batteryLevel << "%\n";

    // 20% కంటే తక్కువ ఉంటేనే ఈ హెచ్చరిక బ్లాక్ రన్ అవుతుంది
    if (batteryLevel <= 20) {
        std::cout << "⚠️ హెచ్చరిక: బ్యాటరీ తక్కువగా ఉంది! దయచేసి వెంటనే ఛార్జర్ కనెక్ట్ చేయండి.\n";
        std::cout << "🔋 బ్యాటరీ సేవర్ మోడ్ ఆటోమేటిక్‌గా ఆన్ చేయబడింది.\n";
    }

    std::cout << "సిస్టమ్ సజావుగా నడుస్తోంది.\n";
    return 0;
}

💡 పై ఉదాహరణలో batteryLevel విలువ 15 కాబట్టి 15 <= 20 అనేది true అయింది. అందువల్ల కర్లీ బ్రాకెట్లలోని వార్నింగ్ ప్రింట్ అయింది. ఒకవేళ బ్యాటరీ 85% ఉంటే, ఆ రెండు వార్నింగ్ లైన్లు స్కిప్ అయి నేరుగా "సిస్టమ్ సజావుగా నడుస్తోంది" మాత్రమే ప్రింట్ అవుతుంది.

3 if - else కండిషన్: డ్యూయల్-పాత్ డెసిషన్ మేకింగ్

నిబంధన నిజమైతే ఒక పని, అబద్ధమైతే మరొక ప్రత్యామ్నాయ పని చేయాల్సి వచ్చినప్పుడు if-else ఉపయోగిస్తాము. దీనిని Dual-Path Decision Making అంటారు. ఇక్కడ రెండింటిలో ఏదో ఒక మార్గం మాత్రమే ఖచ్చితంగా ఎగ్జిక్యూట్ అవుతుంది — రెండు మార్గాలు ఎప్పటికీ కలిసి రన్ అవ్వవు!

💻 Example 2: Dual-Path if-else (ఓటరు అర్హత ధృవీకరణ వ్యవస్థ)
C++17 
#include <iostream>

int main() {
    int citizenAge = 17;

    std::cout << "నమోదైన పౌరుడి వయస్సు: " << citizenAge << " సంవత్సరాలు\n";

    if (citizenAge >= 18) {
        std::cout << "✅ మీరు ఓటు హక్కు వినియోగించుకోవడానికి పూర్తి అర్హులు (Eligible to Vote).\n";
        std::cout << "మీ ఓటర్ ఐడీ కార్డు డౌన్‌లోడ్ చేసుకోవచ్చు.\n";
    } else {
        int yearsRemaining = 18 - citizenAge;
        std::cout << "❌ మీరు ఇంకా మైనర్. ప్రస్తుతం ఓటు వేయడానికి అర్హత లేదు.\n";
        std::cout << "మరో " << yearsRemaining << " సంవత్సరం తర్వాత మీరు దరఖాస్తు చేసుకోవచ్చు.\n";
    }

    return 0;
}

4 మల్టీ-పాత్ డెసిషన్స్: if - else if - else లాడర్ ఆర్కిటెక్చర్

రెండు కంటే ఎక్కువ అవకాశాలు లేదా విభిన్న సంఖ్యా శ్రేణులు (Numerical Ranges, ఉదాహరణకు విద్యార్థి పరీక్ష మార్కుల గ్రేడింగ్ లేదా ఉద్యోగుల ఆదాయపు పన్ను స్లాబ్‌లు) ఉన్నప్పుడు if - else if - else లాడర్ (Ladder) ఉపయోగిస్తాము.

⚡ కంపైలర్ ఎవాల్యుయేషన్ సీక్రెట్ (Short-Circuit Ladder Exit)

కంపైలర్ ఈ లాడర్‌ను పై నుండి క్రిందికి (Top-to-Bottom) క్రమంగా పరిశీలిస్తుంది. ఎక్కడైతే మొదటి కండిషన్ true అవుతుందో, ఆ బ్లాక్ మాత్రమే రన్ అయి వెంటనే మొత్తం లాడర్ నుండి బయటకు (Exit) వచ్చేస్తుంది! మిగిలిన కండిషన్లు ఎంత నిజమైనవైనా సరే కంపైలర్ వాటిని అసలు తాకదు. కాబట్టి తరచుగా వచ్చే లేదా అధిక ప్రాధాన్యత కలిగిన నిబంధనలను పైన ఉంచడం మంచి ప్రోగ్రామింగ్ పద్ధతి.

💻 Example 3: Academic Grade Evaluation Ladder
C++17 
#include <iostream>

int main() {
    int score = 88;

    std::cout << "పరీక్షలో సాధించిన మార్కులు: " << score << "/100\n";

    if (score >= 90) {
        std::cout << "🏆 అద్భుతం! గ్రేడ్: A+ (Outstanding Performance)\n";
    } else if (score >= 80) {
        std::cout << "🌟 వెరీ గుడ్! గ్రేడ్: A (First Class with Distinction)\n";
    } else if (score >= 70) {
        std::cout << "👍 గుడ్! గ్రేడ్: B (First Class)\n";
    } else if (score >= 50) {
        std::cout << "⚠️ గ్రేడ్: C (Second Class - మెరుగుపరుచుకోవాలి)\n";
    } else if (score >= 35) {
        std::cout << "🛑 గ్రేడ్: D (Just Pass)\n";
    } else {
        std::cout << "❌ ఫెయిల్! మళ్లీ పరీక్ష రాయాల్సి ఉంటుంది.\n";
    }

    return 0;
}

5 నెస్టెడ్ కండిషన్స్ & The Dangling Else Problem

ఒక if లేదా else బ్లాక్ లోపల మరొక if-else స్టేట్‌మెంట్‌ను రాయడాన్ని Nested if-else అంటారు. ఒక ప్రాథమిక నిబంధన నెరవేరిన తర్వాతే, మరింత లోతైన ఉప-నిబంధనలను పరిశీలించాల్సి వచ్చినప్పుడు ఇది ఉపయోగపడుతుంది.

⚠️ The Classic "Dangling Else" Trap (ప్రమాదకరమైన బగ్)

C++ లో ఒకే లైన్ ఉన్నప్పుడు కర్లీ బ్రాకెట్లు {} ఐచ్ఛికం (Optional). కానీ బ్రాకెట్లు పెట్టకుండా నెస్టెడ్ కోడ్ రాసినప్పుడు కంపైలర్‌కు ఒక సందేహం వస్తుంది: "ఈ else మొదటి if కా? లేక రెండవ if కా?" దీనినే కంప్యూటర్ సైన్స్‌లో Dangling Else Problem అంటారు.

C++ గోల్డెన్ రూల్: ఒక else ఎల్లప్పుడూ తనకు అత్యంత సమీపంలో ఉన్న మునుపటి జతకాని (unmatched) if కి మాత్రమే అతుక్కుంటుంది!

⚠️ Dangling Else Bug Example & Clean Code Fix
C++17 Anti-Pattern & Solution 
#include <iostream>

int main() {
    int userAge = 25;
    bool hasDriverLicense = false;

    // ❌ తప్పుడు శైలి (Dangling Else): బ్రాకెట్లు లేకపోవడం వల్ల అయోమయం!
    // else అనేది age >= 18 కి చెందదు, hasDriverLicense కి చెందుతుంది!
    if (userAge >= 18)
        if (hasDriverLicense)
            std::cout << "మీరు కారు డ్రైవ్ చేయవచ్చు.\n";
    else
        std::cout << "మీరు మైనర్!\n"; // <-- ఘోరమైన బగ్! 25 ఏళ్ల వ్యక్తికి కూడా ఇది ప్రింట్ అవుతుంది!

    // ==============================================================
    // ✅ సరైన సాఫ్ట్‌వేర్ ఇంజనీరింగ్ పద్ధతి: స్పష్టంగా కర్లీ బ్రాకెట్లు {} వాడండి
    // ==============================================================
    if (userAge >= 18) {
        if (hasDriverLicense) {
            std::cout << "కారు నడపడానికి అనుమతి ఉంది.\n";
        } else {
            std::cout << "లైసెన్స్ లేకపోతే డ్రైవింగ్ చట్టరీత్యా నేరం!\n";
        }
    } else {
        std::cout << "మీకు ఇంకా 18 ఏళ్లు నిండలేదు.\n";
    }

    return 0;
}

6 ఆధునిక C++17 విప్లవం: if with Initializer (Scope Isolation)

సాంప్రదాయ C++ ప్రోగ్రామింగ్‌లో ఒక పెద్ద లోపం ఉండేది: ఒక కండిషన్ పరిశీలించడానికి ముందే మనం వేరియబుల్‌ను డిక్లేర్ చేయాల్సి వచ్చేది. ఆ వేరియబుల్ పని కేవలం ఆ if లోపల మాత్రమే ఉన్నప్పటికీ, అది ఫంక్షన్ చివరి వరకు మెమరీలో బ్రతికి ఉండి బయట నేమ్‌స్పేస్‌ను పాడుచేసేది (Variable Scope Pollution).

దీనికి పరిష్కారంగా Modern C++17 లో సరికొత్త సింటాక్స్ ప్రవేశపెట్టబడింది: if with Initializer!

if (init-statement; condition) {
    // ఇక్కడ 'init-statement' లో సృష్టించిన వేరియబుల్ వాడుకోవచ్చు
} else {
    // else లో కూడా ఆ వేరియబుల్ అందుబాటులో ఉంటుంది
}
// ఇక్కడ ఆ వేరియబుల్ మెమరీ నుండి ఆటోమేటిక్‌గా నాశనమైపోతుంది (Out of Scope)!

7 C++17 కంపైల్-టైమ్ కండిషనల్: if constexpr (Zero Runtime Cost)

సాధారణ if స్టేట్‌మెంట్ ప్రోగ్రామ్ రన్ అవుతున్న సమయంలో (Runtime) CPU ద్వారా ప్రతిసారీ కండిషన్‌ను లెక్కించి నిర్ణయం తీసుకుంటుంది. కానీ కొన్ని సందర్భాలలో కండిషన్ ఫలితం ప్రోగ్రామ్ రన్ అవ్వకముందే, కంపైలేషన్ సమయంలోనే మనకు ఖచ్చితంగా తెలిసిపోతుంది (ఉదాహరణకు టెంప్లేట్ డేటా టైప్స్ లేదా sizeof చెకింగ్స్).

అటువంటి సందర్భాలలో Modern C++17 లో వచ్చిన if constexpr అద్భుతంగా పనిచేస్తుంది.

🚀 Zero-Overhead Metaprogramming (మెషిన్ కోడ్ నుండి డెడ్ బ్రాంచ్ తొలగింపు)

కంపైలేషన్ సమయంలో ఏ బ్రాంచ్ అయితే false అవుతుందో, ఆ కోడ్‌ను కంపైలర్ ఫైనల్ మెషిన్ కోడ్ (బైనరీ) నుండి పూర్తిగా శాశ్వతంగా డిలీట్ చేసి పారేస్తుంది! రన్‌టైమ్ లో CPU ఒక్క క్లాక్ సైకిల్ కూడా ఖర్చు చేయదు. ఇది టెంప్లేట్ ప్రోగ్రామింగ్‌లో కోడ్ పరిమాణాన్ని మరియు రన్‌టైమ్ వేగాన్ని గణనీయంగా పెంచుతుంది.

💻 Example 5: C++17 if constexpr in Generic Functions
Modern C++17 if constexpr 
#include <iostream>
#include <type_traits>

// జెనరిక్ ఫంక్షన్: కంపైల్-టైమ్‌లోనే డేటా టైప్‌ను బట్టి సరైన పాత్ ఎంపిక చేసుకుంటుంది
template <typename T>
void processData(T value) {
    if constexpr (std::is_integral_v<T>) {
        std::cout << "పూర్ణాంకం (Integer): " << value << " | ద్విగుణీకృతం: " << (value * 2) << '\n';
    } else if constexpr (std::is_floating_point_v<T>) {
        std::cout << "దశాంశం (Floating-Point): " << value << " | సగం విలువ: " << (value / 2.0) << '\n';
    } else {
        std::cout << "ఇతర డేటా టైప్ విలువ: " << value << '\n';
    }
}

int main() {
    processData(42);       // కంపైల్ సమయంలోనే కేవలం Integer బ్రాంచ్ మాత్రమే బైనరీలో ఉంటుంది
    processData(3.14159);  // కేవలం Floating బ్రాంచ్ మాత్రమే బైనరీలో ఉంటుంది
    return 0;
}

8 లాజికల్ ఆపరేటర్ల కలయిక (&&, ||, !) & కాంప్లెక్స్ బిజినెస్ రూల్స్

నిజ జీవితంలో ఒక వ్యాపార లేదా సాంకేతిక నిర్ణయం తీసుకోవడానికి బహుళ నిబంధనలు ఏకకాలంలో కలిసి పనిచేయాలి. ఉదాహరణకు ఒక ప్రముఖ టెక్ కంపెనీలో క్యాంపస్ ఇంటర్వ్యూకు అర్హత పొందాలంటే: కంప్యూటర్ సైన్స్ డిగ్రీ ఉండాలి (Degree == true) AND CGPA >= 7.5 AND (C++ లో ప్రావీణ్యం OR Java లో ప్రావీణ్యం) AND యాక్టివ్ బ్యాక్‌లాగ్‌లు సున్నాగా ఉండాలి.

9 షార్ట్-సర్క్యూట్ ఎవాల్యుయేషన్ ఇన్ డెసిషన్ మేకింగ్ & నల్-సేఫ్టీ

మనం Chapter 04 లో నేర్చుకున్న Short-Circuit Evaluation, if స్టేట్‌మెంట్లలో సిస్టమ్ క్రాష్ కాకుండా కాపాడే ఒక రక్షణ కవచంలా పనిచేస్తుంది:

  • లాజికల్ AND (&&): మొదటి కండిషన్ false అయితే, రెండవ కండిషన్ ఎంత ముఖ్యమైనదైనా సరే కంపైలర్ దానిని అసలు ముట్టుకోదు! ఎందుకంటే మొదటిదే ఫెయిల్ అయినప్పుడు మొత్తం స్టేట్‌మెంట్ ఎప్పటికీ true కాలేదు.
  • లాజికల్ OR (||): మొదటి కండిషన్ true అయితే, రెండవ కండిషన్‌ను పరిశీలించకుండానే వెంటనే రిజల్ట్ true గా ఖరారు చేస్తుంది.

🛡️ Null-Pointer Segmentation Fault నివారణ

సాఫ్ట్‌వేర్ డెవలప్‌మెంట్‌లో పాయింటర్లు వాడేటప్పుడు షార్ట్-సర్క్యూట్ అత్యంత ప్రాణాధారమైనది. ఉదాహరణకు:
if (ptr != nullptr && ptr->hasActiveSubscription())
ఒకవేళ ptr నల్ అయితే, మొదటి భాగం false అవుతుంది. షార్ట్-సర్క్యూట్ నియమం ప్రకారం రెండవ భాగమైన ptr->... రన్ అవ్వదు! దీనివల్ల ఆపరేటింగ్ సిస్టమ్ ప్రోగ్రామ్‌ను Segmentation Fault (SIGSEGV) తో క్రాష్ చేయకుండా సేఫ్ చేస్తుంది.

10 టెర్నరీ ఆపరేటర్ (? :) vs if-else: ఎప్పుడు ఏది వాడాలి?

బిగినర్ డెవలపర్లలో తరచుగా ఒక సందిగ్ధత ఉంటుంది: "ఎప్పుడు టెర్నరీ ఆపరేటర్ వాడాలి, ఎప్పుడు if-else వాడాలి?" క్రింది మార్గదర్శకాలు మీకు స్పష్టతనిస్తాయి:

ఫీచర్ / అంశం టెర్నరీ ఆపరేటర్ (condition ? A : B) సాధారణ if - else స్టేట్‌మెంట్
స్వభావం (Nature) ఇది ఒక ఎక్స్‌ప్రెషన్ (Expression). అంటే ఇది కచ్చితంగా ఒక విలువను రిటర్న్ చేస్తుంది. ఇది ఒక స్టేట్‌మెంట్ (Statement). ఇది విలువను రిటర్న్ చేయదు, కోడ్ బ్లాక్‌ను రన్ చేస్తుంది.
ఉత్తమ వినియోగం ఒక వేరియబుల్‌కు విలువ కేటాయించేటప్పుడు, లేదా const వేరియబుల్స్ ప్రారంభించేటప్పుడు. బహుళ లైన్ల లాజిక్ ఉన్నప్పుడు, ఫంక్షన్స్ కాల్ చేయాల్సి వచ్చినప్పుడు, I/O ఆపరేషన్స్ ఉన్నప్పుడు.
const వేరియబుల్స్ సపోర్ట్ ✅ అద్భుతంగా పనిచేస్తుంది (ఉదా: const int max = a > b ? a : b;). ❌ కష్టం (if బయట const పెడితే ముందే విలువ ఇవ్వాలి, if లోపల మార్చలేము).
చదవడానికి సౌలభ్యం (Readability) సింగిల్ లైన్ లాజిక్‌కు చాలా క్లీన్ గా ఉంటుంది. పెద్ద మరియు కాంప్లెక్స్ బిజినెస్ లాజిక్‌కు అత్యంత అనుకూలం.

11 ఆధునిక C++20 బ్రాంచ్ ప్రిడిక్షన్ హింట్స్: [[likely]] & [[unlikely]]

హై-ఫ్రీక్వెన్సీ ట్రేడింగ్ (HFT ట్రేడింగ్ సిస్టమ్స్), AAA వీడియో గేమ్ ఇంజిన్లు (Unreal Engine), మరియు ఆటోనామస్ కార్ల సాఫ్ట్‌వేర్‌లో మైక్రోసెకన్ల సమయం కూడా చాలా విలువైంది. అక్కడ CPU హార్డ్‌వేర్ లెవల్‌లో బ్రాంచ్ మిస్‌ప్రిడిక్షన్ (Branch Misprediction Penalty) వల్ల 15 నుండి 20 క్లాక్ సైకిల్స్ వృధా అవుతాయి.

దీనిని అరికట్టడానికి Modern C++20 సరికొత్త అట్రిబ్యూట్స్‌ను అందించింది: [[likely]] మరియు [[unlikely]].

⚙️ CPU హార్డ్‌వేర్ పై వీటి ప్రభావం ఏమిటి?

ఆధునిక ప్రాసెసర్లు బ్రాంచ్ ప్రిడిక్టర్ (Branch Predictor & Branch Target Buffer) కలిగి ఉంటాయి. మనం [[likely]] అని సూచించినప్పుడు, కంపైలర్ అసెంబ్లీ కోడ్ ఉత్పత్తి చేసేటప్పుడు ఆ హాట్-పాత్ (Hot-path) సూచనలను CPU L1 ఇన్స్ట్రక్షన్ క్యాష్‌లో జంప్స్ లేకుండా నేరుగా ఇన్-లైన్ గా ఉంచుతుంది. దీనివల్ల పైప్‌లైన్ స్టాల్స్ మరియు ఫ్లష్ అవ్వకుండా సున్నా నష్టంతో కోడ్ అత్యంత వేగంగా పరిగెడుతుంది! 

// Modern C++20 High-Performance Branching
if (networkPacketChecksumValid) [[likely]] {
    processRealTimeTradingOrder(); // 99.9% సమయాల్లో రన్ అయ్యే సూపర్ ఫాస్ట్ పాత్
} else [[unlikely]] {
    logCorruptedPacketError();     // 0.1% అరుదుగా మాత్రమే రన్ అయ్యే ఎర్రర్ హ్యాండ్లర్
}

12 సాధారణ బిగినర్ తప్పులు, సెమికోలన్ ట్రాప్స్ & Guard Clauses

C++ లో ప్రోగ్రామింగ్ చేసేటప్పుడు బిగినర్స్ నుండి జూనియర్ డెవలపర్ల వరకు తరచుగా చేసే కొన్ని తీవ్రమైన తప్పులు మరియు వాటిని అధిగమించే పద్ధతులు:

❌ Trap 1: if కండిషన్ పక్కన సెమికోలన్ (;) పెట్టే ఘోరమైన బగ్
if (userMarks >= 90); // ⚠️ సెమికోలన్ ఇక్కడే స్టేట్‌మెంట్‌ను ముగించేసింది!
{
    std::cout << "మీకు గోల్డ్ మెడల్ వచ్చింది!\n"; // ఇది మార్కులతో సంబంధం లేకుండా ఎప్పుడూ ప్రింట్ అవుతుంది!
}

వివరణ: if కండిషన్ బ్రాకెట్ల కుడివైపు పొరపాటున కూడా సెమికోలన్ పెట్టకూడదు! అలా పెడితే ఆ కండిషన్ ఒక ఖాళీ స్టేట్‌మెంట్ (Null statement) తో ముగిసిపోయి, కర్లీ బ్రాకెట్లలో ఉన్న బ్లాక్ సాధారణ స్వతంత్ర బ్లాక్‌గా మారి ఎల్లప్పుడూ రన్ అయిపోతుంది.

❌ Trap 2: అసైన్‌మెంట్ (=) మరియు ఈక్వాలిటీ (==) మధ్య గందరగోళం
int isAdmin = 0;
if (isAdmin = 1) { // ⚠️ పోల్చడం లేదు! 1 ని isAdmin కి అసైన్ చేస్తున్నారు!
    std::cout << "సూపర్ అడ్మిన్ యాక్సెస్ మంజూరైంది!\n"; // ఇది ఎల్లప్పుడూ రన్ అవుతుంది!
}

వివరణ: == సమానత్వాన్ని పోల్చడానికి వాడాలి. కేవలం = వాడితే విలువ మారిపోయి ఆ ఫలితమే (ఇక్కడ 1) కండిషన్‌గా మారి ఎల్లప్పుడూ true అవుతుంది. దీనివల్ల భద్రతా రంధ్రాలు (Security Vulnerabilities) ఏర్పడతాయి.

✅ Pro Software Engineering Pattern: Guard Clauses (నివారించండి Pyramid of Doom)

ఒక if లోపల ఇంకో if, దాని లోపల ఇంకో if రాసుకుంటూ పోతే కోడ్ పిరమిడ్ లాగా కుడివైపుకు వెళ్లిపోతుంది (Arrow Anti-Pattern లేదా Pyramid of Doom). దీనికి బదులుగా చెల్లని నిబంధన లేదా ఎర్రర్ రాగానే వెంటనే return చేసి బయటకు వచ్చేయడాన్నే Guard Clause అంటారు. దీనివల్ల కోడ్ ఫ్లాట్ గా, అత్యంత స్పష్టంగా ఉంటుంది.

13 రియల్-వరల్డ్ ప్రాక్టీస్ ప్రాజెక్ట్: "Banking Loan Approval & Credit Risk Engine"

ఈ అధ్యాయంలో నేర్చుకున్న if, else if, else, Modern C++17 if with initializer, మరియు కాంప్లెక్స్ బిజినెస్ రూల్స్ అన్నింటినీ ఉపయోగించి — బ్యాంకింగ్ రంగానికి చెందిన పూర్తి స్థాయి "Enterprise Home Loan Risk Assessment & Approval Engine" ప్రాజెక్ట్‌ను రన్ చేద్దాం:

💻 Complete Masterclass Practice Project: Loan Approval Engine
C++17 / C++20 Complete Project 
#include <iostream>
#include <string>
#include <iomanip>

int main() {
    std::string applicantName = "కె. రాజశేఖర్ రెడ్డి (K. Rajasekhar Reddy)";
    int age = 34;
    double monthlySalary = 95000.00;
    int cibilScore = 780;
    double existingEmi = 18000.00;
    double requestedLoanAmount = 4500000.00; // ₹45 లక్షల హోమ్ లోన్

    std::cout << std::fixed << std::setprecision(2);
    std::cout << "================================================================\n";
    std::cout << "     🏦 HDFC-STYLE ENTERPRISE HOME LOAN RISK ASSESSMENT ENGINE  \n";
    std::cout << "================================================================\n";
    std::cout << "దరఖాస్తుదారు పేరు : " << applicantName << '\n';
    std::cout << "వయస్సు            : " << age << " సంవత్సరాలు\n";
    std::cout << "నెలవారీ ఆదాయం    : ₹ " << monthlySalary << '\n';
    std::cout << "క్రెడిట్ సిబిల్ స్కోర్ : " << cibilScore << " / 900\n";
    std::cout << "కోరిన లోన్ మొత్తం : ₹ " << requestedLoanAmount << '\n';
    std::cout << "----------------------------------------------------------------\n";

    // 1. ప్రాథమిక వయస్సు ధృవీకరణ (Age Verification Guard)
    if (age < 21 || age > 60) {
        std::cout << "❌ లోన్ తిరస్కరణ: దరఖాస్తుదారు వయస్సు 21 నుండి 60 సంవత్సరాల మధ్య ఉండాలి.\n";
        return 0; // Guard Clause: వెంటనే ప్రోగ్రామ్ ముగించండి
    }

    // 2. C++17 if with initializer: డెట్-టు-ఇన్‌కమ్ రేషియో (DTI) గణన
    if (double dtiRatio = (existingEmi / monthlySalary) * 100.0; dtiRatio > 50.0) {
        std::cout << "❌ తిరస్కరణ: మీ ప్రస్తుత EMI భారం (DTI: " << dtiRatio << "%) 50% కంటే ఎక్కువగా ఉంది!\n";
        std::cout << "ప్రస్తుతం అదనపు లోన్ మంజూరు చేయడం అధిక రిస్క్ అని నిర్ధారించబడింది.\n";
    } else {
        // 3. మల్టీ-లెవల్ అప్రూవల్ లాడర్ (CIBIL Score Risk Tiering)
        double approvedAmount = 0.0;
        double interestRate = 0.0;
        std::string riskLevel;

        if (cibilScore >= 800) {
            approvedAmount = requestedLoanAmount;
            interestRate = 8.35;
            riskLevel = "🟢 Low Risk (Prime Tier A+)";
        } else if (cibilScore >= 750) {
            approvedAmount = requestedLoanAmount;
            interestRate = 8.65;
            riskLevel = "🟢 Moderate Low Risk (Tier A)";
        } else if (cibilScore >= 700) {
            approvedAmount = requestedLoanAmount * 0.80; // 80% మాత్రమే ఆమోదం
            interestRate = 9.25;
            riskLevel = "🟡 Medium Risk (Tier B)";
        } else if (cibilScore >= 650) {
            approvedAmount = requestedLoanAmount * 0.50; // 50% మాత్రమే
            interestRate = 10.50;
            riskLevel = "🟠 High Risk (Tier C - షూరిటీ అవసరం)";
        } else {
            approvedAmount = 0.0;
            riskLevel = "🔴 Rejected (Poor CIBIL Score)";
        }

        if (approvedAmount > 0.0) {
            std::cout << "🎉 ఆమోదం లభించింది (LOAN SANCTIONED!)\n";
            std::cout << "రిస్క్ వర్గీకరణ   : " << riskLevel << '\n';
            std::cout << "మంజూరైన మొత్తం   : ₹ " << approvedAmount << '\n';
            std::cout << "వడ్డీ రేటు (ROI)   : " << interestRate << " % p.a.\n";
            std::cout << "అనుమతించబడిన ఈఎంఐ : ₹ " << (approvedAmount * 0.009) << " (సుమారుగ 20 సం. కాలపరిమితి)\n";
        } else {
            std::cout << "❌ లోన్ తిరస్కరించబడింది. సిబిల్ స్కోర్ మెరుగుపరుచుకోండి.\n";
        }
    }

    std::cout << "================================================================\n";
    return 0;
}

❓ ఇంటర్వ్యూ & పరీక్షల క్విజ్ (Knowledge Check)

ప్రశ్న 1: C++17 లో ప్రవేశపెట్టబడిన if with initializer (if (init; cond)) ఎందుకు వాడాలి?
సమాధానం: సాంప్రదాయక C++ లో కండిషన్ కొరకు సృష్టించే వేరియబుల్స్ ఆ ఫంక్షన్ అంతటా బ్రతికి ఉండి స్కోప్ పొల్యూషన్ మరియు నేమింగ్ కొలిషన్స్‌కు కారణమవుతాయి. C++17 if (init; cond) ద్వారా సృష్టించిన వేరియబుల్ పరిధి (Scope) కేవలం ఆ if-else బ్లాక్ వరకే పరిమితమై ఉంటుంది. ఆ బ్లాక్ దాటగానే అది ఆటోమేటిక్‌గా మెమరీ నుండి డిలీట్ అయిపోతుంది, దీనివల్ల మెమరీ లీక్‌లు మరియు సైడ్-ఎఫెక్ట్‌లు నివారించబడతాయి.
ప్రశ్న 2: if constexpr మరియు సాధారణ if మధ్య గల ప్రధాన సాంకేతిక తేడా ఏమిటి?
సమాధానం: సాధారణ if స్టేట్‌మెంట్ రన్‌టైమ్‌లో (Runtime) CPU ద్వారా లెక్కించబడుతుంది. కానీ if constexpr కంపైలేషన్ సమయంలోనే (Compile-time) లెక్కించబడుతుంది. కంపైలర్ తప్పుడు బ్రాంచ్‌ను ఫైనల్ బైనరీ మెషిన్ కోడ్ నుండి పూర్తిగా తొలగించి పారేస్తుంది. దీనివల్ల రన్‌టైమ్‌లో ఎటువంటి CPU క్లాక్ సైకిల్స్ ఖర్చు కావు (Zero Runtime Overhead).
ప్రశ్న 3: Dangling Else సమస్య అంటే ఏమిటి? దానిని నివారించడానికి సురక్షితమైన మార్గం ఏది?
సమాధానం: కర్లీ బ్రాకెట్లు లేకుండా నెస్టెడ్ if స్టేట్‌మెంట్లు రాసినప్పుడు, ఒక else ఏ if కి వర్తిస్తుందో అయోమయం ఏర్పడటాన్ని Dangling Else అంటారు. C++ లో else ఎల్లప్పుడూ తనకు దగ్గరగా ఉన్న మునుపటి if కి మాత్రమే అనుసంధానమవుతుంది. ఈ ప్రమాదం నుండి తప్పించుకోవడానికి సింగిల్ లైన్ స్టేట్‌మెంట్ ఉన్నా సరే ఎల్లప్పుడూ స్పష్టంగా { } కర్లీ బ్రాకెట్లను ఉపయోగించడమే పరిశ్రమ ప్రామాణిక పరిష్కారం.
ప్రశ్న 4: Modern C++20 లోని [[likely]] మరియు [[unlikely]] అట్రిబ్యూట్స్ CPU పెర్ఫార్మెన్స్‌ను ఎలా మెరుగుపరుస్తాయి?
సమాధానం: ఇవి కంపైలర్‌కు బ్రాంచ్ ప్రిడిక్షన్ హింట్స్ ఇస్తాయి. [[likely]] ఉన్నప్పుడు కంపైలర్ ఆ కోడ్ పాత్‌ను CPU L1 ఇన్స్ట్రక్షన్ క్యాష్‌లో జంప్స్ లేకుండా స్ట్రెయిట్‌గా ఎగ్జిక్యూట్ అయ్యేలా అసెంబ్లీ కోడ్‌ను ఆప్టిమైజ్ చేస్తుంది. దీనివల్ల CPU పైప్‌లైన్ స్టాల్స్ మరియు బ్రాంచ్ మిస్‌ప్రిడిక్షన్ పెనాల్టీ (15-20 క్లాక్ సైకిల్స్) పూర్తిగా తప్పుతాయి.
ప్రశ్న 5: "Guard Clauses" పద్ధతి నెస్టెడ్ if-else ల కంటే ఎందుకు మెరుగైనది?
సమాధానం: నెస్టెడ్ if లోపల మరో if రాయడం వల్ల కోడ్ పిరమిడ్ లాగా కుడివైపుకు జరిగిపోయి చదవడం చాలా సంక్లిష్టమవుతుంది (Pyramid of Doom). Guard Clause పద్ధతిలో చెల్లని లేదా ఎర్రర్ పరిస్థితులు ఎదురైన వెంటనే ఫంక్షన్ నుండి return చేసి బయటకు వచ్చేస్తారు. దీనివల్ల మెయిన్ బిజినెస్ లాజిక్ ఎటువంటి ఇండెంటేషన్ లేకుండా ఫ్లాట్ గా, స్పష్టంగా కనిపిస్తుంది.
