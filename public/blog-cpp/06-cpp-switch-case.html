switch స్టేట్‌మెంట్ & Fall-through (switch, case, break, default)

⚡ Modern C++20 / C++17 🟢 Chapter 6 of 20 📂 Phase 2: Control Flow & Loops 📅 2026 Edition
📌 Covered in this chapter: switch vs if-else Performance · Jump Tables Internal Architecture · Syntax (switch, case, break, default) · The Dangerous Fall-through Trap · Modern C++17 [[fallthrough]] Attribute · Scoped Variables in Case Blocks · C++17 switch with Initializer
ఒక వేరియబుల్ విలువను పదుల కొద్దీ స్థిరాంకాలతో (Constants) పోల్చాల్సి వచ్చినప్పుడు 10 else-if లు రాయడం కోడ్‌ను గజిబిజి చేస్తుంది. C++ లో దీనికి సమాధానమే `switch` స్టేట్‌మెంట్. కంపైలర్ లోపల Jump Table ఎలా పనిచేస్తుందో, బిగినర్లను వేధించే Fall-through మెకానిజం, మరియు C++17 లో ప్రవేశపెట్టిన ఆధునిక ఆట్రిబ్యూట్‌లను ఈ అధ్యాయంలో నేర్చుకుందాం.
1`switch` vs `if-else`: Jump Table రహస్యం

చాలామందికి ఒక సందేహం ఉంటుంది: if-else ఉండగా switch ఎందుకు వాడాలి?

⚡ Under the Hood: Jump Table vs Linear Search

• else-if Ladder: కంపైలర్ ప్రతి కండిషన్‌ను మొదటి నుండి ఒకదాని తర్వాత ఒకటి వరుసగా చెక్ చేసుకుంటూ వెళ్తుంది (Linear Search - $O(N)$ టైమ్ కాంప్లెక్సిటీ). 10వ కండిషన్ మ్యాచ్ అవ్వాలంటే పై 9 తప్పు అని తేలాలి!

• switch Statement: C++ కంపైలర్ కేస్ విలువలతో మెమరీలో ఒక Jump Table (అడ్రస్‌ల అరే) తయారు చేస్తుంది. యూజర్ ఇచ్చిన విలువ ఆధారంగా ఏ లొకేషన్‌కి వెళ్లాలో నేరుగా లెక్కించి ఒకే జంప్‌తో ఆ కేస్‌కి వెళ్లిపోతుంది (Direct Jump - $O(1)$ కాన్‌స్టాంట్ టైమ్!). కాబట్టి అనేక స్థిర విలువల పోలికలో switch చాలా వేగవంతమైనది!

2`switch` సింటాక్స్ & బేసిక్ ఎగ్జాంపుల్

switch స్టేట్‌మెంట్‌లో 4 ముఖ్యమైన భాగాలు ఉంటాయి:

  • switch(expression): పరీక్షించాల్సిన పూర్ణాంక వేరియబుల్ (int, char, enum మాత్రమే!).
  • case constant:: ఆ వేరియబుల్ సమానమవ్వాల్సిన విలువ.
  • break;: ఆ పని ముగియగానే స్విచ్ బ్లాక్ నుండి బయటకు దూకడానికి (Jump out).
  • default:: పైన ఏ కేస్ మ్యాచ్ అవ్వకపోతే ఎగ్జిక్యూట్ అయ్యే బ్యాకప్ బ్లాక్ (else లాంటిది).
💻 Example 1: Day of Week with switch
C++17 ▶ Run in Compiler 
#include <iostream>

int main() {
    int dayNumber = 3;

    switch (dayNumber) {
        case 1: std::cout << "Monday - Work Starts! 💻\n"; break;
        case 2: std::cout << "Tuesday - Deep Work ⚙️\n"; break;
        case 3: std::cout << "Wednesday - Midweek Sync 🚀\n"; break;
        case 4: std::cout << "Thursday - Code Review 🔍\n"; break;
        case 5: std::cout << "Friday - Release & Deploy 🎉\n"; break;
        case 6: 
        case 7: std::cout << "Weekend! Rest & Learn 🌟\n"; break;
        default: std::cout << "Invalid Day Number (Enter 1 to 7)\n"; break;
    }

    return 0;
}
3The Fall-through Mechanism & Modern `[[fallthrough]]`

ఒక case చివర break; పెట్టడం మర్చిపోతే ఏమవుతుంది? కంపైలర్ అక్కడితో ఆగదు! తర్వాతి case కండిషన్ మ్యాచ్ అవ్వకపోయినా సరే, ఆ కింది కోడ్‌ను కూడా ఎగ్జిక్యూట్ చేసుకుంటూ వెళ్లిపోతుంది! దీనినే Fall-through అంటారు.

🛡️ Modern C++17 `[[fallthrough]]` Attribute

కొన్నిసార్లు మనం ఉద్దేశపూర్వకంగానే ఒక కేస్ నుండి మరొక కేస్‌కి జారిపోవాలని కోరుకుంటాం. పాత C++ లో ఇలా చేస్తే కంపైలర్ "Warning: this statement may fall through" అని హెచ్చరిక ఇచ్చేది.

C++17 లో `[[fallthrough]];` అని రాస్తే, కంపైలర్‌కు "నేను కావాలనే బ్రేక్ లేకుండా కిందికి వెళ్తున్నాను, వార్నింగ్ ఇవ్వకు" అని స్పష్టంగా చెప్పవచ్చు.

💻 Example 2: Intentional Fall-through with C++17 Attribute
C++17 [[fallthrough]] ▶ Run in Compiler 
#include <iostream>

int main() {
    int userTier = 1; // 1 = Admin, 2 = Moderator, 3 = Normal User

    std::cout << "--- User Granted Permissions ---\n";
    switch (userTier) {
        case 1:
            std::cout << "[+] Full System Root Access\n";
            [[fallthrough]]; // C++17: కావాలనే కింది పర్మిషన్లు కూడా ఇస్తున్నాం!
        case 2:
            std::cout << "[+] Moderate Content & Ban Users\n";
            [[fallthrough]];
        case 3:
            std::cout << "[+] Read & Write Comments\n";
            break;
        default:
            std::cout << "[-] Guest: Read-only Access\n";
            break;
    }

    return 0;
}
4Scoped Variables in Case Blocks (బగ్ నివారణ)

C++ లో ఒక కేస్ లోపల వేరియబుల్‌ను డిక్లేర్ చేస్తే కంపైలర్ ఎర్రర్ ఇస్తుంది: 

case 1:
    int discount = 50; // ❌ ERROR: jump to case label crosses initialization
    break;

ఎందుకంటే స్విచ్ స్టేట్‌మెంట్‌లో కంపైలర్ ఏ కేస్‌కైనా డైరెక్ట్‌గా జంప్ అవ్వవచ్చు. అలా జంప్ అయినప్పుడు ఆ వేరియబుల్ ఇనిషియలైజేషన్ స్కిప్ అయిపోయి మెమరీ కరప్ట్ అవుతుంది.

✅ సరైన పరిష్కారం: కేస్ లోపల వేరియబుల్ కావాలంటే, కచ్చితంగా కర్లీ బ్రేసెస్ { ... } పెట్టి ప్రత్యేక పరిధి (Local Scope) సృష్టించాలి:

💻 Example 3: Scoped Variable in switch-case
C++17 Scoped Case ▶ Run in Compiler 
#include <iostream>

int main() {
    int planType = 2;

    switch (planType) {
        case 1: { // ✅ కర్లీ బ్రేసెస్‌తో పరిధి సెట్ చేసాం
            int basePrice = 499;
            std::cout << "Basic Plan Selected: Rs. " << basePrice << "\n";
            break;
        }
        case 2: {
            int premiumPrice = 999;
            int freeBonusCredits = 100;
            std::cout << "Premium Plan: Rs. " << premiumPrice 
                      << " (Bonus Credits: " << freeBonusCredits << ")\n";
            break;
        }
        default:
            std::cout << "Standard Free Tier\n";
            break;
    }

    return 0;
}
⚠️ Common Developer Pitfalls in Chapter 6
  • case పక్కన డూప్లికేట్ విలువలు రాయడం: ఒకే స్విచ్‌లో case 1: అని రెండుసార్లు రాస్తే కంపైలర్ error: duplicate case value అని ప్రోగ్రామ్‌ను తిరస్కరిస్తుంది.
  • ఫ్లోటింగ్ పాయింట్ విలువలు వాడటం: switch (3.14) లేదా case 2.5: అని రాయడం C++ లో చట్టవిరుద్ధం (Illegal). డెసిమల్స్ కోసం if-else వాడాలి.
💻 Hands-on Interactive Practice Challenge

టాస్క్: ఒక స్మార్ట్ కాఫీ వెండింగ్ మెషిన్ కంట్రోలర్ రాయండి. కస్టమర్ ఎంపిక (char: 'E'=Espresso, 'C'=Cappuccino, 'L'=Latte, 'M'=Mocha) ఆధారంగా ధర లెక్కించి, తగిన కప్పు సైజు వివరాలను switch ద్వారా ప్రింట్ చేయండి:

C++17 Coffee Machine Challenge ▶ Run in Compiler 
#include <iostream>

int main() {
    char beverageChoice = 'C'; // Cappuccino
    double beveragePrice = 0.0;
    std::string beverageName = "";

    switch (beverageChoice) {
        case 'E':
        case 'e':
            beverageName = "Double Shot Espresso";
            beveragePrice = 120.00;
            break;
        case 'C':
        case 'c':
            beverageName = "Creamy Cappuccino";
            beveragePrice = 180.00;
            break;
        case 'L':
        case 'l':
            beverageName = "Classic Cafe Latte";
            beveragePrice = 160.00;
            break;
        case 'M':
        case 'm':
            beverageName = "Dark Chocolate Mocha";
            beveragePrice = 210.00;
            break;
        default:
            std::cout << "[-] Error: Selected beverage not available in machine.\n";
            return 1;
    }

    std::cout << "========================================\n";
    std::cout << "       SMART COFFEE DISPENSER ☕        \n";
    std::cout << "========================================\n";
    std::cout << "Selected Beverage : " << beverageName << "\n";
    std::cout << "Dispense Price    : Rs. " << beveragePrice << "\n";
    std::cout << "Brewing Status    : READY TO DISPENSE ✅\n";
    std::cout << "========================================\n";

    return 0;
}

❓ Frequently Asked Questions (FAQ)

Q switch లో break మర్చిపోతే ఏమవుతుంది? (Fall-through అంటే ఏమిటి?)

case చివర break; రాయకపోతే, ఆ తర్వాతి case కండిషన్ మ్యాచ్ అవ్వకపోయినా, అందులో ఉన్న కోడ్ కూడా వరుసగా ఎగ్జిక్యూట్ అయిపోతుంది. దీనిని Fall-through అంటారు. ఉద్దేశపూర్వకంగా ఇది చేయాలనుకుంటే C++17 లో [[fallthrough]]; అని రాయాలి.

Q C++ switch లో float లేదా string విలువలను ఎందుకు వాడలేము?

C++ కంపైలర్ switch స్టేట్‌మెంట్‌ను ఆప్టిమైజ్ చేయడానికి మెమరీలో Jump Table అనే బైనరీ అడ్రస్ టేబుల్‌ను నిర్మిస్తుంది. Jump Table కేవలం పూర్ణాంకాలు (Integral Types: int, char, enum) పై మాత్రమే పనిచేస్తుంది. ఫ్లోటింగ్ పాయింట్ లేదా స్ట్రింగ్స్ కోసం if-else వాడాలి.

Q case లోపల కొత్త వేరియబుల్ డిక్లేర్ చేస్తే ఎర్రర్ ఎందుకు వస్తుంది?

ఒక case లో int x = 10; అని రాస్తే, కంపైలర్ ఆ వేరియబుల్ ఇనిషియలైజేషన్‌ను దాటి మరో case కి జంప్ చేయలేక ఎర్రర్ ఇస్తుంది. దీనిని నివారించడానికి ఆ case కు కర్లీ బ్రేసెస్ { int x = 10; ... } పెట్టి ప్రత్యేక పరిధి (Local Scope) ఇవ్వాలి.
