క్లాసెస్, ఆబ్జెక్ట్స్ & Encapsulation (తెలుగులో)

C++ లో సాఫ్ట్‌వేర్ ఆర్కిటెక్చర్‌ను ఎలా డిజైన్ చేస్తారు? Procedural వర్సెస్ Object-Oriented Programming, Class బ్లూప్రింట్ మరియు Object ఇన్స్టాన్సియేషన్, Access Specifiers (public, private, protected), Data Hiding మరియు ఎన్‌క్యాప్సులేషన్, Empty Class సైజ్ రహస్యం, మరియు this Pointer పూర్తి పనితీరు.

1 Procedural vs Object-Oriented Programming (OOP)

సాంప్రదాయ C ప్రోగ్రామింగ్‌లో (Procedural Programming) డేటా మరియు ఫంక్షన్లు విడివిడిగా ఉంటాయి. వేరియబుల్స్ ఒకచోట ఉంటాయి, వాటిని ప్రాసెస్ చేసే ఫంక్షన్లు ఇంకొక చోట ఉంటాయి. ప్రాజెక్ట్ పరిమాణం పెరిగేకొద్దీ ఎవరైనా పొరపాటున డేటాను కరప్ట్ చేసే ప్రమాదం ఉంటుంది.

దీనికి పరిష్కారంగా వచ్చినదే Object-Oriented Programming (OOP). నిజ జీవితంలో ఒక వస్తువుకు లక్షణాలు (Attributes/State) మరియు పనులు (Behaviors/Methods) రెండూ కలిసి ఉంటాయి. ఉదాహరణకు ఒక Car కు రంగు, మోడల్ (డేటా) ఉంటాయి; అలాగే start(), accelerate(), brake() (ఫంక్షన్లు) ఉంటాయి. డేటాను మరియు ఫంక్షన్లను ఒకే రక్షణాత్మక క్యాప్సూల్ లోపల కలిపి ఉంచే పద్ధతినే OOP అంటారు.

2 Class అంటే ఏమిటి? Object అంటే ఏమిటి?

చాలామంది క్లాస్‌కు ఆబ్జెక్ట్‌కు మధ్య తేడాను అర్థం చేసుకోవడంలో తడబడతారు:

[బ్లూప్రింట్ vs రియల్ ఇన్‌స్టాన్స్ అనలాజీ] 1. Class (బ్లూప్రింట్ / ప్లాన్): ఒక ఇంజనీర్ కాగితం మీద గీసిన ఇంటి ప్లాన్ లాంటిది. • ప్లాన్ కాగితం మీద మాత్రమే ఉంటుంది; భూమి మీద ఏ స్థలాన్నీ ఆక్రమించదు! • కంపైలర్ క్లాస్ డిక్లరేషన్‌ను చూసినప్పుడు రామ్ (RAM) లో ఏ మెమరీనీ కేటాయించదు. 2. Object (నిజమైన ఇల్లు): ఆ ప్లాన్ ఆధారంగా భౌతికంగా నిర్మించిన అసలైన భవనం. • రామ్ (RAM) లో స్థలాన్ని ఆక్రమిస్తుంది. • ఒకే క్లాస్ (ప్లాన్) నుండి మనం ఎన్ని ఆబ్జెక్టులైనా (ఇళ్ళు) సృష్టించవచ్చు!
🔥 ఇంటర్వ్యూ గోల్డెన్ క్వశ్చన్: Empty Class సైజ్ ఎంత?
ఒక క్లాస్‌లో ఏ వేరియబుల్స్ లేకపోతే: class Empty {};
దాని సైజ్ sizeof(Empty) ఎంత ఉంటుంది? చాలామంది 0 బైట్లు అనుకుంటారు! కానీ C++ లో దీని సైజ్ ఖచ్చితంగా 1 Byte ఉంటుంది.
ఎందుకంటే C++ నియమం ప్రకారం: "ప్రతి ప్రత్యేకమైన ఆబ్జెక్ట్‌కు మెమరీలో ఒక విశిష్టమైన అడ్రస్ (&obj) ఉండాలి." ఒకవేళ సైజ్ 0 అయితే, పక్కపక్కనే సృష్టించిన రెండు వేర్వేరు ఆబ్జెక్టులకు ఒకే మెమరీ అడ్రస్ వచ్చే ప్రమాదం ఉంటుంది! అందుకని కంపైలర్ డమ్మీగా 1 బైట్ స్పేస్ కేటాయిస్తుంది.
3 Access Specifiers: private, public & protected

క్లాస్ లోపల ఉండే డేటాను ఎవరెవరు యాక్సెస్ చేయవచ్చో నిర్ణయించే సెక్యూరిటీ గేట్లే Access Specifiers:

Access Specifier యాక్సెస్ పరిధి (Visibility Scope) ఎందుకు వాడాలి?
private (డిఫాల్ట్) కేవలం ఆ క్లాస్ లోపలి ఫంక్షన్లకు మాత్రమే కనిపిస్తుంది. బయటి నుండి డైరెక్ట్ యాక్సెస్ ఉండదు. డేటా భద్రత కోసం (Data Hiding). బ్యాంక్ బ్యాలెన్స్, పాస్‌వర్డ్‌లు లాంటి కీలక వేరియబుల్స్‌కు వాడతారు.
public ప్రోగ్రామ్‌లో ఎక్కడి నుంచైనా నేరుగా యాక్సెస్ చేయవచ్చు. యూజర్‌కు అందుబాటులో ఉంచాల్సిన పబ్లిక్ ఇంటర్‌ఫేస్ మెథడ్స్ (Getters, Setters, Actions) కోసం.
protected ఆ క్లాస్ లోపల మరియు దాని నుండి పుట్టిన చైల్డ్ క్లాసులలో (Inheritance) మాత్రమే కనిపిస్తుంది. వారసత్వ సంబంధాలు ఉన్నప్పుడు పేరెంట్ డేటాను పిల్లలకు అందించడానికి.
💡 C++ లో Class కి Struct కి అసలైన తేడా ఏమిటి?
చాలామంది C లాంగ్వేజ్ అలవాటుతో Struct లో కేవలం డేటా మాత్రమే ఉంటుందేమో అనుకుంటారు. కానీ C++ లో struct లో కూడా ఫంక్షన్లు, కన్‌స్ట్రక్టర్లు అన్నీ రాయవచ్చు! రెండింటి మధ్య తేడా కేవలం ఒక్కటే:
• class లోపల మెంబర్లు డిఫాల్ట్‌గా private.
• struct లోపల మెంబర్లు డిఫాల్ట్‌గా public.
4 ఎన్‌క్యాప్సులేషన్ (Encapsulation) & Data Hiding సూత్రం

డేటాను పబ్లిక్‌గా వదిలేస్తే ఎవరైనా తప్పుడు విలువలను అసైన్ చేయవచ్చు. ఉదాహరణకు bankAccount.balance = -50000; అని నేరుగా రాస్తే బ్యాంక్ దివాలా తీస్తుంది!

అందుకే వేరియబుల్స్‌ను private లో దాచి (Data Hiding), వాటిని చదవడానికి Getters మరియు వాటిని మార్చడానికి ఖచ్చితమైన వాలిడేషన్ లాజిక్ ఉన్న Setters ను పబ్లిక్‌గా అందించే డిజైన్ పద్ధతినే Encapsulation అంటారు.

💻 Code Example 1: Robust Encapsulation with Getters, Setters & Validation
bank_account_oop.cpp
⚡ Try in Compiler 
#include <iostream>
#include <string>

class BankAccount {
private:
    // ప్రైవేట్ డేటా మెంబర్లు - బయటి నుండి డైరెక్ట్ గా మార్చలేరు!
    std::string accountHolder;
    double balance;

public:
    // Setter ఫంక్షన్ - కచ్చితమైన వాలిడేషన్ తర్వాతే డేటాను అంగీకరిస్తుంది
    void setAccountDetails(const std::string& name, double initialDeposit) {
        accountHolder = name;
        if (initialDeposit >= 0.0) {
            balance = initialDeposit;
        } else {
            balance = 0.0;
            std::cout << "Warning: Initial deposit cannot be negative! Set to 0.0\n";
        }
    }

    // డిపాజిట్ మెథడ్
    void deposit(double amount) {
        if (amount > 0) {
            balance += amount;
            std::cout << "Deposited: $" << amount << "\n";
        }
    }

    // విత్ డ్రా మెథడ్ (బ్యాలెన్స్ చెక్ రక్షణ)
    void withdraw(double amount) {
        if (amount > balance) {
            std::cout << "Error: Insufficient Funds! Withdrawal Denied.\n";
        } else if (amount > 0) {
            balance -= amount;
            std::cout << "Withdrawn: $" << amount << "\n";
        }
    }

    // Getter ఫంక్షన్ (Read-Only access - const method)
    double getBalance() const {
        return balance;
    }

    std::string getHolder() const {
        return accountHolder;
    }
};

int main() {
    BankAccount myAccount; // ఆబ్జెక్ట్ ఇన్స్టాన్సియేషన్
    myAccount.setAccountDetails("Balaji Rao", 1000.0);

    // myAccount.balance = 50000; // ❌ ERROR! balance is private

    std::cout << "Account Holder : " << myAccount.getHolder() << "\n";
    std::cout << "Initial Balance: $" << myAccount.getBalance() << "\n\n";

    myAccount.deposit(500.0);
    myAccount.withdraw(2000.0); // తిరస్కరించబడుతుంది!
    myAccount.withdraw(300.0);  // విజయవంతం అవుతుంది

    std::cout << "\nFinal Balance  : $" << myAccount.getBalance() << "\n";
    return 0;
}

5 this Pointer అంటే ఏమిటి? Method Chaining మ్యాజిక్

మనం ఒక క్లాస్ నుండి 10 వేర్వేరు ఆబ్జెక్టులను సృష్టించినప్పుడు, ప్రతి ఆబ్జెక్ట్‌కు దాని స్వంత వేరియబుల్స్ ఉంటాయి. కానీ క్లాస్ ఫంక్షన్లు మాత్రం మెమరీలో ఒకే కాపీ ఉంటాయి.

అయితే ఒక ఫంక్షన్ రన్ అవుతున్నప్పుడు, అది ఏ ఆబ్జెక్ట్ యొక్క డేటాపై పనిచేయాలో ఎలా తెలుసుకుంటుంది? ఇక్కడే కంపైలర్ రహస్యంగా this పాయింటర్ ను ప్రతి నాన్-స్టాటిక్ మెంబర్ ఫంక్షన్‌కు మొదటి పారామీటర్‌గా పాస్ చేస్తుంది:

[Compiler Transformation: 'this' under the hood] మనం రాసే కోడ్: obj1.deposit(100); కంపైలర్ అంతర్గతంగా మార్చే విధానం: BankAccount::deposit(&obj1, 100); ▲ └─── 'this' పాయింటర్ గా obj1 అడ్రస్ వెళ్తుంది!

this పాయింటర్ వల్ల రెండు అద్భుతమైన ప్రయోజనాలు ఉన్నాయి:

  1. Name Conflict Resolution: ఫంక్షన్ పారామీటర్ పేరు మరియు క్లాస్ వేరియబుల్ పేరు ఒకటే అయినప్పుడు: this->name = name; అని స్పష్టంగా వేరు చేయవచ్చు.
  2. Method Chaining (Fluent Interface): ఫంక్షన్ నుండి return *this; అని రిటర్న్ చేస్తే, ఒకే లైన్‌లో వరుసగా మెథడ్లను కాల్ చేయవచ్చు: builder.setName().setAge().build();!
💻 Code Example 2: 'this' Pointer & Method Chaining in Action
this_pointer_chaining.cpp
⚡ Try in Compiler 
#include <iostream>

class Calculator {
private:
    double result = 0.0;

public:
    // return *this ద్వారా ప్రస్తుత ఆబ్జెక్ట్ రిఫరెన్స్ రిటర్న్ అవుతుంది
    Calculator& add(double val) {
        this->result += val; // 'this' పాయింటర్ ద్వారా ప్రస్తుత ఆబ్జెక్ట్ డేటా యాక్సెస్
        return *this;
    }

    Calculator& multiply(double val) {
        this->result *= val;
        return *this;
    }

    Calculator& subtract(double val) {
        this->result -= val;
        return *this;
    }

    void show() const {
        std::cout << "Current Result: " << this->result << "\n";
    }
};

class EmptyClass {};

int main() {
    std::cout << "=== 1. Method Chaining using 'this' pointer ===\n";
    Calculator calc;

    // ఒకే లైన్ లో వరుసగా ఆపరేషన్స్ (Fluent Interface)
    calc.add(10).multiply(5).subtract(8).show(); // (0 + 10) * 5 - 8 = 42

    std::cout << "\n=== 2. Memory Sizes of Objects ===\n";
    std::cout << "sizeof(Calculator) : " << sizeof(calc) << " bytes\n";
    std::cout << "sizeof(EmptyClass) : " << sizeof(EmptyClass) << " byte (Guaranteed Unique Address)\n";

    return 0;
}

Q C++ లో ఖాళీ క్లాస్ (Empty Class) సైజ్ ఎంత ఉంటుంది? sizeof(Empty) ఎందుకు 0 కాదు?

C++ లో ఏ ఎలిమెంట్లు లేని ఖాళీ క్లాస్ సైజ్ ఖచ్చితంగా 1 బైట్ (1 Byte) ఉంటుంది. ఎందుకంటే C++ ఆర్కిటెక్చర్‌లో ప్రతి ఆబ్జెక్ట్‌కు రామ్‌లో ఒక ప్రత్యేకమైన మెమరీ అడ్రస్ (&obj) ఉండాలి. ఒకవేళ సైజ్ 0 అయితే, రెండు వేర్వేరు ఆబ్జెక్టులకు ఒకే మెమరీ అడ్రస్ వచ్చే ప్రమాదం ఉంటుంది; కాబట్టి కంపైలర్ కనీస గుర్తింపు కోసం 1 బైట్ స్థలాన్ని కేటాయిస్తుంది.

Q C++ లో 'class' కి మరియు 'struct' కి అసలైన తేడా ఏమిటి?

C++ లో class మరియు struct రెండూ దాదాపు ఒకేలా పనిచేస్తాయి (రెండింటిలోనూ డేటా మరియు ఫంక్షన్స్ ఉంటాయి). తేడా కేవలం 'Default Access Specifier' మాత్రమే: class లో మెంబర్లు డిఫాల్ట్‌గా private గా ఉంటాయి; struct లో మెంబర్లు డిఫాల్ట్‌గా public గా ఉంటాయి.

Q C++ మెంబర్ ఫంక్షన్లలో 'this' పాయింటర్ పాత్ర ఏమిటి?

this అనేది ప్రస్తుతం ఆ ఫంక్షన్‌ను పిలిచిన ఆబ్జెక్ట్ యొక్క మెమరీ అడ్రస్‌ను సూచించే ఒక హిడెన్ కాన్‌స్టంట్ పాయింటర్ (ClassName* const this). పారామీటర్ల పేర్లు మరియు క్లాస్ వేరియబుల్స్ పేర్లు ఒకేలా ఉన్నప్పుడు గందరగోళం రాకుండా this->var ద్వారా వేరు చేయడానికి, మరియు మెథడ్ చైనింగ్ (Method Chaining: return *this;) సాధించడానికి ఇది ఉపయోగపడుతుంది.
