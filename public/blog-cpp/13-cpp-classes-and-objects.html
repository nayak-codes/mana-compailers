క్లాసెస్, ఆబ్జెక్ట్స్ & Encapsulation (తెలుగులో)

C++ లో సాఫ్ట్‌వేర్ ఆర్కిటెక్చర్‌ను ఎలా డిజైన్ చేస్తారు? Procedural వర్సెస్ Object-Oriented Programming, Class బ్లూప్రింట్ మరియు Object ఇన్స్టాన్సియేషన్, Access Specifiers (public, private, protected), Data Hiding మరియు ఎన్‌క్యాప్సులేషన్, Empty Class సైజ్ రహస్యం, మరియు this Pointer పూర్తి పనితీరు.

📌 Covered in this chapter: Procedural vs OOP · Class Blueprint vs Object in RAM · Empty Class 1-Byte Rule · Access Specifiers · Getters & Setters · 'this' Pointer · Method Chaining
1 Procedural vs Object-Oriented Programming (OOP)

సాంప్రదాయ C లాంగ్వేజ్‌లో (Procedural Programming) డేటా మరియు ఆ డేటాపై పనిచేసే ఫంక్షన్లు వేర్వేరు ప్రదేశాలలో ఉంటాయి. వేరియబుల్స్ ఒకచోట గ్లోబల్ గా పడి ఉంటాయి, వాటిని మార్చే ఫంక్షన్లు ఇంకొక చోట ఉంటాయి. ప్రాజెక్ట్ పరిమాణం పెరిగేకొద్దీ వేల లైన్ల కోడ్‌లో ఎవరు ఏ వేరియబుల్‌ను మార్చారో కనిపెట్టడం అసాధ్యంగా మారి సాఫ్ట్‌వేర్ బగ్స్‌తో నిండిపోతుంది.

దీనికి శాశ్వత పరిష్కారంగా వచ్చినదే Object-Oriented Programming (OOP). నిజ జీవితంలో ఏ వస్తువూ కేవలం డేటా మాత్రమే లేదా కేవలం ఫంక్షన్ మాత్రమే అయి ఉండదు. ఒక కారు (Car) ను తీసుకుంటే: రంగు, ఇంధనం, స్పీడ్ (Attributes/Data) ఉంటాయి; అలాగే start(), accelerate(), brake() (Methods/Actions) ఉంటాయి. ఈ డేటాను మరియు ఫంక్షన్లను ఒకే రక్షణాత్మక యూనిట్ (Capsule) లోపల కలిపి ఉంచే అత్యున్నత సాఫ్ట్‌వేర్ విధానమే OOP.

⚙️ Procedural Programming (C Style)

• ఫంక్షన్లు మరియు డేటా వేర్వేరు.
• గ్లోబల్ డేటాను ఎవరైనా సులభంగా కరప్ట్ చేయవచ్చు.
• భారీ ప్రాజెక్టులలో నిర్వహణ (Maintenance) అత్యంత కష్టం.

🏗️ Object-Oriented OOP (C++ Style)

• డేటా మరియు ఫంక్షన్లు ఒకే క్లాస్ లోపల బంధించబడి ఉంటాయి.
• ప్రైవేట్ డేటాను బయటి ప్రపంచం నుండి రక్షించవచ్చు (Data Hiding).
• కోడ్ పునర్వినియోగం (Reusability), భద్రత, స్కేలబిలిటీ అత్యున్నతం.

2 Class (బ్లూప్రింట్) vs Object (నిజమైన ఇన్‌స్టాన్స్)

చాలామంది క్లాస్ అంటే ఏమిటి, ఆబ్జెక్ట్ అంటే ఏమిటి అనే ప్రాథమిక తేడాను అర్థం చేసుకోవడంలో తికమక పడతారు. ఈ సులభమైన రియల్-వరల్డ్ అనలాజీని గుర్తుంచుకోండి:

🏠 ఆర్కిటెక్ట్ ప్లాన్ vs అసలైన భవనం:

  • Class (బ్లూప్రింట్ / ప్లాన్): ఒక ఇంజనీర్ కాగితం మీద గీసిన ఇంటి ప్లాన్ లాంటిది. ప్లాన్ కాగితం పైనే ఉంటుంది కానీ భూమి మీద ఏ స్థలాన్నీ ఆక్రమించదు. అలాగే C++ లో క్లాస్ డిక్లరేషన్ చూసినప్పుడు కంపైలర్ ర్యామ్ (RAM) లో ఏ మెమరీనీ కేటాయించదు!
  • Object (అసలైన ఇల్లు): ఆ ప్లాన్ ఆధారంగా భౌతికంగా నిర్మించిన అసలైన ఇల్లు. ఇది రామ్‌లో ఖచ్చితంగా బైట్ల స్థలాన్ని ఆక్రమిస్తుంది. ఒకే ప్లాన్ (Class) ఉపయోగించి వేలాది ఇళ్ళు (Objects) నిర్మించవచ్చు!
🔥 ఇంటర్వ్యూ గోల్డెన్ క్వశ్చన్: Empty Class సైజ్ ఎంత?
ఒక క్లాస్‌లో ఏ వేరియబుల్స్ లేకపోతే: class EmptyClass {};
దాని సైజ్ sizeof(EmptyClass) ఎంత ఉంటుంది? చాలామంది 0 బైట్లు అనుకుంటారు!
కానీ C++ లో దీని సైజ్ ఖచ్చితంగా 1 Byte ఉంటుంది. ఎందుకంటే C++ నియమం ప్రకారం: "ప్రతి ప్రత్యేకమైన ఆబ్జెక్ట్‌కు మెమరీలో ఒక విశిష్టమైన చిరునామా (&obj) ఉండాలి." ఒకవేళ సైజ్ 0 అయితే, పక్కపక్కనే సృష్టించిన రెండు వేర్వేరు ఆబ్జెక్టులకు ఒకే మెమరీ అడ్రస్ వచ్చే ప్రమాదం ఉంటుంది. అందుకే కంపైలర్ కనీస గుర్తింపు కోసం 1 బైట్ స్పేస్ కేటాయిస్తుంది.
3 Access Specifiers (private, public, protected)

క్లాస్ లోపల ఉండే డేటాను ఎవరెవరు యాక్సెస్ చేయవచ్చో నిర్ణయించే సెక్యూరిటీ గేట్లే Access Specifiers:

Access Specifier యాక్సెస్ పరిధి (Visibility Scope) ఎందుకు వాడాలి?
private (డిఫాల్ట్) కేవలం ఆ క్లాస్ లోపలి ఫంక్షన్లకు మాత్రమే కనిపిస్తుంది. బయటి నుండి డైరెక్ట్ యాక్సెస్ ఉండదు. డేటా భద్రత కోసం (Data Hiding). బ్యాంక్ బ్యాలెన్స్, పాస్‌వర్డ్‌లు లాంటి కీలక వేరియబుల్స్‌కు వాడతారు.
public ప్రోగ్రామ్‌లో ఎక్కడి నుంచైనా నేరుగా యాక్సెస్ చేయవచ్చు. యూజర్‌కు అందుబాటులో ఉంచాల్సిన పబ్లిక్ ఇంటర్‌ఫేస్ మెథడ్స్ (Getters, Setters, Actions) కోసం.
protected ఆ క్లాస్ లోపల మరియు దాని నుండి పుట్టిన చైల్డ్ క్లాసులలో (Inheritance) మాత్రమే కనిపిస్తుంది. వారసత్వ సంబంధాలు ఉన్నప్పుడు పేరెంట్ డేటాను పిల్లలకు అందించడానికి.
💡 C++ లో Class కి Struct కి అసలైన తేడా ఏమిటి?
చాలామంది Struct లో కేవలం డేటా మాత్రమే ఉంటుందేమో అనుకుంటారు. కానీ C++ లో struct లో కూడా ఫంక్షన్లు, కన్‌స్ట్రక్టర్లు అన్నీ రాయవచ్చు! రెండింటి మధ్య తేడా కేవలం ఒక్కటే: class లో మెంబర్లు డిఫాల్ట్‌గా private, కానీ struct లో మెంబర్లు డిఫాల్ట్‌గా public.
4 ఎన్‌క్యాప్సులేషన్ (Encapsulation) & Data Hiding సూత్రం

ఒకవేళ మనం వేరియబుల్స్‌ను పబ్లిక్‌గా వదిలేస్తే, ప్రోగ్రామ్‌లో ఎవరైనా వాటిని నేరుగా మార్చేయవచ్చు (ఉదాహరణకు account.balance = -50000;). ఒక బ్యాంక్ అకౌంట్ బ్యాలెన్స్ రుణాత్మకం కాకుండా అడ్డుకోవాలంటే, డేటాను private లో దాచాలి (Data Hiding).

ఆ డేటాను చదవడానికి Getters మరియు మార్చడానికి కచ్చితమైన వాలిడేషన్ లాజిక్ ఉన్న Setters ను పబ్లిక్‌గా అందించే పద్ధతినే Encapsulation అంటారు:

💻 Example 1: Encapsulation with Getters & Setters
bank_account_compact.cpp
⚡ Try in Compiler 
#include <iostream>
#include <string>

class BankAccount {
private:
    double balance = 0.0; // ప్రైవేట్ డేటా (Data Hiding)

public:
    // Setter with Validation
    void deposit(double amount) {
        if (amount > 0) {
            balance += amount;
            std::cout << "Deposited: $" << amount << "\n";
        }
    }

    // Read-only Getter (const method)
    double getBalance() const {
        return balance;
    }
};

int main() {
    BankAccount myAcc;
    myAcc.deposit(500.0);
    std::cout << "Current Balance: $" << myAcc.getBalance() << "\n";
    return 0;
}
🔍 Line-by-Line కోడ్ బ్రేక్ డౌన్:
  • private: double balance: బయటి నుండి ఎవరూ డైరెక్ట్ గా myAcc.balance = -100 చేయలేరు. కంపైలర్ అడ్డుకుంటుంది.
  • deposit(double amount): అమౌంట్ పాజిటివ్ గా ఉన్నప్పుడు మాత్రమే బ్యాలెన్స్ పెరుగుతుంది. సెక్యూరిటీ వాలిడేషన్ ఇక్కడే జరుగుతుంది.
  • getBalance() const: ఈ ఫంక్షన్ కేవలం బ్యాలెన్స్ ను చదవడానికి మాత్రమే. const ఉండటం వల్ల ఇది డేటాను ప్రమాదవశాత్తూ కూడా మార్చలేదు.
5 this Pointer అంటే ఏమిటి? Method Chaining మ్యాజిక్

మనం ఒక క్లాస్ నుండి ఎన్ని ఆబ్జెక్టులను సృష్టించినా, రామ్‌లో ఫంక్షన్ల కోడ్ మాత్రం ఒకే ఒక్క కాపీ ఉంటుంది. ఒక మెంబర్ ఫంక్షన్ కాల్ అయినప్పుడు అది ఏ ఆబ్జెక్ట్ యొక్క డేటాపై పనిచేయాలో తెలియజేయడానికి కంపైలర్ రహస్యంగా ఆ ఆబ్జెక్ట్ మెమరీ అడ్రస్‌ను this పాయింటర్ ద్వారా పాస్ చేస్తుంది.

⚡ 'this' పాయింటర్ రెండు ప్రధాన ప్రయోజనాలు:

  1. పేర్ల గందరగోళం నివారణ: ఫంక్షన్ పారామీటర్ పేరు మరియు క్లాస్ వేరియబుల్ పేరు ఒకటే అయినప్పుడు this->name = name; అని వేరు చేయవచ్చు.
  2. Method Chaining (Fluent API): ఫంక్షన్ చివర return *this; అని రాస్తే, ఒకే లైన్‌లో వరుసగా మెథడ్లను పిలవవచ్చు: calc.add(10).multiply(2).show();!
💻 Example 2: Method Chaining with 'this' Pointer
this_chaining_compact.cpp
⚡ Try in Compiler 
#include <iostream>

class Calculator {
public:
    double value = 0.0;

    Calculator& add(double v) {
        this->value += v;
        return *this; // ప్రస్తుత ఆబ్జెక్ట్ రిఫరెన్స్ రిటర్న్ చేస్తుంది
    }

    Calculator& multiply(double v) {
        this->value *= v;
        return *this;
    }
};

int main() {
    Calculator c;
    c.add(10).multiply(5); // Method Chaining: (0 + 10) * 5 = 50
    std::cout << "Calculated Result: " << c.value << "\n";
    return 0;
}
🔍 Line-by-Line కోడ్ బ్రేక్ డౌన్:
  • Calculator& add(...): ఫంక్షన్ రిటర్న్ టైప్ క్లాస్ రిఫరెన్స్ (Calculator&) గా ఉంది.
  • return *this;: this అనేది ప్రస్తుత ఆబ్జెక్ట్ అడ్రస్ కాగా, *this అంటే ఆ అసలైన ఆబ్జెక్ట్. దీనివల్ల వెంటనే పక్కనే ఇంకొక మెథడ్ (.multiply(5)) కాల్ చేయడానికి అవకాశం లభిస్తుంది.

Q C++ లో ఖాళీ క్లాస్ (Empty Class) సైజ్ ఎంత ఉంటుంది? sizeof(Empty) ఎందుకు 0 కాదు?

C++ లో ఏ ఎలిమెంట్లు లేని ఖాళీ క్లాస్ సైజ్ ఖచ్చితంగా 1 బైట్ (1 Byte) ఉంటుంది. ఎందుకంటే C++ ఆర్కిటెక్చర్‌లో ప్రతి ఆబ్జెక్ట్‌కు రామ్‌లో ఒక ప్రత్యేకమైన మెమరీ అడ్రస్ (&obj) ఉండాలి. ఒకవేళ సైజ్ 0 అయితే, రెండు వేర్వేరు ఆబ్జెక్టులకు ఒకే మెమరీ అడ్రస్ వచ్చే ప్రమాదం ఉంటుంది; కాబట్టి కంపైలర్ కనీస గుర్తింపు కోసం 1 బైట్ స్థలాన్ని కేటాయిస్తుంది.

Q C++ లో 'class' కి మరియు 'struct' కి అసలైన తేడా ఏమిటి?

C++ లో class మరియు struct రెండూ దాదాపు ఒకేలా పనిచేస్తాయి (రెండింటిలోనూ డేటా మరియు ఫంక్షన్స్ ఉంటాయి). తేడా కేవలం 'Default Access Specifier' మాత్రమే: class లో మెంబర్లు డిఫాల్ట్‌గా private గా ఉంటాయి; struct లో మెంబర్లు డిఫాల్ట్‌గా public గా ఉంటాయి.

Q C++ మెంబర్ ఫంక్షన్లలో 'this' పాయింటర్ పాత్ర ఏమిటి?

this అనేది ప్రస్తుతం ఆ ఫంక్షన్‌ను పిలిచిన ఆబ్జెక్ట్ యొక్క మెమరీ అడ్రస్‌ను సూచించే ఒక హిడెన్ కాన్‌స్టంట్ పాయింటర్ (ClassName* const this). పారామీటర్ల పేర్లు మరియు క్లాస్ వేరియబుల్స్ పేర్లు ఒకేలా ఉన్నప్పుడు గందరగోళం రాకుండా this->var ద్వారా వేరు చేయడానికి, మరియు మెథడ్ చైనింగ్ (Method Chaining: return *this;) సాధించడానికి ఇది ఉపయోగపడుతుంది.
