Arrays, std::string & std::vector (తెలుగులో)

⚡ Modern C++ (C++17 / C++20 / C++23) 🟢 Lesson 7 📂 Phase 07: Arrays, Strings & Vectors 📅 2026 Master Edition
📌 Covered in this in-depth guide: Raw Arrays vs Vector · std::vector · Dynamic Size · std::string · Memory Reallocation

ఒక స్టూడెంట్ మార్కు అయితే ఒక వేరియబుల్ సరిపోతుంది, అదే 100 మంది స్టూడెంట్స్ మార్కులు స్టోర్ చేయాలంటే 100 వేరియబుల్స్ రాయలేము కదా! అందుకే ప్రోగ్రామింగ్ లో Arrays (అర్రేస్) వచ్చాయి. కానీ మామూలు అర్రేస్ లో ఉన్న అతి పెద్ద ప్రాబ్లెమ్ ఏంటంటే, ఒకసారి సైజు ఫిక్స్ చేసాక (ఉదాహరణకు 100), రేపు కొత్త స్టూడెంట్ వస్తే (101 వ వాడు) వాడికి అందులో ప్లేస్ ఉండదు. దీనికి C++ ఇచ్చిన అల్టిమేట్ సొల్యూషన్ std::vector. అలాగే అక్షరాలతో ఆడుకోవడానికి పాత C లాంటి క్యారెక్టర్ అర్రేస్ కాకుండా, సూపర్ పవర్ ఫుల్ అయిన std::string ని C++ లో ఎలా వాడాలో ఈ డీప్ గైడ్ లో చూద్దాం.

1 Raw Arrays కి మరియు std::vector కి ఉన్న తేడా?

పాత కాలం అర్రేస్ (Raw Arrays) లో మనం ముందే కంపైలర్ కి సైజు చెప్పాలి. ఒకవేళ మీరు ఆ సైజు దాటి డేటా పెడితే ప్రోగ్రామ్ క్రాష్ అయిపోయి Segmentation Fault వస్తుంది. కానీ Vector (వెక్టార్) అనేది చాలా మ్యాజికల్ బాక్స్. మీరు అందులో వస్తువులు వేస్తున్న కొద్దీ దానంతట అదే దాని సైజుని డబుల్ (Double) చేసుకుంటూ పోతుంది.

📦 రియల్ లైఫ్ స్టోరీ: ఐరన్ బాక్స్ vs రబ్బర్ బ్యాగ్

ఒక ఇనుప పెట్టె (Raw Array) తీసుకున్నారు అనుకోండి. దాని సైజు ఫిక్స్డ్. అందులో 10 ఆపిల్స్ మాత్రమే పడతాయి. మీరు 11వ ఆపిల్ ని అందులో బలవంతంగా కుక్కితే ఆపిల్ నలిగిపోతుంది లేదా బాక్స్ పగిలిపోతుంది.

కానీ std::vector అనేది ఒక స్ట్రెచబుల్ రబ్బర్ బ్యాగ్ (Stretchy Bag) లాంటిది. మీరు అందులో ఆపిల్స్ వేస్తున్న కొద్దీ అది సాగుతూ (Expand) వెళ్తుంది. ఎంత డేటా అయినా పెట్టుకోవచ్చు. ఒకవేళ బ్యాగ్ ఫుల్ అయితే, బ్యాక్ గ్రౌండ్ లో C++ దానంతట అదే ఇంకో పెద్ద బ్యాగ్ కొనుక్కొని అందులోకి షిఫ్ట్ చేస్తుంది. ప్రోగ్రామర్ కి ఎలాంటి టెన్షన్ ఉండదు!

2 C++ లో std::string పవర్

C లాంగ్వేజ్ లో స్ట్రింగ్స్ అంటే కేవలం క్యారెక్టర్స్ పక్క పక్కన ఉండటం మాత్రమే (char name[10];). రెండు పేర్లు కలపాలి అంటే strcat() లాంటివి వాడాలి, అది చాలా కష్టం. కానీ C++ లో std::string వాడితే, రెండు స్ట్రింగ్స్ ని మీరు + సింబల్ తో (ఉదా: "Hello" + "World") డైరెక్ట్ గా కలిపేయొచ్చు. ఇదొక పెద్ద రిలీఫ్!

3 ఒకే ఒక సింపుల్ కోడ్ (Vector & String Demo)

కింద కోడ్ లో ఒక std::vector తీసుకుని, దానికి మధ్యలో (Run Time లో) డేటా ఎలా పుష్ (push_back) చేస్తున్నామో గమనించండి.

C++ — std::vector & std::string ▶ Run Code 
#include <iostream>
#include <vector>
#include <string>

int main() {
    // ఒక రబ్బర్ బ్యాగ్ (Vector) ని క్రియేట్ చేసాం
    std::vector<std::string> names;
    
    // బ్యాగ్ లోకి వస్తువులు వేస్తున్నాం (push_back)
    names.push_back("Apple");
    names.push_back("Banana");
    names.push_back("Cherry");
    
    // రేంజ్ బేస్డ్ లూప్ తో బయటకి తీస్తున్నాం
    std::cout << "Fruits in Vector:" << std::endl;
    for (std::string fruit : names) {
        std::cout << "- " << fruit << std::endl;
    }
    
    // వెక్టార్ సైజు ఎంత ఉందో డైరెక్ట్ గా అడగొచ్చు!
    std::cout << "Total Fruits: " << names.size() << std::endl;
    
    return 0;
}
4 కోడ్ లో ఏం జరుగుతోంది? (Step-by-Step)
  • #include <vector>: వెక్టార్ పవర్ వాడాలంటే ఈ ఫైల్ ని పైన ఇన్‌క్లూడ్ చేయాలి.
  • std::vector<std::string> names;: ఇక్కడ కంపైలర్ కి "నాకు స్ట్రింగ్స్ ని స్టోర్ చేసుకునే ఒక ఎంప్టీ బ్యాగ్ ఇవ్వు" అని చెప్తున్నాం. మొదట్లో దీని సైజు 0 ఉంటుంది.
  • push_back("Apple"): ఈ ఫంక్షన్ కాల్ చేయగానే బ్యాగ్ సైజు దానంతట అదే పెరిగి, యాపిల్ అందులో కూర్చుంటుంది.
  • size() వాడి అందులో ఎన్ని ఉన్నాయో ఈజీగా చెక్ చేసాం. (ఇది మామూలు అర్రేస్ లో చేయలేము).
5 ఇంటర్వ్యూలలో అడిగే కామన్ ప్రశ్నలు (FAQ)

Q1: వెక్టార్ సైజు ఆటోమేటిక్ గా ఎలా పెరుగుతుంది? (Capacity vs Size)

వెక్టార్ ఫుల్ అయిన ప్రతిసారీ దాని కెపాసిటీని డబుల్ (Double) చేసుకుంటుంది. ఉదాహరణకు 4 వస్తువులు పడితే, 5వ వస్తువు వేసినప్పుడు దానంతట అదే 8 సైజు ఉన్న కొత్త మెమరీ తీసుకుని, పాత డేటాని కాపీ చేసి, పాత దాన్ని డిలీట్ చేస్తుంది. అందుకే దీన్ని డైనమిక్ అర్రే (Dynamic Array) అంటారు.

Q2: ప్రతిసారి డబుల్ అయితే మెమరీ వేస్ట్ అవ్వదా?

కాస్త వేస్ట్ అవుతుంది. మీ దగ్గర 10 లక్షల ఐటమ్స్ ఉంటే, దానికి డబుల్ అవుతుంది. దాన్ని ఆపడానికి మీరు ముందే names.reserve(100); అని చెప్తే, మెమరీ ముందే అలోకేట్ అవుతుంది, డబుల్ అయ్యే రీ-లొకేషన్ ప్రాసెస్ తగ్గిపోయి స్పీడ్ పెరుగుతుంది.

Q3: C++17 లో వచ్చిన std::string_view అంటే ఏంటి?

మనం ఒక ఫంక్షన్ కి std::string పంపిస్తే అది చాలాసార్లు ఆ స్ట్రింగ్ ని జిరాక్స్ (Copy) తీసుకుని పంపుతుంది. దానివల్ల మెమరీ టైమ్ వేస్ట్ అవుతుంది. std::string_view వాడితే, అది కేవలం అసలు స్ట్రింగ్ ని చూస్తుంది (View) మాత్రమే, కాపీ చేయదు. దీనివల్ల రీడ్-ఓన్లీ ఆపరేషన్స్ కి స్పీడ్ సూపర్ ఫాస్ట్ గా ఉంటుంది!
