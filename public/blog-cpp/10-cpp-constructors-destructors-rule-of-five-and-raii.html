Constructors, Destructors & RAII (తెలుగులో)

⚡ Modern C++ (C++17 / C++20 / C++23) 🟢 Lesson 10 📂 Phase 10: Constructors & RAII 📅 2026 Master Edition
📌 Covered in this in-depth guide: Constructors · Destructors · Resource Acquisition (RAII) · Memory Leaks Prevention

గత పాఠంలో మనం క్లాస్ (Class) తయారు చేయడం చూసాము. కానీ ఒక ఆబ్జెక్ట్ మెమరీ లో పుట్టినప్పుడు (క్రియేట్ అయినప్పుడు), దాని లోపల ఉన్న వాల్యూస్ కి మొదట్లోనే ఏదైనా డేటా ఇవ్వాలి అనుకుంటే ఎలా? ఆటోమేటిక్ గా రన్ అయ్యే స్పెషల్ ఫంక్షన్స్ మనకు కావాలి. వాటినే Constructors (కన్‌స్ట్రక్టర్స్) అంటారు. అలాగే ఆ ఆబ్జెక్ట్ పని అయిపోయి మెమరీ నుండి చనిపోయేటప్పుడు, అది వాడుకున్న రామ్ (RAM) ని, ఫైల్స్ ని తిరిగి సిస్టమ్ కి ఇచ్చేయాలి. ఆ క్లీనింగ్ పని చేసేదే Destructors (డిస్ట్రక్టర్స్). ఈ రెండు కలిపితే పుట్టే అద్భుతమైన కాన్సెప్టే "RAII". అది ఎంటో ఇప్పుడు క్లియర్ గా తెలుసుకుందాం.

1 Constructors మరియు Destructors అంటే ఏమిటి?

Constructor: ఇది క్లాస్ పేరుతోనే ఉండే ఒక స్పెషల్ ఫంక్షన్. దీనికి ఎటువంటి రిటర్న్ టైప్ (void లాంటివి) ఉండదు. ఆబ్జెక్ట్ పుట్టగానే ఇది ఎవరి పిలుపు లేకుండా ఆటోమేటిక్ గా దానంతట అదే రన్ అవుతుంది. దీన్ని సెటప్ (Setup) చేయడానికి వాడతారు.

Destructor: ఇది కూడా క్లాస్ పేరుతోనే ఉంటుంది, కానీ ముందు ఒక ~ (టిల్డ్) సింబల్ ఉంటుంది. ఆబ్జెక్ట్ మెమరీ నుండి డిలీట్ అయ్యే చివరి సెకనులో ఇది రన్ అయ్యి, చెత్త అంతా క్లీన్ చేసి పోతుంది.

🎬 రియల్ లైఫ్ స్టోరీ: థియేటర్ లో సినిమా సీటు (RAII)

మీరు థియేటర్ కి వెళ్లి ఒక సీటులో కూర్చున్నారు అనుకోండి.

Constructor (పుట్టుక): మీరు సీటులో కూర్చోగానే, ఆ సీటు మీ పేరు మీద రిజర్వ్ (Book) అయిపోయింది. వేరే వాళ్లు అందులో కూర్చోలేరు. ఆ రిజర్వేషన్ చేసేదే కన్‌స్ట్రక్టర్.

Destructor (ముగింపు): సినిమా అయిపోయిన వెంటనే, మీరు లేచి వెళ్లిపోతారు. మీరు లేవగానే ఆటోమేటిక్ గా ఆ సీటు నెక్స్ట్ వాళ్ళ కోసం ఖాళీ (Clean up/Free) అయిపోతుంది.

అంటే ఒక వస్తువు ఉన్నంతసేపే ఆ మెమరీ లాక్ అయి ఉంటుంది, దాని పని అవ్వగానే దానంతట అదే మెమరీ ని రిలీజ్ చేస్తుంది. C++ లో ఈ అద్భుతమైన ప్యాట్రన్ నే RAII (Resource Acquisition Is Initialization) అంటారు. దీనివల్ల కంప్యూటర్ లో "మెమరీ లీక్స్" (RAM ఫుల్ అయిపోయి హ్యాంగ్ అవ్వడం) జరగవు.

2 ఒకే ఒక సింపుల్ కోడ్ (Constructor & Destructor)

కింద కోడ్ లో ఫైల్ హ్యాండ్లింగ్ కి సంబంధించిన క్లాస్ ఎలా ఆటోమేటిక్ గా కనెక్ట్ అయ్యి, ఆటోమేటిక్ గా క్లోజ్ అవుతుందో చూడండి.

C++ — Constructor, Destructor (RAII) ▶ Run Code 
#include <iostream>
#include <string>

class Database {
private:
    std::string dbName;

public:
    // 1. Constructor (పుట్టినప్పుడు రన్ అవుతుంది)
    Database(std::string name) {
        dbName = name;
        std::cout << "[+] Database '" << dbName << "' is Connected!" << std::endl;
    }

    void doWork() {
        std::cout << "    -> Fetching users from " << dbName << "..." << std::endl;
    }

    // 2. Destructor (~ సింబల్ తో ఉంటుంది, చనిపోయేటప్పుడు రన్ అవుతుంది)
    ~Database() {
        std::cout << "[-] Database '" << dbName << "' is Disconnected. Memory Freed!" << std::endl;
    }
};

int main() {
    std::cout << "--- Main Started ---" << std::endl;
    
    { // ఇక్కడ ఒక చిన్న స్కోప్ (బ్రాకెట్) క్రియేట్ చేశాం
        Database db("Facebook_Users"); // ఇక్కడ Constructor రన్ అవుతుంది
        db.doWork();
    } // బ్రాకెట్ అవ్వగానే ఆబ్జెక్ట్ చనిపోతుంది, Destructor ఆటోమేటిక్ గా రన్ అవుతుంది!
    
    std::cout << "--- Main Ended ---" << std::endl;
    
    return 0;
}
3 కోడ్ లో ఏం జరుగుతోంది? (Step-by-Step)
  • మనం Database db("Facebook_Users"); అనగానే Database(...) అనే కన్‌స్ట్రక్టర్ రన్ అయ్యి, ఆ పేరుని సెట్ చేసి కనెక్షన్ అయినట్లు ప్రింట్ చేసింది.
  • ఆ తర్వాత బ్రాకెట్ } క్లోజ్ అవ్వగానే, ఆ ఆబ్జెక్ట్ యొక్క టైమ్ అయిపోయింది కాబట్టి కంపైలర్ దాన్ని మెమరీ లోనుండి లేపేస్తుంది. ఆ లేపేసే ముందే ~Database() డిస్ట్రక్టర్ ని కాల్ చేస్తుంది.
  • దీనివల్ల ప్రోగ్రామర్ ఎప్పుడూ db.close() అని మ్యాన్యువల్ గా రాయాల్సిన టెన్షన్ లేదు (ముఖ్యంగా ఎర్రర్స్ వచ్చి ప్రోగ్రామ్ క్రాష్ అయినప్పుడు కూడా డిస్ట్రక్టర్ గ్యారెంటీగా రన్ అవుతుంది). ఇదే RAII బ్యూటీ!
4 ఇంటర్వ్యూలలో అడిగే కామన్ ప్రశ్నలు (FAQ)

Q1: కన్‌స్ట్రక్టర్ ని నేను పిలవచ్చా? (ఉదా: db.Database())

లేదండి! కన్‌స్ట్రక్టర్ ని మీరు విడిగా డైరెక్ట్ గా ఎప్పుడూ కాల్ చేయలేరు. ఆబ్జెక్ట్ (వేరియబుల్) ని క్రియేట్ చేస్తున్న ఆ ఒక్క సెకనులో కంపైలర్ మాత్రమే దాన్ని కాల్ చేయగలదు. అది సెటప్ కోసం మాత్రమే వాడే వన్-టైమ్ కీ.

Q2: నా క్లాస్ లో నేను కన్‌స్ట్రక్టర్ రాయకపోతే ఏమవుతుంది? ప్రోగ్రామ్ ఎర్రర్ వస్తుందా?

ఎర్రర్ రాదు. మీరు రాయకపోతే C++ కంపైలర్ దానంతట అదే ఒక డమ్మీ (Empty / Default) కన్‌స్ట్రక్టర్ ని క్రియేట్ చేసి రన్ చేస్తుంది. దాన్ని "Compiler Generated Default Constructor" అంటారు. కానీ అందులోపల ఏ వాల్యూస్ సెట్ అవ్వవు, చెత్త (Garbage) వాల్యూస్ ఉండిపోతాయి.

Q3: Rule of Three / Rule of Five అంటే ఏంటి?

మీరు ఒక క్లాస్ లో మీ స్వంతంగా ఒక డిస్ట్రక్టర్ ని రాయాల్సి వచ్చింది అంటే... మీరు డైరెక్ట్ గా పాయింటర్స్ మరియు ర్యామ్ (Heap memory) తో ఆడుకుంటున్నారు అని అర్థం. అలాంటప్పుడు కాపీ చేసేటప్పుడు క్రాష్ అవ్వకుండా ఉండటానికి మీరు ఖచ్చితంగా Copy Constructor మరియు Copy Assignment Operator ని కూడా రాయాలి. ఈ మూడింటినీ కలిపే రూల్ ఆఫ్ త్రీ అంటారు.
