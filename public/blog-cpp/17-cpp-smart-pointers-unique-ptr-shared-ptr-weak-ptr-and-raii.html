Smart Pointers & Memory Safety (తెలుగులో)

⚡ Modern C++ (C++17 / C++20 / C++23) 🟢 Lesson 17 📂 Phase 17: Smart Pointers & Memory 📅 2026 Master Edition
📌 Covered in this in-depth guide: Memory Leaks · unique_ptr · shared_ptr · weak_ptr · Ownership semantics

పాత C++ లో మీరు new వాడి ఒక ఆబ్జెక్ట్ క్రియేట్ చేస్తే, కచ్చితంగా delete వాడి దాన్ని క్లీన్ చేయాలి. ఒకవేళ మీరు మర్చిపోయినా, లేదా ప్రోగ్రామ్ మధ్యలో ఎర్రర్ వచ్చి క్రాష్ అయినా... ఆ మెమరీ (RAM) లాక్ అయిపోయి అలానే ఉండిపోతుంది. దీన్నే Memory Leak (మెమరీ లీక్) అంటారు. ఈ లీక్స్ వల్ల సర్వర్లు కొద్దిసేపటికి హ్యాంగ్ అయిపోతాయి. దీనికి చెక్ పెట్టడానికే C++11 లో Smart Pointers (స్మార్ట్ పాయింటర్స్) అనే గొప్ప ఫీచర్ ని తెచ్చారు. ఇవి దానంతట అవే delete అవుతాయి! ఈ ఆర్టికల్ లో unique_ptr మరియు shared_ptr ఎలా పనిచేస్తాయో డీప్ గా చూద్దాం.

1 Smart Pointers అంటే ఏమిటి? (RAII మ్యాజిక్)

స్మార్ట్ పాయింటర్ అనేది మామూలు పాయింటర్ కాదు, అదొక క్లాస్. దాని లోపల మామూలు పాయింటర్ ఉంటుంది, కానీ డిస్ట్రక్టర్ (Destructor) లో delete అనే కోడ్ రాసి ఉంటుంది. కాబట్టి ఆ స్మార్ట్ పాయింటర్ స్కోప్ (బ్రాకెట్) అవ్వగానే, అది చనిపోతూ చనిపోతూ లోపల ఉన్న మెమరీని కూడా ఆటోమేటిక్ గా డిలీట్ చేస్తుంది.

🚗 రియల్ లైఫ్ స్టోరీ: ఓలా క్యాబ్ (Ola) మరియు కారు రెంటల్

Unique Pointer (ఓన్ కారు లాంటిది): మీరు ఒక కారు కొన్నారు. ఆ కారు కి మీరు మాత్రమే ఓనర్ (Owner). మీ ఫ్రెండ్ కి అడ్రస్ చెప్పొచ్చు కానీ, అతను ఓనర్ కాలేడు. ఆ కారు మీద పూర్తి హక్కులు మీకే ఉంటాయి. దీన్నే std::unique_ptr అంటారు. ఒక మెమరీ కి ఒకరే ఓనర్ ఉండాలి.

Shared Pointer (షేరింగ్ కారు): ఒక కారుని ముగ్గురు ఫ్రెండ్స్ కలిసి కొన్నారు అనుకోండి. ఆ కారు కి ముగ్గురూ ఓనర్లే. ముగ్గురు వాడుకుంటారు. కానీ ఆ ముగ్గురిలో చివరివాడు ఎప్పుడైతే ఆ కారు వదిలేస్తాడో, అప్పుడే ఆ కారు స్క్రాప్ (delete) అవుతుంది. ముందే డిలీట్ అవ్వదు. దీన్నే std::shared_ptr అంటారు (ఇది లోపల Reference Counting అనే టెక్నిక్ ని వాడుతుంది).

2 Unique vs Shared vs Weak Pointers

1. std::unique_ptr: ఇది చాలా ఫాస్ట్. దీని ఓనర్షిప్ (Ownership) ని మనం వేరే పాయింటర్ కి ట్రాన్స్‌ఫర్ (std::move) చేయగలం కానీ, కాపీ (Copy) చేయలేము.

2. std::shared_ptr: ఒకే ఆబ్జెక్ట్ ని చాలా పాయింటర్స్ పట్టుకుని ఉన్నప్పుడు ఇది వాడాలి. లోపల ఇది కౌంటర్ మెయింటైన్ చేస్తుంది. కౌంటర్ 0 అయినప్పుడు మాత్రమే ఆబ్జెక్ట్ డిలీట్ అవుతుంది.

3. std::weak_ptr: ఇద్దరు shared_ptr లు ఒకరినొకరు పాయింట్ చేసుకుంటే (Cyclic Reference) కౌంటర్ ఎప్పటికీ 0 అవ్వదు, మెమరీ లీక్ అవుతుంది. దాన్ని బ్రేక్ చేయడానికి కౌంటర్ పెంచని ఒక డమ్మీ పాయింటర్ గా weak_ptr వాడుతారు.

3 ఒకే ఒక సింపుల్ కోడ్ (Smart Pointers)

కింద కోడ్ లో new మరియు delete ఎక్కడా వాడకుండా std::make_unique మరియు std::make_shared వాడి ఆబ్జెక్ట్స్ ని సేఫ్ గా ఎలా క్రియేట్ చేసామో చూడండి.

C++11/14 — Smart Pointers Demo ▶ Run Code 
#include <iostream>
#include <memory> // స్మార్ట్ పాయింటర్స్ కోసం 

class Player {
public:
    Player() { std::cout << "Player Spawned! (Memory Allocated)" << std::endl; }
    ~Player() { std::cout << "Player Dead! (Memory Freed)" << std::endl; }
    void shoot() { std::cout << "Pew Pew!" << std::endl; }
};

int main() {
    std::cout << "--- Game Started ---" << std::endl;
    
    {
        // 1. Unique Pointer (సింగిల్ ఓనర్)
        // C++14 లో వచ్చిన make_unique వాడటమే బెస్ట్ ప్రాక్టీస్ 
        std::unique_ptr<Player> p1 = std::make_unique<Player>();
        p1->shoot();
        
        // 2. Shared Pointer (మల్టిపుల్ ఓనర్స్)
        std::shared_ptr<Player> s1 = std::make_shared<Player>();
        std::shared_ptr<Player> s2 = s1; // ఇప్పుడు కౌంటర్ 2 అయింది!
        
        std::cout << "Shared Count: " << s1.use_count() << std::endl;
        
    } // బ్రాకెట్ అవ్వగానే అన్నీ ఆటోమేటిక్ గా డిలీట్ అవుతాయి (No delete keywords needed!)
    
    std::cout << "--- Game Ended ---" << std::endl;
    return 0;
}
4 కోడ్ లో ఏం జరుగుతోంది? (Step-by-Step)
  • #include <memory>: స్మార్ట్ పాయింటర్స్ వాడాలంటే కచ్చితంగా ఈ హెడర్ ఫైల్ ఉండాలి.
  • std::make_unique<Player>(): ఇది డైరెక్ట్ గా new Player() లాగానే మెమరీ తీసుకుంటుంది, కానీ ఆటోమేటిక్ గా సేఫ్ గా దాచిపెడుతుంది.
  • s2 = s1;: మనం s1 ని s2 కి కాపీ చేసినప్పుడు, లోపల ఉన్న కౌంటర్ (Reference Count) 1 నుండి 2 కి మారుతుంది. ఎప్పుడైతే ఆ రెండు పాయింటర్స్ చనిపోతాయో (స్కోప్ దాటుతాయో) అప్పుడు కౌంటర్ 0 అయ్యి, అప్పుడు మాత్రమే డిస్ట్రక్టర్ కాల్ అవుతుంది.
5 ఇంటర్వ్యూలలో అడిగే కామన్ ప్రశ్నలు (FAQ)

Q1: new Player() రాయడానికి, make_unique<Player>() రాయడానికి తేడా ఏంటి?

మీరు new వాడితే మెమరీ అలోకేట్ అయ్యే టైమ్ లో ఏదైనా ఎక్సెప్షన్ (Exception) వస్తే లీక్ అయ్యే ప్రమాదం ఉంది. కానీ make_unique అనేది C++14 లో తెచ్చిన ఒక సేఫ్టీ ఫంక్షన్. ఇది మెమరీ ని తీసుకుని, ఆబ్జెక్ట్ ని క్రియేట్ చేసి సింగిల్ స్టెప్ లో స్మార్ట్ పాయింటర్ కి ఇస్తుంది. ఎప్పుడూ make_unique నే వాడాలి.

Q2: నేను ఒక unique_ptr ని ఇంకో ఫంక్షన్ కి పాస్ చేయొచ్చా?

డైరెక్ట్ గా వాల్యూ లాగా పాస్ చేయలేరు (ఎందుకంటే దాన్ని కాపీ చేయడం ఒప్పుకోదు). మీరు దాన్ని రిఫరెన్స్ (const std::unique_ptr<Player>&) లాగా పాస్ చేయొచ్చు లేదా ఓనర్షిప్ మొత్తం వాళ్ళకి ఇచ్చేయాలి అనుకుంటే std::move(p1) వాడి పాస్ చేయొచ్చు.

Q3: Cyclic Reference (సైక్లిక్ రిఫరెన్స్) అంటే ఏంటి?

మీ దగ్గర A మరియు B అనే రెండు క్లాసెస్ ఉన్నాయి. A లోపల B కి సంబంధించిన shared_ptr, B లోపల A కి సంబంధించిన shared_ptr ఉంటే... రెండిటి కౌంటర్ ఎప్పటికీ 0 అవ్వదు. ఎందుకంటే అవి ఒకదాన్ని ఒకటి పట్టుకుని వేలాడుతుంటాయి. దీనివల్లే భయంకరమైన మెమరీ లీక్స్ వస్తాయి. దీన్ని ఆపడానికి ఆ రెంటిలో ఏదోక దాన్ని std::weak_ptr కింద మార్చాలి (weak_ptr కౌంటర్ ని పెంచదు).
