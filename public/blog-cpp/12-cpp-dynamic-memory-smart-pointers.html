డైనమిక్ మెమరీ & Smart Pointers (తెలుగులో)

జీరో మెమరీ లీక్స్ సాధించండి! Stack vs Heap ఆర్కిటెక్చర్, new మరియు delete[] ప్రమాదాలు, Dangling Pointers, C++ యొక్క రక్షకుడైన RAII సూత్రం, మరియు Modern C++ లోని std::unique_ptr, std::shared_ptr, std::weak_ptr సమగ్ర విశ్లేషణ.

📌 Covered in this chapter: Stack vs Heap Architecture · new & delete[] · Memory Leaks & Dangling Pointers · RAII Design Pattern · unique_ptr · shared_ptr · weak_ptr
1 Stack vs Heap: కంప్యూటర్ ర్యామ్ లో రెండు ప్రపంచాలు

ఒక C++ ప్రోగ్రామ్ రన్ అవుతున్నప్పుడు దానికి కేటాయించబడిన ర్యామ్ (RAM) ప్రధానంగా రెండు విభిన్నమైన ప్రాంతాలుగా పనిచేస్తుంది: Stack మరియు Heap.

🏛️ Stack vs Heap అంతర్గత పోలిక:

1. STACK (స్టాక్ మెమరీ)
  • ఎవరి కోసం: ఫంక్షన్ లోకల్ వేరియబుల్స్.
  • పనితీరు: LIFO (Last-In, First-Out) ప్రకారం ఆటోమేటిక్ క్లీనప్.
  • వేగం: అత్యంత మెరుపు వేగం (CPU Stack Pointer రిజిస్టర్).
  • పరిమితి: పరిమిత సైజ్ (1MB - 8MB). ఎక్కువ డేటా పెడితే Stack Overflow క్రాష్ వస్తుంది!
2. HEAP (హీప్ మెమరీ)
  • ఎవరి కోసం: రన్‌టైమ్‌లో new ద్వారా అడిగిన డైనమిక్ డేటా.
  • పరిమాణం: చాలా పెద్దది (గిగాబైట్ల కొద్దీ ర్యామ్).
  • నియంత్రణ: ప్రోగ్రామర్ బాధ్యత! మనం స్వయంగా డిలీట్ చేయాలి లేదా Smart Pointers వాడాలి.
  • ప్రమాదం: క్లీన్ చేయకపోతే Memory Leak సంభవిస్తుంది.
2 ప్రాచీన పద్ధతి: new మరియు delete[] ప్రమాదాలు

యూజర్ ఎంత డేటా ఇస్తాడో ముందుగా తెలియనప్పుడు (ఉదా: 10,00,000 గేమ్ ఎంటిటీలు), స్టాక్ మెమరీ సరిపోదు. హీప్ మెమరీని అడగడానికి పాత C++ లో new మరియు delete ఆపరేటర్లను వాడేవారు:

🚨 The Delete[] Disaster (అర్రే డిలీట్ ట్రాప్):
మీరు int* arr = new int[100]; అని అర్రే కేటాయించి, డిలీట్ చేసేటప్పుడు బ్రాకెట్లు లేకుండా కేవలం delete arr; అని రాస్తే తీవ్రమైన అన్‌డిఫైన్డ్ బిహేవియర్ (Undefined Behavior) జరుగుతుంది! అర్రేను డిలీట్ చేయడానికి ఖచ్చితంగా delete[] arr; అని రాయాలి!
💻 Example 1: Manual Heap Allocation & Deallocation
raw_heap_allocation.cpp
⚡ Try in Compiler 
#include <iostream>

int main() {
    int* ptr = new int(42); // Allocate 1 int on Heap
    std::cout << "Heap Value: " << *ptr << "\n";
    delete ptr;             // Free the memory to OS
    ptr = nullptr;          // Prevent Dangling Pointer!

    int* arr = new int[3]{10, 20, 30}; // Allocate Array on Heap
    std::cout << "arr[1]: " << arr[1] << "\n";
    delete[] arr;           // Must use delete[] for arrays
    arr = nullptr;
    return 0;
}
🔍 Line-by-Line కోడ్ బ్రేక్ డౌన్:
  • int* ptr = new int(42);: హీప్ లో 4 బైట్లు కేటాయించి అందులో 42 ని నింపి, ఆ అడ్రస్ ను స్టాక్ లో ఉన్న ptr కు ఇచ్చింది.
  • ptr = nullptr;: మెమరీ డిలీట్ అయిన తర్వాత కూడా పాత అడ్రస్ అలాగే ఉండే ప్రమాదాన్ని (Dangling Pointer) నివారించడానికి nullptr సెట్ చేసాం.
3 RAII: C++ యొక్క అసలైన రక్షకుడు (The Golden Rule)

ప్రోగ్రామర్లు ఎంత జాగ్రత్తగా ఉన్నా, ఫంక్షన్ మధ్యలో ఎర్రర్ రావడం వల్ల లేదా మర్చిపోవడం వల్ల delete లైన్ రన్ అవ్వకపోవడం సహజం. దీనిని శాశ్వతంగా పరిష్కరించడానికి C++ సృష్టికర్త కనిపెట్టిన సూత్రమే RAII (Resource Acquisition Is Initialization).

💎 RAII గోల్డెన్ ఫిలాసఫీ:
హీప్ మెమరీని నేరుగా రా పాయింటర్లలో ఉంచకండి! దానిని ఒక స్టాక్ ఆబ్జెక్ట్ లోపల చుట్టండి (Wrap in a Stack Object):
1. ఆబ్జెక్ట్ క్రియేట్ అయినప్పుడు దాని Constructor హీప్ మెమరీని తీసుకుంటుంది.
2. ఫంక్షన్ ముగిసి స్టాక్ క్లియర్ అయినప్పుడు ఆ ఆబ్జెక్ట్ యొక్క Destructor ఆటోమేటిక్‌గా పిలవబడి హీప్ మెమరీని క్షణాల్లో క్లీన్ చేస్తుంది!
దీనివల్ల మనుషులు మర్చిపోయినా కంపైలర్ ఎప్పటికీ మర్చిపోదు. జీరో మెమరీ లీక్స్!
4 Modern C++ Smart Pointers (<memory>)

Modern C++ లో new మరియు delete లను నేరుగా వాడటం బ్యాన్ చేయబడింది. వాటి స్థానంలో మూడు రకాల స్మార్ట్ పాయింటర్లు వచ్చాయి:

Smart Pointer యాజమాన్యం (Ownership) ఎప్పుడు వాడాలి?
std::unique_ptr Exclusive (కేవలం ఒకే ఒక్క ఓనర్) 90% కేసుల్లో ఇదే వాడాలి. కాపీ కుదరదు (Move మాత్రమే చేయగలం). జీరో ఓవర్‌హెడ్ స్పీడ్!
std::shared_ptr Shared (బహుళ ఓనర్లు) ఒకే ఆబ్జెక్ట్‌ను చాలామంది పంచుకున్నప్పుడు. రిఫరెన్స్ కౌంట్ (Reference Count) సున్నా అయినప్పుడు ఆటో-డిలీట్ అవుతుంది.
std::weak_ptr Non-Owning Observer (యాజమాన్యం ఉండదు) Circular References వల్ల ఏర్పడే డెడ్‌లాక్ మెమరీ లీక్‌లను విచ్ఛిన్నం చేయడానికి.
💻 Example 2: std::unique_ptr with Zero Leaks (std::make_unique)
smart_unique_ptr.cpp
⚡ Try in Compiler 
#include <iostream>
#include <memory>

class Song {
public:
    Song() { std::cout << "Song started playing 🎵\n"; }
    ~Song() { std::cout << "Song finished & cleaned up automatically 🧹\n"; }
};

int main() {
    {
        // Modern C++ Best Practice: make_unique
        std::unique_ptr<Song> track = std::make_unique<Song>();
        std::cout << "Inside local scope block...\n";
    } // స్కోప్ ముగియగానే delete రాయకపోయినా Destructor ఆటోమేటిక్ గా రన్ అవుతుంది!

    std::cout << "Outside scope. Zero Memory Leaks Guaranteed!\n";
    return 0;
}
🔍 Line-by-Line కోడ్ బ్రేక్ డౌన్:
  • std::make_unique<Song>(): new రాయకుండా సురక్షితంగా హీప్ లో Song ని క్రియేట్ చేస్తుంది.
  • } స్కోప్ ముగింపు: కర్లీ బ్రాకెట్ దాటగానే unique_ptr డెస్ట్రాయ్ అయ్యి లోపలి Song ను క్షణాల్లో క్లీన్ చేస్తుంది. ఎలాంటి delete రాయాల్సిన పనే లేదు!
5 సాధారణంగా బిగినర్స్ చేసే తప్పులు & బెస్ట్ ప్రాక్టీసెస్

⚠️ Common Beginner Traps

  • Circular Dependency with shared_ptr: ఆబ్జెక్ట్ A ఆబ్జెక్ట్ B ని, ఆబ్జెక్ట్ B ఆబ్జెక్ట్ A ని shared_ptr ద్వారా చూపిస్తే రిఫరెన్స్ కౌంట్ ఎప్పటికీ 0 అవ్వదు (Permanent Memory Leak). ఇందులో ఒకదాన్ని weak_ptr గా మార్చాలి!
  • unique_ptr ని కాపీ చేయడానికి ప్రయత్నించడం: unique_ptr ని కాపీ చేయలేము (Compile Error). బదిలీ చేయాలంటే std::move() వాడాలి.

💡 Industry Best Practices

  • Prefer make_unique over new: ఎప్పుడూ std::make_unique<T>() వాడండి. ఇది సింగిల్ అలొకేషన్ తో సూపర్ ఫాస్ట్ గా ఎక్సెప్షన్ సేఫ్టీ ఇస్తుంది.
  • డిఫాల్ట్ గా unique_ptr ఎంచుకోండి: నిజంగా బహుళ ఓనర్లు అవసరమైతేనే shared_ptr కి వెళ్ళండి; ఎందుకంటే షేర్డ్ పాయింటర్ కు అటామిక్ రిఫరెన్స్ కౌంటింగ్ ఓవర్‌హెడ్ ఉంటుంది.
❓ Frequently Asked Questions (FAQ)

Q Stack మెమరీ కి Heap మెమరీ కి ముఖ్యమైన తేడాలు ఏమిటి?

Stack మెమరీ చాలా వేగవంతమైనది, ఫంక్షన్ కాల్ అయినప్పుడు వేరియబుల్స్ ఆటోమేటిక్‌గా స్టోర్ అయి ఫంక్షన్ ముగియగానే డిలీట్ అవుతాయి (పరిమిత సైజ్ ఉంటుంది, సాధారణంగా 1MB నుండి 8MB). Heap మెమరీ అనేది చాలా పెద్ద డైనమిక్ మెమరీ పూల్; ఇక్కడ 'new' ద్వారా మెమరీ కేటాయించి 'delete' ద్వారా మనమే స్వయంగా క్లీన్ చేయాలి లేదా Smart Pointers వాడాలి.

Q C++ లో RAII (Resource Acquisition Is Initialization) అంటే ఏమిటి?

RAII అనేది C++ లో మెమరీ లీక్‌లను పూర్తిగా నివారించే ఒక గోల్డెన్ డిజైన్ ప్యాటర్న్. ఒక వనరును (మెమరీ, ఫైల్, సాకెట్) ఆబ్జెక్ట్ యొక్క Constructor లో అక్వైర్ చేస్తారు మరియు ఆ ఆబ్జెక్ట్ స్కోప్ దాటి వెళ్ళినప్పుడు దాని Destructor ఆటోమేటిక్‌గా ఆ వనరును విడుదల (deallocate) చేస్తుంది.

Q Modern C++ లో Raw Pointer కి బదులుగా std::unique_ptr ఎందుకు వాడాలి?

std::unique_ptr అనేది హీప్ ఆబ్జెక్ట్‌కు సంపూర్ణ యాజమాన్యం (Exclusive Ownership) కలిగి ఉంటుంది. ఫంక్షన్ ముగిసినా లేదా ఎక్సెప్షన్ వచ్చినా అది ఆటోమేటిక్‌గా మెమరీని 'delete' చేస్తుంది. దీనివల్ల జీరో మెమరీ లీక్ గ్యారెంటీ లభిస్తుంది మరియు ఇది సాధారణ raw pointer అంతే వేగంతో పనిచేస్తుంది (Zero Overhead).
