Operator Overloading & Friend Functions (తెలుగులో)

⚡ Modern C++ (C++17 / C++20 / C++23) 🟢 Lesson 12 📂 Phase 12: Operator Overloading 📅 2026 Master Edition
📌 Covered in this in-depth guide: Operator Overloading (+, -) · Friend Functions · cin/cout Overloading · Encapsulation Bypass

మామూలుగా అయితే int a = 5, b = 10; అని తీసుకుని a + b అని కూడితే 15 వస్తుంది. ఎందుకంటే ఆ + (ప్లస్) అనే ఆపరేటర్ కి నంబర్స్ ని ఎలా కూడాలో తెలుసు. కానీ మీ దగ్గర Vector3D (X, Y, Z కోఆర్డినేట్స్) అనే ఒక సొంత క్లాస్ ఉందనుకోండి. రెండు వెక్టార్ ఆబ్జెక్ట్స్ ని v1 + v2 అని రాస్తే కంపైలర్ కి పిచ్చెక్కుతుంది! ఎందుకంటే రెండు బాక్సులని ఎలా కూడాలో దానికి తెలీదు. ఇలా మనకు నచ్చిన క్లాసెస్ కి ఆపరేటర్స్ ని కొత్తగా నేర్పించడాన్నే Operator Overloading (ఆపరేటర్ ఓవర్‌లోడింగ్) అంటారు. దీనితో పాటు, ప్రైవేట్ రూమ్ లో ఉన్న సీక్రెట్స్ ని యాక్సెస్ చేయడానికి వాడే Friend Functions గురించి కూడా డీప్ గా నేర్చుకుందాం.

1 అసలు Operator Overloading అంటే ఏమిటి?

ప్రోగ్రామింగ్ లో మనం మ్యాథ్స్ లో వాడే సింబల్స్ (+, -, *, ==, <<) అన్నీ బేసిక్ డేటా టైప్స్ (int, float) కి మాత్రమే పనిచేస్తాయి. కానీ C++ లో మనకు ఉన్న ఒక సూపర్ పవర్ ఏంటంటే, ఈ సింబల్స్ ని మన క్లాసెస్ (ఉదాహరణకు Complex Numbers, Matrices, 3D Vectors) కి అప్లై చేసేలా వాటి మీనింగ్ ని మార్చొచ్చు. దీన్నే ఓవర్‌లోడింగ్ అంటారు.

🎮 రియల్ లైఫ్ స్టోరీ: వీడియో గేమ్ లో హెల్త్ ప్యాక్ సిస్టమ్

మీరు ఒక పబ్ జి (PUBG) లాంటి గేమ్ ఆడుతున్నారు. అందులో ప్లేయర్ కి సంబంధించిన హెల్త్, బుల్లెట్స్ ఒక క్లాస్ (PlayerStatus) లో ఉంటాయి. మీరు ఒక హెల్త్ కిట్ (HealthKit) ని పిక్ చేసుకోగానే, మీ ప్లేయర్ స్టేటస్ పెరగాలి.

C++ లో మనం PlayerStatus + HealthKit అని రాసేలా కంపైలర్ కి నేర్పించొచ్చు! అప్పుడు కంపైలర్ ఆ + సింబల్ ని చూసినప్పుడు, ఒక ఫంక్షన్ ని కాల్ చేసి ఆ హెల్త్ కిట్ లో ఉన్న 50 HP ని ప్లేయర్ కి ఆటోమేటిక్ గా యాడ్ చేస్తుంది. దీనివల్ల గేమ్ డెవలపర్స్ addHealth(50) లాంటి బోర్ కొట్టే ఫంక్షన్స్ రాయకుండా, డైరెక్ట్ గా మ్యాథ్స్ లాగా player += health_kit; అని రాసుకుంటూ వెళ్ళిపోతారు. కోడ్ చదవడానికి చాలా అద్భుతంగా ఉంటుంది!

2 Friend Functions (ఫ్రెండ్ ఫంక్షన్స్) ఎందుకు వాడాలి?

క్లాస్ లోపల private గా ఉన్న డేటాని బయట నుండి ఏ ఫంక్షన్ యాక్సెస్ చేయలేదని మనం గతంలో నేర్చుకున్నాం (Encapsulation). కానీ కొన్ని ప్రత్యేక పరిస్థితుల్లో వేరే క్లాస్ లో ఉన్న ఫంక్షన్ గానీ, లేదా బయట ఉన్న ఒక గ్లోబల్ ఫంక్షన్ గానీ మన ప్రైవేట్ డేటాని ముట్టుకోవాల్సి వస్తుంది.

అప్పుడు మనం ఆ ఫంక్షన్ పేరుకి ముందు friend అని మన క్లాస్ లోపల ఒక డిక్లరేషన్ ఇస్తాము. దీని అర్థం ఏంటంటే, "కంపైలర్ గారూ, ఈ ఫంక్షన్ నా బెస్ట్ ఫ్రెండ్, వీడికి నా ప్రైవేట్ లాకర్ పాస్వర్డ్ ఇచ్చేస్తున్నా, అడ్డుకోకండి" అని చెప్పడం. ముఖ్యంగా << (cout) ని ఓవర్ లోడ్ చేసేటప్పుడు ఈ ఫ్రెండ్ ఫంక్షన్స్ ని కచ్చితంగా వాడాలి.

3 ఒకే ఒక సింపుల్ కోడ్ (Operator Overloading)

కింద కోడ్ లో రెండు 2D పాయింట్స్ (x, y) ని + ఆపరేటర్ వాడి ఎలా కూడుతున్నామో, దాన్ని డైరెక్ట్ గా cout తో ఎలా ప్రింట్ చేస్తున్నామో క్లియర్ గా గమనించండి.

C++ — Operator + & cout Overloading ▶ Run Code 
#include <iostream>

class Point {
private:
    int x, y;

public:
    // కన్‌స్ట్రక్టర్ (వాల్యూస్ సెట్ చేయడానికి)
    Point(int xVal = 0, int yVal = 0) {
        x = xVal;
        y = yVal;
    }

    // 1. Operator '+' ని ఓవర్‌లోడ్ చేస్తున్నాం
    // పక్కన ఉన్న ఇంకొక Point ని తీసుకుని, రెండిటినీ కూడి కొత్త Point ఇస్తుంది
    Point operator+(const Point& other) {
        Point result;
        result.x = this->x + other.x;
        result.y = this->y + other.y;
        return result;
    }

    // 2. Operator '<<' ని ఓవర్‌లోడ్ చేస్తున్నాం (cout కోసం)
    // ఇది గ్లోబల్ ఫంక్షన్ కాబట్టి friend అని ఇచ్చాం (ప్రైవేట్ x, y చదవడానికి)
    friend std::ostream& operator<<(std::ostream& out, const Point& p) {
        out << "(" << p.x << ", " << p.y << ")";
        return out;
    }
};

int main() {
    Point p1(10, 20);
    Point p2(5, 15);
    
    // డైరెక్ట్ గా మ్యాథ్స్ లాగా రెండు ఆబ్జెక్ట్స్ ని కూడుతున్నాం! (Operator + magic)
    Point p3 = p1 + p2;
    
    // డైరెక్ట్ గా ఆబ్జెక్ట్ ని ప్రింట్ చేస్తున్నాం! (Operator << magic)
    std::cout << "Result Point: " << p3 << std::endl;
    
    return 0;
}
4 కోడ్ లో ఏం జరుగుతోంది? (Step-by-Step)
  • Point operator+(const Point& other): మనం p1 + p2 అని రాయగానే, కంపైలర్ p1.operator+(p2) అని మార్చి ఫంక్షన్ ని పిలుస్తుంది. అప్పుడు this->x అనేది p1 యొక్క x ని (10), other.x అనేది p2 యొక్క x ని (5) కూడి రిజల్ట్ (15) పంపుతుంది.
  • friend std::ostream& operator<<: మామూలుగా cout కి మన Point ఆబ్జెక్ట్ లో ఏముందో తెలీదు. కాబట్టి మనం ఈ ఫ్రెండ్ ఫంక్షన్ రాసి, అందులో బ్రాకెట్స్ పెట్టి ఫార్మాట్ (x, y) గా మార్చి అవుట్పుట్ స్ట్రీమ్ (out) లోకి తోసాము. ఇది రాయకపోతే మీరు cout << p3; అని రాసినప్పుడు భయంకరమైన ఎర్రర్ వస్తుంది.
5 ఇంటర్వ్యూలలో అడిగే కామన్ ప్రశ్నలు (FAQ)

Q1: C++ లో ఏ ఏ ఆపరేటర్స్ ని మనం మార్చలేము (Cannot Overload)?

చాలా మటుకు అన్నిటినీ మార్చొచ్చు కానీ, కొన్నింటిని కంపైలర్ టచ్ చేయనివ్వదు. అవి: డాట్ ఆపరేటర్ (.), స్కోప్ రిజల్యూషన్ ఆపరేటర్ (::), టెర్నరీ ఆపరేటర్ (?:), మరియు sizeof ఆపరేటర్. వీటి మీనింగ్ మారిపోతే మొత్తం C++ పునాది కదిలిపోతుంది కాబట్టి వీటిని లాక్ చేసారు.

Q2: ఒక క్లాస్ లో వందలాది ఫ్రెండ్ ఫంక్షన్స్ వాడొచ్చా? ఇది మంచిదేనా?

వాడొచ్చు, కానీ అది "Very Bad Design" అవుతుంది! ఎందుకంటే ఎన్‌క్యాప్సులేషన్ ముఖ్య ఉద్దేశ్యమే డేటాని దాచిపెట్టి కాపాడటం. మీరు ఎవరికి పడితే వాళ్ళకి ఫ్రెండ్ షిప్ ఇచ్చేసి ప్రైవేట్ డేటాని ఓపెన్ చేస్తే, దాన్ని హాక్ చేయడం లేదా తప్పు వాల్యూస్ సెట్ చేయడం చాలా ఈజీ అవుతుంది. కేవలం cin / cout ఓవర్ లోడింగ్ లాంటి అత్యవసర సమయాల్లో మాత్రమే ఫ్రెండ్ ని వాడాలి.

Q3: జావా లాంటి లాంగ్వేజెస్ లో ఆపరేటర్ ఓవర్‌లోడింగ్ ఎందుకు లేదు?

జావా తయారు చేసిన జేమ్స్ గోస్లింగ్ ఏమనుకున్నాడంటే, "ఆపరేటర్ ఓవర్‌లోడింగ్ వాడితే కోడ్ చూడటానికి సింపుల్ గా అనిపిస్తుంది కానీ, బ్యాక్ గ్రౌండ్ లో ఏ భారీ ఫంక్షన్ రన్ అవుతుందో డెవలపర్ కి తెలీక కన్ఫ్యూజ్ అవుతాడు" అని దాన్ని తీసేసాడు. జావాలో మీరు p1.add(p2) అని మ్యాన్యువల్ గా ఫంక్షన్స్ రాయాల్సిందే. కానీ C++, C# మరియు పైథాన్ లో ఈ ఓవర్‌లోడింగ్ ఫీచర్ ఉంది.
